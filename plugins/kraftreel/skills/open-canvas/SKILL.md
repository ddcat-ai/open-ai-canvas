# 打开影策画布

当用户要求打开、启动、进入或使用影策时，不要把 URL 交给用户手动复制，不要通过浏览器点击“新建画布”。优先确认影策网页服务可用，然后直接打开带 `mode` 的 URL，让网页自动创建或选择画布并使用在线 Agent。

## 默认打开方式

- 新建画布：`<画布网页地址>/canvas?mode=new`
- 最近画布：`<画布网页地址>/canvas?mode=recent`
- 交接上下文：`<画布网页地址>/canvas?mode=handoff&...`

默认打开新建画布；只有用户明确要求最近画布或交接上下文时，才改用对应模式。

## 工作流

1. 如果当前仓库是影策项目，优先使用当前仓库的 `web/` 前端。
2. 先检查本地端口归属：如果 `3000`、`3001` 等端口已被占用，必须用平台可用的进程/端口工具确认监听进程的工作目录属于当前仓库的 `web/`，不能只因为端口存在就当成本地画布。
3. 如果已有当前仓库的 Vite dev 服务，复用它并记录真实画布地址，例如 `http://localhost:3001`。
4. 如果没有当前仓库的服务，启动本地画布开发服务，默认在 `web/` 下运行 `bun run dev`；若默认端口被其他项目占用，使用 `bun run dev -- --port <空闲端口>`。不要执行构建或测试。
5. 直接构造并打开最终 URL：`<真实画布地址>/canvas?mode=new`（或按用户意图使用 `mode=recent` / `mode=handoff`）。
6. 画布网页会自动创建或选择具体画布，并使用在线 Agent；不要再添加 `agentUrl`、`agentToken`，也不要尝试连接本机 Agent。
7. 打开后检查画布页面和在线 Agent 面板是否正常显示；不要启动 Canvas Agent HTTP Runtime。

## 用户只安装插件时

- 如果当前工作区不是影策源码仓库，优先提示用户先打开或启动影策网页。
- 可以使用线上画布地址或用户给出的本地地址作为 `<画布网页地址>`，但不需要通过本地 Canvas Agent 获取 URL 或 token。
- 不要假设用户已经安装本仓库依赖；插件的 MCP 会通过 `npx -y kraftreel-cli mcp` 使用已发布的远程适配器。MCP 首次使用需要用户自行完成 `login web` 和 `project use`，但打开网页不以此为前置条件。

不要要求用户手动填写 token 或复制 JSON。不要探测 `127.0.0.1:17371`，也不要恢复 Dreamina CLI、肖像本机引擎或本机 Agent 连接。
