# 08: 官方初始内容与完整流程验收

**What to build:** 为上线准备六类可用官方示例，并在真实应用中证明“角色卡 → 官方/个人/姿势参考 → 图片任务 → 预览命名保存 → 刷新重新选用”的完整流程可用，同时完成失败恢复、权限、节点隔离与界面回归，交付可复核的验收记录。以用户已确认的《角色卡梳妆台功能规格》验收边界为准。

**Blocked by:** 05：官方素材配置与梳妆台选用；06：姿势库直接选入梳妆台；07：关闭、刷新后的任务与结果恢复。

**Status:** implemented-pending-acceptance

**实施记录：** 用户将本轮验收目标明确为本地。已在独立本地数据中通过原后台 API 发布六类自绘测试图片，并用真实页面、后端 Worker 和本地图片协议测试上游完成主链路、保存失败重试、六槽组合、刷新恢复、版本冲突、声音与旧形象保留、窄屏及明暗主题检查。正式官方内容与真实供应商效果不在本轮本地结果中冒充完成。专项、类型、lint 和构建通过；全量检查中两项原有问题已在原始基线复现，Agent 依赖补齐后的失败项已复跑通过。

- [ ] 在已明确且已获授权的目标环境，通过现有官方素材管理能力准备衣服、表情、姿势、配饰、发型、五官各至少一项正式示例，记录合法来源与使用授权，确认资源可访问并发布。
- [ ] 正式素材与目标环境访问是内容交付前置条件；缺少时记录具体缺项，不用未知授权图片或测试占位图冒充完成，不因本任务自行部署或写入未授权环境。
- [ ] 验收从已有至少两套形象的角色开始，在同一画布放置该角色两个分别选用不同形象的节点。
- [ ] 从发起节点打开真实梳妆台，确认基础形象正确，混合使用官方衣服、个人表情、姿势库视角，并分别验证六类选用、替换、清除及分类上传回填。
- [ ] 提交图片任务并预览选图、命名保存，确认形象只增加一项，原有形象、声音和设定保留；发起节点使用新形象，另一个节点保持旧选择。
- [ ] 刷新后角色名称、图片、来源和节点选择仍正确，能够重新选用旧形象；关闭后重开、生成中刷新可恢复任务及待保存结果。
- [ ] 验证重复保存、保存响应丢失与失败后重试只写入一项，不新增图片任务或二次生成费用；版本冲突不会覆盖其他修改。
- [ ] 覆盖素材不可访问、角色删除/失权、节点删除、官方插件不可用、素材下架和账号切换，确认错误提示可行动且权限无绕过。
- [ ] 验证模型切换参数、参考图能力、包含基础图的数量限制及图序用途；超限或不支持时明确阻止提交，不能丢图后继续生成。
- [ ] 浏览器自动化在真实组件和应用状态上运行，可在统一任务 HTTP 边界控制确定输出；不使用独立 HTML 或脱离应用状态的截图作为通过证据。
- [ ] 在已授权图片渠道至少完成一次真实多参考图生成，记录实际模型、输入组合与效果观察；人工评估身份保持及槽位效果，不将固定测试输出当成模型效果验证。
- [ ] 检查明暗主题、窄屏滚动、加载/空态/错误态、键盘操作、焦点恢复、命名入口和浮层事件边界，确保不会误触画布拖拽或缩放。
- [ ] 回归现有角色手动绑定/命名/选用、素材库分类、官方素材管理及姿势库画布插入；新增能力最大程度复用原组件，无重复资产库、形象库、任务队列或模型调用链路。
- [ ] 每项前置任务已有相关专项验证；本任务补组合链路验证，不以健康检查、静态阅读或重复全量测试代替业务证据。
- [ ] 同步功能清单、代码地图、用户操作、API/OpenAPI、实际数据库变化及待测试记录；区分已执行、未覆盖和仍待用户确认的项目，不伪造完成结论。
- [ ] 若实施交付需要推送，执行仓库要求的最新远端同步、改动文件格式化及推送前验证，记录总结和本地未覆盖项；本票本身不构成部署或外部发布授权。
