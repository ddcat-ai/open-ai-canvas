# 02: 角色形象安全新增与命名

**What to build:** 用户通过现有角色工作室上传或选择一张有权访问的图片，将其命名并新增为同一角色的形象。保存保留原有形象、声音和设定，重复请求不生成重复条目，并发修改不会互相覆盖。这是后续梳妆生成结果保存所复用的业务能力，以《角色卡梳妆台功能规格》为依据。

**Blocked by:** None (can start immediately).

**Status:** implemented-pending-acceptance

**实施记录：** 已实现版本比较、不可变版本回执、来源保留和节点独立选用。服务端测试覆盖重放、不同内容复用操作号、越权和冲突；本地保存失败重试及声音保留已验证，固定版本节点的明确选用另有专项回归。

- [ ] 复用现有图片选择/上传、造型管理、角色版本和 representations 写入能力，用户可以完整演示“选图 → 命名 → 新增形象 → 刷新后选用”。
- [ ] 名称去除首尾空格后不能为空，沿用现有名称约束；允许同名，以稳定造型 ID 区分，不新建第二个角色或独立形象库。
- [ ] 保存新增形象时保留原角色定义、全部原有造型、声音绑定和其他图像表达；在现有唯一构建入口修正可能造成字段丢失的重建行为。
- [ ] 现有造型读写、重命名、删除和重新绑定流程保留附加元数据，支持后续记录生成来源，无需先引入图片任务依赖。
- [ ] 写请求携带基于的角色版本与稳定保存操作标识；后端事务内校验版本和资源/角色权限后创建完整新版本。
- [ ] 版本已经变化时返回机器可读冲突，界面保留待保存图片和名称，刷新角色详情后允许用户重新保存，不静默覆盖其他修改。
- [ ] 同一保存操作重试返回已保存形象及最新角色详情；服务端先识别幂等成功再判断旧版本冲突，覆盖响应丢失及并发重复请求，不能只依赖按钮禁用。
- [ ] 服务端确认后才提示保存成功并更新角色缓存；写失败保留输入，不能把本地缓存写入当作成功。
- [ ] 发起节点选用新形象，并更新封面与引用提示词；同角色其他节点保持各自已有选择。节点已删除时仅保存角色形象，不重建节点。
- [ ] 非所有者或无当前空间写权限的操作被服务端拒绝；官方只读角色沿用现有复制为个人角色后编辑的流程。
- [ ] 沿用现有重命名、选用及删除交互；形象引用的资源删除仍受业务引用检查保护。
- [ ] 用既有角色业务及资源权限测试覆盖旧数据保留、节点隔离、事务冲突、幂等重试和越权；同步角色写入 API/OpenAPI、必要迁移及数据库专题，记录待验收项。
