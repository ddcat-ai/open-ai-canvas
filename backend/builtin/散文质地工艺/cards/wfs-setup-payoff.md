## I — 方法论骨架 (Interpretation)

读者的大脑是个永不停歇的模式探测器：它自动把每个细节归类为"铺垫 / 呼应 / 正走向呼应"。这意味着写作本质上是**埋线—收线**的工程——你放下的任何信息，大脑都会默认它将来要发酵出结果。

落到喜剧，这套机制有三条关键推论：

- **随意即噪音**：一个细节若只出现一次、再无回响，大脑会判它为"噪音"并降低对作者的信任。长剧的每一句闲笔、每个老物件都必须有去处。
- **克制才能有等待的快感**：过早揭晓"奶奶装傻的真相"或点明主旨，等于提前拆掉观众期待呼应的引擎（p19）。埋下去，留距离，让它自己响。
- **长线是奖赏**：用"年轻时一句话 / 一个老物件，老年时兑现"做跨集呼应，给观众"我的模式判断成立了"的满足。倒叙（g18）与记忆整合（g33）是天然工具——但倒叙必须"立即增进对主线的理解"，旧物的意义可以随展开从心结变成慰藉。多线群像可用螺旋结构（g30）迂回铺陈，而非 A→Z 硬直线。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《迷途青春》— 隔 70 页的长线呼应（c33）
- **问题**: 作者要示范"看似随意的信息如何成为伏笔"。
- **方法论的使用**: 牙医乔治的朋友汤姆鼓吹"想想蔚蓝天空、一望无际的沙滩"，这句话出现在第 98 页，直到第 169 页才被重新提起——读者却一直记着。
- **结论**: 嵌入情境的小信息即是伏笔，不必打旗标；读者的模式探测器会自动锁定它。
- **结果**: 证明长剧可做"年轻时一句话，老年兑现"的跨集长线，给模式成立的奖赏。

### 案例 2: 倒叙必须服务主线（g18）
- **问题**: 克龙要区分"好倒叙"与"补课式倒叙"。
- **方法论的使用**: 好倒叙"立即增进对主线的理解"——揭示当年为何离开老家、为何怕亲密；差倒叙只是事后补背景。
- **结论**: 群像用倒叙揭"当年那件事"可以，但须让当集内在弧更清晰，而非单纯交代身世。
- **结果**: 提供"倒叙即主线加速器"而非"回忆杀 filler"的判定标准。

### 案例 3: 螺旋而非直线（g30）
- **问题**: 故事从"问题发威"到"解决"看似应是两点最短距离。
- **方法论的使用**: 克龙指出实际路线"常常是条迂回曲折的路线"，含过去/现在/未来/内外层次。
- **结论**: 群像多线用螺旋结构铺陈比硬直线更耐看。
- **结果**: 群像叙事不必每集推平一条线，可让多条伏笔在不同层次交错回收。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 写某集时埋了一个梗/老物件/台词，担心"后面忘收"或"收得太硬"。
2. 想做跨集长线呼应（如第一集的存折、第三集的拖鞋，要在季终兑现）。
3. 用倒叙或回忆揭人物前史，不确定是否"服务了主线"。
4. 怕第一集就把"奶奶装傻"的真相或主旨说破，毁了等待呼应的快感。

### 语言信号 (用户的话里出现这些就应激活)

- "这集埋了个伏笔，后面怎么收才不突兀？"
- "想做个跨集长线呼应，年轻时的话老年兑现那种。"
- "倒叙会不会变成补课的废戏？"
- "第一集就把真相抖出来行不行？"
- "setup payoff / 伏笔回收 / 旧物新解怎么设计？"

### 与相邻 skill 的区分

- 与 `wfs-change-closure` 的区别: 本 skill 管"线"（伏笔埋—收、信息克制、倒叙/螺旋），对象是结构本身；`wfs-change-closure` 管"改变"（这集结尾老人信念是否被情节推翻）。一条伏笔可以服务改变，但"埋线"归本 skill、"检验改变是否发生"归 `wfs-change-closure`。先看本 skill 搭线，再用 `wfs-change-closure` 验收。
- 与 `wfs-causal-chain` 的区别: `wfs-causal-chain` 管单场内"A 因→B 果"的硬因果；本 skill 管跨场/跨集的"铺垫—呼应"长线回收。短因果归 `wfs-causal-chain`，长呼应归本 skill。
- 与 `wfs-stakes-hook` 的区别: `wfs-stakes-hook`（组A）管每页/每屏"一触即发"的张力钩子；本 skill 管钩子之外的伏笔如何被埋下并回收。两者常配合使用。

## E — 可执行步骤 (Execution)

1. **建伏笔—回收台账**
   - 完成标准: 列出本集/本季所有埋下的信息点（台词、道具、旧物、倒叙碎片），每条标注"预计回收集数/场景"，无标注的即噪音候选，需补回收或删。

2. **检验埋线自然度与克制度**
   - 完成标准: 每条伏笔都能嵌入情境（非硬塞旗标），且未在本集过早揭示真相/主旨；若"第一集就点破"，标记为违反 p19，改回克制。
   - 判停条件: 若某倒叙只是补身世、不增进当集内在弧 → 跳到步骤 3 重做其切入点。

3. **套螺旋/长线回收结构**
   - 完成标准: 确认跨集伏笔在季终有"模式成立"的回收（如老物件从心结变慰藉），且群像多线用螺旋而非硬直线铺陈；给出"观众看到回收时会心一笑/一紧"的具体落点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需要检验"这集老人的内在信念有没有被情节推翻/结尾是否闭环"——那是 `wfs-change-closure`，本 skill 只管线、不管改变发生没。
- 需要的是每屏"一触即发"的利害钩子设计——`wfs-stakes-hook`（组A）。

### 作者在书中警告的失败模式

- **随意细节即噪音（ce11/ce26 同源）**: 一个信息只出现一次再无回响，大脑判为噪音、信任下降。长剧最易在温情片段塞无回收的闲笔。
- **过早揭示（p19）**: 第一集就抖出"装傻真相"或点明主旨，剥夺等待呼应的快感。
- **偏离模式显随意（ce17）**: 为反套路而反、转折无因果，读者预期被打断却无因→觉被耍。伏笔回收必须源自错误信念的因果，不是纯"没想到"。

### 作者的盲点 / 时代局限
### 容易混淆的邻近方法论

- `wfs-change-closure`（改变检验，最易与本 skill 互抢：用户说"呼应"时其实想要"改变闭环"，需分辨他问的是线还是改变）。
- `wfs-causal-chain`（单场硬因果 vs 跨集长线呼应）。
