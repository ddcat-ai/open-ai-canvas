## I — 方法论骨架 (Interpretation)

克龙的因果铁律：**故事不是事件流水账，而是「A 因→B 果→C 果」的硬因果链**。读者默认你写的每一条信息、每一个细节都会发酵出结果——小到主角用了多少发胶，都该引起某个后续。所以写法上有两条硬规则：(1) **删掉不导向结果的事件**——任何「然后…然后」式的闲笔，只要把「然后」删掉故事不缺任何东西，就是噪音；(2) **每场结尾都要改变主人公的处境或认知**——否则这场合水。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《迷途青春》——隔70页才回收的伏笔（c33 现成模板）
- **问题**: 作者要示范「嵌入情境的小信息即伏笔」。
- **方法论的使用**: 一句「朋友劝搬佛罗里达」出现在第 98 页，直到第 169 页才再次想起，但读者一直记着——因为它被当成必要信息埋下、又自然回收。
- **结论**: 看似随意的小信息，只要「必要且回收」，读者就信任；长剧可做「年轻时一句话，老年兑现」的跨集长线。

### 案例 2: 《破绽》——前17分钟全指向一人（c03 现成模板）
- **问题**: 作者要示范「故事从头到尾回答一个问题」，无关事件不能存在。
- **方法论的使用**: 前 17 分钟看似以凶手为主角，其实每件事都必要、都指向比查姆——没有一件是平铺的噪音。
- **结论**: 每个事件都必须服务于内在线索，否则就是可删的闲笔。
- **结果**: 提供群像「真正戏眼晚登场、前情全为其必要铺路」的审查标尺。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 自检某集「有点水/然后…然后」，怀疑有闲笔。
2. 发现前面埋的线到后面没下文，担心破坏信任。
3. 想确认删掉某段情节，故事是否还成立。

### 语言信号 (用户的话里出现这些就应激活)

- "这集有点水，是不是闲笔/然后…然后？"
- "前面埋的线到后面没下文了，观众会觉被耍吗？"
- "这段删掉也不影响故事吧？它有必要吗？"
- "每场结尾好像什么都没改变，是不是注水？"

### 与相邻 skill 的区分

- 与 `wfs-setup-payoff`（组B）的区别: 本 skill 是「每细节必须必要、必有结果」的**总审查原则**；`wfs-setup-payoff` 是具体的「埋线-收线」手艺。本 skill 判出「有线无回收」后，跳它去设计呼应。
- 与 `wfs-conflict-engine` 的区别: 本 skill 管「细节的因果必要性/逻辑」；`wfs-conflict-engine` 管「逼改变的冲突动力」。前者查逻辑，后者查动力。
- 与 `wfs-stakes-hook` 的区别: 本 skill 管每细节必要性；`wfs-stakes-hook` 管每页张力钩子，不重叠。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **删掉不导向结果的闲笔**
   - 完成标准: 逐场问「这细节后续发酵了吗」，答「否」且无回收计划者删；判停条件：若有埋线但无回收点，跳到 `wfs-setup-payoff`（组B）设计呼应，而非保留悬空。

2. **每场结尾改变处境或认知**
   - 完成标准: 每个场景结尾主人公处境或认知有变化（用「如果删掉这场，弧还走吗」检验）；无变化则该场标记注水。

3. **建伏笔-回收表**
   - 完成标准: 列出所有埋线及对应回收点；判停条件：若有线无回收，回到步骤 1 并跳 `wfs-setup-payoff`；全部线有回收则通过。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已经确认细节必要、只想专门设计「怎么埋线/怎么收线」的手艺——回 `wfs-setup-payoff`（组B），本 skill 只审查不教手艺。
- 已经确认逻辑通顺、只想设计「绕不开的冲突」——回 `wfs-conflict-engine`。
- 已经确认逻辑通顺、只想查每页张力钩子——回 `wfs-stakes-hook`。

### 作者在书中警告的失败模式

- **ce25（信息平铺无必要性）**: 交代和后续无关的背景——某段信息到结尾也没发酵，读者不信其重要、跳读。每条信息都该「引起某个结果」。

### 作者的盲点 / 时代局限
### 容易混淆的邻近方法论

- `wfs-setup-payoff`（组B，易混：本 skill 是必要性总原则，它是埋线-收线手艺）。
- `wfs-conflict-engine`（易混：本 skill 管因果逻辑，它管冲突动力）。
- `wfs-stakes-hook`（每页张力，不重叠）。
