## I — 方法论骨架 (Interpretation)

Joke Map 解决"写什么"的焦虑，把灵感变成可操作步骤：
1. **列话题**：先随意列出你关心的主题（邮局、相亲、健身……）。
2. **做细节联想表**：对选中的话题，自由联想出**具体细节**而非类别——"邮局"要联想到"慢、丢件、错送、骑马邮差"，不是"服务/效率"这种抽象词。
3. **提炼 punch-premise**：从某个细节出发，写一句**负面意见**（"邮差不可靠"），不含例子。
4. **造相反 setup-premise**：为这个负面意见配一句**正面/相反意见**（"邮差很可靠"），它要能生出一整组 setups。
5. **写一组 setups**：基于 setup-premise，列出多条铺垫句——不是一条，是一组，足以撑起一个 routine。

关键反直觉点：**笑话藏在细节里**，越具体越好笑；在宽泛概括里找梗必卡壳。

## A1 — 书中的应用 (Past Application)

### 案例 1：邮局 routine 的选题
- **问题**：学生说"我想写邮局，但不知写啥"。
- **方法论的使用**：作者让其对"邮局"做联想表→得到慢/丢件/错送等细节→选"不可靠"做 punch-premise→造相反 setup-premise"邮差很可靠"→写出一组 setups（"我妈说重要文件走邮局最稳"等）。
- **结论**：一个宽泛话题经 Map 后变成一组可写笑话的素材。
- **结果**：成为全书 routine 组装的主线案例。

### 案例 2：细节下沉示范
- **问题**：为何学生总卡在"写不出梗"？
- **方法论的使用**：作者指出他们在"宽泛概括"里找梗；下钻到细节（Stanislavski："Generality is the death of art"）后宝藏自现。
- **结论**：选题阶段就决定成败。
- **结果**：成为 Joke Map 步骤 B 的核心理由。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？
1. 坐到桌前想写段子，但"不知写什么"。
2. 有个话题但只写出一条就枯竭。
3. 写出来的东西太泛、不具体、不好笑。

### 语言信号
- "写什么好笑 / 没素材"
- "选题太宽，写不出来"
- "帮我想想这个话题能怎么写"
- "association list / joke map 怎么用"

### 与相邻 skill 的区分
- 与 `joke-prospector-mine`：Map 解决"从话题到 setups"（产料）；Mine 解决"拿到一个 setup 怎么挖 punch"（加工）。先 Map 后 Mine。
- 与 `premise-opposition`：Map 用到了前提对立，但 Map 是完整选题流程；premise-opposition 是其中"意见为何相反"的原理。

## E — 可执行步骤 (Execution)

1. **列 5–10 个话题**
   - 完成标准：写出清单，不必筛选。
2. **选一个话题，做细节联想表（下钻到具体）**
   - 完成标准：表中 80% 是具体细节/画面，而非抽象类别；若仍是类别→继续下钻（"服务"→"排队两小时"）。
3. **从细节提炼 2–3 条 punch-premise（纯负面意见，不含例子）**
   - 完成标准：每条都是"对主题的负面看法"，能套到多个情境。
4. **为每条 punch-premise 造相反 setup-premise**
   - 完成标准：setup-premise 与 punch-premise 意见相反，且能派生多条 setup。
5. **选一个 setup-premise，写 5+ 条 setups**
   - 完成标准：得到一组铺垫句，而非一条；若只写出一条→回到步骤 3 换前提。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 已有明确 setup 只想挖 punch → 用 `joke-prospector-mine`。
- 段子写好了只想改表演 → 用 `act-outs-pov` / `rehearsal-process`。

### 作者在书中警告的失败模式
- **在宽泛概括里找梗**：必卡壳；必须下钻到细节（ce05）。
- **punch-premise 夹带例子**：把自己限制在一个情境，无法横向展开（ce04）。
- **把 setup-premise 当 setup 用**：只写出一则笑话就不知去向；它应生出一组 setups（ce03）。

### 作者的盲点 / 时代局限
- Map 假设"话题来自个人经验"；纯虚构/二次元题材需另补联想来源。

### 容易混淆的邻近方法论
- "头脑风暴"常见做法是列关键词；Dean 的 Map 要求细节+前提对立，是有方向的结构化 brainstorming，不是随便想。
