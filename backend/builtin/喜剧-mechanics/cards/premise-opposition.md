## I — 方法论骨架 (Interpretation)

笑话的动力来自"对立意见碰撞"：
- **punch-premise**：对某个主题的**负面意见**（如"邮差不可靠"），只含"负面看法 + 主题"两部分，**绝不能夹带具体例子**——夹了例子就把自己锁死在一个情境。
- **setup-premise**：同一个主题的**相反/正面意见**（"邮差很可靠"），它应当能派生出**一整组** setups，而非只一条。
- **方向律**：笑话总是朝更负面移动——要么 good→bad（直接反转），要么 bad→worse（程度升级）。没有这种"对立位移"，就不成笑话。

判断一个段子好不好笑，先看它的前提是否真有对立：若 setup 与 punch 是同一方向的同调重述，观众没有预期可破，自然不笑。

## A1 — 书中的应用 (Past Application)

### 案例 1：邮差不可靠
- **问题**：如何从一个主题生出一串笑话？
- **方法论的使用**：punch-premise="邮差不可靠"→ 相反 setup-premise="邮差很可靠"→ 从 setup-premise 写出一组 setups（"我妈说重要文件走邮局最稳"等），每个 setup 都能被 punch-premise 击碎。
- **结论**：一个对立前提对 = 一组可写笑话的矿。
- **结果**：成为 Joke Map/Mine 的底层逻辑。

### 案例 2：punch-premise 夹带例子的反例
- **问题**：为何有人写出"邮差因送错门而不称职"后就写不出第二条？
- **方法论的使用**：punch-premise 里塞了"送错门"这个例子，于是只能写"找错地址"这一种，排除了慢/乱/漏等其他方向。
- **结论**：夹例子=自我设限。punch-premise 必须是纯负面意见。
- **结果**：作者明确列为写作禁忌（ce04）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？
1. 写 punch-premise 时忍不住把具体例子写进去。
2. 写出的段子 setup 与 punch 像在说同一件事，不好笑。
3. 想理解"为什么喜剧总是往坏里写"。

### 语言信号
- "punch-premise / setup-premise 怎么写"
- "我的 punch 跟 setup 好像一个意思"
- "为什么笑话都往坏里写"
- "comedy is two opposite ideas 什么意思"

## E — 可执行步骤 (Execution)

1. **写 punch-premise：对主题的一句负面意见，不含例子**
   - 完成标准：可套到多个情境；若只能想到一个具体场景→删掉例子，保留看法。
2. **写相反 setup-premise**
   - 完成标准：与 punch-premise 意见相反，且能派生多条 setup。
3. **检查对立方向**
   - 完成标准：good→bad 或 bad→worse；若同调→改前提。
4. **（若写不出第二则同主题笑话）回头查前提**
   - 完成标准：能写出一组 setups；若仍单点→说明前提没写对，回步骤 1。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 已有 setup 只想挖 punch → 用 `joke-prospector-mine`。
- 段子写好了只差演 → 用 `act-outs-pov`。

### 作者在书中警告的失败模式
- **punch-premise 夹带例子** → 自我设限（ce04）。
- **把 setup-premise 当 setup 用** → 只写出一则笑话就卡住（ce03）。

### 作者的盲点 / 时代局限
- "总朝负面"对纯智力/语言游戏类幽默（如某些 wordplay）解释力偏弱。

### 容易混淆的邻近方法论
- "反差"是口语；本 skill 的"前提对立 + 负面方向律"是可操作的写作约束，不是泛泛的"弄个反差"。
