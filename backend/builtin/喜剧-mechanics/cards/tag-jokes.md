## I — 方法论骨架 (Interpretation)

tag 是"已完成一个 joke 之后，再追一个 punch"的技术，目的是用**同一个 setup 多拿几次笑**，直接拉高 LPM（每分钟笑声）。三种打法：
1. **用原 target assumption**：同一个被击碎的假设，换一个 reinterpretation 再砸一次（如"took out"先解作"带去庆生晚餐"，再解作"杀父"）。
2. **用另一 1st-story 假设**：setup 本来还藏着别的假设，挑一个没用过的来破。
3. **用 2nd-story 新假设**：从刚揭示的 2nd story 里再找一个可破的假设。

关键：tag 不是"把 joke 再说一遍"，而是"在同一场景里再找一个可破的假设"。它廉价、高效，是 Dean 提 LPM 的首选手段之一。

## A1 — 书中的应用 (Past Application)

### 案例 1：took out 双关 tag
- **问题**：一个 setup 能否拿到两次笑？
- **方法论的使用**：setup "我带他出去了"→ 第一 punch "带去庆生晚餐"(reveal)，tag 再砸同一 target assumption→"杀了他父亲"。
- **结论**：同一假设、不同再解读 = 两次笑。
- **结果**：成为 tag 三类技法的范本。

### 案例 2：LPM 提升
- **问题**：为何要费心加 tag？
- **方法论的使用**：作者指出单位时间笑声数（LPM）决定素材效率；一个 setup 拿 2–3 次笑，远胜写三条独立铺垫。
- **结论**：tag 是用最低成本提 LPM。
- **结果**：成为 Ch4 打磨章的核心收口技法。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？
1. 一个 setup 抖完只笑一次，觉得"浪费"。
2. 想知道怎么在不写新铺垫的情况下多拿笑。
3. 在优化"每分钟笑声"。

### 语言信号
- "这个梗能再追一句吗 / 抖两次"
- "怎么提高 LPM / 笑声密度"
- "tag 怎么写"
- "一个 setup 多拿几次笑"

### 与相邻 skill 的区分
- 与 `reveal-at-end`：reveal 管单个 punch 内部"翻转词置末"；tag 管"在 joke 之后追加新 punch"。
- 与 `rule-of-three`：tag 是同一 joke 内的追加；rule-of-three 是列表/排比里的第三拍破模式。

## E — 可执行步骤 (Execution)

1. **确认基础 joke 已完成（setup + 1st story + punch + 2nd story）**
   - 完成标准：观众已为第一 punch 笑过。
2. **找可再破的假设（三选一）**
   - 完成标准：原 target assumption / 另一 1st-story 假设 / 2nd-story 新假设，至少命中其一。
3. **写一个 tag punch，reveal 置末**
   - 完成标准：tag 的 reveal 独立成立、不重复第一 punch 的措辞；转 `reveal-at-end` 排结构。
4. **朗读检验节奏**
   - 完成标准：第一笑与 tag 笑之间留足停顿；若 tag 拖沓→删。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 基础 joke 本身不响（先回 `joke-binary-structure` / `joke-prospector-mine` 修）。
- 段子还在选题阶段 → 用 `joke-prospector-map`。

### 作者在书中警告的失败模式
- tag 变成"重复同一句" → 不是新笑点，是啰嗦。
- 为了 tag 硬加，破坏原节奏 → 得不偿失。

### 作者的盲点 / 时代局限
- 过度 tag 在短 Club 段子里好用；在叙事长 comedy 中可能打断叙事流。

### 容易混淆的邻近方法论
- "call back"（后段回扣前文梗）是跨 joke 的呼应；tag 是同一 joke 内的追加，二者不同（见 GLOSSARY）。
