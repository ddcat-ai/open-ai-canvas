## I — 方法论骨架 (Interpretation)

Joke Mine 是"有了 setup 之后怎么长出 punch"的挖掘机，五步：
1. **选 setup，列假设**：写出观众看到 setup 后会自动跳出的所有推测（ assumptions）。
2. **选一个目标假设 + 找 connector**：挑那个你想击碎的关键假设作 target assumption；问"是什么让它做出这个假设？"答案就是 connector（那点可被多解的信息）。
3. **列再解读**：对 connector 列出多种"另类解读"（reinterpretations）——越多越好，这是 punch 的候选池。
4. **选一个再解读，编 2nd story**：把一个再解读展开成可信的"第 2 个故事"。
5. **写成 punch**：用一句话表达这个 2nd story，并把 reveal 放在末尾（见 `reveal-at-end`）。

卡住时：第 4 步换一个再解读就有了新笑话；还不灵就回第 2 步换目标假设。一个 connector 多个再解读 = 多个 punch 的矿脉。

## A1 — 书中的应用 (Past Application)

### 案例 1：从"停车被追尾"挖 punch
- **问题**：有个 setup（"我停在标志前被追尾"），但讲出来不好笑。
- **方法论的使用**：列假设（"他受伤了吗""是我走神了"）→ 选"他质问我的动机"作目标假设→ connector 是"我当时的状态"→ 再解读成"我在等律师电话才敢说"→ 编成 2nd story→ 写成 punch。
- **结论**：同一个 setup 经 Mine 后冒出可抖的包袱。
- **结果**：作者用来演示 POV 与 Mine 的协同。

### 案例 2：rear-ended 邮件笑话
- **问题**：如何展示 Mine 产出多个 punch？
- **方法论的使用**：同一 connector 列出"受伤/走神/怕律师"等多个再解读，每个都能成一条 punch 或 tag。
- **结论**：Mine 的产出端是再解读的清单，数量即弹药。
- **结果**：成为 Joke Mine 的标准示范。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？
1. 有了一个铺垫句，但想不出抖什么包袱。
2. 写出的 punch 平淡，像陈述而非反转。
3. 想知道"connector / target assumption 到底怎么找"。

### 语言信号
- "我有 setup 但想不出 punch"
- "怎么抖包袱 / 笑点怎么挖"
- "target assumption / connector 怎么定位"
- "joke mine 怎么用"

### 与相邻 skill 的区分
- 与 `joke-prospector-map`：Map 是"从话题到 setups"；Mine 是"从 setup 到 punch"。先 Map 后有 setup，再 Mine。
- 与 `joke-binary-structure`：Mine 是生产流程，binary-structure 是判断"挖出来的 punch 是否真成立"的标准。

## E — 可执行步骤 (Execution)

1. **写下一个 setup，列出观众的假设（3+ 条）**
   - 完成标准：假设是观众"会自己跳出的推测"，不是你硬塞的。
2. **选一个要击碎的目标假设，问"是什么让观众这么想？"定位 connector**
   - 完成标准：能说出 connector 是哪点信息；若找不到→换一个目标假设。
3. **对 connector 列 3+ 个再解读**
   - 完成标准：每条都是"兼容却意外"的另类解读；卡住就强行列 5 个。
4. **选一个再解读，展开成 2nd story**
   - 完成标准：2nd story 与 setup 的 1st story 意见相反且可信。
5. **写成 punch，reveal 置末**
   - 完成标准：一句话表达 2nd story；reveal 在末尾（转 `reveal-at-end`）。若 punch 仍平→回步骤 3 换再解读。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 还没有 setup、连写什么都不知道 → 用 `joke-prospector-map`。
- 笑话写好了只差台上演 → 用 `act-outs-pov` / `rehearsal-process`。

### 作者在书中警告的失败模式
- **假设列得太少**：矿脉就薄；至少列 3 条再选。
- **connector 与 setup 脱钩**：punch 和铺垫不接，观众无预期可破。

### 作者的盲点 / 时代局限
- Mine 偏向"语言/情境"喜剧；纯肢体 visual gag 难以套用这套提问法。

### 容易混淆的邻近方法论
- "随便想个反转"不是 Mine；Mine 靠"假设→目标假设→connector→再解读"的链条，是可重复的，不是灵感。
