## I — 方法论骨架 (Interpretation)

把一场演出从"能演"提升到"好秀"，靠两件事：

1. **B-C-A 排序**：用笑声强度给素材评级——A 最炸、B 次之、C 最弱（D/F 是失败料，不出场）。开场放 **B**（次强，稳住场子又不透支最强），中间放 **C**（最弱，观众已坐稳能接住），收尾放 **A**（最强，炸场离场）。这是"先稳后炸"的能量曲线。
2. **录制—评分—进化闭环**：每次演出现场录制→回放→给每个笑话评 A/B/C/D/F→删 D/F、改写 B/C、重排→再演。素材也沿 **bit → cluster → act** 生长：现场反馈让单 bit 聚成 cluster、cluster 长成 act，再反向从 act 里挖新 bit。

辅助技巧：**hammocking**（把弱/新料"挂"在已验证好笑的笑话之间，以稳托弱、降低砸场风险）、**graphing**（把笑声画成点线图，直观看起伏）。

## A1 — 书中的应用 (Past Application)

### 案例 1：B-C-A 排序
- **问题**：一场 10 分钟 open mic 怎么排？
- **方法论的使用**：作者给出经验律——次强 B 开场稳住、最弱 C 放中、最强 A 收尾；形成"先稳后炸"曲线。
- **结论**：排序本身就是表演设计。
- **结果**：成为 Ch13 演出工程的核心律。

### 案例 2：录制评分进化
- **问题**：为什么有人演了一年还在原地？
- **方法论的使用**：作者要求录制回放、按笑声评 A/B/C/D/F、删 D/F 改写重排；bit→cluster→act 反向催生新 bit。
- **结论**：没有反馈闭环就没有进化。
- **结果**：成为"好秀变伟大"的方法论收口。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？
1. 攒了几段 routine，但不知道一场演出怎么排顺序。
2. 演了很多场却感觉没进步。
3. 想安全地试新写的弱素材。

### 语言信号
- "演出怎么排序 / 开场放什么"
- "B-C-A 是什么意思"
- "怎么从演出里持续进步"
- "新段子怕砸，怎么试"

### 与相邻 skill 的区分
- 与 `routine-builder`：routine-builder 管"段子内部怎么连"；本 skill 管"整场 show 的宏观排序与进化"。
- 与 `fearless-bombing`：本 skill 是"演出工程/进化"；fearless 是"面对怯场/砸场的心理应对"。

## E — 可执行步骤 (Execution)

1. **给每个素材评 A/B/C/D/F**
   - 完成标准：以现场笑声强度为准；D/F 暂不进 show。
2. **排成 B-C-A**
   - 完成标准：B 开场、C 居中、A 收尾；若开场直接 A→浪费最强且难收尾。
3. **录制并回放评分**
   - 完成标准：每场留录音/录像，逐 joke 评级。
4. **删 D/F、改写 B/C、重排**
   - 完成标准：下一轮 show 已消化本轮反馈。
5. **(试新料)用 hammocking 挂强料间**
   - 完成标准：新弱料夹在两则已验证 A/B 之间降低砸场风险。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 单个 joke 还没写好 → 用 `joke-prospector-mine`。
- 段子内部衔接 → 用 `routine-builder`。

### 作者在书中警告的失败模式
- **完美首演后自负**（ce07）：有时首演因过度紧张 unconscious 接管异常好，比砸场更危险——让人误以为已掌握；作者：三到五年才入门。
- **有反馈不迭代**：演完不录制不评分→停滞。

### 作者的盲点 / 时代局限
- B-C-A 基于线下 club 单口场景；短视频/算法分发的"前 3 秒定生死"逻辑下，开场需更强钩子，B 开场未必适用。

### 容易混淆的邻近方法论
- "把最好的留最后"是常识；B-C-A 加上"中间放最弱"与"录制评分闭环"才是 Dean 的完整工程。
