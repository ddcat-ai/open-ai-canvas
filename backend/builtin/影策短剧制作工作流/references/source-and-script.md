# 输入与剧本

## 什么时候使用

当用户提供小说章节、故事梗概、剧本、续集材料或局部修订要求时使用。先锁定本轮范围，再决定是否需要改编。已定稿内容直接进入制作提取，不要求重写成另一种格式。

## 范围与证据

从用户消息、附件和当前画布中记录：采用章节/场次、文本版本、目标时长、画幅、语言、风格、声音和交付目标。长文本分批读取时写明已读范围、未读范围和下次起点；不得从摘要或截断内容声称读完整章。

把内容分为三类：

| 类型 | 处理方式 |
|---|---|
| 已确认事实 | 保留来源和顺序，可进入剧本与分镜 |
| 改编提案 | 明确写出变化、理由和影响，未经确认不当作事实 |
| 未知/缺口 | 保持未知，只有会阻塞本轮决策时才提问 |

## 小说转视听剧本

1. 按原文顺序提取人物、事件、地点、时段、对白、声音、物件状态和未解信息。
2. 把叙述和心理映射为可见行动、可听对白、已有旁白或必要的画内文字；不为了“更完整”编造前史。
3. 为每个事件分配稳定编号 `E01`、`E02`……，记录执行者、对象、顺序、起态和末态。
4. 若需要新增对白、删除事件、提前揭示或改变视角，单列为改编提案。
5. 复杂章节先交一份全局事件表，再按用户确认的范围写场景剧本。

推荐剧本结构：

```markdown
## 场 01｜地点｜时段

**场景目标**：本场结束时哪一件事发生变化。
**起始状态**：人物、道具、空间和已知信息。

### E01｜行动或信息
- **画面**：实际能看见的行为。
- **声音**：对白、OS、VO、环境声或动作声。
- **状态变化**：人物、道具和空间的变化。

### E02｜行动或对白
...

**结束状态**：下一场可以核实的起点。
**待确认项**：只列影响本轮制作的项目。
```

## 已定稿剧本

原稿中的场号、对白、OS/VO、人物称谓、时间码和硬约束直接保留。制作简报只补执行需要的选择，不逆向补写大纲或人物生平。原稿时长和自然对白冲突时，提出延长、拆分或调整范围的选项，不偷偷删词。

## 时间预算

分别估算：自然对白、必须串行的动作、画内文字阅读、反应停顿、转场和可并行的声音。并行动作可以重叠，不能把顺序动作压进同一时间点。记录：

- 剧情自然时长；
- 模型单次支持时长；
- 生成片段总时长；
- 最终剪辑时长。

模型能力不能证明剧情一定能容纳。分段时优先保留事件顺序、对白完整和关键反应；如果仍冲突，标记“时长约束冲突”。

## 影策画布交接

- 先用 `canvas_get_state` 确认是否已有正文、分镜和相关节点。
- 文稿成果写入 `text` 或 `markdown` 节点；创建/修改使用 `canvas_apply_ops` 的真实能力字段。
- 多镜头、需要逐镜维护的内容使用 `canvas_create_storyboard`，每行提供场景、时长、画面、对白、运动、声音和连续性字段。
- 修改时先 `canvas_read_storyboard` 获取最新 `snapshotHash` 和真实 `rowId`，再调用 `canvas_edit_storyboard`；不复制整表、不猜 ID。
- Markdown 报告是可读依据，不等于结构化分镜，也不等于视频已生成。
