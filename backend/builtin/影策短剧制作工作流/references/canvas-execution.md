# 影策画布执行

本文件只描述影策 Agent 的真实执行合同。工具参数、节点类型和字段以当前能力返回为准；技能正文不能授权未注册工具、任意 metadata、外部媒体 URL 或绕过任务/审批链路的调用。

## 真实工具

### 读取

- `canvas_get_state`：读取项目、节点、连线、快照和关联任务。
- `canvas_list_node_types`：读取可创建节点类型、连接约束和生成模式。
- `canvas_read_storyboard`：分页读取结构化分镜行，取得真实 `rowId` 和快照。
- `canvas_read_batch_table`：读取批量创作表的真实行和配置。
- `model_list`：按模式和实际参考节点查询可用模型、能力和价格。
- `task_get`：查询当前用户任务状态。
- `skill_search`、`skill_read_file`：读取已安装技能的正文和引用文件。

### 写入

- `canvas_apply_ops`：新增合法节点、更新允许字段、建立合法引用边；一次最多 20 项，必须带最新 `snapshotHash`。
- `canvas_create_character`：用已验收、已就绪的三视图图片（可加参考音频）创建角色卡，写入角色库并放置角色卡节点；不用文本节点冒充角色卡。
- `canvas_create_storyboard`：创建有真实镜头行的 `script` 节点，不用 Markdown 冒充分镜。
- `canvas_edit_storyboard`：追加、修改或删除单行；`update/remove` 必须使用最近读取的真实 `rowId` 和 `snapshotHash`。
- `canvas_edit_batch_table`：只修改批量计划，不提交生成任务。
- `canvas_arrange_nodes`：只整理坐标，不创建、删除或连线。
- `generate_media`：提交图片、视频或音频生成；先准备提示词、模型和真实引用。
- `image_annotation_render`、`image_layer_split`：仅在当前能力和用户目标确实需要时使用。
- `plan_update`、`ask_user`：更新可见计划或询问一个必须由用户决定的问题。

## 标准执行链

1. `canvas_get_state`，确认当前项目、已有内容、快照、关联任务和当前采用版本。
2. `canvas_list_node_types`，确认文本、分镜及媒体节点类型和字段。
3. 写入/复用输入文稿与剧情事实账本。剧本阶段可产出草分镜，但显式标记“草案，不可投产”。
4. 先确认共享风格基底，再建立角色、服装、场景、关键道具/武器资产台账；按 `assets.md` 生成/登记参考，回读真实资源并完成验收、确认和版本锁定。核心角色验收后用 `canvas_create_character` 建角色卡并回读引用状态（见 `character-cards.md`）。音色参考只有用户选择时才准备。
5. 检查投产门槛：必需资产均已锁定、无未解决冲突，风格基底已确认。未通过则停止于资产/草案阶段，不创建制作版分镜，不提交视频任务。
6. 通过门槛后调用 `canvas_create_storyboard` 创建制作版分镜，行内写入已确认事件、时长、场景状态、服装/道具状态、对白/声音、连续性字段和真实资产引用。
7. 创建后 `canvas_read_storyboard` 回读，核对行数、顺序、时长、资产引用及真实行 ID。修改时再次读取最新快照，再调用 `canvas_edit_storyboard`；冲突则重新读取，不覆盖用户新改内容。
8. 为每个已批准生成段准备合法媒体节点和引用边；`canvas_apply_ops` 不提交生成、不收费。检查媒体模型实际能够读取这些锁定资产。
9. 用 `model_list` 传入真实参考节点，查询模型/渠道、参考数量、时长、画幅、音频能力和价格。按实际能力选择，不猜模型名；参考超限时制定经用户确认的分批方案，不静默丢弃身份锚点。
10. 向用户说明本批次对象、数量、模型、参数、参考资产和费用范围，获得具体授权后调用 `generate_media`。提示词只使用真实 `@图片1`、`@视频1`、`@音频1` 顺序。
11. 用 `task_get` 或真实事件流核验状态；成功后确认结果资源可访问，并逐项检查剧情、角色、服饰、场景、道具和声音连续性，再回写节点/采用状态。
12. 独立节点用 `canvas_arrange_nodes` 整理，输出阶段、阻塞项、真实节点/任务和未核验范围。

草分镜不是视频生成授权，也不是资产门槛豁免。即使用户催促直接生成，仍要说明缺失资产会造成的跨镜/跨集一致性风险；只有用户明确要求带风险继续且该动作符合系统权限与平台规则时，才按明确范围执行，并将结果标记为未锁定资产条件下的试片，不得宣称可连续交付。

## 禁止事项

- 不调用没有出现在当前能力清单中的函数。
- 不直接写画布 JSON，不伪造节点 ID，不把文本内容当作已生成媒体。
- 不向生成接口传外部 URL、Cookie、密钥或未验证资源。
- 不用节点标题、文件名或 `generating` 状态宣称视频完成。
- 不覆盖已有任务或已有采用结果；重试必须是用户明确的新授权。
- 不把连线当作审批、分镜阶段或采用证明。
- 不把 `canvas_apply_ops` 当作媒体生成工具；生成统一走 `generate_media`。

## 影策后端接口边界

浏览器只通过登录态的影策后端运行 Agent：创建运行使用 `POST /api/agent/runs`，续轮使用 `POST /api/agent/runs/:id/messages`，事件使用 `GET /api/agent/runs/:id/events`，审批使用对应的 approval decision 接口。技能不直接访问模型供应商、画布数据库或第三方 API。
