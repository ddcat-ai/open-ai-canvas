# 核心角色卡资产

角色卡是核心角色在账号角色库中的正式资产，也是画布上可被分镜和生成稳定引用的角色身份。画布里的三视图、定妆图和音色说明只是候选与证据；只有打包成角色卡并通过验收，角色才算“已锁定”。

## 哪些角色必须建卡

- 主角、反派和重要配角；
- 跨两个以上场次/片段出镜，或跨集复用的角色；
- 剧情需要观众辨认身份的角色（例如回忆、伪装、相似人物对照）。

一次性路人、群演和只出现声音的模糊身份不建卡，直接在提示词或文本节点中描述，并在资产台账里记录“未建卡”及理由。

## 建卡前置条件

1. 风格基底已确认，故事圣经中该角色的身份卡已确认。
2. 三视图/转面图已生成、实际查看并验收：各视角像同一人，年龄感、脸型、发型、服装、比例与身份卡一致，无多余人物、文字或手持武器。
3. 该图片节点已保存到账号资源库且状态就绪；外部 URL、未完成任务或仅有提示词的节点不能建卡。
4. 用户启用音色资产时，参考音频已获授权、格式受支持且已就绪；未启用时角色卡不绑定声音，不影响建卡。
5. 先用 `canvas_get_state` 检查画布上是否已有同名角色卡；已有则复用并核对版本，不重复建卡。

未满足前，角色停在“待生成/待验收/待确认”，三视图和定妆图留在 `FRAME-CHAR-<id>` 背板中作为候选。

## 建卡

使用 `canvas_create_character`，参数以本轮真实 schema 为准：

- `name`：与故事圣经一致的角色称呼；服装/形态变体卡用“角色名·变体名”，避免与基础卡同名。
- `imageNodeId`：已验收的三视图节点。它会成为角色卡的三视图与主形象，后续生成默认引用它，所以不要传剧照、半身特写或未验收候选。
- `audioNodeId`：仅在用户启用音色并验收参考音频后传入。
- `definition`：只填故事圣经和已验收图片能支撑的字段，未知项留空，不补设定。

| 字段 | 来源 |
|---|---|
| `role` | 剧中身份、阵营与关系 |
| `aliases` | 原文中的别称、称号 |
| `appearance` | 年龄感、脸型、发型发色、面部识别锚点 |
| `physique` | 身高比例、体型轮廓 |
| `clothing` | 基础服装、颜色、材质、固定配饰 |
| `personality` | 影响表演的性格与神态 |
| `props` | 固定随身物（武器仍单独登记为 PROP 资产） |
| `consistencyPrompt` | 不允许漂移的锚点，写成可直接拼进提示词的短句 |
| `multiViewPrompt` | 生成该三视图所用的已锁定提示词 |
| `voiceLanguage` / `voiceAge` / `voiceTimbre` | 已确认的音色设定（启用音色时） |

建卡属于写操作，按权限审批。批准后用 `canvas_get_state` 精读该节点，确认 `character.version`、`visualStatus`、`imageReference.ready`，启用声音时确认 `audioReference.ready`；再把角色卡节点放入 `FRAME-CHAR-<id>` 背板，并在资产台账登记 `CH-xx`、角色卡节点 ID、角色资产 ID、版本号、状态和确认依据。

## 在分镜与生成中使用

- 正式分镜行的 `characterAssetIds` 指向角色卡并写明版本，例如 `CH-01@角色卡v2`。
- 生成时把角色卡节点作为参考节点传入：系统自动附带三视图参考和角色设定文字，音频生成自动使用绑定声音。不要再为同一角色另传三视图图片节点，也不要在提示词里重复粘贴整段设定，只写本镜的表情、动作和状态。
- 角色卡占用图片参考名额并计入 `@图片N` 顺序；先用 `model_list` 带上真实参考节点核对参考上限。
- 节点正文为空不代表角色卡为空，设定以 `character.definition` 为准。
- 角色卡不可读或 `imageReference.ready=false` 时，该角色视为未锁定，触发硬停止。

## 维护与版本

Agent 不能直接修改角色卡的设定、形象或声音；这些修改在角色库中完成，每次修改都会生成新版本。维护流程：

1. **发现需要维护**：剧情新增可核实的外观事实、验收时发现漂移、用户要求改设定或换音色。
2. **提出变更单**：列出角色、字段、旧值、新值、依据（事件编号或用户确认），以及受影响的分镜行和已生成片段，请用户在角色库中修改。
3. **回读核对**：修改后精读角色卡，确认版本号已递增、内容与变更单一致，并更新台账版本。
4. **影响处理**：Agent 放置的角色卡跟随角色库当前版本，之后的生成自动使用新版本；已提交的生成任务记录了当时使用的角色卡版本。按 `state-and-delivery.md` 判断哪些片段需要重做，未受影响的已采用结果继续有效，重做需要重新授权。

服装、伤态等剧情变体优先作为分镜状态和 `FRAME-CHAR` 中的变体参考图管理；只有变体长期出镜且必须单独锁定外观时，才另建“角色名·变体名”角色卡，并在台账写明适用场次范围。

## 禁止事项

- 不用 `canvas_apply_ops` 新建文本节点冒充角色卡，也不手写角色卡 metadata。
- 不用未验收图片、剧照或网络图片建卡；不为凑齐资产伪造设定。
- 不把“角色卡已创建”报告为“角色资产已全部锁定”：服装变体、武器和音色仍按各自台账验收。
- 不为已有同名角色重复建卡；已有卡不符合设定时走维护流程。
