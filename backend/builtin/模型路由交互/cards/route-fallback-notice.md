# 缺路由降级提示

## R — 原文要点 (Reading)

剧典原创综合方法（基于多个上游技能的最小提问纪律整理）：上游技能的一致纪律——信息不足时**只问影响成败的那几个问题**（能假设的先假设并继续，但声明假设）；素材缺失时不猜（没有产品图就问，不许描述替代实物）；超出能力边界时明确声明（本技能只产出剧本层不含制作衔接；只规划不调生成不花积分；provider 特定技能不把自家语法说成通用规则）。降级提示三要素：**缺什么**（具体到参数/素材/路线）、**卡在哪**（哪一步无法继续）、**下一步选项**（用户可选的 2-3 条出路，含自由文本出口）。

## I — 方法论骨架 (Interpretation)

1. **静默失败是红线**：匹配不到路线时不给假结果、不换路线瞎跑——用户以为成了其实偏了，比明说做不了更糟。
2. **缺什么要具体**：不说「信息不足」，说「缺一张产品图」或「缺生成时长（影响分镜结构）」。
3. **假设要声明**：可假设的假设并继续，输出中标注「补充默认」。
4. **出路给选项**：至少给两条可执行出路+自由文本出口（配合 options-presentation）。
5. **边界即信任**：明确声明「这个我做不了」的地方，正是用户信任「这个我能做」的地方。

## A1 — 应用案例 (Past Application)

- 场景：用户要「用 ComfyUI 出图」→ 本生态无 ComfyUI 执行桥 → 降级提示：缺本地 ComfyUI 服务与工作流文件；出路：a) 走已接的生图渠道（Seedream/Ddcat）b) 提供 ComfyUI API 地址评估接入 c) 只要提示词自己本地跑。
- 场景：用户要 3D 模型 → 无对应技能 → 提示缺 3D 生成路线，给出替代（先出多视图图集再外挂 3D 工具）。

## A2 — 触发场景 (Future Trigger)

- 技能路由 top_k 全部低分或不相关时。
- 用户请求涉及未接入的模型/平台/工具时。
- 关键参数缺失且无法假设时。

## E — 可执行步骤 (Execution)

1. **判无路由**：确认候选路线全不匹配（非低分误判）。
   *完成标准*：路由判定有记录。
2. **定位缺口**：写清缺什么（素材/参数/路线）。
   *完成标准*：缺口具体到项。
3. **声明假设**：能假设的假设并标注，不能假设的进缺口。
   *完成标准*：假设项全部显式标注。
4. **给出路**：2-3 条可选下一步+自由文本出口。
   *完成标准*：出路可执行且含退出项。
5. **不静默**：任何降级都有明示，无假结果。
   *完成标准*：输出含降级说明。
