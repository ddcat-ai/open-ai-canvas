## I — 方法论骨架 (Interpretation)

布洛克把"边框/画幅"从纯技术参数提升成**构图控制手段**：边框的物理比例（宽:高）直接决定屏幕能装下多少空间信息、承载多少情绪容量。

- **不能硬搬**：横屏构图逻辑（左右平衡、横向透视）直接套进会信息混乱、主体被裁、纵深错觉失效——这是 ce18 警示的核心。
- 落到：上下分屏可同时呈现"手机界面 + 子女反应"制造代际同框反差；纵向可用服装条纹、家具边线低成本搭线性主题；窄框下更靠影调/色彩分离定焦点（见 vis-space-four-types 的 g40）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 作者定义画幅宽高比即空间容量
- **问题**: 学生把画幅当不可控技术参数，不意识到它限制构图。
- **方法论的使用**: 用"宽÷高"定义画幅，指出它决定图像平面能容纳的空间信息与情绪容量。
- **结论**: 画幅是主动的构图控制手段，不是出厂设定。
- **结果**: 成为第三章空间体系的组成部分，与四种空间谱系并列。

### 案例 2: 画幅随意导致空间容量失控（ce18 边界）
- **问题**: 把画幅当纯参数随便选，不意识到它决定容量与情绪。
- **方法论的使用**: 警示"随意选画幅"会让空间信息失控、情绪错位。
- **结论**: 选画幅前要先想"这框要装多少、装什么"。
- **结果**: 支撑"不能套横屏构图"的下游适配原则。

### 与相邻 skill 的区分

- 与 `vis-space-four-types` 的区别: 本 skill 管"边框宽高比决定的空间容量"（能装多少），`vis-space-four-types` 管"空间类型选型"（纵深/平面/有限/模糊）。先定画幅容量，再在框内选空间类型。
- 与 `vis-contrast-affinity` 的区别: 强度轴管强弱，本 skill 管框的物理比例与分割。
- 与 `vis-seven-elements` 的区别: 七元素是总清单，本 skill 是空间元素下"边框"这一具体抓手。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定画幅与纵向分割方案**

2. **核对容量与主体不被裁**
   - 完成标准: 确认关键主体（表情/包袱）在窄框内完整可见、焦点清晰；若横屏构图硬搬导致裁切，给出重构图（用影调/色彩分离定焦点，呼应 vis-space-four-types 的 g40）。
   - 判停条件: 若发现主体被框裁掉或信息超载（横向过窄塞太多），回到步骤 1 重排纵向分割。

3. **设计上下分屏反差（如适用）**
   - 完成标准: 若用分屏，输出"上屏内容+下屏内容+反差意图"（如手机蓝屏 vs 子女皱眉），并确认两屏情绪靠对比/相似轴协调（呼应 vis-contrast-affinity）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只问空间类型选型（纵深/平面/有限/模糊）→ 转 `vis-space-four-types`。
- 只问强度总开关（强/弱）→ 转 `vis-contrast-affinity`。
- 只问七元素总清单 → 转 `vis-seven-elements`。

### 作者在书中警告的失败模式

- **ce18（画幅随意/空间容量失控）**: 把画幅当纯参数随便选，不意识到它决定容量与情绪，导致信息混乱。尤甚——横向窄，硬搬横屏构图必乱。
- **横屏构图硬搬**: 左右平衡、横向透视逻辑直接套会裁主体、毁纵深错觉。

### 作者的盲点 / 时代局限
### 容易混淆的邻近方法论

- `vis-space-four-types`（易混：都涉及"空间"，但本 skill 是边框容量、那是类型选型）。
- `vis-line-shape`（易混：可用服装/家具边线搭线性主题，但那是线形情绪，不是画幅）。
