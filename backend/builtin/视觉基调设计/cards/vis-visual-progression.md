## I — 方法论骨架 (Interpretation)

布洛克给了一条把"强度"变成"可设计曲线"的法则：**让画面的复杂度随时间一步步涨上去，强度就跟着涨。**

- **四个台阶**：一个点（孤立元素）→ 一条线（元素连成序列）→ 一个面（铺开成块/群）→ 一个体（立体、纵深、满屏混战）。每上一层，画面里的视觉信息量、运动密度、元素关系都变多。
- **核心等式**：复杂度 ↑ = 视觉强度 ↑。这其实是"对比相似"原理的时间版——越往后元素越不一样、越满、越动，对比越堆越厚。
- **为什么好用**：它把"这集够不够炸"翻译成"我让复杂度爬了几级"，可数、可对齐到叙事。不用靠感觉喊"再加点戏"。
- 落到：单集用"简单→复杂"进阶把平淡日常推向反套路高潮——如从安静客厅（点：一人特写）一路进阶到超市抢购/全小区闹剧（体：满屏人动物交错）。视觉强度曲线即叙事密度曲线，也能用"人数/道具量/运动密度"低成本实现升级。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《愤怒的公牛》每场拳赛都是进阶一环（c01 标准示范）
- **问题**: 作者要示范"复杂度递增=强度递增"如何表现打斗激烈程度。
- **方法论的使用**: 每个拳击场景建立在情节、声音和视觉密度之上，逐场进阶——从零星交手到满屏混战，复杂度层层加码。
- **结论**: 视觉进阶能精确控制"这场比那场更烈"的强度感，是 fw04 的教科书案例。
- **结果**: 提供可类比锚点——证明"从点到体"能迁移到任意"升级"场景。

### 案例 2: 作者用"点→线→面→体"定义视觉进阶本身
- **问题**: 需要一条统一法则描述所有元素的"变复杂"。
- **方法论的使用**: 把任一元素的演化抽象成四台阶（孤立→连缀→铺开→立体）。
- **结论**: 七元素每个都能各自走完四台阶，整体复杂度即各元素台阶之和。
- **结果**: 成为"强度曲线"的构造骨架，与对比相似原理互通。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 单集想从"安静日常"一路推到"反套路爆发/混战"，需要强度升级设计。
2. 觉得某集"平、没爬升、高潮不够爽"，要诊断复杂度有没有递进。
3. 想用"拳赛越打越烈"的类比给群像戏做升级（如麻将局→全小区闹剧）。
4. 低成本想靠"人数/道具/运动密度"实现视觉升级而不靠大调度。

### 语言信号 (用户的话里出现这些就应激活)

- "这集怎么从平淡推到高潮，视觉上越来越炸"
- "单集强度曲线怎么设计，简单到复杂"
- "像愤怒的公牛那样拳赛越打越烈，戏怎么升级"
- "视觉进阶、点线面体、复杂度递增、intensity curve"
- "这集高潮不够爽，是不是复杂度没爬上去"

### 与相邻 skill 的区分

- 与 `vis-contrast-affinity` 的区别: 对比相似管"每一刻强还是弱"；本 skill 管"强度如何随时间从弱爬到强"（复杂度递增维度）。
- 与 `vis-rhythm-design` 的区别: 节奏管快慢拍（时间间隔），本 skill 管复杂度台阶（信息量密度），二者常叠加但不同轴。
- 与 `vis-story-visual-map` 的区别: 故事映射管"四段（开冲突高结）对齐"，本 skill 管"复杂度递增"这一具体手法，可嵌入映射的高潮段。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **标出本集复杂度四台阶的落点**
   - 完成标准: 把单集时间轴分成"点→线→面→体"至少 3 个可识别台阶，并写明每阶增加了什么（如"点=独坐；面=老姐妹围坐；体=全小区抢购"）。

2. **对齐复杂度台阶与叙事密度**
   - 完成标准: 确认每上一阶，叙事事件（冲突/笑点）也同步加码，视觉升级不空转；至少 1 处视觉升级对应明确情节转折。
   - 判停条件: 若发现"视觉满但叙事空"或"叙事炸但视觉平"（台阶错位），回到步骤 1 重排台阶与情节对应。

3. **给出低成本的升级杠杆**
   - 完成标准: 列出本集可加的低成本复杂度源（人数增加、道具堆积、运动密度、画中画分割），标注至少 2 个不依赖大调度即可实现的升级点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只问"这一刻强还是弱"的总开关 → 转 `vis-contrast-affinity`。
- 只问单集各元素静态清单 → 转 `vis-seven-elements`。
- 只问"故事四段怎么映射视觉" → 转 `vis-story-visual-map`。
- 只问节奏快慢拍本身 → 转 `vis-rhythm-design`。

### 作者在书中警告的失败模式

- **复杂度空转（进阶错位）**: 视觉越堆越满但叙事没跟上，或反之——进阶必须绑定情节密度，否则只是"热闹"而非"强度"。
- **误把"多"当"强"**: 复杂度递增靠的是对比/差异堆叠（见 vis-contrast-affinity），单纯加相同元素（全相似）不会升级，会变成 ce02 式催眠。

### 作者的盲点 / 时代局限
### 容易混淆的邻近方法论

- `vis-contrast-affinity`（易混：进阶本质是对比随时间堆叠，但本 skill 专讲"时间维的复杂度递增"）。
- `vis-rhythm-design`（易混：都让画面"动起来"，但节奏是拍子、进阶是密度台阶）。

## 相关 skills (阶段 3 填充)

### depends-on（使用前需先理解）
- `vis-seven-elements`：进阶把"复杂度"加到七个元素上，须先认得这七元素。

### contrasts-with（易混淆，注意区分）
- `vis-rhythm-design`：本 skill 管"复杂度随时间的台阶（信息量密度）"，节奏管"动的间隔/重复/快慢"。二者常叠加但不同轴。

### composes-with（常配合使用）
- `vis-contrast-affinity`：进阶本质是"对比随时间堆叠"，复杂度台阶靠对比/差异累加，强度轴驱动复杂度。
- `vis-story-visual-map`：把进阶嵌入故事四段的高潮段。
