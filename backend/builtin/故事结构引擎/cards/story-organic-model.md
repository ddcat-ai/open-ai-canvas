## I — 方法论骨架 (Interpretation)

把故事看作会成长的生命体，而不是可随意组装的机器。它由多个相互联结、相互界定的子系统构成——主题、角色、揭露、结构、世界、象征、场景、对白——任何元素都不能单独成立，主角也不例外。

因此创作程序必须"由内而外"：先定最深层的意念（前提与设计原则），再逐层长出角色、主题、结构、世界、场景、对白。这是对"表象的、机械的、零碎的、普通的"创作程序的替代方案。

写作过程中要时刻追问"这一层如何呼应其他层"：角色是否由结构承载、主题是否由对决与揭露传递、场景是否服务整体。

最高审美判据是"技巧消失于无形"：观众只觉得角色自发行动、故事自己长出来，看不到轮子和齿轮。凡结构外露、看起来像硬套上去的，即是失败信号。

两条支撑原则：一是"写什么>怎么写"——地基有缺陷，地面上再下功夫也无用；二是"写能改变你人生的东西"——故事的独特性与感染力，来自作者与意念的深度关联。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《教父》七大步骤拆解（第3章）
- **问题**: 如何证明"七大关键步骤"不是外贴的公式，而是有机生长在故事里的骨架？
- **方法论的使用**: 特鲁比用有机体观拆《教父》，逐个找出弱点/需求、欲望、对手、计划、对决、真实自我揭露（由凯伊代受）、新的平衡点，展示这些步骤在表象之下以有机方式环环相扣。
- **结论**: 同一个拆解模板同时适用于《教父》这种复杂长故事与《窈窕淑男》这种精巧喜剧——子系统的联结方式相同。
- **结果**: 读者可借这套骨架回头拆自己的故事，验证各子系统是否互相呼应。

### 案例 2: 《教父》早稿 vs 定稿的场景编排（第9章，作者亲自改写案例）
- **问题**: 早稿把西西里线整段堆在前面，故事"猛然陷入停顿"，婚姻线突兀难信。
- **方法论的使用**: 用整体观诊断——问题不在局部文字，而在场景这个子系统没有服务主角发展；于是按结构逻辑把桑尼线与西西里线交叉剪辑，让两线会合于"看似落败"。
- **结论**: 只动一个子系统（场景编排），整体质量大幅提升。
- **结果**: 作者称这次修改克服了"场景编排隐含的致命失误"，证明"子系统服务于整体"的诊断价值。

### 案例 3: 《摩西五经》四段推演（第2/5/6/7章）
- **问题**: 一个故事的诸多子系统从哪里来？
- **方法论的使用**: 从同一个设计原则（不知身份者追寻自由并接受新律令）依次长出主题要旨、故事世界（奴役城市→旷野→山顶）、象征概述（着火灌木丛、瘟疫、十诫石板）。
- **结论**: 所有子系统都从同一颗种子生长、互相派生，而不是各写各的。
- **结果**: 成为"由内而外"程序的完整示范——一个案例贯穿四章。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 正要开始一个新故事，问"该先写什么、从哪儿下手"。
2. 已完成初稿或大纲，觉得"故事是拼凑的、机械的、散架的"，想找整体性问题。
3. 在"先定主题还是先想角色""先结构还是先对白"之类的顺序上纠结。
4. 手握一个绝妙的写法技巧，却怀疑"故事本身值不值得写"。

### 语言信号 (用户的话里出现这些就应激活)

- "我该先写什么？" / "what should I write first?"
- "我的故事很机械，像零件拼出来的" / "my story feels mechanical"
- "有没有一个写故事的整体流程？" / "a whole workflow for writing?"
- "写什么和怎么写哪个更重要？" / "what vs how?"
- "故事像活的，还是一堆零件？" / "story as organism"

### 与相邻 skill 的区分

- 与 `story-premise` 的区别: organic-model 管"为什么先写前提、整体顺序怎么走"的世界观与总流程；premise 管"如何把前提本身发展好"。用户已有具体点子要检验时走 premise。
- 与 `story-seven-key-steps` 的区别: organic-model 是总流程与整体观；seven-key-steps 是骨架的具体内容（弱点→欲望→对手→计划→对决→自我揭露→新平衡）。用户要搭骨架时走 seven-key-steps。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先定内核（写什么）**: 把故事意念压成一句话前提，并追问"它为什么对我重要"。
   - 完成标准: 能写出一个句子（含事件+主角感受+结局含义），并说清自己为何非写它不可。
   - 判停条件: 若用户已有确定前提且只想搭骨架，直接移交 story-seven-key-steps。

2. **按由内而外顺序逐层建构**: 前提→角色→主题→结构→场景→对白；每完成一层，写一句"它如何服务上一层/与其他层呼应"。
   - 完成标准: 每一层都有呼应说明，不存在孤立的装饰性元素。

3. **有机体诊断（整体检验）**: 遍历子系统（主题/角色/揭露/结构/世界/象征/场景/对白），逐项问"删掉它故事是否受损""它与别的子系统如何互相界定"。
   - 完成标准: 能指出至少一个"看似必要实则孤立"的元素并决定删改。
   - 判停条件: 若各子系统互相呼应、无外露的机械痕迹，即可收尾，不再加新元素。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 前提已定、只想要主角与对手的骨架 → story-seven-key-steps。
- 只改一个场景、一段对白的具体执行 → 场景建构/对白类 skill。
- 纯灵感记录、无结构意图的自由头脑风暴（无需按流水线强制）。
- 直觉型/边写边想（pantser）作者若抗拒前置设计 → 建议降级为"事后诊断"，不要强行套流程。

### 作者在书中警告的失败模式

- ce20 用三幕式硬套: "幕的切分发生在故事的表象……机械的故事观，势必会让故事变成松散的片段"（第1章）。
- ce27 按时间顺序编排场景: 写出"堆砌而成的故事，其中包含许多无用的场景"（第9章）。
- ce12 复制某部电影的意念: "似乎有商业潜力，却看不出作者的任何个人特质……注定失败"（第2章）。

### 作者的盲点 / 时代局限

- 全部方法论默认"单主角+因果链条+个人转变"的好莱坞线性情节剧；对亚洲家族史诗、群像纪实、散点叙事缺乏供应。
- "先设计好一切再动笔"的建构主义预设，对直觉型作者缺乏同等辩护。
- 对意识流、氛围叙事、留白美学等实验叙事只能作为反例提及，没有等效的正向方法论。

### 容易混淆的邻近方法论

- 麦基/斯奈德的三幕式节拍表: 按页数与时间机械切分；本 skill 以结构步骤与子系统呼应组织故事。
- "角色驱动 vs 情节驱动"之争: 本 skill 视之为伪二分——有机体要求两者互相界定，而非二选一。
