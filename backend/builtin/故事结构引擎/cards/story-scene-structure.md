## I — 方法论骨架 (Interpretation)

场景编排是动笔前的最后一道全局工序：把每个场景压成一句话清单，并给每个场景标注它所承载的结构步骤标签（欲望、计划、看似落败……）。随后用四类操作收拢全局：

1. **重新安排顺序**：依据结构逻辑而非时间先后——"接下来发生什么"是最省力的直觉，但也最容易写出堆砌的故事。
2. **合并场景**：每个场景基本只完成一个行动。
3. **删减 / 增补**：场景若不能促成主角的进一步发展，就删掉；减重后补断层。
4. **检查并列关系**：两个并列场景的关系可能比单个场景更重要（对比内容、比例与步调；视觉与声音并列可造出第三种意义）；多线式情节靠交叉剪辑制造密度。

场景本身是微型故事，呈**倒三角形**：开头为整个场景确立框架，中间具有"漏斗效应"让一切汇聚于一点，最重要的字词或对白落在**结尾的顶点**。建构一个场景要回答五问：在角色转变弧线中的位置？要解决的难题？策略？谁驱动场景、想要什么（欲望）？欲望的终点在哪（=顶点）？

场景与场景构成**因果链**：每个场景是前一个场景的结果、又是后一个场景的原因；删除任一场景都应能看出剧情的断裂。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《教父》早稿 vs 定稿——场景编排改变故事命运
- **问题**: 特鲁比亲自对比《教父》早稿与定稿的编排：早稿把桑尼之死与巴兹尼揭露放在前面，随后转入漫长平缓的西西里线，故事"猛然陷入停顿"，阿波罗妮亚的婚姻突兀难信。
- **方法论的使用**: 定稿把桑尼线与西西里线**交叉剪辑**，两线会合于麦克的"看似落败"（桑尼遇害后妻子几乎同时丧生），之后才揭示巴兹尼为幕后黑手。
- **结论**: 适当的场景并列（甚至整个序列的并列）能大大提升故事品质；编排应依结构而非时间顺序。
- **结果**: 作者明确写"作者克服了场景编排隐含的致命失误"，这是全书唯一的"同一故事两种编排"直接对照。

### 案例 2: 《急诊室的故事》——多线式情节的场景编排
- **问题**: 一集五条情节线，如何编排才不乱、才有戏剧密度？
- **方法论的使用**: 五条线（躁郁母亲来访、医生遭起诉、本顿侄儿被杀案、葛林脑瘤、卡特的药物测试）表面各异，深层全是"说谎/说真话"同一难题的变奏，并如漏斗会合于各线的揭露点；每条线至少涵盖七大关键步骤。
- **结论**: 多线式编排中，故事整体质量取决于情节线的**并列关系**（共同主题变奏 + 会合点）。
- **结果**: 作为"多线式场景编排"的范例；五条线靠交叉剪辑创造戏剧密度。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户说"场景顺序总觉得不对"、"写了二十个场景不知道哪个先写哪个后写"。
2. 用户写完的单个场景"平平的、没重点"，想把关键信息/对白推到结尾顶点。
3. 用户在做多线叙事，问"几条线怎么穿插、什么时候切"（交叉剪辑 / 并列）。
4. 用户不确定"某个场景要不要删"，需要"是否促成主角发展"的判据。
5. 用户在做写作前的大纲，想先列场景清单再动笔。

### 语言信号 (用户的话里出现这些就应激活)

- "场景顺序""分场""编排" / "scene order" "reorder scenes" "sequence"
- "倒三角""关键句放哪""重心" / "inverted triangle" "punchline" "climax of the scene"
- "交叉剪辑""多线穿插""并行场景" / "cross-cutting" "parallel scenes" "intercut"
- "这个场景该删吗""场景太水" / "should I cut this scene"
- "先列场景清单""分场大纲" / "scene list" "scene breakdown" "outline"

### 与相邻 skill 的区分

- 与 `story-plot-22-steps` 的区别: 22步是把**整体情节**的信息/冲突按步骤排列；本 skill 是在情节确定之后，把每一个**场景**落实成清单并检查其内部结构——22步决定"有什么"，本 skill 决定"怎么排、每场怎么写"。
- 与 `story-seven-key-steps` 的区别: 七大步骤是整条故事弧的DNA；本 skill 以"场景"为单位，关注场景内部（倒三角）与场景之间（因果链/并列）的局部结构。
- 与 `story-dialogue-three-tracks` 的区别: 对白三音轨解决"一场戏里的台词怎么写"；本 skill 的倒三角顶点是"把最好的字词留到结尾"的**位置决策**，两者可以配合使用。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **建立场景清单**
   - 把故事现有的全部场景（或与用户讨论出的场景）逐条压成一句话描述，并给每个场景标注结构步骤标签（欲望/计划/看似落败/对决……）；多线故事标注情节线编号。
   - 完成标准: 一份编号的场景清单，每条 = 一句话 + 结构标签 + 所属情节线；若用户只有梗概，先补出缺失场景再标注。

2. **按结构逻辑重排、合并、增删**
   - 以"是否促成主角进一步发展"为唯一判据逐场景裁决；重新安排顺序（考虑并列场景的对比内容、比例步调，多线则考虑交叉剪辑点），合并完成同一行动的多余场景，减重后补断层。
   - 完成标准: 输出重排后的新清单，并注明每一处"为什么前移/后移/合并/删除"；能画出删除任一场景后剧情在哪断裂。
   - 判停条件: 若用户只想处理**单个**场景的内部写法而非全局编排，则跳过本步，直接进入步骤3对该场景做倒三角检查。

3. **逐场景做倒三角形检查（五问）**
   - 对每个关键场景回答：在转变弧线中的位置？难题？策略？欲望（谁驱动、想要什么）？终点（顶点=最关键的字词/对白落点）？
   - 完成标准: 每个关键场景都标出顶点字词/对白及其所在结尾位置；若顶点落在场景中段或开头，给出前移/重构建议，并确认场景间因果链成立。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户在打磨对白文风、潜台词本身（不涉及场景的位置与形状）——交给对白三音轨。
- 用户还在整体情节层面（信息如何保留/提供、步骤序列）——先走 `story-plot-22-steps`。
- 目标叙事是碎片化、反因果、氛围流——"每个场景必须促成主角发展"的判据会破坏这类作品，不要强行套用。

### 作者在书中警告的失败模式

- 按时间顺序而非结构顺序编排场景 → "大部分作者选择下一个场景时，主要根据时间轴的下一个行动下决定。这样一来，就会写出一个堆砌而成的故事，其中包含许多无用的场景。"（第9章）《教父》早稿即实例。
- 驱动力阶段重复相同的情节节拍 → "这里虽说有四个不同的行动，但它们都是相同的情节节拍。这就是重复，不是发展。"（第8章）

### 作者的盲点 / 时代局限

- **好莱坞情节剧框架**：场景=微型故事的假设依赖因果链与个人转变；对以氛围、意象、静默为主的场景缺乏正向方法论。
- 场景编排预设"先设计好一切再动笔"；对 pantser（边写边想）型作者，流程化的场景清单可能造成压力而非助力。
- "场景=一个时间一个地点的一项行动"的定义偏旧，对互动叙事、游戏叙事、流媒体碎片化观剧场景未覆盖。

### 容易混淆的邻近方法论

- **分场大纲 / 分场纲要**：一般人把它当"记流水账"，本 skill 强调它必须带**结构标签**并接受"删场景"裁决。
- **三幕式切幕**：按页码切幕是机械外壳（作者批判对象）；场景编排按结构步骤切，两者判断依据完全不同。
- **节拍表 (beat sheet)**：节拍是时间轴上的情绪点；场景倒三角是"一场戏内部的汇聚结构"，粒度不同。
