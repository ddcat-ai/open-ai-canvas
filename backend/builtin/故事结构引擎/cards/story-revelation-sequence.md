## I — 方法论骨架 (Interpretation)

情节的质量取决于"何时、向谁、透露多少信息"。把故事里每一次角色或观众获知新信息的时刻单独抽出来，当作一条序列来检查，就是揭露序列。三要素：

1. **合乎逻辑**：揭露出现的顺序，应是主角最可能体会到这一信息的顺序，而不是作者方便交代的顺序。
2. **一个比一个强烈**：每则新信息都要比上一则更重要、更爆炸；否则情节停滞甚至倒退。
3. **步调加快**：越到后面揭露越密集；最高形式是"逆转"——把观众对整个故事的理解全部倒转。

"幽灵"是特鲁比用来取代"背景故事"的概念：故事开始前发生、至今仍缠着主角的事件，是主角弱点的来源。它的功能是**反欲望**——欲望把主角往前推，幽灵把他往后拉。幽灵应在故事前三分之一由他人点明，开场不能把信息一次倒完。

"真实自我揭露"是对主角自身的终极揭露，必须：突然发生、为主角带来新信息（他头一回发现自己一直在自欺）、随即用新的道德行动来证明、并且**不由主角自己说出来**（可由他人代受，如《教父》中凯伊看见麦克的堕落）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《异形》——揭露序列作为情节引擎
- **问题**: 恐怖片依赖一步步发现，但如果揭露乱排，观众很快就不害怕了。
- **方法论的使用**: 特鲁比把《异形》的揭露拆成序列：船员察觉异形在通风井移动 → "母亲"电脑显示公司可牺牲船员 → 艾许是机器人 → 异形是"完美的杀人机器" → 异形挡在航天飞机前 → 最后发现异形躲在航天飞机里。每个揭露带动角色做抉择、改变欲望与动机。
- **结论**: 揭露的顺序=主角最可能体会到的顺序；越往后越致命（逃进的空间恰是最致命处）。
- **结果**: 该序列成为"揭露序列的建构（逻辑、强度递增、步调加快）"的教科书范例。

### 案例 2: 《第六感》——逆转式揭露
- **问题**: 想制造让观众走出影院仍在回味的结尾。
- **方法论的使用**: 结尾的逆转式揭露让观众发现主角其实早已死亡；观众不得不回到开头"重洗同一叠扑克牌"。
- **结论**: 逆转是揭露序列的最高形式，但代价是它"只能为观众带来一次循环"——是最有限制的永不完结手法。
- **结果**: 用作"重洗扑克牌"的正例，同时在"永不完结的故事"一章被当作局限性反例。

### 案例 3: 《唐人街》——负向的真实自我揭露
- **问题**: 真实自我揭露不一定是正面成长，主角也可能向下沉沦。
- **方法论的使用**: 伊芙琳死后，杰克喃喃自语"愈少愈好"——他相信自己的人生无用且具毁灭性，因为他再次伤害了自己爱的人。
- **结论**: 揭露的方向由主角的欲望与选择决定，负向揭露同样有力。
- **结果**: 作为"负向真实自我揭露"的典型例证被反复引用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户说"结尾反转太突兀 / 读者觉得是硬凑的"，想检查或重排信息释放的节奏。
2. 用户想给主角设计"过去的创伤 / 罪责"（幽灵），但不确定何时揭开、由谁说破。
3. 用户写到了主角的"醒悟 / 转变"时刻，担心变成说教或空泛的宣言。
4. 用户觉得情节"平淡、停滞"，想用揭露序列排查哪些信息泄早了、哪些没接上。
5. 用户想做一次"逆转"式结尾（如"原来 TA 早已……"），想评估可行性。

### 语言信号 (用户的话里出现这些就应激活)

- "反转太突兀" / "结尾 twist 太硬"
- "揭露""揭晓""揭秘" / "reveal" "revelation"
- "主角的过去""幽灵""心结""创伤" / "backstory" "ghost" "trauma"
- "自我揭露""醒悟""顿悟""主角明白了" / "self-revelation" "epiphany"
- "信息什么时候给""秘密何时揭穿" / "when to reveal" "keep the secret"

### 与相邻 skill 的区分

- 与 `story-plot-22-steps` 的区别: 22步是情节的**完整地图**（幽灵、触发事件、三次揭露、看似落败、闸门等全序列）；本 skill 只聚焦"揭露"这一类信息事件的质量与编排，是22步中可独立抽出的子系统。
- 与 `story-seven-key-steps` 的区别: 七大步骤里的"真实自我揭露"只是七步之一；本 skill 把揭露放大成贯穿全故事的一条序列来管理，并补充"幽灵"这一22步专属概念。
- 与 `story-endings` 的区别: 结尾的"逆转揭露"也可由本 skill 管理，但本 skill 的重心是**过程**（信息怎么一步步给），ending skill 的重心是**结局形态**（故事结束后的生长）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列清所有揭露点**
   - 通读目标故事（或与用户对谈收集），列出每一个"角色或观众获知新信息"的时刻：编号、内容、由谁获知（主角/观众/他人）、出现在故事哪个位置。
   - 完成标准: 生成一份完整的揭露清单，且每一条都写清了"新信息是什么 + 谁知道了 + 大致位置"；若用户只提供梗概，则以梗概能确定的为准并注明缺项。

2. **按三要素检查序列，并给出调整建议**
   - 检查①顺序是否合乎主角最可能的体会顺序；②强度是否一个比一个强；③步调是否越来越快。逐条给出"保留/前移/后移/加强/删减"结论。
   - 完成标准: 对每项揭露给出明确的调整判断，画出排序后的新序列；指出序列里最大的"泄气点"（哪一条破坏了递增）。
   - 判停条件: 若用户的目标只是"评估某一次反转是否可行"而非全局调整，则完成步骤1+对该反转的三要素定位后即可停下，不必重排全部序列。

3. **核对幽灵与最终真实自我揭露**
   - 确认幽灵事件明确、构成反欲望、在故事前1/3由他人点明、开场没有信息过载。
   - 确认最终揭露满足四规则：突然、带新信息、以行动证明、非主角说出（或由他人代受）；并提示逆转式揭露的使用代价。
   - 完成标准: 输出一份"揭露序列调整报告"，含幽灵设计要点与最终揭露的四规则自查；若用户要求，同步给出修改后的场景/段落建议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户在打磨对白文风、描写、语言节奏本身（不涉及信息何时揭晓）——那是对白三音轨等执行层 skill 的领域。
- 用户在从零搭建完整情节（22步全流程）——先走 `story-plot-22-steps`，本 skill 可作为其中"揭露"子步骤被调用。
- 目标叙事是氛围流、意识流、留白美学（如契诃夫式"无人改变"）——揭露序列以因果链与信息差为硬核，强行套用会破坏这类叙事。

### 作者在书中警告的失败模式

- 揭露没有一个比一个强、步调没有加快 → "如果你打造揭露时没有逐步增加强度，情节就会停滞，甚或倒退。这是致命伤，必须不惜一切代价避免。"（第8章）
- 开场说明过多、第一页就把幽灵的来龙去脉讲完 → "这一大堆信息其实会将观众推离故事。"（第8章）
- 让主角站出来用对白说出自己的体悟 → "不要让主角站出来说明他学到了什么。这么做太刻意、太说教。"（第3章）

### 作者的盲点 / 时代局限

- 全书方法以**好莱坞情节剧**为样板：揭露序列预设"因果链 + 个人转变 + 秘密可解"，对非秘密驱动的叙事（群像、散点、反讽性静止）供应不足。
- 22步整体有"先设计好一切再动笔"的建构主义偏向，对直觉型、边写边想型作者如何安排揭露缺乏同等辩护。
- 揭露=信息差的范式对后网络时代叙事（互动、游戏、社交）没有覆盖；"观众被逐步喂信息"的前提在这些媒介中会失效。

### 容易混淆的邻近方法论

- **"反转/意外" (plot twist)**：一次性的惊讶≠揭露序列。揭露强调"合乎逻辑、整体递增"，单点反转若不接入序列，就会陷入"情节停滞"的失败模式。
- **伏笔 (foreshadowing)**：伏笔是埋设暗示，揭露是兑现信息；本 skill 只管"兑现"这一侧。
- **背景故事 (back story)**：特鲁比明确说"背景故事"太宽泛，幽灵特指"仍缠着主角、构成弱点来源"的那一类事件。
