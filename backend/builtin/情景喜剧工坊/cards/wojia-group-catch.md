## I — 方法论骨架 (Interpretation)

1. 标准结构：私下共识 → 权威突现 → 立场翻转。
2. 笑点不落在被抓的人，落在旁观者"改口的速度梯度"上——谁最先翻谁最可笑。
3. 至少 3 名旁观者才能拉出梯度；2 人只有尴尬无笑点。
4. 翻转必须齐整到近乎排练过才好笑，但齐整过头即破产（窄窗口）。
5. 线上等价物：错发消息、麦没静音、屏幕共享忘关——"私下共识可见性突然翻转"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 标准型（第1集）
- **问题**: 如何制造集体爆点。
- **方法论的使用**: 背后议论傅老 → 傅老突现 → 志新小凡秒改口。
- **结论**: 改口速度梯度即笑点。
- **结果**: 经典群口抓包成立。

### 案例 2: 事实戳破变体（第22集）
- **问题**: 突现者不靠身份靠什么。
- **方法论的使用**: 全家脑补"琼瑶式小蜜" → 傅老抛真实年代（1943、1944）戳破。
- **结论**: 突现者可带"事实"而非身份。
- **结果**: 变体成立，笑点仍在改口梯度。

### 用户会在什么情境下需要这个 skill?

1. 写群像／会议场景，想制造"背后说人被听到"的爆点。
2. 线上办公（群聊、视频会）复刻抓包结构。
3. 设计多人反转桥段。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **安排 ≥3 名旁观者形成私下共识**
   - 完成标准：共识在当事人不知情下建立（背后议论／群聊接龙）。

2. **让当事人／权威"突现"翻转共识可见性**
   - 完成标准：共识暴露的瞬间清晰可指（现身、发错消息、共享忘关）。

3. **写出由快到慢的改口梯度并保持齐整窄窗口**
   - 完成标准：能排出"谁先翻谁后翻"的顺序，且不过度机械。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 仅有 2 名角色：拉不出改口梯度，只剩尴尬。
- 无"私下共识"前提：突现无对照，不成抓包。

### 作者在书中警告的失败模式

- ce05 机械复用节拍可预测：每次抓包都同节拍，观众预判则破产。
- ce08 冗长铺垫：为翻转堆砌过多前戏拖垮节奏。
- ce01 硬挠笑点：为搞笑强行让角色夸张改口，不自然则死。

### 作者的盲点 / 时代局限

- 抓包高度依赖表演节奏与现场反应，纯台词折损，不可当配方抄。
- 部分时代梗（如"琼瑶式小蜜"）需当代转译。

### 容易混淆的邻近方法论

- 与"尴尬被发现"混淆：常识只到"被听到很尴尬"；本书笑点落在"改口梯度"且要求齐整窄窗口。

## 相关 skills

- **depends-on `wojia-vocal-signature`（S1 声口复用）**：本卡的笑点落在"谁先改口、谁后改口"的梯度上；若旁观者声口不分，梯度无法被读出，抓包只剩尴尬。先立声口再写抓包。
- **contrasts-with `wojia-co-conspire`（B1 全家圆谎）**：一对反向结构——本卡是私下共识被**暴露**后集体翻转，B1 是虚假共识被合力**保住**。同一场景里选一个方向，不能同时。
