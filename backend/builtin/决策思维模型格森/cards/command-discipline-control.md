## I - 方法论骨架

孙子把组织能力放进胜算核心。“将”不是只会喊口号，而要智、信、仁、勇、严；“法”不是形式制度，而是编制、职责、通道、资源使用。团队执行不动，常常不是员工不努力，而是目标不一、命令不明、授权不清、赏罚不信、负责人缺少某项领导能力。

这个 skill 用来诊断组织为何执行失灵。

## A1 - 书中的应用

### 案例 1：将是五事之一

- 问题：战略好坏取决于领导者质量。
- 方法：用智、信、仁、勇、严检查将。
- 结论：领导力是战略变量。

### 案例 2：法令孰行

- 问题：制度写了但不执行。
- 方法：比较谁的法令真正被执行。
- 结论：组织可信度来自长期一致执行。

### 案例 3：令素行

- 问题：临时严格，团队不服。
- 方法：平时命令就能执行，战时才有纪律。
- 结论：执行力不是突击出来的。

## A2 - 触发场景

### 用户会在什么情境下需要这个 skill?

1. 团队目标不一、执行混乱、责任不清。
2. 老板越级指挥、授权和一线判断冲突。
3. 赏罚制度不可信，团队观望。
4. 用户提到将、法、赏罚、军令、纪律。

### 语言信号

- “团队为什么执行不动？”
- “将者智信仁勇严怎么用在管理？”
- “法令孰行怎么检查？”
- “赏罚不明是不是问题根源？”
- “老板总临时改命令，怎么办？”

### 与相邻 skill 的区别

- 与 `temple-calculation` 的区别：庙算评估将和法，本 skill 深挖组织执行。
- 与 `short-war-resource-control` 的区别：如果问题是拖延消耗，用后者；如果来自组织纪律，用本 skill。
- 与 `terrain-context-diagnosis` 的区别：环境复杂可能影响组织，但本 skill 看内部控制。

## E - 可执行步骤

1. **检查将**
   - 完成标准：分别评估智、信、仁、勇、严是否缺位。
2. **检查法**
   - 完成标准：列出职责、流程、授权、资源、汇报线、决策权是否清晰。
3. **检查令与赏罚**
   - 完成标准：说明命令是否稳定、赏罚是否兑现、执行是否一贯。
4. **输出组织修复动作**
   - 完成标准：给出统一目标、明确授权、减少越级、调整赏罚、替换负责人或缩小任务。

## B - 边界

### 不要在以下情况使用

- 用户要求独裁式控制、羞辱员工、违法命令或压榨管理。
- 团队问题主要来自外部资源不足，而非组织执行。
- 用户只想找人背锅，不愿检查系统。

### 失败模式

- 把严误解为粗暴。
- 只要求下属执行，不检查命令是否清楚。
- 赏罚临时化，破坏信任。

### 来源边界

本 skill 依据《始计》《行军》《地形》《九地》中关于将、法、令、赏罚的内容；现代使用限于合法、尊重人的组织管理。
