## I — 方法论骨架 (Interpretation)

- 先把单集"钉"在几个帐篷柱(tent-poles)上再填肉，避免故事散架：① 开头（引信/inciting incident）
  ② 结尾（resolution）③ 第三幕末的"最坏情况"(worst case)。
- 关键反直觉点：**worst case 不是"坏事情发生"，而是"与主角目标相对立之事 / 反派看似得逞"**。
  例：怕高的医生，worst case 是妻子拒绝他，而非病人死或下雨成灾。
- 已知 Act3 末的 worst case，基本结构就解了一半——因为可以"从危机往回推"角色如何走到这一步。
- 与 grid 配套：tent-poles 是"地标"，grid 是把地标之间填成完整地图。

## A1 — 书中的应用 (Past Application)

### 案例 1: 虚构 Jane & Sally 警探剧的 tent-poles 示范
- **问题**: 作者要教新手如何"先看见房子的骨架"再写。
- **方法论的使用**: 设定开头（有人偷名鞋引出猫女盗）→ 结尾（真凶是报案人）→ Act3 末 worst case
  （怕高的 Jane 被迫爬上窗台救被绑架的 Sally，且因恐惧手抖可能错失唯一机会）。worst case 精准对准
  "Jane 的内心恶魔"而非外部灾难，再据此往回推 Act1/2 的断点。
- **结论**: 钉住 worst case 后，Act1/2 的 cliffhanger（揭穿女盗、Sally 被绑）自然浮现。
- **结果**: 成为书中"先结构后血肉"的标准模板（作者自陈"that's a silly story"但意在教骨架）。

### 案例 2: Smallville 选 act break 的实战
- **问题**: 原四幕 Act One 过长，团队要决定在哪断幕。
- **方法论的使用**: EP Kelly Souders 把断点选在"Act One 结尾有一个动作 beat"处——这正是把 tent-pole
  式的强节点当作断幕依据的实务（case-004）。
- **结论**: 锚点（强节拍）决定幕断位置，而非机械按页数切。
- **结果**: 示范 tent-poles 思维如何落地为真实改结构决策。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

2. 用户纠结"这一集最大的危机/转折该放哪"，或把"坏事情"误当成戏剧危机。
3. 用户想从结尾或 3/4 处危机往回倒推整集，避免顺写时中段塌陷。

### 语言信号 (用户的话里出现这些就应激活)

- "这一集开头钩子、结尾、还有3/4处最大危机怎么定 / 先钉住几个关键点再写"
- "最坏情况 / tent-poles / 结构锚定 / 单集三锚点 / 最大危机放哪"
- "anchor my episode structure / worst case at three-quarters / tent-poles"

### 与相邻 skill 的区分

- 与 `tvd-grid-reverse-engineering` 的区别: 本 skill 只定"3–5 个锚点"(开头/结尾/worst case/幕断)，
  grid 是把锚点之间**填满成逐 beat 地图**。先锚定(tent-poles)再做 grid 最顺，二者易混但层级不同。
- 与 `tvd-dramatic-beat` 的区别: beat 是"一个动力步"，tent-poles 是"散落全剧的几个最关键节点"，
  不在同一粒度。
- 与 `tvd-a-b-c-stories` 的区别: A-B-C 管"几条并行线"，tent-poles 管"整集纵向的几个锚点"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **钉住开头引信与结尾两个最易定的帐篷柱**
   - 完成标准: 能用一句话写出"是什么事件把本集（的某计）引爆"(开头) 与 "本集如何收束"(结尾)。

2. **定义本集 worst case（对准主角目标的对立，而非泛泛坏事）**
   - 完成标准: worst case 句明确写出"主角想 X，最坏情况是反派/阻力让 X 几乎失败（约在 3/4 处）"，
     且不是"天灾/巧合"而是与主角内在目标直接冲突。例：欲调和，worst case 是家人误会更深、她权威崩塌。

3. **从 worst case 往回推 Act1/2 断点与前置 beat**
   - 完成标准: 产出从危机倒推的 2–3 个前置转折点，并标出每幕末的 cliffhanger；确认无"中段无推进"塌陷。
   - 判停条件: 若往回推时发现 beat 过多超容量，跳到 tvd-grid-reverse-engineering 做整体容量核查与精简。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户要的是"整张分幕节拍表"而非"几个锚点"——此时用 tvd-grid-reverse-engineering。
- 用户问的是"整季 首尾与每集情感节点"——那是 tvd-season-arc-planning，tent-poles 只服务单集。

### 作者在书中警告的失败模式

- **ce08 故事过载 (too much story)**: 作者警告"you might have fooled yourself in the outline by counting
  sequences of scenes as one beat… you need to re-think the stories themselves, or delete an entire arc."
  未先锚定 tent-poles 就埋头填细节，是最容易导致过载失真的原因——tent-poles 正是为防止此坑而设。

### 作者的盲点 / 时代局限

  "计划彻底搞笑翻车/面子尽失"，但须仍对准主角目标而非纯外部意外。

### 容易混淆的邻近方法论

- 与 `tvd-grid-reverse-engineering` 极易混（新手常把"锚点"与"整张grid"当一个东西）；记住
  tent-poles=几个地标，grid=填满地标之间的地图。
