## I — 方法论骨架 (Interpretation)

将产品的事实描述转化为消费者购买理由的系统方法：

**核心区分**：
- 特色 = 产品是什么（事实描述，厂家视角）
- 功效 = 产品为你做什么（使用价值，消费者视角）

**操作方法——双栏表格法**：
1. 左栏列出所有产品特色（事实、参数、功能）
2. 对每条特色追问："这如何让用户的生活更好/更省力/更省钱/更快乐？"
3. 右栏写出对应的功效（消费者利益）
4. 右栏的产出就是文案的"卖点清单"

**转化关键问题**：这项特色如何让产品更有吸引力？更实用？更有乐趣？更负担得起？

**底层原则**：消费者买的不是产品，而是产品能为他们做的事。菜鸟只写特色，老手转化成功效。

## A1 — 书中的应用 (Past Application)

### 案例1: 2号铅笔完整转化示范
- **问题**: 如何为一支普通铅笔找到卖点
- **方法论的使用**: 对10项铅笔特色逐一转化
- **结论**: 六边形→不会滚下桌；有橡皮擦→方便改错；7.5英寸长→能写很久；2号笔芯→写起来滑顺清晰
- **结果**: 一支普通铅笔通过转化产生了10条有力的消费者利益

### 案例2: 个人计算机特色转化
- **问题**: 作者如何描述自己的写作工具
- **方法论的使用**: PC能编辑更正文字(特色) → 省时+提高生产力+赚更多钱(功效)；可分离键盘(特色) → 放在最舒服的位置(功效)
- **结论**: 同一产品的不同特色可以产生完全不同类型的功效（效率型vs舒适型）
- **结果**: 展示了转化的灵活性

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 写产品文案时，手头只有产品规格参数，不知道怎么变成"卖点"
2. 准备销售演示，需要把技术参数翻译成客户听得懂的好处
3. 写简历/自我介绍，罗列了经历但不清楚"对方为什么要在乎"
4. 做竞品分析，比较自己的产品和对手的差异化价值

### 语言信号

- "这些特点怎么变成卖点"
- "我的产品有X功能，但不知道怎么写才吸引人"
- "怎么把技术参数翻译成客户能懂的话"
- "帮我找一下这个产品的卖点"

### 与相邻 skill 的区分

- 与 `five-stage-sales` 的区别: 本skill处理"卖点提炼"（找什么），后者处理"卖点组织"（怎么排列）
- 与 `usp-extraction` 的区别: 本skill是全部卖点转化，后者是找到最独特的那一个

## E — 可执行步骤 (Execution)

1. **列出产品的所有特色**
   - 来源：产品规格、使用体验、客户反馈、与销售人员对谈
   - 完成标准: 至少列出8-15条特色，不遗漏

2. **逐条转化：每条特色问"所以呢？这对用户意味着什么？"**
   - 转化公式：[特色] → 所以你可以 [做X] / 不再 [受Y之苦] / 节省 [Z]
   - 一条特色可能有多个功效
   - 完成标准: 每条特色至少有1个对应功效

3. **筛选和排序功效清单**
   - 挑出最有力的2-3个作为主卖点（用于标题）
   - 其他作为辅助卖点（用于正文）
   - 完成标准: 能明确说出"最重要的3个卖点是什么"

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 技术文档/B2B规格书——读者就是看特色的，不需要"翻译"
- 产品定位讨论——定位先于转化，需要先知道"卖给谁"再转化
- 纯功能清单（如API文档）——读者需要的是准确信息而非说服

### 作者在书中警告的失败模式

- 只写特色不写功效——"销售人员只会描述产品特色，以为顾客应该自己知道产品有什么好处"
- 功效写得太抽象——"质量好""服务优"不是具体功效，要说"具体能为你做什么"

### 作者的盲点 / 时代局限

- 过于强调功能性功效，忽略了情感性功效（品牌认同、社交价值、自我实现）
- 在体验经济时代，"产品能为你做什么"不限于功能，还包括"使用产品时的感受"
