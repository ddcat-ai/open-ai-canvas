## I — 方法论骨架 (Interpretation)

用看似逻辑严密的方式组织事实来支持销售论点。"伪逻辑"不是造假，而是选择性地呈现和组织真实事实，使其自然推导出"你应该购买"的结论。

**核心方法**：
1. **数字对比法**：用具体数字创造价值感（"花1000省5500"）
2. **权威引用法**：引用行业权威/研究/专家的观点背书
3. **研究数据法**：展示产品性能的量化证据
4. **时间序列法**：使用前后对比展示效果变化
5. **因果链构建**：将产品特色与消费者利益用逻辑链条连接

**关键原则**：
- 所有使用的事实必须是真实的——伪逻辑不等于造假
- 不做全面的逻辑论证，而是选择最有说服力的事实角度
- 让读者自己"推导"出购买结论，比直接说"你应该买"更有说服力

## A1 — 书中的应用 (Past Application)

### 案例1: 会计师的数字对比
- **问题**: 怎么让小企业主相信雇会计师值得
- **方法论的使用**: "花1000省5500"——用具体数字创造"投入vs回报"的逻辑
- **结论**: 数字本身是真的（会计师确实帮客户省了那么多税），但选择性呈现了"省了税"这个角度
- **结果**: 读者自然推导出"雇会计师是划算的"

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 产品确实好但客户不信——需要增加"证据感"
2. 竞品对比文案——需要用事实证明"我们更好"
3. 定价较高的产品——需要让客户觉得"值这个钱"
4. 需要量化产品效果的广告

### 语言信号

- "怎么让客户相信我们的产品"
- "怎么证明我们比竞品好"
- "文案不够有说服力"
- "客户觉得价格太高"

### 与相邻 skill 的区分

- 与 `five-stage-sales` 的区别: 后者是整体结构，本skill是Stage 4(证明功效)的深化技巧
- 与 `feature-to-benefit` 的区别: 后者找卖点，本skill证明卖点

## E — 可执行步骤 (Execution)

1. **列出你想证明的核心论点**
   - 例："我们的产品比竞品省50%的时间"
   - 完成标准: 论点具体且可验证

2. **选择1-2种伪逻辑方法**
   - 有具体数字？→ 数字对比法
   - 有研究/测试？→ 研究数据法
   - 有名人/专家背书？→ 权威引用法
   - 有使用前后对比？→ 时间序列法
   - 完成标准: 方法与可用证据匹配

3. **用选定方法组织事实，让结论自然浮出**
   - 不要直接说"你应该买"——让数字/对比/证据自己说话
   - 完成标准: 读者读完能自然推导出购买理由

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 无法提供真实事实支撑时——伪逻辑≠造假
- 法规严格限制的行业（医疗/金融）——某些对比和数据使用可能违规
- 品牌信任已建立的场景——过度"证明"反而显得心虚

### 作者在书中警告的失败模式

- 使用虚假数据——一次被揭发，信用永久受损
- 过度"证明"导致文案枯燥——说服力需要在逻辑和情感之间平衡

### 作者的盲点 / 时代局限

- 未讨论现代消费者对"营销数据"的警惕性——当代消费者对广告中的数据更加怀疑
- 未涉及第三方验证/认证的权重提升——现代营销中，第三方认证比自说自话更有效
