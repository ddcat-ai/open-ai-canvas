## I — 方法论骨架 (Interpretation)

本 skill 是"配图侧"的总控，把配图工作流拆成两层：

**① 普通配图主干（内容层，IP 与普配共用）**
1. 选认知锚点：找读者最易卡住/需转折/最值得总结处，而非每 500 字机械插一张。
2. 译关系结构：流程/对比/分层/路线/环形网络，把抽象观点变语义关系。
3. 变视觉隐喻：筛选=漏斗、连接=桥、决策=砝码——物件让关系一眼可读。
4. 选风格画幅：16:9/1:1/9:16 分别安排主体/文字/留白，非裁三遍。
5. 生成验收：一图一意、关系不画反、风格统一、承接上下文。

**② IP 升级（在主干上叠加身份层+表演层，见关联 skill）**
- 八步法：保留普配流程 → 建角色圣经 → 标参考边界 → 身份画风解耦 → 建动作库 → 加表情视线 → 连续画面 QA（含回归测试） → 明确文字交付模式并存参。

**③ 两种文字交付模式**（必须显式选，非默认两步）
- 一次融合：人物+场景+少量中文直接成品，适短文字/图文紧。
- 两阶段：纯图→扩展画布+标题说明→发布成品，适频繁改字/多尺寸/品牌排版严。

**④ 小互工作流四步（agent 编排循环）**：读全文判配不配（不配也写理由）→ 按语义选图型（情绪图/示意图/四格）→ 现想画面写提示词定尺寸 → 逐张自查返工。用户只拍两次板：生图前看清单、挑角色与画风。

**⑤ 动笔前四规矩（质量门禁）**：每段都过、判不配也写理由；该配别漏不该配别凑（看读者会不会卡住）；先分类再动笔；画完自己挑刺。

## A1 — 书中的应用 (Past Application)

### 案例 1：普通配图五步示范
- **问题**：一段讲机制的原理，枯燥难懂，要不要配图、配成啥没章法。
- **方法论的使用**：先选认知锚点（读者卡处），译成关系结构（如流程），变视觉隐喻（漏斗），定 16:9 画幅，生成后验收一图一意。
- **结论**：无人物也能很好解释内容，IP 不是来替代它。
- **结果**：读者滑动中获得停顿与记忆点。

### 案例 2：工作流三轨实例（小互）
- **问题**：一组 IP 图容易滑成一个样、看三张就腻。
- **方法论的使用**：先分类——情绪图（演处境非摆愁脸）、示意图（角色钻进流程当一部分）、四格漫画（心路四表情），同一画风同一世界但形态各异。
- **结论**：按内容类型分轨，避免同质。
- **结果**：连载可读性提升。

### 案例 3：自查返工闭环（小互）
- **问题**：出图好看但把道理画错，比丑图还坑人。
- **方法论的使用**：动笔前四规矩 + 出图后自查表（点对没、结构全不全、角色占多大、字错没），画歪抽出来标重画。
- **结论**：AI 越好看，内容关越要紧。
- **结果**：QA 闭环，不合格自返工。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要给一篇公众号/文章自动或半自动配图，不知从哪段配、配成啥型。
2. 已有配图但想升级成"有固定 IP 角色"的系列配图。
3. 纠结图里文字怎么合成（一次融合 vs 两阶段）。
4. 配图总偏少/看三张就腻/好看但把理画错，需要质量门禁。

### 语言信号（用户的话里出现这些就应激活）

- "IP 配图 / 文章配图 / 怎么给文章自动配图"
- "配图工作流 / 配图前怎么判断 / 图文字怎么合成"
- "illustration workflow / auto-illustrate / IP illustration"

### 与相邻 skill 的区分

- 与 `character-ip-master` 的区别：master 是跨媒介总控；本 skill 只管**配图这一媒介**的总控（五步+八步+交付+门禁），不跨视频。
- 与 `ip-character-bible` 等的区别：本 skill 编排它们（身份/动作/画风/表情），不写具体角色档案或动作语义。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **内容层先行（普通配图五步）**
   - 完成标准：列认知锚点+关系结构+视觉隐喻+画幅，确认"这段该不该配、配成什么关系"。

2. **动笔前四规矩过滤**
   - 完成标准：每段判配不配且写理由；按"读者会不会卡住"而非"自己觉得讲清没"筛。

3. **分轨（三轨分流）**
   - 完成标准：按内容定情绪图/示意图/四格，避免一组图滑成一个样。

4. **叠加 IP（调用子 skill）**
   - 完成标准：按需调 `ip-character-bible`（身份）/ `ip-action-library`（动作）/ `ip-performance-faces`（表情）/ `ip-style-decoupling`（画风）。

5. **选文字交付模式**
   - 完成标准：短文字紧图文→一次融合；频繁改字多尺寸→两阶段；显式标注当前选哪种。

6. **生成 + 自查返工**
   - 完成标准：逐张过自查表（点对错/结构/角色占比/字错），不合格返工。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯视频/数字人表演提示词（走 ai-acting-master）。
- 纯静态头像/logo/品牌 VI 设计，与"文章配图工作流"无关。
- 单张出图且无系列连续性需求。

### 作者在书中警告的失败模式

- **错误公式**：把"普通配图+固定人物"当 IP 配图，人物贴角落只成装饰。
- **只换脸/只换画风**：内容结构没变，产出仍同质化；定制=改工作流不是换模板。
- **内容关松动**：该配漏配/不该配硬凑，或一张好看却把道理画错——比丑图更坑人。

### 作者的盲点 / 时代局限

- 普通配图五步偏"人工判断认知锚点"，未给可自动化锚点检测的硬规则；agent 化时仍需人/模型判读。
- 两种交付模式依赖具体模型能力（一次融合需 Image2/Banana 类），未覆盖所有生图后端。

### 容易混淆的邻近方法论

- 与"纯排版/封面设计"混淆：本 skill 重"内容关系→视觉隐喻"的语义转化，不是版式美化。
