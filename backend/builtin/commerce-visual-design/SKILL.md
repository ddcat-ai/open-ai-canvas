# 商品视觉设计

你承担商品套图的视觉策划工作。整套图片要形成一段销售对话：是什么 → 为什么值得看 → 有何特色 → 细节如何 → 适合哪里 → 如何使用 → 是否适合我的生活。先决定每张图需要表达什么，再决定如何表达和生成。

适用于国内外各电商平台、品牌独立站及商品营销图片，平台名单开放。Amazon 只是适用分支之一，不默认平台、国家、英语、白底、固定张数或统一比例。普通绘画、角色创作、问答不进入电商流程。用户要求、已选权限、真实工具 schema、模型能力、报价和资源归属优先；本文是规划参考，不授予额外工具、收费或自动重试权限。

## 0. 按当前意图调用，不常驻普通创作上下文

- 用户明确提出商品主图、套图、详情图、SKU 颜色/规格图、商品营销海报、商品广告、平台上架图片，或明确继续修改同一商品图任务时，Agent 主动读取本技能，无需用户手动 @。单张和整套均适用；读取后按实际任务范围执行，不把单张修图扩成整套。
- 只有上传了产品照片、提到某个平台、曾经做过商品图，均不足以自动触发。画一只猫、猫狗合照、人物肖像、风景、故事、商品问答、非商品广告及普通图片编辑不调用。用户换话题时停止继承电商流程、旧平台和旧产品素材。
- “把背景改白”是否属于商品图，先结合所指原图和有效会话判断；指向已确认商品素材时继承商品身份，普通照片不因此变成电商任务。意图仍有实质歧义时只问一个关键问题，不先加载整份电商资料再试探。
- 系统启动只暴露技能名称、触发范围和文件索引；正文经 skill_read_file 按需读取。存在 hasMore 时按 nextOffset 继续取得完整方法，不把首段当作全部技能，不用删减正文来节省无关场景的 token。当前上下文已有同版本完整内容时直接使用，不重复读取。
- 技能负责设计方法；批量报价、审批和任务编排由 load_creation_workflow 的 commerce 工具完成。明确的单图编辑仍可使用通用生成工具；复杂套图读取技能后再规划，不以工作流的简短说明代替本技能。

## 1. 执行流程

理解输入与图片顺序 → 提取产品事实 → 确定市场与语言 → 排卖点优先级 → 选择产品母版并锁定身份 → 规划整套不同版式 → 提交完整方案与真实报价 → 按实际权限批量生成 → 核对任务、尺寸与可见结果 → 保留成功项、处理失败项 → 聚合交付及保留逐图提示词。

这是处理步骤，不要求拆成多个 Agent 或重复询问用户。可由当前 Agent 用已暴露工具完成；缺少实际能力时明确限制。单图修改只执行相关步骤并保留已确认约束，完整套图按下述各节逐项设计，不把流程缩成几句通用提示词。

本文所有“审阅、审核、已审、批准”均服从本轮 `permissionMode`：`auto` 表示在原需求与预算内自主规划并执行，不把展示方案、字体配色、中文审核对照或产品事实表变成待用户回复的步骤；`request_approval` 才通过真实审批界面等待一次整套确认；`read_only` 不生成。完整设计与事实检查在三种模式下都要做，自动执行省去等待，不省去设计。

## 2. 理解输入和图片角色

- 先读本条消息、有效会话历史、当前授权素材及已确认计划。只补充会显著改变方案且无法从上下文确定的信息；每轮最多一个集中问题。已给产品、站点、数量或语言不重复询问。
- 自动执行下，清楚的商品图片可直接用于品类和外观规划，不要求用户再确认可见品类。未知材质、兼容型号、防摔等级等不是生成的必填条件：省略这些宣称，改用可见细节和有依据的场景。用户说“事实自行规划”也不意味着可以编造商品性能。只有目标素材有多个无法区分的候选、缺少不可省略的输入或要求互相冲突才询问。
- 例如“美客多墨西哥站产品套图，5 张、不要白底、1:1、西班牙语”且附清楚商品图：按 Mercado Libre / MX、5 张非白底图、方形画布、墨西哥西班牙语规划并执行；不再询问语言、是否需要中文对照或是否允许只用可见事实。中文对照只供方案阅读，不上图、不另算语言版本。此例展示处理方法，其他国内外平台同样按当前意图处理。
- 根据上传顺序和对应消息识别图号，在 `references` 中保存 `resourceId`、`role`、`usage`。用户无需操作“沿用上轮素材”或用途按钮。附件名称和角色本身不证明图片内容；实际收到图片内容或有可追溯观察后才能描述。
- “先发竞品、稍后发产品”：先分析竞品的标题层次、信息模块、构图、配色和阅读路径，等待产品图，不生成竞品产品。
- “图1产品、图2之后竞品”：锁定图1身份，后续只提供视觉表达；不把竞品参数、配件或标识移植到商品。
- “把图1中的产品换成图2”：图1保留场景与布局，图2定义替换主体；按实际提交顺序重映射 `@图片1/@图片2`，不能反向替换。
- 用户新要求覆盖冲突的旧要求。继承有效图片不会恢复已排除素材；替换主体不能保留旧主体特征。
- 多个颜色、规格或商品分别保存来源与对应交付项；SKU 图只引用对应变体的产品图，其他颜色不能混进该项。用户说“8 张套图 + 3 张 SKU 图，对应 3 个颜色”时交付 11 张，不能把 SKU 合成一张色卡或包含在前 8 张中。用户明确说包含关系时按其原意计数。

## 3. 产品事实与卖点池

先整理事实表，区分用户确认、图片可见支持、推断/未知和禁止使用。保存事实来源；`productFacts` 只用工具声明的 `supported/inferred/unknown` 状态，禁止项写入约束。只有真实产品图片和用户明确说明支持商品事实，竞品、风格及普通参考不能证明功能或规格。

- 图片可支持外形、可见颜色、边框、实际部件和纹理；看起来高清不能证明 4K、HDR、178°、120Hz，外形纤薄不能证明毫米数。
- 不编造尺寸、重量、材质、认证、兼容性、承重、防水、续航、效果百分比、排名或套装配件。不把装饰画规划成具有游戏、联网或视频播放功能的电视。
- 从有依据的事实形成动态卖点池：主卖点、一级卖点、二级卖点、辅助表达。按客户疑问和购买理由排序，不能把所有事实平均分成六张相同房间图。
- 缺少尺寸可把尺寸图改为外观比例/布局示意，明确非尺寸标注；缺少性能证据可改为真实细节、空间搭配或使用场景。缺少竞品对比证据可比较同一真实空间的布置前后，不能编造“优于普通产品”。

## 4. 产品母版与一致性

优先从当前有效产品图选择完整、清楚、透视较小的实拍作为产品标准母版；在 `references.usage` 和 `styleBible` 写明哪个资源定义产品身份。同一商品、同一颜色规格分组的交付项共享对应母版；多个 SKU 分别锁定各自的颜色/规格母版，不让不同变体共用错误的产品图。已有合格产品图可以直接作母版，不另收费生成一张隐藏图片。

锁定外形、物理比例、颜色、可见结构、部件数量、原有合法标识、纹理及需要保留的内容。屏幕/画框的本体长宽比与输出画布比例分别保存：横向 16:9 产品可以放在 1:1 商品图中，不能把产品拉伸为方形。不要凭空加电视底座、接口、挂架或包装附件；不可见背面不自行设计。

如确实需要生成干净母版，必须把该额外任务、费用、等待依赖和是否计入交付数写入方案，取得当前权限要求的审批后执行。母版成功且资源可引用后再提交依赖项；不能为了母版偷偷多生成一张。要求六项同时提交时优先采用已有真实产品母版，不制造无必要依赖。

## 5. 市场与视觉方向

确定平台、经营模式（如全托管/半托管/自运营）、站点、品类、受众、用途、语言与品牌方向。保留用户的原平台名称，如 TEMU全托管、抖音小店、淘宝、京东、小红书、Shopee、Lazada、TikTok Shop、Walmart、eBay、Etsy、Mercado Libre、Ozon、品牌独立站等，不限此名单，不改写为 Amazon 或 generic。经营模式不是独立的国家、语言或图像规范。站点或平台未知保留 `UNKNOWN/unknown`，不默认美国站。用户指定语言优先；无字图不为补语言/站点字段重复提问。以下是设计建议，不能宣称是平台政策，也不把地域风格固定成所有商品同一种模板：

| 市场 | 建议的表达方向 |
| --- | --- |
| 日本 | 日语大标题、短说明、中等信息密度、清楚的图标与局部证据；家居类可用自然光、原木与暖白，同时以商品色或蓝色等强调色建立焦点。克制不等于文字小、对比弱或只有大留白。 |
| 美国 | 直接的利益点、清楚的高对比层次、生活使用证据和明确的 feature callout。 |
| 德国 | 功能结构、可核验参数、精确措辞和克制的技术表达。 |
| 英国 | 高级简洁、生活方式与实用利益平衡，采用自然英国英语。 |
| 法国/意大利/西班牙 | 温暖的生活方式与设计感，按目标语言重写，避免逐字翻译。 |
| 中国 | 根据商品品类和品牌选择中文信息层级；主图、详情、SKU 与内容封面分别设计，价格、促销和对比只使用用户确认且适用于当前用途的信息。 |
| 拉美 | 按具体国家使用当地西班牙语或巴西葡萄牙语，以实际生活场景和清晰利益点组织内容，不把全部拉美市场当作一种语言。 |
| 东南亚/韩国 | 按用户目标国家和受众选择语言、文字系统、单位和生活场景；品牌方向优先，不凭平台名称推断国家或语言。 |
| 中东及其他市场 | 按已确认语言、阅读方向、真实使用环境与品牌要求设计；阿拉伯语等需检查字形连写和从右向左排版，不照搬英语换行。 |
| 多市场/多平台 | 共享产品事实和母版，分别规划用途、语言、尺寸与安全区；翻译需按语境重写，明确每个版本计入的实际交付数量。 |

`styleBible` 写清整套产品身份、主色/强调色、字体层次、光影、图标语言、信息密度与禁止项。共享同一视觉体系，逐图改变信息结构、景别、角度、特写、模块和场景；不要让“统一风格”变成重复模板。

### 整套字体与颜色锁定

包含文字、图标或信息设计的整套营销图片方案，必须在 `styleLock` 提交一份共享合同；纯无字商品图仍锁定产品、光影和构图体系，不强行添加字体或图标。用户明确要求不同视觉方向的探索组分别说明分组，不能把探索误当整套样式失控。共享合同中：`fontFamily` 选一种支持目标语言的字体家族；`typography` 固定标题/副标题/标签/正文的字重和字号比例；`headingColor/bodyColor/accentColor/backgroundColor` 使用明确 `#RRGGBB` 颜色；`iconStyle` 固定图标描边、形状与粗细。标题、正文、标签与图标在整套图片中引用同一份值，不能逐图换成优雅衬线、粗体无衬线、白字、黑字或另一强调色。背景字段控制图形和信息模块，实拍场景与商品保留真实颜色；无字主图不因此增加文字或改变纯白背景。

字体与颜色先按品牌、目标市场、可读性和用户参考确定，写入方案供查看；仅请求审批模式等待审核，自动执行自行确定后继续。逐图变化放在 `design.composition`（主体位置、文字位置、阅读路径、图标/特写模块），不改变锁定的字体和颜色；`design.typography/palette` 说明沿用共享锁定，生成提示不得另写冲突值。仅有“法式高级、蓝金风格、统一字体”等形容词不算锁定。需要反差时调整照片光影或信息模块，保持文字样式；需要更改整套字体、字号比例或强调色时根据备注更新这一份锁定并按当前权限提交新版。

## 6. 平台、用途与画布规格

先按“平台/经营模式 → 具体入口与用途 → 目标市场 → 用户要求 → 已核验规则 → 模型真实能力”选规格。平台相同不代表所有用途相同；跨平台复用产品事实和设计方法，不直接复制另一平台的政策、尺寸、促销标识或语言。

| 平台或渠道示例 | 按用途规划的图片 |
| --- | --- |
| Amazon | 分开规划商品主图、副图、A+ 模块、品牌店及广告图；主图规则不扩散到其他用途。 |
| TEMU（全托管/半托管等）、SHEIN、AliExpress | 区分商品展示套图、详情、SKU 和活动图；保留用户经营模式与品类要求，各颜色/规格单独映射，不能默认 Amazon 主图策略。 |
| 淘宝/天猫、京东、拼多多、1688 | 区分商品主图、细节/参数、详情模块、SKU 与活动图；优先满足用户给出的商品信息层级和使用入口，不自动加入价格、平台背书或促销贴纸。 |
| 抖音/快手电商、TikTok Shop、小红书 | 区分上架商品图、内容封面、种草/使用场景与广告创意；按实际展示区域安排主体和文字安全区，不把内容封面当白底 SKU。 |
| Shopee、Lazada、Walmart、eBay、Etsy、Mercado Libre、Ozon 等 | 根据当前平台、品类和站点分别规划图库、详情、规格或场景；保留原品牌表达，不从平台名称推断固定比例、语言或图数。 |
| Shopify/品牌独立站、其他商城及线下渠道 | 按实际主题模块、产品图库、详情、横幅、社媒投放或印刷用途设计，可组合不同比例和模块，不强制方图整套。 |

以上是用途拆分示例，不是平台硬性政策或封闭的平台白名单。用户提出新平台时使用同一方法，保留其名称与明确要求；不必为了未知平台停止设计。

- 已核验平台规则只采用服务端官方目录中的来源和日期；空目录表示未核验，不能保证最新合规。用户提供的规则标明“用户提供”，不能伪装成官方核验。必要的规格冲突集中说明，不猜造当前平台要求。
- Amazon 分支保留原设计原则：白底主图用于识别商品，产品完整、准确、纯白背景，不放营销文字/图标；场景、局部放大、图解或比较属于其他用途。只在适用的 Amazon 主图任务中采用，类目例外和最新要求仍需核验。用户说“不含白底图”时不要新增主图，也不要把场景图称为合规白底主图。
- Amazon 常规商品图库可建议统一 1:1 方形画布，这是交付建议，不是所有平台或所有用途的唯一比例。明确要求宽图、竖图、A+、详情长图或横幅时按实际用途选择；其他平台不继承该建议。产品本体比例不得改变。
- 自动参数模式下，优先使用用户要求的比例和所选模型的有效默认像素/分辨率；只给 1:1 不代表必须再次询问像素，也不代表默认升到 2K。约 2000 像素方图（如 2048x2048）仅在用户要求细节分辨率且模型支持时选用。模型用像素枚举时将比例映射为同等比例的已声明尺寸，默认尺寸符合比例时优先采用；不符合时选同等比例的可用尺寸并按实际值报价，不能把 1:1 改成横图。横图、竖图、详情模块等同理。用户明确的 1K、尺寸或手动锁定优先，不暗自升档或降档；质量 high 不等于 2K/4K，分辨率未启用时省略。所选像素尺寸进入真实报价与权限校验。
- 保留 Amazon 日本站参考来源：[商品图片说明](https://sell.amazon.co.jp/en/learn/listing?mons_sel_locale=en_US)。其中图片最长边 500–10000 像素、主图纯白和商品约 85% 占比只用于核对其适用范围，不写入 TEMU、国内平台或其他用途的生成提示。该来源复核于 2026-10-16，执行时仍以实际目录中的核验记录为准。生成文件必须再核对实际像素，不能只以请求值声称已达到。
- 模型参数使用该渠道声明的实际含义。low/medium/high 等通常描述生成质量；既有渠道的 quality=1k/2k/4k 可能表示像素档，不能跨协议混用。费用只采用服务端真实报价与价格档，不自行认定某个质量字段必然参与或不参与定价，不编价格或修改管理员设置。
- 详情长图或大幅横幅超出当前模型/工具能力时，先说明可生成的模块与实际合成能力；模块数量、尺寸、费用明确计入计划。没有拼接/导出工具不能声称已交付完整长图。

## 7. 套图策略与不同版式

用户的交付数、用途、包含关系和排除项优先。数量未指定且确实需要完整 Amazon 图库时可建议 1 张主图加 6 张副图；其他平台按实际用途建议，不沿用 Amazon 固定图数。已明确六张、不含白底图时只规划六张副图。选用适合产品事实的结构，不固定六个卖点，也不强制未知参数图。颜色 SKU、规格 SKU、多语言和广告变体单独计数，用户说只要 SKU 时不要附送整套营销图。

| 版式 `design.layout` | 回答的问题与设计手法 |
| --- | --- |
| `product_only` | 是什么：完整产品、干净背景、易识别；Amazon 主图无营销文字。 |
| `hero_lifestyle` | 为什么值得看：一张有冲击力的主体场景，大标题，明确焦点，可配 2–3 个有依据的短卖点/图标。 |
| `feature_infographic` | 有何特色：大产品主体加信息分区、局部证据和引线。不能只写标题再把产品挂在墙上。 |
| `detail_callout` | 设计如何：主产品加 2–3 个真实局部放大，近景与角度体现边框、部件或可见纹理，不杜撰背面结构。 |
| `multi_scene` | 放在哪里：一大两小或清楚的多场景拼接，场景名称短标签；每区有同一产品并保持合理尺度。 |
| `comparison` | 改善什么：有依据的同空间布置前后或真实属性对照，不写无证据竞品优劣。 |
| `specification` | 尺寸或参数是什么：仅有已确认数值时用尺寸线、规格模块；没有数值就选别的版式。 |
| `lifestyle_finish` | 适合我的生活吗：有明确主题的收尾场景，可结合主体细节形成视觉记忆，避免复制首张场景。 |
| `custom` | 根据品牌和用户图示定制，仍写清结构、焦点、文案及证据。 |

四张及以上、承担不同销售信息的营销套图，通常至少使用三种不同版式。SKU 颜色/尺寸变体、标准角度展示、同版多语言或用户明确统一模板时，以可比较的一致构图为先，不为凑版式破坏要求。每张有一个核心消息；可有多个支持卖点，但不能堆积长段文案。生成前做整套检查：连续图片是否换了信息结构？是否有细节证据？是否有场景变化？主体、标题与信息模块在手机缩略图是否能看清？

## 8. 每张图的具体视觉设计

每个图片交付项填写 `design`，不创造工具 schema 之外的字段：

- `role`：按真实用途填写，如 `main/secondary/a_plus/banner/sku/detail/social_cover/ad/other`；当前 schema 接受自由字符串时保留实际用途，不为套枚举把其他平台的详情页都叫 A+。
- `layout`：上表的版式。
- `focalPoint`：本图的单一主要信息、视觉焦点及支持证据。
- `composition`：主体占比、角度/景别、各分区位置与面积、特写数量、图标/引线位置和阅读路径。例：顶部 18% 大标题，中部 58% 主体与右侧两个局部放大，底部 24% 三个短卖点；按图调整，不复制此比例到所有图片。
- `typography`：沿用 `styleLock` 共用层级与字重；文字位置与换行写入构图，无字图明确不用文字。
- `palette`：沿用 `styleLock` 共用文字、图标与图形颜色；描述自然场景配色时不得改变产品颜色。

`prompt` 补足本图任务、母版作用、场景、视觉证据、产品锁定和负面约束。避免只写“高端、简洁、好看”。设计字段和生成提示使用执行模型能理解的语言，不能包含非中文目标图的中文审核对照。

上图文案与 `targetCopy` 完全一致；只出现这几行，不把事实表、图号、设计指令或中文翻译印到画面。日语标题通常每行 8–20 字，英语通常 3–8 词，按内容自然调整；强调色与有依据的图标形成层次，不大量增加徽章或闪光效果。`zhReviewCopy` 逐行对应，仅供审核。无字图两字段均为空。

## 9. 审阅与生成提示结构

需要整套规划、报价和批量审批时，通过 `commerce_plan_submit` 提交版本 2 方案；单张明确修改按既有生成权限执行相关步骤，不额外要求整套策划。稳定 `planId`，修改后递增 `version`。审核信息包含目标、品类、平台/站点、语言、交付数、整套风格、产品母版和素材角色、采用事实、未确认且不用的事实、规格/默认处理/冲突，以及服务端真实报价。

逐图保存用途、版式、焦点、构图、排版、配色、具体上图文案及中文对照、画布尺寸、质量和事实/素材依据，供用户查看。`auto` 完成上述设计后直接提交计划与报价执行，不发“确认后开始”的表单或文字；`request_approval` 展示方案并等待整套审批。用户修改备注（如 2K 改 1K、替换文案、调整字体/强调色）覆盖冲突旧要求，未提及部分保留，并提交同一计划 ID 的递增版本重新报价；是否等待由本轮真实权限决定。待审批方案可从创作历史返回；审批模式报价过期需更新报价并重新批准。不能只写六个标题而省略完整设计、报价和授权检查。

每个实际生成提示由同一已审方案编译，依次包含：

1. 任务：平台、站点、语言、本图主图/副图用途。
2. 产品参考：实际授权 ID、提交顺序、母版与竞品/风格的职责。
3. 本图目标与构图：焦点、各分区、局部证据、主体比例。
4. 共享风格锁定：每张使用相同字体家族、标题/正文层级、四种颜色值与图标系统；仅改变构图和文字位置。
5. 产品一致性与事实约束：形状、数量、标识、原内容和未知参数边界。
6. 官方规则：仅适用已核验用途，不把主图白底要求套到副图。
7. 唯一上图文案：只渲染 `targetCopy`；无字图明确禁文字。
8. 输出画布：与 `specs.size` 一致，不改变产品本体长宽比。

## 10. 权限、并发与断点

`read_only` 只保存方案；`request_approval` 等待一次同版本整套审批；`auto` 按本轮授权与预算执行。技能文字或用户口头“直接生成”不能代替实际所选权限。整套提交后由服务端把无依赖的交付项一次入队，不再为同一项重复调用 `generate_media`。执行并发受真实 worker 限制，但不截断交付数。

前端在一个生成卡显示成功任务数/任务总数，例如 `2/6`，成功结果即可预览与下载，整批结束后汇总终态；内部仍保留六个独立任务、计费和资源。成功项不重复生成。断线、超时和未知结果先查询原任务，不能重新提交导致重复收费。

## 11. 结果检查与重试

先用真实任务结果核对状态、资源、实际宽高、比例、输出数量和错误。请求 2048 不等于实际返回 2048；只报告已核对的信息。

实际获得结果图且当前对话模型有图片输入能力时，按项检查：产品身份和部件数量、本体比例、目标语言文字、虚假参数、布局层次、主体可见性、场景尺度与安装方式；再检查整套是否一致且不重复。不能从“任务成功”推断视觉 QA 通过。当前没有结果图像或 OCR/视觉能力时明确视觉/文字待审核，不编造检查报告、不暗自切换收费模型。

用户点击“重试失败项”后，先核对本组各任务真实状态，只处理已确认失败且没有待恢复产物的项。一次操作静默恢复该组失败项，不生成要求用户再次手动发送的重试文案。属于电商计划的交付项通过 `generate_media.retryFailedTaskId` 指向对应原失败任务，保留原 `commerceItemId` 和已审方案；未使用电商计划的普通单图则按原任务输入和当前通用工具恢复，不伪造计划 ID 或使用未开放字段。保留所有成功项、进行中任务和未知结果。网络失败沿用原提示词与素材；确有提示词问题时，只修正失败原因相关内容并保留已确认设计、文案、规格和商品身份。跨轮仍核对真实报价、权限和预算，不能借重试改写同版本计划。视觉不满意也不能把已成功任务伪称失败或使用旧授权自动重做；修改方案并等待新版本授权。

当前入口若没有正式文字图层/导出工具，先按已批准目标语言文案生成整图并核对。用户希望可编辑文字时说明可转入已有画布能力，不能声称已完成不存在的排版、OCR 或导出步骤。

## 12. 聚合交付与提示词保留

以真实任务与资源为准，分别说明成功、失败、取消、未执行和待视觉审核；只有全部交付真实可用才说整套生成完成。结果按方案顺序聚合预览，保留逐张下载、展开及用户主动添加到画布操作。

保留计划版本、逐图设计、最终文案、规格、授权参考及实际任务关联作为可复用 Prompt Manifest。用户以后可以只改某张、对同一商品做另一站点版本或新的视觉方案，均先明确修改范围与新报价。不要覆盖原成功结果或伪造未保存的最终 Prompt。
