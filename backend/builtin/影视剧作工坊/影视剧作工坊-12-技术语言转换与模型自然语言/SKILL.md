# 技术语言转换与模型自然语言（模块 12）

> 主链定位：ST 唯一语义出口 + 平台适配。把导演与渲染层技术语言翻译成模型可直接执行的画面语言。

## 做什么
把导演和渲染层的技术语言，翻译成即梦能直接执行的画面语言。只做语言转换，不生产内容，不做技术决策。

## 底层逻辑
逐秒六维是转换的基本单位。每个镜头按时间轴拆成逐秒行，每一秒从六个维度描述：主体状态、动作节拍、机位运动、资产状态、光影变化、声音点。

六维是内部工作台，用来拆解每一秒。拆完后聚合成八要素。六维行不进入交付文件，不进模型提示词。

## 三层路由
模块的路由由三层串联组成：**风格解析 → 通道决定 → 子模块调度**。数据层（`channels/`）存放各通道的术语映射表，逻辑层（本节）负责解析与调度。同一镜头只走一条通道、只激活该风格词需要的子模块组合。

### 构建原则：子通道按「渲染器自身技术文档类目」划分
各渲染器通道内部，按其技术文档自身的类目体系划分子通道（UE5 用 光照与全局光照/材质与着色/后期处理/体积效果/毛发与织物/角色与皮肤/程序化纹理/色彩管理/灯光滤镜；Arnold 用 光照/标准表面着色器/标准毛发着色器/皮肤/眼睛/体积与大气/置换与细分/程序化纹理/灯光滤镜/色彩管理）。各通道类目可不同，但映射目标一致——全部转为即梦可直接执行的纯画面语言。
- 通道类目以「渲染环节 + 画面元素」混合组织（如光照、材质、后期为一类；角色与皮肤、毛发与织物为元素类），不强制跨渲染器同名。
- 跨渲染器的同名元素（皮肤/眼睛/毛发）目标画面一致，映射到同一批视觉词条；不同通道的同名子通道在词表层面各自维护。
- 好处：子通道即技术文档的天然章节，新增渲染器时直接照其文档类目建子通道，映射不漏项。

### 第一层：风格解析层
用户输入风格词时，先解析它指向什么视觉目标。风格词分两类：
- **指向画面对象**：真人质感、超写实3D、国漫风格、二次元、半写实3D。这类词决定画面「像什么」，触发对应的画面对象子模块。
- **指向渲染环节**：极致光影、电影感、体积感、氛围感。这类词决定画面「怎么渲染」，触发对应的渲染环节子模块。

### 第二层：通道路由层
风格解析完成后，决定走哪条渲染通道。
- **有明确渲染器技术词 → 按技术词走**：出现 Lumen/流明、Nanite/纳米、Substrate/基底材质、VSM/虚拟阴影贴图 → UE5 通道（实时渲染）；出现 Path Tracer、Standard Surface、Subsurface Weight、Atmosphere Volume → Arnold 通道（离线渲染）。
- **出现渲染模式词 → 按渲染模式走**：出现「实时渲染」→ UE5 通道；出现「离线渲染」→ Arnold 通道。实时渲染与离线渲染是通道的渲染模式属性：**UE5 = 实时渲染通道，Arnold = 离线渲染通道**。
- **只有风格词、无渲染器技术词 → 按风格词默认路由**：
  - 真人质感、超写实3D、国漫风格、半写实3D → 默认 UE5 通道。理由：UE5 的 MetaHuman 生态覆盖皮肤、毛发、眼睛、微表情的完整参数体系；风格化材质（国漫、半写实）在 Substrate 材质系统里也有对应表达。
  - 极致光影、电影感 → 看场景：室内封闭空间走 Arnold（Path Tracer 间接光照与焦散更精确）；室外开阔空间走 UE5（Lumen 动态全局光照更高效）。
  - 二次元、赛璐璐风格 → 不走任何渲染通道。这类风格排斥写实渲染，直接走独立的风格化输出，不调用 UE5 或 Arnold 的子模块。

### 第三层：子模块调度层
通道确定后，按风格词激活对应的子模块组合（子模块即 `channels/` 下的画面对象子通道）：
- **真人质感**：激活 皮肤、毛发、眼睛、微表情 四个子模块。皮肤调 Burley SSS 或 Subsurface Weight；毛发调 Groom 或 Standard Hair；眼睛调 Cornea 或 Cornea Shader；微表情调 FACS 或 Displacement；光照调 Lumen 或 Skydome Light；后期调 色调映射、胶片颗粒。
- **超写实3D**：激活 材质、光照、后期 三个子模块。材质调 Substrate 或 Standard Surface；光照调 Lumen 或 Physical Sky；后期调 ACES 色调映射、景深。皮肤调次表面散射，但不调微表情和眼睛的精细参数——超写实3D 追求整体画面像 CG 电影，不是人物面部特写。
- **国漫风格**：激活 材质、光照、后期 三个子模块，映射方向不同。材质排斥 PBR 写实，调「皮肤通透但非真人质感，发丝成束不单根可见，布料有手绘感」；光照调「主次光分明，高光受控，暗部有风格化色块」；后期调「色彩浓郁，暗部偏蓝或偏紫，高光偏暖」；皮肤调「肤色均匀，有淡淡红晕，无毛孔无雀斑」。
- **极致光影**：激活 光照、体积、后期 三个子模块。光照调 Lumen 硬件光线追踪或 Path Tracer；体积调 体积雾、体积云；后期调 泛光、镜头光晕、色调映射。不激活皮肤、毛发、眼睛子模块——极致光影追求光线本身的物理表现，人物是光的载体，不是细节主体。
- **电影感**：激活 光照、后期、体积 三个子模块。光照调「明确主次光，前中后景，受控高光」；后期调「胶片颗粒、暗角、色调映射」；体积调「体积雾、光束穿透尘埃」。皮肤和毛发只调基础参数——电影感追求氛围，不追求毛孔级细节。
- **半写实3D**：激活 材质、光照、皮肤、毛发 四个子模块。皮肤只调「肤色自然，无塑料感」，不调毛孔和雀斑；毛发调「发丝成束，有自然光泽」，不调单根发丝；材质调「布料有褶皱，金属有反射」，不调微观粗糙度。
- **二次元**：不调用 UE5 或 Arnold 子模块，走独立风格化输出。画面输出「平涂色块，清晰描边，无写实光影，高光为几何形状，眼睛占面部比例大，头发成块状」。

### 不指定通道时的默认规则
- 用户只写风格词、不写渲染器技术词：按风格词默认路由（见第二层）——真人质感/超写实3D/国漫风格/半写实3D 走 UE5；极致光影走 Arnold；电影感看场景；二次元不走通道。
- 用户只写了一个风格词、没写任何渲染环节词（光照/材质/后期）：只激活该风格词对应的**核心**子模块。真人质感只激活 皮肤、毛发；超写实3D 只激活 材质、光照；国漫风格只激活 材质、后期。
- 用户写了多个风格词：**取交集**。例：「真人质感 + 极致光影」→ 激活 皮肤、毛发、眼睛、微表情（真人质感核心）+ 光照、体积、后期（极致光影核心）。例：「国漫风格 + 电影感」→ 激活 材质、光照、后期；材质映射方向按国漫走，光照和后期按电影感走。

### 风格词和技术词冲突时
- 同时写了风格词和渲染器技术词：**以技术词为准**。
  - 「真人质感 + Lumen」→ UE5 通道，激活 皮肤、毛发、眼睛、微表情，光照调 Lumen。
  - 「真人质感 + Path Tracer」→ Arnold 通道，激活 皮肤、毛发、眼睛、微表情，光照调 Path Tracer。
  - 「国漫风格 + Subsurface Weight」→ 冲突。国漫排斥写实渲染，Subsurface Weight 是写实皮肤参数。路由层报错，回退上游，要求用户明确视觉目标。若用户坚持「国漫 + 皮肤透光」，按国漫走，Subsurface Weight 映射为「肤色均匀，有淡淡红晕，无毛孔」。

### 视觉输出层
无论走哪条通道、激活哪些子模块，视觉输出层始终输出纯画面语言。风格词本身不进入输出。
- 用户写「真人质感」→ 输出「耳尖鼻翼有暖红透光，皮肤有血色，发丝根根分明，眼白有自然红血丝」。
- 用户写「国漫风格」→ 输出「肤色均匀，有淡淡红晕，发丝成束，描边清晰」。

一句话总结：**风格词决定激活哪些子模块，技术词决定走哪条通道。两者都有时技术词优先；两者都没有时按风格词默认规则走。风格词本身不进入输出，只用来触发子模块调度。**

### 通道索引（数据层）
映射表文件统一放在 `channels/` 子目录，按通道名存放：
- UE5 通道 → `channels/UE5.md`（**实时渲染**；识别词：Lumen/流明、Nanite/纳米、Substrate/基底材质、VSM/虚拟阴影贴图、实时渲染）
- Arnold 通道 → `channels/Arnold.md`（**离线渲染**；识别词：Path Tracer、Standard Surface、Transmission、Caustics、Atmosphere Volume、离线渲染）
- 二次元 / 赛璐璐 → 不走渲染通道，走独立风格化输出（无 channels/ 文件）。

UE5 通道子通道（按实时渲染类目）：光照与全局光照 / 材质与着色 / 后期处理 / 体积效果 / 毛发与织物 / 角色与皮肤 / 程序化纹理 / 色彩管理 / 灯光滤镜。
Arnold 通道子通道（按自身类目）：光照 / 标准表面着色器 / 标准毛发着色器 / 皮肤 / 眼睛 / 体积与大气 / 置换与细分 / 程序化纹理 / 灯光滤镜 / 色彩管理。

新增渲染器通道时，只新增映射表（丢一个文件进 `channels/`）并注册到本索引。

### 与 `channels/` 的分工
- **`channels/` 管技术词 → 画面语言**：Lumen → "光线自然反弹"。
- **`prompt/` 管画面语言 → 可执行提示词**：公式、槽位、顺序、长度、块结构、正向锁。

先走完本模块正文的转换，再进 `prompt/` 组织形态；`prompt/` 不重新做技术决策。

## 转换原则
- 技术词转视觉结果词。
- 数值转程度词。
- 物理词转观感词。
- 只写镜头里看得见的。

模型看不见渲染管线，只看见画面效果。转的时候自问：这个技术最终在画面上长什么样。看不见的不写。

## 输出
六维逐秒行聚合成八要素：渲染规格、画幅画质、环境场景、人物外观状态、人物动作、镜头运镜构图、光影色彩、声音层。

声音层三轨分开：对白轨、音效轨、BGM轨。
- 对白用双引号包裹，标注说话者和语气。
- 无对白写「无对白」。
- 音效轨不能为空。
- 无 BGM 写「无 BGM」。

画质词直接写进末尾。4K超高清、电影质感、细节丰富、画面流畅。画质词不需要转换。

## 生成层净化
剥离内部标记：指令性括号注释、题材码编号、资产ID裸码、相邻重复语义块。净化只剥内部标记，不重写画面语言。

## 验收
逐维自问：模型能直接画出来吗。「光线自然反弹」能画，「Lumen」不能画。任何一条答不上来，回去重转。

逐秒表验收三条：零技术词残留，零数值直出，接戏点对齐。

## 交付
交付文件就是给即梦的提示词。打开就能复制粘贴，不需要再加工。

文件里只有八要素、三轨声音、画质词、负面规避词。没有档位编号，没有转换轨迹，没有验收结论，没有引擎名称，没有工程术语。

以下词一个都不能出现：**Lumen、Nanite、Arnold、UE5、PBR、SSS、ACES、85mm、f/1.4、3200K、拓扑、LOD**。

## 按模式的拼装顺序（交付文件怎么拼）

> 本模块是交付文件的**制造方**：这里回答"**怎么拼**"——包括三模式的**顺序**与本节的**形态**。拼出来**合不合格**由 13 判——见 `review/14-交付规格与合规判据.md`。
> **平台形态各有专属拼装规格**：即梦见 `platform/09-即梦交付拼装规格.md`（整段连缀 + 锚定段段首 + 负面三法）；块状脚手架（豆包 / Seedance）见 `prompt/12` 与本节。
> 平台能力事实（图片限制、时长、画幅生效范围）见 `platform/03-即梦视频生成模式与提示词规格.md`。

**三种模式不是同一份文件换个名字**——各层取舍完全不同。共同点：**全局风格前缀逐字前置一次；画质词在末尾；负面规避词殿后。**

### 一、文生视频 —— 九层顺序

```
① 全局风格前缀（逐字，来自 02）
② 主体 + 外观（资产锚定段逐字，来自 04/05）
③ 环境与空间（GEO 场景布局块逐字，来自 04/06）
④ 动作（本镜唯一主动作 + 程度副词）
⑤ 镜头（景别 + 机位 + 运镜预设名，来自 06/08）
⑥ 光影与色彩（来自 06/02）
⑦ 声音三轨（对白 / 音效 / BGM，来自 09）
⑧ 画质词（末尾）
⑨ 负面规避词
```

**唯一可指定画幅的模式**——画幅写进头部字段（`16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `21:9`）。

### 二、首帧 —— 六层顺序（②③ 整段删除）

```
① 首帧指涉句（"以输入图作为第 1 帧"）
② 变化（只写动 / 变的：动作、表情、光影变化、环境动态）
③ 镜头运动（点名预设）
④ 风格 / 氛围提示（可省——图已定调）
⑤ 声音三轨
⑥ 负面规避词
```

**硬性差异**：**②③ 两层不存在**。环境与主体外观已经在图里，**再写一遍等于给同一个主体两个互相竞争的输入**，调和过程引入漂移。本模式的字**一个都不该用**来描述"画面里本来就有"的东西。

### 三、首尾帧 —— 五层顺序（只写中段）+ 两张图提示词

```
① 首尾帧指涉句（"以图1为第 1 帧，图2为最后 1 帧"）
② 中段过渡描述（从起止状态推出中间发生了什么）
③ 镜头运动（中段）
④ 声音三轨
⑤ 负面规避词
```

**外加两份附随产物**（**由 04 产出**，不由本模块拼）：

| 附随产物 | 来源 | 硬条件 |
|----------|------|--------|
| 首帧图提示词 | 04 | 与尾帧图**同一画幅比例**；锚定段**逐字一致** |
| 尾帧图提示词 | 04 | 同上；须与首帧图属**同一连续动作的起止状态** |

**硬性差异**：两端已被两张图钉死，本模式**只写中段**。复述任一端 = 与输入图打架。

### 四、三模式对照

| 层 | 文生视频 | 首帧 | 首尾帧 |
|----|:--------:|:----:|:------:|

| 变化 / 中段 | ✅ 动作 | ✅ 只写变化 | ✅ **只写中段** |
| 镜头 | ✅ | ✅ | ✅ |
| 光影与色彩 | ✅ | ⚪ 只在变化时写 | ⚪ 只在变化时写 |
| 声音三轨 | ✅ | ✅ | ✅ |
| 画幅 | ✅ 头部字段指定 | ❌ 按输入图 | ❌ 按输入图 |
| 画质词 | ✅ 末尾 | ✅ 末尾 | ✅ 末尾 |
| 负面规避词 | ✅ 殿后 | ✅ 殿后 | ✅ 殿后 |

**口诀**：**文生视频从零写全；首帧只写变化；首尾帧只写中段。**

### 五、长度核算

| 模式 | 建议 | 硬上限 | 说明 |
|------|------|--------|------|
| 文生视频 | ≤ 400 字 | **≤ 800 字** | 九层都写，最容易超 |
| 首帧 | 明显短于 T2V | **≤ 800 字** | 砍掉 ②③ 后天然短 |
| 首尾帧 | 最短 | **≤ 800 字** | 只有中段 |

超 800 字平台直接拒收。**首帧 / 首尾帧若逼近上限，说明把图里已有的东西又写了一遍**——回查 §二 / §三 的硬性差异。

**时长按秒写，不写帧数**；交付前先确认走 **API（5s / 10s）** 还是 **UI（4–15s）**。

### 声音层输出档位（默认全量，可去配乐）

**默认全量**：**⑧对白 + ⑨背景音 + ⑩BGM** 三轨齐全，打开即成品。

**可选「去配乐」档**：拿掉 **⑩BGM**、保留 ⑧⑨，**为后期配乐留出音区**。

| 档位 | ⑧对白 | ⑨背景音 | ⑩BGM |
|------|:-----:|:-------:|:-----:|
| 全量（默认） | ✅ | ✅ | ✅ |
| 去配乐 | ✅ | ✅ | **`NO BGM`（显式抑制）** |

**去配乐不是省略 ⑩，而是把 ⑩ 写成 `NO BGM`**——即梦 Seedance 2.0 自带音效/配乐，不声明 ≠ 不生成（`09-音效/audio/03-配乐.md`：**`NO BGM` 是规格，`no music` 只是偏好**）。去配乐档**不得残留任何音乐类 token**（除 `NO BGM` 本身）。

**档位必须在交付文件头部声明**（`【声音层】全量 / 去配乐`），否则 13 无法判定。完整规则见 `prompt/32-三模式标准交付模板.md` §三之补二；合规判据见 13 `review/14` 的 G7–G9。
