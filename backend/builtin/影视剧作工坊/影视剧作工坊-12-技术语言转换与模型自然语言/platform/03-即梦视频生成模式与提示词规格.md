# 即梦视频生成 · 三模式与提示词规格

## 〇、本文件只管三件事

**本工坊最终交付的是提示词，不是 API 调用。**因此本文件只保留**决定提示词怎么写**的部分。

**只认三种模式**：**文生视频** · **首帧** · **首尾帧**。

**已剔除**（不影响提示词写法，属平台实现细节）：

| 剔除项 | 为什么剔除 |
|--------|-----------|
| **720P / 1080P 分档** | 这是 API 的 `req_key` 与输出规格分档，**不改变一个字提示词**。写提示词时无需知道走哪档 |
| **运镜模式**（`recamera`） | 运镜由 08 运镜设计的预设词承载，不构成独立输入模式 |
| 参考图 / 全能参考入口 | 见下节说明 |

> **关于参考图**：参考图生视频与首帧的**提示词写法是同一套**——都是"给一张图 + 描述变化"。区别在平台侧把图放在哪个槽位，属提交细节。本工坊在提示词层不再区分，**统一按"首帧"处理**；需要多素材组合时按平台 UI 的 `@素材名` 写职责声明即可。

## 一、三种模式

| 模式 | 输入图 | 图在视频中的时间位置 | 提示词写什么 |
|------|--------|---------------------|--------------|
| **文生视频** | 无 | — | 从零描述整场：主体 + 环境 + 动作 + 镜头 + 风格 |
| **首帧** | **1 张** | **第 1 帧** | **只写变化**——绝不重新描述图里已有的内容 |
| **首尾帧** | **2 张**（首帧 + 尾帧） | **第 1 帧 / 最后 1 帧** | **只写中段**——两端已被图钉死 |

**共同铁律**：首帧与首尾帧模式下，**重新描述图中已有内容等于给同一个主体两个互相竞争的输入**，调和过程引入漂移。起点已经确定了，就只说明"接下来发生什么"。

## 二、首尾帧：由 04 在链内产出「单帧图提示词」

**这是本文件最重要的一条流程约定。**

04 场景与人物设计**走进全链路时，产出就是「单帧图」**（单张、完整画面），标准格式见其 `characters/19` 十槽位。**首帧图 / 尾帧图是「单帧图」在链内的两个实例**——不新增环节、不新增模块。

若某镜走**首尾帧生视频**，由 04 在链内直接产出**两张单帧图提示词**：

```
导演链路行进中（到 07 镜头链定稿）
        ↓
04 场景与人物设计 · 主链内触发
        ↓ 直接产出两个单帧图提示词：
   ① 首帧图 —— 视频第 1 帧（单帧图格式）
   ② 尾帧图 —— 视频最后 1 帧（单帧图格式）
        ↓
   拿去生图 → 得到两张图
        ↓
首帧图 + 尾帧图 + 视频提示词 → 首尾帧生视频
```

**三条硬性衔接条件**（缺一条首尾帧就跑不成）：

1. **两张图必须同一画幅比例**——比例不一致在提交阶段直接失败。**比例在生图阶段就定死**，视频阶段补救不了。
2. **两张图必须是同一连续动作的起止状态**——不是两个无关画面。起止状态不连续时，中段会漂移到"能同时接住两端"的折中画面。
3. **两张图的人物/场景锚定段逐字一致**——只有状态与姿态不同；外貌描述必须完全相同，否则两端人物对不上。

**归属**：这两条提示词走 04 的**单帧图触发流程**（`characters/19` 标准格式 + `scenes/11-场景提示词模板.md`），**不新增模块、不新增技能**。视频提示词本身仍由 12 装配。

## 三、提示词规格（硬约束）

### 3.1 图片（首帧 / 首尾帧模式）

| 约束项 | 值 |
|--------|-----|
| 格式 | **仅 JPEG、PNG** |
| 单图大小 | **≤ 4.7 MB** |
| 分辨率 | **≤ 4096×4096**，且**最短边 ≥ 320** |
| 长短边比例 | **≤ 3**（最极端 3:1，超过拒收） |
| 图数量 | 首帧 = **1 张**；首尾帧 = **2 张** |
| **首尾帧专项** | **尾帧图必须与首帧图比例相同** |

### 3.2 时长

| 口径 | 值 |
|------|-----|
| API 口径 | **帧数 = 24 × n + 1**（24 fps）；可选 `121` = 5s、`241` = 10s |
| UI 口径 | 可在 **4–15s** 内自由选择，≤ 15s |
| **提示词层的处理** | 写**秒数**即可（"5 秒""10 秒"）；**不要写帧数**——帧数是提交参数，不是画面语言 |

> ⚠️ **交付前必须先确认走 API 还是走 UI**：API 只开放 5s / 10s 两档，UI 开放 4–15s 连续区间。按 UI 写了 8 秒、实际走 API，该镜直接不成立。

### 3.3 画幅（链路级硬规则）

| 约束项 | 值 |
|--------|-----|
| 可选比例 | `16:9` · `4:3` · `1:1` · `3:4` · `9:16` · `21:9` |
| **生效范围** | ⚠️ **仅文生视频可指定**。**首帧 / 首尾帧按输入图自动匹配最接近的比例** |

> **推论——写提示词前就要定死**：走首帧或首尾帧时，**画幅在出图阶段就被锁死了**。要 9:16 竖屏成片，**首帧图与尾帧图就必须已经是 9:16**。这一条联动 04（单帧图）与 06 `shotlang/03-构图.md`（画幅两条不可混为一谈）。

### 3.4 提示词长度

| 约束项 | 值 |
|--------|-----|
| 语言 | 中英文均可 |
| **建议长度** | **≤ 400 字** |
| **硬上限** | **≤ 800 字** |

> 与 `prompt/12-提示词结构.md` §3.1 的"50–80 词最佳区间"不冲突：那是**连贯性最优点**，这是**平台拒收线**。越过 800 字连提交都不成立。

## 四、模式路由

```
这张画面需要一张已存在的图作为起点吗？
├─ 不需要 → 文生视频
│            画幅用 aspect_ratio 显式指定（唯一能指定画幅的模式）
└─ 需要 → 起点数量？
    ├─ 只要起点（1 张图）→ 首帧
    │    提示词：只写变化
    └─ 要精确的起止两端（转场 / 变形 / A→B 状态迁移，2 张图）→ 首尾帧
         提示词：只写中段
         → 先由 04 出「首帧图提示词 + 尾帧图提示词」（§二）
```

**选模式的落地判据**：

| 情形 | 选 | 理由 |
|------|-----|------|
| 无任何素材 | 文生视频 | 唯一能自由指定画幅的模式 |
| 已有定妆图，动作简单 | 首帧 | 起点确定，成本最低 |
| 要做精确转场 / 变形 / 状态迁移 | 首尾帧 | 两端都被钉死，中段不会乱跑 |
| 要复杂动作或换场景 | 首帧（图只作起点），动作写进提示词 | 详见 `prompt/14-seedance导演.md` 的续接与扩展公式 |

## 五、交付前自检（严格，逐项）

**通用**
- [ ] 模式已明确是**文生视频 / 首帧 / 首尾帧**之一？
- [ ] 提示词 **≤ 800 字**（建议 ≤ 400）？
- [ ] 时长按**秒**写，且已确认走 **API（5s/10s）** 还是 **UI（4–15s）**？
- [ ] 提示词**没有写帧数**（帧数是提交参数，不是画面语言）？

**首帧模式专项**
- [ ] 提示词**没有重新描述图里已有的内容**？
- [ ] 只说明了"接下来发生什么"？

**首尾帧模式专项**
- [ ] **已由 04 产出首帧图提示词与尾帧图提示词**？
- [ ] 两图**画幅比例相同**？
- [ ] 两图属于**同一连续动作的起止状态**？
- [ ] 两图的**人物/场景锚定段逐字一致**（只有状态与姿态不同）？
- [ ] 两图的**人物外貌描述完全相同**？
- [ ] 视频提示词**只写中段**，没有复述两端的画面？

**图片合规**
- [ ] JPEG/PNG、≤ 4.7MB、≤ 4096×4096、最短边 ≥ 320、长短边比 ≤ 3？
