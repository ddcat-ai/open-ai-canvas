| 套餐要求 | 全套餐 | 全套餐 | **仅商业/团队套餐** | 本版未单独验证套餐可用性——见 Higgsfield 套餐文档 |

**何时用 Cinema Studio：**
- 需要 2 个以上镜头且必须像同一部片子
- 角色几何必须跨剪切锁定
- 要专业光学物理（镜头耀斑、景深、传感器颗粒）——仅 2.5
- 在做短片、品牌内容或任何长于一条片段的序列

**何时留在标准生成：**
- 单条片段就够
- 速度比一致性重要
- 在正式投入完整序列前探索点子

## ⚠ 版本探测——先问

**生成任何 Cinema Studio 输出之前，务必问用户：**

> 你在用 **Cinema Studio 2.5** 还是 **Cinema Studio 3.0**？

如果用户已说明版本（如"我用 3.0"或"Cinema Studio 3.0"），记住它，不要再问。但绝不假设——2.5 与 3.0 的功能集根本不同。

**为什么这很重要：**
- 2.5 有光学物理（机身+镜头组栈）、调色、3D 模式、网格生成
- 3.0 **全都没有**——输出这些是浪费用户时间并制造混乱
- 3.0 有 2.5 没有的：原生音频、Smart 智能镜头控制、21:9 超宽、15s 时长
- 两版的 Speed Ramp 选项不同
- 两版的类型清单不同

**版本已知后，只用该版本的输出格式与功能集。** 绝不把一个版本的功能混进另一个版本的输出。

## Cinema Studio 2.5 十步工作流

Cinema Studio 2.5 把管线向两头延伸：生成之前的**前期**（Soul Cast + 场景提示词），生成之后的**后期**（调色）。

```
 1. SCRIPT 剧本       → 写好或粘贴场景描述 / 镜头清单
 2. SOUL CAST         → （2.5 新增）由参数生成 AI 演员，或使用已存元素
 3. REFERENCE 参考     → 上传角色照片 → 创建 Reference Anchor（或用 Soul Cast 演员）
 4. ELEMENTS 元素      → （可选）按需定义 @Characters、@Locations、@Props
 5. OPTICAL STACK 光学栈 → 选择机身 + 镜头 + 焦距 + 光圈（图像模式）
 6. HERO FRAME 英雄帧  → 生成一张定义视觉基调的关键图
 7. COLOR GRADE 调色   → （2.5 新增）在视频生成前对关键帧调色
 8. CAMERA CONFIG 相机配置 → 在 UI 中设 Director Panel 运镜 + Speed Ramp + 时长
 9. SHOT MODE 镜头模式  → 选 Single Shot / Multi-Shot Auto / Multi-Shot Manual
10. GENERATE 生成 → EXPORT 导出 → 接入时间线或导出至剪辑
```

## 元素系统——定义一次，处处调用

元素（Elements）是 Cinema Studio 的可复用资产库。角色、场景或道具创建一次，之后在任何提示词里用 `@` 引用。

**三种元素类型：**

| 类型 | 存什么 | 调用方式 |
|------|---------------|-----------|
| Character 角色 | 人物、外观、服装 | `@CharacterName` |
| Location 场景 | 环境、场地、氛围 | `@LocationName` |
| Prop 道具 | 物件、载具、特定物品 | `@PropName` |

**创建工作流：**
1. 打开 Elements 面板 → 新建元素 → 选类型
2. 上传参考图
3. 给元素命名（它就成为 `@` 标签）
4. 加描述（外观细节、关键特征）
5. 保存 → 现在起本项目中所有镜头都可用

**逐角色情绪：** 多镜头模式下，每个角色可设**逐场景的情绪**。可用情绪：

| 情绪 | 效果 |
|---------|--------|
| Joy 喜 | 微笑、温暖表情、积极能量 |
| Fear 惧 | 瞪眼、紧绷姿态、防御性身体语言 |
| Surprise 惊 | 挑眉、张嘴、警觉站姿 |
| Sadness 悲 | 垂眼、垮塌姿态、收敛能量 |

在 UI 中逐角色逐场景设情绪——把表情变化从提示词字段里挪出去，让模型处理面部动画的微妙处。

**@ 标签规则——只用用户给的，一个不多**
只对用户在本轮对话中明确给出的元素使用 @ 标签。
如果用户给了 `@Marcus` 但没给场景或道具标签，就把场景和道具写成普通描述。绝不替用户没点名的东西发明或假设 @ 标签。
用户给的每个 @ 标签 = 该元素已就位。沉默 = 没有。

**未提供元素——全部写成描述：**
```
一位深色头发、穿红大衣的女人在深夜走过市中心窄巷。
她拎着一只磨损的皮公文包。她在路灯下停住，转向镜头。
```

**用户只给了 @Sarah——用它，其余描述：**
```
@Sarah 在深夜走过市中心窄巷。
她拎着一只磨损的皮公文包。她在路灯下停住，转向镜头。
```

**用户给了 @Sarah、@DowntownAlley、@LeatherBriefcase——三个全用：**
```
@Sarah 走过 @DowntownAlley，拎着 @LeatherBriefcase。
她在路灯下停住，转向镜头。
```

**关键规则：** 与用户给的严格一致。不多，不少。
用户给的标签 = 元素存在。其他一切 = 写成描述。

### 元素库界面——来源页签与分类

`@` 符号打开统一的资产选择器。选择器是二维结构：顶部是来源页签（资产从哪来），Elements 页签内是元素分类（项目资产如何分组）。

**来源页签（5 个）：**

| 页签 | 里有什么 |
|-----|--------------|
| **Uploads 上传** | 用户直接带来的资产——原始照片、底板、道具照 |
| **Image Generations 图像生成** | 可引用的历史生成静帧（用于跨镜头自引用连续性——把某次生成里出现的特定造型或姿态拉回新一次生成） |
| **Video Generations 视频生成** | 可引用的历史生成片段（用于镜头记忆或运动参考——把上一条片段的取景或运动喂回新一次生成） |
| **Elements 元素** | 项目库中精选/已存资产——连续性的主阵地 |
| **Liked 收藏** | 选择器内所有已收藏资产——常用参考快速调取 |

**Elements 页签内的元素分类（6 个）：**

| 分类 | 分组内容 |
|----------|----------------|
| **All 全部** | 项目中的一切 |
| **Pinned 钉选** | 本项目中置顶速取——用户当前序列的工作集 |
| **Shared 共享** | 跨协作者或跨语境可用（具体共享范围由平台管理） |
| **Characters 角色** | 身份参考——人物、面孔、演员 |
| **Locations 场景** | 环境参考——室内、外景、场地 |
| **Props 道具** | 物件参考——载具、道具、置景件 |

先生成库再生成内容。对有循环角色、场景或道具的项目——短片、系列品牌视频、多镜头序列——先把每个循环资产建成元素，之后每个镜头用 `@` 引用。这就是 Reference-Based Prompt Mode（参考驱动提示模式）纪律的平台原生实现：带角色的参考，而非当灵感用的参考。见 `../higgsfield-seedance/SKILL.md` 的 Reference-Based Prompt Mode 纪律，以及本节前文"@ 标签规则——只用用户给的"关于提示词内部如何用 @ 标签的指引。

**跨镜头连续性技巧。** 续接工作时，**Image Generations** 与 **Video Generations** 来源页签让你引用同一项目的先前输出——当角色元素捕捉不到某次特定生成里出现的造型或姿态时很有用。从 Generations 页签拉回精确帧，而不是从零重写提示词。

## Soul Cast——AI 演员生成

Soul Cast 是 Cinema Studio 2.5 的角色生成系统——用参数造 AI 演员，不用上传照片。它与 Soul ID 有本质区别。

### Soul Cast 与 Soul ID 对比

| | Soul Cast | Soul ID |
|--|-----------|---------|
| 输入 | 参数选择 | 真人 20+ 张照片 |
| 用途 | 从零生成 AI 演员 | 维持已知面孔的一致性 |
| 需要照片 | 否 | 是 |
| 底层模型 | Nano Banana 2 | — |

### Soul Cast 参数类别（共 8 类）

| # | 类别 | 选项 |
|---|----------|---------|
| 1 | **Genre 类型** | 动作、冒险、喜剧、剧情、惊悚、恐怖、侦探、爱情、科幻、奇幻、战争、西部、历史、情景喜剧（14 项） |
| 2 | **Budget 制作预算** | 制作预算滑杆（百万美元）——高=精制大片感，低=生猛粗粝 |
| 3 | **Era 年代** | 自 1900s 起按十年选择——把角色锚进正确时代 |
| 4 | **Archetype 原型** | 天真者、普通人、英雄、照料者、探索者、反叛者、恋人、创造者、弄臣、智者、魔法师、统治者（12 项） |
| 5 | **Identity 身份** | 性别、种族、年龄 |
| 6 | **Physical Appearance 外观** | 身高、眼色、发型、胡须等 |
| 7 | **Details 细节** | 疤、纹身、雀斑、其他不完美 |
| 8 | **Outfit 服装** | 休闲、正装、高级时装、军装、运动、工装、复古（7 风格） |

### 关键特性

- 每个关键帧最多加 **3 个 Soul Cast 角色**——从已存元素选或现场生成
- **"保存到元素"**按钮——跨项目复用某个 Soul Cast 演员
- 每个演员自动生成**背景故事 + 角色卡**（性格特质、动机、恐惧、缺陷、强项）
- 为消灭"塑料/蜡像"AI 感而生——强项是**皮肤质感与情绪**
- 底层由 **Nano Banana 2** 模型驱动

### Soul Cast 工作流

```
1. 打开 Cinema Studio → 进入 Soul Cast 面板
2. 设 类型 + 年代 + 预算，确立视觉世界
3. 选 原型 + 身份 + 外观
4. 加 细节（不完美）+ 服装
5. 生成 → 审阅背景故事 + 角色卡
6. 保存到元素 → 从此以 @CharacterName 在所有镜头可用
7. 重复以添加更多角色（每个关键帧最多 3 个）
```

## 内置调色套件

Cinema Studio 2.5 新增后期调色套件，在视频生成**之前**施加于关键帧——让所有片段获得统一的视觉内聚。

### 控制项

| 控制项 | 效果 |
|---------|--------|
| 色温 | 暖 ↔ 冷偏移 |
| 对比 | 阴影/高光分离 |
| 饱和度 | 色彩强度 |
| 锐度 + 效果 | 细节增强 |
| 高光 | 亮部控制 |
| 胶片颗粒 | 模拟质感叠加 |
| 曝光 | 整体亮度 |
| Bloom 光晕 | 高光发光/漫射 |

### 工作流

1. 生成关键帧图（Hero Frame 或网格挑选）
2. 点关键帧 → **"Colorgrade"**按钮
3. 按口味调参
4. 应用——调色在视频生成前烘焙进关键帧
5. 对每个关键帧重复，维持序列视觉内聚

**技巧：** 先调 Hero Frame，之后的关键帧向它看齐。
这就是片场 DIT（数字影像工程师）的后期等价物。

## 光学物理引擎

Cinema Studio 的图像模式给你完整的机身+镜头组栈。这些是**UI 里的确切名称**（旧版名称有误——此处已修正）。

**Claude 在写 Cinema Studio 图像提示词时的职责：** 永远推荐一个具体的光学组栈——机身+镜头+焦距+光圈——并附一行理由。绝不留空，也绝不说"按喜好选"。要做判断。

---

### 按意图推荐光学组栈

用用户的创作意图选组栈。最重要的信号是**这张图要有什么感觉**——而不只是类型。

#### 人像 / 角色聚焦

## 镜头模式

### Single Shot 单镜头
标准生成——一条提示词一条片段。与普通 Higgsfield 相同，但施加光学组栈与 Director Panel。

### Multi-Shot Auto 自动多镜头
一条提示词描述整个序列。Cinema Studio 自动拆镜。
适用：粗排序列、探索、不需要逐镜控制时。

```
示例："一个女人走进酒吧，坐下，点了杯酒。酒保滑过来。
她抿了一口，盯着瓶子后面镜子里的自己。"
→ Cinema Studio Auto 生成：建立镜头 / 走向座位 / 点单 / 上酒 / 镜像特写
```

### Multi-Shot Manual 手动多镜头
逐场景全控。最多 6 个场景，每个场景自带：
- 提示词
- 运镜（Director Panel）
- Speed Ramp
- 时长

**⚠ 12 秒总时长硬帽：** Multi-Shot 序列中所有场景时长合计不得超过 **12 秒**。逐场景时长规划要落在此限内（如 6 场景 × 2s、4 场景 × 3s、3 场景 × 4s）。

**成本透明：** 手动多镜头出 4 个变体 = **共 24 次生成**（6 场景 × 4 变体）。据此规划 credits。

**手动多镜头工作流：**
1. 场景 1：建立镜头——广角、立场景
2. 场景 2：角色引入——中景、出主角
3. 场景 3：动作节拍——更近、有运动
4. 场景 4：反应——特写、情绪
5. 场景 5：后果 / 转折——中景或广角
6. 场景 6：收束 / 点睛——看情况

**Morph-Cut 与 Smooth-Cut 的呼吸空间——2 秒静滞时刻。** 剪辑师把变形切（morph cut）与平滑切（smooth cut，DaVinci Resolve、Premiere 等剪辑器里通过形变相似帧隐藏剪切的转场风格）落在静止上，不落在运动上。如果每个镜头都在动作中途开始和结束，镜头间的每个剪切也都得发生在动作中途——而模型渲染动作中途的转场很差。按"每个镜头的**开头**和**结尾**各提示一个显式的 2 秒静止或近静止时刻"来造出好剪的素材。可造的静止示例：一个持住的凝视、一个定格的姿态、动作开始前的持住停顿、动作停止后的屏息。镜头中段可以随剧本要多动感有多动感；边界挣得剪切。本规则改编自 Mr. Core 方法论，与 `../higgsfield-pipeline/SKILL.md` § Stage 8 — Assembly 的剪辑侧工作流配对。

## Reference Anchor（参考锚）系统

Reference Anchor 把角色几何（面部结构、比例、服装剪影）锁进序列中所有镜头——防止标准生成里发生的角色漂移。

**设置：**
1. 上传一张清晰、布光好的角色参考照
2. Cinema Studio 由它生成锚点
3. 项目中后续每个镜头都引用该锚点
4. 与 Soul ID 组合可全锁面部 + 几何

**最佳实践：**
- 锚点用正面、中性表情的照片
- 锚图避免眼镜、帽子或不常戴的配饰
- 每角色一个 Reference Anchor——有群演就加多个
- 锚点在整个 Cinema Studio 项目中持续存在

## 位置参考表

场景值得与角色同等的"资产先行"待遇。如果一个房间、小巷、车内或外景会跨多个镜头反复出现，就把它作为独立资产生成一次并复用——不要在每个场景提示词里重新描述。逐场景重述是"每个镜头都在重新发明环境"这一失败的根因：墙会漂、家具会重新排布、尺度会变，世界不再像一个地方。

### 开拍这个空间之前先植入视觉锚物

`[FIELD — Higgsfield Studio, ADILIADA breakdown, 2026-08-14]` 位置表阻止房间被*重新发明*；但它本身拦不住人**在里面走来走去**。便宜的补充是刻意预植几件固定、独特的物体，然后围绕它们走位：角色坐的椅子、两人靠窗对话的窗、要穿过的珠帘。它们给模型可命名的东西，跨代挂住位置；也给你走位语言——"在窗边，画面左侧"是可核查的，"在房间左边"不是。

选**独特且不可移动**的锚物。第二把一模一样的椅子不是锚，是歧义。

**生成任何东西之前先把各底板互相校准。** 要互切的场景在资产阶段就互相匹配色彩、光与饱和度，这样镜头开始落地时场景们已经在性格上互相认同——否则每次生成都继承一个略有差异的世界，错配只在剪辑里浮出水面，那时就成了 `../higgsfield-pipeline/SKILL.md` § The Edit's unification problem，要靠调色去解。

### 五视图位置表

位置表从足够多的角度捕捉空间，让模型有完整的空间模型可取用。把这五个视图作为一组资产生成：

| 视图 | 锁什么 |
|------|---------------|
| 正面全景 | 整体尺度、焦点、地平线 |
| 左角透视 | 侧面几何、左侧纵深 |
| 右角透视 | 侧面几何、右侧纵深 |
| 反向 / 对面视图 | 广角中相机背后是什么——补全 360° 足迹 |
| 环境细节特写 | 质感、磨损、招牌、锚定身份的小道具 |

用 Grid Generation（2×2 或 4×4）或 3D 模式从一张 hero 全景生成备角——这保持各视图光与材质身份一致，这正是全部意义所在。

### 复用时要保住什么

把场景带回来拍新镜头时，锁这四样属性：建筑（墙、开口、尺度）、光质（来源方向、色温、软硬）、色彩处理（调色板、调色）、关键环境细节（招牌、破损、让此地成为此地的那几件道具）。这些不进场景提示词——它们住在位置资产里。场景提示词只描述变化：角色动作、相机行为、大气运动、时段变化（若有）。

### 这防止的失败模式

没有位置表，一个设定在"雨夜小巷"的六场景序列会渲染出六条不同的巷子。每个场景提示词都从零重新解释"雨夜小巷"。有位置表并标为 @ 元素或作为参考加载后，六个场景共享同一条巷子——水洼在同样的位置、霓虹招牌写着同样的字、砖墙是同样的纹路。

与位置揭示配对的镜头词汇（Pan、Crane、Dolly Reveal），见 `../../vocab.md`。

## 参考表类型——角色与场景之外

参考表不只服务于脸和房间。底层原则比"角色或场景"更窄——参考表是任何一次性建成、用来**锁定生产某个特定属性**的资产。每种表固定工作的一个不同轴：身份、建筑、运动行为、服装、调色板、产品。某属性需要跨多个镜头一致成立，就给它单独一张表；只在一个镜头里有意义，就内联写掉，继续往前。

**一张表何时回本：** 某属性会出现在三个以上镜头里，表就比每次重述更省，且比只靠提示词文本一致得多。单镜头细节——一次性道具、背景群演、一次性灯光点——不值得建表。

角色表（见 `../higgsfield-soul/SKILL.md` → Character Sheet Creation）与上面的位置参考表已覆盖身份与建筑。以下三种表把同一模式扩展到生产的其余部分：

### 调色板 / 情绪表

项目的色彩与色调锚。把整部片子的视觉情绪锁在一张表上：阴影密度、光比、饱和度、签名点缀色、调色方向。与 Soul Hex 色彩系统及 `../higgsfield-moodboard/SKILL.md` 的情绪板配对使用。
其用途细节：阴影密度、主光/补光比、饱和度水平、签名点缀色、调色方向。用一张精选静帧或一小格调色参考——目标是给每一次后续生成一个一致的调色板去够。

用例：黑色电影里每个场景共享同样的阴影密度与暖琥珀压冷蓝的调色；赛博朋克序列里霓虹对基础光的比值跨 15 个剪切保持不变；品牌战役里签名点缀色无论主体是什么都出现在每个镜头里。与 Soul Hex 色彩系统及 `../higgsfield-moodboard/SKILL.md` 的精选情绪板天然配对。

### 产品参考表

当产品跨多个镜头反复出现——品牌战役里的 hero SKU、叙事片里的循环道具、电商里一个商品从十几个角度拍——给它与角色或场景同等的"资产先行"待遇。把产品作为多视图参考表生成一次，后续镜头调用它。在每个场景提示词里重述产品，是"每个镜头都在重新解释产品"的根因：品牌标识漂移、材质走样、几何重新排布，hero 商品不再像一个物件。

产品参考表用 7 段提示词脚手架。每段固定产品身份的一个轴。按顺序搭建——锁先行，然后构图，然后表面处理，然后采集参数，然后负空间。

**1. 身份锁（Identity Lock）**——产品*是什么*。几何、尺度、色彩值、定义性比例、区别性物理特征。与角色表身份块同一纪律，施加于物件。

**2. 品牌锁（Branding Lock）**——产品上每个品牌元素的位置、尺度、色彩与处理：logo、字标、吊牌、缝制标签、压印标记。写明相对产品几何的位置（前幅正中、左袖、右下角）与渲染工艺（刺绣、丝印、压印、烫金）。

**3. 布局（Layout）**——多视图网格。标准产品参考表布局覆盖八正交视图加微距特写：

| 视图 | 锁什么 |
|------|---------------|
| 正面 | 主读——品牌位置、整体剪影 |
| 背面 | 反面细节、次要品牌、结构缝线 |
| 左侧 | 侧视几何、左侧纵深 |
| 右侧 | 侧视几何、右侧纵深 |
| 顶部 | 俯视剪影、帽冠/盖/开口几何 |
| 底部 | 底面细节、底座/鞋底/足迹 |
| 3/4 视角 | hero 角度——合并正面与侧面读法 |
| 微距特写 | 品牌细节 / 材质织法 / 结构接缝 / 任何配得上独立一帧的产品专属细节 |

八视图对五视图位置表的五视图——产品比场景需要更多正交角度，因为相机更近、几何即主体而非环境。微距特写是位置表"环境细节特写"视图的产品对应物，放大到每个产品专属关注点各一帧。

**4. 背景（Background）**——`#DCDCDC` 浅灰、无影布光、无渐变、无反光。棚拍产品照惯例：背景贡献零视觉信息，产品读作唯一主体。四条约束全写——只写 `#DCDCDC` 而不带无影+无渐变+无反光三件套，仍给模型留了加氛围噪声的余地。

**5. 写实（Realism）**——材质写实块。按材质填充的可复用模板；六个轴合起来让表面读起来可触、物理落地，而非渲染出来的平板：

- **凸起结构（Raised structure）**——什么从基底表面凸起、凸多少
- **紧密密度（Tight density）**——表面元素在单位面积内排得多密
- **可见方向（Visible direction）**——纹理、织法、线迹或流动在表面上的方向性
- **微阴影（Micro shadowing）**——凸起元素投进表面凹谷的小阴影
- **随形压缩（Surface compression following form）**——材质在接缝、边缘或附着件处的形变
- **曲率整合（Curvature integration）**——表面及其纹理如何跟随产品整体几何，而非浮在它上面

六个轴用材质专属词汇填充。刺绣、皮革、针织、缎面、拉丝金属、麂皮各有自己的值集；六轴不变。

**6. 相机（Camera）**——默认产品参考相机包：**Canon EOS R5 + RF 100mm f/2.8L Macro IS USM，f/8，ISO 100**。100mm 微距在 f/8 下让整个产品从最前缘到最后缘在全部八视图里保持锐利合焦；ISO 100 把传感器噪点挡在灰背景之外。只在特定镜头需要不同读法时替换——如 hero 品牌细节微距要浅景深（f/4），或超大产品要更广焦段（RF 50mm）。

**7. 限制（Restrictions）**——内容保真块。产品参考表的职责是捕捉真实产品，不是风格化或重新诠释版。这一块告诉模型对源物**不许**做什么：不重设计、不重释品牌、不美化、不加造型。取景纪律（无环境语境、无道具）也在此作为内容保真意图的一部分强制执行；第 4 节的背景/灯光约束管自己那摊，不在此重复。

- 不重设计
- 不风格化
- 不重新诠释品牌
- 不添加元素
- 不换用品牌
- 不加 logo
- 不加文字浮层
- 不加道具
- 不加环境
- 不加灯光效果
- 不磨皮或美化
- 不修容

产品参考表锁定产品；产品的叙事化使用发生在下游调用该表作参考的场景提示词里。

#### 帽子——完整示例

一顶带刺绣 logo 的黑色棒球帽，按产品参考表搭建：

- **身份锁**——六片式棒球帽、黑色棉斜纹、弯帽檐、可调搭扣、预弯帽冠、每片气眼
- **品牌锁**——刺绣字标居中于前幅、白线、宽 4cm、位于帽檐缝上方 3cm
- **布局**——正面/背面/左/右/顶/底/3-4 视角，另加刺绣字标、片缝、搭扣的微距特写
- **背景**——`#DCDCDC` 浅灰、无影布光、无渐变、无反光
- **写实（材质写实按刺绣填充）：**
  - 凸起结构——线迹凸起结构，线浮于棉斜纹基底之上
  - 紧密密度——每个字形上线迹密度紧密
  - 可见方向——线迹方向沿每个字母的笔画路径可见
  - 微阴影——线行之间针脚凹谷中的微阴影
  - 随形压缩——线张力拉扯斜纹处、缝线周围的织物压缩
  - 曲率整合——刺绣曲率跟随预弯前幅，而非平板铺开
- **相机**——Canon EOS R5，RF 100mm f/2.8L Macro IS USM，f/8，ISO 100
- **限制**——不重设计、不风格化、不重释品牌、不添元素、不磨皮美化

皮革 / 针织 / 缎面 / 拉丝金属 / 麂皮 hero 产品：把材质写实块的刺绣词汇换成该材质在六轴上的自有值集——脚手架完全相同。

## Hero Frame（英雄帧）

Hero Frame 是你在投入视频前生成的一张关键图——它定义序列的视觉基调、灯光、色彩与构图。

**为什么重要：** 先出 Hero Frame 约花 1 credit。生成后改视频要花全价视频 credits。先把 look 在图上做对。

**Hero Frame 工作流：**
1. 带完整光学组栈描述你的开场镜头
2. 生成图像（Soul 2.0 或 Nano Banana 2）
3. 审：灯光对吗？色彩？角色 look？
4. 在图上迭代到完全正确
5. 用作视频生成的首帧 / 风格参考

**Hero Frame 作为风格锁：**
拿到心仪的 Hero Frame 后，把它作为参考上传给你的第一条视频镜头。在提示词里用氛围与灯光语言描述匹配——不用相机/类型指令（那些进 UI 设置）：
```
与参考图同样的阴天正午光。
收敛、降饱和的色调。角色从画面左侧进入。
```

## Higgsfield Popcorn（爆米花）——故事板集成

Popcorn 是 Higgsfield 的故事板工具。在投入 Cinema Studio 生成之前，先用它把序列视觉化。

**Popcorn → Cinema Studio 工作流：**
1. 打开 Popcorn → 描述你的故事 / 场景拆解
2. Popcorn 生成带镜头描述的视觉故事板
3. 审镜头顺序、机位角度、关键时刻
4. 导出故事板 → 导入 Cinema Studio 作镜头清单
5. 配置每个镜头：光学组栈、Director Panel、Speed Ramp
6. 以 Multi-Shot Manual 模式生成，故事板即剧本

**何时先上 Popcorn：**
- 任何超过 3 个镜头的序列
- 镜头顺序没把握时
- 客户或协作者需要在生成前批准结构
- 多机位角度的复杂动作序列

## 关键帧插值——首/尾帧

精确定义镜头从哪开始、到哪结束。消除模型瞎猜过渡时出现的形变伪影。

**设置：**
- **首帧（Start Frame）**：上传或生成镜头的第一帧
- **尾帧（End Frame）**：上传或生成镜头的最后一帧
- Cinema Studio 在二者之间插值运动

**最佳用途：**
- 精确的角色入场 / 退场
- 起止位置精确的物件揭示
- 镜头间匹配剪辑（A 镜尾帧 = B 镜首帧）
- 位置必须精确的受控运镜

## 3D 模式——高斯泼溅

Cinema Studio 能用高斯泼溅给**任一生成图建 3D 版**。激活后你可以在画面里移动——变透视、环绕场景，找到原始 2D 生成里不存在的构图。

**怎么用：**
1. 在 Cinema Studio 生成一张图（任意模型、任意光学组栈）
2. 对生成图激活 3D 模式
3. Cinema Studio 把场景重建为 3D 高斯泼溅
4. 用虚拟相机自由移动——环绕、推近、变角
5. 把满意的构图捕为新帧
6. 用该帧作视频生成的首帧

**何时用 3D 模式：**
- 生成很满意但想要别的机位角度
- 同一场景需要反打或过肩
- 在静态场景里构建虚拟运镜
- 投入视频前想探索视差与景深

**工作流技巧：** 生成 Hero Frame → 进 3D 模式 → 找 2–3 个不同角度 → 每个角度作 Multi-Shot Manual 序列中不同镜头的首帧。一次生成变多个镜头。

## 网格生成——批量变体

不用一张一张出图，Cinema Studio 可以产出 **2×2、3×3 或 4×4 网格**——单次生成最多 16 个变体，只按一个 credit 计费。

**网格规格：**
| 网格 | 变体数 | 成本 |
|------|-----------|------|
| 2×2 | 4 图 | 1 生成 credit |
| 3×3 | 9 图 | 1 生成 credit |
| 4×4 | 16 图 | 1 生成 credit |

**何时用网格生成：**
- 探索构图——出 16 个选项挑最好的
- 角色表创建——一遍出多姿态/多角度
- 投入视频前对视觉方向做 A/B
- 省钱迭代——花 1 credit 得最多 16 个选项

**网格工作流：**
1. 写提示词 + 配光学组栈
2. 选网格规格（2×2 到 4×4）
3. 生成——所有变体自动聚组呈现
4. 挑最好的变体
5. 用作 Hero Frame、首帧，或对任一单独结果进 3D 模式

## 分辨率设置

Cinema Studio 支持图像生成的显式分辨率控制：

| 设置 | 分辨率 | 最佳用途 |
|---------|-----------|----------|
| 1K | 1024px | 快迭代、概念探索 |
| 2K | 2048px | 标准质量、多数工作流 |
| 4K | 4096px | 最终交付、印刷、hero 资产 |

**经验法则：** 探索与网格生成从 1K–2K 起步。只对最终选定的构图切 4K。分辨率越高=生成时间越长、credits 越多。

## 帧提取循环——生成、动画、提取、重复

Cinema Studio 2.5 最强的工作流之一是**帧提取循环**。你可以从任一生成的视频里提取**首帧或尾帧**，喂回图像工作流——形成迭代创作循环。

**循环：**
```
1. 生成图像 → Hero Frame 或网格挑选
2. 动画化    → 把图变成视频（任意模型）
3. 提取帧    → 从视频拉出首帧或尾帧
4. 喂回      → 用提取帧作新的起始图
5. 重复      → 从新起点再次动画化
```

**为什么重要：**
- 视频的尾帧常产出你直接提示不出的构图
- 提取帧自带模型物理——自然运动模糊、重量、动量
- 链式 提取→动画 造就有机的视觉演化
- A 镜尾帧变 B 镜首帧——无缝连续

**最佳用途：**
- 不用多镜头模式也能搭出连贯的长序列
- 从模型生成的端点发现意外构图
- 造变形序列（角色变老、日夜转换等）
- 用提取帧作锚做场景间匹配剪辑

## 物件与人物插入

Cinema Studio 2.5 能把原始首帧里**不存在的角色与物件插入场景**。这在以前基本不可能——模型会无视新主体，或为塞进它们而弄坏场景。

**怎么用：**
1. 生成或上传基础场景（环境）
2. 在提示词里描述进入场景的角色或物件
3. Cinema Studio 把新主体合成进既有环境
4. 插入尊重原场景的灯光、透视与尺度

**最适合：**
- 加一个走入建立镜头的角色
- 把道具或载具放进既有环境
- 跨多次生成逐步堆高场景复杂度
- "如果"式探索——同一场景换不同主体

**插入提示词模式：**
```
[简述既有场景]。一个穿深色大衣的男人从画面左侧进入，
走向中心。他拎着一只公文包。
```

## Clustering——自动生成聚组

同一提示词的所有生成在 Cinema Studio 界面里**自动聚组**（归为一组）。这意味着：

- 网格生成的每个变体都留在同一个视觉组里
- 同一提示词的迭代重生成易于对比
- 长项目无需手动文件夹管理也保持有序
- 快速扫各簇，从每个提示词里挑出最佳结果

**技巧：** 把聚组为你所用——每个关键镜头出多个变体，然后在装配最终序列前从每簇里挑赢家。

## ⚠ 提示词字符上限——512 字符

Cinema Studio 的提示词字段在 **2.5 与 3.0 都是硬上限 512 字符**。但字符的消耗方式因版本而异。

### Cinema Studio 2.5 字符预算

2.5 用 **@ 元素标签**（角色、场景、道具）。每个标签为其内部 ID 与引用元数据消耗约 **80–100 个隐藏字符**。

- 每条提示词**最多 2 个 @ 元素标签**——每个标签吃约 80–100 隐藏字符
- 用 2 个 @ 标签时，可见文本控制在 **~250 字符**内
- 用 1 个 @ 标签时，可见文本控制在 **~350 字符**内
- 用 0 个 @ 标签时，可见文本控制在 **~450 字符**内
- 提示词被拒就删词——绝不当成 bug

### Cinema Studio 3.0 字符预算

3.0 用 **@ 引用**（上传的图像、视频、音频——共最多 12 个）。@ 引用系统与 2.5 的元素标签结构不同。引用作为媒体附件挂载而非内联元数据，因此可能比 2.5 的元素标签消耗**更少的隐藏字符空间**。

- 512 字符硬上限仍然生效
- 挂 @ 引用时，可见文本以 **~350–400 字符**内为安全起点
- 不挂 @ 引用时，可用到接近满额的 **~450–500 字符**
- 提示词因超长被拒，先削可见文本——不要当成 bug
- 3.0 提示词可以比 2.5 **更具描述性**，因为 @ 引用给文本留了更多空间

## @ 元素跨场景持续

Multi-Shot Manual 中，**场景 1 加入的 @ 元素会持续作用于后续所有场景**。
不需要在每个场景提示词里重加 @ 标签。

**多角色序列的推荐模式：**
1. **场景 1：** 用 @ 元素确立全部角色（如 `@HERO` 与 `@badguy3`）
2. **场景 2–6：** 只用**视觉描述**指称角色（如"穿皮夹克的男人"）——Reference Anchor 会锁住他们的外观

**为什么有效：** 场景 1 的 @ 元素把角色几何锁进 Reference Anchor。后续场景自动继承该锁。后场再用 @ 标签会迫使模型重新处理参考数据，与动作提示词抢资源，引发角色互换、编舞断裂、动作丢失等问题。

## 打斗戏与动作设计规则（实测）

双人打斗序列是 Cinema Studio 里最难生成的内容之一。这些规则来自大量实测。

### 打斗戏里 AI 能渲染什么
- 两人对峙 / 对视 ✓
- 一般的打斗 / 搏斗能量 ✓
- 一人被抵在墙上 ✓
- 一人倒地 ✓
- 有人走开 ✓
- 音效与动作匹配 ✓

### 打斗戏里 AI 无法可靠渲染- 具体一拳打在脸上 ✗
- 踢腿（回旋踢、前踢等） ✗
- 复杂武术编排 ✗
- 精确的因果序列（击中 → 踉跄） ✗
- 道具战斗（托盘、推车、物件当武器） ✗
- 近身缠斗（常渲染成拥抱） ✗

### 角色互换问题

同一条动作提示词里用两个 @ 元素时，AI 经常**互换谁是主角谁是反派。** 无论提示词意图如何，先被提到的角色 tends 被派"主角"角。

**修法：**
- @ 元素只用于**静态/慢场景**（对峙、抵墙、走开）
- 编舞重要的**动作场景**用**纯文本**
- 用 @ 标签就把英雄角色写在提示词**最前**
- 每个场景结尾声明谁在哪，锚定位置

### 打斗序列模板（Multi-Shot Manual）

```
场景 1（@ 元素）—— 对峙：锁人，蓄张力
场景 2（纯文本）—— 第一次交锋：写打斗能量，不写具体招式
场景 3（纯文本）—— 升级：身体碰撞、烈度上升
场景 4（@ 元素）—— 特写时刻：抵墙、狠瞪
场景 5（纯文本）—— 终结：有人倒下
场景 6（@ 元素）—— 收场：英雄背对镜头走远
```

@ 元素场景（拍脸）与纯文本场景（拍动作）交替。
观众的大脑在剪切之间自行补全角色连续性——真实电影剪辑就是这么工作的。

### 围绕 AI 优势设计动作

上面的打斗规则描述模型在任何动作时刻能渲染与不能渲染什么。下面的规则讲如何*设计*动作本身，让模型永远不必渲染它做不到的东西。这些规则改编自 Mr. Core 方法论——平台上一线创作者的长片工作流文档——适用于所有动作序列，不只打斗。

**选模型渲染起来宽容的场地。** 有的空间藏漂移，有的空间暴露漂移。围绕宽容的场地设计动作：

- **宽容：** 圆形竞技场（相机可以无连续性参照地旋转）、模糊废墟（没有供观众审计的建筑线条）、重复纹理（森林、沙丘群、柱廊——帧间漂移读作视差而非错误）、雾 / 尘 / 烟环境（视觉噪声盖住大多数伪影）。
- **惩罚：** 熟悉地标（观众知道建筑的真实几何）、强视线几何的建筑（走廊或网格里任何漂移即刻可见）、带文字或招牌的公共空间（字在帧间漂）、连续反光面（镜面或玻璃连续性是酷刑）。

**围绕模型能渲染的编舞。** 别写模型做不到的动作再试图用提示词语言补救。提前把动作剪到模型的长处上：

- 对峙、擦身、接触前一瞬、接触后遗、身体穿越空间——全部可靠渲染。
- 精确徒手、道具战、多人缠斗、编排武术、逐帧打击——全部稳定失败。
- 剧本要的是第二类，就把它改排成第一类的一组镜头。剪切替模型完成它在单条 take 里做不到的事。

**每镜头一次变换。** 每次生成只规划一个状态变化——一个地点到另一个地点、一个情绪节拍到下一个、一个动作到它的后果。多节拍镜头（"她进门，看见尸体，拔枪，朝门口逼近"）迫使模型在两三个意图之间插值，结果至少在其中一个上漂移。在第一个节拍处切。第二个节拍单独生成。

**单代成型策略。** 把镜头规划到第一次生成即成品。生成二十次挑一张是预算失败，不是工作流——每多一次生成，都是在为本该前期做好的功课付第二遍钱。把每次生成当交付物。

## Cinema Studio 3.0（商业/团队套餐）

> **套餐要求：** Cinema Studio 3.0 独占于**商业与团队套餐**。免费与个人套餐用户请用 Cinema Studio 2.5，后者持续完整支持。

> **版本切换：** Cinema Studio 2.5 与 3.0 在平台上并存。用 Cinema Studio UI 右上角的版本选择器切换。

### 3.0 的不同之处

Cinema Studio 3.0 是与 2.5 分离的生成引擎。关键差异：

- **更长时长上限：** 15s（对比 2.5 的 12s）
- **视频分辨率更低（暂时）：** 视频封顶 720p（对比 2.5 的 1080p）；图像在 Character/Location 模式最高 4K（General 模式封顶 2K）
- **原生音频：** 音频经统一多模态架构与视频同时生成——双声道立体声，非后期
- **Smart 智能镜头控制：** 模型按类型与场景描述自动规划镜头语言
- **超宽画幅：** 新增 21:9（2.5 没有）
- **无光学物理引擎：** 2.5 的机身+镜头组栈在 3.0 不可用
- **无调色套件：** 2.5 的内置调色在 3.0 不可用
- **无 3D 模式 / 网格生成：** 这些 2.5 特性在 3.0 不可用

> **分辨率注记：** Cinema Studio 3.0 视频分辨率（720p）可能上调。要 1080p 视频请用 Cinema Studio 2.5。3.0 图像分辨率按模式而异：Character/Location 支持 4K，General 封顶 2K。

### Cinema Studio 3.0 快速规格

2.5 与 3.0 的完整差异见顶部对比表。3.0 专属要点：

- **视频：** 最长 15s、720p（可能上调）、48 credits/次
- **图像（Soul Cast 3.0）：** 最高 4K（Character/Location）· 2K（General），0.125 credits
- **类型（7）：** General、Action、Horror、Comedy、Noir、Drama、Epic
- **Speed Ramp（7）：** Auto、Slow-mo、Ramp Up、Flash In、Flash Out、Bullet Time、Hero Moment
- **画幅（7）：** Auto、1:1、3:4、9:16、4:3、16:9、21:9
- **音频：** 开/关——与视频同趟原生生成（双声道立体声）
- **镜头控制：** Smart（自动镜头规划）或 Custom 多镜头（最多 6 场景、总长 15s）
- **图像模式：** Cinema Studio 3.0 图像模式以 **Soul Cinema** 为默认模型——完整图像模式选择器（Cinematic 模型组 + Featured 模型组）见下方 3.5 章节的 § Image Mode，3.0 与 3.5 共用。

## Cinema Studio 3.5

Cinema Studio 3.5 是最新的 Cinema Studio 版本，与 2.5、3.0 并列在模型选择器中——三版在平台上并存、版本由用户手选、之间无自动路由。3.5 定位为深手动层之上的**简化创作面**：默认一切路由到 Auto、引擎代为选择，组栈的任何位置都可手动覆盖。

对比 3.0 的新增：

- **三药丸主界面**——Genre / Style / Camera 收拢为主界面上三个主药丸
- **光学物理回归**——机身/镜头/焦距/光圈界面回来了，经 Camera Settings 面板可达（词汇与 2.5 不同——见下）
- **Style Settings 面板**——三条预设轴（Color Palette 调色板 / Lighting 灯光 / Camera Moveset Style 运镜风格）加自由 Manual Style 模式
- **AI director 开关**——底部工具栏可见（功能尚未文档化；见 § AI Director Toggle）

**操作哲学：** 默认 Auto，有理由才手动。每个药丸默认 Auto、可覆盖——但有具体创作理由才覆盖。

### 三药丸主界面

3.5 把创作控制收拢进主界面三个药丸：

| 药丸 | 控什么 | 界面 |
|------|------------------|---------|
| **Genre 类型** | 手动类型目录 | 单选器 |
| **Style 风格** | Color Palette / Lighting / Camera Moveset Style + Manual Style 模式 | 三轴预设堆叠，或自由提示词 |
| **Camera 相机** | Camera Body / Lens / Focal Length / Aperture | 四轴面板 |

每个药丸默认 Auto。打开药丸即可覆盖。

### Cinema Studio 3.5 类型

UI 确认：**General · Action · Horror · Comedy · Noir · Drama · Epic**（7 个类型）。

类型选择器在 UI 中可滚动浏览，可能呈现未在此枚举的其他类型——当前完整清单以实机 UI 为准。

**这是提示词领地。** Manual Style 输入被引擎当作风格提示词处理，所以套用既有的 Style/Director-Language 提示模式纪律：把风格意图翻译成可观察的电影决策——相机行为、空间逻辑、灯光与色彩、表演模式、节奏、质感。避免空洞标签（"cinematic""epic""moody"）与导演点名（"Wes Anderson style"）——在引擎听来是风格噪声。完整纪律见 `../higgsfield-seedance/SKILL.md` 的 Style/Director-Language Prompt Mode，通用提示词规则见 `../higgsfield-prompt/SKILL.md`。

### Camera Settings——四轴面板

Camera 药丸展开为四子轴面板。两种操作模式：

**模式 1——Auto 自动**（默认）。四条子轴都默认 Auto；引擎代选。

**模式 2——逐轴调整。** 用户从每条轴手动选择。

#### 机身（3 款）

| 机身 | 何时用 |
|------|----------|
| Clean Digital 干净数字 | 锐利、中性、无性格——企业、商业、科幻冷峻、一切要"拍到而非调过"的东西 |
| Fine Film 精致胶片 | 电影胶片质感但无重颗粒——叙事剧情、角色戏、高规格感 |
| Raw 16mm 生16mm | 重颗粒、有机、低保真——年代粗粝、独立剧情、恐怖、纪录写实 |

#### 镜头（5 种性格）

| 镜头 | 何时用 |
|------|----------|
| Vintage Haze 复古雾化 | 柔和复古性格带微妙光晕——怀旧、年代、记忆、爱情 |
| Warm Halation 暖光晕 | 暖高光光晕——黄金时刻、梦境室内、柔性剧情 |
| Anamorphic 变形宽银幕 | 椭圆焦外+水平耀斑——行业标准电影感、动作、大片、高规格 |
| Extreme Macro 极微距 | 超近渲染——质感细节、食物、产品、昆虫、精细表面 |

#### 焦距（5 档）

`8mm · 14mm · 35mm · 50mm · 75mm`

- **8mm**——超广、沉浸式畸变。动作主观视角、环境、迷失感。
- **14mm**——广角、环境、尺度。建立镜头、风景、建筑。
- **35mm**——自然人眼视场。纪录、街头、双人镜头、抓拍。
- **50mm**——经典人像压缩。角色特写、单主体。
- **75mm**——紧人像压缩——3.5 相对 Cinema Studio 2.5 所载 8/14/35/50mm 组新增。反应、情绪高潮、角色孤立。

#### 光圈（3 档）

`f/1.4 · f/4 · f/11`

- **f/1.4**——浅景深。主体锐利、背景奶油焦外。亲密、聚焦、情绪。

- **f/11**——深景深。前后全锐。产品、风景、建筑。

### Cinema Studio 3.5 输出控制

| 控制项 | 选项 |

**质量档——实操指引：**
- **480p**——草稿/探索档。投入更高分辨率终稿前做提示词迭代用。知道它的极限：见正下方 § 草稿验证的是提示词，不是成片。
- **720p / 1080p**——成片质量档。二者怎么选取决于场景里有什么物理；见下方 § 物理渲染——分辨率决策矩阵。

> **Seedance 2.0 的 4K 还到不了 Cinema Studio。** 独立面（Create Video / API `seedance_2_0`）下，Seedance 2.0 在 `mode=std` 输出最高 **4K**——但在 Cinema Studio 3.5 内质量控制封顶 **1080p**。客户要真 4K Seedance 母版，从独立 Create Video 面板（mode=std，resolution=4k）生成，不经 Cinema Studio。Cinema Studio 镜头要 4K *成片*，以 1080p 做母版再放大（见 `higgsfield-pipeline`）。

#### 草稿验证的是提示词，不是成片

480p 草稿**不是你将用 1080p 重渲那条 take 的廉价预览**。Seedance 2.0 的 schema **没有 seed 参数**（已验证——`../../specs/model-specs.yaml` 只列 `resolution`、`mode`、`genre`，别无其他），所以更高分辨率的重跑是**全新一掷**，不是重渲。"480p 批准这条 take、再 1080p 重渲它"不是平台支持的工作流。

草稿**能**验证的（跨掷保留，因为是提示词驱动）：

- 镜头数与结构服从
- 走位服从（位置、运动方向、出入场）
- @handle / 身份污染（错误角色特质渗进别的主体）
- 台词位置
- 内容过滤器过/不过

草稿**不能**验证的（每次生成全新重掷）：

- 表演——那条 take 的表情、手势微妙处、微时序
- 相机微轨迹——具名运动内的确切路径
- 片段内的节拍时序

**想保住的 look，文档化的迁移机制是 Hero Frame**（`../higgsfield-assist/SKILL.md`）加**首尾帧钉扎**（本文 § 关键帧插值）——钉帧，不钉掷。细节判断（烟丝、铭文可读性、反光）必须在**最终分辨率复检**：480p 藏住的恰是那些判断要看的细节。
**声音提示：** Sound 开启时，音频与视频同趟原生生成。要细致提示音频行为（对白、SFX、环境、音乐），见 `../higgsfield-audio/SKILL.md`。

**Batch Size 批量：** 定位为探索倍增器——一次跑出多个变体。具体成本行为因套餐而异且可能变动。

> 本节不列具体 credit 价格。成本因套餐而异且随时间变动——以 Higgsfield 实时套餐文档为准。

### 逐镜头设置条

交付给用户的每个 Cinema Studio 3.5 镜头，都应以一行**设置条**领衔，把*在 UI 里预置的东西*与*进提示词框的东西*分开。标准格式：

```
Genre: <类型> · AR: <画幅> · Quality: <480p|720p|1080p> · Duration: <N>s · Shots: <N> · Sound: <开|关> · Camera: <机身> / <镜头> / <焦距> / <光圈> · Style: <Auto | 预设, 预设, 预设 | Manual>
```

实例：

```
Genre: Noir 黑色电影 · AR: 21:9 · Quality: 1080p · Duration: 12s · Shots: 3 · Sound: On 开 · Camera: Fine Film / Anamorphic / 50mm / f/1.4 · Style: Manual
```

设置条规则：

- **条内一切都是 UI 控件，不是提示词文本。** 不要在提示词正文里复述设置条的值——引擎已从面板拿到，复述浪费提示词预算且可能冲突。
- 相机轴用 3.5 词汇（上方 Camera Settings 面板）。`Auto` 是任何位置的合法值——显式写出而不是省略该位，让用户知道没有遗漏。
- `Style:` 是 `Auto`、逗号分隔的预设栈（调色板、灯光、运镜风格——与 Style 药丸自身显示的标签格式相同），或 `Manual`（意为：已存 Manual Style 块生效——见下方撰写指南）。
- **UI 镜头计数器封顶内部剪切。** 声明"严格 N 镜"的提示词必须让 N 落在计数器的值内——提示词要的剪切多于计数器允许的，引擎就会即兴决定砍哪些。生产观察上限为**每次生成 4 镜**（2026-06-11 会话）。API 核验 2026-07-05：`cinematic_studio_video_v2` 目录面暴露 `multi_prompt` **无最大值**且无约束规则——该上限是 API 不文档化的 UI 行为，把 4 当工作上限，承诺更多之前先在实机 UI 核验。

### Manual Style——撰写指南

Manual Style 是**保存的可复用风格块**（≤2,000 字符，每项目写一次），不是逐镜头草稿纸。搞清什么放哪里，既防提示词臃肿，也防 look 漂移：

| 层 | 放什么 | 示例 |
|-------|---------------|----------|
| **Manual Style 块**（存一次，作用于每个镜头） | 项目的恒定 look：调色、灯光*法则*、质感、表演基调 | "漂白旁路调色，黑部压死。所有光都有动机且是实用光源——绝无无动机补光。35mm 颗粒带轻微光晕。表演收敛，无戏剧化手势。" |
| **提示词正文**（逐镜头） | 镜头之间的变化：主体、走位、动作、本场*具体*光源、音频线索 | "她穿过装卸场走向怠速的卡车；钠灯泛光从左侧打来，车灯扫过她身后的墙。湿水泥上的脚步声。" |
| **三条风格轴**（不用 Manual 时） | 同一意图的预设堆叠近似 | Sodium Decay + Practicals + Intimate Observer |

已存块的撰写规则：

- 写**法则，不写描述**——"所有光都有动机"治理每个镜头；"一盏路灯亮着"只属于一个镜头的提示词正文。
- 覆盖四个 register：**调色**（调色板+对比行为）、**灯光法则**（允许什么光存在）、**质感**（胶片型号/颗粒/光晕）、**表演基调**（表演幅度）。各一两句——2,000 字符预算是给精确的，不是给量的。
- 套用 Style/Director-Language 纪律（无空洞标签、无导演点名——见上文模式 3 注记）。
- Manual Style **取代**三条预设轴——别再叠预设指望它们合并。

完整 master-style 示例（一个完整的已存块）：

```
冷峻程序化惊悚。调色：降饱和冷调、钢蓝阴影，
高光绝不过曝，黑部压在粉碎线上方一点。灯光法则：每个
光源都是实用光源或有动机——日光灯、显示器、车灯；
无美化补光；面孔可以沉到 50% 阴影。质感：干净数字，
低光带微弱传感器噪声，无胶片颗粒，无光晕。表演
基调：收敛且程序化——细微眼部运动大于手势，
无人提高音量。
```

### 图像模式

Cinema Studio 3.5 在 Image 与 Video 之间有**模式切换**。上文各节（三药丸主界面、Style Settings、Camera Settings、输出控制）描述的是视频模式——默认面与 3.5 的主用途。本小节讲图像模式的差异。

#### 图像模式模型选择器

图像模式选择器分两组：**Cinematic 模型组**（工作室原生——完整图像模式 UI 适用）与 **Featured 模型组**（可从外壳内运行的第三方引擎，仅提示词控制）。

**Cinematic 模型组——四个选项：**

| 模型 | 选择器描述 | 何时用 |
|-------|--------------------|----------|
| **Soul Cinema**（默认） | 电影感图像生成 | 通用电影感图像工作；默认起点 |
| **Cinematic Characters** | 有表现力的面孔与细节造型 | 角色特写、表演驱动人像、表情与造型工作 |
| **Cinematic Locations** | 电影感灯光的丰富环境 | 建立镜头、环境/位置底板、氛围驱动图像 |
| **Cinematic Cameras** | 带相机控制的图像生成 | 要显式机身/镜头/焦距/光圈控制时——用 2.5 光学词汇（见下） |

**Soul Cinema 由 Cinema Studio 3.0 与 3.5 的图像模式共用**——3.0 侧说明见上方 § Cinema Studio 3.0（商业/团队套餐）。逐模型选择指南（何时选哪个 Cinematic 模型）见下方 § Per-Cinematic-model selection guide。各 Cinematic 模型专属的示例提示词推迟到未来版本。

**Featured 模型组——选择器概览：** 图像模式选择器还呈现 **Featured 模型**（如 Higgsfield Soul 2.0、GPT Image 2、Seedream 5.0 Lite，及 `../higgsfield-models/MODELS-DEEP-REFERENCE.md` 所列其他第三方引擎）。Featured 模型可从 Cinema Studio 外壳内选择，但选中即意味着**工作室专属 UI 功能（Style Settings、Camera Settings 面板）不可用**——外壳还在，创作控制退回纯提示词。Featured 模型的提示词，路由到该模型自己的文档 `../higgsfield-models/MODELS-DEEP-REFERENCE.md`，别当成 Cinema Studio 配置问题处理。

> ⚠ 注意：Featured 列表里另有一个单独命名的模型叫 **Higgsfield Soul Cinema**，与 Cinematic 列表的 **Soul Cinema** 名字相近但不是一回事。二者不可互换。

Soul Cinema 的身份提示与参考工作流，见 `../higgsfield-soul/SKILL.md`。

#### 画幅——8 种

`1:1` · `3:4` · `2:3` · `9:16` · `3:2` · `4:3` · `16:9 (Cinematic)` · `21:9 (Cinematic)`。16:9 与 21:9 在选择器中标"Cinematic"。图像模式的画幅集与上方 § Cinema Studio 3.5 输出控制所载视频模式 7 种不同。

#### 分辨率——取决于所选 Cinematic 模型

| 所选模型 | 分辨率选项 |
|----------------|--------------------|
| Soul Cinema（默认） | 1.5K / 2K |
| Cinematic Cameras | 1K / 2K / 4K |
| Cinematic Characters / Cinematic Locations | 本版未单独验证 |

#### 逐 Cinematic 模型选择指南

四个 Cinematic 模型共用同一个 Cinema Studio 外壳，但各专一种图像意图。每个模型带的选择器描述是一行提示；本小节把它展开成实用的选择指南。词汇纪律适用：Soul Cinema、Cinematic Characters、Cinematic Locations 是 3.5 原生，动 Camera Settings 面板就用 3.5 词汇；只有 Cinematic Cameras 继承 2.5 光学词汇（见下方专节）。

##### Soul Cinema——默认

Soul Cinema 是默认 Cinematic 模型，在没有具体理由选其他三个时，它就是正确起点。它是通用电影感图像生成：场景设定、给定环境中 Soul ID 角色的 hero 帧、情绪驱动关键帧、意图是"让它看起来电影"而非"让这个角色有戏"或"让这个场景有氛围"的单图生成。Soul Cinema 也是与 Soul Cinema enhancer 开关及短提示词风格探索配对的模型——见 `../higgsfield-pipeline/SKILL.md` Pipeline E（enhancer 驱动的多风格短片工作流）。

选 Soul Cinema 当：你要均衡的电影感画面、你开着 enhancer 用短提示词探索风格、你在生成将交下游动画的 I2V 关键帧、或你在用 Soul ID 身份参考且要平台的通用电影 look。避开 Soul Cinema 当：你明确要最大面部表情保真（用 Cinematic Characters）或最大环境氛围（用 Cinematic Locations）。Soul Cinema 专属身份提示与参考工作流，见 `../higgsfield-soul/SKILL.md` § Soul Cinema as the CS 3.0/3.5 default image model。

##### Cinematic Characters——表情面孔与造型

Cinematic Characters 专精表演驱动人像：微表情保真、服装与造型细节、脸在扛戏的角色特写。选择器描述（"有表现力的面孔与细节造型"）就是操作意图——这个模型把生成权重压向面部结构、视线方向、嘴部张力、发型几何、衣物质感，多于环境氛围或广角建立构图。

选 Cinematic Characters 当：脸扛着这个镜头（反应节拍、情绪高潮、角色介绍特写）、你从 `../higgsfield-soul/SKILL.md` 取微表情方向（Deadpan Neutral、Quiet Devastation、Predator Glare 等）、或服装造型细节是提示词的一部分且需要保真渲染。避开 Cinematic Characters 当：镜头很广角色在画面里很小（用 Soul Cinema 或 Cinematic Locations），或显式机身/镜头/焦距控制比面部表情更重要（用 Cinematic Cameras）。与 `../higgsfield-soul/SKILL.md` 的微表情库天然配对；Soul ID 激活时遵守身份 vs 运动分离规则。

##### Cinematic Locations——环境与氛围

Cinematic Locations 专精建立镜头、环境底板、氛围驱动图像——模型权重压向空间纵深、光量、天气与时段渲染、建筑或自然世界细节。选择器描述（"电影感灯光的丰富环境"）就是操作意图：环境是主体、画面里的人只是尺度参照而非表演主体时，这个模型就对了。

选 Cinematic Locations 当：你在为多镜头序列生成建立镜头、搭五视图位置表（见本文前文 § 位置参考表）、为下游合成生成环境底板、或拍一张灯光与天气扛画面的情绪氛围镜头。避开 Cinematic Locations 当：角色是前景、脸重要（用 Cinematic Characters），或镜头需要经 2.5 词汇的显式光学控制（用 Cinematic Cameras）。与五视图位置表工作流天然配对；跨多镜头的位置一致性要紧时，与 Soul HEX 色板提取配对。

##### Cinematic Cameras——见下方 h4

Cinematic Cameras 是第四个 Cinematic 模型，详述在下一小节（`#### Cinematic Cameras——2.5 词汇的图像模型`）。与上面三个不同，它继承 Cinema Studio 2.5 光学词汇为可配置的机身/镜头/焦距/光圈组栈。显式光学控制比其他三个模型的专精轴更重要时选它。

#### Cinematic Cameras——2.5 词汇的图像模型

从图像模式选择器选 **Cinematic Cameras**，会展开 **Cinema Studio 2.5 相机词汇**为可配置组栈——机身/镜头/焦距/光圈，取自本文前文 § Optical Physics Engine 所载同一界面。Cinematic Cameras 是图像模式进入 2.5 六机身十镜头性格的入口；它是与 Soul Cinema、Cinematic Characters、Cinematic Locations 并列的兄弟 Cinematic 模型——不是叠在另一模型上的开关。

Cinematic Cameras 选择器有三个页签：

| 页签 | 里有什么 |
|-----|--------------|
| **All 全部** | 2.5 机身+镜头+焦距+光圈的完整库 |
| **Recommended 推荐** | Higgsfield 置顶建议 |
| **Saved 已存** | 用户保存的相机组栈 |

选择器还有 **+ Save setup** 按钮——配置好的机身+镜头+焦距+光圈组合可存为可复用组栈，后续生成从 Saved 页签调回。

> **逐 Cinematic 模型选择指南**（哪个意图选哪个模型）见上方 § Per-Cinematic-model selection guide。**仍推迟到未来版本：** 各 Cinematic 模型专属示例提示词、Featured 模型在图像模式何时合理、Cinematic Cameras 的 Save Setup 工作流、视频模式并行 Cinematic/Featured 结构的完整选择器覆盖。本文前文的光学物理引擎节（§ Optical Stack Recommendations by Intent）记载 2.5 模式组栈推荐，直接适用于 3.5 图像模式的 Cinematic Cameras——词汇完全相同，界面不同。

## 物理渲染——分辨率决策矩阵

本规则适用于 **Seedance 2.0** 与 **Cinema Studio 3.x**（3.0 与 3.5）的输出。分辨率高不总是好——正确选择取决于场景里有什么物理。快速运动上渲染更多像素会产生闪烁与伪影；精细物理上渲染更少像素会产生糊化或融化的小元素。把分辨率档位匹配到镜头的物理。

矩阵有**两轴**：镜头的物理 AND 交付语境。先读物理行，再套交付语境列——对原生交付正确的推荐，对放大收尾管线可能是错的。

| 场景类型 | 原生交付（社媒帖、1080p 时间线） | 放大收尾管线（4K 母版） |
|------------|------------------------------------------------|--------------------------------------|
| 快速/混乱运动（爆炸、水流、人群、急运镜） | **720p**——每帧更少像素=更顺滑的流动、快速变化上更少闪烁/伪影 | **模型最高分辨率，`std` 模式**——720p 母版迫使 3× 放大，其代价与伪影超过它避开的闪烁 |
| 精细物理（头发、沙、小颗粒、玻璃碎、织物织法） | **1080p**——保住小元素锐利（而非糊化或融化）所需像素密度 | **模型最高分辨率，`std` 模式** |
| 接地重量（重车、悬挂行程、质量撞击） | **1080p**——材质重量读作真实所需像素密度 | **模型最高分辨率，`std` 模式** |
| 草稿 / 探索 / 迭代 | **480p**——投入前提示词迭代最快档 | **480p 仅限提示词迭代**——绝不做母版（见 § 草稿验证的是提示词，不是成片） |

**放大收尾规则：**

- 母版用模型的 **`std` 模式最高分辨率**。母版绝不低于**交付分辨率的一半**——再低，放大器是在发明细节，不是恢复细节。
- 4K 收尾管线里允许逐镜头 720p，仅作为**记录在案的例外**（如某镜头 1080p 下闪烁明显毁 take）——在 shotlist 里记下镜头与理由，让收尾阶段知道放大倍率变了。

> **fast 模式陷阱（经模型 schema 验证）：** Seedance 2.0 的 `fast` 模式**不能输出 1080p**——按 `../../specs/model-specs.yaml`，`mode=fast` 禁止 `resolution=1080p`。在 `fast` 里起草然后"升到 1080p"，会静默同时改变模式与分辨率：最终渲染走的是与草稿所验证不同的管线（`std`）。显式预检最终组合：`python3 scripts/seedance_lint.py --model seedance_2_0 --mode fast --resolution 1080p` 正是因此失败。

**另见：** Seedance 2.0 提示模式指引见 `../higgsfield-seedance/SKILL.md`。

> 本节不列 credit 价格。480p 定性为迭代档——具体成本比例因套餐而异且可能变动。
