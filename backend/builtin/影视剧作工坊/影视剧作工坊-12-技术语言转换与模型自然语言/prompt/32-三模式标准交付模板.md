# 三模式标准交付模板

## 一、两种交付形态（先选形态，再拼内容）

同一个镜头，交付层可以出**两种形态**。两者内容同源，**不是二选一的技术方案，而是两种受众**：

| 形态 | 给谁看 | 结构 | 特点 |
|------|--------|------|------|
| **形态 A · 工程交付文件** | 导演 / 制片 / 后续加工者 | **①–⑩ 字段化**（模型无关真源） | 字段齐、可核对、可跨平台重转；**不绑定任何模型** |
| **形态 B · 即梦模式交付** | 直接投喂即梦 / Seedance | 按**即梦万能公式**连缀成段 | 打开即复制粘贴；**一镜一提示词** |

**转换关系**：**过了转换层（12 的转换原则）后先得到 ①–⑦ 七要素真源**；再「选定输出模型后，按该模型参数规范把 ①–⑦ 转译为最终 Prompt」——形态 B 就是这一步的即梦产物。

> 出处：`01/spec/01-四轴判定与触发机制.md` §1——"导演生成文件七要素（①–⑦，模型无关通用真源）……选定输出模型后，按该模型参数规范把①–⑦转译为最终 Prompt。"

## 二、①–⑩ 字段定义

**①–⑦ = 七要素（模型无关真源）**；**⑧–⑩ = 声音三轨**。合起来即交付文件的行结构。

| 字段 | 管什么 | 只写什么（禁写什么） |
|------|--------|---------------------|
| **① 渲染规格** | 写实度 / 风格基调 / 质感基线 | 只写风格标签（"电影级写实""极致几何细节""光线自然反弹"）；**不写渲染器名与算法名** |
| **② 画幅画质** | 比例 / 分辨率 / 画质基调 | "竖屏 9:16、1080P、超清画质、细节锐利"；**不写码率与数值参数** |
| **③ 环境场景** | 地点 / 空间 / 三层纵深 | 前景 / 中景 / 背景语义描写；不写场景层级与网格信息 |
| **④ 人物外观状态** | 外貌 / 服装 / 表情 | **引用角色锚定段（逐字）**，不用模糊词 |
| **⑤ 人物动作** | 主体行为与细节 | 可见动作、微表情、呼吸、身体细节；不承载完整台词文本 |
| **⑥ 镜头运镜构图** | 机位 / 运动 / 画面布局 | 景别 + 角度 + 运镜预设名 + 构图 |
| **⑦ 光影色彩** | 光线方向 / 色调 | 可执行布光说明；**数值转程度词**（3200K → 暖橙灯光） |
| **⑧ 对白** | 台词轨道 | 双引号包裹 + 说话者 + 语气；无对白写「无对白」 |
| **⑨ 背景音** | 音效 / 环境声轨道 | 事件@秒记法；**此轨不能为空** |
| **⑩ BGM** | 配乐轨道 | 配器 + 速度 + 情绪；无 BGM 写「无 BGM」 |

**行结构（DirectorPlus 口径）**：
```
id + ①渲染规格～⑩BGM + ## 负面规避词表 + ## 逐秒精细化说明
```

**拼装铁律**：**①–⑦ 顺序固定、缺一不可**；每个要素**只写模型能直接画出来或演出来的内容**，不写内部参数、不写推理过程。

## 三、与即梦 Seedance 万能公式的对齐

**即梦侧通用公式（八段）**：

```
主体 + 动作 + 场景 + 光影 + 镜头语言 + 风格 + 画质 + 约束
```

**字段映射**：

| 即梦公式段 | 对应 ①–⑩ 字段 | 说明 |
|-----------|--------------|------|
| 主体 | **④ 人物外观状态** | 即梦的"主体"比 ④ 宽——含产品 / 物体 / 场景主体 |
| 动作 | **⑤ 人物动作** | 一致 |
| 场景 | **③ 环境场景** | 一致 |
| 光影 | **⑦ 光影色彩** | 一致 |
| 镜头语言 | **⑥ 镜头运镜构图** | 一致 |
| 风格 | **① 渲染规格** | 即梦把"风格"与"画质"分列；① 内部含风格基调 |
| 画质 | **② 画幅画质** | 对应 |
| 约束 | 负面规避词表 + 正向锁 | 我们的负面词表独立成块；正向锁并入尾部 |
| （无对应） | **⑧⑨⑩ 声音三轨** | 即梦 Seedance 2.0 **自带音效/配乐**，音频也支持上传；我们是显式三轨 |
| （无对应） | 时长 / 画幅枚举 | 即梦放在**提交参数**里，不写进正文 |

**两处实质差异**（不是错，是口径不同）：

1. **即梦把「镜头类型/焦距」放在最前**（"9:16 竖屏产品特写"开头），而 ①–⑩ 把 **② 画幅** 放第二、**⑥ 镜头** 放第六。
   → **处理**：走形态 B（即梦交付）时按即梦习惯把**画幅 + 景别**提到最前；走形态 A（工程文件）时保持 ①→⑦ 固定序。
2. **即梦的「约束」是一段护栏**（"保持标志清晰，无额外文字，无产品形状扭曲"），而我们把负面词独立成表、正向锁放尾部。
   → **处理**：形态 B 允许把护栏**并入末段**；形态 A 保留独立负面词表。

## 三之补 · 对白与音频段怎样融入（本文件的关键补充）

### 1. 位次要按官方块顺序定，不靠感觉

即梦 Seedance 官方**块状脚手架的具名块顺序**（依据：`14-seedance导演.md` §块顺序）：

```
SCENE CONTEXT → ACTIVE REFERENCES → LOCATION MAP → FIRST FRAME/BLOCKING
→ FORMAT MODE → OPTICS → CAMERA → ACTION → PERFORMANCE → PHYSICS
→ LIGHTING → COLOR GRADE → WARDROBE → 【AUDIO】 → STYLE → OUTPUT SETTINGS → POSITIVE LOCKS
```

原文规则：**"先语境与参考，再空间与时间，再动作与物理，然后描述性风格回到各自归属位，然后是技术后缀，锁殿后。"**

**结论**：**AUDIO 在描述性内容之后、技术后缀（STYLE / OUTPUT SETTINGS）之前**，而**锁（POSITIVE LOCKS）始终殿后**。

### 2. 于是八段公式扩为九段 —— 音频插在「镜头语言」之后

```
主体 + 动作 + 场景 + 光影 + 镜头语言 + 【音频】 + 风格 + 画质 + 约束
  ①      ②     ③      ④        ⑤          ⑥         ⑦     ⑧     ⑨
```

**为什么不放最末**：官方把 `POSITIVE LOCKS`（正向锁）钉在最后一位。若把音频塞到"约束"之后，音频就成了全句收尾，**与官方块顺序相反**——模型会把收尾权重给音频而非护栏。

**为什么不放最前**：音频是**并行轨道**，不是语境。放进开头会挤掉主体/动作的前部权重（前 20–30 词承担不成比例的权重）。

**可省规则**：官方明说"只使用该镜头需要的块"。**无对白、无音频需求的镜头，音频段整段省略**——不要写"无音频"占位。

### 3. 对白不是"描述项"，是"条目" —— 三条轨写法不同

`⑧对白` `⑨背景音` `⑩BGM` 字段上并列，但**对白的性质与另两轨不同**：

| 轨 | 性质 | 来源 | 写法 |
|----|------|------|------|
| **对白** | **条目**（逐字、可能要锁） | 文本生成 **或** 上传音频 | 说话者 + 语气/语速/音量 + **双引号逐字台词**；注入式加 `@音频N` + 时间戳锚定 |
| **背景音** | 描述 | 生成 | `事件@秒` 记法；**此轨不能为空** |
| **BGM** | 描述 | 生成 | 配器 + 速度 + 情绪；压制时写 **`NO BGM`**（规格级，不是偏好级） |

**对白的两条路径，绝不可混**：

| 路径 | 何时用 | 音频段怎么写 | 硬约束 |
|------|--------|-------------|--------|
| **生成式**（让模型说） | 无现成配音，要模型生成对白 | `对白：她低语，语速偏慢："还不到时候。"` | 对白片段 **3–8 秒**；**每镜只有一张说话的脸**；机位锁 `locked-off static` 或 `slow Dolly In`；**头部/面部运动 token 不与对白同框** |
| **注入式**（上传音频） | 已有配音，要严格按它播 | `音频 @Audio1 从 0 秒到结尾严格按上传内容播放` | **删掉所有环境音 / 音效 / 音乐 token**——它们会招来生成式音频引擎覆盖上传音频 |

### 4. 对白块的三行模板（直接抄）

```
音频：对白：<说话者>，<语气>、<语速>、<音量>："<逐字台词>"
      口型：<lip_sync=A 配音先行 / B 生成对口型>；机位 locked-off static（或 slow Dolly In）
      声景：背景音 <事件@秒>；BGM <配器+速度+情绪> 或 NO BGM
```

**注入式**把第 1 行换成：
```
音频：@Audio1 从 0 秒到结尾严格按上传内容播放（对白逐字：""）
      （删除全部环境音/音效/音乐 token）
```

### 5. 「内联法」与「专门块法」的判据

`09/audio/01-对白.md` 给了两种合法写法，**不是二选一，按复杂度分流**：

| 写法 | 何时用 | 形态 |
|------|--------|------|
| **内联法**（短提示词首选） | 只有一句对白、无音效编排、无上传音频 | 对白就近织进**动作段**（"她低语：'还不到时候。'"），音频不独立成段 |
| **专门块法** | **多层音频（对白+音效+环境+BGM）**、有时序、有上传音频 | 独立 `Audio:` 块，按上面的三行模板 |

**判据一句话**：**单句对白可以内联；只要涉及口型同步、时序或上传音频，必须独立成段。**

### 6. 对白与相邻字段的边界

- **⑧对白 vs ⑤人物动作**：**台词文本属 ⑧**；**嘴部状态与说话的动作**（"下颌闭合，呼吸抬起胸口""双唇静息"）属 **⑤**。两者不重复写。
- **⑧对白 vs ④人物外观状态**：④ 里**不写**"她会说话"这类信息；说话能力由 ⑧ 承载。
- **⑧对白 vs ①渲染规格**：音频段的风格（如"温暖近场人声"）**不并入** ①，留在音频段内。

## 三之补二 · 声音层输出档位（默认全量，可去配乐）

**默认全量**：交付文件的声音层（**⑧对白 + ⑨背景音 + ⑩BGM**）**三轨齐全**——打开即成品。

**可选档位「去配乐」**：拿掉 **⑩BGM**，保留 **⑧对白 + ⑨背景音**，**为后期配乐留出音区**。

| 档位 | ⑧对白 | ⑨背景音 | ⑩BGM | 交付用途 |
|------|:-----:|:-------:|:-----:|---------|
| **全量档（默认）** | ✅ | ✅ | ✅ | 一次成片，直接可用 |
| **去配乐档** | ✅ | ✅ | **`NO BGM`（显式抑制）** | 后期配乐：后期铺 BGM，不与生成音乐打架 |

### 关键：去配乐是「显式抑制」，不是「省略」

**不能只是不写 BGM。**即梦 Seedance 2.0 **自带音效 / 配乐**——不声明就等于请它自由发挥，生成出一段你后期要拆掉的音乐。

**正确写法：第 ⑩ 轨写 `NO BGM`（规格级），不是 `no music`（偏好级）。**

> 依据（`09-音效/audio/03-配乐.md`）：**`NO BGM` 是规格而 `no music` 只是偏好**。

### 与引擎层的呼应

E09 引擎（塔氏口径）本来就主张"**音乐不要铺满**""把自然音全部放在中音区，**为音乐留出高音区与低音区的动态空间**"。**去配乐档不是省事，是把这条执行到极致**——给后期让路。

### 档位声明（必写，否则审核无法判定）

交付文件头部必须声明档位：

```
【声音层】全量（对白 + 背景音 + BGM）
【声音层】去配乐（对白 + 背景音；BGM 显式抑制）
```

### 同一镜的两种写法对照

| 档位 | 音频段写法 |
|------|-----------|
| **全量** | `他低声说，语速偏慢："还能撑两天。"背景音：冰凌滴水@1s、烛焰轻爆@2s；BGM：低沉大提琴单音，缓慢，压抑。` |
| **去配乐** | `他低声说，语速偏慢："还能撑两天。"背景音：冰凌滴水@1s、烛焰轻爆@2s；NO BGM。` |

⚠️ **去配乐档不得残留任何音乐类 token**：`配乐`、`BGM`、`背景音乐`、`插曲`、`音乐` 一律不得出现——**唯一的例外是 `NO BGM` 这一处规格句本身**。

⚠️ **去配乐档不改变 ⑨背景音的"不能为空"要求**：环境声与音效照常写，它正是后期配乐要挂靠的节奏底座。

### 模板 B · 首帧

**与 T2V 的硬性差异：③ 环境场景 与 ④ 人物外观状态 两层整段删除**——图里已有，复述等于给同一主体两个互相竞争的输入。

**形态 A · 工程交付文件**

```
【镜号】S__-___
【模式】首帧（1 张图 = 视频第 1 帧）
【时长】__ 秒
【输入图】__（画幅必须 = 目标成片画幅）

① 首帧指涉句：以输入图作为第 1 帧
② 变化：只写会动 / 会变的（动作、表情、光影变化、环境动态）
③ 镜头运动：（点名预设名）
④ 风格 / 氛围提示：（可省——图已定调）
⑤ 声音三轨：对白 / 背景音 / BGM
⑥ 负面规避词表

```

**形态 B · 即梦模式交付**

```

```

**硬性自检**
- [ ] **未复述输入图中已有的内容**（环境 / 主体静态外观 / 构图）← 最高优先级硬项
- [ ] 有明确的首帧指涉句
- [ ] 只描述会动 / 会变的内容
- [ ] 镜头运动**点名**，非暗示
- [ ] 输入图画幅 = 目标成片画幅（图生视频 `aspect_ratio` 不生效）
- [ ] **有对白时**：3–8 秒、一镜一张说话的脸、机位锁定、头部运动 token 未与对白同框

## 五、三模式取用速查

| 维度 | 文生视频 | 首帧 | 首尾帧 |
|------|:--------:|:----:|:------:|
| 环境场景（③） | ✅ 逐字写 | ❌ **禁写** | ❌ **禁写** |
| 人物外观状态（④） | ✅ 逐字写 | ❌ **禁写** | ❌ **禁写** |
| 指涉句 | ❌ 无 | ✅ 首帧 | ✅ 首尾帧 |
| 画幅指定 | ✅ 头部字段 | ❌ 按输入图 | ❌ 按输入图 |
| **音频段（⑧⑨⑩）** | ✅ 需用才写 | ✅ 需用才写 | ✅ 需用才写 |
| **音频段位次** | 镜头语言**之后**、风格/画质/约束**之前** | 同左 | 同左 |
| 附随图提示词 | — | — | ✅ 两份（**由 04 出**） |
| 提示词长度 | 九层写全，**最易超 800 字** | 天然短 | **最短** |

> **音频段是三者共用的规则**（不像 ③④ 那样按模式取舍）：**有则写、无则整段省略**，位次固定在镜头语言之后。
> **对白随时段走**：首帧/首尾帧同样受 **3–8 秒对白窗口**约束；首尾帧的中段若含对白，说话的脸仍然只能有一张。

**口诀**：**文生视频从零写全；首帧只写变化；首尾帧只写中段。**
**信号**：首帧 / 首尾帧若逼近 800 字上限，说明**把图里已有的东西又写了一遍**——回查上表。
