## 第一章 提示词结构
### 1.1 三种基本格式

| 格式 | 适用场景 | 输出类型 |
|---|---|---|
| **A —— 结构化 JSON** | 输出包含离散区域、带标签的部件、UI 元素、多格网格或信息层级 | UI 界面示意图、落地页、信息图、爆炸图、角色参考设定表、杂志版式、多格海报、漫画页、卡片网格 |
| **B —— 浓密电影化散文** | 输出是一个场景、一帧画面、一个主体，没有 UI 元素或布局区域 | 人像、电影感场景、概念艺术、插画、风景、时尚大片 |
| **C —— 自动推导元提示词** | 只给出主题，希望模型自行生成整个构图 | 概念海报、关系图、百科式信息图 |

**分流决策：**
- 有离散区域 / 网格 / 版式 → 格式 A。
- 单一场景 / 单一主体 / 单帧画面 → 格式 B。
- 只有主题、布局交给模型 → 格式 C。

**平局裁决：** 当 A 与 B 之间确实难以取舍时（例如"一个角色，周围带着一些标签"），默认选 A。布局精度是结构化提示词的首要差异化能力。在 B 本也可行时误选 A，代价很小；在需要 A 时误选 B，代价是丢掉全部布局锚定。

#### 格式 A —— 结构化 JSON

写一个 JSON 对象，描述画面中每一个可见区域。支持精细布局的模型会把它当作布局规格书（layout spec）来读。

**核心字段：**
- `type` —— 一句话描述这张图是什么（"infographic poster"、"landing page mockup"、"exploded view diagram"、"anime character reference sheet"）
- `style` —— 视觉风格（"cute flat vector illustration, cozy, warm, soft shading"）
- `subject` / `character` —— 主要实体，附带具体视觉属性
- `layout` —— 各区域的嵌套对象：`header`、`centerpiece`、`sections`、`footer`、`left_side`、`right_side`、`grid_panels`、`top_header`、`bottom_bar` 等
- `background` —— 颜色、材质或场景
- 文字内容以带引号的字符串内嵌。真实文字原样保留，不要转述；CJK 等非拉丁文字保持原文。

**关键模式：**

*计数加标签（count-and-label）。* 多个同类项目时，给出 `count` 与平行的 `labels` 数组：

```json
"messages": {
  "count": 7,
  "items": ["user1: hello", "user2: hi there", "..."]
}
```

*按位置圈定区域。* 明确写出位置名：`top-left`、`top-center`、`mid-right`、`bottom-center-right`。

*带 title、position、count、labels 的区块对象*（用于多分区信息图）：

```json
{
  "title": "衣装・装備詳細",
  "position": "bottom-left",
  "count": 9,
  "labels": ["胸当て", "肩当て", "腕甲", "..."]
}
```

*可模板化插槽。* `{argument name="city" default="Tokyo"}` 类记法仅在用户明确要可复用模板时使用；一次性提示词保持具体。默认值应是真实可信的值，不是占位字符串。

*内联字体标注。* 字体重要时就地写进字符串：`"title in large serif font"`、`"11px Inter Regular"`、`"Space Grotesk Bold Caps"`。

**实战示例（极简形态）：**

```json
{
  "type": "landing page mockup",
  "style": "clean modern e-commerce, soft pastel palette, generous whitespace",
  "layout": {
    "header": {
      "logo": "small black wordmark 'AURA'",
      "nav": ["Shop", "About", "Journal", "Contact"],
      "cart_icon": "top-right"
    },
    "hero": {
      "left_side": "large product photo of amber glass serum bottle on marble",
      "right_side": {
        "headline": "Skin, restored.",
        "subheadline": "A 7-day reset ritual. Clinically tested.",
        "cta_button": "black pill button 'Shop the ritual'"
      }
    },
    "below_hero": {
      "ingredient_grid": {"count": 4, "labels": ["Vitamin C", "Niacinamide", "Peptides", "Hyaluronic Acid"]}
    }
  }
}
```

#### 格式 B —— 浓密电影化散文

写一段连续的段落，信息大致按此顺序排布：图像类型/媒介 → 带具体视觉细节的主体 → 姿态或动作 → 背景/环境设定 → 环境细节 → 灯光 → 配色/胶片型号/质感 → 情绪描述词。

这个顺序是脚手架而非硬性规则；关键在于把最具体的视觉锚点（媒介、主体、道具）放在足够靠前的位置，让模型先锚定它们。

**要点：**
- **具体胜过氛围。** "White ribbed tank top and a loose beige knit cardigan slipping off one shoulder" 胜过 "casual outfit"。
- **具体道具。** 指名道姓引用确切的东西："a white vintage Toyota Levin hatchback with red taillights"。
- **摄影与胶片语言。** "35mm film photograph"、"direct camera flash"、"low-angle dynamic perspective"、"aerial drone shot"、"shallow depth of field" —— 这些词会把输出引向所指的观感。
- **文字嵌入引号。** 按最终渲染效果原样放进引号：`elegant vertical Japanese text that reads "都会の夜に溶けていく"`。
- **画面有人脸时避免 "photorealistic"。** 改用 "cinematic"、"film photograph"、"35mm"、"editorial portrait" —— 规避塑料皮肤失败模式。

**实战示例：**

> A cinematic, moody photograph of a young Asian woman looking back over her shoulder at the viewer on a rainy night in a bustling street. She has wet, stringy black hair plastered to her face and a melancholic expression, wearing a loose, oversized greyish-green jacket. The street is wet, reflecting the blurred, glowing neon signs and traffic lights of the city. Parked on the wet asphalt to her left is a white vintage Toyota Levin hatchback with its red taillights illuminated. On the top left side of the image, elegant vertical Japanese text reads "都会の夜に溶けていく" in a large serif font. The overall aesthetic is atmospheric and cinematic, 35mm film texture, muted warm palette, capturing a quiet introspective moment amidst urban chaos.

#### 格式 C —— 自动推导元提示词

用户给出一个主题，由模型自行生成完整构图。结构：

```
Please automatically generate a [output type] centered around [THEME].

Require the AI to automatically derive and uniformly design the entire following visual system based on this theme, without my extra specification:
- [list of derivations the model should make — core subject, supporting structure, hovering elements, color hierarchy, material contrast, lighting, typography, etc.]

[Overall Style]
[specific style direction — "cel-shaded illustration", "ultra-realistic 3D commercial CGI rendering", "watercolor and ink hand-drawn illustration", etc.]

[Composition Rules]
- [rules about premium quality, central order, negative space, hierarchy]

[Visual Quality]
- [rules about detail level, lighting, materials]

[Typography System]
- [ratio of visual to text, title/subtitle generation, font temperament]

[Signature]
Naturally add the signature "[NAME]" in the [position].
```

**何时使用：** 用户只给主题、未指定布局时。若布局已被明确指定，改用格式 A —— 自动推导把布局控制权交给了模型，那是错误选择。

### 1.2 通用构图公式

**静帧图像提示词公式：**

```
[Shot size 景别] + [Angle 机位] + [Movement hint 运动暗示] of [主体描述].
[Pose, expression, or action 姿态/表情/动作].
[Environment — location, weather, atmosphere 环境].
[Lighting — time of day, source, quality 灯光].
[Style — cinematic, film stock, color grade 风格].
```

**完整示例：**

```
Medium close-up, low angle, slow dolly in toward the character.
She stares past the camera with narrowed eyes, jaw set, braids falling over
one shoulder. A frozen battlefield stretches behind her, smoke rising from
distant fires. Golden hour backlight rims her silhouette.
Style: Cinematic, Kodak Vision3 500T, desaturated teal shadows, warm highlights.
```

**多元素模型六要素公式**（高保真多元素生成模型上实测有效的展开形式）：
1. **主体（Subject）** — 谁/什么："a stoic robot barista with glowing blue optics"
2. **构图（Composition）** — 取景："extreme close-up"、"low angle"、"wide shot"
3. **动作（Action）** — 正在发生什么："brewing coffee, steam rising"
4. **场景（Location）** — 环境："a futuristic café on Mars, warm amber lighting"
5. **风格（Style）** — 美学："photorealistic"、"3D animation"、"film noir"、"watercolor"
6. **摄影/灯光** — "shallow depth of field (f/1.8)"、"golden hour backlight"、"muted teal color grading"

### 1.3 交付前检查清单

输出提示词前对照六项检查（30–60 秒）：

1. **区域覆盖** —— 每一个可分辨的可见区域，是否都有命名的位置或字段？
2. **计数与标签** —— 存在多个同类项目时，数量与标签是否显式给出？
3. **真实文字保留** —— 真实文字是否保持原文语言并放进引号？
4. **写实框定** —— 人脸占比高的提示词，是否避开了 "photorealistic"，改用胶片/电影语言？
5. **风格具体性** —— 风格描述是否具体到能产出可辨识的美学？
6. **JSON 有效性（仅格式 A）** —— 大括号、逗号、字符串内引号转义是否正确？

### 1.4 多张参考图的使用纪律

- **指明每张参考图的用途。** 多参考输入时，逐张写明分工："Use Image A for pose, Image B for style, Image C for background"。不写分工，模型会把所有参考平均化。
- **说明身份来源。** 附两份以上参考时显式声明："face, bone structure and skin tone come from the character reference; wardrobe and accessories come from the look reference."
- **参考槽位角色约定。** 团队实践中可把每个槽位锁定稳定分工并在整个项目保持一致：`@Image1` = 角色身份，`@Image2` = 服装，`@Image3` = 环境＋灯光，`@Image4` = 构图，`@Video1` = 运动，`@Audio1` = 节奏＋氛围。这是团队侧纪律，不是模型强制；回报是长分镜列表上的参考稳定性。

### 1.5 提示词经济 —— 精简的提示词更能保住脸

当附上了强力参考图时，**身份负载由参考图承担，提示词的职责是说明在这张图里要对这个身份做什么。**

- 用**简短的辨识性称呼**指代主体 —— "the woman with the deep red-burgundy hair" —— 而不是用一段话重新描述参考图已展示的骨相。
- 把负载放在提示词**独有**传达的信息上：构图、取景、姿态、表情、手在做什么、参考图里还没有的着装。
- **删掉参考图已经承载的身份描述**，除非它对这张特定的图有承重作用。
- 模型对提示词**开头**的权重最高 —— 把构图和姿态放在开头。

**经验法则：** 如果一句话重新描述了所附参考图里已经可见的东西，就删掉它，除非构图依赖它。**例外是第一张底版** —— 脸部锁定没有任何参考可依托，它本身就是参考，因此它获得最长、最具体的描述；它之后的一切都更精简。
