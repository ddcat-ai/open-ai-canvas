**总纲：三条结构定律。**

1. **提示词必须描述一个场景，而不是一个主体。**内容过滤器不是关键词黑名单，而是一个把整条提示词当作一场戏来读的语言模型——它比较的是"读起来像电影人在描述一个镜头"与"读起来像写给朋友的便条"。一个孤立看敏感的词可以安然待在结构良好的电影化提示词里；一条没有画面可读的提示词（没有场景、没有视觉目的、没有叙事逻辑）让过滤器无从下手，宁可保守拒稿。**先修语气，再修用词。**
2. **两种体制，不是矛盾。**短句单镜头用 MCSLA 公式与字数区间；多镜头、重参考、高控制的生产工作用块状脚手架——那里*结构取代字数上限*。
3. **写之前的路由先于写本身。**选场景原型、选提示词模式、选工作模式，然后再填公式——同一句话在不同模式下是不同种类的指令。

# 一、MCSLA 公式

每条高效提示词的五个层级——当作摄影指导的核对清单，每层都填好，模型就拥有它需要的一切：

| 字母 | 要素 | 说明 | 示例 |
|------|------|------|------|
| **M** | 模型（Model） | 使用哪个生成引擎 | "使用 Kling 2.6" |
| **C** | 镜头（Camera） | 点名的镜头控制 | "第一人称无人机镜头在巷子里穿行" |
| **S** | 主体（Subject） | 谁/什么 + 外观 | "一位穿沙色西装的女性，眼神锐利" |
| **L** | 外观（Look） | 风格 + 色彩 + 灯光 | "电影感，黄金时刻，变形宽银幕光斑" |
| **A** | 动作（Action） | 场景中发生什么 | "她缓缓转身，风掀起她的外套" |

**导演公式到 MCSLA 的映射与优先级：**主体 → S，动作 → A，两者都进前 20–30 词（前部 token 承担不成比例的权重）；场景是语境细节；镜头 → C 排在主体动作之后；风格 → L 排在镜头之后；约束是末尾护栏。

**类型路由器——各类型的目标长度与开头要素：**

| 类型 | 开头用 | 目标长度 | 开头示例 |
|------|--------|----------|----------|
| 产品 / 电商 | 主体 | 30–50 词 | "一个哑光黑的无线耳机充电盒在大理石底座上缓缓旋转……" |
| 生活方式 / 社交 | 动作 | 40–60 词 | "她伸手去够咖啡杯，蒸汽袅袅上升……" |
| 剧情 / 叙事 | 场景 | 60–100 词 | "凌晨 2 点，雨水砸在东京一条狭窄的小巷里……" |
| 音乐录影带 | 风格 | 50–80 词 | "变形宽银幕光斑、压暗的黑色、16mm 胶片颗粒……" |
| 风光 / 旅行 | 场景 | 30–60 词 | "黎明的光越过火山山脊，雾气从火山口倾泻而下……" |
| 商业 / 品牌 | 风格 | 40–70 词 | "干净的白色影棚，柔和均匀的布光……" |
| 动画 / 艺术 | 风格 | 50–90 词 | "赛璐璐描线、高饱和配色……" |

出现在风格开头的质感词（"16mm 颗粒"）是**观感选择**，放对位置；同一个词缀在末尾沦为干瘪的品质乞求时，会软化整个画面（见《负面约束预防总表》整帧劣化）。

## 1.1 两种工作流格式

**文生视频（T2V）**——从零描述整个场景：

```
[主体 + 外观]。
[环境——地点、时间、天气、氛围]。
[动作——发生什么以及如何发生]。
[镜头——点名的控制]。
[风格——风格 + 调色]。
```

**图生视频（I2V）**——图片定义起始帧：

```
[以输入图片作为第一帧来指涉]。
[描述应该移动、变化或动起来的内容——而不是已经可见的内容]。
[镜头——点名的控制]。
[风格/氛围提示]。
```

**I2V 关键规则：**绝不重新描述图片里已有的内容——只描述应该*变化*的部分。重新描述静态元素等于给同一个主体两个互相竞争的输入，调和过程引入漂移。

## 1.2 叙事式与时间戳式

- **流动叙事（多数场景首选）**——把场景写成连续的动作，不加时间戳。
- **时间戳式（仅用于精确多节拍）**——变形、多阶段动作、卡点 MV 时才用；对应自定义多镜头模式：

```
0–3 秒：大远景定场镜头。拳手独自站在拳台中央，胸口起伏。
3–6 秒：急推变焦对准他的脸。额头挂汗，下颌紧咬。
6–10 秒：他举起双拳，360 环绕。人群喧嚣渐起。
```

# 二、Seedance 六槽公式

每条 Seedance 提示词命中六个槽位，顺序如下：

```
[镜头运动] + [主体] + [动作] + [场景] + [风格] + [灯光]
```

严格来说六槽都是可选的——但六槽齐备的提示词几乎从不被标记，因为过滤器拥有解读每个词的完整语境；缺 3 个以上槽位正是被标记的来源。

**最小可行提示词：**

> **缓慢推轨推近：一个穿深色大衣的身影，独自站在雨后湿滑小巷的尽头。冷青色阴影，一盏实用光源路灯，浅景深。**

镜头✓ 主体✓ 动作✓ 场景✓ 风格✓ 灯光✓——六槽齐备，约 30 词，因场景完全可读而通过过滤器。

# 三、提示词工艺法则

## 3.1 长度与顺序——注意力模型

模型**从左到右阅读提示词，注意力权重递减**：第一句影响力最大；到第三句已进入"细节地带"，元素开始被弥散地采样而非当作主要指令。

- **短句体制最佳区间：50–80 词。**一条 70 词的提示词稳定胜过 200 词的同场景版本——越过约三句，更多的词买到的是弥散，不是控制。
- **三句话结构：**① 主体 + 动作，② 镜头 + 风格，③ 约束 / 正向锁。
- **把最重要的承重元素放在开头**——镜头的生命在主体上就由主体开头，活在运镜上就由运动开头。
- 两个长度数字不冲突：50–80 词是连贯性最优点；约 180 词是过滤器/编码器风险线（>220 词常使文本编码器直接失败）。
- **Seedance 短篇：30–100 词胜出，主体 + 动作放前 20–30 词。**

## 3.2 说出具体之物——消灭空洞形容词

`电影感`、`史诗感`、`美`、`高质量`、`惊艳` 是贴在极大量训练素材上的高频标签，采样自宽泛弥散的分布，不会把输出推向任何具体方向。**不是删掉了事——换成一个有名字、训练分布窄的所指：**

| 空洞形容词 | 有名字的替代物 |
|---|---|
| "电影感 / 史诗感" | 一套灯光布置："黄金时刻逆光，长影向前延伸"；或一条镜头规格："变形宽银幕 2.39:1，来自实用光源的镜头光晕" |
| "美丽 / 高质量" | （删除——改为描述具体的视觉） |
| "动感 / 活力四射" | 快速横移、甩摇、手持；疾跑、跳跃、双臂摆动 |
| "酷炫转场" | 匹配剪辑 / 甩摇 / 重切 |
| "高质量 / 4K 质感" | （删除——分辨率是渲染设置，不是提示词用词） |

导演名字作短句备用招可用（"韦斯·安德森式对称"→居中对称构图、粉彩色调），但**块状脚手架中禁止**——改用可观察语言描述观感本身（详见 §4.2 可测量语言规则）。

## 3.3 "快"是劣化最严重的关键词

与复杂动作或运镜组合时，"快"是单个劣化最严重的关键词：运动叠加时时间分支本来就要并行跑多个高速计算，"快"要求所有计算同时全速运行——两个互相竞争的快速元素会抖动，三个会叠成难以挽救的误差。

**修法：描述物理，而不是速度。**`双脚重重蹬地，每一步完全伸展，双臂以 90 度摆动` 在零劣化下产生速度感。可以让一个元素承担速度——但不能所有元素同时承担。

## 3.4 提示词正文不放负面提示词

Seedance 对提示词文本**没有负面嵌入架构**——每个 token 都被读作*正向*指令。`negative: 抖动、弯曲的肢体` 会被解析成模型试图渲染的场景描述（噪声），让输出更糟。改用**正向约束语句**——直接声明什么必须为真：

```
面部稳定。肢体解剖结构自然。光照一致，无闪烁。
身体比例全程一致。
```

适用范围：打击的是 `negative:` 列表语法与裸否定清单，不是每一个"无"字——正向声明内部的锁式尾巴（"光照一致，无闪烁"）经过实战验证，没有问题。

## 3.5 歧义动词——同形异义词陷阱

一个词如果存在说得通的第二种读法，模型可能选它。案例："风撕扯着她的外套"——本意是织物被猛烈拉动；模型有时把"撕扯"读成撕碎或流泪，镜头随之改变。

**定稿前自检：这个词还能被看成第二种物理现象吗？如果有，换成只有一种现象能对应的说法。**

- "风撕扯着她的外套" → "风猛烈地抽打着她的外套"
- 种子同形词清单（每误读一词就扩充）：撕扯（撕裂/流泪）· 开火（射击/拍摄）· 闪电（奔跑/闪电/螺栓）· 拉（拉拽/素描/拔枪）· 挥手（挥手/海浪）· 冲锋（冲锋/充电）· 摇摆（摇摆/岩石）· 落（落下/水滴）· 火（火焰/开火）· 击（击打/划火柴/闪电）· 碎（打碎/暂停/破晓）· 捶（捶打/心跳）· 咔嚓（折断/拍照）。

## 3.6 运动提示词法则

- **只写单向运动。**一个提前完成的短动作给模型留下几秒钟要填的时间线，它会用**反向执行**来填——向前走然后退回来。把**同方向的 2–3 个相连动作串成链**让运动占满整条片段；一次刻意地去而复返是**两个镜头**，绝不写成一条提示词。
- **给运镜命名终点。**运镜需要目的地而不只是名字——说明**运动结束时画面里是什么**（"缓慢推轨推近，最终停在她双手捧杯上"）。没有终点的运镜会漂移或反向。
- **细节刻度跟随景别。**特写配得上微观细节（手指收紧、下颌绷动）；大远景配得上大幅度弧线（穿过庭院、人群分开）。交叉错配在该景别下无法渲染，并劣化整个片段（详见《构图·纯技术文档》§细节刻度）。

## 3.7 程度副词与三幕节奏

模型无法仅凭画面推断强度——用副词引导解读：`缓缓地`、`猛烈地`、`轻柔地`、`爆发性地`。示例："她**缓缓地**转身，双眼**刻意地**眯起，随后**爆发性地**向前扑去。"

每条动作提示词遵循三幕弧线：**蓄力**（张力积聚）→ **爆发**（动作炸开）→ **余波**（物理后果逐一呈现）。示例："拳手站稳脚跟，双拳攥紧（蓄力）。她踢出一记旋踢，命中沙袋（爆发）。沙袋剧烈摇摆，铁链哗哗作响，沙尘从接缝处喷出（余波）。"

**物理语言**替换氛围词：~~"有力的一拳"~~ → `拳头命中，汗珠慢动作飞散，对手的头猛然后仰`；~~"飞驰的汽车"~~ → `轮胎空转，碎石向后喷溅，加速瞬间车身下沉`。

# 四、块状脚手架——生产体制

短句体制（MCSLA、六槽、50–80 词）管单镜头；块状脚手架是**生产模式**——多镜头、重参考、高控制——在这里结构取代字数上限：要紧处写密，不要紧处写疏，每件重要的事只说一次。

## 4.1 块顺序

只使用该镜头需要的块：

```
场景语境（SCENE CONTEXT）
生效参考（ACTIVE REFERENCES）
位置图（LOCATION MAP）
首帧/走位（FIRST FRAME / BLOCKING）
格式模式（FORMAT MODE）
光学（OPTICS）
镜头（CAMERA）
动作（ACTION）
表演（PERFORMANCE）    （当表演要紧时）
物理（PHYSICS）
灯光（LIGHTING）
调色（COLOR GRADE）    （当调色浓重/风格化时）
服装（WARDROBE）       （当服装要紧时）
音频（AUDIO）
风格（STYLE）          （技术风格后缀）
输出设置（OUTPUT SETTINGS）（当格式必须钉死时）
正向锁（POSITIVE LOCKS）
```

逻辑：先语境与参考，再空间与时间，再动作与物理，然后描述性风格各归其位，技术后缀随后，锁殿后。自然主义单镜头可以省去调色/服装/输出设置块，把注记并入位置图与灯光。

## 4.2 可测量语言规则

- **只用正向措辞**（对 §3.4 的官方确认）。
- **速度用 km/h**——"以 40 km/h 移动"，不写"快"。
- **大气用 % / 米**——"雾密度 40%"、"雾霭在 15 米处可见"；跨镜头分步建立（20% → 40% → 60%）。
- **巨型尺度用人类身高比较**——"有四个头脚相叠的人类那么高"，不写"巨大"。
- **左/右永远以摄影机为准。**
- **情绪经由肌肉运动表达，不用标签**（肌肉级极端版见《面部肌肉FACS》）。
- **白平衡用开尔文**，场景内固定：3200K / 4000K / 5600K / 8500K。
- **物理块用真实单位写质量与尺寸**——重量写进去，重力才读得对："这只蜘蛛 10–12 厘米、50–70 克——它轻轻落下；这个男人 70–80 公斤——坠落砸得很重。"材料行为同理（"藤蔓在受力下微微拉伸，像纤维质木材一样吱嘎作响"）。
- **道具因果互动**——物体绝不自己动；每个道具事件都需要一个可见的物理原因与事件顺序："杯子只有在可见的袖口接触下才倾倒"；"按按钮是一个完整的机械事件——接触、2–3 毫米行程、咔哒、回弹；屏幕只在咔哒之后亮起。"
- **不写导演名字、代表作或设备型号名**——它们会被忽略或破坏复杂运动；描述观感本身。
- **只用英文提示词**（中文例外仅存在于发布窗口期——动用前先核实当前上限状态）。

## 4.3 正向锁

一条**锁**是钉在它所保护对象旁边的简短硬性修正——"车灯在每一个镜头中都保持发光"。正向锁块收尾整条提示词：连续性（角色、道具、环境跨剪切完全一致）加对关键信息的一次正向重述。

**三个被点名的"好心本能"漂移源——各自需要一条常设锁：**

1. **环境发明——头号漂移源，高于角色漂移。**附上位置参考后，模型会"好心地"拓宽房间、添上没被展示过的家具——多位创作者称这是片段间漂移的最大单一来源。常设锁："布景只包含参考所展示的内容——不添加参考之外的家具、房间或地理"；要紧处写明确的不在场（"地上没有任何东西，床上没有任何东西"）。
2. **角色身高均一化。**画面里有两个人时，模型漂向等高。每个有两名以上角色的提示词写入真实身高（"她 165 厘米，他 178 厘米"），让相对比例永不悬浮。
3. **大远景中的比例漂移。**一个人形锚点跨剪切缩成小点。锁住："女孩保持为镇定的常人尺寸锚点——绝不缩成远处的一个小点。"

## 4.4 剪切格式四级阶梯

四个精度等级，选该镜头需要的那一级：

1. **一镜到底**——"一个连续镜头，摄影机不自行剪切。"
2. **顺序剪切、无时间码**——`CUT 1 … CUT 2 … CUT 3`，剪切要紧而精确时机不要紧时用。
3. **计时多镜头**——在声明的秒数处显式剪切（`1.0s 硬切`），节拍必须落在时钟上时用。
4. **自由发挥空镜**——不锁剪切，让模型自己找角度。

凡声明了剪切（无论是否计时），都加上："只在指定点剪切，摄影机不自行剪切。"剪切词表：硬切 / 重切 / 匹配剪辑 / 插入切 / 反打切 / 甩摇切；淡入淡出只在被明确要求时使用。计时节拍必须加总等于声明时长（4–15 秒）。

## 4.5 @ 标签命名法与最小参考文本

- 用户指定的标签逐字采用；否则按加载顺序 `@image1 @video1 @audio1`。
- 参考行 = 角色/体格 + 当前状态 + 独特可见特征 + 动作关键细节 + 声音（仅有台词时）+ "与参考 100% 一致"。**不写年龄**（内容过滤器一读到未成年信号就急剧收紧；同样的信息由体格、磨损与姿态携带——见《表演行为主模块》年龄盲规则）。
- **参考文本保持极简**——长篇外貌文本会与图像打架并劣化它（与 I2V 主体漂移同一机制）。
- **关键细节无论如何用文字写明**——小字、标志、颜色——即使参考图可见；模型可能把它们丢掉。
- **绝不把标签放进该对象不在场的镜头**——模型会强行把它塞进画面。

**给标签命名**——规则是"一个元素，一个名字"，否则项目会长出重复项（同一张沙发活在三个名字之下）：

```
@loc_ON_dorm_commonroom_front_s2    类型 + 项目 + 名称 + [角度] + 场景
@char_ON_Rudy_s2_v1                 类型 + 项目 + 名称 + 场景 + 版本
@prop_ON_pizza                      类型 + 项目 + 名称
```

场景后缀把资产绑定到它所在之处；版本后缀在状态改变时出现——**改变后的状态是一个有新名字的新资产，绝不是覆盖**（宿舍里的角色与病床上的同一个角色，是一个人的两个资产）。标签一致性是唯一规则；相关名字成对可见（地点与走位参考共用同一词干）。

## 4.6 上下文隔离

每次生成都是一块白板，对之前的镜头没有记忆。绝不带入场景编号、剧本标题、前情摘要、未使用的标签或角色，或"如上 / 接续"式措辞——这正是续接公式要求逐字重贴身份块、而不是回指更早提示词的原因。

## 4.7 特殊协议

- **四机制极限 FOV 多镜头堆栈**（8° / 107°）：① 全序列身份锁（所有节拍共用单一位置参考），② 镜头锁开场——每个节拍以显式 FOV 短语开头，③ 镜头核对收尾——每个节拍末尾确认 FOV，④ 色彩经由材质与光呈现，而不是一张清单。**四者缺一，极限 FOV 多镜头在 2–3 个节拍后崩坏。**
- **甩摇需要 ≥0.8 秒的模糊行程**——低于 0.8 秒被渲染成没有模糊的硬切（稳定 → 0.8 秒甩摇 → 稳定）。
- **实时 / 慢动作混用**：速度模式之间只允许硬切；每个镜头从头到尾一种速度。
- **防冲击锁**（裂纹/破碎）："人群是挤压，不是击打"；"裂纹源于边缘应力，而非中心冲击"；"没有冲击点——基于压力的裂纹"；时序从边缘到中心依次推进。
- **观察模式**（偷拍效果）三者同时具备：前景遮挡覆盖画面 20–30% + 摄影机与主体之间的大气雾霭 + 8–12° 远距视点。节拍之间更换遮挡类型；视点保持单一。

## 4.8 实战校准——生产语料结论

来自 13 个共享项目、9 位创作者、约 4,000 条生产提示词的语料校准：

- **脚手架在整个平台成立**：每个项目（写实冒险、韩剧爱情、电视院制剧、动画、定格民俗）跑同一套"风格前缀 + 约束 + 可变镜头"结构；镜头标记出现在旗舰项目 95% 的提示词中；15 秒是主导时长。
- **字数阶梯随语域抬升**：技术演示 218 词 → 电视院制剧 538 → 广告 779 → 类型选集 955 → 冒险电影 1,433（p90 2,648）→ 定格情感剧 2,059。50–80 词是单镜头学说；生产多镜头简报高出它一个数量级。长度随表演复杂度伸缩——绝不为整洁而截断一条反应弧。
- **语域收缩模板**：写实作品保留每一个块（带真实质量的物理块、毛孔级表演块）；风格化作品（动画、定格）舍弃物理/皮肤真实感，保留镜头节拍 + 连续性 + 一条硬性媒介锁。
- **风格前缀是每项目编译常量**：分镜表项目中逐字放在每条场景提示词顶部；独立块提示词则把风格侧面分布进各自归属块（分布式风格——光进灯光块、色彩进调色块、镜头/光学特性进光学块、皮肤与表演进表演块、格式/颗粒/帧率进风格+输出设置后缀；任何风格相关的东西都不开头）。交付哪种形态由工作流决定，不由口味决定。
- **视频提示词是人工撰写的**：提示词增强器在采集到的视频任务中全部关闭、在图像任务中开启——让增强器扩写图像提示词，绝不碰视频简报。

# 五、五种提示词模式

五种生成模式各自采用六槽公式，但应用于不同起点。**同一句话在不同模式下是不同种类的指令**——选模式先于写提示词。

| 模式 | 用途 | 骨架 |
|------|------|------|
| **参考驱动** | 已有角色 + 新动作；跨镜头一致性的主力 | `[源图角色："作为主角"]。[主体执行的动作]。[环境与氛围]。[镜头运动]。[灯光提示]`——绝不重新描述图像已展示的东西 |
| **续接** | 时间上的下一拍；从上一片段最后一帧接起 | `[接续上一条片段]。[紧随最后一帧的新动作]。[续接的镜头调度]。[状态变化]`——只写接下来发生什么；五规则见《镜头组接·纯技术文档》 |
| **扩展镜头** | 空间上拓宽画幅（不是时间延展，也不是镜头拉远） | `[源画幅参考]。向[方向]扩展场景。[新揭示区域]。[保持原主体/构图]` |
| **编辑镜头** | 修补特定细节的定向补丁 | `把[特定元素]改为[新状态]。保持[其余一切]不变。[保全身份、构图、灯光与镜头行为]`——说改什么的同时永远说保持什么 |
| **变换** | 片段内的显式状态变化——变化本身就是内容 | `[起始状态主体]。[触发时刻]。[变换中途——以可观察物理术语]。[结束状态]。[贯穿的镜头行为]。[灯光/色板偏移]` |

**变换的纪律**：必须是一条连续弧线，不是一次剪切；明确描述中间状态——模型需要一个中点锚，否则从起点直接跳到终点（像剪切）或渲染成含混的模糊。时长保持短（5–8 秒是单次变换最佳区间），更长会漂移。区别于视频转视频素材变换（那是从实拍素材出发的另一个工作流）。

**模式选择规则：**已有角色 + 新动作 → 参考驱动；时间下一拍 → 续接；空间拓宽 → 扩展；修补细节 → 编辑；核心创意是片内变化 → 变换。发现自己在一条提示词里跨多个模式——停，选一个，生成，然后把输出当作下一个模式的输入。

# 六、参考角色体系

参考（图像/视频/音频）按它锁定的东西扮演语义角色。**一个属性必须跨多镜头一致读出 → 指派给参考角色；只对一个镜头要紧 → 内联写进正文。**

| 角色 | 锁定什么 | 句式 |
|------|----------|------|
| **角色（Character）** | 主角身份——面孔、体格、辨识标记 | `@Image1 作为主角。[身份块逐字粘贴]。[动作]` |
| **末帧（Last-Frame）** | 新片段从哪个特定帧开始渲染 | `接续上一条片段——[最后一帧所见的简短描述]。[新动作]` |
| **环境（Environment）** | 世界与场景——建筑、光质、天气 | `@Image1 作为环境。[主体+动作]。[与环境一致的光线提示]` |
| **道具（Prop）** | 特定复现物件——戏服、武器、产品、车 | `@Image1 作为道具。[互动]。[与参考相同的几何与材质]` |
| **深度图（Depth Map）** | 场景的三维骨架（亮近暗远的灰度图） | 空间必须守住的场合使用；几何输入不携带风格，与环境参考配对（详见《构图·纯技术文档》） |
| **构图（Composition）** | 取景与构图本身 | `@Image4 仅作构图指南——复制取景与裁切，不复制质感` |

三种被点名的角色短语：`与参考 100% 一致`（身份锁）、`仅风格参考`（模型可延展的环境）、`多样性参考`（人群列队表——克隆大军的修法，见《角色身份与微表情》）。

**逐图槽位约定**（按上传顺序指派句柄，生产中为每槽锁定稳定角色）：`@Image1` 角色身份 · `@Image2` 服装 · `@Image3` 环境+灯光 · `@Image4` 构图 · `@Video1` 仅运动 · `@Video2` 仅镜头运动。

**承重规则：动作上提示词说了算，质感与世界感上参考说了算。**提示词负责写发生了什么；参考负责带出它看起来什么样。身份要紧时，视频参考与图片参考搭配使用。

**提示词守不住的东西，就烤进资产。**当一个属性无论写得多好都会漂移，停止在文本里写它，前移一步生成进资产——参考随后承载该属性。案例是变形宽银幕光学：在视频提示词里要它逐镜漂移；在图像阶段要它就守得住。推广到颗粒、镜头特性、偏色、整段话才能指定的人群。代价：烤进资产的属性不再能逐镜头导演——只烤整条序列恒定的东西。

# 七、场景原型路由器

写提示词之前先判断场景属于哪种原型——原型决定镜头行为、空间逻辑与随时间变化的东西。原型叠加在公式**之上**：先选原型，再填公式。

**动作原型**（决策树：追逐戏？→ 追逐。两个对手互易优势？→ 对决。单次决定性接触？→ 冲撞。都不是 → 默认对决）：

| 原型 | 镜头焦点 | 空间动态 |
|------|----------|----------|
| **追逐** | 距离收拢/拉开；被追者在画面前方，追击者在后方 | 路径变窄/变宽 |
| **对决** | 镜头压低偏向强势一方；强势必须交替 | 拳手互换位置 |
| **冲撞** | 蓄势慢 → 命中快 → 余波慢 | 接触点 = 中心 |

**对决规则：任何一方连续占优不得超过一个节拍。**一方主导全场就描述为单方面痛击，而不是对决。

**通用原型**（决策树：主体在空间中移动？→ 旅途。隐藏变可见？→ 揭示。一切不变？→ 氛围。都不是 → 默认氛围）：

| 原型 | 变化的是什么 | 镜头签名 |
|------|--------------|----------|
| **旅途** | 空间中的位置——道路、飞行、步行 | 跟拍、航拍、并行走动，风景掠过 |
| **氛围** | 什么都不变——氛围就是内容 | 运动极简。缓慢推近或固定保持，戏剧性由微变化承载 |
| **揭示** | 隐藏 → 可见 | 摇镜、摇臂、推轨揭示——镜头控制观众*何时*看到主体 |

**对话原型**（决策树：双方施压、主导易手？→ 对峙。一方榨取一方抵抗？→ 审讯。各有所需？→ 谈判。都不是 → 默认对峙）：

| 原型 | 权力动态 | 镜头签名 |
|------|----------|----------|
| **对峙** | 流动的——每次交锋主导权易手 | 紧凑过肩镜头，权力转换时镜头越过轴线 |
| **审讯** | 不对称——一方榨取一方抵抗 | 提问者低机位仰拍，沉默时推近 |
| **谈判** | 平衡——双方各有所需 | 对称取景，景别对等 |

**台词词数上限：15 秒约容纳 25–30 个口语词。**超了就保留主导权翻转的那句、其前一句铺垫、其后一句反应，其余转成身体行为。

# 八、引擎硬约束

违反它们，无论提示词多好，输出都会崩坏：

**角色与空间：**
- **跨剪辑最多追踪 3 个角色**——每个镜头点出演对手戏的组合与互动向量；超过 3 个就认混身份。
- **出画 = 隐性剪辑**——出画角色在本镜头剩余时长内不存在；绝不在同一连续镜头里编排"出画 + 再入画"。
- **画外 = 不存在**——状态变化必须先在镜头内展示才能被提及；不要提及画外发生的受伤、道具变化或位移。
- **空间连续性在剪辑处断裂**——任何剪辑之后重新锚定位置与朝向；明确说出运动方向。
- **避免反射镜头**（刀刃、水洼、镜子）——渲染反射会破坏场景地理。

**感官：**只描述能看见或听见的东西——没有气味、味觉或内心想法（✅"松针铺满地面，风穿过枝叶"；❌"空气里有松树的气味"）。微表情当物理写（✅"下颌咬紧，鼻孔张开"；❌"看起来很生气"）。

**动作：**意图 + 具名招式，而非生物力学（✅"旋踢后摆腿命中"；❌"左前臂旋转 45° 在手腕高度格挡"——用户点了招式名就保留，描述关节力学就压缩成意图）。力与方向，而非破坏序列（✅"被砸进汽车，金属凹陷"；❌ 三连破坏链）。

**双对比剪辑规则（强制）**：每次剪辑必须同时改变景别**和**镜头性格。景别刻度：大远景 → 远景 → 中景 → 中近景 → 特写 → 大特写；镜头性格：手持 | 固定 | 稳定跟拍 | 摇臂 | 航拍。错误：中景手持 → 特写手持；正确：中景手持 → 大特写固定锁定。

**插入镜头**：任何景别下的亚秒级（0.3–0.5 秒）戏剧标点——不承担剧情节拍；**有因果动机**（观众明白为什么看到它）；**点名主体**（"他的手抓着金属"，不是"一只手"）；同样服从双对比。

**年龄盲角色规则**：绝不按年龄描述角色。触发词：男孩、女孩、儿童、小孩、年轻、青少年、小的。有图片输入时按角色身份（骑手、身影、旅人）、服装和动作描述；没有图片输入时用功能性标签（"一个披羊毛斗篷的身影"）。

**默认从事件中间开始**：场景默认已处于进行之中，除非明确要求"以……开场"或"以……收尾"——不要把前 2 秒浪费在铺垫节拍上。

# 九、迭代纪律

## 9.1 先分岔——失败是系统性的还是随机性的？

在约 1.5% 的视频通过率门槛下，**大多数失败是方差，不是提示词坏了。**

- **失败都是同一种失败吗？**（每次都身份漂移、剪辑数量总不对）→ **系统性**。提示词错了——单变量迭代它。
- **失败方式五花八门、偶尔接近命中？**（这次表演平淡，下次运镜跑偏）→ **随机性**。提示词是对的，只是那一掷没中。**别再碰提示词——锁定它，批量开火，然后淘汰。**

## 9.2 批量抽卡与淘汰标准

判定为随机性时，正确动作是**方差收割**：同一条锁定提示词不变，一次掷 N 发，淘汰筛选。与风格扇出（N 种*不同*外观）正好相反——那是探索，这是利用。

**淘汰标准——对照生成前锁定的可证伪成功标准，不挑"最好看的"：**

1. **先用不变量做硬性闸门**：身份、服装、剪辑数量、文字可读性、点名的物理锚点——触碰任何一条即出局，无论多好看（批量修不了结构性失败，只能躲过随机性失败）。
2. **幸存者中给正在失败的那个随机轴打分**——你重掷所追求的表演、运镜或构图，最好的一发获胜。
3. **一个保留者，其余全部记账**（保留 + 真实的淘汰原因），分母保持诚实。
4. **整批都过不了硬性闸门** → 失败终究是系统性的——停止收割，回去迭代提示词。

## 9.3 一次只改一个变量

提示词接近但还不对时，每次重新生成**只改恰好一个变量**。改了两个而变好，不知道哪个起作用；变差，不知道哪个弄坏——花了一次生成，对提示词一无所获。

**例外**：提示词锁定后纯粹为风格探索而变化（五个灯光变体）时批量改动没有问题——这条规则管*打磨*阶段，不管*扇出*阶段。

工作流：生成基线 → 挑出一个具体问题 → 只改那个变量 → 重新生成 → 与基线对比 → 锁定改动 → 下一个问题。

### 提示词窗口卫生

迭代会积累杂物，四条卫生模式：

- **删除过时的提示词块**——上一段还在写便利贴道具、现在已经转到角色生成，删掉便利贴块，否则模型偶尔把过期道具拽进新生成。
- **就地替换，不追加**——追加式编辑累积互相矛盾的从句（旧"紧特写"与新"大远景"并存），输出退化。迭代时就地替换相关从句。
- **移除过期参考图**——资产变了（拍立得从冰箱上被揭走）就从窗口移除过期参考。
- **过载净化**——提示词膨胀到约 2–3k 字符以上时做一次净化：合并冗余从句、删过时限定词、保留承重结构。

## 9.4 六遍诊断——还不知道哪里出问题时

迭代规则假设你知道该改哪个变量。说不出为什么时，运行六遍诊断序列——每遍按顺序隔离一个变量：

| 遍 | 变量 | 问题 |
|----|------|------|
| 1 | 主体 | 角色/物体的描述是否无歧义？ |
| 2 | 动作 | 动作是否具体（基于物理）且对该镜头单一？ |
| 3 | 镜头 | 运镜是否点名（预设或具体动词），而非暗示？ |
| 4 | 风格 | 观感是否有锚点（调色、镜头、灯光），而不是只有形容词？ |
| 5 | 音频 | 音频是否被描述为带有具体声音的并行轨道？ |
| 6 | 输出 | 画幅、时长和分辨率是否刻意设置？ |

顺序不随意：主体和动作承载最重的 token 权重，按序诊断最先暴露杠杆最高的问题。**不要盲目跑满六遍**——六次重生成花六个额度；大多数失败落在第 1 或第 2 遍。到了第 4 遍仍纹丝不动，提示词需要的可能是结构性重写，而不是迭代。

# 十、发送前核对与常见错误

**写之前先回答五个问题**——"给我来点电影感的"对模型什么都没说：

| 问题 | 要指定什么 |
|------|------------|
| 谁？ | 主体 + 外观 |
| 哪里？ | 环境 + 氛围 |
| 发生什么？ | 1 个主要动作 |
| 镜头运动？ | 点名预设 |
| 情绪/类型？ | 风格 + 调色 |

**每个场景一个动作**：每条片段 1 个主要动作，次要最多 1–2 个；复杂序列拆成独立镜头再拼。**快动作技巧**：快速动作不断变形时，先用慢动作生成再后期加速——模型在慢动作下渲染的物理更干净。

**常见提示词错误速修表：**

| 错误 | 修正 |
|------|------|
| 图生视频里重新描述图片内容 | 只描述变化/移动的部分 |
| 笼统的镜头语言 | 使用确切的预设名称 |
| 未指定风格 | 始终包含视觉风格 + 调色 |
| 单个镜头动作太多 | 拆成多次生成再串联 |
| 相互矛盾的运动 | 绝不同镜混用推轨推近 + 推轨拉远 |
| 先描述冲击结果再描述动作 | 只描述动作，让模型渲染结果 |
| 指名道姓的武术招式链 | 用整体打斗气势代替破坏序列 |
| 动作场景里用多个元素引用 | 静态场景用 @，动作场景用纯文本 |
| 身份与运动混在同一块 | 拆成身份块 + 运动块（见《角色身份与微表情》） |
| 画幅比例写进提示词正文 | 画幅是按模型区分的枚举值，在头部字段设置；正文用日常语言描述取景 |
| "16:9 变形宽银幕" | 输出规格与风格语域二选一（见《镜头语言·纯技术文档》§画幅） |

**子技能冲突裁决顺序**：用户明确指示 > 场景原型 > 情绪同步。裁决不显而易见时摆上台面——告诉用户哪方提名了什么、为什么选这个；暗自挑选是失败模式，透明挑选才是纪律。

**情绪纪律**：绝不留下泛化情绪（"悲伤""惊讶"）——每一种至少对应三四种截然不同的身体实现，泛化提示词每次重生成得到不同的镜头。分解为肌肉动作、呼吸、眼神与皮肤状态；没把握时提供选项让用户选（"是哪一种惊讶？(a) 轻微正向……(b) 震惊……(c) 难以置信……(d) 带着喜悦的惊讶"）。**分层情绪**命名两个语域的叠加（焦虑的决心、疲惫的温柔、苦涩的自嘲）：主导状态写在脸上，底层状态写在呼吸与姿态里，可见的破绽放在眼睛里。再叠一个**微小细节**（"非常难过，下唇在颤抖"）——简单情绪 + 微小细节的复合，胜过过度分解，也胜过过度泛化。具名预设库见《角色身份与微表情》微表情部分。

**音频作为一等元素**：在提示词中单独描述音频，BGM、环境音效与对白作为并行轨道处理（音频纪律详见《负面约束预防总表》时序部分与音画相关条目）。
