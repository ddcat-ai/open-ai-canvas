# 触发与任务识别（模块 01）

> 主链定位：四轴判定（工作模式/视频模式/渲染引擎/输出模型）+ 最小链路与组合触发，只做路由。

## 做什么

本模块是整个工坊的**唯一入口**。任何请求先进这里，过两道闸门，然后被路由出去：

- **闸门一 · 值不值得做** —— 场景审计（数据层 `audit/`）。只跑在文本上，先于任何生成。
- **闸门二 · 怎么做** —— 四轴判定。
- **出口** —— 最小链路 / 组合触发 → 按路由表调 02–13。

本模块**不生产画面内容、不写提示词、不做技术决策**。它只判定与分派；一旦判定完成，领域工作一律交给对应模块。

## 闸门一：场景审计（生成前审查）

> 一句话：**结构上已死的场景照样能生成得干净利落**——模型对"一个节拍配不配待在那里"没有意见；失效只在素材已经生成、剪辑却立不起来之后才浮出水面。所以最便宜的审查发生在生成之前。

每个镜头都消耗额度与迭代次数，本闸门唯一的职责是阻止你花钱渲染一场不可能成立的戏：它决定**哪些**镜头值得这笔开销。

### 五要素引擎（因果链按序检查）

```
目标（Goal）→ 障碍（Obstacle）→ 策略（Tactic）→ 反转（Reversal）→ 价值位移（Value Shift）
```

| 要素 | 判定要点 |
|------|----------|
| **目标** | 主角为之战斗的**唯一且不变**的那件事。大目标从不改变；他可以在*策略*上犯错，绝不在目标上犯错。每场戏的目标必须是指向故事目标的因果一环——**删掉这场戏、链条依然成立 → 不合格**，不允许孤立的戏 |
| **障碍** | 一个**危及**路径阶段或整个目标的环境态势——是*威胁*，不只是*代价*。要说清"什么处于风险 + 规模（局部/全局）"。什么都没处于风险 → 障碍是假的，戏会松掉 |
| **策略** | 威胁**逼**主角选出的那一招，是基于当前不完整知识的合情合理的猜测。引擎本质是**知识缺口**。**每一个失败的策略都必须返回信息**——失败的策略只有在失败什么都没教会时才构成弱点 |
| **反转** | 违背预期的转折，三种形式：① 我自己的动作反噬我 ② 隐藏的施动者被揭露 ③ 局面转向策略所意图的反面。**每个已解决的序列 ≥1 个** |
| **价值位移** | 拱顶石：**观众对一个角色的解读因反转而发生的改变**。它不发生在纸面上，而发生在观看者的头脑里——每次反转都逼观众重新评判这个角色 |

### 两条硬规则

1. **反转与价值位移在序列层面评判，不在单场戏层面。**单场戏可以是纯粹的升级，但一个*已解决的序列*如果零反转，就不合格。序列可以嵌套，每个收束单元都需要自己的反转——审计时标明你在哪个规模上审计。
2. **没有价值位移的反转是惰性的。**一次结构转折若不能移动观众的判决，就不算反转。说不出观众的**前判决**和**后判决**，这个转折就是死重——无论情节翻了多大。

### 审计输出与处置

审计按目标 → 障碍 → 策略 → 反转 → 价值位移的顺序走，输出固定格式（链条检查 + 最弱点 + 三层修改建议）。

**不合格不直接打回重写**，而是给三层建议，三个层级各有意义、不得合并成一次重写：

- **最小改动** —— 保留用户的版本
- **干净版** —— 一个完全成立的版本，即使离原版更远
- **可选** —— 仅当它确实有所增益时

**使用边界**：本引擎的定义**刻意不采用教科书术语**，按原文使用，不要替换成标准编剧术语的宽松解释（那些会让判不过关的场景蒙混过关）。判例来源未在自有素材上系统验证——**作强启发式使用**。

执行细节、审计输出格式与完整流程见 `audit/01-场景审计.md`。

## 闸门二：四轴判定

四轴**独立判定、可叠加、可默认兜底**。四轴的**判定细则本体**见 `spec/01-四轴判定与触发机制.md` §3。

**固定解析顺序**：**工作模式 → 视频模式 → 渲染引擎 → 输出模型**（先定产出范围，再定输入形态，再定光影体系，最后定执行端；后轴不覆盖前轴）。

| 轴 | 取值（默认加粗） | 互斥性 | 细则 |
|----|------------------|--------|------|
| **工作模式** | 🎯 单镜 Prompt / 🎨 角色定妆 / 🎬 片段分镜（≤5 镜）/ **📽️ 完整分镜** / 📦 全量交付 | 只能向前升级 | `spec/01` §3.1 |
| **视频模式** | 图生视频 I2V / 混合 Hybrid / **文生视频 T2V** | 三选一 | `spec/01` §3.2 |
| **渲染引擎** | **UE5 实时** / Arnold 离线光追 | 二选一**互斥**，禁止混用 | `spec/01` §3.3 |
| **输出模型** | 豆包 / **即梦（默认，v1.1.0 作者授权改定）** / H3 Mini（海螺） | 三选一**互斥**，同一交付文件不混用 | `spec/01` §3.4 |

**等价关系**：显式声明「完整分镜 + T2V + UE5 + 即梦」≡ **什么都不声明**——默认兜底就是把四个默认值填进四轴，与显式同义。

**判定纪律**：写之前的路由先于写本身。**先选场景原型、选提示词模式、选工作模式，然后再填公式**——同一句话在不同模式下是不同种类的指令。

### 视频模式的两层粒度

源系统的**视频模式轴是三值**（I2V / Hybrid / T2V）；**即梦平台侧可再细分为三种输入模式**。两者不冲突，是同一轴的两层：

| 源系统轴值 | 即梦平台侧子模式 | 提示词写法 |
|-----------|-----------------|-----------|
| **文生视频 T2V** | 文生视频 | 从零写全；**唯一可指定画幅** |
| **图生视频 I2V** | **首帧**（1 张图 = 第 1 帧） | **只写变化** |
| 同上 | **首尾帧**（2 张图 = 第 1 帧与最后 1 帧） | **只写中段**；图由 04 出 |
| **混合 Hybrid** | 先出人物参考图再入 I2V | 参考图强约束 |

平台侧的模式判据、硬约束与拼装规格见 **12 `platform/03-即梦视频生成模式与提示词规格.md`**；拼装顺序见 12 SKILL.md 的「按模式的拼装顺序」节。

场景原型路由（动作 / 通用 / 对话三族）也属本闸门的判定内容，归 12 `prompt/12-提示词结构.md` §七；**先选原型，再填公式**——原型叠加在公式*之上*，决定镜头行为、空间逻辑与随时间变化的东西。

## 出口：最小链路与组合触发

判定完成后，按下表决定调哪几个模块、按什么顺序调。规则与总路由表一致（见 `影视剧作工坊-路由/SKILL.md`）：

- **单阶段请求** → 直接调用对应模块 skill，不进链。
  例：用户只问运镜 → `影视剧作工坊-08-运镜设计`。
- **端到端请求** → 从 02 起按 13 级主链顺序逐级调用，每级把产物交给下一级。
  例："把这段剧本做成视频生成提示词"。
- **返修** → 11 链路校验不通过时，回溯到对应级重做，而不是从 01 重走全链。
