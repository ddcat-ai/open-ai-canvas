## 1. 功能概述（Feature Introduction）

### 1.1 定位与目标

本技能将**剧情文本**转化为**影视级漫剧分镜头脚本与可直接执行的生成 Prompt 包**，每一个镜头经得起专业摄影指导审视。核心交付是「导演生成文件（文件A）」——代表摄像机视点所见的、每镜一条正向 Prompt，是唯一的生图/生视频真源。

### 1.2 美术风格锚定（强制）

- **国漫写实风**：角色比例写实（7.5–8 头身），面部符合真人骨骼比例，非大眼 Q 版卡通。
- **UE5 质感**：全局光照（Lumen GI）、纳米级几何（Nanite）、光线追踪反射与焦散、电影级景深（DOF）、体积雾与大气散射。
- **材质表现**：皮肤次表面散射（SSS）、织物纤维级纹理、金属各向异性高光、毛发物理解算。
- **光影基调**：电影级三点布光为主体 + 环境光叙事，强调明暗对比的戏剧张力，**拒绝平光**。
- **统一锚定前缀（每个 prompt 必含）**：
  ```
  chinese donghua realistic style, unreal engine 5 render, cinematic lighting,
  volumetric fog, ray tracing reflections, subsurface scattering skin,
  film grain, shallow depth of field, 8k ultra detailed,
  dramatic chiaroscuro, professional color grading
  ```

### 1.3 平台适配规范（红果竖屏）

| 维度 | 规范 |
|------|------|
| 画幅 | 9:16 竖屏（1080×1920） |
| 安全区 | 上下各留 8% 给状态栏/交互按钮，核心内容居中 84% |
| 字幕区 | 底部 15% 预留字幕，关键视觉元素不得进入 |
| 单集时长 | 1–3 分钟（60–180 秒） |
| 镜头密度 | 每集 25–50 镜 |
| 钩子结构 | 前 5 秒强视觉冲击；每集尾镜必为悬念钩子（cliffhanger） |
| 8 秒红线 | 单一静态镜头 ≤8s（刻意情绪留白须标注理由），全技能统一硬约束 |

### 1.4 输出格式与三文件交付

分镜表以 Markdown 表格逐镜输出，行业必填六项标注（镜号/时长/景别/镜头运动/画面描述/对白音效）缺一不可；画面描述须含**剪影可读性**与**三层纵深说明**；面部特写必须标注微表情编号（如 `M23 克制心痛`）；转场必须引用转场库编号（如 `T44 落雪覆盖`）。

**三文件交付（每段落一套）**：

| 文件 | 名称 | 默认 | 内容 |
|------|------|------|------|
| **文件A** | 导演生成文件 `E集-P段号-15s导演生成文件.md` | 必产 | 每镜一条正向 Prompt（唯一生图真源）；内嵌 #1 JSON 真源 / #4 索引汇总 / #7 配音台本 |
| **文件B** | 故事板与分镜头 `E集-P段号-15s故事板分镜.md` | 必产 | 九格故事板 + 分镜表 + 分镜头图片 + 段 Reel 时间轴 + 配音台本 BGM Cue + 本段资产清单 |
| **文件C** | 自检交付文件 `E集-自检报告.md` | **触发式** | 各段自检清单 + #2 机检报告（validate.py PASS/FAIL）+ #10 全片自检报告（Step 6 A~P 层） |

> **交付档位（双档，单一真源 `scripts/seg_tiers.py`）**：15 秒档（默认，±1.5s）／10 秒档（声明「十秒输出交付」激活）。同一部剧全片锁定一档，禁止中途切换。

### 1.5 核心工作流（Step 1–6）

| 步骤 | 名称 | 关键读物 | 产物 |
|------|------|----------|------|
| Step 1 | 剧本解析 | ⑨ 大师剧本技法库（结构/钩子/对白/伏笔） | 核心目标卡、冲突轴线 |
| Step 2 | 角色视觉设定 / 风格基准 | ⑤ 风格基准库 + ⑪ 资产管理库 + ㉕ 角色资产库 | 角色设定卡、风格基准 |
| Step 3 | 构图设计 | ⑳ 镜头焦距库 + ㉓ 9 格模板 + ㉙ 故事板硬约束 | 九格故事板、叙事方案对比 |
| Step 4 | 逐镜细化 | ㉔ 文戏武戏规则 + ⑩ 图生视频模板 + ⑱ 工具适配档案 | 导演生成文件①–⑦（每镜 Prompt） |
| Step 5 | 节奏时间轴（Reel 模拟） | ⑧ 导演分镜体系（节奏量化） | Reel 校验结论、连续播放检查 |
| Step 6 | 全片自检 | ⑮ 质量闭环 + ㉝ 返修决策 | A~P 层自检报告、集索引汇总 |

**导演生成文件七要素（①–⑦，模型无关通用真源）**：① 渲染规格 → ② 画幅画质 → ③ 环境场景 → ④ 人物外观状态 → ⑤ 人物动作 → ⑥ 镜头运镜构图 → ⑦ 光影色彩。选定输出模型后，按该模型参数规范把①–⑦转译为最终 Prompt。

### 2.2 资料库体系（40 库 + 两层存档）

- **40 库（①–㊵）**：按场景/题材/步骤路由，命中即读，未命中不载。其中 **6 库始终读**（所有分镜任务第一个读）：① 分镜方法论、⑧ 导演分镜体系、⑨ 大师剧本技法、⑤ 风格基准、⑥ 场面调度精华、⑦ UE5 灯光精要。
- **母书存档层（`guide-books/`，约 74.8 万字符）**：4 部电影专著全本 + 2 蒸馏手册，是 ⑥⑦⑧㊱⑨⑩ 的母书。命中「要出处/要完整案例/精华不够用/用户点名」四类条件才下钻；先精华后母书，禁止整本通读。
- **剧本样本库（`script-library/`，约 680 万字符）**：319 部竖屏短剧全文，按 20 题材存放。仅对标拆解/卡点参考/人物设定参考/用户点名时读，先读 `INDEX.md` 再定位，禁止复制具体情节进产出。

### 2.3 双引擎（资产层 + 空间层）

| 引擎 | 运行环境 | 触发时机 | 作用层 | 输出 |
|------|----------|----------|--------|------|
| **UE5 建模引擎（v1.0）** | UE5 编辑器 Python（`import unreal`），非独立 | Step 2 后、任何 3D 资产进入 V4 前（资产闸门） | 资产生产与 QC | 命名/LOD/材质 QC 过的 3D 资产 + 坐标 + 材质参数 + 渲染基底 |
| **UE5+Arnold V4 构图引擎** | 独立 Python（纯数学/可扣子节点） | Step 4 复杂空间/群戏站位/多物体碰撞/物理焦距视场角 | 空间物理计算 | `composition_prompt_segment`（拼进①⑥⑦）+ `collision_check` + `composition_score` |

**5 个硬约束咬合点**：① 资产闸门（未经建模 QC 禁止进 V4）② 渲染基底继承 ③ 材质↔着色闭环 ④ 渲染规格双层 ⑤ 自检复用。

### 2.4 加密体系（时间锁 V1）

- **对象**：7 个引擎相关文件（V4 核心 + 建模三脚本 + schema + 2 个 .ini）。
- **机制**：`magic` + JSON header（时间戳 + SHA256 + HMAC）+ base64(XOR 密文)；纯标准库实现，零第三方依赖。
- **三道闸**：① 时间锁（超时自毁）② HMAC 验签（防篡改）③ SHA256 完整性（防损坏）。
- **密钥**：`encrypted/.clock_key`（32 字节 hex），独立备份至 `Desktop/clock_key_backup_*.key`。
- **双备份策略**：明文 + 加密双份留存；密钥丢失即死文件，故独立灾备。

### 2.5 双真源同步

技能根（`.workbuddy/skills/漫剧导演全流程/`）与桌面（`Desktop/漫剧导演全流程/`）字节级同步，由 C7 门自动校验；任一处修改须同步另一处。整体灾备另存 `Desktop/漫剧导演全流程-整体plus版-*.zip`。

## 3. 四轴判定模型（Four-Axis Determination）

收到用户请求后**先判定四轴**再进入流程。四轴**独立判定、可叠加、可默认兜底**。

### 3.1 工作模式轴（默认 📽️ 完整分镜）

| 模式 | 触发条件 | 流程 | 输出 |
|------|----------|------|------|
| 🎯 单镜 Prompt | 「出一张图」「写个 prompt」 | 跳过 Step 1–3，直接单镜 | 1 条生图 prompt + 负面词 |
| 🎨 角色定妆 | 「设计角色」「出设定图」「定妆」 | 只走 Step 2 | 角色设定卡 + 设定图 prompt |
| 🎬 片段分镜 | 「拆这段戏」≤5 镜 | 精简 Step 3–5 | 精简分镜表 + Reel（无 JSON sidecar） |
| **📽️ 完整分镜（默认）** | 给完整剧本/多场景；或未声明其余 | 完整 Step 1–6 | 文件A + 文件B + 触发式文件C + 集索引 |
| 📦 全量交付 | 「全部生成交付文件」「一键交付」「跑流水线」 | Step 1–6 + 一键流水线 | 十项交付清单一次出齐 |

> 模式只能向前升级（片段发现 >5 镜转完整；全量交付内含完整分镜不重复 Step 1–6）。

### 3.2 视频模式轴（v63 起默认 文生视频 T2V）

| 模式 | 触发声明 | 权重 | 核心文件 |
|------|----------|------|----------|
| 图生视频 I2V | 「图生视频」「参考图生视频」 | 首尾帧 90% | 两类核心文件 |
| 混合 Hybrid | 「混合」「先出人物参考图」 | 导演生成文件 90%（参考图强约束） | 人物参考图前置 + 两类核心文件 |
| **文生视频 T2V（默认）** | 未声明 / 「文生视频」「纯文本生视频」 | 导演生成文件 90%（纯文本驱动） | 两类核心文件 |

> 默认已从 I2V 切到 T2V；要 I2V 须显式声明。混合模式按「视频交付方式」再分支取舍 Prompt 集。

### 3.3 渲染引擎轴（v63 起默认 UE5 实时）

| 引擎 | 触发 | 默认 | 互斥 |
|------|------|------|------|
| **UE5 实时** | 未声明（默认） | ✅ | 与 Arnold 互斥 |
| Arnold 离线光追 | 「Arnold 模式」「阿诺德模式」「离线渲染模式」「物理光追模式」「电影 CG 静帧模式」 | ❌ 触发式 | 与 UE5 互斥，禁止混用 |

> 声明 Arnold → 读 ㉗ Arnold 渲染库，替代 ⑤ UE5 灯光库的人物光影部分；㉛㉜ 物理阈值两分支通用。仅 ㉚ 甲骨文/文物特例允许 Arnold+UE5 受控混合。

### 3.4 输出模型方案轴（默认 豆包）

| 模型方案 | 触发声明 | 默认 | 互斥 |
|---------|----------|------|------|
| **豆包** | 未声明（默认） | ✅ | 三方案互斥 |
| 即梦 | 「即梦」「即梦视频」 | ❌ 触发式 | 三方案互斥 |
| H3 Mini | 「H3 Mini」「MiniMax」「H3」「海螺」 | ❌ 触发式 | 三方案互斥 |

> 三方案互斥，**靠提示词触发，默认豆包**；同一交付文件一次只出现一种模型方案，不混用（豆包/即梦/H3 Mini 同一镜 Prompt 不可并存）。
> H3 Mini 七段编写逻辑：① 主体 → ② 场景环境 → ③ 运镜与景别·焦距（取自 ⑳ 焦距库）→ ④ 光影与风格 → ⑤ 画幅与时长 → ⑥ 环境音 → ⑦ 配乐；V4 的 `composition_prompt_segment` 拼进其运镜光影段。

### 3.5 四轴叠加矩阵（常见组合）

| 组合 | 工作 | 视频 | 引擎 | 模型 | 说明 |
|------|------|------|------|------|------|
| 默认链路 | 完整 | T2V | UE5 | 豆包 | 未声明即走此链 |
| 参考图生视频 | 完整 | I2V | UE5 | 豆包 | 用户供参考图，首尾帧 90% |
| 混合定妆优先 | 完整 | Hybrid | UE5 | 豆包 | 先出人物参考图基准 |
| 电影 CG 静帧 | 完整 | T2V/I2V | Arnold | 豆包/即梦 | 文物/电影级静帧，㉚ 特例可混合 |
| H3 Mini 出片 | 完整 | T2V/I2V | UE5 | H3 Mini | MiniMax H3 Mini 执行，七段转译 |
| 一键全量 | 全量 | T2V | UE5 | 豆包 | Step 1–6 + 一键流水线 |

### 3.6 叠加触发解析规则

- **固定解析顺序**：工作模式 → 视频模式 → 渲染引擎 → 输出模型（先定产出范围，再定输入形态，再定光影体系，最后定执行端；后轴不覆盖前轴）。
- **正交性**：四轴作用层正交无交集——工作=做多少 / 视频=拿什么驱动 / 引擎=光影素材端 / 模型=执行端转译；仅引擎与模型两端对接，不互斥。
- **等价关系**：显式声明「完整 + T2V + UE5 + 豆包」≡ 什么都不声明（默认兜底是把四默认值填进四轴，与显式同义）。

## 4. 触发机制（Triggering Mechanism）

### 4.1 触发体系总览（四层）

技能触发按「**判定 → 触发 → 读取 → 执行**」顺序作用：

| 层 | 触发对象 | 判定时机 | 默认值 | 互斥性 |
|----|----------|----------|--------|--------|
| **L1 四轴判定** | 工作/视频/引擎/输出模型 | 首条消息 | 完整 / T2V / UE5 / 豆包 | 四轴独立可叠加；视频三选一；引擎二选一互斥；模型三选一互斥 |
| **L2 触发式交付** | 文件C自检 / 模块化子输出 / 全量交付 / 十秒档 | 用户显式提示词 | 文件C 不产 / 15 秒档 | 全量交付内含完整分镜，不重复 Step |
| **L3 引擎条件触发** | 建模引擎 / V4 构图引擎 | 按镜条件 | 建模=资产生产必跑 / V4=复杂镜才跑 | 建模先于 V4（资产闸门） |
| **L4 库读取触发** | 40 库按场景/步骤/题材/风格 | 命中条件即读 | 6 库始终读 | 双真源同步，C7 门校验 |

### 4.2 触发三原则（单独 / 叠加 / 默认兜底）

> 四轴判定的根本规则，三条同时生效，缺一不可。

- **原则① · 单独触发**：任一轴的任一方案均可单独声明，只切该轴，其余三轴维持默认。例：只说「即梦」→ 工作/视频/引擎不变，仅输出模型切即梦。
- **原则② · 叠加触发**：多轴可同时声明，四轴作用层正交无冲突，命中即切、未命中取默认，下游按四轴组合贯通解析。例：「混合 + Arnold + H3 Mini」三轴同时生效不互相抵消。
- **原则③ · 默认兜底**：四轴全部未声明（用户只给剧本）→ 走默认链路，与任一轴的显式触发**语义等价**。不存在「声明了某轴却下游断裂」的情况——**全链路始终成型**。

### 5.3 时间锁加密（clock_lock_crypto V1，纯标准库）

**加密文件结构（.clock）**：

```
行1: CLOCK_LOCK_V1                  # magic 标识
行2: <JSON header>                  # 时间戳 + 哈希 + HMAC
行3: <base64 payload>               # 加密内容（SHA256 迭代密钥流 XOR）
```

**header 字段**：`magic` / `issued_at`（签发 ISO8601 UTC）/ `expires_at`（失效时间，null=永不过期）/ `payload_sha256`（明文 SHA256）/ `hmac_sha256`（防篡改签名）。

**三道闸（任一不过即失效自毁）**：① 时间锁 `now > expires_at` → 超时自毁 ② HMAC 验签 `header+payload` 不符 → 被篡改 ③ SHA256 完整性 解密后不符 → 内容损坏。

**CLI**：

```bash
python scripts/clock_lock_crypto.py

python scripts/clock_lock_crypto.py encrypt <in> <out> --valid-days 365

python scripts/clock_lock_crypto.py verify <plaintext> <clock> <keyfile>

python scripts/clock_lock_crypto.py decrypt <clock> <out> <keyfile>
```

**密钥**：`encrypted/.clock_key`（32 字节 hex）；密钥文件本身不在加密范围，但记入 SHA256 指纹供审计；独立备份至 `Desktop/clock_key_backup_*.key`，丢失即死文件。

**与技能体系映射**：防篡改校验 ↔ 文件C 自检·#2 机检；时间锁 ↔ ⑱ 工具适配档案时效件；双备份 ↔ 双真源一致性铁律；SHA256 ↔ ㊴ 卷积校验；HMAC ↔ ㊵ 材质校验。
