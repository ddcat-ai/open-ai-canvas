# 融合执行规则（十条）

来源资产（下篇《影视视觉风格精华熔炼》全文）与本层已有的六维 DNA、视觉控制轴、光影系统、色彩系统、影像质感、15 位导演视觉 DNA、15 种通用影视视觉风格、风格融合、冲突检测、图片→视频规则、负面约束、调用模板与执行规则**全部进入融合层**——不做删节式引用，任何一条都可能被下游取用。

1. **风格不是单个标签。**风格调用优先拆解为：构图与镜头 / 色彩与光影 / 质感与氛围 / 经典场景 / 角色与动作 / 色调细节。调用时至少选 3–5 个真正决定画面的参数，**不要只调用风格名称**。
2. **五轴融合。**实际组合至少按五轴处理：**构图 / 光影 / 色彩 / 质感 / 动作与运镜**。导演名或电影名只作为**风格锚点**，不作为最终提示词的唯一内容。
3. **风格剂量。**默认每次优先选择**少量高权重特征**；质感组件默认 **2–4 个**，用户显式要求时才允许突破。
4. **风格冲突。**冲突检测**不得静默删除用户明确要求**。默认取"主导系统 + 局部点缀"；用户明确要求混合冲突时，**保留冲突**，并把冲突作为视觉意图的一部分传递到语义转换层（12）。
5. **视频必须增加动态。**图片视觉描述进入视频链时，必须额外处理五个维度：**人物动作 / 镜头动作 / 环境动态 / 细节捕捉 / 最终情绪**。
6. **负面约束分类组织。**Negative 按**通用 / 风格 / 镜头与动作 / 人物 / 模型能力**等来源组织，**不得机械堆入最终提示词**（交给 13 交付文件审核按类取用）。
7. **参数化且不丢真相。**焦段、光圈、色温、帧率、时长等技术字段可以生成模型语义，但**技术真相本身不得因语义化而被删除**。做法是双份保留：`render_profile` 里留原值，画面层另出一份模型语义版；12 做画面化改写时依据原值，**不得凭最终画面语言反推技术真相**。
8. **字段级映射。**视觉 DNA 的拆解结果映射到**构图 / 光影 / 色彩 / 质感 / 表演 / 运镜 / 负面**各自独立的字段，**不压缩回单一风格字符串**。
9. **回到主链路。**融合后的视觉能力最终必须回到主生成链路：**导演决策 → 生成语义 → 语义转换（12）→ 验证（11）→ 最终提示词交付（13）**。本层不得自成终点。
10. **完整保留优先于精简。**任何"这段用不上"的判断都可能导致下游缺字段；宁可多写一行推导依据，也不要删源。
