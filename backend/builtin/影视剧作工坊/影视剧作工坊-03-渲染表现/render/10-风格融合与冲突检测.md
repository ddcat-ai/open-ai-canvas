# 风格融合引擎（执行层）

风格融合不要简单地写成：

```
导演A + 导演B + 导演C + 胶片 + 霓虹 + 武侠 + 赛博朋克
```

正确方式是**先拆轴，再决定谁控制哪一个轴**。

---

# 一、五轴融合

| 轴 | 管什么 |
|---|---|
| **A 构图语言** | 景别、角度、对称 / 失衡、留白、遮挡 |
| **B 光影语言** | 光源类型、硬软、反差、明暗区域 |
| **C 色彩语言** | 主辅色、冷暖关系、饱和度策略 |
| **D 质感语言** | 胶片 / 光学 / 工艺 / 环境 / 运动质感 |
| **E 动作与运镜语言** | 镜头运动形式、主体动作强度 |

**每个轴只放一个来源。**两位导演可以在不同轴上各管一项，但不能在同一轴上抢占同一参数。

示例：

```
构图：东方武侠
光影：自然诗意
色彩：冷青 + 暖金
质感：35mm 细颗粒
运镜：缓慢推近
```

这样形成的是一套**视觉系统**，而不是名字堆叠。

# 二、冲突检测

出现下列冲突时，**应自动减权**：

| 冲突 | 两端 |
|---|---|
| 光线性格 | 平面柔光 ↔ 极端硬光 |
| 饱和度 | 极低饱和 ↔ 极高饱和 |
| 动静强度 | 静态固定机位 ↔ 强烈高速运动 |
| 秩序 | 极致对称 ↔ 强烈失衡 |
| 光源性质 | 真实自然光 ↔ 高度人工舞台光 |
| 密度 | 极简留白 ↔ 元素密集 |
| 洁净度 | 细腻洁净 ↔ 粗粝重颗粒 |

## 判决规则

1. **默认选一个主导系统**，其他系统只作为**局部点缀**（例如整体采用对称绘本构图，只在某个过渡段落保留手持呼吸感）。
2. **用户明确要求混合冲突时，保留冲突**，并把"这里存在冲突"作为视觉意图的一部分显式传递到语义转换层（12）——不得静默删除。
3. 冲突被保留时，要在 `render_profile` 里标注来源与比例（谁主导、谁点缀、点缀占多少），供 11 链路校验核对。

## 与其他模块

- E 轴（动作与运镜）的最终形态交给 **08**；本表格只判断"动静强度是否冲突"。
- B 轴与 D 轴的具体参数分别落到 **06 灯光**与 **02 调色**；本层负责发现"两者打架"。
