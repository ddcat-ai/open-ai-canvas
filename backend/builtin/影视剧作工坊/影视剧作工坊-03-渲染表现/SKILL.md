# 渲染表现（模块 03）

> 主链定位：风格→路径路由。把 02 定下的"这部片是什么调子"翻译成"这条画面用什么生产路径实现"，产出可交付的渲染档案。

## 做什么

确立**每个镜头（或每条风格档位）的视觉生产路径与渲染属性**，产出 `SHOT_RENDER_PROFILE` ——它是 12 技术语言转换选择 UE5 / Arnold 通道时的唯一依据。

本模块回答四个问题：**用什么做（载体 / 美术方向）→ 做到多真（写实度）→ 怎么算（渲染策略）→ 谁去算（渲染器）**，以及画面侧的六维 DNA（构图 / 光影 / 色彩 / 质感 / 场景 / 动作）。

**方法边界**：

- 02 定**整片影调与调色**（调色情绪、调色板、胶片型号、60/30/10）；本模块定**生产路径与材质光学响应**。选了某种调色板不等于选了某个渲染器。
- 06 定**单镜的景别、机位、灯光物理**；本模块的构图轴与光影系只给**风格侧取值倾向**，落地参数以 06 为准。
- 08 定**镜头运动形式与参数**；本模块只在五轴的 E 轴上判断"动静强度"。
- 12 定**技术词→画面语言的转换**；本模块产出的是技术字段本身，**技术词不进最终提示词**。

## 双引擎

- **渲染智能** —— 本模块内的固定链前半段（意图解析 → 路由 → profile 生成）。
- **语义转换** —— 12 技术语言转换（UE5 / Arnold 通道）：UE5 通道（实时渲染：Lumen / Nanite / Substrate / VSM）与 Arnold 通道（离线渲染：Path Tracer / Standard Surface / Atmosphere Volume）。二次元 / 赛璐璐**不走渲染通道**，走独立风格化输出。

两者通过 `SHOT_RENDER_PROFILE` 衔接：渲染智能产出字段，语义转换消费字段。

## 基础引擎
本模块的底层方法论源：`engine/E03-渲染表现.md`（本模块目录内，12 条，来自 book02）。
执行本模块前先查阅该引擎，取其判断依据、创作准则与反模式清单；引擎为只读源层，本模块负责执行流程。

其中两条对本模块最关键：**介质选择参与质感定义**（换介质即换全片气质）、**让光可见：先给光一个介质**（体积光必须有灰尘 / 蒸汽 / 水珠承载）。

## 执行流程

1. **接风格前提** —— 从 02 拿到全局风格前缀（调色情绪、调色板、60/30/10、胶片型号），从 01 拿到本次任务的四轴判定。
2. **拆视觉意图四维** → `render/01`
   按 A 生产体系 / B 写实度 / C 渲染策略 / D 渲染器逐维取值；**用户没说的维度保持未指定**，补齐的必须标为推导值。
3. **组九轴组合** → `render/02`
   落到九轴取值组合，过七条兼容原则；需要路径别名（虚幻五 / 阿诺德 / 国漫 3D / 好莱坞级）时按别名表转写。
4. **走渲染路由、产出 profile** → `render/03`
   按九步处理顺序生成 `SHOT_RENDER_PROFILE`，`locked_fields` 与 `derived_fields` 分开写；**渲染器不得反向改写写实度**（禁止反向污染）。
5. **拆视觉 DNA** → `render/05`
   取导演流派时先在 `render/08` / `render/09` 里找到锚点行，再把它拆到六维；**至少选 3–5 个真正决定画面的参数**，不写单一风格标签。
6. **定光色策略** → `render/06`
   选一支光影系 + 一种色彩策略；具体数值以 02 的调色板与 60/30/10 为准，布光落地以 06 为准。
7. **配质感组件、控剂量** → `render/07`
   从五组里取 **2–4 个**组件；胶片型号沿用 02 的选择；运动质感里的手持、抖动、呼吸感须在 08 的预设库（`moves/09-镜头运动预设库.md`）取同名预设，避免本层与运镜层写出两种不同的抖动。
8. **过五轴融合与冲突检测** → `render/10`
   每个轴只放一个来源；七组冲突按"主导 + 点缀"判决，用户明确要求时保留冲突并标注比例。
9. **图片 / 视频分流** → `render/11`
   进视频链必须补齐**人物动作 / 镜头动作 / 环境动态 / 细节捕捉 / 最终情绪**五维；运镜初稿再交 08 落成参数。
10. **过十条融合规则** → `render/04`
    重点自查：用户明确要求的东西有没有被静默删除、技术真相有没有因语义化丢失、有没有压缩回单一风格字符串。
11. **填调用接口、生成反向约束** → `render/13` / `render/12`
    字段级落到 `visual_style`；`negative_constraints` 按来源分类、与目标风格一一对应（交给 13 按类取用，不机械堆入提示词）。
12. **交下游** —— profile 与 `visual_style` 交给 **12** 走 UE5 / Arnold 通道转画面语言；技术词本身不进最终提示词。

## 与其他模块的关系

- **上游 01 / 02** —— 01 判定本模块是否参与（纯脚本类任务可跳过）；02 给影调基线，本模块负责把它落到生产路径上。
- **下游 06 / 07 / 08 / 10** —— 它们消费本模块的取值倾向并落成各自的参数；冲突时以它们的落地参数为准。
- **下游 12** —— profile 中的渲染器字段决定走 UE5 通道还是 Arnold 通道；二次元 / 赛璐璐不走通道。
- **交叉 11 / 13** —— 11 校验 profile 的 `locked_fields` 有没有被下游吃掉；13 消费分类后的负面约束。
- **同层 04** —— 04 的美术画风族（国风 / 次世代 CG / 半厚涂 / 胶片油画）与本模块的美术方向轴（GUOMAN / NEXT_GEN / ANIME_COMIC）是同域的不同层：**04 定资产画风，本模块定渲染策略**，两者可叠加不覆盖。

## 硬规则速记

- **四维正交**：生产体系 / 写实度 / 渲染策略 / 渲染器互不推导——"次世代"不等于 UE5，"电影 CG"不等于 Arnold。
- **渲染器不反向定义意图**：选了 Arnold 不擅自升超写实，选了 UE5 不擅自降成预览质感。
- **推导值必须标记**：补齐的轴进 `derived_fields`，不得伪装成 Human Lock。
- **导演名 / 类型名只做锚点**，不写进最终提示词；至少拆 3–5 个 DNA 参数。
- **风格剂量 2–4 个质感组件**，一次只用一种胶片型号。
- **每个轴只放一个来源**；冲突按"主导 + 点缀"，不得静默删除用户明确要求。
- **技术字段原值与画面语义双份保留**，不得凭画面语言反推技术真相。
- **视频必须补齐五维动态**（人物动作 / 镜头动作 / 环境动态 / 细节捕捉 / 最终情绪）。
- **负面约束按类生成**——与目标风格不对应的通用禁词会削掉画面里想要的东西。
- **不承诺 100% 复刻**，交付的是视觉 DNA 与风格方向。
