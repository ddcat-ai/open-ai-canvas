# Higgsfield 具名运动预设

> **落位说明**（并入影视剧作工坊时添加，正文保留原文）
> 来源：Higgsfield 具名运动预设（higgsfield-motion v3.2.1）　原文文件名：`8-运动预设库.md`
> 现行位置：`影视剧作工坊-08-运镜设计/moves/12-运动预设.md`

Higgsfield 拥有 100 多个具名运动预设。在提示词中**按准确名称**引用它们，平台就会应用该预设的招牌效果。可以把它们理解为 VFX 宏——一个名字就能触发一整套预先构建好的视觉效果。

> **范围说明** `[FIELD — 13 个项目社区采集 + 实时预设目录拉取，时间均为 2026-07-18]`：运动预设是**病毒式特效 / 社交类产品**，而不是电影语法。13 个被采集的社区电影/广告项目没有一个用过任何运动预设——严肃的影视作品都是通过 Cinema Studio / Seedance 区块简报以自由提示词方式驱动镜头（`../higgsfield-camera/SKILL.md`、`../higgsfield-seedance/SKILL.md`）。另外，实时目录拉取显示约 100 个唯一预设名扩展成了约 1,900 个按模型划分的变体（kling / higgsfield / wan / minimax / seedance 各家族，内嵌固定参数）；拉取时的分类权重偏向 effects/viral/vfx/ugc。预设类请求照旧路由到这里——但当自由提示词的镜头语言才是经过制作验证的路径时，不要把影视拍摄类需求引导到预设上。

**在提示词中的用法：**
```
[你的场景描述。] 应用 [预设名称] 预设。
```

## Intent-First Choreography（意图优先编舞）—— Cinema Studio 3.0 / Seedance 2.0 最佳实践

这些原则适用于 Cinema Studio 3.0 的生成引擎（仅限 Business/Team 套餐），是对上文运动预设库的补充。

### 意图优先于时间戳（Intent over Timestamps）

描述动作的**意图与后果**，而不是精确到逐帧的编舞。让 AI 导演去处理关键时刻之间的插值。

**错误：** `在第 0 秒：角色抬起右臂。在第 1 秒：手臂达到 45 度。在第 2 秒：手臂完全伸展。在第 3 秒：能量球成形。`

**正确：** `角色缓缓抬起手臂，能量在掌中汇聚，直到在一片炫目的闪光中爆发。火花四散落在地板上。`

### 以 @Video 参考作为首选方法（@Video Reference as Primary Method）

对于所有动作戏和打斗戏，@Video 参考（Reference）是最可靠的方法：

1. 上传一段展示你想要的运动的参考片段
2. 用 1–3 句话描述高层动作
3. 添加程度副词（`violently`（猛烈地）、`gracefully`（优雅地）、`explosively`（爆发式地））和物理后果（`dust erupts`（尘土爆起）、`sparks fly`（火花四溅））
4. 告诉模型参考该片段

```
参考 @Video1 的动作编舞。
一名剑士爆发式地拔剑，连续快速斩断三根竹竿。
竹竿倒下，树叶飞散，剑刃在阳光下闪耀。
```

> **能力边界：** 关于 `@Video` 参考对场景世界 / 材质纹理 / 镜头性格 / 制作质感各自哪些读得可靠、哪些读得不太可靠——以及它完全做不到的部分——参见 `../higgsfield-camera/SKILL.md` 的「Video Reference — What It Reads, and What It Can't」一节。上文针对动作的具体指导仍然是打斗戏与追逐戏的首选方法。

### One Action Per Shot（每镜头一动作）规则

对于纯文本动作（没有视频参考），不要把多个不同的动作串进同一句话里。按镜头拆分：

**错误：** `她跳过墙，落地翻滚，拔出武器，边跑边开了三枪。`

**正确（拆成多个独立的 Cinema Studio 3.0 镜头）：**
- 镜头 1：`她跃过墙头，大衣翻飞。重重落地后向前翻滚。`
- 镜头 2：`从翻滚中起身，她一气呵成地拔出武器。`
- 镜头 3：`全速奔跑中，她连开三枪。枪口火光照亮小巷。`

### Beat Density（节拍密度）诊断

如果输出模糊、抖动或形变：说明**在太短的时长里塞进了太多动作。**

模型能处理的是**每 5 秒 1–2 个清晰的动作节拍**。如果你的提示词在 5 秒窗口里出现 4 个以上动作，模型无法全部解析，就会产生伪影。

| 时长 | 最大节拍数 | 示例 |
|----------|-----------|---------|
| 3–5 秒 | 1–2 | 跳跃 + 落地 |
| 5–8 秒 | 2–3 | 跳跃 + 落地 + 拔武器 |
| 8–12 秒 | 3–5 | 跳跃 + 落地 + 拔武器 + 开火 + 找掩体 |
| 12–15 秒 | 4–6 | 完整动作序列（使用多镜头） |

**修复方法：** 把密集的动作拆分到多个镜头，或延长时长，给每个节拍更多时间。

## Kling 3.0 Motion Control（动作迁移）—— 何时用、怎么用

**重要：** 这不是一个具名运动预设。本子技能中上方的全部内容都是 VFX 预设库——Explosion（爆炸）、Werewolf（狼人）、Air Bending（御气术）等等——由预设名称触发预先构建好的效果。Kling 3.0 Motion Control（动作迁移）则是一套完全不同的系统：一种基于参考视频的动作迁移工作流。你上传一张角色图像，加上一段承载你想要动作的短片段，模型会把该动作迁移到角色身上。提示词描述的是动作周围的世界——而不是动作本身。

### 何时选择 Motion Control（When to Choose Motion Control）

当生成需要受指导的、可复现的运动，而不是松散的自由发挥时，就用 Motion Control。典型场景：舞蹈编舞、体育或运动节拍、表演或反应节拍、口播人像（talking head）的精确手势，以及把同一动作模式迁移到不同角色身上（例如把一段采集好的表演应用到多张主视觉图上）。它也可以作为更重量级的 Kling 3.0 合成之前的场景原型化步骤——先锁定动作，再围绕它搭建周围场景。

### Higgsfield 八步工作流（The 8-Step Higgsfield Workflow）

按以下顺序在 Higgsfield 界面中运行 Motion Control：

1. 在 Higgsfield 中**打开 Video（视频）标签页**。
2. 在模型选择器中选择 **Kling Motion Control 3.0**。
3. **上传动作参考视频**——承载你想要迁移的表演的短片段。
4. **上传角色图像**——面部和身体都应清晰可辨；动作将被映射到它上面。
5. **选择输出分辨率**——720p 用于更快迭代，1080p 用于最终交付。
6. **设置 Scene（场景）来源**——决定环境是来自动作视频的背景，还是来自角色图像的背景。
7. **打开 Advanced Settings（高级设置）**——在此处的提示词输入框中描述灯光、氛围与背景处理，并选择方位模式（Image Orientation（图像方位）适用于身体基本静止、以镜头为主导的镜头；Video Orientation（视频方位）适用于舞蹈或动作这类全身运动）。
8. **生成（Generate）**——审看结果：如果动作不对，先迭代参考片段；如果场景不对，再迭代提示词。

## 动作参考输入检查清单（Motion Reference Input Checklist）

输入质量决定输出质量。如果参考片段很糟糕，迁移结果也会很糟糕——再怎么打磨提示词也救不了一个糟糕的源。在点击 Generate（生成）之前，请对照这份起飞前检查清单核对参考片段：

- [ ] **画面中只有一个清晰主体。** 多人片段会干扰动作提取；裁剪或修剪到单个表演者。
- [ ] **头部和身体都完整可见。** 只要有一个被切掉，动作迁移就会丢失面部表演与身体动作之间的关联。
- [ ] **真实的人类动作。** 风格化动画、逐帧转描素材和重度滤镜片段的迁移不可靠。自然表演的识别效果最好。
- [ ] **没有剪切、叠化或生硬的镜头转场。** 参考必须是一个连续镜头（continuous shot）——片段内的任何剪切都会在生成输出中表现为跳变或突兀的断裂。
- [ ] **避免极快的动作。** 在源里看起来一片模糊的动作无法被干净地迁移。慢速到中速的表现最好。
- [ ] **片段时长 3–30 秒。** 低于 3 秒动作数据不足；超过 30 秒则超出 Motion Control 支持的范围。

**经验法则：** 如果你都难以逐帧描述参考片段里正在发生什么，模型同样会难以做到。在把积分烧在一次注定失败的生成之前，先修剪、重拍或重新挑选参考片段。

### 绑定模式、动作来源与输出变短诊断（Binding modes, motion source, and the shortfall diagnostic）

几个控件和一项诊断补全了 Motion Control 工作流的全貌：

- **动作来源——上传片段或动作库。** 动作既可以来自你自己上传的参考片段，*也可以*来自 Higgsfield 内置的动作库。当你想要一段经过验证的成熟表演（一段舞蹈、一个运动节拍）而不必自己采集素材时，动作库是更快的路径。
- **Matches Video 与 Matches Image（匹配视频 / 匹配图像）。** 迁移会把结果绑定到动作视频或角色图像二者之一。*Matches Video* 跟踪参考片段的全身运动与节奏；*Matches Image* 把结果锚定在角色图像上（更适合身体基本静止、以镜头为主导的镜头）。这与工作流第 7 步中 Image-Orientation（图像方位）/ Video-Orientation（视频方位）的选择是同一个维度——根据是身体在动还是镜头在动来选择。
- **Element binding（元素绑定）（仅 Matches Video 可用）。** 对表演中的单个元素进行绑定，仅在 *Matches Video* 模式下可用。如果你需要元素级绑定，必须处于 Matches Video 模式。
- **特写（Close-up）面部输入 + 情绪转变。** 特写面部输入能很好地承载情绪转变——当节拍是表演或反应的瞬间而非全身运动时，选它。
- **输出变短诊断（shortfall diagnostic）。** 如果**输出突然比源片段短**，通常说明动作**太快或太复杂**，无法干净地连续迁移。放慢参考、简化动作或重新修剪后再重新生成——输出比源短，就是模型在告诉你：输入超出了它能干净迁移的范围。
