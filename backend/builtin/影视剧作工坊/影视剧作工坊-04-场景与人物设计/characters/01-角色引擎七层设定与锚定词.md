# 标准角色逻辑引擎规则库（Character Engine）

> **何时加载本库**：当你需要（1）从零设计角色（建设定卡）；（2）从文学剧本提取/补全角色；（3）校验 AI 生成的角色一致性（锚定词/状态追踪）；（4）审计已有角色的穿帮/崩坏问题时，加载本库。
> **回答的问题**：角色如何被标准化记录、如何被一致地生成、如何随剧情被追踪。
> **与 L2 的分工**：L2 回答「角色为什么成立」（欲望/需求/缺陷/弧光），本库回答「角色如何落地为标准系统」（设定卡/锚定/指纹/状态追踪）。
> **用法**：按规则编号逐条执行；建卡走七层，锁定走三段（锚定/指纹/映射），追踪走状态表。
> 所有判定以本库规则编号为准，引用 L2 规则时用 C 前缀编号。

## 1.1 设定卡七层结构（角色标准化的基础）

每个主要角色必须建立七层设定卡，缺层即视为未完成：

| 层 | 内容 | 验收标准 | 对应 L2 |
|----|------|----------|---------|
| 识别层 | 姓名 / 代号 / 年龄 / 性别 / 身份 / 职业 / 作品中的权重（主角/配角/龙套） | 一句话能定位此人是谁 | — |
| 外貌层 | 体型 / 身高 / 脸型 / 五官特征 / 发型发色 / 瞳孔 / 肤色 / 着装风格 / 标志性物件 / 可辨识标记（伤疤/痣/纹身） | 可被 AI 生成、可被演员还原 | — |
| 性格层 | 核心特质（3-5 个）/ 行为习惯 / 情绪模式 / 口头禅 / 语言风格 | 特质能对应到具体行为 | C2 |
| 心理层 | 欲望（Want）/ 需求（Need）/ 缺陷（Flaw）/ 恐惧（Fear）/ 错误信念 | 欲望与需求冲突 | C1 |
| 背景层 | 出身 / 关键经历 / 创伤事件 / 现状处境 | 背景能解释性格与选择 | C10 |
| 弧光层 | 起点状态 / 中点动摇 / 终点改变 / 改变代价 | 弧光有完整闭环 | C3/C4 |
| 关系层 | 与各主要人物的关系类型 / 欲望交叉 / 功能 / 质变节点 | 关系网无孤立节点 | C13 |

**规则 E1**：设定卡必须**单卡自洽**——仅凭一张设定卡，不参考任何剧情，就能还原出「这个人是谁、要什么、怕什么、会怎么做」。自洽性检查：七层之间互相印证，无矛盾（外貌不影响性格判断、背景能解释缺陷）。

## 1.2 锚定词体系（AI 生成一致性）

角色要跨镜头/跨场景保持一致，必须把外貌层拆成两段：

```
锚定段（不可变，每次生成必带）
  性别/年龄/体型/脸型/五官特征/发型发色/瞳孔/肤色/可辨识标记/标志性物件
可变段（按场景变化，允许替换）
  服装/妆容/情绪/表情/发型状态/道具/状态（受伤/湿/脏）
```

**规则 E2**：锚定段必须**短而硬**——压缩到 30-50 词内、只含 AI 能稳定还原的具象词（数字、名词、固定搭配），禁止抽象形容（"气质忧郁""很帅"）进锚定段。
- ✅ 示例：「30岁东亚男性，身高182，瘦长脸，深棕色短发三七分，深棕瞳孔，窄双眼皮，薄唇，左眉尾一道旧疤，常穿深灰夹克，腕戴旧钢表」——全具象，AI 可稳定还原。
- ❌ 反例：「忧郁帅气、气质清冷、有故事感的男人」——抽象词，AI 每次生成都不同。

**规则 E3**：可变段变化必须有**剧情依据**——服装更换、状态改变必须对应剧本中的可见事件（换了衣服、受了伤），禁止无交代跳变。
- ✅ 示例：第10场角色受伤流血 → 第11场手臂缠绷带，分场表有对应事件。
- ❌ 反例：上一场完好，下一场突然拄拐——无事件交代，穿帮。

锚定词写法模板（每角色一份）：
```
[稳定锚定]：30岁东亚男性，身高182，瘦长脸，深棕色短发三七分，深棕瞳孔，
窄双眼皮，薄唇，左眉尾一道旧疤，常穿深灰夹克，腕戴旧钢表。
[可变段]：服装/表情/状态按场景替换。
```

## 1.3 语言指纹（对白一致性）

**规则 E4**：每个主要角色建立**语言指纹**，对白必须命中指纹，违反即改：

| 指纹维度 | 内容 |
|----------|------|
| 用词偏好 | 高频词 / 禁用词 / 专业术语 / 方言词 |
| 句式习惯 | 短句/长句 / 疑问句占比 / 是否爱用比喻 |
| 口头禅 | 固定口头禅 1-2 个（可随弧光演变） |
| 沉默习惯 | 何时不说话 / 用什么动作替代说话 |
| 称呼方式 | 对特定人物用什么称呼（亲昵/疏远/挑衅） |

**规则 E5**：语言指纹随**弧光变化允许渐变**——但变化必须有触发事件（E3 同理），且一次只变一个维度，禁止整卡换人。

## 1.4 行为一致性（性格 → 行为映射）

**规则 E6**：性格层每个核心特质必须映射 ≥2 个**可观察行为**，写入设定卡。无行为映射的特质 = 废卡。

示例：
```
特质：控制欲强
行为1：别人说话时反复打断并纠正细节
行为2：对时间极度敏感，频繁看表
行为3：事情失控时会把物品摆回原位
```

**规则 E7**：压力反应分级——同一角色在轻压/中压/重压下的反应必须**同源升级**（C12）：轻压的应对方式在重压下可见地放大，而非变成另一个人。

## 1.5 状态追踪（跨场一致性）

**规则 E8**：剧本推进中，为每个主要角色维护**状态追踪表**，逐场更新，作为一致性审计依据：

| 字段 | 内容 |
|------|------|
| 场次 | 角色出场的场次号 |
| 服装/造型 | 本场状态 + 变更依据 |
| 情绪状态 | 承接上场情绪的连续性 |
| 关系进度 | 与在场人物的关系刻度（+1/-1/质变） |
| 身体状态 | 伤/病/疲劳/醉酒等，注明何时何故 |
| 认知状态 | 本场知道了什么（信息差对齐 L1-N10） |

**规则 E9**：相邻两场之间的任何状态变化必须有**可指认的触发**——找不到触发即视为穿帮，修正方式：补事件或撤变化。

## 1.6 关系网（角色间结构）

**规则 E10**：每个主要角色至少与 2 个其他角色有**功能性关系**（推动/阻碍/折射），孤立角色（只出现、不连接）删除或重建关系。
**规则 E11**：关系网必须包含至少一个**三角结构**（主角-对手-争夺物），且每条关系标注质变节点（C13）。

关系网表（每对关系一行）：
| 人物A | 人物B | 关系类型 | 欲望交叉 | 功能 | 质变节点 |
|-------|-------|----------|----------|------|----------|

## 1.7 角色引擎检查清单

- [ ] E1 设定卡七层齐全且单卡自洽？
- [ ] E2 锚定段短而硬（30-50词、具象、无抽象形容）？
- [ ] E3 可变段变化有剧情依据？
- [ ] E4 每个角色有语言指纹且对白命中？
- [ ] E5 语言渐变有触发且单维度变化？
- [ ] E6 每个特质映射 ≥2 个可观察行为？
- [ ] E7 压力反应同源升级？
- [ ] E8 状态追踪表逐场维护？
- [ ] E9 相邻场状态变化有触发？
- [ ] E10 无孤立角色？
- [ ] E11 关系网有三角结构且标注质变节点？
- [ ] （联动）C1-C13 角色逻辑规则通过？

## 1.8 常见缺陷与修复

| 缺陷 | 症状 | 修复方向 |
|------|------|----------|
| 卡面漂亮人设假 | 设定卡写得好但进不了戏 | 特质映射行为（E6），行为入戏（S6） |
| AI 角色长得不一致 | 每镜头像换人 | 锚定段压缩加锁定（E2），可变段限变更（E3） |
| 台词千人一面 | 换名字分不出谁在说话 | 建语言指纹并逐句校验（E4） |
| 性格崩坏 | 重压时行为完全走样 | 压力反应同源升级（E7/C12） |
| 服装穿帮 | 上一场受伤下一场完好 | 状态追踪表逐场核对（E8/E9） |
| 工具人角色 | 只出现不连接 | 补功能性关系或删除（E10） |
