## 场景设定表（Location Reference Sheets）

场景值得和角色一样的"资产先行"待遇。如果某个房间、小巷、车内或外景要跨多个镜头反复出现，就把它作为独立资产生成一次、反复复用——不要在每个场景提示词里重新描述它。逐场重新描述是"每个镜头都在重新诠释环境"这一失败的根源：墙面漂移、家具重新布局、比例失准，世界不再像一个统一的地方。

### 开拍前先预植视觉锚物

`[FIELD — Higgsfield Studio, ADILIADA breakdown, 2026-08-14]` 场景设定表能阻止房间被*重新发明*；但它本身阻止不了人**在房间里乱走**。便宜的补法是刻意布置几件固定的、辨识度高的物件，然后围绕它们做调度：角色坐的那把椅子、两人靠着说话的那扇窗、角色穿过的那道珠帘。它们给模型一个可命名的东西，让位置在多次生成之间有依靠；也给你一个可以用来写调度的坐标——*"在窗边，画面左侧"*是可核验的，而*"房间左侧"*不是。

选锚物的标准是**辨识度高且不可挪动**。第二把一模一样的椅子不是锚物，是歧义。

**生成任何东西之前，先把各底板的色调互相校平。** 将要互相剪辑在一起的场景，在资产阶段就把颜色、光线、饱和度匹配好，这样镜头开始落地时各场景在气质上已经一致——否则每次生成继承到的世界都略有不同，不匹配只会在剪辑里暴露出来，那时就变成 `../higgsfield-pipeline/SKILL.md` § The Edit 在调色阶段要解决的统一问题。

### 五视图场景设定表（The Five-View Location Sheet）

场景设定表要从一个空间足够多的角度采样，让模型手里有一个完整的空间模型。以下五个视图作为一組资产生成：

| 视图 | 锁定内容 |
|------|---------------|
| 正面全景 | 整体比例、视觉焦点、地平线 |
| 左侧斜视角 | 左侧几何结构、左向纵深 |
| 右侧斜视角 | 右侧几何结构、右向纵深 |
| 反打/对面视角 | 全景里镜头背后的东西——补完 360° 足迹 |
| 环境细节特写 | 材质、磨损、招牌、能锚定身份的小道具 |

对主全景图使用 Grid Generation（2×2 或 4×4）或 3D Mode，从同一个种子产出各替代角度——这能让光线和材质身份在各视图间保持一致，而这正是五视图的全部意义。

### 复用时要锁定的四项

把场景带回来拍新镜头时，锁定这四个属性：建筑结构（墙、开口、比例）、光质（光源方向、色温、软硬）、色彩处理（色板、调色）、关键环境细节（招牌、破损、让"此地是此地"的具体道具）。这些东西不要写进场景提示词——它们住在场景资产里。场景提示词只描述变化：角色动作、镜头行为、大气运动，以及（若有）昼夜时段变化。

### 这防住什么失败

没有场景设定表，一段设定在"被雨浸透的小巷"里的六场戏会渲染出六条不同的小巷——每个场景提示词都从零开始重新诠释"被雨浸透的小巷"。有了场景设定表并标记为 @ Element 或作为参考载入，六个场景共享同一条小巷——水洼在同样的位置、霓虹灯写着同样的字、砖墙是同样的纹路。

# 模板：俯视平面图预可视化（Top-Down Floor Plan Pre-Visualization）

面向 **Claude** 的元提示词模板（不是面向 Seedance）。一次生成俯视平面图＋可直接粘贴的 Seedance 调度说明（blocking note）——在任何 Seedance 生成开始之前，先把空间几何锁定。

> **地图是给你自己看的，文字才是给模型的。** 本模板渲染出的 HTML artifact 是一份创作辅助——你去看图、核对几何关系是否符合你的意图，而真正进入 Seedance 提示词的是那份**调度说明（blocking note）**。绝不要把平面图本身当作参考图附上去。
>
> 这不是风格偏好，而是图示方法在各方资料中唯一达成共识的一点：给视频模型看的调度参考图要画成**正面视角、从摄影机一侧看过去，绝不俯视**——视频模型按画面思考，不按平面图思考；把平面图递给它，等于交出一份它根本无法映射到镜头上的几何。俯视图适合用来*推理*一个空间，却不适合*展示*一个空间。两个事实同时成立，而本模板完全活在推理这一侧。
>
> **负责"展示"这一侧的是 `staging-reference.md`**——那张正面视角、按颜色编码的轮廓线稿图，它才是真正附进生成的那张，并带有一套三层防串染（anti-bleed）架构使其可以安全附加。在向任何人保证它能钉死位置之前，先读一读它那篇措辞克制的警示说明。

## 何时使用本模板

任何多人或几何关系复杂的镜头——历史上 Seedance 在这类镜头上曾把空间重组搞错：进门镜头、走廊方向性镜头、需要跨剪辑保持稳定的双人调度。本模板所预防的失败类别，见 `../../skills/higgsfield-seedance/FAILURE-MODES.md` § Spatial-awareness failures。

## Claude 提示词模板（可直接粘贴）

```
Build a top-down floor plan for [SCENE]. Mark every character with
their position, which direction they're facing, and who they're
looking at. Include distance between characters and a scale.

Below the diagram, write a paste-ready blocking note for Seedance —
one short paragraph per character covering: where they are, which way
they face, gaze line, pose, what they're touching.

Render as an HTML artifact.

Scene: [DESCRIPTION]
```

`[SCENE]` 填一行式场景标题（例如 "diner standoff"，小餐馆对峙）。`[DESCRIPTION]` 填完整的场景描述——人物、地点、动作、情绪。描述越丰富，空间重组的效果就越好。

## 你会得到什么

- 一个以可视化方式渲染俯视平面图的 HTML artifact
- 一份可直接粘贴的调度说明，其格式化后的形态可直接复制进 Seedance 提示词正文的空间布局块（Spatial Layout Block）（该输出由哪种块结构承接，见 `../../skills/higgsfield-seedance/SKILL.md` § Spatial Layout Block）

## BAD / GOOD / GREAT（差 / 良 / 优）

**BAD（差）：** 跳过预可视化。直接从场景描述写 Seedance 提示词，让 Seedance 自己决定空间重组。多人物镜头的后果：角色站错画面两侧、穿模走过家具、朝向错误。

**GOOD（良）：** 使用本模板，得到俯视图，目测核对几何关系，再把相关位置手动转写进 Seedance 提示词。空间精度显著提升。但几何关系复杂时，转写环节会引入误差。

**GREAT（优）：** 使用本模板，并把 Claude 生成的调度说明直接粘贴进 Seedance 提示词的空间布局块（Spatial Layout Block）。零转写。Claude 所推理的几何与 Seedance 所收到的几何完全一致。锁定之前，先在 Claude 对话里迭代平面图——调整位置、视线、接触点，直到地图符合意图，再把调度说明复制过去。

## 用地标锁定道具比例

这张图还能锁定道具**相对于某个固定地标的尺寸与位置**，让大型陈设件在一条条 take 之间保持同一比例。把道具钉在一个有名字的地标上，同时给出明确的尺寸倍数和一条共享视线：

```
Mark the fire hydrant. Lock the skydancer to its right — two times a person's
height, standing on the same line as the hydrant.
```

地标（消防栓）是 Seedance 能稳定渲染出来的东西；把道具系在地标上——*一个人的身高 ×2、同一条线*——等于给了模型一个相对锚点，而不是一个它本来每次生成都要重新猜的绝对尺寸。任何超大件或位置关键、必须跨剪辑保持比例的道具（充气人偶、车辆、招牌）都适用这个方法。

## 第三阶段——场景：批量要便宜，按光来筛

`[FIELD — AI-vs-VFX, 2026-08-08]` 场景静帧是整条流水线里迭代最便宜、出错最贵的地方。

**经济账决定方法。** 七个积分买一次 GPT Image 2 生成，或 **56 张 Soul Cinema 变体**。在这个比率下，正确的行为不是去写一个更好的提示词——而是先大批量撒网，再来评判。

**评判先看光，别的都往后排。** 来自实际制作的弃用原因，按出现顺序：

| 弃用原因 | 画面表现 |
|---|---|
| 塑料感，阳光穿透得不自然 | 场景是阴天——光应该柔，硬光与底板矛盾 |
| 云的位置不对，图太黑 | 构图没问题，曝光害了它 |
| 光落在平原上很好，落在瀑布上不行 | 镜头主体读起来像一个窟窿 |
| **通过** | 聚焦瀑布，水读作蓝色，阴天但不发黑 |

**静帧里的坏光，就是视频生成出垃圾的原因。** 整条规则就这一句。一张主光不对的场景图，会和视频提示词里每一条布光条款作对——因为视频模型匹配的是参考图，不是你那段文字。

**锁定之前，先让入围者在视频里过一遍。** 静帧看着好，动起来可能很糟。给每个入围者花一次短生成，比在大制作镜头里才发现便宜。

### 反打视角的场景（Reverse-angle locations）

一场戏几乎总要拍到同一个地方的另一个方向——你刚往里看的洞穴内侧、房间的另一头、马路对面的街。把它当作*匹配场景*生成，而不是新场景：挂上已锁定的场景资产，写一份显式的承接清单。

```
Reverse angle of the exact same basalt cave as in the reference image — same location,
same materials, same color grade, now facing the opposite direction: the dead-end back of
the cave.
MATCH TO REFERENCE — carry over exactly:
— the same rough black basalt of the ceiling and walls: layered, horizontally streaked,
  wet sheen, identical texture scale;
— the same floor: dark grey-brown fine volcanic gravel, matte and slightly damp,
  identical grain size and tone;
— the same cold overcast palette: graphite black, wet slate grey, muted earth-brown;
  fine film grain and soft naturalistic contrast identical to the reference frame.
```

点名**材质、颗粒度、色板和调色**——这四样东西最会出卖"两个镜头其实不是同一个地方"。写明新视角*不包含*什么（"这一侧是完全封闭的实心岩石：没有第二个洞口，没有透光缝，画面里任何地方都没有瀑布"），因为模型会干脆凭空发明一个第二出口，也不肯接受死路。这种本能就是环境发明——`../higgsfield-seedance/SKILL.md` § Positive Locks 里的头号漂移源。

### 场景设定表

- **场景设定表用 3/4 视角拍，不用正面。** 正面的"好看图片"在大全景里会变成一张平面墙纸，一旦越过画面边缘，模型每次都会发明新的周边环境。3/4 视角给模型可读的纵深——它能把角色放对位置，并覆盖接近一整圈的角度。
- **每个场景里留一个锚物**——一根柱子、一盏灯、一张沙发——并把调度绑在它上面。"角色在灯边，面向大门"能用。"角色在房间里"是抽彩票。
- **只留一套光的逻辑**：一个光源、一个影子方向，永远不要两个太阳。否则每个新角度都会重新发明布光。
- **反打视角，路线 1：** 在 GPT Image 2 或 Nano Banana 里生成同一房间的另一个角落，匹配原图的柔焦质感。
- **反打视角，路线 2**（制作后期才发现的招）：生成一段**空场景的视频**，让镜头慢慢走过整个空间——Seedance 会参照设定表把另外几面画得保持一致。截下你需要的那一帧，交给 Seedream 或 Nano Banana Pro，用提示词做一次材质/布光升级。一张图就这样长出一整套场景设定表。

### 给每张参考图命名角色——并禁止场景继承

你不替参考图定角色，模型就自己定，而且定错：该抄脸的抄了构图，该抄色板的抄了脸。

```
@roco for character reference
@jaxx for character reference
@loc_cave_front for location reference — take only the space and the texture: raw concrete,
black rock walls. Do not use as a starting frame, do not inherit the composition, the angle,
or the grade.
```

**场景类参考必须显式禁止继承。** 这就是 `SKILL.md` § Reference Roles 里的 Environment 角色，用模型自己的工作语言写出来。

**全项目只用一本命名辞典。** 所有资产都挂在标签下——`@roco`、`@loc_cave_front`——同一批标签用在所有地方：文档里、提示词里、界面里。

## GEO SPATIAL LAYOUT 块（地理块）

**早期 take 里最昂贵的问题：** 角色瞬移、互换位置、镜头跳到错误的一侧。原因很简单——模型不记得上一个镜头里谁站在哪。

解药是一份**几行字写完的现场平面图**：地标物件、右边是什么、左边是什么、镜头站在哪。**不写角色、不写动作——只写这个地方本身。** 每个场景写一次，然后逐字不改地粘进该场景的每一个镜头。模型在每一个镜头里拿到的是同一个房间，人就没地方可丢了。

```
GEO SPATIAL LAYOUT (locked across every shot — pure spatial map):
— PLATFORM = raised circular ritual stone disc at the edge of a cliff.
— ALTAR-MONOLITH: at the cliff edge, MID-RIGHT position relative to the platform.
— RITUAL CENTER: CENTER-LEFT, ~3 m from the altar.
— 180° AXIS: camera ALWAYS stays on the corpse-field side — it NEVER crosses the line.
— BACK-LIGHTING: crimson horizon glow comes from BEHIND the platform, rim-lighting
  silhouettes from camera's perspective.
```

读图与写图的规则：

- **GEO 只是地图。** 这个地方的*外观*仍然来自场景资产——它的描述词和参考图要连着地图一起放进提示词。
- **左右只从镜头出发。** 用 "frame-left" 和 "frame-right"——模型听不懂"角色的左边"。
- **位置用地标加米数来定**——"在祭坛边"、"三米开外"。
- **写明镜头站在哪一侧、永不越过哪条线。** 这样每一次切换都在同一条轴上。
- **每次切换后，重新点名谁站在哪、看向哪。** 模型不记得上一个镜头。
- **给静态对白一个房间的角落，而不是整个房间。** 模型的空间越小，它安放角色的自由度就越小。

> **与空间调度块（Spatial Layout Block）的关系**（`SKILL.md` § Spatial Layout Block）：那个块是逐镜头的、*包含人物*——画面位置、占幅、朝向、接触点。GEO 是逐**场景**的、不含人物，逐字不改地粘进该场景的每个镜头。两个都用：GEO 锁死房间，空间调度块锁死这个镜头里谁站在其中。

# 模板：多人角色锚定提示词（Multi-Character Anchor Prompt）

可直接粘贴的 Seedance 2.0 提示词模板，适用于画面中有两个及以上角色的镜头。在动作描述之前，先锁定每个角色的身份、位置、深度、姿态、视线与接触点。

## 何时使用本模板

任何有两个及以上角色、且位置安排、朝向与角色间关系都很要紧的 Seedance 提示词——用本模板替代散落的内联空间片段后，角色互换、越轴、视线对不上这三类问题都会显著减少。

## 提示词模板

```text
[At/from N seconds] N characters in frame.

Character A — [identity, Soul ID handle].
  Screen position: [left third / center / right third],
  x-position [%], y-position [%], frame occupancy [%].
  Depth layer: [foreground / midground / background].
  Body orientation: [toward camera / away / profile-left /
    profile-right / three-quarter].
  Pose: [physical configuration — standing, seated, mid-stride].
  Gaze: [where they look — frame-position OR "looking at Character B"].
  Contact points: [physical surfaces they touch — feet on wet
    asphalt, left hand on the railing].
  State lock: [emotional or physical state — calm, exhausted,
    injured, soaked].

Character B — [identity, Soul ID handle].
  [...same fields...]

Cross-character relationships:
  Distance between A and B: [approximate].
  Eyeline: [A → B, B → A, both → off-screen, mutual avoidance].
  Crossing rule: [neither crosses the central vertical axis /
    A may cross right-to-left at N seconds].
  Negative space: [where the empty area sits in frame].

Camera: [shot size], [angle], [lens], [movement].
Setting: [location, time, weather, atmosphere, production design].
Aesthetic: [genre, lighting, color grade, texture, VFX].
Audio: [ambience, SFX, dialogue, music].
Continuity locks: [costume / state / prop invariants].
Final frame: [composition at last frame].
```

## 各字段该填什么

- **Identity（身份）** 对应一个 Soul ID 角色句柄（本模板所承接的每角色 10 属性结构，见 `../../skills/higgsfield-soul/SKILL.md` § Character Anchor Block）
- **Screen position（画面位置）** 按 `../../skills/higgsfield-seedance/SKILL.md` § Frame Coordinate System 的规定，将定性锚点与百分比记法成对书写（vocab.md § Editing Syntax 的方括号记法随 v3.7.7 子阶段 2f 发布）
- **Contact points（接触点）** 用于防止 `../../skills/higgsfield-seedance/FAILURE-MODES.md` 中收录的角色悬空（character-floating）失败模式
- **Cross-character relationships（角色间关系）** 用于防止角色互换与越轴失败——结构上的原理见 seedance SKILL.md 的 § Spatial Layout Block

## BAD / GOOD / GREAT（差 / 良 / 优）

**BAD（差）：** 把内联空间片段散落在动态描述（Dynamic Description）里。`Character A walks in. Character B is by the window.` 结果：Seedance 自行挑选默认位置；A 和 B 跨剪辑互换；视线漂移。

**GOOD（良）：** 使用模板，填写每角色的锚定块，但只给定性位置（`left third` / `right third`）。空间精度提升；角色间关系保持得更好。但在紧凑镜头上，坐标精度仍然不够。

**GREAT（优）：** 使用模板，填满每一个字段，包括与定性锚点成对使用的百分比记法，并写明角色间关系（距离＋视线＋越轴规则＋负空间——见 [vocab.md](../../vocab.md) § Composition Vocabulary → Crossing rule 与 § Negative space）。先用 `top-down-map.md` 对场景做预可视化，再把 Claude 生成的调度说明粘贴进 Character A / Character B 字段。只要角色相同，这个块可以跨剪辑复用——每个剪辑复制一份再微调，不必重新逐项填写。
