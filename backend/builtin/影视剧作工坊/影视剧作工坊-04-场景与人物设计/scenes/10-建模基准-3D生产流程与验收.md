# 标准 3D 建模逻辑引擎规则库（Modeling Engine）

> **何时加载本库**：当你需要（1）为 3D/伪真人成片规划建模生产路径（选软件、定流程）；（2）产出/审核模型资产需求与验收结论（角色、场景、道具、生物）；（3）按影视级标准校验拓扑、UV、贴图、LOD 与导出；（4）把模型需求/验收结论交付渲染引擎（UE5/Arnold）时，加载本库。
> **回答的问题**：影视级模型怎么建、按什么标准建、建完怎么验收、怎么交到渲染。
> **地位**：本引擎隶属**渲染引擎分类**（工程工作流：引擎四·渲染 + 引擎十·空间物理构图 + 引擎七·真人物理 + 引擎六·3D建模 + 引擎八·语义转换 + 引擎九·后期校验）——建模生产路径与模型验收结论为逻辑产出；**进入生成层的输出（材质观感词等）须经引擎八语义转换**，成品由引擎九验收。
> **用法**：先按资产类型走 ME-1 软件路由，再按 ME-2 阶段门逐段执行；每个阶段对照对应规则（ME-3 拓扑 / ME-4 UV / ME-5 命名导出）验收后放行。
> 所有判定以本库规则编号为准（ME 前缀）。
> 规则依据：Autodesk Maya 官方建模文档、Maxon ZBrush 官方文档、SideFX Houdini 官方文档、Blender 官方手册与 Blender Studio 角色工作流、Adobe Substance 3D 官方文档、OpenUSD 官方资产管线规范。

## 0. 定位边界（ME-0）

**规则 ME-0**：本引擎是**逻辑引擎，不是建模工具**——不执行建模软件操作、不产出模型文件（.fbx/.ma/.zpr/.blend 等）。产出物只有三类：**建模生产路径**（软件路由+阶段门）、**模型需求单**（交建模执行）、**模型资产验收结论**（按规则判定 PASS/FAIL）。建模动作由生产环节（建模执行）完成，本引擎定标准、出路径、下需求、做验收。

- ✅ "角色模型需求单：ZBrush 高模 → Maya 重拓扑 → UDIM → Substance → UE5 导出；验收四问待建模反馈"。
- ❌ "打开 ZBrush 雕刻高模"、"导出 .fbx 给渲染"——建模执行动作，不在本引擎职责内。

## 1. 资产类型与软件路由（ME-1 执行）

影视级建模先分**资产类型**，再按类型选软件与流程——没有"一个软件建所有东西"的标准，只有"按资产选对的工具链"的标准。

| 资产类型 | 主工具链（行业主流） | 流程要点 |
|----------|----------------------|----------|
| 角色/生物（有机） | ZBrush（高模雕刻）→ Maya/Blender（重拓扑）→ Substance（贴图） | DynaMesh 塑形 → 细分雕刻 → 重拓扑 → UV |
| 硬表面/机械/道具 | Maya / Blender（多边形建模）→ ZBrush（细节补充） | 智能挤出/布尔 → 拓扑规整（高规整低各向异性）→ 折痕 |
| 场景/环境/大规模 | Houdini（程序化）→ Maya（组装） | 节点式生成 → HDA 复用 → 实例化 |
| 植被/散布/碎片 | Houdini Labs（程序化生成） | Tree/散布节点 → 变体 → 实例 |
| 服装/布料 | Marvelous Designer → 回拓扑 | 版片模拟 → 重拓扑 → 缝合细节 |
| 贴图材质 | Substance 3D Painter/Designer | PBR 通道 → UDIM → 纹素密度一致 |

**规则 ME-1**：按「资产类型 × 交付目标（动画/静帧/实时）」路由软件，禁止用单一软件套所有资产；路由结果回写角色引擎（模型需求单）与渲染引擎（几何预算）。

- ✅ 角色 → ZBrush 雕刻出高模 → Maya Quad Draw 重拓扑出动画拓扑 → Substance 出贴图 → 交付 Arnold/UE5。
- ❌ 场景植被逐棵手工建模，或角色直接用 ZBrush 高模进动画——拓扑不可变形、资产不可复用。

## 2. 影视级建模流程（阶段门）

流程五段，**逐段验收后放行，禁止跳段**：

```
阶段一 高模     → 阶段二 拓扑    → 阶段三 UV    → 阶段四 贴图    → 阶段五 LOD与导出
雕刻/塑形       动画拓扑         展 UV            PBR 通道         LOD/格式/单位
验收：形准细节足  验收：可变形      验收：无拉伸      验收：通道完整     验收：下游可读
```

**规则 ME-2**：按「高模 → 拓扑 → UV → 贴图 → LOD/导出」顺序执行，每段以该段验收项为门禁；高模阶段只做形与细节，拓扑阶段只做面流，禁止混段作业（如在高模上直接画贴图）。

### 阶段一 · 高模（形准与细节）

- **有机资产**：ZBrush DynaMesh 先做低/中分辨率基底（官方定位：完美基础网格），捏形后 Ctrl+拖拽空白处重网格去拉伸；细节阶段转**细分层级**（Subdivision Levels）雕刻，避免 DynaMesh 细节丢失。
- **硬表面**：Maya/Blender 多边形建模（智能挤出、分割多边形面），ZBrush 补细节。
- 高模细节产出后，**烘焙到低模**：官方流程为从最高细分层级生成 normal/displacement/bump，导出到修改后的最低分辨率模型——高模不直接用于动画/渲染，只作为细节源。

### 阶段二 · 拓扑（动画可变形）

- **手动**：Maya Quad Draw 逐面重建（官方四步：吸附参考面 → 定义顶点 → 创建多边形 → 调整多边形），Relax 笔刷均匀顶点间距。
- **自动**：Maya Retopologize（Remesh→Retopologize 顺序执行）——官方明确**有机表面用默认设置，硬表面设高 Topology Regularity + 高 Face Uniformity + 低 Anisotropy**。
- **ZRemesher**：ZBrush 自动重拓扑，目标面数可控（默认 5000 为参考目标）。
- **Blender**：重拓扑修改器（固定边缘环/固定顶点/邻近环自动固定），关键环手动锁、填充区自动。

**规则 ME-3**：拓扑必须满足（1）**two-manifold（二流形）**——禁止非流形几何（官方明确 Legacy Boolean/Reduce 无法处理非流形）；（2）四边面优先，极点（>4 边汇点）置于非变形区；（3）边环跟随肌肉/关节变形方向（面部、肩、膝）；（4）雕刻图层依赖顶点顺序——**拓扑变更会损坏雕刻层**，先锁定设计再重拓扑。

- ✅ 角色脸部：眼眶/嘴周/鼻翼四边环（edge loop）环绕，关节处环形边，极点藏在耳后/下颌。
- ❌ 三角面/五边形堆在嘴角、肩关节——动画时变形撕裂，表情不可控。

### 阶段三 · UV（无拉伸 + 纹素一致）

- **UDIM 平铺**：影视级资产用 UDIM（UV Tile 工作流），多平铺跨 tile 无缝绘画（Substance 3D 官方：启用 Use UV Tile workflow，同纹理集多 tile 并排显示、跨 tile 绘画）。
- **纹素密度（Texel Density）**：全网格保持**一致纹素密度**（官方明确：密度差异过大肉眼可见）；UV 无拉伸（面积比例≈模型面积比例）。

**规则 ME-4**：UV 必须（1）启用 UDIM 平铺（精细资产）或单纹理集（简单道具）；（2）同一网格纹素密度一致（Maya UV Toolkit 的 Texel Density 工具统一）；（3）无 UV 拉伸、无重叠（对称件除外）；（4）接缝置于不显眼/遮挡区。

- ✅ 角色头部 UDIM 1001 面部 + 1002 颅侧 + 1003 颈部，密度统一 1024px/m，接缝藏耳后与发际线。
- ❌ 一张 0-1 UV 塞下全身、面部只占一角——特写必糊（Adobe 官方 PBR 指南：UV 纹素密度不足直接导致边缘伪影/糊）。

### 阶段四 · 贴图（PBR 通道）

- **Substance 3D Painter** 标准：Base Color / Normal / Roughness / Metallic / AO / Height 通道；PBR 物理渲染模型（官方定义）；色彩管理走 **OpenColorIO**（官方：从导入到显示全链路颜色转换一致）。
- 纹理通道可按 RGB 打包（如 ORM=Occlusion+Roughness+Metallic）节省显存。

**规则 ME-5**：贴图必须（1）PBR 通道齐全且命名可辨识；（2）色彩管线对齐 OCIO；（3）通道打包有约定（如 _ORM）；（4）贴图分辨率与纹素密度匹配（高密度区给高分辨率 tile）。

### 阶段五 · LOD 与导出（下游可读）

- **LOD 链**：LOD0 100% 面数（近景）→ LOD1 50% → LOD2 25% → LOD3 10%（远景）——行业通行递减标准；UE5 Nanite 场景**免除手动画 LOD**（Nanite 自动虚拟化 LOD），但非 Nanite 资产（骨骼网格/半透明）仍需 LOD 链。
- **单位与轴**：统一**米制**（Maya 官方 `currentUnit -linear "m"`）；Z-up（UE）或按引擎转换；导出前**重置变换（Freeze Transform）**，避免缩放异常。
- **格式**：带动画导出 FBX 二进制；跨工具/多镜头共享用 USD——`.usdc`（Crate 二进制）生产、`.usda`（ASCII）调试、`.usdz` 打包（注意 UDIM 纹理不支持嵌入 usdz）；场景组织用**引用/实例**替代复制（USD 官方：reference 替代 copy、instancing 大幅省内存）。

**规则 ME-6**：导出必须（1）单位米制、轴一致、变换已冻结；（2）按下游选格式（动画→FBX；跨工具共享→USD；UE5→按 Nanite/骨骼分开）；（3）命名规范统一（资产类型前缀 + 名称 + 版本，如 `chr_heroine_v01`；LOD 后缀 `_LOD0/_LOD1`）；（4）材质引用路径相对化，禁止绝对路径。

- ✅ `prop_cup_01_LOD0.fbx` + 米制 + 冻结变换 + 相对贴图路径，UE5 直接导入即用。
- ❌ 中文名+绝对路径+厘米单位直接拖进引擎——尺寸失真、引用断链、贴图丢失。

## 3. 程序化资产（Houdini）

影视级大规模资产（场景、植被、碎片、地形）走 Houdini **节点式程序化**（官方定位：每个动作存为节点，网络=可重复的"配方"；属性沿节点链传递）。

- **HDA（Houdini Digital Assets）**：把程序化工具打包为可复用资产，团队共享、自动化重复任务（官方明确 HDA 支持工作室级生产）。
- 程序化模型可**替换输入节点快速迭代**（官方范例：platonic solid 换 box 即得新造型）。

**规则 ME-7**：资产数量级大到手工不可行（>10³ 级散布/地形/重复件）必须走程序化（Houdini/HDA）；程序化资产要参数化（可调参复用）并做变体集（USD variant 管理 LOD/状态/材质包）。

## 4. 资产命名规范（ME-8，深化 ME-6）

资产命名是**跨工具/跨环节的可读性契约**（模型→渲染→构图 scene_objects 全部按名引用）。参考影视级 UE 资产命名体系，通用化规则：

| 资产类 | 命名模板 | 示例 |
|--------|----------|------|
| 骨骼/角色网格 | `CH_{角色类型}_{名称}_{序号}_V{版本}`（Main/Support/Crowd） | CH_Main_heroine_01_V02 |
| 静态网格（场景/道具） | `SC_` / `Prop_` + `{名称}_{序号}_V{版本}` | Prop_cup_01_V01、SC_room_01_V02 |
| 材质实例 | `MI_{名称}_{序号}` | MI_cup_porcelain_01 |
| 纹理 | `T_{名称}_{通道}`（通道：BaseColor/Normal/Roughness/Metallic/AO） | T_cup_porcelain_BaseColor |

**规则 ME-8**：资产命名必须（1）按四类模板前缀+版本号（V\d{2}），禁止中文名/空格/无版本；（2）纹理通道后缀可辨识（BaseColor/Normal/Roughness/Metallic/AO），通道打包有约定（如 ORM）；（3）LOD 后缀 `_LOD0/_LOD1`；（4）命名是机检项——导入下游前逐资产过命名检查，不合规拒绝进入渲染。

- ✅ `CH_Main_heroine_01_V02.fbx`、`T_cup_porcelain_Normal`——全链路可引用、可机检。
- ❌ `主角.fbx`、`texture_1.jpg`——无法引用、无法机检、无法版本回溯。

## 5. LOD 档位与细节保留（ME-9，深化阶段五）

| 资产类型 | LOD 档位 | 距离分层（近景→远景，可随场景缩放） |
|----------|----------|--------------------------------------|
| 静态网格 | 3 档：LOD0 100% → LOD1 50% → LOD2 25% | 近景主导 → 中景 → 全景 |
| 骨骼网格 | 4 档：LOD0 100% → LOD1 50% → LOD2 25% → LOD3 10% | 近景(≈500) → 中景(≈1500) → 全景(≈3000) → 极远(≈10000) |

**规则 ME-9**：（1）**近景/特写资产细节 100% 保留**——高模细节不可为省面减损（超写实镜头主体禁减面丢细节）；（2）LOD 距离自动计算可开启，但骨骼网格按手工距离分层（近景主导）；（3）实时/虚拟制片场景（Nanite 类）免除手动画 LOD，但骨骼网格/半透明/动态变形资产仍需 LOD 链；（4）LOD 切换以"近景优先"为准——竖屏/特写主导的成片，中近景资产面数预算最高。

## 6. 材质验收规则（ME-10，深化 ME-5）

材质描述与参数须**物理合法、双引擎一致**。校验为**文本规则仿真**（不执行真实渲染验证，报告须标注）——这正是逻辑引擎职责：定标准、做判定，不操作材质软件。

**规则 ME-10** 校验四维：

1. **术语一致性**：双引擎（UE5/Arnold）术语混用 → FAIL（同一资产不可同时声明两套不兼容参数口径）
2. **参数合法**：修饰词推断（"抛光"→粗糙度区间）+ 显式参数优先（"粗糙度 0.12"直接识别，优先于修饰词推断）→ 与标准材质参数范围比对：关键参数越界 FAIL、非关键 WARN、偏离推荐值 INFO；参数值紧跟材质名独占一句
3. **跨材质一致性**：同场景材质物理关系自洽（玻璃展柜与内部文物的透射逻辑、水面与倒影）
4. **风格约束**：超写实材质禁风格化牺牲物理正确性（皮肤禁塑料感/禁过度磨皮；金属度禁写 0.5 中间态）

标准材质分 25 类（建筑 7 / 人物 7 / 自然 6 / 道具 5），每类含双引擎参数合法范围 + 推荐值 + 关键参数越界即 FAIL + 超写实约束。

**规则 ME-10b（迭代闭环）**：材质定位偏差 → 回退至硬锁物理参数或合格纹理特征 → 强化负面词禁该材质 → 重生成 → 复验；**最多 3 轮**，未达标终止并输出告警（记失败库）。

- ✅ "幕墙玻璃，粗糙度 0.02" → 显式参数识别 → 双引擎范围比对 → PASS。
- ❌ "UE5 Lumen 材质 + Arnold SSS 混写" → 术语混用 FAIL；"皮肤磨皮到塑料感" → 风格约束 FAIL。

## 7. 与上下游引擎接口

| 上游/下游 | 接口 | 本引擎动作 |
|-----------|------|------------|
| 成片类型引擎（FT-5.3） | 3D 类型角色呈现规则 | 角色卡 → 模型需求单（面数/风格/拓扑要求） |
| 标准角色引擎（E1-E11） | 角色卡外貌层/语言指纹 | 外貌 → 模型资产；语言指纹 → 表情系统需求 |
| 渲染引擎（render-engine） | 几何基线/渲染器选型 | 按渲染器定 LOD/格式（UE5 Nanite 免 LOD；Arnold 高模直接渲） |
| 渲染子项 UE5（U5 几何基线） | Nanite 限制 | 骨骼网格/半透明/动态变形走传统路径，需 LOD 链 |
| 镜头引擎（CL） | 分镜表特写需求 | 特写级资产细节预算（近景资产面数/贴图分级） |
