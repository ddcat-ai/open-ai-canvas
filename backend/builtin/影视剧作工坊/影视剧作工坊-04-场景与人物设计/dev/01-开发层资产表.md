# Higgsfield 场景引擎——这场戏值得生成吗？

`[DEMO — Tigran (tig-scene-engine), 2026-06-26]`（演示溯源标记：来自 Tigran 的 tig-scene-engine，2026-06-26） `[UNPROVEN HERE]`（此处尚未验证） **以下定义是专门定制的，刻意不采用教科书式的标准定义。**请按字面原样应用；不要替换成标准编剧术语中那些更宽松的注解——它们会让本引擎判定不合格的场次蒙混过关。

**提示词工程师为什么需要它。** 每个镜头都要消耗积分与迭代次数。一场结构上已死的戏，生成起来和一场鲜活的戏同样顺畅——模型对"某个节拍配不配占它那个位置"毫无立场——所以问题只有在素材生成出来、剪辑却立不起来之后才暴露。本技能是整个仓库里成本最低的一道关：它只处理文本，在任何生成开始之前运行，其全部职责就是阻止你花钱去渲染一场根本立不住的戏。

它决定的是**哪些**镜头值得花这笔钱。`higgsfield-shotlist-director` 把定稿的场次拆成镜头；`higgsfield-acting` 写出镜头内部的表演。

## 五要素引擎

### 1. 目标（Goal）

主人公为之奋斗的那一件、且始终不变的事：修复某件早已确立的事实，并尽快抵达能了结它的结果。"早已确立"指*任何*此前铺垫过的东西——可能埋在很深的背景故事里，可能发生在几场戏之前，也可能就在一分钟前。

- **大目标从不改变**，而且主人公对它的判断也从不出错。他可能在**战术**上犯错，但绝不会在目标上犯错。
- **每一场戏的目标都必须是通往故事目标的一环因果。** *检验方法：*如果删掉这场戏、因果链依然成立，那这场戏就不合格。不允许有孤儿场次。
- "他*应当*做什么"并不是另一项需要单独检验的东西——正确动作由**障碍＋赌注**决定。如果主人公采取了一个赌注根本撑不起的战术（楼着火他还在洗澡），这是一处可标记的不一致：要么判定为劣质写作，要么判定为刻意的自我破坏。

### 2. 障碍（Obstacle）

一种强有力的情势，它**危及**的要么是路径上的某一阶段，要么是整个目标。它是*威胁*，而不只是*代价*。

- 它可以是一片**分叉的搜索空间**（可找的地方很多，时间有限），也可以是一堵**单一的硬墙**（电池彻底没电——你没法在一台死机上继续搜索）。一堵硬墙通常会长出一个自带全新地形的子目标。
- 点明它的**规模**：*局部*（威胁当前阶段）还是*全局*（威胁整个目标）。
- 障碍正是**迫使主人公选择或改变战术的东西。**没有危机 → 不需要战术 → 没有这场戏。
- *审计检验：*说出到底什么处于危险之中、处于哪个规模。如果实际上什么都没有，那障碍就是假的，这场戏随之松垮。

### 3. 战术（Tactic）

威胁**迫使**主人公选出的那一步动作——基于他当下（往往不完整）的认知做出的合理猜测。这是**不确定性之下的搜索，而不是把错误等同于愚蠢。**

- 一个"错误"的战术并不等于愚蠢；它是对一片他无法尽收眼底的空间做出的一次合理试探。引擎在于**认知差**：他以为的与现实之间的距离。
- **每一次失败的战术都必须带回信息**，收窄搜索范围、重塑下一步动作。戏剧性在于收窄，而不在于惩罚。
- ✅ 合格：战术是对当前信息的合理下注，**而且**它的失败教会了他新的东西。
- ❌ 薄弱：一个他毫无理由去尝试的战术，或者一次**零信息**的失败——原地空转。失败的战术只有在失败什么也没教会人时才算弱点。

### 4. 反转（Reversal）

一次违背预期的转向。有三种形态：

1. **我自己的动作反噬我**——我为某件事*而做*的事，开始*不利于*那件事（我洗澡是为了体面地去提案；洗澡害我迟到，提案黄了）。
2. **隐藏的主体性被揭穿**——我以为自己在对其*施加作用*的那个东西或那个人，其实一直在对我*施加作用*。这是惊悚片的经典手法；它往往恰好在认知差弥合的一刻引爆。
3. 一般情形：局势转向战术意图的反面。

**位置要求：每个段落**至少一次反转。单场戏可以只是纯粹的层层升级，但一个*已了结的段落*若零反转，即**不合格**。

**段落**指的是从某个具体危机被打开到它被了结之间连续的场次——危机要么被克服，要么击垮主人公、逼出一条新路。段落可以**嵌套**，每个了结单元都需要属于自己的反转。审计时请标明你检查的是哪个规模。

### 5. 价值转移（Value Shift）

**由反转触发的、观众对角色解读的改变。**这是拱顶石，也是被误解得最深的一要素：它不发生在纸面上，而发生在观看者的头脑里。每一次反转都迫使观众**重新评判**角色——那是一份不断被修订的移动判决（*和善 → 历练老到 → 狡猾 → 不对，他是走投无路 → 孝顺的儿子 → 真是一条汉子*）。

> **核心法则：没有价值转移的反转是失效的。**一次结构上的转向，若撼动不了观众的判决，就不算反转。如果你说不出观众会持有什么样的**事前判决**和**事后判决**，那这次转向就是死重——不管情节翻了多少个面。

审计**轨迹**，而不只看有没有：这些重新评判是在累积出一幅不断加深的肖像，还是只是在来回摇摆？

---

## 因果链

> **目标**（固定不动；每一场戏都是通往它的一环因果）
> → **障碍**（危及某一阶段或整个目标；说出风险所在＋规模）
> → **战术**（被威胁逼出；一个合理猜测；其结果必须带回信息）
> → **反转**（违背预期的转向；每个已了结段落 ≥1 次）
> → **价值转移**（观众重新评判角色；无转移 → 反转形同虚设）

---

## 审计流程

按顺序过一遍因果链。反转与价值转移在**段落**层面评判，而不是场次层面。

1. **目标**——用一行话说出这场戏的目标。它是通往故事目标的因果一环吗？做删除检验。如果你不知道故事目标，先问——没有它就无法完整审计目标。
2. **障碍**——说出情势是什么、它究竟危及什么、规模多大。
3. **战术**——每个战术是否都被危机所迫？在当前认知下是否合理？每个结果是否带回信息？把原地空转和来路不明的战术标出来。
4. **反转**——定位每一处反转，说出其形态，确认每个已了结段落至少一次。
5. **价值转移**——对**每一处**反转，说出事前判决 → 事后判决。说不出来就标记为 **INERT（失效）**，并将其列为首要修复对象。然后再评估轨迹。

### 审计输出

```
SCENE/SEQUENCE: <one-line identification>

CHAIN CHECK
• Goal — <verdict + one line>
• Obstacle — <what's jeopardized + scale + verdict>
• Tactic — <forced? reasonable? returns info? verdict>
• Reversal — <form + present? ≥1 in sequence? verdict>
• Value Shift — <before-verdict → after-verdict per reversal, or INERT; trajectory note>

WEAKEST POINT: <the single element that, if fixed, recovers the most>

WHAT IF…
1. (Minimal) <change ONLY the weakest point so the rest of their scene still works>
2. (Clean) <a version that fully works, even if it departs further from the original>
3. (Optional) <only if it genuinely adds something>
```

三个层级的重要性就在这个顺序上：**最小改动版保留用户的版本**，干净版是你的版本，第三个层级可有可无。不要把它们合并成一次重写。

## 反套路演练

三个快速测试，用来杀死套路化内容，任何步骤都可用：

- **永远追问为什么。** 反复问"为什么？"，直到答案让你*自己*都意外。"他有所防备。"为什么？"他被人背叛过。"为什么这件事至今还支配着他？"因为背叛他的那个人，也教会了他一切。"刻板印象，就是*任何*角色都可能说出的那句台词；你的角色该有的，是只有他能说的那一句。
- **一个创伤，两种角色。** 同样的创伤会造就相反的人。"幼年被抛弃" → 一个人奔向每一段关系、死死抓住；另一个人拒绝需要任何人。选那个*不那么*显而易见的反应。
- **闭眼认人 / 剪影测试 (Eyes Wide Shut / Silhouette test)。** 不看脸、只凭形体，你能认出这个角色吗？如果剪影读不出来（战士 / 神秘学者 / 盗贼），设计就是通用的——生成之前先修好。

## 填写

**1. 主题陈述** —— 是一个主张，不是一句话梗概（logline）。
> _______________________________________________
> *（例如：「归属感是自己挣来的，不是别人欠你的。」）*

**2. 这个故事在争辩什么？** —— 表述成一个可检验的信念。

# 角色引擎·七层卡 ⊕ 九问卡 融合卡

**三处冲突裁决之一落本件：七层设定卡与九问角色表不是两张卡，是一张卡的developing两端。**

| | 九问卡（开发端） | 七层卡（标准端） |
|---|---|---|
| 回答 | 这个人*为什么成立*、有什么可拍 | 这个人*如何被标准化记录、一致生成、逐场追踪* |
| 形态 | 访谈/工作表（世界观先行，逐问约束下一问） | 单卡自洽的规则库（E1-E11）＋锚定词＋状态表 |
| 时机 | 开发期（建角色之前） | 落卡期（建卡与跨镜头生成时） |
| 依据 | `九问角色卡.md`、`角色关系网-四辐条.md`（higgsfield） | `2-人物资产层/角色基准-角色引擎七层设定与锚定词.md`、`角色基准-标准角色设定卡模板.md`（ai-film-art） |

## 单卡工作流（按顺序走，每步约束下一步）

1. **前提**（`故事前提-四字段.md`）→ 2. **世界观六维**（`世界观设定表-六维.md`；硬世界观落《场景基准-世界观视觉宪法》）→ 3. **九问访谈**（`九问角色卡.md`：剪影+矛盾先于一切外貌细节）→ 4. **关系网**（`角色关系网-四辐条.md`：对手/盟友/导师/映衬四辐条，对应七层卡关系层"无孤立节点"E10/E11）→ 5. **七层落卡**（按《标准角色设定卡模板》逐层填：识别/外貌/性格/心理/背景/弧光/关系＋语言指纹＋状态追踪表）→ 6. **锚定词**（外貌层拆锚定段/可变段，E2 短而硬 30-50 词，E3 可变有剧情依据）→ 7. **反套路三测**（`反套路三测.md`：追问为什么/一个创伤两种角色/剪影测试）→ 8. **试镜**（`2-人物资产层/试镜-屏幕测试.md`：长得一致≠能出演）→ 9. **锁定**（图集与版式规范出设定表 → 试镜赢家版本即为后续所有镜头的身份基准）。

## 九问 → 七层 落卡映射

| 九问采集 | 落进七层 |
|---|---|
| 他是谁（身份、可饰演年龄段、地位） | ① 识别层 |
| 剪影测试通过的身体特征（闭眼认人） | ② 外貌层 → 同步产出锚定段 |
| 矛盾（他想要的 vs 他需要的） | ④ 心理层（Want/Need 冲突，C1） |
| 创伤与**不那么显而易见**的反应 | ⑤ 背景层 + ③ 性格层（一个创伤两种角色，取意外解） |
| 弧光要他付出什么代价 | ⑥ 弧光层（闭环+代价，C3/C4） |
| 四辐条关系（对手/盟友/导师/映衬） | ⑦ 关系层（欲望交叉+质变节点，E10/E11） |
| 声音触发词、口头禅 | ⑧ 语言指纹 |

**纪律**：
- 九问没问完不落卡；七层没落齐不锚定（E1 缺层即未完成）。
- 落卡后的开发增补走状态表（⑨），不回改锚定段。
- 只建需要的那部分——单张主视觉不需要阵营表；没建完的圣经是常态，凭空编造的不是。
