## The Four Audio Layers（四层音频）

每条具备音频能力的提示词都应考虑四层。并非每条提示都需要四层俱全，但明确该纳入哪几层，能给模型清晰的方向。

### 1. Dialogue（对白）——角色说什么

对白放进引号。明确谁在说话、语气如何、说什么语言。

```
她说："我们得走了。现在。"
他低语："还不到时候。"
```

**最佳实践：**
- 对白要短——每个角色每个镜头 1-2 句
- 指明情绪语气："急切地说"、"低语"、"隔着房间喊"
- 非英语：指明语言和方言 → `She speaks in Cantonese: "走啦"`
- Seedance 1.5 Pro：支持英语、中文（含四川话、粤语、台湾国语、上海话）、日语、韩语、西班牙语、印尼语

### 4. BGM（背景音乐）——音乐情绪

不要点歌名或艺人名（内容过滤）。描述音乐的质感。

```
BGM: 缓慢的钢琴，小调，忧郁。
BGM: 紧张的管弦乐推进——低音弦乐，逐渐上扬。
BGM: lo-fi 嘻哈节拍，温暖的黑胶底噪，松弛。
```

**最佳实践：**
- 描述配器、速度、情绪——不要只给流派标签
- "紧张的弦乐，逐渐推进"比"悬疑音乐"更有效
- 指明音乐进出的时机："钢琴在中段进入，一路推进到结尾"
- 节拍同步类内容："剪切卡在强拍上"或"运动在 drop 处达到峰值"

### 压制音乐——`NO BGM` 是规格，`no music` 只是偏好

`[DEMO（演示实证）— Joey cinema-director-v3, 2026-08-16]` `[UNPROVEN HERE（此处未验证）]` 当一段片子必须不带配乐时，措辞很关键。**`no music` 读起来只是一个薄弱的风格偏好**，敌不过模型"生成视频底下要有铺底"的强先验。**`NO BGM` 读起来是制作术语**——硬规格——才是该写的形式。首次使用时展开一次，让缩写无歧义，之后直接用缩写即可。

**先立正面，再做否定。** 先说音频*是*什么，再说它*不是*什么——绑定到表面与材质的剧情内声源，加上房间底噪（room tone）。一条没有任何正面内容的压制条款，会把"寂静"听起来像什么交给模型决定，而它会决定要一个铺底垫。

```
Audio: diegetic sound only（仅剧情内声）——湿石面上的脚步声、衣料摩擦、呼吸、房间底噪。
NO BGM——不出现任何背景音乐。无配乐、无原声带、无器乐曲、无铺底音轨、无环境音乐垫、
无持续低鸣、无音床。任何时刻都不出现任何音乐性内容。
```

**必须在寂静中收尾的场景，把 `NO BGM` 提到最前面。** 音频指令越早出现分量越重；等模型读到收尾的音频块时，它早已决定这段片子听起来是什么样。在片头与镜头数、剪切策略并列写明 `NO BGM`，再在收尾的音频条款里重申一次。

> **枚举要谨慎——这与本仓库的否定词规则相抵触。**
> `../shared/negative-constraints.md` 与本仓库的 staging-reference 学说都认为**在否定之下点名某个事物，其 token 依然会被送入**，可能诱导出你正想拒绝的输出。来源的那串长列表（配乐、原声带、器乐曲、铺底音轨、环境音乐垫、持续低鸣、音床、渐强、警示音、哼唱、口哨、歌词）是对一个真实失败的回应——光秃秃的否定会让模型自行补一段"环境质感"并认为指令已被遵守——但那只是某位实践者的补救，**此处未经测量**。默认用上面的短形式；只有当短形式在你面前的镜头上已经失效时才动用完整枚举，并预期枚举本身带有一定的诱导风险。

**Attached-track lock（附加轨锁定）。** 当附加了音频轨或视频轨，它就是唯一且完整的音频来源，并拥有全部内部时序——绝不要把逐节拍的时序强加给一次 lipsync 素材：

```
AUDIO: 附加片段 @Video 1 是本序列唯一且完整的音频来源。不得生成任何额外音频——
无房间底噪、无拟音、无环境声、无呼吸声、无新增对白、NO BGM。
```

**The unheard-track technique（未入混音轨技巧）** 让身体对着混音里并不存在的音乐表演——配乐打算后期再加时很有用：声明该轨不可闻，然后对照它描述表演（*"大致踩着那条听不见的 87 BPM 节拍演唱"*），再加上确实可闻的剧情内声层。

## 音频提示词结构

把音频提示自然地织进提示词里，或在结尾设一个专门块。

### 内联法（短提示词首选）：

```
一个女人走进安静的图书馆。高跟鞋敲在大理石地面上——每一步都在回响。
她低声问图书管理员："你们有《书信全集》吗？"
远处有翻页声。楼上某处一只钟在滴答。
```

### 专门块法（复杂音频更适用）：

```
[场景描述——视觉内容、动作、镜头]

Audio:
  Dialogue: 她说 "我们黎明出发。" 他回答："我会准备好。"
  SFX: 咖啡杯放下，椅子向后刮响
  Ambient: 清晨的厨房——窗外鸟鸣，水壶刚烧开
  BGM: 无——寂静强化紧张感
```

### Beat sync（节拍同步）——音频为画面编舞

上传一段 MP3 作为 `@Audio1`，然后把音频特征映射到视觉元素。最低要求是三句话，各管一件事——**节奏来源 / 哪个视觉元素响应 / 能量如何映射到弧线**：

```
以 @Audio1 作为节奏基础。将镜头转场同步到节拍位置。视觉能量随音频渐强而累积，
在 drop 处达到峰值。
```

你可以**把不同的视觉元素指派给不同的音频特征**——像混一首曲子那样做音画混搭：

```
@Audio1 驱动视觉节奏。镜头剪切落在强拍上。主体运动在 build 段加速，在峰值保持，
在 drop 处释放。色温随渐强转向更暖。
```

镜头 ← 节拍位置。运动 ← 动态轮廓。色彩 ← 整体能量弧。

它能**与其他参考叠加**——角色来自 `@Image1`，镜头风格来自 `@Video1`，节奏来自 `@Audio1`，一并处理：

```
@Image1 作为角色参考。跟随 @Video1 的镜头运动风格。@Audio1 作为节奏基础——
将所有镜头转场同步到节拍位置。角色运动应随音乐脉动。
```

**唯一的约束：** `@Video1` 的镜头风格与 `@Audio1` 的节奏必须**在时间上兼容**。从视频参考里取来的缓慢连续推轨与一支 EDM 曲目互相打架，等于给时序分支下达自相矛盾的指令——与混合风格冲突的参考*图像*属同一失败类别。选能共存的参考。（姊妹条目：`../higgsfield-seedance/SKILL.md` § Reference Roles → Load-Bearing Rule：参考各守其道。）

### 卡点剪辑——把分开生成的片段组装到一条轨上

`[EMPIRICAL（实测）— MiniMax H3 技能语料，重新推导；跨模型剪辑手艺]` Beat sync 管的是片段*内部*发生什么；这三条法则管的是片段所落在的时间线：

- **一条主轨。** 整段片子绑定后期铺上的一条连续音乐轨——绝不把逐片段的音频首尾拼接。音乐上的接缝比画面上的接缝先被听见。
- **剪切落在音乐标点上**——一口气、一句词的停顿、一记军鼓、一次 drop。绝不在唱音的元音中间硬切，除非切入的镜头是一个口型延续该元音的大特写（ECU）：口型连续性是*剪辑*约束，不只是提示词约束。
- **有意掩盖批量调色漂移。** 分批生成的片段调色永远对不齐。对整条时间线做一次统一的细颗粒处理加一条 LUT，作为刻意的收尾步骤，把片段间的色彩差异藏起来——否则它们会被当作连续性错误。

### 15 秒提取问题——选好窗口，别直接上传整轨

音频参考上限是 **15 秒，而且模型取的是你上传内容的前 15 秒**。丢进一整首 3 分钟的曲子，你几乎总是在喂它**前奏**——能量低、常常只有环境声、没有节奏驱动。时序分支无从映射。

正确的 15 秒应走一条 **build → drop（铺垫 → 落点）** 弧线：张力上升直至峰值。这个动态梯度正是化成视觉能量结构的东西。能量均匀的段落给了模型可检测的节拍却**没有弧线**——输出节奏上同步了，戏剧性上却是平的。

窗口通常藏在哪里：

- 预副歌进副歌
- 器乐铺垫进 drop（EDM、电子、嘻哈）
- 主歌高潮进桥段
- 前奏的最后 15 秒，正好破进第一个 hook

**上传前精确截取这一段。** MP3 格式，码率 **≥256kbps**——更低码率会劣化节拍检测。别上传整轨然后祈祷；选好窗口，剪出来，上传那一段。（把工作流反过来——音频先行、画面围着它搭——会在结构层面改变输出，不是微调。）

### Seedance 2.0
- 上传 MP3 音频作为 @Audio 参考（Rule of 12 的一部分）
- **仅支持 MP3**——WAV/AAC/OGG/FLAC 静默失败且不报错
- 每段最长 15 秒，最多 3 个音频文件，单个 10MB；beat-sync（节拍检测）需要 **≥256kbps**
- **实测到的强制边界** `[EMPIRICAL（实测）— 第三方，China Ark 通道，2026-08]`：单段时长强制在 **1.8–15.2 秒**，且**所有附加片段的总时长同样封顶 ≤15.2 秒**——三段各自合法的 6 秒片段会被拒（捕获到 400 错误）。由第三方在 China Ark 通道上实测；Higgsfield 自家代理的强制行为**未经核实**——如果多片段附加失败，首先怀疑这个总时长上限。
- 时间戳锚定（Timestamp anchoring，音频作输出时）：`"Audio @Audio1 与上传内容完全一致地从 0s 播放到结尾。不得修改。"` 然后删除所有环境声/SFX/音乐词，防止生成引擎覆盖。
- **`@Audio1` 同时也是视觉驱动**——beat sync、`[AUDIO: Xs]` 脚本块与前 15 秒提取陷阱，都见上方 § 音频作为条件输入一节。

> **提示词正文的仅剧情内声（diegetic-only）约定**——一套建立在 Seedance 2.0 音频能力之上的提示词写作纪律。BGM 是合法的音频*层*（见上方 § The Four Audio Layers（四层音频））——Seedance 本来就能生成它。仅剧情内声约定说的是你在提示词正文里*应该写什么*：只写物理上存在于场景中的声音（湿人行道上的脚步、动作带起的衣料声、呼吸、房间底噪、天气、武器射击、人群反应、舞台烟雾），而不是点名歌曲、歌词或配乐提示。如果音乐是留给成片的，后期再叠，不要写进提示词正文。
>
> 即使 BGM 受支持，这套纪律仍然重要的两个理由：(i) 配乐描述词（"戏剧性的弦乐"、"管弦乐渐强"）对生成音频的约束不足，经常产出与场景不搭的通用音乐垫；(ii) 上面条目里的 *timestamp-anchoring*（时间戳锚定）+ *remove-all-music-tokens*（删除一切音乐词）模式在上传 MP3 音频参考时已经在强制这套纪律——仅剧情内声约定把该模式推广到所有 Seedance 提示，无论是否附加了音频参考。

## 场景音频生成——Seed Audio 1.0

区别于上文的视频内联合音频：**Seed Audio 1.0**（字节跳动，2026-06-23 在 FORCE 大会上发布）是一个独立的**一次生成整场音频的生成器**。一次生成即产出多说话人对白 + 音乐 + SFX + 环境声，且已完成混音——是广播剧式的一场戏，不是单条人声轨。用它为你要在后期组装的素材铺声底，或生成完全没有视频的场景音频。

### 何时选它——决策表

| 你的需求 | 用什么 | 理由 |
|----------|-----|-----|
| 一整场戏的声底：多个说话人 + 音乐 + SFX + 环境声，一次混好 | **Seed Audio 1.0**（`seed_audio`） | 一次生成的场景音频；剧本式提示词驱动整场混音 |
| 一条干净的人声轨（旁白、单人 VO） | **`text2speech_v2`**（选一个引擎） | 单人声 TTS——更简单，引擎可选 |
| 声音直接烧进生成的视频里，与画面动作和口型同步 | **Seedance `generate_audio`**（视频内） | 原生联合生成——音频与画面同一次产出（见 § 音频作为条件输入） |

### 已验证的接口面 [OFFICIAL（官方）— 模型规格 2026-08-01]

模型 id `seed_audio`（output_type `audio`）。参数：

| 参数 | 取值范围 / 选项 | 默认值 |
|-------|-----------------|---------|
| `format` | wav / mp3 / pcm / ogg_opus | wav |
| `sample_rate` | 8000–48000 Hz | 24000 |
| `speech_rate` | −50..100 | 0 |
| `loudness_rate` | −50..100 | 0 |
| `pitch_rate` | −12..+12 | 0 |
| `voice_type` + `voice_id` | preset（预置）\| element（克隆元素）——**必须成对出现** | 无 |

媒体角色：`image_references` + `audio_references`。按 fal 的 schema：最多 **3 段参考音频**（每段 ≤30 秒、≤10MB）**异或（XOR）一张图像参考**——图像参考与音频参考不能同时使用。提示词中按加载顺序引用音频输入：`@Audio1`、`@Audio2`、`@Audio3`。

### 剧本格式提示 [EMPIRICAL（实测）— 社区指南，非官方文档]

本小节的一切都是社区收敛出的实践，不是规格——当作起点，不当作保证。把提示词写成**广播剧剧本**：

- 以场景头开场：`[Scene: 忙碌的咖啡馆，清晨]`
- 说话人标签加情绪括注：`Host (温和、明快): "…"`
- 声音提示就地内联：`[sound: 意式咖啡机，轻柔爵士淡入]`
- 音乐按**情绪而非流派**写："轻柔的钢琴推向凯旋的管弦"，而不是"电影配乐"
- **约 4 个不同说话人**是可靠上限
- 先**测试 20 秒片段**，再向约 2 分钟的上限扩展
- 音频要进后期就输出 **WAV**（`format: wav`）

紧凑的完整示例：

```
[Scene: 雨夜收摊的夜市]
Vendor (疲惫而温和): "最后几串——半价，拿去吧。"
Girl (兴奋): "两串！不——三串！"
[sound: 雨点敲打油布棚顶，远处一辆踏板车驶过]
Vendor (轻笑): "就三串。小心，很烫。"
[sound: 硬币落在金属托盘上，炭火嘶嘶]
Music: 一支孤独的弱音小号在雨声中淡入，惆怅而有希望。
```

### 生成后配音——Supercomputer 工作流 [DEMO（演示实证）]
