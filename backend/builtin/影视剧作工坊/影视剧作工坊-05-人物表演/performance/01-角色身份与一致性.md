## Soul ID 是什么？

Soul ID 是一套角色一致性系统。只需创建一次角色参考，即可在无限次生成中复用——不同场景、角度、光照与动作——而面部与核心外观保持一致。

---

## 工作原理

1. **创建 Soul ID** —— 上传一张参考图，或使用 Soul 2.0 生成一张
2. **系统存储该角色** —— 为其分配一个 ID
3. **在后续提示词中引用** —— "使用 Soul ID 角色 [名称/参考]"
4. **角色保持一致** —— 面部、肤色、基本特征在多次生成中保持不变

---

## 何时使用 Soul ID

✅ 你在用同一角色构建多镜头序列
✅ 你在创作有反复出场主角的短片/故事
✅ 你在打造 AI 网红或品牌吉祥物
✅ 你希望产品广告战役中的面部保持一致
✅ 你在制作多场景动作序列，需要主角外观始终如一

❌ 只需要一个镜头时不要使用——对单次生成而言是杀鸡用牛刀
❌ 追求最大创意变化时不要使用——一致性会限制风格范围

## 使用 Soul ID 编写提示词

当 Soul ID 角色处于激活状态时，你的提示词应当：

**1. 简洁地引用角色：**
```
Soul ID 角色夜晚走过拥挤的东京街头。
```

**2. 描述变化之处——而非角色长什么样：**
```
Soul ID 角色此刻身着正式黑色西装。她站在讲台上，向会议室发表讲话。
镜头：Dolly In（推轨推近）推向她的面部。
风格：电影感，冷色调企业灯光，16:9。
```

**3. 你可以更换服装、场景、表情：**
```
Soul ID 角色此刻身穿红色连衣裙，独自在舞厅中起舞。
镜头：360 Orbit（360 度环绕）。
风格：电影感，温暖的金色吊灯光。
```

**关键规则：** 不要重新描述面部或核心特征——Soul ID 会处理这些。
只描述与基础角色*不同*的地方。

## 身份与运动分离——硬性规则

当 Soul ID 激活时，**每条提示词都必须拆分为两个区块**。这是防止身份漂移最重要的一条规则。

### 身份块（Identity Block）——仅静态描述
包含：面部特征、服装、体型、辨识性标记、色彩基调。
不包含：任何运动、镜头、速度或时间性语言。

### 运动块（Motion Block）——仅时间与镜头
包含：镜头运动、动作编排、速度、环境变化。
不包含：任何角色外观的重复描述。

### 前后对照示例

**示例 1 —— 动作场景：**

❌ **混合（错误）——导致身份漂移：**
```
一个高个子女人，绿眼睛，有雀斑，身穿皮夹克，冲过一座仓库，镜头跟拍她，
她的绿眼睛闪着坚定的光，她的雀斑在荧光灯下清晰可见，她跃过一道栏杆。
```
面部在片段中途变形，因为模型在处理运动的同时重新读取了面部描述词。

✅ **分离（正确）——身份保持锁定：**

**身份块：**
```
Soul ID 角色——高挑身材，绿色眼睛，鼻梁与面颊散布浅色雀斑，
身穿合身黑色皮夹克、深色牛仔裤。
```

**运动块：**
```
她冲过一座灯光昏暗的仓库，步履未乱便跃过一道金属栏杆。
镜头：Action Run（动作奔跑）——在她身后低位，与她的速度同步。
头顶荧光灯闪烁。
风格：电影感，冰冷的工业蓝，高对比度。16:9。
```

**示例 2 —— 情绪特写：**

❌ **混合（错误）——镜头运动中面部扭曲：**

一个饱经风霜的男人，深深的皱纹，忧伤的棕色眼睛，身穿灰色羊毛大衣，

### 哪些描述词放在哪里

| 身份块（Identity Block） | 运动块（Motion Block） |
|---------------|-------------|
| 脸型、肤色、眼睛颜色 | 镜头运动名称 |
| 发型、发色、头发长度 | 动作动词（跑、转身、坐下） |
| 体型、身高、体格 | 环境运动（风、雨、灯光） |
| 服装、配饰、珠宝 | 速度与时机提示 |
| 疤痕、纹身、辨识性标记 | 氛围变化（光线偏移、雾气） |
| 角色的色彩基调 | 场景的风格与调色 |

## 创建高质量的 Soul ID 参考

Soul ID 参考图的质量决定一致性的质量。

**为获得最佳效果：**
- 使用**正面或 3/4 角度**的肖像——完整面部可见
- **均匀光照**——避免生硬阴影遮蔽特征
- **中性至轻微的表情**——微笑可以，极端情绪会限制灵活性
- **清晰的图像**——无模糊、无遮挡，尽量避免眼镜
- **单一主体**——参考画面中不要有其他人

**用于生成 Soul ID 参考图的图像模型：**
- **Soul 2.0** —— 最适合时尚前卫、高美感的角色
- **Nano Banana Pro** —— 最适合极致的写实锐度
- **Seedream 4.5** —— 适合多种风格

## 图集不是菜单——上面的每一样东西都是一次请求

构建图集的直觉做法是把*所有东西*都放上去——每一件武器、每一种状态、画成展开状态的机构——然后每个镜头只引用你需要的部分。**但模型不是这样读图的。只要它看到一个细节，就会试图把它展示出来。**

报告的失败案例：某张机甲图集把驾驶舱舱门画成了开启状态。模型**把开启的舱门置于主体的标准外观之上**，导致大多数生成的舱门本应关闭却开着——或者开启与关闭两个版本互相冲突，使整个设计变形。主体在图上画得更大也无济于事；存在感压过了比例。

解决办法是更多的图集，而不是一张更丰富的图集：

- 从基础图集上**擦除所有非默认状态**，对任何可伸缩、带铰链或可展开的部件尤其小心。
- **为每个场景单独建一张图集**，即使差异看起来很小。只在武器实际展开的镜头中**才挂载展开武器图集**。
- **更好的做法是：当镜头必须展示机构如何运作时，给该机构单独的特写作为独立输入**，让它获得焦点，而不是与整体形象竞争。

> **图集上的文字标注对视频几乎不起作用。** 细节下面的小标签教不会模型如何操作它——你仍然要在提示词中把整个操作过程描述出来。模型不会推理*"这是把可伸缩的刀刃，我知道怎么安排它出场"*；每一个机构在使用它的镜头里都要被写成具体的物理动作。

这是"多样性图集"一节的图集侧孪生规则：问题从来不是"这张图集可以包含什么"，而是"模型将被要求从这张图集渲染出什么"。

## 不可触碰的底图——两遍构建角色

角色要用两个模型分两遍构建，而真正的功夫在*之后*：

1. **面部遍**生成身份底版（identity plate）——以**特写**生成，让模型以最高细节捕捉身份。这张特写是后续该角色所有资产校验时对齐的锚点。
2. **造型遍**构建全身服装——戏服、材质、轮廓——与已锁定的面部相匹配。

然后把两者组装成一张图集，**附带一条硬性条件：原始特写肖像绝不再过一遍模型。** 组装在编辑工具中*围绕*它进行。每一次状态变化——一道疤痕、一个发型、污渍、伤口、一件新服装——都用蒙版逐点融入，**绝不触碰底图**。

**为什么重要：** 底图始终保持*同一批像素*，因此身份及其承载的皮肤质感能在角色后续每个版本中幸存。这是对"双工具精修管线（Two-Tool Refinement Pipeline）"一节所记录漂移的结构性解法——那里每多过一遍模型，质感就向塑料软化一分；而底图永不再过模型，所以永不软化。

### 守住脸，改变其他一切

同一规则可推广到同一角色的替代版本——不同年代、不同宇宙，在一个世界里是英雄、在另一个世界里是反派。**新版本是新的外观，不是新的人：** 服装、妆容、发型、疤痕与损伤都可以变，而面部保持同一批像素。正是这一点让替代版本仍然被认作同一个人——而这正是这项工作的全部难点：在"让他们不同"与"让他们相同"之间求生存。

一条值得写明的推论，因为图集往往就在这里悄悄烂掉：**新状态就是有新名字的新资产，绝不覆盖旧资产。** 在公共休息室里的角色和躺在病床上的同一个角色，是一个人的两份资产。

## 参考底版——两条轴线

`[此处未经验证]`
照片级写实的角色工作实际运行着两件听起来像一件事、实则不是的事。把它们分开是底版构建中最有用的一个想法，因为"照片级写实"听起来两者都涵盖，而参考图上只应该有其中之一。

**轴线一——生物写实：完全开启。** 主体必须被读作一个真实活着的人：毛孔质感，下颌与发际线的绒毛，次表面散射，一根一根的发丝与碎发，有真实织法与垂坠感的织物，有真实表面的金属，有深度与水分的眼睛。这条轴线永不关闭。

**轴线二——摄影拍摄行为：每张底版上都关闭。** 底版不是一张对打光布景的翻拍。不要主光方向、不要暗面、不要投影或接触阴影、背景不要光衰减、不要溢光、不要焦外虚化、不要景深衰减、不要暗角、不要眩光、不要雾感。

**为什么轴线二要关闭：** 这些是*参考图*，不是成品帧。任何烤进底版的光——脸颊上的三角光、鼻子投影、脚下的接触阴影、背景布上的暖色渗光——都会被每一个读取它的下游生成继承并放大，并与实际场景想要的任何光照打架。**底版携带零光照；所有光照都由后续的场景提示词完成。**

> **陷阱。** 在底版提示词里写*"由真实摄影师用真实相机在真实布景上拍摄"*会连同轴线一一起把轴线二**打开**——而轴线二恰恰是污染参考图的东西。主体应该看起来像一个真实的人，被平光渲染，身后空无一物。

唯一幸存的拍摄短语：`用 50mm 定焦镜头拍摄，锐度均匀，柔和的自然胶片颗粒。是拍摄而非生成。`——焦距用平实语言点名，不带光圈、不带焦外、不带衰减，因此买到了反 AI 均质化的信号，却没有打开拍摄行为。

### 背景是"色场"，不是"房间"

这是最常丢失的区分。被拍摄下来的无缝背景纸是一个*物理表面*——它接受光照、发生衰减、承接溢光、留存主体的影子，有一个供主体站立的地面。**底版背景完全不是这些。** 它是一片平坦均匀的色场，主体身后空无一物：没有表面、没有地面、没有墙、没有墙角、没有接缝、没有地平线、没有主体可接触的平面。主体不站*在*任何东西上，也不站*在任何东西前*，主体的任何行为都不影响这片色场。

### 悦目写实的上限

皮肤全写实永远开启——但写实绝不等于不讨好。不要痤疮、瑕疵、明显斑点、未被要求的疤痕、坑洞毛孔，或任何读起来像临床记录的攻击性细节。质感要细腻、柔和、均匀、自然。**哑光是反塑料的杠杆；细腻均匀是悦目的杠杆，两者同时运行。** 二者冲突时，向悦目一侧解决——一张脸永远应该好看。

### 提示词经济——精简的提示词更能锁住脸

这与直觉相反。当强参考已挂载时，**参考图承担身份负载，提示词的职责是说明在这张图里要用这个身份做什么。** 在强参考之上再叠厚重视觉描述，会造出双重加重的提示词，稀释模型真正需要从文本获得的方向。

- 用**简短的辨识性称呼**指认主体——*"那个深酒红色头发的女人"*——而不是用一段话重新描述底版已经展示的骨骼结构。
- 把负载放在提示词**独有**传达的信息上：构图、取景、姿势、表情、手在做什么、参考图中还没有的服装。
- **删掉参考图已承载的身份描述**，除非它对这张特定图是承重的。
- 模型对提示词前端的读取权重最大——把构图和姿势放在前面，而不是埋在描述之下。

**经验法则：** 如果一句话在重新描述挂载参考中已经可见的东西，除非构图依赖它，否则删掉。**例外是第一张底版**——面部锁定没有参考可依赖，它*就是*参考本身，它获得本文件中任何内容里最长、最具体的描述。其后的一切都应更精简。

当挂载两张或更多参考时，**说明每一张承担什么**，以免模型把平均化：*"脸、骨骼结构与肤色来自角色参考；服装与配饰来自造型参考。"*

## 角色图集创建

**角色图集**是一张多角度参考图，从若干视点展示同一角色——通常为正面、3/4、侧面轮廓和背面。它为模型提供全面的几何信息，并显著提升一致性。

**每个角色的两张图底线**：绝不要把只带一张图的角色交给视频模型。最低限度是**一张清晰的面部视图 + 一张全身图**——"让 Seedance 不必去猜"。下文的一切都从这条底线向上构建。

**背景：** 把图集放在**中性灰**上，不要白色或黑色——这是经过验证的结论（人物用浅灰圆形背景幕，生物图集用 `#7f7f7f`）。

*灰色为何有效* `[此处未经验证]`：纯白与纯黑会制造**最大的主体-背景对比度**，而图像与视频模型在高对比边缘放大错误最狠——光晕、边缘呼吸与轮廓失稳正是在那里被烤进画面。中性中灰底降低了这种对比度，带来更干净的边缘提取，并且当静帧日后被读取为参考帧时继承的对比度也少得多。由于几乎每一张角色底版最终都会成为视频工作的种子，灰色是正确的常设默认值，而非风格偏好。保持*色场*中性、绝不暖偏，但也不要让它把主体染冷——皮肤与服装按真实色调渲染，如同中性日光之下。参见"参考底版——两条轴线"一节。

**如何创建角色图集：**
1. 在 Cinema Studio 中用你偏好的光学栈生成角色
2. 使用 **Grid Generation（网格批量生成）**（2×2 或 4×4）产出多个变体
3. 或者，使用 **3D Mode（3D 模式）**（高斯泼溅）围绕单次生成旋转，
   捕捉正面、侧面与 3/4 角度
4. 把最佳角度编排成一张合成的参考图
5. 上传作为你的 Soul ID 参考

**角色图集应包含的内容：**
- **正面脸** —— 中性表情，均匀光照
- **3/4 角度** —— 展示面部特征的立体深度
- **侧面轮廓** —— 鼻子、下颌、耳朵结构
- **全身**（可选） —— 体态、戏服、比例
- **内嵌道具图集**（可选） —— 把反复出现的角色道具直接烤进角色图集的一个面板。图像生成对多元素角色图像处理得很好，因此道具连续性通常无需单独的道具图集也能保持。对那些以这种方式保持不住的道具，参见下文"高难度道具图集"一节。

**用于生成角色图集内容的提示词模板：**
```
[角色描述] 的正面肖像，中性表情，均匀的棚拍灯光，
干净的背景。可见头部与肩部。
```
然后使用 3D Mode 环绕同一生成结果，捕捉更多角度。

**为什么重要：** 多角度角色图集为 Soul ID 提供了远多于单张照片的几何数据。这直接转化为在极端角度变化、动作镜头与侧面视角下更好的一致性。

### 混合图集——为真人"选角"

上文的一切都假设角色是*虚构*的。为真人"选角"——客户、朋友、婚礼电影中的那对新人——是另一个问题，仅靠图集管线解决不了它。把某人的照片作为参考喂进去，回来的图集是**一个相貌相近的演员，而非本人**：戏服和身体到位，脸却差之毫厘。这种"差之毫厘"是本人家属一眼就能识破、旁人却毫无察觉的那种——也因此是最糟糕的一种。

注意这*不是*什么。下文"远景面部变通方案"一节修复的是*塑料感的 AI 面孔*，做法是从更近景的生成面板裁出一张脸贴进更远的镜头——那是质量修复，全程都是生成的像素。而这里修复的是*身份*，像素来自相机。

**演示中的混合做法：**

1. 正常生成图集。保留它真正擅长的部分——
   戏服质感、磨损、轮廓、身体、面板几何。
2. **擦除全身面板上的头部。** 让它们保持无头。生成的脸
   是出错的部分；删掉它，它就无法再捣乱。
3. **把本人的真实照片粘贴进肖像面板。** 该面板
   现在是摄影的，不是生成的。
4. 以这张合成图作为角色参考使用。

**为什么有效：** 肖像面板是视频模型读取身份的地方，而它现在是一张真实的脸，而非对脸的近似。全身面板仍然承载服装与比例——这本来就是它们的全部职责——而且无头的面板不可能贡献一张错误的脸，因此合成图中恰好只有一张脸，而那张脸是正确的。

**约束条件，而且不可选。** 这会把一个真实的、可识别的人送进生成管线。要为这一特定用途取得本人许可，发布的任何内容中都不要包含原始照片，也不要对未同意的人使用这项技术。这项方法所面向的交友、婚礼与礼物类业务，恰恰是许可既容易获得、也容易被跳过的场景。

### 按任务选图集模型，而非按项目

同一条图集提示词跑三个图像模型，得到的不是同一东西的三种质量——而是三种不同的强项，正确答案因角色而异。一次对比测试把同一条提示词跑在 Seedream 5.0 Pro、GPT Image 2 和 Nano Banana 上，结果：

| 模型 | 在那次对比中它赢在哪 |
|---|---|
| Seedream 5.0 Pro | 戏服的**质感与磨损**，以及戏服在全部三个面板间的一致性 |
| GPT Image 2 | **卷发** —— 蓬松、自然，且每个角度都一致；其他模型都守不住它 |

[此处未经验证] —— 某一次制作在两个角色上的对比。要把*方法*当作结论，而不是这张表：**把同一条图集提示词跑过两三个模型，比较后再锁定**，因为起决定作用的维度就是你的角色最难渲染的那个东西（头发、服装磨损、皮肤、标志性道具），而这个维度因角色而异。相对于依赖它们的那些镜头，图集很便宜；一次错误的锁定要在之后的每一次生成中付出代价。

模型规格与当前定价随平台版本变动，使用前请对照平台当前页面核实。

### 单提示词六面板角色图集（3×2 网格）

作为上述多步骤拼装的替代方案，可以
**用一条提示词 → 一张 16:9 图像 →
带六个标注面板的 3×2 网格**生成整张角色图集。
同一角色只描述一次；由于生成只有一遍，
身份在全部六个面板上保持最大锁定。
当图像模型支持 16:9 网格布局时（Nano Banana Pro
及类似的网格能力模型），Soul ID
参考工作优先使用这种方式。

六个面板按规范顺序：

- **面板 1 —— 正面全身：** 正对镜头的中性站姿，
  从头到脚的完整造型可见
- **面板 2 —— 3/4 转身：** 身体与镜头约成 30° 角，重心
  放在后侧髋部
- **面板 3 —— 背面全身：** 正后方视角，展示发丝垂落与
  背面可见的配饰细节
- **面板 4 —— 腰上肖像：** 头、肩、上躯干
- **面板 5 —— 手部细节特写：** 双手向前，戒指
  叠戴、美甲效果、所持道具
- **面板 6 —— 面部细节特写：** 锁骨以上的紧凑裁切，
  耳环、唇部、皮肤质感、眼睛

**提示词模板** —— 开头一次性描述身份，
随后是各面板的位置标签及每个面板的差异点
（站姿、取景、焦点）。以这句话收尾："角色身份
在全部六个面板上完全一致并锁定。六个面板
使用统一的棚拍背景与灯光。"

**为什么单提示词优于多步骤：** 上面的多步骤拼装
（Grid Generation + 3D Mode + 合成）由多个独立生成拼出
一张图集——即使参考很强，身份也可能
在面板之间漂移。单提示词
3×2 网格保持身份锁定，因为全部六个面板
在同一次生成中一起渲染。

### 分栏换装图集（幽灵人台 + 身份面板）

一种双面板图集模式，用于**在不动身份的前提下给既有角色换装**——例如给主角换上一身新的 Y2K 造型：

- **左栏 —— 仅服装，幽灵人台：** 全套新服装
  以穿着状态悬浮呈现的衣物——身体不可见，没有人，没有头。
  在这里完整描述服装（版型、面料、图案、配饰、
  鞋履）；这个面板负责服装。
- **右栏 —— 仅身份：** 取自既有角色参考的
  大幅头肩特写，声明**"面部与输入 100% 一致"**——
  同一身份、同一特征、同一发型、同一皮肤，无漂移。这个面板负责脸；
  服装只以左栏服装的上缘形式出现。
- **清晰的纵向分隔、中性灰棚拍背景、均匀柔光**，
  贯穿两个面板。

这种分栏让视频模型有一个面板读取*他们穿什么*，另一个面板读取*他们是谁*，换装因此无法把脸一起带走。注册为单个 Element，这张图集便两者兼备。与下文"多形态状态追踪"一节互补——服装状态也是一种状态，同样要有自己的图集。

## 角色锚定块

"角色图集创建"一节构建的是进入 Soul ID 的多角度身份参考，而**角色锚定块**是逐镜头的提示词结构，锁定该角色在特定镜头中如何出现。角色图集属于构建期；锚定块属于拍摄期。

一个完整的锚定块要为画面中的每个角色指明十项属性：

1. **身份** —— 这是哪个角色（有参考时与 Soul ID
   称呼对应）
2. **画面位置** —— 定性锚点 + 百分比记法，
   按画面坐标（Frame Coordinate System）配对使用
3. **景深层** —— 前景 / 中景 / 背景
4. **画面占比** —— 角色占据画面面积的百分比
5. **身体朝向** —— 角色面朝的方向（面向
   镜头、背对、左侧脸、右侧脸、四分之三侧面）
6. **姿势** —— 当前的身体形态（站立、坐、
   倚靠、迈步途中）
7. **视线方向** —— 角色在看哪里，可用画面位置或另一主体
   指称（"看着角色 B"）
8. **接触点** —— 角色所依托的
   物理表面或物体
9. **状态锁定** —— 当前的情绪或身体状态（平静、
   力竭、受伤、湿透、运动中）——跨场景的状态纪律
   见"多形态状态追踪"一节
10. **面部表情** —— 具体的情绪档位（镇定、
    恐惧、浅笑、咬紧牙关）

该块在 Seedance 输出格式中位于动态描述之前；当多个角色同框时会接入空间布局块（Spatial Layout Block）（多角色扩展沿用同一写法）。

### 多形态状态追踪

当角色在项目中发生状态变化——打斗场景的伤口延续到下一场、中途换装、跨多个阶段的变身——要**为每个状态生成单独的锚定图集**。不要依赖基础角色图集加提示词文本来追踪差异；在迭代压力下模型会丢失状态。

这套纪律就是电影制作所说的**场记（script supervising）**：每个镜头都记录自己应对齐角色的哪个版本。一个有五个阶段的角色（初始 → 打斗受伤 → 部分变身 → 接近完全 → 完全变身）会得到五张不同的 Soul ID 图集，每个阶段一张。镜头清单按名称引用对应的图集；提示词在身份块中指明阶段。

代价是每个状态多一次角色图集生成；回报是没有任何镜头会打开一个必须留到逐帧审查时才被抓住的连续性 bug。

### 远景面部变通方案

在远景中，角色图集面板上的脸常常读起来有塑料感——当画面大部分是身体或环境时，模型会降低面部细节的优先级。变通办法：先渲染远景，再从**更近的镜头**（中近景、肩上、头肩景）裁出**脸**，在后期把远景中的脸替换为裁出的那张。

这是一种角色图集构建技术，不是生成技术。在角色图集中专门保留一个更近景的面板，用于此目的——那张你会在需要时剪下来贴回远景的脸。

### 高难度道具图集

有些道具无法从单一参考面板稳定生成——模型总把怪物利爪渲染成剑、手持道具默认成通用形状、配饰无法跨镜头保持连续。对这类道具，在角色图集之外**单独建一张道具图集**：

- **内侧视图** —— 内部结构或组装细节
- **外侧视图** —— 轮廓与表面
- **状态变体** —— 开启 / 关闭 / 展开 / 握持 /
  战斗启用，视道具的剧情需要而定

与上文"角色图集创建"一节中**内嵌道具图集**条目互为相反的模式——内嵌适用于能干净生成的道具；独立道具图集是生成不干净的道具的兜底方案。

## 双工具精修管线（Two-Tool Refinement Pipeline）

对高投入的角色——在项目中承担大量镜头的主角——用 **Soul Cinema** 做初次生成，再用 **GPT Image 2** 做精修编辑，产出的锚定图集比任何单一工具都更强。Soul Cinema 是首轮生成用的图像面（针对角色描述的大批量生成）；GPT Image 2 是第三方（OpenAI）编辑面，在修改服装、配饰、光照或背景元素时能保留既有图像细节——尤其是面部几何。

分工按任务划分：

- **Soul Cinema** —— 生成角色初始外观，覆盖姿势、表情与光照变体。批量更大；该模型批量生成表现好。
- **GPT Image 2** —— 编辑选中的 Soul Cinema 输出，精修戏服、更换配饰、调整光照，或用状态变体扩展图集。在编辑压力下对面部的保留更好。

什么时候两个工具都用：该角色将出现在数十个镜头中，值得把迭代成本前置。一个来自制作一线的规划锚点——某部 90 分钟剧情长片的主角在任何叙事镜头生成开始之前，就消化了约 600 次 Soul Cinema 生成加约 200 次 GPT Image 2 生成。

什么时候只用一个工具：只出现在寥寥几个镜头中的角色不值得承担双工具的开销；单次 Soul Cinema 生成即可。

### 反"AI 垃圾感"写实合成（快速手动变体）

每一次 GPT Image 2 编辑都会把 Soul Cinema 的皮肤质感磨平，滑向扁平、塑料的"AI 垃圾感"——面部失去毛孔级写实，而那正是 Soul 遍的价值所在。Soul Cinema **Re-Pass（重过一遍）**（把编辑后的结果再送回 Soul Cinema 重新生成）是一种修复；在任何照片编辑器中做**图层蒙版合成**是更快的手动变体，且原脸分毫不动：

1. 在 **GPT Image 2** 中生成服装/配饰的编辑（正是这一步把皮肤磨软了）。
2. 叠两个图层：**原始高细节 Soul Cinema 镜头在上**，
   **GPT 编辑版在下**。
3. 在上层**只把变化区域**（旧服装）**蒙版掉**，
   让新服装从下层透出来。
4. 结果：脸、皮肤与背景保持 Soul 品质；
   只有服装来自编辑。

想要一张干净的重新生成图集时用 Re-Pass；必须精确保留原始面孔、只移植编辑区域时用图层蒙版合成。与"逐个生成 + Photoshop 合成"的做法互补。

## 微表情——细腻的表演指导

使用这些面部表演指导为 Soul ID 角色增加情绪深度。与 Soul Cast 或角色提示词结合，可获得精确到演员级的控制。

> **肌肉级控制** —— 当下文某个命名表情颗粒度太粗、而你需要具体到面部肌肉时（强颜欢笑与真心微笑之别、混合或诡异表情、逐拍对话表演的 AU）——见
> 《面部肌肉》（FACS Action Unit 编码）。这里每个命名表情
> 都可分解为一个 AU 组合；FACS 是其下的精确控制层。

### 核心组（Core Set）

| 名称 | 描述 | 最适用于 |
|------|-------------|----------|
| **Deadpan Neutral（面无表情）** | 情绪扁平，无可见情绪，面具般的静止 | 惊悚、审讯、AI/机器人角色 |
| **Fierce Focus（凌厉专注）** | 高强度锁定凝视，眉梢微沉，全神贯注 | 动作、竞技、对峙 |
| **Subtle Arrogance（微露倨傲）** | 下巴微抬，半阖的双眼，若有似无的冷笑 | 反派登场、权力关系、时尚 |
| **Candid Profile（抓拍侧影）** | 未摆拍的侧面角度，自然且未察觉镜头 | 纪录片、街头摄影、生活流 |
| **Post-Workout Fatigue（训练后疲态）** | 沉重的眼睑，微张的双唇，薄薄一层汗光，松弛的肌肉 | 健身、事后、力竭场景 |
| **Predator Glare（掠食者凝视）** | 一眨不眨的凝视，头部微低，双眼锁定前方 | 恐怖、惊悚、威慑 |
| **Sunblind Squint（强光眯眼）** | 双眼因强光眯起，面部微皱 | 户外场景、沙漠、海滩、黄金时刻 |
| **Total Dissociation（彻底抽离）** | 千码凝视，双眼失焦，情绪缺席 | 创伤、休克、心理剧 |
| **Controlled Breath（克制的呼吸）** | 双唇微启，鼻翼张缩，刻意的平静 | 动作前的张力、冥想、恢复 |

### 扩展组（Extended Set）

| 名称 | 描述 | 最适用于 |
|------|-------------|----------|
| **Suppressed Smile（强忍笑意）** | 压着即将绽开的笑，嘴角微微抽动 | 喜剧、暗喜、浪漫张力 |
| **Quiet Devastation（静默崩毁）** | 双眼泛起水光，下颌绷紧，强撑着不垮 | 剧情、悲恸、情绪高潮 |
| **Wary Recognition（警觉认出）** | 双眼微微睁大，头部向后微仰 | 重逢、怀疑、反转反应 |
| **Nervous Composure（紧张中的镇定）** | 面色平静却在吞咽，下颌有细微紧绷 | 面试、谎言、高注码扑克 |
| **Cold Calculation（冷酷算计）** | 双眼扫视，无情绪外泄，临床般冷静 | 反派谋划、劫案部署、谍战 |
| **Bitter Amusement（苦涩玩味）** | 单侧冷笑，眼睛并不在笑 | 愤世、黑色幽默、背叛之后 |
| **Exhausted Relief（脱力如释）** | 双眼合上，肩膀垂落，一口气息松开 | 生存、获救、磨难终结 |

| **Vulnerable Openness（脆弱的坦露）** | 柔软的眼神，双唇微启，毫无设防 | 浪漫、告白、情感坦白 |

## 多样性图集——没有克隆体的人群

上文的一切都在为**单一**身份的紧锁定做优化。把那套机器对准人群就会适得其反：**单角色参考会造出克隆大军**——每个士兵、群众演员、路人都是同一个人。一个经典的前后对照：用一张精灵参考生成的精灵大军，回来时是一模一样的克隆体；修复方法是新建一张图集外加一处标签改动。

**修复方法——多样性队列图集：**

1. **构建一张有若干个截然不同的角色并排站立的图集** —— 例如用四个完整设定的精灵，在中性灰背景上排成全身队列：不同性别、不同发色（金发 / 深发 / 赤褐 / 银发）、不同体格、不同甲色（银 / 金 / 玫瑰金）。队列中每个成员都被单独描述；图集上任何地方出现的雷同，都会变成人群中的雷同。
2. **在视频提示词中把它声明为"VARIETY reference（多样性参考）"** —— 而非身份锁定。参考模板：`@elf —— 精灵大军（elven army）的 VARIETY reference：一张包含四个不同精灵的图集……大军是由这四种类型构成的多样化集群，每个精灵都独一无二，没有两个相同。`并在正向锁定中强化："由 @elf 的四种类型构成的多样化集群。"

**角色分工：** `100% matches the reference`（100% 匹配参考）锁定*单个*角色的身份；`VARIETY reference` 则告诉模型把这张图集当作*人口样本*，从中插值出多样化的人群。身份锁定给主角用，多样性图集给主角身后的人群用——两者可以是同一条提示词中的两个 Element。

**与空底版场地规则搭配使用——但那条规则有前提，而这里过去陈述它时没写前提。** 默认仍然成立：生成无人的场地，让视频模型依据多样性图集自行生成人群。这样你得到一张服务所有镜头的底版，人群在每个镜头中仍可调度。

但它会在"人群本身就是场地"的场地上**反转**。一座夜间嘉年华广场用空底版反复出错——模型每次拍摄都得从文字凭空捏出一个拥挤的节日人潮，而各次拍摄彼此对不上。把广场连同**已然涌动的盛装人群**一起生成、烤进场地资产，问题就解决了，而报告的副作用正说明问题：*"提示词保持干净简洁。"*人群不再是每个镜头提示词都要重新规定的东西。

**用哪条规则——在生成底版时、开拍之前决定：**

| 空底版 + 多样性图集 | 人群烤进底版 |
|---|---|
| 人群是*点缀*——路人、背景人流 | 人群**就是布景**：节日、座无虚席的竞技场、全盛市集 |
| 人数与行为逐镜头变化 | 场景每个镜头中都是同一片稠密人潮 |
| 你需要人群可调度（"他们四散"） | 人群是布景，从不接受调度 |
| 密度为低到中 | 密度高到文字无法在不撑爆每条提示词的前提下规定它 |

裁决的检验法：**用文字把人群写出来，看看有多长。** 如果在每条镜头提示词里规定人群都要花掉一段话，那段话就该放进场地产物里。并在敲定场景前先验证——专门跑一次便宜的测试生成，纯粹为了看烤进去的人群稳不稳，这才是正确的顺序。

[此处未经验证] —— 一次制作、一种场地类型。可以确定的是：这条规则的无条件形式是错的。

## AI 网红工作流

Soul ID 是 AI 网红工作流的基石。

**工作流：**
1. 用一张高质量肖像（生成或上传）创建 Soul ID
2. 生成该角色在不同服装/场景下的图像
3. 使用图生视频配合运动预设使其动起来
4. 如有需要，用 Lipsync Studio 添加语音
5. 把镜头串联成完整的内容系列

**网红内容的提示词模板：**
```
Soul ID 角色 [名字] 在黄金时刻的现代厨房里。
她端着一只咖啡杯，热气升腾。她带着温暖的微笑直视镜头。
镜头：轻微的 Dolly In。风格：生活方式，暖色调，9:16 竖幅。
```

## Cinema Studio 3.0 Soul Cast

Cinema Studio 3.0 沿用了 Soul Cast 自 2.5 版以来的 8 类参数：

| 类别 | 选项 |
|----------|---------|
| 类型（Genre） | General、Action、Horror、Comedy、Noir、Drama、Epic |
| 预算（Budget） | $10M – $500M（影响制作价值的美术观感） |
| 年代（Era） | 1900s – 2020s（以十年为步进） |
| 原型（Archetype） | Innocent、Everyman、Hero、Caregiver、Explorer、Rebel、Lover、Creator、Jester、Sage、Magician、Ruler（12 种） |
| 身份（Identity） | 性别、种族、年龄 |
| 外貌（Physical Appearance） | 体格、身高、眼睛颜色、发型、发质、发色、面部毛发 |
| 细节（Details） | 疤痕、纹身、配饰、辨识性标记 |
| 服装（Outfit） | 衣物、材质、颜色 |

### 3.0 Soul Cast 模式

| 模式 | 用途 | 输出 |
|------|---------|--------|
| General | 开放式角色生成 | 角色图像 |
| Character | 聚焦的角色创建，参数详尽 | 角色图像 |
| Location | 环境/场景生成 | 场地图像 |

### 3.0 Soul Cast 规格

- 图像分辨率：最高 4K（Character/Location 模式）· 最高 2K（General 模式）
- 批量大小：1 或 10

### 角色一致性最佳实践

**使用 2–3 张清晰、光照良好的参考照：**
- 正面视图（首要身份锚点）
- 3/4 角度视图（立体理解）
- 侧面轮廓（剪影 + 头发/耳朵/下颌线）

**服装描述必须具体：**
- ~~"休闲装"~~ → `合身的橄榄绿棉质 T 恤、深靛蓝修身牛仔裤、带红色点缀的白色皮面运动鞋`
- 加入模型可以锚定的材质、颜色与独特细节

**在 I2V（图生视频）工作流中——描述动作，而非外观：**
参考图已经承载了角色的视觉身份。重新描述外观会造成冲突。

- **错误：** `@Image1 —— 一位棕色卷发、绿色眼睛、身穿红色夹克的女人走过公园。`
- **正确：** `@Image1 —— 她走过公园，驻足仰望飘落的树叶。镜头：缓慢侧向跟拍。`

**如果特征在镜头之间漂移：**
直接把角色图集图像用作 @Image1，获得更紧的身份锚定。一张干净、光照良好的角色图集胜过多张随手拍的照片。

**多角色场景：**
用不同的 @Image 标签分别引用每个角色：

```
@Image1 作为角色 A（侦探）。@Image2 作为角色 B（目击者）。
角色 A 探身越过桌子，语气坚定地说话。角色 B 移开视线，手足无措。
镜头：缓慢推近角色 B 的面部。
```

## Soul Cinema 作为 CS 3.0/3.5 的默认图像模型

**Soul Cinema** 是 Cinema Studio 3.0 与 3.5 图像模式选择器中的默认 Cinematic 模型——当你把 Cinema Studio 切到图像模式且不更改模型选择时，运行的就是它。它同时服务两个 Cinema Studio 版本，既区别于较早的独立“Soul Cinema Preview”模型。

**它是一个单步生成器。** Soul Cinema 接受一个场景构想（"描述你想象的场景"）并以电影级影像质感直接渲染——一条提示词 → 一批图像，无需合成或多遍流程。独立 Image 标签页的控件有：宽高比（如 16:9）、分辨率（如 2k）、增强器开关（开/关）、批量大小（如 1/4）、可选的 **Color Transfer（色彩转移）**控件（把一张参考图的颜色/调色拉到生成结果上），以及可选的 **+ Character** 参考（一个 Soul ID 或角色图像）。上文的双工具精修管线是当某个镜头需要特定编辑时*可选*的 GPT Image 2 第二遍——并非 Soul Cinema 本身的要求；Soul Cinema 作为单步电影感场景生成器可以独立使用。

Soul Cinema 是图集生成中成本最低的通道之一，因此在**从零构建的场地底版与角色**上默认选择它。Soul Cinema 质量上限为 2k，因此必须是 4K 的图集要在 GPT Image 2 或 Nano Banana Pro 中完成——按任务选模型的完整阶梯见上文“按任务选图集模型，而非按项目”一节。

### 在 Soul Cinema 中进行 Soul ID 身份提示

当 Soul ID 激活且 Soul Cinema 是所选图像模型时，上文记录的**身份与运动分离**规则同样适用——但 Soul Cinema 的通用电影感权重意味着身份块承担大部分工作，而"运动块"被**场景/风格块（Scene/Style Block）**取代（因为图像生成没有时间维度）。

**身份块** —— Soul ID 参考 + 仅静态描述：
```
Soul ID 角色 —— [仅面部/身体/服装描述词，不含镜头或运动语言]。
```

**场景/风格块** —— 环境 + 光照 + 风格方向：
```
[场景]，[时段]，[光照质感]，[色彩基调]。
风格：电影感，[调色]，[宽高比]。
```

在提示词中让两个区块保持文本分离。不要在场景/风格块内重新描述身份——如果面部/服装描述词泄漏进环境措辞，Soul Cinema 对身份漂移是敏感的。何时选 Soul Cinema、Cinematic Characters、Cinematic Locations 还是 Cinematic Cameras，属 Cinema Studio 的选型问题，此处不展开。

### 影棚感 vs. 电影感——Soul Cinema 作为重过流程

当模型返回的角色读起来是**影棚感**——干净、光照均匀、光亮、略带塑料感——这个结果不是成品，而是中间产物。影棚感是提示词中没有任何氛围或调色在做功时模型的默认输出；它渲染得称职，但读起来像"AI 生成"而非"拍摄而成"。（区别于产品 **Cinema Studio**——这里的"影棚"描述输出的视觉质感，而非产生它的生成环境。）修复方法是把影棚感输出当作起始帧，配上明确的电影感方向——色板、调色、镜头特性、光照语言——重新过一遍 Soul Cinema，直到观感到位。

**诊断影棚感。** 症状：皮肤读作平滑/均匀，而非有镜面高光；光照分布均匀（无主光/辅光比，无方向性投影）；色板宽广而准确，而非经过调色；衣物面料读作崭新干净，而非有磨损或垂坠感；整个画面看起来像产品摄影，而非电影剧照。

**重过流程。** 拿着影棚感输出，然后：

1. 把它作为参考上传进 Soul Cinema（或者，若想精确保留身份、只改观感，可使用 Seedance 的 Edit Shot）。
2. 加上明确的调色方向——"Bleach Bypass"、"Teal Orange Epic"、"Sodium Decay"、"Bleached Warm"——从 Cinema Studio 3.5 Color Palette 预设中挑选，或在 Manual Style 中自行描述。
3. 加上方向性光照语言——单一主光源、侧缘轮廓光、逆光（contre-jour）、剪影——而不是"光照良好"或"布光均匀"。
4. 加上镜头特性——Vintage Haze、Warm Halation、Anamorphic——打破默认的临床式锐利。
5. 加上色板压缩——"柔和"、"去饱和"、"压碎的黑色"——把宽广准确的色板拉成经过调色的色板。

影棚感只是路上的一站，不是终点。把重过一遍规划进工作流；不要把第一次生成当成成品。
