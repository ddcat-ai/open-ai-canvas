# 负面约束与预防措辞总表（Shared Negative Constraints）

装配视频提示词（Seedance／即梦等）时，把下面对应类别的预防块追加进提示词，以预防常见的 AI 视频/图像生成瑕疵。本文件按类别组织；写提示词前，先扫一遍与内容相关的类别。

> **总纪律：一切预防措辞都写成正向句**（"要什么"），不要写成否定句（"不要什么"）——理由见下文 §你写下什么词，就招来什么。

---

## 身体 / 动作瑕疵（Body / Motion Artifacts）

多发生在模型无法在单次生成内解析复杂物理动作时。

| 瑕疵 | 为什么会发生 | 建议的预防措辞 |
|------|-------------|----------------|
| **肢体漂浮 / 多出肢体** | 姿态含糊或被遮挡时，模型幻觉出多余 appendage | "Anatomically correct, all limbs visible and naturally positioned"（解剖结构正确，所有肢体可见且位置自然） |
| **肢体粘连** | 两个角色靠得太近——模型分不清哪只手臂是谁的 | 让角色保持一臂距离或分开镜头；写"distinct body separation between characters"（角色之间身体界限分明） |
| **身体比例失真** | 相互冲突的身体描述词过载（高个 + 矮壮）或极端机位 | 只选一个身体描述词并保持一致；避免互相矛盾的大小线索 |
| **动作抖动 / 卡顿** | 一条片段里塞了太多动作——模型在它们之间摇摆 | 每条片段 1 个主动作 + 最多 1–2 个次动作；复杂序列拆成多次生成 |
| **快动作形变（motion morphing）** | 高速运动超出模型的时间一致性 | 先生成慢动作（Slow Mo），后期再提速（剪映/CapCut、Premiere、DaVinci） |
| **指定招式失败** | 具名招数（回旋踢、上勾拳）需要模型执行不了的多帧精确编排 | 写"general fighting energy"（总体格斗气势）或"struggling"（缠斗中），不写具名招式；描述结果，不描述技术 |
| **扭打生成成拥抱** | 近身肢体接触对模型来说语义含糊 | 动作戏用纯文本（不用 @ Elements）；描述身体位置关系，不写扭抱招式名 |

## 面部 / 身份瑕疵（Face / Identity Artifacts）

多发生在模型跨帧或跨代生成时丢失"这是谁"。

| 瑕疵 | 为什么会发生 | 建议的预防措辞 |
|------|-------------|----------------|
| **脸部形变 / 漂移** | 没有 Soul ID 参考，或提示词内外观描述互相冲突 | 多镜头工作一律用 Soul ID（见 《身份与微表情》）；删除互相矛盾的外观描述词 |
| **跨镜头身份漂移** | 各条提示词里的角色描述不一致，或身份与运动混写进同一个块 | 角色描述在所有提示词中逐字复制粘贴；身份块与运动块分开写（见 《身份与微表情》 §身份与运动分离——硬性规则） |
| **双角色换脸** | 动作戏里用 @ Elements——模型搞混哪个角色是哪个 | @ Elements 只用于静态/慢速场景；动作戏用纯文本；主角写在提示词最前面 |
| **运镜中脸部扭曲** | 身份描述词与时间/运动语言混写，导致模型逐帧重新解释这张脸 | 身份描述词（脸、服装、身体）放静态的身份块；镜头与运动放独立的运动块 |
| **表情错误 / 面部僵死** | 没有微表情指导，或情绪线索互相冲突 | 用具体的微表情术语（见 《身份与微表情》 §微表情）；每个镜头一种情绪 |
| **皮肤塑料感 / 蜡感** | 角色工作用错了模型，或描述词过度平滑 | 写实皮肤用 Kling 3.0 或 Soul Cast；追加"natural skin texture, subtle imperfections"（自然皮肤质感，细微不完美） |

## 质感 / 灯光瑕疵（Texture / Lighting Artifacts）

多发生在模型误读视觉风格或渲染指令时。

| 瑕疵 | 为什么会发生 | 建议的预防措辞 |
|------|-------------|----------------|
| **质感闪烁** | 跨帧风格描述不一致，或模型在两种视觉风格之间拉锯 | 锁定一个具名风格（Cinematic / VHS / Super 8MM / Anamorphic / Abstract）；绝不混用互相竞争的风格 |
| **过亮 / 平光** | 提示词没写灯光——模型默认均匀的通用布光 | 永远指定光源与光质："single side-light"（单一侧光）、"golden hour"（黄金时刻）、"practical only"（只用画面内实用光源） |
| **VFX 预设显卡通** | 预设类型配错模型，或风格与特效冲突 | 写实类预设（Explosion 爆炸、Freezing 冰冻）→ Kling 3.0/2.6；风格化预设（Animalization 动物化、Multiverse 多元宇宙）→ Wan 2.5；追加"photorealistic, physically accurate"（照片级写实、物理准确） |
| **产品镜头显廉价** | 没指定表面/背景，灯光通用 | 指定背景表面（"raw concrete" 素混凝土、"black velvet" 黑丝绒），加质感线索（"surface catches light on edges" 表面边缘吃光） |
| **风格被无视 / 输出平庸** | 风格描述太含糊（"让它好看点"）或根本没点名风格 | 用确切的具名风格 + 具体调色："Style: Cinematic. Cold blue shadows, warm amber highlights, high contrast"（风格：电影感。冷蓝阴影、暖琥珀高光、高对比） |
| **调色不一致** | 同一序列的各镜头调色描述不同 | 把调色锁进 Moodboard，或在每条提示词里逐字重复同一套色彩语言 |

## 整帧劣化——"质量词"与"观感选择"之别（Whole-Frame Degradation）

有些作者伸手就来的"电影感"词，会被模型读成关于**渲染**的指令而不是关于**拍摄对象**的指令——而渲染指令落在**整个画面**上。随手丢进去一句 `film grain` 当质量注记，画面里**所有东西**都跟着变软；一句 `imperfect focus`，连主体一起失焦。

**统领性区分：***内容*可以不完美——不匀的光、不对称的构图、凌乱的房间、摄影师的晃动；*画质*必须锐利。不完美是**拍摄对象的选择**，永远不是渲染指令。

正因如此，同一个词在一种从句里是有意的技法、在另一种从句里就是昂贵的错误。三种用法是合法的，而且是有意使用的：

| 合法用法 | 它是什么 |
|----------|----------|
| **观感选择（look choice）** | 胶片/质感本身就是作品声明的基调——写进风格/质感槽位，并注明它属于什么（例：一部 MV 的开场即宣告"16mm 颗粒"） |
| **光学即内容（optics as content）** | 有名字的光学事件，发生在有名字的元素上、有名字的时刻（热浪扭曲让远处轮廓游移；锁定对焦前一次短暂的寻焦） |
| **底版匹配（plate matching）** | 颗粒、模糊与焦点衰减与既有底版匹配，使合成元素不显贴入 |

劣化来自第四种用法：**裸放**的词——不挂在任何东西上，拖在提示词尾部，作为对写实感的一般性哀求。

| 裸放的质量注记 | 模型会拿它做什么 | 应该写成 |
|----------------|------------------|----------|
| `film grain`（尾部、无归属） | 噪点铺满整幅画面；精细细节随之变软 | 作为有归属的观感点名："Super 8MM warm grain, soft vignette"（Super 8MM 暖颗粒、柔暗角）——或作为底版匹配："grain matched to the reference frame"（颗粒与参考帧匹配） |
| `imperfect focus` / `soft focus` / `dreamy` | 全局锐度下降——主体随一切一起变软 | 点名光学事件、元素与时刻："a brief focus hunt on the badge before it locks"（徽章锁定对焦前一次短暂的寻焦） |
| `edges not perfectly sharp` / `slight natural deviation` / `not completely stable` | 有效分辨率下降；画面读起来发糊 | 直接删掉，把不完美放进**拍摄对象**：墙上挂歪的相框、缺口的马克杯、只照亮半张脸的光 |
| `blurry background` | 主体跟着一起糊 | 说明哪个平面保持锐利——见下文 §景深 |
| `hazy` / `foggy`（未量化） | 整帧起雾，主体在内 | 留给真正的空气透视，量化并定位（"haze ramps 20% → 70% behind the ridge" 山脊后雾气 20%→70% 递增），并写明主体自身的锐度 |

`[此处未验证 — UNPROVEN]` —— 本节由公开提示词语料重新推导得出，**尚未在自有素材上做 A/B**。能定案的实验是：同一镜头跑一组双臂 480p 对照——A 组结尾裸放 `film grain, imperfect focus`，B 组用具名观感替换——比较主体的细节保留度。在该实验跑完之前，这只是一种起草偏好，不是规则。

### 景深——两种正向替换，两种意图

"别糊"其实是两种不同的请求，正向替换也因此不同。两种写法都对，但不可互换：

| 作者真正想要的 | 正向写法 | 适用场合 |
|----------------|----------|----------|
| 整幅画面前后全锐 | "sharp focus throughout, deep depth of field"（全程锐利对焦，大景深） | 风景、定场镜头、群戏调度、背景即信息的产品置景 |
| 主体清晰而背景**有意**柔化 | "subject in sharp focus, background falling into soft bokeh"（主体锐利对焦，背景落入柔和焦外） | 人像、对白覆盖、在杂乱布景中隔离一个人 |

第一种回答"整幅画面发糊"；第二种回答"背景的虚化吃掉了我的主体"。裸写 `blurry background` 两个都答不了——它从没说清哪个平面该保持锐利。

## 时序 / 一致性瑕疵（Temporal / Consistency Artifacts）

多发生在视频跨帧、或一个序列跨多次生成时。

| 瑕疵 | 为什么会发生 | 建议的预防措辞 |
|------|-------------|----------------|
| **I2V 输出近乎静止** | 提示词在重新描述静态图，而不是描述该动什么 | 只描述**会变化/会运动**的东西；加明确的镜头运动与大气运动（"dust floats" 尘埃漂浮、"steam rises" 蒸汽上升） |
| **镜头运动不生效** | 镜头写得含糊，而没用确切的预设名 | 用确切的预设名单独成行："Camera: Dolly In"——而不是"the camera slowly moves forward" |
| **互相矛盾的运镜** | 一条提示词里有多个冲突镜头（Dolly In + Dolly Out、Crane Up + Crane Down） | 每个镜头一个主运镜；需要多个就分段生成再衔接 |
| **场景连续性断裂** | 各镜头的角色/环境描述不一致 | 角色描述逐字复制粘贴；用 Cinema Studio 的 Reference Anchor；锁定 Moodboard 风格 |
| **运动预设不可见** | 预设名没写准确，或场景语境撑不起该效果 | 预设名与列表逐字一致："Apply Explosion preset"；指令放在提示词末尾；确保场景语境撑得起效果 |
| **口型不同步** | 音频超过 8 秒、头部运动 token 与口型引擎打架、或非 MP3 格式 | 对白片段剪到 3–8 秒；删掉所有头/脸运动 token；MP3 仅用于 Seedance 2.0（可用时）；镜头锁静态或慢速 Dolly In |
| **背景音乐盖掉对白** | 环境/音乐 token 会招来生成式音频引擎替换上传的音频 | 加时间戳锚定："Audio @Audio1 plays exactly as uploaded from 0s to end"；删掉**所有**环境音/音效/音乐 token |

## 内容过滤 / 安全瑕疵（Content Filter / Safety Artifacts）

这类问题导致生成被拦截，或产出被"消过毒"的输出。

| 瑕疵 | 为什么会发生 | 建议的预防措辞 |
|------|-------------|----------------|
| **生成被拦截（恐怖/黑暗题材）** | 平台安全过滤器被露骨的内容描述触发 | 描述氛围，不描述露骨行为："unsettling"（令人不安）、"something is wrong"（有什么不对）、"dread"（恐惧弥漫）；恐怖效果用运动预设实现 |
| **真人实名被拦截** | 对名人/公众人物姓名的内容过滤 | 用角色描述代替真名；用 Soul Cast 创造原创角色 |
| **品牌 / IP 名被拦截** | 商标/版权过滤 | 按外观描述产品（"a matte black insulated mug, minimal design, no branding" 哑光黑保温杯、极简设计、无品牌标识）——绝不用品牌名 |
| **武器 / 暴力被过滤** | 露骨的武器或伤情语言触发审核 | 写"tension"（张力）、"aftermath"（事后）、"impact"（冲击），不写血腥伤情；VFX 用运动预设实现 |

## Cinema Studio 专属瑕疵（Cinema Studio 2.5）

仅在使用 Cinema Studio 2.5 时适用。

| 瑕疵 | 为什么会发生 | 建议的预防措辞 |
|------|-------------|----------------|
| **提示词被拒（过长）** | Cinema Studio 有 512 字符硬上限；每个 @ Element 芯片额外吃掉约 80–100 个隐藏字符 | 每条提示词最多 2 个 @ 标签；可见文本控制在：2 个标签 ≈250 字符以内、1 个 ≈350、0 个 ≈450 |
| **@ Elements 在动作戏引发换脸** | AI 按 @ 标签逐个重新处理参考数据，与动作编排互相竞争 | 场景 1 用 @ Elements 锁定角色，后续场景改用纯文本描述 |
| **3D 模式几何破洞** | 高斯泼溅（Gaussian splatting）无法重建被完全遮挡的区域 | 3D 模式只用于景深清晰、遮挡极少的图；避免原图的极端角度 |
| **光学栈错位** | 相机/镜头/光圈名被写进了提示词框而不是 UI 下拉框 | 光学栈语言永远不进提示词——只属于 UI 设置 |

## Cinema Studio 3.0 注意事项

> **不支持负面提示词：** Cinema Studio 3.0 的生成引擎不支持负面提示词语法。不要写"no blur""avoid shaky camera"或任何基于否定的约束。改用正向替换：

| 负面写法（3.0 禁用） | 正向替换 |
|----------------------|----------|
| "no shaky camera" | "locked-off static camera, no movement"（锁定机位，无运动） |
| "no blur"——指整幅画面发糊 | "sharp focus throughout, deep depth of field"（全程锐利，大景深） |
| "no blur"——指背景虚化吃了主体 | "subject in sharp focus, background falling into soft bokeh"（主体锐利，背景柔焦外） |
| "don't make it dark" | "bright, evenly lit, overcast daylight"（明亮、布光均匀、阴天日光） |
| "avoid jittery motion" | "smooth, fluid motion, one action per shot"（平滑流畅，每个镜头一个动作） |
| "no extra limbs" | "anatomically correct, all limbs naturally positioned"（解剖正确，肢体位置自然） |
| "don't change the character" | "consistent character appearance, same outfit and features throughout"（角色外观一致，服装与五官全程不变） |

> **3.0 的预防措辞：** 上面各表的所有预防措辞在 3.0 下照常可用——它们本来就是按正向约束写的。关键区别只是：3.0 要求**所有**约束都是正向的。本文件的约束块已经兼容。

## 你写下什么词，就招来什么（The words you write are the words you summon）

一线制作团队把这条规则列为维系制作的四件事之一：**"说你要什么，不要说你避开什么——你写下的词就是你招来的东西，包括'no'里面的那些词。"** 两个实战案例把它讲透。

**色彩战争。** 一部 committed 冷青绿走廊的片子，走廊不断被翻成暖黄色——因为参考图自己泄露了暖色：这里一扇亮着的暖窗、那里一盏暖光灯泡——而模型把它放大了。**否定清单（"no yellow"）毫无用处。** 起作用的是带预算、带失败条件的正向写法：

```
The dominant color must be cold teal-green. Yellow exists only inside
the lamp bulb and a palm-sized halo beneath it. If the frame turns
yellow, the frame is wrong.
```

（主色必须是冷青绿。黄色只存在于灯泡内部及其下方一个巴掌大的光晕里。如果画面变黄了，画面就是错的。）

注意这个句型：它不**禁止**黄色，它给黄色**划拨**了一个位置——一个点名的来源、一个写明的尺寸——然后给了模型一个它能自己套用的检验条件。

**用叙述覆盖参考图。** 当参考图里有一扇裁不掉的红色发光窗，解法不是封禁，而是对影片世界的一句事实陈述：

> *"That window glowing in the reference is switched off in our film."*（参考图里那扇发光的窗，在我们的片子里是关掉的。）

模型接受了。参考图不是合同——你可以告诉它这个镜头里什么不一样，而正向地说出来，胜过禁止参考图里出现的东西。

**与正当封禁的边界。** 两种已被验证的例外：其一，烤进资产的不良属性，只在**资产阶段**封禁一次、下游绝不再提；其二，模型主动扑向的默认项——打斗里的慢动作——值得点名，因为不动的默认值本身就是失败。除这两类之外，一律优先正向写法。

## 本文件使用方法（How to Use This File）

装配提示词时，扫一遍与提示词内容匹配的类别：

1. **以角色为核心的提示词** → 查 面部/身份 + 身体/动作
2. **动作/追逐提示词** → 查 身体/动作 + 时序/一致性
3. **恐怖/黑暗提示词** → 查 内容过滤/安全 + 面部/身份
4. **产品/商业提示词** → 查 质感/灯光
4b. **追求电影感/不完美感/模拟质感的提示词** → 写质感词之前先查 整帧劣化
5. **多镜头序列** → 查 时序/一致性 + 面部/身份
6. **Cinema Studio 提示词** → 查 Cinema Studio 专属 + 所有相关类别
6b. **Cinema Studio 3.0 提示词** → 查 Cinema Studio 3.0 注意事项 + 所有相关类别（只用正向替换）
7. **音频/对白提示词** → 查 时序/一致性（口型同步条目）

把相关预防措辞追加进提示词，或用它们在生成之前抓住并修掉问题。
