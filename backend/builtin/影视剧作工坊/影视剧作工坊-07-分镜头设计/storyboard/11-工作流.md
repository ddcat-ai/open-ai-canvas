# 改编工作流

> **落位说明**（并入影视剧作工坊时添加，正文保留原文）
> 来源：chaoge-storyboard-v1.4.0 · workflow
> 原文文件名：`workflow.txt`
> 链路归位：见第四批提取索引 `INDEX.md`（镜头→光影→物理→分镜连续→提示词→声音BGM→连续性）

本文件用于源文本接收、双制式诊断、统一改编、场次级AI导演接力和长文本续作。

## 一、接收与预检

收到小说或剧本后，先区分三个层级：**原文分批输入、剧情拆集、导演拆段**。三者分别决定上下文负载、剧集结构和下游生成单元，不得互相替代。AI导演接力版在本阶段只组织场次，不预先完成导演拆段。

先统计有效字符数、章节数、现有场/集标记和文本完整性。对当前会话可完整读取的文本按体量门禁人工统计；无法精确统计时标为估算。随包的 Python 统计脚本只供下载包用户本地使用，小影 Agent 不运行脚本或声称获得机检结果。按以下质量门禁处理：

| 有效字符数 | 接收策略 |
|---:|---|
| 3,000 以下 | 可直接进入单集或单段详细改编 |
| 3,000–12,000 | 最佳详细改编区间 |
| 12,000–20,000 | 可处理，详细输出优先在完整戏剧节点处分批 |
| 20,000–50,000 | 先交付全局诊断、故事总纲和情节地图；详细稿按8,000–12,000字分批 |
| 50,000 以上 | 不一次性详细改编；先建立项目总纲，再按每批 2–5 章且不超过 12,000 字推进 |

章节数只作辅助指标。章节过长时仍服从字符门禁；约 50 章或以上即使字数不明，也先执行项目级规划。不要要求用户随意删减关键情节，优先建议分批；正文缺页或文件截断时才要求补齐来源。

逐段扫描当前允许处理的全文，在内部建立五张表：

1. **故事圣经**：题材、时代/世界规则、主角目标、阻力、核心冲突、情感基调、结尾状态。
2. **角色称呼映射**：`真实姓名 = 姓名 / 昵称 / ID / 职称 / 代号`，并记录关系、目标、秘密和当前状态。
3. **情节节点账本**：按因果顺序编号；每个节点写明触发、行动、结果、后续依赖，不把同一事件拆成重复节点。
4. **人物与场景资产账本**：规范人物名、地点、时段、氛围、进入/离开场景的人物。这里只登记人物和场景。
5. **连续性账本**：服装、伤势、持有物、人物位置、已知信息、时间流逝和未兑现伏笔。物件可作为剧情事实记录，但不得建立道具资产表。

长文本不能只分析开头。若附件读取失败、文件截断或正文显著缺页，明确指出缺失范围并停止在可验证边界。

## 二、接收诊断

完成体检后先给制式与拆分建议。用户尚未选模式时，输出以下精简结构；用户可以只回复“按推荐”：

```text
📄 已完成源文本解析
原文体量：约 X 个有效字符 / X 章
输入状态：适合直接处理 / 需要分批处理 / 必须先做项目总纲
题材与规格：...
核心冲突：...

情节目录（N 个节点）
1. ...
2. ...

双制式判断
- 横屏精品剧：16:9，不拆集，预计总时长约 X–X 分钟
- 竖屏系列短剧：9:16，建议 N 集，每集90至120秒
- 推荐方案：……
- 推荐理由：……
- 处理批次：一次完成 / 共 N 批；批次只用于控制输出体量，不等于拆集

请选择制作制式：
A. 横屏中长精品剧，16:9，不拆集
B. 竖屏系列短剧，9:16，每集90至120秒

请选择交付去向：
1. 完整执行分镜版
2. AI导演接力版

可以直接回复“按推荐”。
```

如果用户已说明制作制式或交付去向，复用已知答案，不重复询问。只有会改变交付结构的未知项才询问，最多一次2个短问题。宿主有结构化选择控件时优先使用两个选择问题；没有时使用上述聊天卡。AI导演接力是交付去向，不是第三种制作制式。

### 推荐标准

- 优先推荐横屏中长精品剧：故事依赖完整氛围积累、复杂人物关系、多阶段表演、长动作因果或单一完整结局，压缩成连续短集会明显损伤体验。
- 优先推荐竖屏系列短剧：冲突密度高、节点可独立形成钩子、移动端观看成立，并能在每90至120秒形成局部目标、变化和落点。
- 横屏模式固定不拆集。内容过长时仅按完整幕或场景分批输出，最终仍合并为一个作品。
- 竖屏模式先按105秒中值估算集数，再根据戏剧节点调整；不能只用总秒数机械等分。
- 用户明确指定制式时服从用户，不用推荐结果反复劝说。

## 三、统一改编规则

默认目标是忠实而不是机械照抄，适用于两种制作制式。

### 保留

- 原书名、章节号与章节名；用户另有要求除外。
- 人物姓名、身份、关系、世界设定、关键地点与标志性道具。
- 事件因果、信息揭示顺序、关键台词含义、人物弧光和结尾钩子。

### 可转换

- 心理描写 → 微表情、动作、VO、音效或环境反馈。
- 长叙述 → 可见动作链或蒙太奇。
- 重复信息 → 一次清晰表达；不能删掉后续剧情所依赖的信息。
- 过长对白 → 保留信息与情绪功能后压缩；用户要求原句保留时不得改写。

### 交付结构

```text
《原书名 / 原章节名》

零、故事简介
一、角色称呼映射（仅有多重称呼者）
二、人设篇
三、分场视觉剧本
```

分场视觉剧本采用：

```text
第 1 集
第一场 场次名
【场景】地点｜时段｜内景/外景｜环境状态
【登场人物】角色 A、角色 B
【场次任务】本场要建立、改变或兑现的剧情事实。
【连续性】入场前必须继承的位置、服装、伤势、持有物、时间与光线。
【建议景别与机位】只写能帮助理解空间、表演或信息揭示的场次级建议，不编号、不定秒。
△ 每个可见动作独占一行。
角色 A（情绪/动作）：台词。
角色 B（VO）：独白。
【声音】环境声、动作声与必要音乐判断。
【场尾状态】人物位置、动作结果、信息变化与下场接口。
【钩子】...
```

动作行按因果顺序展开，复杂动作可拆成多个可见节拍，但这些节拍不是预先锁定的镜头。场景、时段、主要目标或空间关系改变时新开场次。横屏不写虚构集号；竖屏保留真实集号。

## 四、创作性改写例外

不再把原创重构作为启动菜单。只有用户明确要求原创化、大幅重写或只保留某个母题时，才在完成事实提取后围绕用户允许保留的内容重构；默认不展示中间事实稿。

### 必须重构

- 人物姓名、个人目标、身份细节、性格缺口和关键选择。
- 主要场景、标志性道具、冲突的具体发生方式。
- 台词措辞、句式、攻防策略与潜台词。
- 至少一层事件因果或反转机制，避免原情节逐场一一对应。

### 可以保留

- 用户明确指定的题材、核心母题、情绪曲线或抽象权力关系。
- 类型片常见结构，如受压—反击—反转，但具体表达必须重新设计。

### 禁止

- 只改姓名、地点、服装、道具和同义词，却保留逐场事件及台词结构。
- 向用户保证“已经规避版权”“绝对原创”或可通过任何平台审核。
- 在用户未要求时公开新旧逐项映射；默认只提供新成品与重构说明。

创作性改写后的标题与章节名必须适配新故事，不能残留原名关键词。完成后仍直接进入当前制式的技术分镜。

## 五、按交付去向生成

制作制式与交付去向确认后，读取 [storyboard-schema.md](storyboard-schema.md)，以情节节点账本为索引组织场次。每个节点至少落到一个场次或场内节拍，重要转折应具备建立、行动、反馈和结果。

用户直接上传小说时，内部自动完成事实提取和镜头化转换，无需先展示另一个模式的中间稿。

根据交付去向自动选择：

- 用户选择AI导演接力版时，输出场次级视觉剧本。每场只列`【登场人物】`和`【场景】`，保留建议景别与机位，不写镜号、单镜秒数、场次精确秒数、镜头总数、焦段表或`@资产`。下游AI导演依据平台和内容决定15秒、30秒或其他可用生成单元。
- 用户选择完整执行分镜版时，完整输出镜号、景别、机位、运镜、时长、表演、声音和衔接，作为当前执行方案。
- 两种交付去向都必须服从已经确认的横屏或竖屏制作制式。

## 六、长文本与续作

- 20,000字以上先锁定故事总纲、全篇情节目录和情节地图，再输出第一批，避免边写边改总结构。
- 横屏模式每批优先包含完整的幕、场或戏剧单元；竖屏模式每批优先包含完整的一集。单个交付单元过长时，只在完整场景末尾停止。
- 详细改编批次优先 8,000–12,000 字，通常 2–5 章；不得超过 20,000 字质量硬上限。
- 批次外维护进度：已覆盖节点、未覆盖节点、人物/场景和连续性当前状态、下批起点。
- 用户说“继续”“接着写”“下一批”时，从进度账本继续，不重新解析已确认内容。
- 用户修改前文时，先更新故事圣经和受影响的后续节点，再继续。

## 七、对话交付与进度记录

默认在对话中交付经核对的 Markdown，不自动保存本地文件。小影没有任意本地文件写入工具；用户要求本地文件时，应如实说明限制并提供对话正文，不得声称已保存或提供虚构路径。

若用户要求写入画布，只在当前工具 schema 支持目标节点且用户明确提出时使用画布工具，并以真实工具响应确认结果。画布内容不是本地文件。长文本分批时在对话中维护已完成节点、未完成范围和下一批起点；上下文中没有的旧批次不声称已读取或已累计。

## 八、交付洁净度

正文按用户要求的 Markdown 结构直接交付。代码块仅用于需要保留的文本示例，不强制把正文包入代码块。代码块外简要说明人工核对范围、未核对项及下一批起点；不得追加本地文件链接或把人工核对描述成脚本验证。AI导演接力版不得在摘要中追加镜头数量。
