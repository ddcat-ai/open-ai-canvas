# 智能需求问诊路由

> **落位说明**（并入影视剧作工坊时添加，正文保留原文）
> 来源：director-production-agent · intake-router
> 原文文件名：`intake-router.txt`
> 链路归位：见第四批提取索引 `INDEX.md`（镜头→光影→物理→分镜连续→提示词→声音BGM→连续性）

这层路由只负责识别用户最终要交付什么。问清后立即进入 `SKILL.md` 中已有的完整项目、快速单镜、复检返修、视觉色卡或文字执行流程，不替代任何专业制作模块。

## 总原则

- **明确需求直接执行**：导演或影片对象明确，且交付物或动作明确时，不问问题。
- **歧义需求才问**：输入只有导演名、影片名，或只说“做视频”“做一个风格”而无法判断交付物时，启动问诊。
- **每次只问一个**会改变执行分支的问题；不要一次发调查表。
- **最多三轮**。第三轮后仍缺非关键资料时，采用专业默认值继续，并在结果中简短标注假设。
- **不得重复询问**对话中已经出现的导演、影片、Seedance 版本、画幅、时长、场景、参考图或最终用途。
- 能调用 `request_user_input` 时优先用它；不可用时使用一条简短的普通文本问题，提供不超过三个互斥选项。
- 用户说“你自己决定”“直接做”“按你专业判断”时，视为授权：选择最能形成可执行交付的分支并继续，不得再阻塞。
- 用户上传生成结果并说“检查、哪里不对、修一下”时，直接进入导演复检/局部返修，不做需求问诊。

## 先判断是否已经明确

同时满足以下两项即为明确：

1. 已知风格对象：导演、影片、混合比例，或用户上传的场景/结果图至少有一种。
2. 已知交付动作：出色卡图片、要色值 Prompt、做单镜、做完整分镜、生成 Seedance 指令、审片返修等至少有一种。

明确示例：

- “诺兰，给我一张导演色卡图片” → 直接执行视觉色卡。
- “岩井俊二《四月物语》，写 10 秒 Seedance 2.0 分镜提示词” → 直接执行快速单镜。
- “王家卫 70% + 阿基·考里斯马基 30%，生成混合色彩方案” → 直接执行文字色彩方案；若用户说“出图”则直接生成色卡。
- 上传视频结果并说“检查导演感为什么不准” → 直接复检并输出局部返修指令。

需要问诊示例：

- “侯孝贤” → 不清楚要色卡、Prompt 还是视频方案。
- “帮我做导演风格” → 不清楚对象与交付物；先问交付物，下一轮再问对象。
- “我要做一个 AI 视频” → 不清楚是单镜还是完整项目。

## 第一层：只问最终交付物

问题模板：

> 这次你最终要我交付哪一种？
> 1. 视觉色卡（PNG 图片 + HEX）
> 2. 文字 Prompt / 执行手册（可复制使用）
> 3. 完整 AIGC 视频方案（导演控制、分镜、Seedance 2.0、复检）

如果上下文已经明确其中一项，跳过本层。

## 第二层：只问所选分支的类型

选择“视觉色卡”时：

> 色卡按哪种依据制作？
> 1. 导演综合色卡
> 2. 指定电影独立色卡
> 3. 从你上传的场景图片取色

选择“文字 Prompt / 执行手册”时：

> 你要哪种可复制文本？
> 1. 色值与调色 Prompt
> 2. 导演风格控制 Prompt（镜头、光线、表演、剪辑、声音）
> 3. 完整导演执行手册

选择“完整 AIGC 视频方案”时：

> 这次按哪种制作深度？
> 1. 快速单镜 Prompt
> 2. 完整分镜项目包
> 3. 已生成视频的复检与返修

如果用户原话已包含“综合/某电影/上传图取色”“色值/完整手册”“单镜/完整分镜/返修”，跳过对应问题。

## 第三层：只补一个真正阻塞执行的事实

只允许询问会明显改变成品的一个事实：

- 影片分支：同一导演存在视觉差异明显的创作时期，而用户选择了电影独立色卡或精准影片风格。
- 画幅：画面布局依赖竖屏/横屏，且上下文没有平台或比例。
- 时长：动作节拍和镜头数量依赖时长，且用户要视频 Prompt 或完整项目。

默认值：抖音视频默认 `9:16`；单镜默认 `8秒`；完整项目未给总时长时先按 `30秒`；导演综合色卡不强迫用户指定影片。采用默认值后必须继续执行。

## 路由结果

- 视觉色卡 → `SKILL.md` 的“视觉色卡模式”。
- 色值 Prompt、导演控制 Prompt、执行手册 → “文字执行模式”或“导演风格控制器 V2”。
- 快速单镜 → AIGC 导演 Agent 的快速单镜分支。
- 完整项目 → AIGC 导演 Agent 模式，输出固定 12 章。
- 复检返修 → 导演复检/局部返修流程。

问诊结束后不要复述整套问卷，直接交付用户选择的结果。
