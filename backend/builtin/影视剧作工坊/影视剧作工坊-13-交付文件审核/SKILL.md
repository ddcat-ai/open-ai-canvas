# 交付文件审核（模块 13）

> 主链定位：PV 校验 + TD 放行 + T2V/I2V 交付规格 + 负面约束总库。

## 做什么

本模块是 13 级主链的**最后一道闸门**，也是整条链的**质量闭环**。它做三件事：

1. **放行** —— 交付文件能不能出（PV 校验 + TD 放行）。
2. **定规格** —— 交付按 T2V 还是 I2V 出、字段与形态怎么钉死。
3. **兜底与复盘** —— 负面约束总库集中取用；生成之后失败时，走失败诊断层定位、裁定、记录。

**本模块无 `engine/`**：四本导演学专著不覆盖交付审核与失败诊断，本模块的知识源是数据层而非方法论引擎。

## 失败诊断闭环（review/）

### 第一步永远是分层，不是修复

**总纲：诊断先于修复。绝不在诊断之前原样重发**——同样的文本会绊响同一个分类器、踩中同一处渲染边界；重发不是诊断。

| 失败时机 | 含义 | 该做什么 |
|----------|------|----------|
| **< 10 秒**（即时） | 内容过滤器拒稿——提示词根本没到渲染层 | 按语气重写 + 移除风险词。**绝不绝不绝不原样重新生成** |
| **> 30 秒**（延迟） | 基础设施、超时或复杂度——提示词过了过滤器但渲染失败 | 简化动作密度、缩短时长、再试 |

循环出现的即时失败是过滤器问题，**绝不是渲染能力问题**——在重写完成之前，先拦住重新生成的手。

### 先分岔——系统性还是随机性

在约 1.5% 的视频通过率门槛下，**大多数失败是方差，不是提示词坏了**。

- 失败**都是同一种**失败 → **系统性**：提示词错了，走单变量迭代。
- 失败方式**五花八门、偶尔接近命中** → **随机性**：锁定提示词，批量开火，然后淘汰。

**防线**：一个保留者、其余全部记账（保留 + 真实的淘汰原因），分母保持诚实。整批都过不了硬性闸门 → 失败终究是系统性的，停止收割，回去迭代。

### 镜头裁定——交付镜头的五种裁定

修复处理的是彻底失败；大多数真实交付落在中间地带**部分可用**。任何东西重新触发之前，每条交付镜头必须拿到五种裁定之一：

| 裁定 | 适用情形 | 下一步 |
|------|----------|--------|
| **保留（Keep）** | 镜头使命已交付，无致命伤 | 锁定、记录、继续 |
| **后期修复** | 瑕疵属于剪辑师的领域（调色、文字、混音、修剪、首尾帧不稳） | 绝不为几分钟能剪好的事烧掉好几条 |
| **编辑而非重生成** | 构图与时机都对，恰好只有一层错了 | 只修出错的那一层——"当编辑而非当重跑器" |
| **重掷（Re-roll）** | 提示词是对的，只是采样运气不好 | 同一提示词原样再来 |
| **重写（Rewrite）** | **同一瑕疵出现在两条镜头上** | 是系统问题不是运气——先诊断，再改提示词 |

**重写绊线是双向的**：同一瑕疵出现两次 → 停止往同一堵墙上重掷；每次都是*不同*瑕疵 → 失手是随机的，属于批量抽卡的领地而不是重写。

**尝试预算——第一条镜头开拍前声明**：一个条数预算数字 + 一条写下来的"够好"标准（主要目标已交付、次要瑕疵可后期）。不写下来，这个标准会悄悄变成"完美"，而任何预算都扛不住"完美"。预算过半而同一瑕疵毫无进展时，停止迭代并改变策略。

**拍摄日志**：每条镜头一行——改了什么、结果如何。两行共享同一瑕疵，重写绊线就可审计。

### 交付前自我修复清单

发送前把对策整合成一遍预防（每条提示词花 60–90 秒，在烧额度之前抓住大多数可预防的失败）：

- [ ] 帧率写在提示词正文中（不只元数据头）？
- [ ] 身体/感性语域 token 已清理？
- [ ] 首次出现的元素已标记"不在源关键帧中"？
- [ ] 相邻物体不变量已点名（"X 保持吸附""Y 不移动"）？
- [ ] 运动把整条片段花在一个方向上？短动作串成 2–3 个同向节拍？运镜有具名终点？
- [ ] 对白窗口被完整写出？短台词扩长或静默写进脚本？每张可见的脸都带嘴部状态？
- [ ] 每镜头一个主导运镜？复合运镜拆成先后相位或分开的剪切？
- [ ] 几何用空间布局块锁定？
- [ ] 为最终条次预留了逐帧审查时间？

完整清单、诊断流程图与视觉锚定诊断流程见 `review/13-失败诊断.md`。

## 交付规格与放行

### T2V / I2V 交付规格 —— 按模式判合规

交付按哪种模式出，决定这份文件**该有什么、不该有什么**。**12 负责按顺序拼装（`SKILL.md` 的「按模式的拼装顺序」节），本模块负责判它合不合格**——逐条判据见 `review/14-交付规格与合规判据.md`。

| 模式 | 交付文件的核心差异 | 最高优先级硬项 |
|------|-------------------|----------------|
| **文生视频** | 九层写全；**唯一可指定画幅**的模式 | 八要素齐备 + 画幅已显式指定 |
| **首帧** | **主体外观与环境两层整段删除**，只写变化 | **未复述输入图中已有内容** |
| **首尾帧** | **只写中段**；外加两张图提示词（由 04 出） | **两图同一画幅比例** + **两图锚定段逐字一致** |

**声音层档位（三模式通用）**：交付文件头部必须声明 **【声音层】全量 / 去配乐**。

- **全量（默认）**：⑧对白 + ⑨背景音 + ⑩BGM 三轨齐全。
- **去配乐**：⑩ 必须是 **`NO BGM`**（显式抑制），且**不得残留任何音乐类 token**（除 `NO BGM` 本身）。
- ⚠️ **去配乐 ≠ 省略 ⑩**：Seedance 2.0 自带音效/配乐，不声明 ≠ 不生成。判据 **G7（档位与内容匹配）/ G8（档位已声明）/ G9（零音乐 token）**。

**放行规则**：全部 PASS 才放行；**任一 FAIL 即阻断**，并按判据编号退回对应模块（12 拼装 / 04 首尾帧两图 / 08 运镜 / 09 声音与档位）——**本模块不改写内容**。

完整判据（G1–G7 / T1–T5 / F1–F6 / L1–L7）与退回路由见 `review/14-交付规格与合规判据.md`。
