## I — 方法论骨架 (Interpretation)

**行为 = 动机 × 能力 × 触发**，三者必须同时在场。注意是乘法：
任意一项为零，行为即为零。这就是它作为"断点定位器"的价值——
当预期行为没有发生，不要笼统归因为"用户不想要"，而是依次检查：

- **T（触发）**：他在那个时刻被提示了吗？提示落在他有可能行动的时刻吗？
- **A（能力）**：他做得到吗？门槛在时间、金钱、体力、脑力、社会偏差、非常规性哪一项？
- **M（动机）**：他此刻想不想？

本书在此之上加了一条**排序主张**，这是它真正反直觉的部分：
**优先提升能力（简化），而不是拉高动机。** 三条理由：

1. 动机是用户的内部状态，波动大，设计者控制不了；能力是产品的外部属性，随时可交付。
2. 简化的效果是永久的；激励的效果随刺激撤除而消失（现金奖励尤其明显）。
3. 提升动机通常需要持续付费（补贴、优惠、投放），边际成本不递减；
   删掉一步则一次投入长期生效。

实践中还要加一层：**触发的时机往往比触发的存在更关键**。
一条发在用户既没动机也没能力时刻的提醒，等于没发，
而且会消耗用户的通知容忍度——这是唯一"用坏了就再也拿不回来"的资源。

所以分诊顺序是：**触发时机 → 能力 → 动机**。多数团队的顺序恰好相反。

## A1 — 书中的应用 (Past Application)

### 案例 1: 一键登录 / 用 Facebook 账号登录
- **问题**: 注册环节大量流失，用户不是不想用，而是卡在填表上。
- **方法论的使用**: 不去强化"注册有什么好处"（动机），而是砍掉记密码、填资料（脑力+时间）。
- **结论**: 缺口在 A 而非 M。
- **结果**: 一键登录成为行业标配，注册转化显著提升。

### 案例 2: Twitter 的 140 字限制
- **问题**: 让普通人发布公开内容，心理与时间成本都很高。
- **方法论的使用**: 用字数上限同时降低"时间"和"脑力"两项门槛——
  140 字意味着不需要构思结构、不需要修改，随手可发。
- **结论**: 约束反而提升能力（在福格的意义上）。
- **结果**: 发布行为的门槛被压到极低，UGC 供给量爆发。

### 案例 3: YouVersion 的音频版《圣经》
- **问题**: 用户想读经，但通勤、做家务时腾不出眼睛和手。
- **方法论的使用**: 增加音频形式，降低体力与脑力门槛，
  并把推送时机对准用户历史活跃时段（T 的时机优化）。
- **结论**: 同一批用户的完成率提升，来自 A 与 T 的改造，而非更强的信仰动机。
- **结果**: 日均阅读（收听）时长显著高于同类应用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **某个关键转化率低**：注册、下单、上传、邀请、续费——数据不好但原因不明。
2. **团队的第一反应是"加激励"**：讨论已经滑向发优惠券、做活动、写更煽情的文案。
3. **内部推行新流程/新系统无人使用**：不是产品问题，是组织内的行为设计问题。
4. **个人习惯建立失败**：想跑步/写作/背单词但做不到，需要拆解自己缺哪一项。
5. **需要判断资源该投向哪里**：手上只有一次改版机会，要决定改流程还是做活动。

### 语言信号 (用户的话里出现这些就应激活)

- "用户为什么不点 / 为什么不提交"
- "转化率上不去，是不是该发点优惠"
- "怎么提高用户的意愿 / 积极性"
- "推了新系统但没人用"
- "我知道我该做但就是做不到"
- "why don't users convert" / "should we offer incentives" / "Fogg behavior model"

### 与相邻 skill 的区分

- 与 `ability-simplification` 的区别：本 skill 是**分诊**（判断缺 M/A/T 哪一项），
  那个是分诊结论为"缺 A"之后的**执行工具**（六元素排查 + 三步删减）。
  用户若已明确知道是门槛问题，可跳过本 skill 直接用那个。
- 与 `external-trigger-design` 的区别：本 skill 只判断"触发是否存在/时机是否对"，
  那个负责触发类型的选择、授权与投放设计。
- 与 `internal-trigger-mining` 的区别：那个挖的是驱动行为的**情绪根源**（M 的来源），
  本 skill 处理的是行为发生与否的**结构性缺口**。
- 与 `hook-model-loop` 的区别：本 skill 只管第二环，那个管四环全局。

## E — 可执行步骤 (Execution)

1. **把"行为"写成一个具体动作**
   - 格式："某个具体的人，在某个具体时刻，做某个可观测的动作。"
   - 反例："用户要更活跃"（不是动作）。正例："新用户在注册后 3 分钟内创建第一个项目"。
   - 完成标准：动作可埋点、可计数、有明确时刻。

2. **查 T：触发是否存在，且时机是否对**
   - ① 在该时刻，用户收到提示了吗？（有/无）
   - ② 提示的时刻，用户**有可能**行动吗？（在开会/在开车/在睡觉 = 不可能）
   - ③ 这个时刻，用户的相关情绪在发作吗？（对齐内部触发）
   - 完成标准：三问都有答案。
   - 判停条件：若①为"无"或②为"不可能" → 断点在 T，转 `external-trigger-design`，
     **不要**继续往下查（此时 A 和 M 的数据都不可信）。

3. **查 A：能力六元素中最短的那一项**
   - 逐条问：时间 / 金钱 / 体力 / 脑力 / 社会偏差 / 非常规性。
   - 只找**最短板**一项——能力由最短板决定，均匀优化是浪费。
   - 完成标准：指出一项，并说明它在这个场景里具体表现为什么。
   - 判停条件：若短板明显 → 断点在 A，转 `ability-simplification`。

4. **查 M：动机是否真的不足**
   - 只有在 T 与 A 都成立时，才允许判定"动机不足"。
   - 检查方式：那些**已经完成**该行为的用户，与未完成者在情境上有何差异？
     若差异主要在情境（时机/设备/场合）而非人群，说明仍是 T/A 问题伪装成 M 问题。
   - 完成标准：给出"确实是动机问题"的证据，或推翻它。

5. **若确为动机问题，先找情绪而不是发钱**
   - 转 `internal-trigger-mining` 定位负面情绪根源，让产品去承接这个情绪；
   - 只有在无法承接时才考虑外部激励，并**必须**提醒现金激励的挤出效应（见 ce01）。
   - 完成标准：给出的方案不以"发优惠券/加积分"作为第一选项。

6. **输出改造顺序**
   - 格式：断点 → 改造动作 → 预期指标变化 → 验证方式。
   - 强制包含一句资源建议：本次改版应把主要资源投向 ___（T/A/M 三选一）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **行为已经发生但用户不回来**——那是留存与闭环问题，用 `hook-model-loop`；
  B=MAT 只解释单次行为的发生与否。
- **用户根本不需要这个行为**——三因齐备也不会有价值，
  先回到 `habit-zone-screening` 或核心价值验证。
- **群体/组织层面的结构问题**（利益冲突、考核错位、权责不清）——
  B=MAT 是个体行为模型，把制度问题当成体验问题会误导。
- **强制性行为**（法律要求、合规打卡）——动机由外部制度提供，模型的解释力下降。

### 作者在书中警告的失败模式

- **ce04 — 强化动机而不提升能力**：数据不好时第一反应是加激励、发红包、做营销煽动，
  结果成本上升、转化不变。警告信号：增长手段全是"发奖励/搞活动"；
  关键路径超过 3 步却无人质疑。
- **ce18 — 触发时机与情绪脱节**：在用户不可能行动的时刻发送提醒，
  不仅无效，还会导致通知权限被永久关闭。
- **ce01 — 用现金买行为**：外部现金奖励会挤出内在动机，停发即断崖。
- **ce19 — 用积分/徽章冒充动机设计**：可预期的奖励不产生渴望。

### 作者的盲点 / 时代局限

- 福格模型是**单次行为**模型，对"行为已经发生但态度未改变"无解释力；
  态度改变需配合 `commitment-escalation`。
- 三要素并非严格可分：提高能力常常同时提高动机（省事本身让人更愿意做），
  分诊时不要陷入归类洁癖，只要能定位到可改造的动作即可。
- 书中未处理"动机过高反而伤害体验"的情形（如过度激励导致刷量、作弊）。
- 本书对 M 的分解（三组核心动机）较浅，若需深入动机分析，
  应转向专门的动机/说服类方法（本书该部分因缺乏独特性已在阶段 1.5 淘汰）。

### 容易混淆的邻近方法论

- **COM-B 模型（Michie）**：结构相近（Capability/Opportunity/Motivation），
  但它是加法式框架且更偏公共卫生；B=MAT 的乘法关系与"能力优先"排序是本书取用的关键。
- **漏斗分析**：告诉你在哪一步流失，不告诉你为什么；B=MAT 提供归因维度。
  两者应配合：漏斗定位步骤 → B=MAT 定位原因。
- **JTBD**：解释"用户雇佣产品做什么"，接近 M 的来源，不处理 A 与 T。
- **助推（Nudge）**：偏向环境设计与默认选项，可视为 A/T 的一类手法，
  但缺少本模型的分诊排序。
