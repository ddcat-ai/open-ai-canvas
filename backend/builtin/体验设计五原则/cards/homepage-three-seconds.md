## I — 方法论骨架 (Interpretation)

主页之所以是全站最难做的一页，不是因为设计难，而是因为它被要求同时干六件互相打架的事：

① 说清我们是谁、要干什么（身份与使命）；② 展示网站的层次结构（有哪些东西）；
③ 提供搜索；④ 推销（转化、活动、卖点）；⑤ 放时效内容（新闻、动态）；
⑥ 给老用户快捷方式。

六件事都要占位，空间只有一屏。所以主页**注定是妥协**——这一点必须先被承认，
否则每次讨论都会退化成"都很重要，都得放"。

Krug 的处理办法是给出一条**不可让步的底线**：无论怎么妥协，一个第一次来的人必须在
三五秒内答出三个问题——

- **这是什么？**（Site ID / 身份）
- **我能在这里做什么？**（提供什么价值、能完成什么任务）
- **为什么我应该在这，而不是别处？**（差异、可信度）

三问答不出，后面五件事做得再漂亮都是浪费——因为访客已经走了。这就是"大爆炸理论"：
第一次接触形成的印象决定了之后一切关系的形态，而且它不可逆。

三问的常见修法是加一句**口号（tagline）** 和一块明确的"我们是干什么的"欢迎区，
而不是继续堆功能入口。

还有一个必须处理的**根因**：主页失焦往往不是设计能力问题，是**组织政治**。
每个部门都想在主页上有个位置，最后主页被瓜分到失去焦点——Krug 借用经济学的
"公地悲剧"来命名它。识别出这一点很重要，因为如果根因是政治，再画十版设计稿也没用，
必须先建立取舍原则和决策机制。

因此本 skill 的输出必须包含一项通常被回避的东西：**这张主页明确放弃了什么**。
取舍不写下来，就等于没做。

## A1 — 书中的应用 (Past Application)

### 案例 1: 三秒三问
- **问题**：主页承载的目标太多，无法判断哪些可以砍。
- **方法论的使用**：Krug 不试图给六件事排序，而是抽出一条与其他五件正交的底线——
  新访客能否在几秒内答出三问。
- **结论**：三问是必要条件；其余诉求都是可谈判的。
- **结果**：讨论从"你的模块重要还是我的重要"变成"这个模块是否妨碍三问"，
  争论对象从利益变成了标准。

### 案例 2: 公地悲剧
- **问题**：主页越改越满，每一轮评审都有新部门要求加内容。
- **方法论的使用**：把现象命名为"公地悲剧"——公共资源上每个人的局部理性导致集体损失。
- **结论**：这是资源分配问题，不是审美问题。
- **结果**：解法从"重新设计"转向"先建立主页准入规则"。

### 案例 3: 大爆炸理论
- **问题**：团队认为首页印象不好可以在后续页面弥补。
- **方法论的使用**：作者用宇宙大爆炸类比——第一次接触时形成的东西决定了此后一切关系的形态。
- **结论**：首屏印象基本不可逆。
- **结果**：把首页资源投入的优先级抬到最高。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 主页/首页改版，各方诉求塞不下，不知道砍谁。
2. 新访客留存差、跳出高，怀疑"人家没看懂我们是干嘛的"。
3. 每个部门/业务线都要求在首屏有入口。
4. 要写产品官网首屏、slogan、一句话介绍。
5. 写开源项目 README 的开头，或个人主页/简介/名片的第一屏。
6. 公众号首屏、小店首页、活动落地页第一屏排布。
7. 做路演/提案的第一页，或自我介绍的头三句。

### 语言信号（用户的话里出现这些就应激活）

- "主页放什么 / 首页太满 / 首屏怎么排 / 一屏放不下"
- "每个部门都要个位置 / 大家都说自己重要"
- "别人看不懂我们是干嘛的 / 新用户不知道这是什么"
- "slogan 怎么写 / 一句话介绍 / README 开头写什么"
- "homepage / above the fold / value proposition / hero section / landing page"

### 与相邻 skill 的区分

- 与 `positioning-*` 系列（`positioning-find-the-hole`、`positioning-oversimplified-message` 等）
  的区别：那些解决**定位本身是什么**（在心智里占哪个位置、用哪个词）；
  本 skill 假设定位已定，解决**在一屏空间里如何把它传达出去，以及其他诉求怎么排队**。
  如果用户连"我们到底是什么"都没想清楚 → 先转 positioning 系列。
- 与 `billboard-scan-design` 的区别：那个给通用的版面法则；本 skill 专门处理首屏特有的
  "多目标冲突 + 三问底线 + 组织政治"。两者常配合：先用本 skill 定取舍，再用它排版。
- 与 `trunk-test-navigation` 的区别：那个测的是**深层页面**的方位感，且明确排除首页；
  本 skill 只管首页。两者是互补的一对。
- 与 `omit-needless-words` 的区别：那个删文字；本 skill 删**诉求**（整个模块、整块内容）。

## E — 可执行步骤 (Execution)

1. **清点当前首屏承载的全部诉求，并标注提出方**
   - 列表：模块 / 目的 / 谁要的 / 支撑的业务指标。
   - 完成标准：每一项都有明确归属；无法说出归属的项标为"历史遗留"，默认候删。

2. **做三秒测试**
   - 找一个没见过这个产品的人（或明确以"隔壁邻居"视角模拟），看 3–5 秒，然后问：
     这是什么？你能在这做什么？为什么用它而不是别的？
   - 完成标准：三个答案被逐字记录，并与期望答案比对。

3. **判定底线是否达标**
   - 三问全对 → 进入步骤 4。
   - 有任何一问答不出 → **优先修三问**：补口号（tagline）、补一句"我们是做什么的"、
     把身份区从视觉噪声里拎出来。判停条件：三问未过之前，不讨论其他模块的增减。

4. **对其余诉求排序并显式取舍**
   - 按"对新访客的价值 × 使用频率 ÷ 占用空间"排序。
   - 逐项判断：妨碍三问吗？（妨碍 → 移出首屏）
   - 完成标准：形成保留/下移/删除三类清单。

5. **识别公地悲剧型占位**
   - 标记那些"因为某部门要求而存在、对新访客无价值"的模块。
   - 若这类模块 ≥3 个 → 判定根因是组织政治，输出建议：先建立主页准入规则
     （谁能上、凭什么上、多久复审一次），再谈设计。
   - 完成标准：给出根因判定（设计问题 / 政治问题 / 两者兼有）。

6. **写下"本首屏明确放弃的目标"**
   - 至少列出 2 条被放弃的诉求及其去处（移到二级页 / 移到底部 / 彻底删除）。
   - 完成标准：这一条非空。取舍不写下来等于没做取舍。

7. **输出**
   - ① 三问达标情况与修法；② 保留/下移/删除清单；③ 放弃声明；
     ④ 根因判定与（如需）准入规则草案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **深层页面与流程页**：详情页、结算页、后台工作台不适用三问底线，
  它们的判据是任务完成而非身份传达。
- **定位尚未确定时**：如果连"我们是什么、和谁不同"都没有答案，本 skill 只会把
  混乱排得更整齐。先转 positioning 系列。
- **老用户占绝大多数的产品**（内部系统、工具型 App 的日常入口）：这类首页的首要
  目标是快捷入口而非身份传达，三问的权重应大幅下调。
- **纯视觉排版问题**：转 `billboard-scan-design`。

### 作者在书中警告的失败模式

- **认为首页印象可以在后续页面弥补**（大爆炸理论的反面）。
- **用增加模块来解决"没说清楚"**。三问答不出时，正确动作是加一句口号并让身份区更突出，
  而不是再塞两个入口。
- **把政治问题当设计问题处理**：公地悲剧型主页反复重设计只会反复失守。

### 作者的盲点 / 时代局限

- 第 3 版正文写于 2013 年，默认主体是**桌面网站的主页**。今天大量产品的真实"第一接触面"
  已经不是主页——而是搜索结果落地页、分享卡片、小程序入口、应用商店详情页、
  短视频里的一段介绍。**三问原则可迁移，但"主页"这个载体的判断需在当代语境下重新检验。**
- 未覆盖**算法分发**下"没有首页"的产品形态（信息流应用打开即内容）。
- 作者未讨论如何**量化**首屏取舍（今天可用 A/B 测试与分层埋点直接验证），
  他对定量方法整体上是回避态度。
- 只诊断不生成：本 skill 不产出 slogan 文案本身。

### 容易混淆的邻近方法论

- **价值主张画布（Value Proposition Canvas）**：那是**推导**价值主张的工具；
  本 skill 假设价值主张已有，处理它在一屏里的表达与排队。
- **AIDA / 落地页转化框架**：那些以转化为目标函数，会主张更强的推销密度；
  本 skill 以"新访客理解"为目标函数。两者存在真实张力，需按业务阶段选择。
