## I — 方法论骨架 (Interpretation)

上瘾模型是**价值中立的技术**：同样的机制既能帮人每天读经文、记账、健身，
也能让人整夜刷不该刷的东西。差别不在技术，在使用者的意图。

作者把伦理判断压缩成两个具体、可自答的问题，形成四象限：

| | **我自己会用**（自用） | **我自己不用**（不自用） |
|---|---|---|
| **能显著改善用户生活** | **健康习惯推广者** ✅ 最佳象限 | **兜售商** ⚠️ 成功率最低 |
| **不能改善用户生活** | **娱乐用户者** ◐ 可接受但短命 | **经销商** ❌ 最危险 |

**四象限的解读：**

- **健康习惯推广者**：自己是重度用户，且真心认为产品让人变好。
  信息优势与道德立场重合，纠错信号最灵敏。
- **兜售商**：出发点良善但自己不用。
  作者认为这是**成功率最低**的象限——不是因为不道德，
  而是因为缺乏共鸣，容易误判需求，且没有自我纠错信号。
- **娱乐用户者**：自己也玩，但不假装它能改善生活（游戏、娱乐内容）。
  诚实且可接受，但作品生命周期短，需靠持续创新
  （对应 `variability-sustainability` 的工作室模式）。
- **经销商**：自己不用，也不认为有益，纯粹榨取。
  机制越强，伤害越大。

**关键立论（本单元最独特之处）：**
第一个问题"我自己会用吗"**同时是伦理判据和信息优势判据**——
道德与效能在这里被合并论证。这不是常见的伦理框架结构。

**元原则：** 判据是"我**应该**做吗"，不是"我**能够**做吗"。
技术可行性从来不是理由。

**保护义务：** 任何能养成习惯的产品都会产生一小部分无法自控的重度用户。
设计者有义务识别他们、提供退出与节制机制，而不是只看平均值。

## A1 — 书中的应用 (Past Application)

### 案例 1: 作者自己的减肥产品自省
- **问题**: 如何判断自己在做的是好产品还是套路。
- **方法论的使用**: 作者自问"我自己会用这个产品吗"，
  并以此作为区分健康习惯推广者与兜售商的第一判据。
- **结论**: 如果答案是否定的，多半是在做一个自己都不相信的东西。
- **结果**: 形成书末的自省式伦理检查法。

### 案例 2: 拉斯维加斯老虎机
- **问题**: 同样的多变酬赏机制，为什么在这里是有害的。
- **方法论的使用**: 老虎机是多变酬赏的极端形态，机制威力最大，
  但落在"不改善生活 + 设计者不玩"的经销商象限。
- **结论**: 机制的强度与伦理无关；强机制放在错误象限就是伤害放大器。
- **结果**: 成为全书讨论道德操控的引子。

### 案例 3: 兜售商的共鸣缺失
- **问题**: 为什么"我们是为用户好"的团队反而常常失败。
- **方法论的使用**: 兜售商（改善 × 不自用）依赖二手调研做核心决策，
  团队里没有重度用户，出现"用户不懂，我们懂"的说法。
- **结论**: 缺乏共鸣不仅是道德问题，更直接导致产品判断失准。
- **结果**: 被作者列为成功率最低的象限。

### 案例 4: 重度用户的尾部风险
- **问题**: 平均数据健康，是否就意味着产品无害。
- **方法论的使用**: 作者指出任何习惯型产品都会产生一小部分无法自控的用户，
  长尾分布意味着同样的设计对多数人是便利、对少数人是失控。
- **结论**: 设计者有告知与保护义务，需提供退出与节制机制。
- **结果**: 成为产品伦理讨论中"尾部责任"的早期表述。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **团队在讨论"这样做是不是有点过分"**——出现了道德不适感但说不清。
2. **要给某个上瘾机制做决策**（无限滚动、自动播放、连胜奖励、抽卡）。
3. **KPI 是时长/频次**，有人担心方向不对。
4. **面向脆弱人群的产品**（未成年人、老年人、金融杠杆、健康焦虑）。
5. **被指责为暗黑模式**，需要一个能对内对外说清楚的判据。
6. **立项评审**——在设计开始前而非上线后做伦理判断。
7. **要不要做防沉迷/时长提醒**，需要理由支撑投入。
8. **团队自己不是目标用户**，需要判断这是不是风险。

### 语言信号 (用户的话里出现这些就应激活)

- "这样做是不是不太好 / 会不会太套路 / 有点不厚道"
- "我们是不是在做暗黑模式"
- "老板要求把时长再拉上去"
- "要不要加防沉迷 / 使用时长提醒"
- "这个功能对用户到底有没有好处"
- "product ethics" / "dark pattern" / "manipulation matrix" / "is this manipulative"

### 与相邻 skill 的区分

- 与 `autonomy-reactance` 的区别：那个是**策略层面**的有效性问题
  （怎么做才不引发抵触），本 skill 是**价值层面**的应不应该问题。
  若讨论是"用户不接受，怎么让他接受" → 那个；
  若讨论是"我们该不该这么做" → 本 skill。
- 与 `habit-as-business-asset` 的区别：那个论证习惯的**商业价值**（该不该投入资源），
  本 skill 判断习惯设计的**正当性**。两者常在同一场立项会上先后出现。
- 与 `variable-reward-design` / `investment-design` 的关系：
  本 skill 是它们的**强制后置检查**。
  凡是设计了强多变酬赏或高沉淀投入的方案，都应过一遍本 skill。
- 与 `habit-opportunity-scan` 的关系：那个的"第 0 号入口——观察自身行为"
  与本 skill 的"我自己会用吗"同源，可联用：
  从自身真实需求出发找机会，天然落在健康习惯推广者象限。

## E — 可执行步骤 (Execution)

1. **把讨论对象具体化**
   - 不要评判"我们公司"，评判**一个具体的设计决策或一个具体的产品**。
   - 完成标准：写出一句"我们打算让用户【做什么】，通过【什么机制】"。

2. **回答问题一：它能显著改善用户的生活吗**
   - 判据不是"用户喜欢"，而是"用户**事后**是否认为这段时间花得值"。
   - 证据来源：用户自述获益、行为的长期结果、卸载/退出时的理由。
   - 完成标准：给出"是/否/存疑"及依据。
   - 注意：说不清 = 否。"我们相信它有价值"不构成依据。

3. **回答问题二：我（团队）自己会用它吗**
   - 判据是**真实使用**，不是"我愿意试试"。
   - 检查：团队里有几个人是重度用户？他们用的是给用户的版本还是内部版本？
   - 完成标准：给出团队自用率的事实描述。
   - 注意：若目标用户与团队差异极大（老年人、儿童、特殊病患），
     则需引入**能代表用户的人**进入决策圈，这是对"自用"的等价替代。

4. **定位象限并读出结论**
   - 健康习惯推广者 → 继续，但仍需做步骤 6 的尾部保护。
   - 兜售商 → **首要任务是补共鸣**：引入真实重度用户共研，
     或让团队真正使用一段时间。在此之前不要扩大投入。
   - 娱乐用户者 → 可接受，但要诚实（不要对外宣称"改善生活"），
     并预期生命周期有限（转 `variability-sustainability`）。
   - 经销商 → **停止**。这不是优化问题，是方向问题。
   - 完成标准：明确写出象限与对应结论。

5. **做机制强度与人群脆弱度的交叉检查**
   - 机制越强（强多变性、强沉淀、无限滚动、社交压力），容错越低。
   - 人群越脆弱（未成年、认知障碍、经济困难、健康焦虑），门槛越高。
   - 完成标准：若"强机制 × 脆弱人群"同时成立 → 即使落在良性象限，
     也必须加装保护（步骤 6），不得跳过。

6. **履行保护义务（尾部责任）**
   - 识别：找出使用强度分布最尾部的那 1%，看看他们的真实状态。
   - 干预：使用时长提示、冷静期、频次上限、一键关闭、账号注销与数据导出。
   - 上报：客服收到"停不下来"类反馈时必须有上报路径，不能沉在工单里。
   - 完成标准：至少落地 1 项可验证的保护机制，并指定负责人。

7. **换掉错误的北极星指标**
   - 若核心指标只有时长/频次/付费，追加至少一个**用户获益指标**
     （自述获益、任务完成、目标达成、事后满意度）。
   - 完成标准：写出新增指标及采集方式。
   - 判停条件：若组织拒绝引入任何获益指标 → 这是经销商象限的组织信号，
     应向上升级而非默默执行。

8. **留下书面记录**
   - 把象限判定、依据、保护措施写进决策文档。
   - 目的：让后来者知道这个决策是被审视过的，也便于事后复盘。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **代替法务合规审查**——未成年人保护、隐私法规、广告法有明确的法律要求，
  四象限是价值判断工具，不能替代专业合规意见。
- **用来给已定方案背书**——如果结论已经定了，本 skill 只会变成"伦理洗白"，
  这是它最常见的滥用方式。
- **对个人做道德审判**——四象限评的是产品与决策，不是评人。
  把它用来指责同事会让团队再也不敢讨论伦理。
- **纯执行层问题**——用户抵触（`autonomy-reactance`）、
  数据不好（`habit-testing`）都不是伦理问题，不要混淆。
- **完全不涉及习惯/成瘾机制的产品决策**——本 skill 的判据是围绕
  "习惯设计的正当性"构建的，用于一般商业决策会过于粗糙。

### 作者在书中警告的失败模式

- **ce13 — 兜售商陷阱**：自己不用却认为对用户有益。
  警告信号：团队无人是重度用户；依赖二手调研做核心决策；
  出现"用户不懂，我们懂"的说法。
- **ce14 — 经销商陷阱**：明知无益仍靠上瘾赚钱。
  警告信号：核心指标只有时长/付费，无用户获益指标；
  内部避免讨论"这对用户好吗"；有意隐藏退出/关闭路径。
- **ce15 — 忽视重度上瘾用户的伤害**：只看均值，忽略尾部失控者。
  警告信号：无使用时长提醒或冷静期设计；
  客服收到"停不下来"的反馈却不上报。
- **ce21 — 用启发法制造虚假稀缺**：短期转化提升，长期信任崩塌。
  警告信号：库存数字永远是"仅剩 X 件"；倒计时结束后自动重置。

### 作者的盲点 / 时代局限

- **"我自己会用吗"存在明显失效场景**：面向儿童、老年人、
  特定疾病患者的产品，创造者不可能是用户。
  书中没有给出替代判据，本 skill 步骤 3 的"引入代表用户"是外推补充。
- **四象限过于二元**：现实中"能否改善生活"往往是剂量问题——
  每天 20 分钟有益、4 小时有害的产品，在四象限里无处安放。
  实践中需要引入"剂量-效应"维度，书中完全没有。
- 作者本人后来（《不可打扰》）修正了部分立场，
  承认习惯设计者对注意力经济的负面外部性负有更大责任——
  本书第六章的乐观基调应打折看待。
- **平台责任与组织激励未讨论**：个体设计者的自省无法对抗
  以时长为 KPI 的组织结构。书中把伦理完全放在个人良知上，
  缺少制度层面的解法（如指标设计、独立审查、外部监督）。
- 成书于监管介入之前，未涉及今日的**未成年人防沉迷、算法备案、
  注意力监管**等强制要求，这些已把部分伦理问题变成合规问题。

### 容易混淆的邻近方法论

- **暗黑模式清单（Dark Patterns Taxonomy）**：枚举具体的欺骗手法
  （虚假倒计时、隐藏取消入口），是**行为层**的黑名单；
  本 skill 是**意图层**的判据，能覆盖清单未列出的新手法。两者互补。
- **企业社会责任 / ESG**：组织层面的合规与披露框架，
  颗粒度远粗于单个功能决策。
- **价值敏感设计（Value Sensitive Design）/ 伦理设计工具包**：
  学术方法，流程更完整但更重；本 skill 的优势是**两个问题即可自答**，
  能在会议现场使用。
- **合规审查（法务/隐私影响评估）**：回答"合不合法"；
  本 skill 回答"该不该做"。合法但不该做的事大量存在。
