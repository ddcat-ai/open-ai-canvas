## I — 方法论骨架 (Interpretation)

不看行业、不看话术、不看战略 PPT，**直接看你的收款凭据上写的单位是什么**——那才是你真正在卖的东西。

五档计价单位：

| 计价单位 | 你实际在卖 | 组织会自动优化 |
|---|---|---|
| 原料（重量/体积/规格） | 初级产品 | 单位成本、产能 |
| 有形产物（件/台/套） | 产品 | 良率、出货量 |
| 活动（次/单/工单/人天） | 服务 | **速度、单量、快点结束** |
| 时间（时段/入场/会期/停留） | 体验 | **顾客愿意待多久、值不值票价** |
| 结果（达成/指标/变化量） | 变革 | **顾客是否真的变好** |

真正的力量在第二列到第三列的因果：**计价单位是组织行为的隐形指挥棒。**

- 按工单量结算的客服团队，一定会优化"快点挂断"——这不是员工态度问题，是结构必然。
- 按人天结算的乙方，一定会优化"项目做得久一点"。
- 按课时结算的教培，最怕的是"学员学会了就不来了"——它与顾客利益结构性对立。

所以有两条反直觉的操作推论：

1. **想改变组织优化的方向，改激励口号无效，加培训无效，换人也大概率无效——改计价单位才有效。**
2. **想升级产出，第一步不是改产品，是改计价单位。** 计价单位一改，产品和流程会被组织自己拉着跟上。

## A1 — 书中的应用 (Past Application)

### 案例 1：银行业的自我初级产品化（第2章 p082）
- **问题**：银行服务为什么普遍陷入无差别的价格竞争？
- **方法论的使用**：作者指出快餐连锁与呼叫中心"总是想尽办法压缩每一秒为客户服务的时间"，银行业普遍如此。按处理效率结算 → 组织的唯一优化目标变成"每笔业务用时更短"。
- **结论**：这个计价与考核结构系统性地消除了一切可收费的体验空间，最后只剩利率和费率可比。
- **结果**：银行业出现广泛的初级产品化趋势。

### 案例 2：变革性担保与按结果收费（第9、10章）
- **问题**：培训、咨询、健身这类生意，怎么摆脱"按小时卖自己"？
- **方法论的使用**：把计价单位从"活动/时间"改为"结果"，并配变革性担保（对结果作出担保，作为定价结构的一部分而非营销话术）。
- **结论**：一旦按结果收费，机构的关注点被迫从"卖出更多课时"转向"顾客是否真的变好"，后续实施（追踪与巩固）从成本项变成必需项。
- **结果**：作者以此论证变革级产出天然抗商品化——每个人的结果不可互换。

### 案例 3：保险的收费对象迁移（图 9-2）
- **问题**：保险如何从赔付走向预防？
- **方法论的使用**：收费对象从"保额/保单"改为"结果（你不会出事）"。
- **结论**：一旦向结果收费，保险公司才有动力真正去改变投保人的行为与风险状况。
- **结果**：产出从"补偿损失"升级为"让损失不发生"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **行为跑偏且培训无效**：团队/客服/销售/供应商总是敷衍、赶工、糊弄，讲道理和加培训都改不动。
2. **设计商业模式或改造收费方式**：要在按次、包月、按量、按结果之间做选择。
3. **外包合同或乙方管理**：乙方按人天结算，项目越拖越久；或按交付件结算，质量注水。
4. **佣金/提成结构设计**：销售提成挂在签单量上，导致过度承诺、售后崩盘。
5. **订阅制转型**：从一次性买断转向订阅，不确定该按什么维度计费。
6. **机构与顾客利益冲突**：教培怕学员学会、维修厂怕车不坏、律所怕案子早结——想解开这个结。
7. **想升级产出但不知从哪下手**：`economic-value-progression` 定级后的第一个落地动作。

### 语言信号 (用户的话里出现这些就应激活)

- "按小时/按次/按人天/按件收费，合适吗"
- "提成/佣金/绩效怎么设计"
- "客服总是想快点挂断 / 员工只求做完不求做好"
- "培训了很多次还是老样子 / 激励失效了"
- "要不要改成订阅制 / 包月还是按量"
- "乙方总把项目拖长"
- "学员学会了就不来了，这生意本身有问题"
- "billing model" / "pricing unit" / "per-hour vs outcome-based" / "value-based pricing" / "SLA"

### 与相邻 skill 的区分

- 与 `economic-value-progression` 的区别：那个判断**卖哪一级**（战略定级，回答"该不该升级"）；本 skill 改**以什么单位收款**（执行杠杆，回答"怎么让组织跟上"）。通常先定级再改单位。
- 与 `transformation-customer-as-product` 的区别（★易混，尤其在健身/教育/咨询行业）：**只要用户没打算改变「我们交付什么、为什么结果背书」，哪怕行业是改变人的生意，也归本 skill**（例：健身房问年卡改成按什么收 → 本 skill）；一旦话头转到「我们其实卖的是学员的改变 / 要不要做效果担保」→ 转那个 skill 先重定义产出。
- 与 `ing-the-thing-admission-fee` 的区别（★易混）：**硬判据看「这段过程现在收不收钱」。现在免费、问题是该不该开始收（免费方案、免费打样、免费体验引流）→ 那个 skill；已经在收钱、问题是换成按什么单位收 → 本 skill。**后者只处理一个特定动作——把体验单独拆出来收入场费（时间档）；本 skill 覆盖全部五档单位的选型，包括向下改（结果档→活动档也可能是对的）。
- 与 `incentive-inverted-u` 的区别：那个讲**金钱激励给多大**（金额的倒 U 型效应，对内）；本 skill 讲**对外收款按什么单位算**（结构而非金额）。金额调不动的问题，往往要靠单位来解。
- 与 `pain-of-paying-tuning` 的区别：那个讲付款的**形式与时点**如何影响付款痛感（顾客侧心理）；本 skill 讲计价单位如何影响**卖方组织的行为**（供给侧结构）。

## E — 可执行步骤 (Execution)

1. **拿出真实的收款凭据（发票/合同/账单/结算表），读出单位**
   - 不看宣传语，只看"数量 × 单价"这一行的单位是什么。
   - 完成标准：能一句话说出"我们按 ______ 收钱"。

2. **推演这个单位会让组织优化什么**
   - 问："如果所有人都只想把这个单位的数字做大/成本做小，他们会怎么干？"
   - 完成标准：推出的行为与用户抱怨的"跑偏行为"能对上。若能对上，病因确认——**不是人的问题，是单位的问题**。
   - 判停条件：若推不出用户抱怨的行为，说明病因在别处（招聘、流程、工具），本 skill 不适用，退出。

3. **检查计价单位与顾客利益是否结构性对立**
   - 问："顾客达成他真正的目的，会让我们的收入变多还是变少？"
   - 变少 → 结构性对立（教培怕学会、维修厂怕不坏、按工时的乙方怕早完工）。这类对立无法靠职业道德弥合。
   - 完成标准：明确写出"顾客成功 → 我们收入↑/↓"。

4. **选新单位（沿五档上移或下移）**
   - 上移一档：活动 → 时间（收停留/入场/会期）；时间 → 结果（收达成）。
   - **下移也可能是对的**：若顾客只想快点结束（把该环节视为成本），把"时间"改回"活动"甚至"件"，配合自助化，才是正解。
   - 完成标准：新单位能通过步骤 3 的检验（顾客成功 → 我们收入↑）。

5. **给新单位配三件套：定义、计量、担保**
   - 定义：这个单位到底怎么算（"结果"必须被定义为可观测的具体指标，否则无法结算）。
   - 计量：谁来测、多久测一次、争议怎么裁。
   - 担保：向结果收费时，配变革性担保（未达成如何处理），它是信任装置也是风控上限。
   - 完成标准：三项都有具体答案，特别是"结果"不能是"客户满意"这种不可裁量的表述。

6. **做归因与道德风险的压力测试（仅当新单位是"结果"时）**
   - 归因：结果到底是我们做出来的，还是客户本来就行？→ 设对照或基线。
   - 挑客：按结果收费会诱使我们只接容易成功的客户 → 明确是否接受，以及如何披露。
   - 迎合：结果导向会诱使我们迎合而非质疑客户的目标 → 设置拒单标准（见 `transformation-customer-as-product` 的道德刹车）。
   - 完成标准：三个风险各有一条应对，或明确写出"接受该风险，因为……"。

7. **先小范围试行，再全量切换**
   - 完成标准：选一个客户群/一条产品线试跑一个结算周期，观察组织行为是否按预期迁移。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **用户问的是价格数字高低**（定多少钱、要不要打折、怎么设锚点）→ 转 `reference-price-framing` / `arbitrary-coherence-pricing`。
- **结果不可观测或严重滞后**（医疗预后、长期教育成效、公共政策）：按结果收费会退化为扯皮，此时"时间"或"活动"档反而更诚实。
- **强监管行业的计价方式被法规锁死**（医保、公用事业、部分金融产品）：先确认法规空间，否则方案不可执行。
- **纯内部绩效考核设计**（无对外收款单位可改）：本 skill 的杠杆是对外计价，内部指标是次生的。可参考但不要直接套。

### 作者在书中警告的失败模式

- **按处理时长/工单量结算 → 组织必然优化"快点挂断"**（第2章 p082）。作者以快餐连锁、呼叫中心、银行业为例，指出这直接导致行业性初级产品化。
- **变革生意按服务定价**（第9章）：健身卖次卡、培训卖课时、咨询卖人天、心理咨询卖小时，既系统性自我贱卖，又与顾客利益结构性对立。
- **担保只是营销话术**：作者主张变革性担保应是定价结构的一部分。若只在宣传页写"包学会"而结算方式不变，等于没改。

### 作者的盲点 / 时代局限

- **案例来自 1990s 美国的线下服务业**（快餐、呼叫中心、银行网点）。**案例已过时；数字化与线上语境下需重新检验，但"计价单位反向指挥组织行为"这一机制本身仍然成立**，且在 SaaS 时代被大量印证（按席位 vs 按用量 vs 按成效的不同组织后果）。
- **⚠️ 作者由此推出的"因此应该延长服务时间"不成立。** 原文说"不愿在顾客身上花时间的唯一结果就是顾客流失"（第2章 p082），但过去 25 年亚马逊一键下单、Uber、自助点餐、SaaS 自服务、Costco 恰恰靠**削减交互时间**取胜。
  **正确的边界条件是：顾客把该环节视为「成本」时，压缩时间是对的；只有当顾客把它视为「价值」时，压缩时间才有害。** 本书没有给出这个边界，使用时必须自己补上。
- **按结果收费的风控框架缺失**：书中给了"变革性担保"的案例，但没有处理归因困难、挑选易成功客户的道德风险、以及医疗/教育领域结果担保的法律风险。E 段步骤 6 是本次整理补入的。
- **未讨论计价单位切换的迁移成本**：老客户的合同、财务系统、销售习惯都要改，书中把它当作纯粹的观念问题。

### 容易混淆的邻近方法论

- **KPI/OKR 设计**：那是内部指标；本 skill 是对外计价单位。内部指标通常是计价单位的下游产物——改了计价单位，KPI 会被迫跟着改；只改 KPI 不改计价单位，往往被计价单位拉回原地。
- **价值定价（value-based pricing）**：那讲"按顾客感知价值定金额"，仍是数字问题；本 skill 讲"按什么维度计数"，是结构问题。两者可叠加。
- **成本加成定价**：与本 skill 正交，且通常是初级产品/产品档的默认做法。
