## I — 方法论骨架 (Interpretation)

把"让用户养成习惯"这件说不清的事，拆成四个可以分别设计、分别诊断的阶段：

1. **触发** — 提示行为开始。外部触发（广告、通知、好友分享）负责第一次把人带来；
   内部触发（无聊、孤独、焦虑等情绪）负责让人自己回来。
2. **行动** — 在期待酬赏的状态下做出的最简单动作。这一步遵循 B=MAT：
   动机、能力、触发缺一不可，且能力（简化）永远优先。
3. **多变的酬赏** — 满足需求的同时**保留渴望**。关键不是奖励多大，而是结果不可预测。
4. **投入** — 用户付出时间/数据/精力/社会资本，一方面沉淀带不走的储存价值，
   另一方面为下一次循环加载新的外部触发。

真正的要点不在四阶段各自做好，而在它们必须**闭合成环**：第四阶段回指第一阶段。
因此这是复利结构而非线性漏斗——每循环一次，用户与产品的联结增强一分，
直到外部触发可以被用户自己的情绪替代。当这一步发生，习惯就形成了。

诊断时的用法是"定位断点"而非"全面优化"：一个产品留不住人，
几乎总是四环中有一环断了，找到那一环，其余三环的努力才有意义。

## A1 — 书中的应用 (Past Application)

### 案例 1: Instagram
- **问题**: 一个只有滤镜功能的小工具，凭什么值 10 亿美元？
- **方法论的使用**: 作者用四阶段拆解——内部触发是"怕错过值得留住的瞬间"；
  外部触发是好友的点赞与评论通知；行动被压缩到"拍—选滤镜—发"三步；
  酬赏是不可预期的社交反馈；投入是逐渐积累的照片流、关注者与关系网。
- **结论**: 它的价值不在滤镜（可复制），而在闭环完整（难复制）。
- **结果**: 13 名员工被 Facebook 以 10 亿美元收购，成为习惯型产品的标准范本。

### 案例 2: 《圣经》应用 YouVersion（第七章全案）
- **问题**: 一个网页版读经工具，用户只在电脑前偶尔打开。
- **方法论的使用**: 创始人格鲁恩瓦尔德发现真实场景是排队、等车、临睡前的碎片时间，
  于是逐环改造：触发改为按个人活跃时段投放的推送；
  行动改为"打开即读一节"（后加音频版进一步降低门槛）；
  酬赏是每天不同的经文内容 + 社群分享的认同；
  投入是阅读计划进度、书签、高亮与笔记。
- **结论**: 四环补齐后，产品从"工具"变成"日常仪式"。
- **结果**: 安装量过 2 亿，日均阅读时长远超同类。

### 案例 3: 电子邮件（作者的教学样本）
- **问题**: 为什么人们会一天几十次地检查一个"工作工具"？
- **方法论的使用**: 触发是"怕错过重要信息"的焦虑；行动是点开收件箱；
  酬赏同时具备三类——社交（谁给我写信）、猎物（有没有有用信息）、
  自我（清空收件箱的完成感）；投入是整理、归档、通讯录与回复历史。
- **结论**: 邮件是最古老的习惯养成型产品，四阶段全部齐备。
- **结果**: 成为全书演示"如何用四阶段拆解既有习惯"的标准例题。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 产品/内容/社群**留存差**，用户来一次就不再回来，但说不清问题出在哪。
2. 要从零**设计一个需要反复使用**的东西（App、功能、栏目、课程、社群、个人习惯）。
3. 手上有一个新点子，想快速判断它**有没有形成习惯的潜力**（用五问自查过滤）。
4. 竞品明明不如自己，用户却不迁移，想搞清楚粘性到底建立在什么上。
5. 增长团队和产品团队各执一词（一个要投放、一个要改功能），需要一个共同坐标来分诊。

### 语言信号 (用户的话里出现这些就应激活)

- "用户来了就走 / 留存太差 / 次日留存只有 x%"
- "怎么让用户对我们上瘾 / 怎么做用户粘性"
- "我们的产品好像可有可无"
- "想设计一个让人每天都想打开的 ___"
- "帮我看看这个产品/点子有没有戏"
- "hook model" / "how to make a habit-forming product" / "why do users churn"

### 与相邻 skill 的区分

- 与 `habit-zone-screening` 的区别：那个是**前置可行性筛选**（这个品类值不值得做习惯设计），
  本 skill 假定值得做，接着定位闭环断点。若用户问的是"该不该做"，先转那个。
- 与 `bmat-behavior-diagnosis` 的区别：那个只管第二环（行动为什么不发生），
  本 skill 管四环全局与编排。
- 与 `habit-testing` 的区别：那个是**用数据验证**习惯是否已形成（事后测量），
  本 skill 是**用结构定位**问题（设计与诊断）。

## E — 可执行步骤 (Execution)

被激活后按以下顺序执行：

1. **确认对象与"一次完整使用"的定义**
   - 问清：谁是用户？他做完哪个动作算"用了一次"？期望多久用一次？
   - 完成标准：能写出一句"某类用户在某情境下，做 ___ 算一次使用，理想频率是 ___"。
   - 判停条件：若理想频率低于每月一次 → 停止本 skill，转 `habit-zone-screening`。

2. **跑五问自查，逐环收集事实（不做评价）**
   - ① 用户真正需要什么？你的产品缓解什么痛苦？（内部触发）
   - ② 你靠什么把用户吸引过来？（外部触发）
   - ③ 期待酬赏时，用户能做的最简单动作是什么？（行动）
   - ④ 用户是满足于所得酬赏，还是想要更多？（多变的酬赏）
   - ⑤ 用户对产品做了哪些"点滴投入"？
   - 完成标准：五个问题都有具体、可观测的答案；答不上来的直接标记为"空"。

3. **定位断点（最多两个）**
   - 规则：任何一问答"空"或答案空泛 → 该环即断点。
   - 若多环皆断，按闭环顺序取**最靠前**的一环优先（前面不通，后面白修）。
   - 特别检查第四环 → 第一环的回指：投入有没有生成下一个外部触发？
     若没有，闭环未合拢，这是最常见也最致命的断点。
   - 完成标准：明确指出 1–2 个断点环节，并写明判断依据。

4. **转交对应专项 skill**
   - 内部触发缺失 → `internal-trigger-mining`
   - 外部触发无效/时机错 → `external-trigger-design`
   - 行动门槛高 → `bmat-behavior-diagnosis`（先分诊）→ `ability-simplification`
   - 酬赏可预期/错配 → `variable-reward-design`；若怀疑会耗尽 → `variability-sustainability`
   - 无投入/无沉淀 → `investment-design`
   - 闭环未合拢 → `load-next-trigger`
   - 完成标准：给出明确的下一步 skill 与要解决的具体问题。

5. **过一遍伦理闸门**
   - 强制调用 `manipulation-matrix-ethics` 的两个问题：我自己会用吗？它显著改善用户生活吗？
   - 完成标准：给出象限定位；若落在"经销商"象限，明确提示风险并建议中止。

6. **给出改造顺序与验证方式**
   - 输出：断点 → 改造动作 → 预期观测指标 → 用 `habit-testing` 复测的方式。
   - 完成标准：用户拿到的是一个有先后顺序的行动清单，不是一堆并列建议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **单次转化优化**（落地页文案、投放素材、结算流程 A/B）——那是转化问题不是习惯问题，
  四阶段会把讨论引向不相关的方向。
- **天然低频的品类**（买房、报税、婚庆、年度体检、大额 B 端采购）——
  频率不足时任何 hook 投入都是浪费，先用 `habit-zone-screening` 判定。
- **产品核心价值尚未成立时**——习惯放大已有价值，不创造价值。
  用户说"没什么用"而不是"忘了用"，问题不在闭环。
- **一次性活动/campaign**——没有第二次循环，闭环无从谈起。

### 作者在书中警告的失败模式

- **ce22 — 相信 hook 能救一个没有价值的产品**：习惯建立在已存在的需求之上，
  没有可感知用途，频率再高也只是骚扰。
- **ce20 — 闭环断在最后一环**：用户投入了，但投入不产生任何后续触发，
  产品每次都要重新花钱把用户拉回来。这是本 skill 最该优先检查的一处。
- **ce05 — 只做外部触发，从不建立内部触发**：停投广告即断崖，
  这不是养成了习惯，只是在租用注意力。
- **ce19 — 把上瘾模型当成游戏化**：贴上积分/徽章/排行榜不等于闭环，
  可预期的奖励不产生渴望。

### 作者的盲点 / 时代局限

- 本书成书于 2013 年前后，案例集中在移动互联网早期的消费级 App，
  对 B 端产品、订阅制 SaaS、AI 对话式产品的适配需要自行外推（外推通常成立，但要注明是外推）。
- 书中默认"用户使用频率越高越好"，未处理"注意力过载"与平台反成瘾监管的现实约束。
- 四阶段的边界并非严格互斥（如"加载下一个触发"同时属于投入与触发），
  诊断时不要在归类上纠缠，只要能定位到可改造的动作即可。

### 容易混淆的邻近方法论

- **AARRR 海盗指标 / 转化漏斗**：单向、以转化为终点；上瘾模型是闭环、以复访为终点。
  两者可并用，但不要用漏斗的语言讨论第四环。
- **游戏化（PBL：点数/徽章/排行榜）**：是酬赏的一种外壳，不是闭环。
- **精益创业的 MVP 循环**：那是组织的学习循环（建造—评估—学习），
  本模型是用户的行为循环。二者在 `habit-testing` 处交汇。
