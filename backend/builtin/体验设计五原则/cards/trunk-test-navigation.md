## I — 方法论骨架 (Interpretation)

在物理空间里，人有大量免费的方位线索：这栋楼有多大、我走了多远、上过几层楼、
门在哪个方向。**在一个数字产品里，这些线索一条都没有。** 没有大小感，没有距离感，
没有"我走到哪儿了"的身体记忆。

所以导航不是"链接的集合"，它是**人工制造方位感的装置**。判断导航好坏的标准
也就不是"链接全不全"，而是"用户随时知不知道自己在哪"。

Krug 给了一个极快的检验方法——后备厢测试。挑一个**深层页面**（不能是主页，
也不能是你最熟的那页），瞥一眼，然后立刻回答六个问题：
① 这是什么网站？② 我在哪一页？③ 主要栏目有哪些？④ 这一层我还有什么选择？
⑤ 我在整个体系中处于什么位置？⑥ 我怎样搜索？

答不出，或者犹豫超过一秒，就是失败。注意这个测试的关键设定是"深层页面"——
因为真实用户大量从搜索引擎、分享链接、扫码直接落在深层页，他们从来没经过你精心
设计的首页。

对应的构造方法是**持久导航四元素**（每页固定出现）：站点 ID（左上角，链回首页）、
主要栏目、实用工具（次要功能，通常右上）、搜索。再加三层"你在这里"：
每页有且只有一个显著的**页面名称**（而且要和点进来的那个链接文字一致）、
当前项在各级导航中**高亮**、深层结构补**面包屑**（放顶部、用 > 分隔、
末项是当前页且加粗不可点）。

移动语境的补充：屏幕小迫使导航折叠，藏进汉堡菜单的东西约等于用户看不见；
没有 hover 也就没有了"悬停预览"这条廉价线索。因此移动端更依赖页面名称与面包屑
这类**显性**方位标记。

## A1 — 书中的应用 (Past Application)

### 案例 1: 后备厢测试
- **问题**：如何在不做正式测试的情况下，快速判断导航是否合格。
- **方法论的使用**：把"迷路"这种抽象体验，转化成六个必须秒答的问题，并强制取样于深层页。
- **结论**：任何一问答不出，都是结构缺陷而非美观问题。
- **结果**：一个 60 秒、零成本、任何人都能做的自检工具。

### 案例 2: 标签页（tabs）为什么常常失效
- **问题**：很多站点用标签页，但用户看不出哪个是激活的。
- **方法论的使用**：Krug 指出关键不在标签的形状有多别致，而在于激活的标签必须
  用不同颜色/外形形成对比，并且**与它下面的空间在物理上连接起来**，从而"弹到最前面"。
- **结论**：标签的隐喻只有在物理连接成立时才生效。
- **结果**：给出了一条可直接检查的具体判据。

### 案例 3: 网站里没有比例感
- **问题**：设计者不理解为什么用户会在结构清晰的网站里迷路。
- **方法论的使用**：作者对比物理空间——在网站上"没有比例感，也没有方位感"，
  导航是唯一的替代物。
- **结论**：方位感不是自然产生的，必须被制造出来。
- **结果**：导航从"功能模块"升级为"必需的基础设施"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户/同事反馈"找不到东西""不知道点哪里回去""在里面绕晕了"。
2. 要设计或改版网站/App/后台的导航结构、菜单层级。
3. 文档站、知识库、Wiki、飞书云文档目录越堆越乱，新人读不明白。
4. 大量流量从搜索引擎或分享链接直接落到深层页，跳出率高。
5. 在纠结"要不要加面包屑""层级是不是太深""侧边栏放什么"。
6. 做一份很长的 PPT/报告，担心听众翻到中间不知道自己在哪一部分。

### 语言信号（用户的话里出现这些就应激活）

- "用户找不到 / 我在哪 / 怎么回去 / 绕晕了 / 迷路"
- "要不要加面包屑 / 侧边栏放什么 / 层级太深了吧"
- "导航怎么设计 / 菜单结构 / 信息架构"
- "从搜索进来的人看不懂这个页面"
- "navigation / breadcrumbs / site structure / information architecture / lost"

### 与相邻 skill 的区分

- 与 `billboard-scan-design` 的区别：那个管**单页内部**的信息投递（层次、区域、降噪）；
  本 skill 管**跨页的方位感**（我在哪、能去哪、怎么回去）。页面很好看但用户仍迷路 → 用本 skill。
- 与 `dont-make-me-think-audit` 的区别：那个是通用问号审查；本 skill 是导航专项，
  提供固定的六问与四元素构造法。若审查发现问号集中在"分类/位置"上，转本 skill。
- 与 `frontend-dev` 的区别：那是导航组件的工程实现；本 skill 只定结构与判据。
- 与 `feishu-kb-recall` 的区别：那个是从知识库里**召回内容**；本 skill 是让知识库
  **本身可被导航**。

## E — 可执行步骤 (Execution)

1. **取样：随机挑 2–3 个深层页面**
   - 硬性要求：不能是首页，不能是你最熟的那页；优先挑真实流量落地页
     （搜索来源、分享链接、扫码入口）。
   - 完成标准：样本页已确定并说明来源。

2. **执行后备厢测试（每页 60 秒）**
   - 瞥一眼（不许细读），立刻逐条回答并**圈出答案所在位置**：
     ① 这是什么网站/产品？ ② 我在哪一页？ ③ 主要栏目有哪些？
     ④ 这一层我还有什么选择？ ⑤ 我在体系中的位置？ ⑥ 怎么搜索？
   - 记录两类失败：**答不出** 与 **犹豫 >1 秒**。
   - 完成标准：每页得到一张六问评分表。

3. **对照持久导航四元素，找出缺失项**
   - 站点 ID（左上、链回首页）／主要栏目／实用工具（次要，右上）／搜索。
   - 完成标准：明确列出缺哪几个、放在哪里。

4. **检查"你在这里"三层标记**
   - ① 页面名称：是否存在、是否唯一显著、是否**与点进来的链接文字一致**。
   - ② 高亮：当前项在各级导航中是否被视觉标出。
   - ③ 面包屑：深层结构是否有；位置在顶部、用 > 分隔、末项加粗不可点。
   - 完成标准：三层逐条给出"有/无/不合格"。

5. **移动端追加检查**
   - 折叠进汉堡菜单的是否包含高频入口？（是 → 提出上浮建议）
   - 没有 hover 后，可点项是否仍可辨认？
   - 返回路径是否明确（不能只依赖系统返回键/手势）？
   - 完成标准：移动端三问均有结论。

6. **只修失败项，不做整体重设计**
   - 按"失败页数 × 严重度"排序，输出 ≤5 条改动。
   - 判停条件：若六问中有 ≥4 问在多数页面失败 → 这是信息架构问题而非导航装饰问题，
     标记为需要 IA 重构，并建议先用 `diy-usability-test` 找 3 人验证分类命名。

7. **输出**
   - 一张表：页面 / 六问评分 / 缺失元素 / 改动建议 / 优先级；
     外加一句结论："本产品的方位感缺口主要在 ____。"

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **单页/单屏产品**（落地页、单功能小工具、单页应用的单一视图）：没有跨页方位问题。
- **单页内部的视觉排版问题**：转 `billboard-scan-design`。
- **内容本身缺失或错误**：导航再好也带不到不存在的内容。
- **信息流/推荐流类无层级产品**：这类产品的用户不需要方位感（也不存在"某一层"），
  全书的任务型前提在此不成立。
- **有意的探索型体验**（解谜游戏、叙事网站、艺术展示）：迷路可能是设计目标。

### 作者在书中警告的失败模式

- **只在首页检查导航**。真实用户大量直接落在深层页，首页正常不代表体系成立。
  后备厢测试特意要求取样深层页正是为此。
- **标签页只做形状不做物理连接**。激活标签若没有与下方内容区连成一体，隐喻失效。
- **页面名称与入口链接文字不一致**。用户点了"预订机票"却落在标题为"航班查询"的页面上，
  会怀疑自己点错了。

### 作者的盲点 / 时代局限

- 第 3 版正文写于 2013 年，导航惯例（面包屑、标签页、左上 logo、右上搜索）来自
  **英文桌面 Web**。今天中国用户以移动 App/小程序为主入口，这些惯例的使用频率与形态
  都已改变（底部 tab bar、微信内的返回逻辑、小程序胶囊按钮）。
  **凡涉及具体控件与位置的判断，需在当代移动端与小程序语境下重新检验**；
  但"方位感必须被人工制造"这一原则不变。
- 作者对**搜索作为主要导航方式**着墨不足（今天很多产品里搜索已取代浏览成为主路径），
  也未覆盖**算法推荐入口**带来的"无结构进入"。
- 作者只给检验方法，不给信息架构的生成方法（如卡片分类、树测试）。

### 容易混淆的邻近方法论

- **卡片分类（Card Sorting）/ 树测试（Tree Testing）**：这两个是**生成与验证分类体系**
  的专门方法；后备厢测试只检验"当前结构是否被表达清楚"。若本 skill 判定为 IA 问题，
  应转向它们。
- **尼尔森启发式"系统状态可见性"**：本 skill 的"你在这里"体系是它在导航维度的具体化。
