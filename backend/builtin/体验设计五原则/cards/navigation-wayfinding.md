## I — 方法论骨架 (Interpretation)

导航不是"每页放几个链接"这么简单,它要同时达成三件事:
1. 给用户**跳转方法**(有效促进行为的链接);
2. 传达**元素间关系**(哪些更重要、如何关联);
3. 传达**内容与当前页的关系**(哪个选择支持用户目标)。

五类导航系统各司其职:
- **全局导航**: 覆盖全站的关键通路(到主要栏目)。
- **局部导航**: 架构中"附近"的通路(父/兄弟/子级)。
- **辅助导航**: 全局/局部到不了的快捷相关链接。
- **上下文导航**: 嵌在内容里的内联链接(用户读文时正好需要)。
- **友好导航**: 不常需但便利的链接(如营业时间)。

**指示标识(wayfinding)**: 结合导航+信息设计,帮用户建立"我在哪/能去哪/哪条路更近"的心理图像(颜色编码、图标、标签、排版)。核心假设: **用户不会把上一页信息带到下一页**——因为搜索引擎可能让任何页成为入口,所以每页都要自解释。

## A1 — 书中的应用 (Past Application)

### 案例 1: 三目标诊断导航失败
- **问题**: 导航只堆链接,用户仍迷路。
- **方法论的使用**: 作者用三目标检验——缺"关系传达"或"当前页关系"则链接成乱麻。
- **结论**: 只给链接不够,要传达结构与位置。
- **结果**: 成为导航设计的质量标尺。

### 案例 2: 上下文导航被滥用
- **问题**: 文字里塞满超级链接。
- **方法论的使用**: 作者指出若链接不明确的支持任务,用户不知哪个需要,反成乱麻。
- **结论**: 上下文导航须精准支持用户任务。
- **结果**: 说明五类导航需按需选用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 用户反馈"找不到 X / 迷路 / 不知在哪"。
2. 设计菜单、面包屑、页脚、上下文链接。
3. 复盘跳出率高、任务完成率低。
4. 多入口产品(任何页可能为首页)的导航设计。

### 语言信号
- "用户找不到设置"
- "导航怎么设计?"
- "面包屑 / 全局导航 / 上下文链接"
- "navigation / wayfinding / 迷路"

### 与相邻 skill 的区分
- 与 `information-architecture-building` 的区别: IA 是"信息如何组织"; 导航是"用户如何在结构中穿行"。IA 在先。
- 与 `interface-design-defaults` 的区别: interface 关注控件与最常见行为; 导航关注移动路径与位置感。

## E — 可执行步骤 (Execution)

1. **对照三目标自检**
   - 完成标准: 现有导航是否同时给跳转、传关系、传当前页关系; 缺项则补。
2. **选齐五类导航**
   - 完成标准: 按场景配全局/局部/辅助/上下文/友好,不滥用(如上下文链接须支持任务)。
   - 判停条件: 若仅单界面产品,跳过导航系统(用 interface 即可)。
3. **加指示标识强化位置感**
   - 完成标准: 用颜色/图标/标签/排版让用户懂"我在哪/能去哪",且每页自解释(不依赖上一页)。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 单界面全功能产品(如一个计算器)无需导航系统。
- 不要为"全导航"而堆链接: 上下文导航滥用成乱麻。

### 作者在书中警告的失败模式
- 假设用户带上一页记忆: 实际任何页都可能成入口,必须每页自解释。
- 导航只给链接不传关系: 用户仍不知哪个选择有效。

### 作者的盲点 / 时代局限
- 五类导航偏网站; App 底部栏/抽屉等模式需映射,但三目标与 wayfinding 原则不变。

### 容易混淆的邻近方法论
- 不要与"信息设计"混淆: 导航是移动,信息设计是"信息如何呈现/分组"(见 interface/contrast skill)。
