## I — 方法论骨架 (Interpretation)

概念模型是用户对"交互组件将怎样工作"的**心智预期**。比如购物车=容器,于是"放进/拿出/结账"成套。它的作用与设计要点:

- **用于开发时保持一致,不是给用户看的**: 不需要告诉用户"我们用的是零售商店模型"——用户凭直觉即可,因为交互符合其隐含预期。明示反而混淆。
- **选熟悉模型降低学习成本**: 零售商店模型因最广为熟悉被普遍采用; 打破传统(如用"分类订货单"代替购物车)可以,但要有好理由,并准备好符合用户需求的替代模型。
- **不要逐字照搬现实比喻**: 现实物体(书桌/杂志)在屏幕上常失效——Slate 把网站做成杂志最终放弃; 西南航空书桌首页成反面教材。比喻若不能让用户正确理解功能,反增混淆。

一致性还要求: 即使概念模型不同的地方,共用模块(开始/结束/保存)也要统一处理,让用户把一处学到的知识迁移到别处。

## A1 — 书中的应用 (Past Application)

### 案例 1: 购物车=容器模型
- **问题**: 电商"加入/移除/结账"如何统一。
- **方法论的使用**: 作者以购物车为容器模型,约束视觉与语言(放进/拿出/结账);对比"分类订货单"模型会用"编辑/寄出"。
- **结论**: 熟悉模型让用户快速适应不熟悉网站。
- **结果**: 成为概念模型一致性的标准范例(c02)。

### 案例 2: Slate 杂志模型失败
- **问题**: Slate 把网站做成杂志(封面/页数/翻页)。
- **方法论的使用**: 作者指出杂志模型在网上无效,Slate 最终放弃。
- **结论**: 逐字照搬现实比喻行不通。
- **结果**: 成为"过度运用比喻"反面教材(c03)。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 设计新功能,选"用什么比喻/心智模型"承载。
2. 产品里同一概念(如"收藏""订单")在不同页面表现不一。
3. 评审发现"这功能用户看不懂是干嘛的"。
4. 想打破常规交互但怕用户不买账。

### 语言信号
- "用购物车还是文件夹比喻?"
- "用户好像不懂这个功能是啥"
- "概念模型 / 心智模型 / 一致性"
- "conceptual model / metaphor"

### 与相邻 skill 的区分
- 与 `metaphor-restraint` 的区别: 本 skill 讲"概念模型如何保持一致、选熟悉模型"; metaphor-restraint 讲"抑制建立比喻的冲动、比喻为何常失效"。两者同源,本 skill 偏建设,metaphor 偏克制。
- 与 `error-handling-design` 的区别: 概念模型是"组件如何被理解"; error-handling 是"出错时系统如何响应"。

## E — 可执行步骤 (Execution)

1. **选定主导概念模型**
   - 完成标准: 为关键组件选一个用户熟悉的心智模型,记录其隐喻与对应操作。
2. **全程保持一致**
   - 完成标准: 同一概念在所有出现处用相同语言/操作;共用模块(开始/保存)跨模型统一处理。
   - 判停条件: 若必须打破熟悉模型,写下理由并备好替代模型。
3. **检查比喻是否逐字照搬现实**
   - 完成标准: 移除"现实物体图形代表抽象功能"导致的猜测;不能让用户猜图标含义。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 纯展示性视觉元素无交互含义,无需概念模型。
- 不要为"一致"而强行统一本应不同的概念——一致性指同一概念,非所有元素雷同。

### 作者在书中警告的失败模式
- 逐字照搬现实比喻: 书桌/杂志模型在屏幕上失效,增加猜测(c03/ce03)。
- 同一元素时而当位置、时而当对象,破坏一致性。

### 作者的盲点 / 时代局限
- "不告诉用户模型"对复杂 B 端产品可能需适当 onboarding; 完全靠直觉对陌生领域未必够。

### 容易混淆的邻近方法论
- 不要与"视觉风格指南"混淆: 概念模型是交互逻辑一致性,风格指南是视觉一致性(见 contrast-consistency-surface)。
