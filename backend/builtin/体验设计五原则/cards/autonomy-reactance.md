## I — 方法论骨架 (Interpretation)

**逆反心理（reactance）**：当人感到自己的选择自由被限制时，
会本能地做出与被要求方向相反的行为——**与请求内容的好坏无关**。
这是本 skill 的核心诊断：如果抵触强度和方案质量不相关，问题就在自主权上。

**工具一：明示拒绝权（"But you are free"）**
一项覆盖 42 项研究、约 22000 名参与者的元分析显示：
在请求后加上"你有权拒绝"这类措辞，顺从率大约翻倍。
机制是：明示拒绝权把"被要求"重新框定为"自己选择"，逆反无从发作。
**关键：这句话必须是真的**——如果实际上无法拒绝，效果会反转成信任损失。

**工具二：改良既有行为，而非发明新行为**
让人开始做一件全新的事，需要跨越"非常规性"门槛（见 `ability-simplification` 六元素）；
而在既有行为上做改良，用户只需要换一个更省事的做法。
- Fitocracy：健身者本来就在互相攀比、分享成果 → 把这个行为搬到线上（成功）。
- MyFitnessPal：要求用户开始记录每一餐卡路里 → 这是一个全新行为（失败）。

**工具三：默认值的谨慎使用**
默认开启能提高采纳率，但一旦触及**隐私、身份、公开可见性**，
默认开启就会从"便利"变成"侵犯"，触发集体逆反（Quora 案例）。
判据：这个默认值是否改变了"别人能看到我什么"。是 → 不要默认开启。

## A1 — 书中的应用 (Past Application)

### 案例 1: "你有权拒绝"元分析
- **问题**: 如何在不施压的情况下提高请求的接受率。
- **方法论的使用**: 在请求后附加一句明确的拒绝许可。
- **结论**: 承认对方的自主权比强化说服更有效；顺从率约翻倍，
  且在多种文化与请求类型中稳定复现（42 项研究 / 约 22000 人）。
- **结果**: 成为本书最反直觉的操作性结论之一。

### 案例 2: Quora"可视浏览"被迫撤回
- **问题**: 想通过"谁看了你的答案"提高社交酬赏强度。
- **方法论的使用（反面）**: 默认对全部用户开启，未征得同意。
- **结论**: 即使功能本身可能提高酬赏，**未经同意地改变隐私默认设置**
  会引发强烈抵触，收益被逆反抵消。
- **结果**: 用户反弹，公司撤销该功能。

### 案例 3: MyFitnessPal 要求记录卡路里
- **问题**: 帮助用户管理饮食。
- **方法论的使用（反面）**: 要求用户开始一套全新的日常行为——逐餐记录。
- **结论**: 这是"发明新行为"，非常规性门槛极高，多数用户坚持不下来。
- **结果**: 长期留存有限，成为对照组。

### 案例 4: Fitocracy 把线下攀比搬到线上
- **问题**: 让健身者持续使用一款社交产品。
- **方法论的使用**: 健身者本来就在互相展示成绩、寻求认可，
  产品只是把这一既有行为线上化并放大（社交酬赏）。
- **结论**: 改良既有行为的采纳阻力远低于发明新行为。
- **结果**: 早期形成活跃社区。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **新功能上线被骂**，尤其是默认开启、无法关闭的功能。
2. **公司要推行新流程/新工具，员工强烈抵触**（周报系统、OKR 工具、考勤方式）。
3. **改版后老用户激烈反弹**，反馈里出现"凭什么""我没同意"。
4. **要设计授权/隐私相关的默认值**，需要判断该不该默认开启。
5. **要让用户开始一个新习惯**，需要判断是"发明"还是"改良"。
6. **强制分享/强制授权/强制绑定**正在被讨论。
7. **说服一个明确反对的人**（领导、同事、客户），常规摆事实讲道理已失效。

### 语言信号 (用户的话里出现这些就应激活)

- "用户强烈反弹 / 被骂惨了 / 差评刷屏"
- "员工不配合 / 推不动 / 阳奉阴违"
- "默认开启被投诉了 / 用户说凭什么"
- "要不要强制 / 能不能设成必填"
- "怎么让他们接受这个新流程"
- "reactance" / "users pushed back" / "forced adoption" / "opt-out backlash"

### 与相邻 skill 的区分

- 与 `ability-simplification` 的区别：**这是最需要分清的一对**。
  那个处理"做不到"（能力阻力），本 skill 处理"不愿被安排"（心理阻力）。
  判据：如果把流程简化到一步，抵触会消失吗？会 → 用那个；不会 → 用本 skill。
  （六元素中的"非常规性"是两者的交界，本 skill 提供的解法是"改良既有行为"。）
- 与 `commitment-escalation` 的区别：那个是**如何让人自愿迈出第一步**（正向推进），
  本 skill 是**如何不引发抵触**（防守）。二者常联用：
  先用本 skill 保住自主权（给拒绝权），再用那个设计一个微小的自愿动作。
- 与 `external-trigger-design` 的区别：那个管通道与时机；
  当自主型触发的问题是"默认开启、强制推送、无法关闭"时，两者联用。
- 与 `manipulation-matrix-ethics` 的区别：那个是价值层面的自检（我该不该做），
  本 skill 是策略层面的有效性问题（怎么做才不引发逆反）。
  若讨论涉及"这样做对用户好不好"，转那个。

## E — 可执行步骤 (Execution)

1. **做归因判定：是"做不到"还是"不愿被安排"**
   - 检验问题："如果这件事变得极其简单，抵触会消失吗？"
   - 会 → 停止，转 `ability-simplification`。
   - 不会（对方说的是"凭什么""我没同意""为什么要按你说的做"）→ 判定为逆反，继续。
   - 完成标准：写出判定依据（原话中的自主权信号）。

2. **找出自由被剥夺的具体点**
   - 逐条列：哪一项是被强制的？默认开启？无法关闭？必填？限期？公开可见？
   - 完成标准：至少定位 1 个具体的"自由剥夺点"，而不是笼统说"用户不喜欢"。

3. **恢复拒绝权（且必须是真的）**
   - 加一句明确的拒绝许可："本季度可继续使用旧格式""此功能可随时关闭"。
   - 提供真实可用的退出路径，且退出不被惩罚、不被公示。
   - 完成标准：写出这句话的具体措辞 + 退出路径在哪。
   - 判停条件：若实际上无法提供退出（法律/合规强制）→ 本工具不适用，
     改为压缩强制范围、提前告知、给出时间缓冲，并明确说明"为什么这次不能选"。

4. **检查是"发明新行为"还是"改良既有行为"**
   - 问："他们现在**已经在用什么方式**做这件事？"
   - 若答不出 → 说明你在发明新行为，风险高。
   - 完成标准：写出既有行为的具体形态（在群里发进度、口头汇报、用 Excel 记）。

5. **把方案改造成既有行为的省事版本**
   - 目标是让对方感觉"还是那件事，只是更方便了"，而不是"要学一套新东西"。
   - 完成标准：能用一句话说清"你原来做 X，现在做 X 只需要更少的步骤"。

6. **重做默认值决策**
   - 判据：这个默认值是否改变了"别人能看到我什么"或"我的数据流向哪里"。
   - 是 → 改为默认关闭 + 明确邀请开启（附带价值说明）。
   - 否 → 可默认开启，但保留一键关闭。
   - 完成标准：逐项给出默认值与理由。

7. **设计小范围试点，而不是一次性全量**
   - 让早期采纳者自愿加入，用他们的反馈说话（此时人际型触发生效）。
   - 完成标准：写出试点范围、退出机制与观察指标（含"关闭率/退出率"）。

8. **监控逆反信号**
   - 信号：反馈中"凭什么/我没同意/为什么强制"的出现频率；关闭率；阳奉阴违率。
   - 判停条件：这些信号上升时，**减少强制而非加强宣导**——
     加大宣导会强化"被要求"的感觉，使逆反加剧。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **抵触的真实原因是难用**——给拒绝权只会让更多人拒绝。先简化。
- **抵触的真实原因是看不出价值**——此时应补价值论证
  （`habit-as-business-asset` 或 `internal-trigger-mining`），拒绝权无济于事。
- **法律/安全/合规强制**（隐私协议、安全审计、财务规范）——
  这类场景不能提供真实的拒绝权，硬套这套话术反而制造虚假选择、损害信任。
- **紧急情况下的强制变更**（安全漏洞修复、数据迁移）——先做后说更合适，
  但事后必须说明理由。
- **对方的抵触是理性的实质反对**（方案确实有问题）——
  这时该改方案，而不是用心理技巧绕过反对意见。这是本 skill 最容易被误用的地方。

### 作者在书中警告的失败模式

- **ce02 — 强推功能触发逆反**：默认开启且难以关闭，用户反馈出现"凭什么""我没同意"，
  最终被迫撤回。警告信号：强制弹窗、强制授权、强制分享。
- **ce15 — 忽视重度用户的自主权**：无退出机制、无节制设计，
  尾部用户失控后引发舆论与监管风险。
- **ce18 — 触发被关闭**：过度推送本质也是一种自由侵犯，
  代价是永久失去自主型触发通道。
- **ce14 — 有意隐藏退出/关闭路径**：这已越过操控矩阵的伦理线，
  强制转 `manipulation-matrix-ethics`。

### 作者的盲点 / 时代局限

- 书中把"你有权拒绝"当作可直接套用的话术，但该元分析的原始场景多为
  **一次性的陌生人请求**（募捐、问卷）。用于**长期关系**（雇主-员工、产品-老用户）时，
  若拒绝权反复被提及却从未被真正尊重，会迅速失效甚至反噬。书中未讨论这一衰减。
- **文化差异未讨论**：在高权力距离的组织文化中，
  "你可以拒绝"可能被理解为客套，实际拒绝仍有代价——需要配套匿名或制度保障。
- "改良既有行为"这一原则在**颠覆式创新**场景下会给出保守答案：
  有些成功产品确实创造了全新行为（早期的短视频拍摄、直播打赏）。
  书中未讨论何时应该冒这个险，实践中需与 `habit-opportunity-scan` 的"新生行为"对照使用。
- 本 skill 的技巧具备被滥用的可能（用形式上的选择权掩盖实质强制），
  必须与 `manipulation-matrix-ethics` 配套。

### 容易混淆的邻近方法论

- **助推理论（Nudge）/ 默认选项**：主张用默认值引导行为；
  本 skill 给出的是**默认值的边界条件**（涉及可见性与隐私时不可默认开启）。
  两者方向经常相反，需要按"是否触及自我暴露"来切换。
- **变革管理（Kotter 八步 / ADKAR）**：强调紧迫感、愿景与沟通；
  本 skill 的差异是**主动放弃一部分控制权**来换取采纳，这在多数变革模型中不被建议。
- **说服术（Cialdini 六原则）**：其中"承诺与一致"与 `commitment-escalation` 相关，
  但本 skill 的立论是"少施加影响反而更有效"，与增强影响力的路径不同。
- **UX 的 opt-in/opt-out 最佳实践**：操作层面高度重合，
  本 skill 补充的是心理机制解释与"改良而非发明"的采纳原则。
