## I — 方法论骨架 (Interpretation)

多变的酬赏能不能长期奏效，取决于它的**多变性来源**。

**有限多变性（finite variability）**
内容由公司预先生产：关卡、剧情、活动、专栏、课程、节目。
特征：可穷尽。用户玩得越久，可能性空间越小，惊喜递减，
最终退化为可预期的机械劳动。
**这是结构性的，不是团队不努力。** 再优秀的内容团队也只能延缓，不能避免。

**无穷多变性（infinite variability）**
内容由用户或第三方持续生产：UGC 信息流、他人评论、社交反馈、市场行情。
特征：产品自身不产内容，只提供舞台，多变性随用户规模自我再生。

**两条出路：**

**出路 A — 接受它，转工作室模式。**
好莱坞和游戏业早就承认单个作品的生命周期有限，
于是按"作品组合 + 命中率"来经营：持续推出新作，用少数爆款覆盖多数失败。
组织形态、成本结构、招聘方式、财务模型都要随之改变——
这是一个**企业级决策**，不是产品迭代决策。

**出路 B — 注入无穷多变性。**
把一部分内容生产权交给用户：共创、问答、评论、排行、社区、二创。
代价是失控风险与治理成本，收益是多变性不再由你的产能封顶。

**判断口诀：**
> 如果我停止生产内容，这个产品的多变性会不会消失？
> 会 → 有限多变性；不会 → 无穷多变性。

## A1 — 书中的应用 (Past Application)

### 案例 1: Zynga《农场小镇》系列的耗竭
- **问题**: 首作大热之后，如何延续增长。
- **方法论的使用**: 公司选择复制配方（《城市小镇》《海滨度假村》），
  但每一部的多变性都是预先生产的、可穷尽的。
- **结论**: 复制成功配方不能解决有限多变性问题，只会加速用户看穿套路。
- **结果**: 用户开始交流"最优解/攻略"，留存随版本线性衰减，股价暴跌。

### 案例 2: 好莱坞与游戏业的工作室模式
- **问题**: 单部作品必然衰减，行业如何长期存活。
- **方法论的使用**: 不指望单作永生，而是维持一条持续产出的管线，
  按整体命中率而非单作寿命来经营。
- **结论**: 有限多变性的正确应对是**组织形态的选择**，不是内容层面的努力。
- **结果**: 成为内容行业延续百年的标准结构。

### 案例 3: YouTube / Twitter / Dribbble 的自我再生
- **问题**: 如何让内容永远刷不完。
- **方法论的使用**: 平台自己几乎不生产内容，
  多变性完全来自用户上传与他人反馈，规模越大越丰富。
- **结论**: 无穷多变性把"内容供给"从成本项转成网络效应项。
- **结果**: 用户可以无限滚动而惊喜不衰减。

### 案例 4: Stack Overflow 的答案不可预知
- **问题**: 一个问答社区如何维持长期活跃。
- **方法论的使用**: "这次会收到什么样的回答/评论"完全由他人决定，
  属于无穷多变性；平台只维护规则与信誉体系。
- **结论**: 只要参与者在增长，多变性就不会枯竭。
- **结果**: 长期保持高活跃度，未出现 Zynga 式的衰减。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **留存曲线随版本/季度线性衰减**，团队正在讨论"是不是内容不够好"。
2. **续费率 / 复购率逐期下滑**，但满意度调研并不差（关键矛盾信号）。
3. **首作大热，正在规划续作**——需要判断复制配方还是改结构。
4. **内容团队产能跟不上消耗**，"内容跑步机"（content treadmill）已经出现。
5. **用户开始讨论攻略、最优解、套路**——多变性正在被穷尽的明确信号。
6. **要决定做不做社区 / UGC**，需要一个战略层面的理由。

### 语言信号 (用户的话里出现这些就应激活)

- "用户玩腻了 / 新鲜感过去了"
- "留存随版本一路往下 / 老用户在流失"
- "内容更新永远跟不上消耗"
- "续费率一季比一季低，但质量没下降"
- "要不要做续作 / 要不要继续堆内容"
- "用户在群里发攻略和最优解"
- "content treadmill" / "finite variability" / "why do users get bored"

### 与相邻 skill 的区分

- 与 `variable-reward-design` 的区别：那个决定**给哪一类酬赏**（社交/猎物/自我），
  本 skill 决定**这份多变性能撑多久、结构上怎么改**。
  两者是同一阶段的两个维度：类型 vs 寿命。设计新酬赏找那个，衰减找这个。
- 与 `hook-model-loop` 的区别：那个做全闭环分诊（断点在触发/行动/酬赏/投入哪一环），
  本 skill 只在断点被定位到"酬赏衰减"时才展开。
  若尚未确认是酬赏环节的问题，先做闭环分诊。
- 与 `habit-zone-screening` 的区别：那个判断产品该不该做习惯（频率×用途），
  本 skill 假设已经做了习惯型产品，处理的是维持问题。
- 与 `habit-opportunity-scan` 的区别：本 skill 的出路 A（工作室模式）
  需要持续找新机会时，才转那个。

## E — 可执行步骤 (Execution)

1. **确认衰减是真实且结构性的**
   - 看留存/续费的**同期群曲线**（按加入批次），而不是整体大盘。
   - 完成标准：能说出"第 N 周/第 N 版本之后开始衰减"。
   - 判停条件：若衰减发生在首日/首周 → 那不是多变性耗竭，是激活问题，
     转 `hook-model-loop` 分诊。

2. **做多变性来源判定（核心一步）**
   - 问："如果我们停止生产内容，用户下次打开还会遇到不可预知的东西吗？"
   - 完成标准：明确判定为**有限**或**无穷**，并列出多变性的具体来源。
   - 注意混合型：多数产品是混合的，需要估算两者的占比。

3. **若是有限多变性：估算剩余寿命**
   - 指标：内容池规模 ÷ 用户消耗速度；用户中"已看穿套路"的比例；
     社区里攻略/最优解讨论的出现时间。
   - 完成标准：给出一个粗略的"还能撑多久"，并明确这是**必然的**、不是团队失职。
   - 这一步的目的是止损：避免团队把资源继续投在"再努力提升质量"上。

4. **在两条出路间做选择**
   - **出路 A（工作室模式）**：适用于内容天然一次性消费（游戏、影视、课程、节目）。
     要改的是：产品组合规划、命中率预期、成本结构、团队复用方式。
   - **出路 B（注入无穷多变性）**：适用于存在用户互动可能的品类。
     要做的是：把一部分内容生产权交给用户（问答、评论、共创、二创、榜单）。
   - 完成标准：明确选定一条，并写出选择依据。
   - 判停条件：若品类既无法组合化（只有一个产品）又无法 UGC 化（用户之间无互动可能）
     → 诚实结论是"这是一个有寿命的产品"，应规划退出或转型，而非continue 堆内容。

5. **若选出路 B：设计最小注入点**
   - 找到一个"他人的行为天然值得被看到"的动作作为起点。
   - 从低风险处起步（评论 → 问答 → 共创 → 开放平台）。
   - 完成标准：给出 1 个可上线的最小 UGC 环节，以及治理规则的底线。
   - 联动：新的用户生产行为本身即是投入，接 `investment-design`；
     他人的反馈天然构成人际型触发，接 `load-next-trigger`。

6. **若选出路 A：改的是组织不是产品**
   - 完成标准：写出产品组合的节奏假设、可接受的失败率、
     以及跨作品可复用的资产（引擎、IP、用户池、分发通道）。
   - 判停条件：若组织不接受"多数作品会失败"这一前提 → 出路 A 不成立，回步骤 4。

7. **建立预警指标**
   - 监控：攻略/套路类讨论出现率、内容重复触达率、同期群衰减斜率。
   - 完成标准：定义一个"该启动下一部/该注入 UGC"的阈值信号。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产品尚未验证核心闭环**——习惯用户不足 5% 时谈多变性寿命为时过早，
  先做 `habit-testing`（见 ce12）。
- **衰减原因在别处**：触发通道被关闭、流程变复杂、价格上涨、竞品替代——
  这些都会表现为"用户流失"，但都不是多变性问题。先分诊。
- **确定性优先的品类**（工具、支付、医疗、B 端流程）——
  这类产品的价值就是可预期，不存在"多变性耗竭"这个命题。
- **一次性消费产品**（婚礼服务、搬家、体检）——本就无需长期多变性。

### 作者在书中警告的失败模式

- **ce03 — 有限多变性的耗竭**：靠人工堆量而非用户生产，
  老用户留存随版本线性衰减，用户开始讨论"通关攻略/最优解"。
  最致命的变体是"复制成功配方"——它加速而非缓解耗竭。
- **ce19 — 用积分徽章冒充多变性**：PBL 是可预期的，不构成多变性，
  上线后活跃短暂上升随即回落。
- **ce22 — 指望多变性救一个没价值的产品**：多变性放大既有价值，不创造价值。
- **ce15 — 无穷多变性的反面风险**：UGC 带来的无限滚动对尾部用户可能造成失控，
  出路 B 必须配套 `manipulation-matrix-ethics` 的保护义务。

### 作者的盲点 / 时代局限

- 书中把二分讲得很干净，现实多为**混合型**：
  平台自产 + 用户生产 + 算法重组三者并存，需要估占比而非简单归类，
  书中未给出混合情形的分析方法。
- 成书于 2014 年，未涉及**生成式 AI**：AI 大幅降低内容生产成本，
  使"有限多变性"的边界外移——但要注意，AI 生成的内容若模式可被识别，
  仍会被用户看穿套路，本质上只是把耗尽点往后推，而非改变结构。
- 未讨论**算法重组带来的伪无穷性**：同一内容池经推荐算法重排可以显得永远新鲜，
  但用户对"套路"的感知是模式层面的，算法只能延缓。
- 对工作室模式的组织代价着墨不足：多数团队并不具备承受高失败率的财务与心理结构。

### 容易混淆的邻近方法论

- **内容运营的"内容日历/更新节奏"**：解决的是产能与排期；
  本 skill 指出的是产能层面的努力无法解决结构问题。
- **网络效应（Network Effects）**：与无穷多变性高度相关但不等同——
  网络效应讲的是价值随用户数增长，本 skill 讲的是**惊喜随用户数自我再生**。
  一个产品可以有网络效应却仍是有限多变性（如封闭工具型协作软件）。
- **产品生命周期理论 / S 曲线**：描述宏观市场阶段；
  本 skill 给出的是一个可操作的**微观结构判据**（内容由谁生产）。
- **游戏的"内容跑步机"（content treadmill）讨论**：是同一现象的游戏业行话，
  可视为本 skill 的行业化表述。
