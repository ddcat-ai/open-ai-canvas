## I — 方法论骨架 (Interpretation)

外部触发是"把信息传递给用户、告诉他下一步做什么"的载体。
按**获取方式与资源性质**分四类，四类的经济学完全不同：

| 类型 | 定义 | 成本结构 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| **付费型** | 买来的（广告、投放、CPA） | 持续付费，停投即停 | 获客、冷启动 | 买不到习惯，不可持续拉活 |
| **回馈型** | 靠公关/媒体/热榜/应用商店推荐换来的 | 需持续经营，不可控 | 短期爆发式获客 | 无法预期、无法复制、留存不解决 |
| **人际型** | 熟人推荐、分享、被 @、被点赞 | 边际成本近零，可病毒式扩散 | 高质量获客 **+** 部分拉活 | 需产品本身有可分享性 |
| **自主型** | 用户已授权的通道（通知、桌面图标、邮件订阅、日历） | 一次授权、长期使用 | **驱动重复参与的主力** | 需授权；滥用则被永久关闭 |

**结论一：获客与留存必须用不同类型的触发。**
前两类是"租用注意力"，后两类才是"拥有注意力"。
一款只靠付费型触发活着的产品并没有养成习惯（见 ce05）。

**结论二：自主型触发有授权前提，且不可再生。**
用户必须先同意（安装、允许通知、订阅）。
一旦通知被关闭、邮件被退订，这条通道基本无法收回——
它是四类中唯一"越用越少"的资源，必须像预算一样管理。

**结论三：时机 > 频次 > 文案。**
外部触发的作用是把用户从"内部触发发作的那一刻"接入产品。
投放时刻必须落在两个条件同时成立的窗口：
① 目标情绪正在发作；② 用户此刻有能力行动（B=MAT 里的 M 与 A 同时在线）。
统一时间群发几乎必然违背这两条。

## A1 — 书中的应用 (Past Application)

### 案例 1: Any.do 在"会议刚结束"投放触发
- **问题**: 待办类产品的提醒发早了没用（还没开完会），发晚了已经忘了。
- **方法论的使用**: 通过日历授权（自主型触发）识别会议结束时刻，
  在"刚散会、还记得刚才要做什么、且有几分钟空闲"的窗口弹出提示。
- **结论**: 时机由**情绪 + 能力的交集**决定，不是由运营排期决定。
- **结果**: 触发与用户当下心境高度契合，转化率显著高于定时提醒。

### 案例 2: YouVersion 按个人活跃时段推送
- **问题**: 统一时间群发经文推送，打开率平平。
- **方法论的使用**: 依据每个用户的历史阅读时段投放（有人是清晨，有人是睡前），
  把触发对准 c09 中发现的"孤独/寻求慰藉"时刻。
- **结论**: 自主型触发的价值在于**可个性化定时**，这是付费型触发做不到的。
- **结果**: 打开与完成率提升；圣诞节的特别推送甚至被用户主动截图分享，
  自主型触发顺势转化成人际型触发。

### 案例 3: Facebook 的人际型触发密度
- **问题**: 如何让用户在没有广告投放的情况下持续回访。
- **方法论的使用**: 把好友的点赞、评论、标记、生日全部变成通知，
  用户之间互为触发源，平台自身几乎不需要发起触发。
- **结论**: 人际型触发的规模随用户关系数增长，是唯一能"自我扩张"的触发通道。
- **结果**: 形成极高的自然回访频次。

### 案例 4: 亚马逊把"比价"变成自主型入口
- **问题**: 用户产生购物念头时，第一站未必是亚马逊。
- **方法论的使用**: 允许在自家 App 内查看竞品价格，把"比价冲动"这一外部行为
  内化为回到自家 App 的理由，使自己成为购物决策的默认入口。
- **结论**: 最好的自主型触发是"成为默认解决方案"，而不是多发一条推送。
- **结果**: 强化了"想买东西先打开亚马逊"的心理默认设置。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **推送打开率持续下滑**，团队正在讨论加大发送量（危险信号）。
2. **要设计召回 / 拉活方案**，需要决定用哪条通道。
3. **通知授权率低或关闭率上升**，需要判断是否在透支自主型通道。
4. **获客做起来了但留不住**——典型的"只有付费型触发"结构。
5. **要决定推送在几点发**、要不要做个性化时机。
6. **要设计分享 / 邀请机制**，即把产品接入人际型触发。
7. **预算讨论**：广告投放和产品内触发机制之间怎么分配。

### 语言信号 (用户的话里出现这些就应激活)

- "推送该怎么做 / 一天发几条 / 几点发"
- "push 打开率一直在掉"
- "召回策略 / 拉活方案 / 用户不回来了"
- "通知权限开启率太低 / 用户把通知关了"
- "投了很多广告但留存不行"
- "要不要做分享 / 邀请 / 裂变"
- "push notification strategy" / "re-engagement" / "owned vs paid channels"

### 与相邻 skill 的区分

- 与 `internal-trigger-mining` 的区别：那个找**情绪**（挂在哪），
  本 skill 定**渠道与时刻**（怎么送达）。顺序是先那个后这个；
  跳过那个直接做本 skill，结果必然是 ce05（买量续命）。
- 与 `load-next-trigger` 的区别：那个是**用户自己刚才的投入自动生成的**触发
  （发消息→对方回复→通知），来源是闭环内部；
  本 skill 涵盖全部四类外部触发，包括产品/运营主动发起的。
  若问题是"用户做完就走了、系统没生成任何后续提示"，转那个。
- 与 `autonomy-reactance` 的区别：那个处理"强制/被强加"引发的抵触；
  当自主型触发的问题是"默认开启、无法关闭、用户反感"时，两者要联用。
- 与 `bmat-behavior-diagnosis` 的关系：本 skill 只解决 T（触发）这一项。
  若触发已经送达且时机正确，用户仍不动，回去分诊 M 与 A。

## E — 可执行步骤 (Execution)

1. **确认内部触发已就位**
   - 需要一句："当【人】在【情境】感到【情绪】时，她希望【缓解】。"
   - 判停条件：拿不出这句话 → 先转 `internal-trigger-mining`，不要往下走。

2. **盘点现有触发，按四类型归类**
   - 列出目前所有把用户拉回来的方式，逐条标注类型。
   - 完成标准：得到四类型的占比。
   - 诊断：若 80% 以上流量来自付费型 + 回馈型 → 判定为"租用注意力"结构（ce05），
     核心任务是建立后两类通道，而非优化广告。

3. **区分获客触发与留存触发，分别定策**
   - 获客：付费型 / 回馈型 / 人际型。
   - 留存：自主型 / 人际型。
   - 完成标准：明确写出"这条触发是为了拉新还是为了回访"，不允许一条触发身兼两职而不加区分。

4. **为自主型通道做授权与预算管理**
   - 授权：在用户体验到酬赏**之后**再请求通知权限（顺序与 ce07 同理）。
   - 预算：给自主型触发设一个"每周条数上限"，并监控关闭率。
   - 完成标准：写出授权请求的时机，以及关闭率的红线值（超过即减量）。

5. **确定投放时刻：找到情绪发作窗口**
   - 从内部触发陈述反推：这个情绪一天中在什么时刻发作？
   - 用数据校验：现有用户的自然活跃时段分布（按个体，不按整体均值）。
   - 完成标准：给出个性化时机规则，而不是一个统一时间点。
   - 特别检查：那个时刻用户**有能力行动**吗（在开会/在开车 = 无能力）。

6. **改写触发内容：承接情绪，而非通报事实**
   - 反面："您有 3 条未读消息 / 该打卡了"。
   - 正面：直接接住情绪并给出低门槛的下一步（"今天只有 3 分钟？先过 5 个词"）。
   - 完成标准：每条触发文案都能对应到一个具体情绪。

7. **设计人际型触发的挂载点**
   - 找到产品中"一个用户的行为天然会让另一个用户想知道"的动作。
   - 完成标准：至少 1 条无需运营干预、由用户行为自动产生的触发链路。
   - 判停条件：若产品是纯单人工具、不存在此类动作 → 承认人际型通道不适用，
     把重心压在自主型 + `load-next-trigger`。

8. **建立监控**
   - 必看：通知关闭率、退订率（自主型通道的余额）。
   - 次看：分时段打开率、停投后的自然回访占比。
   - 完成标准：明确"什么信号出现就必须减少发送"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **内部触发尚未找到**——此时任何触发设计都是在给"没人想接的电话"选号码。
- **产品还没有可感知价值**——外部触发只会加速卸载（ce22）。
- **用户来了但完不成关键动作**——问题在 A 不在 T，转 `ability-simplification`。
- **低频品类**（年度体检、报税、买房）——不要试图用高频推送把低频行为习惯化（ce10），
  正确做法是把资源压在回馈型/人际型获客上，留存靠数据沉淀。
- **强制型 B 端流程**——用制度触发比用通知触发更有效，且不消耗自主型通道。

### 作者在书中警告的失败模式

- **ce05 — 只做外部触发，从不建立内部触发**：停投即断崖，获客成本永远摊不薄。
  警告信号：Push 是唯一回访来源；说不出用户"在什么情绪下"想起你。
- **ce18 — 触发投放时机与情绪脱节**：统一时间群发、不分人群，
  结果打扰用户、通知被关闭——**永久失去外部触发通道**。
  警告信号：打开率持续走低但仍在加大发送量（这是最危险的组合）。
- **ce02 — 强推功能触发逆反**：自主型通道的默认开启若越界，会引发抵触甚至撤回，
  联用 `autonomy-reactance`。
- **ce20 — 加载下一个触发缺失**：闭环第四步指不回第一步，
  于是只能靠运营手动推送——这是自主型触发被过度消耗的根因，转 `load-next-trigger`。

### 作者的盲点 / 时代局限

- 成书于 2014 年，当时通知权限管控远比现在宽松。
  如今 iOS/Android 的分级授权、摘要投递、系统级免打扰，
  使**自主型通道的稀缺性远超书中描述**——书里的"多发几条无妨"在今天是高风险动作。
- 四类型划分未涵盖今天常见的**算法分发型触发**（信息流推荐、系统级小组件、
  智能助理主动提示），这类触发的授权关系与四类型都不完全一致。
- 书中对**回馈型触发**的评价偏正面（PR/榜单），
  未讨论其不可预期性带来的规划风险——不应把它写进增长模型。
- 未讨论触发的**跨渠道疲劳**：同一用户同时收到 push + 短信 + 邮件 + 微信服务号，
  单渠道的关闭率看着正常，总疲劳度已经超标。

### 容易混淆的邻近方法论

- **增长黑客的 AARRR 漏斗**：关注各环节转化率；本 skill 关注触发的**资源性质与可持续性**，
  会明确指出"付费型触发的转化率再高也不构成习惯"。
- **CRM / 生命周期营销（Lifecycle Marketing）**：按用户阶段编排触达；
  本 skill 的差异是把"触发必须对齐内部触发的情绪发作窗口"作为硬约束，
  而非按注册天数排期。
- **Permission Marketing（许可式营销）**：与自主型触发的授权前提高度相似，
  可视为本 skill 该维度的扩展读物。
- **A/B 测试文案优化**：优化的是同一时刻的表达；
  本 skill 主张时机的收益远大于文案，顺序不能颠倒。
