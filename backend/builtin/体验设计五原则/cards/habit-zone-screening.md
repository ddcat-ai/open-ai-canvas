## I — 方法论骨架 (Interpretation)

在投入研发之前，先用一张二维图判断一个行为**有没有可能**变成习惯：

- **横轴：发生频率** — 这个行为自然情况下多久发生一次？
- **纵轴：可感知用途** — 用户觉得你的方案比他现在的做法好多少？

两者同时足够高，行为才落入"习惯区间"，才可能自动化。推论很硬：

- 频率不足 → 再有用也成不了习惯（报税软件一年用一次，用户永远记不住你）。
- 用途不足 → 再高频也留不住（用户会流失到更省事的替代方案）。

当两轴都不理想时，**优先攻频率**。因为可感知用途受制于技术与竞品，天花板明显；
而频率可以通过缩短循环周期、增加合理触发、降低单次成本来推动。
极端例证是谷歌与必应：盲测中结果质量差距并不显著，
但用户的高频搜索习惯让谷歌保持压倒性份额——**习惯本身成了可感知用途的替代品**。

第二个判据回答"要不要因为它不解决痛点就否决它"。
投资人爱问"你是维生素还是止痛药"，本书给出第三条路：
习惯养成类产品**出场时通常是维生素**（满足情感需要，不用也不痛），
但它通过反复循环把自己嵌进用户的内部触发，用户一旦停用就会**产生痒**——
此时它已变成止痛药。它自己制造了它要缓解的疼痛。

所以正确的立项问题不是"它现在解决刚需吗"，而是：
**它的自然频率够不够高，让它有机会把自己变成刚需？**

## A1 — 书中的应用 (Past Application)

### 案例 1: 谷歌 vs 必应
- **问题**: 必应的搜索质量在盲测中与谷歌不相上下，为什么份额差距巨大？
- **方法论的使用**: 作者指出搜索是极高频行为，长期高频使用已把谷歌固化为默认动作；
  当纵轴（质量差异）拉不开时，横轴（频率）积累出的习惯成为决定性变量。
- **结论**: 高频品类中，先形成习惯者的优势不需要靠持续的功能领先来维持。
- **结果**: 谷歌长期保持搜索市场主导地位。

### 案例 2: 亚马逊展示竞争对手价格
- **问题**: 允许用户在自家 App 里比价，不是把用户送走吗？
- **方法论的使用**: 亚马逊已处在极高频的购物入口位置，
  把"比价"这个高频动作纳入自身，等于加固横轴。
- **结论**: 高频入口的价值大于单次交易的流失风险。
- **结果**: 强化了"想买东西先打开亚马逊"的心理默认设置。

### 案例 3: Evernote 的微笑曲线
- **问题**: 一个"记笔记"这样看似可有可无的维生素型工具，如何变成付费刚需？
- **方法论的使用**: 随使用月数增长，用户沉淀的笔记（储存价值）越多，
  停用的痛感越强，维生素逐步转为止痛药。
- **结论**: 定位不是静态的，可以被循环改变。
- **结果**: 使用 33 个月后付费用户比例升至 26%，留存曲线在下滑后回升。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **立项/选赛道**：手上有几个方向，要判断哪个有做成高粘性产品的可能。
2. **被质疑"这是不是刚需"**：需要一个比"我觉得有用"更硬的判据来回应投资人或老板。
3. **低频产品焦虑**：明知用户一年只用几次，却在纠结要不要做推送、积分、社群。
4. **判断该先提频率还是先提体验**：资源有限，需要决定攻哪一轴。
5. **评估一个成熟品类能否被颠覆**：想知道自己"更好一点"够不够。

### 语言信号 (用户的话里出现这些就应激活)

- "这个值不值得做 / 有没有戏"
- "这算刚需吗 / 是不是伪需求"
- "用户会天天打开吗"
- "我们是低频产品，怎么提高留存"
- "投资人问我们是维生素还是止痛药"
- "is this a real need" / "our product is low frequency" / "vitamin or painkiller"

### 与相邻 skill 的区分

- 与 `hook-model-loop` 的区别：本 skill 回答"**该不该**做习惯设计"（前置门），
  hook-model-loop 回答"**怎么**做/断在哪"。顺序上本 skill 在前。
- 与 `habit-as-business-asset` 的区别：那个论证"习惯**能带来什么商业收益**"以及
  "为什么更好的产品打不动市场"（面向说服与竞争策略）；本 skill 判断"这个行为**能否**成为习惯"。
- 与 `habit-opportunity-scan` 的区别：那个是**主动寻找**新机会的扫描器，
  本 skill 是对**已有候选**做判定。

## E — 可执行步骤 (Execution)

1. **写出被评估的具体行为（不是产品名）**
   - 格式："某类用户在某情境下，做 ___ 这个动作。"
   - 完成标准：动作可观测、可计数。若只能写出"使用我们的 App"，说明还没想清楚。

2. **估横轴：自然发生频率**
   - 问：在没有你的产品时，这个行为**自然**多久发生一次？（不要用"我们希望他每天用"）
   - 参考刻度：每日多次 / 每日 / 每周数次 / 每周 / 每月 / 每季 / 每年。
   - 完成标准：给出一个频率区间和它的现实依据（同品类数据或合理假设）。
   - 判停条件：若自然频率 < 每月一次 → 直接跳到步骤 5（低频结论）。

3. **估纵轴：可感知用途**
   - 问：与用户**当前的做法**（含"什么都不做"）相比，你的方案好在哪，好多少？
   - 注意用"用户能感知到的差异"，而不是技术指标。
   - 完成标准：能说出一句用户会自己讲出来的对比句。
   - 交叉检查：若差距仅为"好一点点"，提醒调用 `habit-as-business-asset` 的 9 倍效应做折价。

4. **落点判定**
   - 双高 → 落入习惯区间，可以做习惯设计，转 `hook-model-loop`。
   - 高频 / 低用途 → 有机会，但要先补价值，否则做闭环等于给无用行为加装饰（见 ce22）。
   - 低频 / 高用途 → **不做习惯设计**，转为"高价值低频工具"策略（见步骤 5）。
   - 双低 → 建议放弃或重新定义行为。
   - 完成标准：明确写出落在哪一格及理由。

5. **低频情形的两条出路（不要硬做 hook）**
   - 出路 A：接受低频，改用回馈型/人际型触发获客，把留存寄托在**储存价值**上
     （用户的数据、历史、档案留在你这里），而不是推送。转 `investment-design`。
   - 出路 B：改变行为定义，把低频母行为拆出一个高频子行为
     （年度体检解读 → 日常指标追踪；年度报税 → 月度票据归集）。
   - 完成标准：给出选定的出路和它对应的第一个动作。

6. **做维生素/止痛药定位判断**
   - 问三件事：①现在停用它，用户会痛吗？②如果不会，循环多少次后会开始痒？
     ③这个"痒"来自哪种储存价值（内容/数据/关注者/信誉/技能）？
   - 完成标准：给出"当前是维生素/止痛药"的判定，以及转化路径的第一步。
   - 提醒：若答不出第③问，说明转化路径尚不存在，不要把"以后会变刚需"当作既成事实（见 ce09）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已经确认是高频品类、正在排查具体留存断点时——直接用 `hook-model-loop`，
  本 skill 会把讨论拉回已解决的问题。
- 需要用真实数据判断习惯是否已形成时——那是 `habit-testing` 的事，
  本 skill 是**事前估算**，不能替代事后测量。
- 评估的是一次性活动、营销 campaign、工具型内容（一份报告、一次培训）——
  这些本就不追求重复使用。
- 纯商业模型/单位经济测算——频率在这里是财务变量而非行为变量，判据不同。

### 作者在书中警告的失败模式

- **ce10 — 低频行为强行习惯化**：在买房、报税、婚庆等场景套用 hook，
  投入大量资源做 push、积分、社交，收效甚微。
- **ce09 — 做维生素却以为自己在做止痛药**：高估必要性，
  在习惯形成之前就假设用户离不开自己，从而低估获客与留存难度。
  警告信号：用户调研里出现"挺好的，但没它也行"。
- **ce22 — 相信 hook 能救没有价值的产品**：习惯放大已有价值，不能创造价值。
- **ce16 — 忽视 9 倍效应**：估纵轴时把"我们更好"当成用户能感知的差异，
  忽略了用户对现状的 3 倍高估与自己对创新的 3 倍高估。

### 作者的盲点 / 时代局限

- "习惯区间"没有给出量化阈值（多高算高频？），实际使用中依赖判断，
  容易被自我说服。建议强制写出频率的**现实依据**，而不是期望值。
- 本书隐含"高频=好"的价值预设，未讨论高频对用户注意力的负外部性；
  在今天做判断时应与 `manipulation-matrix-ethics` 配合。
- 谷歌 vs 必应的论证略过了分销、默认设置、品牌等非习惯因素，
  把结果全部归因于习惯有夸大之嫌。引用时应保留这一保留意见。

### 容易混淆的邻近方法论

- **PMF（产品市场匹配）**：PMF 问"有没有人要"，本 skill 问"要得够不够频繁"。
  一个产品可以有 PMF 但永远成不了习惯（如婚纱摄影）。
- **Jobs to be Done**：JTBD 挖的是任务与情境（更接近 `internal-trigger-mining`），
  不处理频率这个维度。
- **RFM 模型**：那是对既有用户的分层统计，本 skill 是对行为的事前判定。
