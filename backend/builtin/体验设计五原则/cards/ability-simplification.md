## I — 方法论骨架 (Interpretation)

"能力"不是抽象的"做得更简单一点"，而是六项可逐条排查的具体资源约束：

| 元素 | 含义 | 典型表现 |
|---|---|---|
| 时间 | 要花多久 | 表单太长、加载太慢、要等审批 |
| 金钱 | 要付多少 | 付费墙、押金、隐性成本 |
| 体力 | 累不累 | 要起身、要打字、要跑一趟 |
| 脑力 | 要不要动脑 | 要想密码、要做选择、要理解术语 |
| **社会偏差** | 会不会被他人视为异类 | 公开发言、举报、暴露隐私、被同事看见 |
| **非常规性** | 与既有例行行为偏离多远 | 要求学一套全新的做法 |

后两项是本书最容易被漏掉、也最有价值的两项——多数人做"简化"时只看前四项。

**核心纪律一：能力由最短板决定。** 找到最稀缺的那一项，只优化它。
六项均匀发力是浪费，而且往往会漏掉真正卡住用户的那一项。

**核心纪律二（Hauptly 三步删减法）：**

1. **先理解用户使用产品的根本原因**（回到内部触发）；
2. **列出用户从触发到获得酬赏的所有步骤**——包括心理步骤，
   如"要想一下密码""要判断该选哪个""要鼓起勇气"；
3. **一步步删，删到不能再删。**

第一步是必要前置，不是客套话：**不理解目的就删步骤，会删掉承载价值的那一步。**
很多"极简改版"把产品做没了，就是跳过了第一步。

## A1 — 书中的应用 (Past Application)

### 案例 1: Twitter 的 140 字限制
- **问题**: 让普通人公开发布内容，时间与脑力成本都很高。
- **方法论的使用**: 用硬性字数上限同时削减"时间"（写得快）与"脑力"（不需要谋篇布局）。
- **结论**: 约束在福格意义上是能力的提升，不是功能的削减。
- **结果**: 发布门槛被压到极低，内容供给量爆发。

### 案例 2: iPhone 锁屏直达相机
- **问题**: 想拍下眼前一瞬，但解锁—找图标—打开 App 的过程让瞬间溜走。
- **方法论的使用**: 削减"时间"与"体力"，把关键路径从四步压到一步。
- **结论**: 抓拍这个行为的能力短板是时间，不是操作复杂度。
- **结果**: 手机摄影成为高频行为，也成就了 Instagram 的行动阶段。

### 案例 3: 一键登录（用已有账号登录）
- **问题**: 注册环节大量流失。
- **方法论的使用**: 短板是"脑力"（记密码、想用户名）而非"时间"，
  因此解法是复用已有身份，而不是把表单字段从 8 个减到 6 个。
- **结论**: 找对短板，改造量小而效果大。
- **结果**: 成为行业标配。

### 案例 4: YouVersion 音频版
- **问题**: 用户在通勤、做家务时无法阅读。
- **方法论的使用**: 短板是"体力/注意力"（要腾出眼睛和手），
  解法不是缩短经文，而是换一种消费形态。
- **结论**: 简化不等于"减少内容"，而是"减少所需资源"。
- **结果**: 使用场景大幅扩展，完成率上升。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **流程/表单/引导太长**，明确要做减法，但不确定该减哪里。
2. **改版做了简化但效果不明显**——多半是优化了非短板项。
3. **明明很简单的事却没人做**（内部意见箱、匿名反馈、员工互评、公开提问）——
   这类场景的短板通常是社会偏差，而非操作步骤。
4. **要推行一个与用户既有做法差别很大的新方式**——短板是非常规性。
5. **要设计新手引导**，需要决定第一步只留什么。

### 语言信号 (用户的话里出现这些就应激活)

- "流程太长了 / 步骤太多 / 表单太复杂"
- "怎么降低门槛 / 减少摩擦"
- "新手引导该怎么设计"
- "东西很简单，但就是没人愿意做"
- "用户嫌麻烦"
- "simplify this flow" / "reduce friction" / "shorten onboarding" / "too many steps"

### 与相邻 skill 的区分

- 与 `bmat-behavior-diagnosis` 的区别：那个是**分诊**（缺的是 M/A/T 哪一项），
  本 skill 是分诊结论为"缺 A"后的执行工具。若用户还不确定原因，先用那个。
- 与 `investment-design` 的区别：**方向相反且必须区分清楚**。
  本 skill 用于**行动阶段**（酬赏之前），此处一切多余步骤都要删；
  那个用于**投入阶段**（酬赏之后），此处适度摩擦反而提升留存。
  判断口诀：这一步在用户"爽到"之前 → 删；之后 → 可能要留。
- 与 `autonomy-reactance` 的区别：那个处理"用户抗拒被强加"的心理阻力，
  本 skill 处理"用户做不到"的能力阻力。社会偏差与非常规性两项与它相邻，
  若阻力来自"被强制"而非"做不到"，转那个。

## E — 可执行步骤 (Execution)

1. **锁定一个具体的目标行为**
   - 格式："某个具体的人，在某个时刻，完成 ___。"
   - 完成标准：可观测、可计时、有明确起点与终点。

2. **先回答"用户为什么要做这件事"（Hauptly 第一步，不可跳过）**
   - 回到内部触发：他此刻在躲什么难受、想解决什么？
   - 完成标准：能写出一句情绪层面的答案，而非功能层面的答案。
   - 判停条件：若答不出 → 先转 `internal-trigger-mining`，
     否则后面的删减会删掉承载价值的步骤。

3. **列出全部步骤，包括心理步骤**
   - 物理步骤：点击、输入、跳转、等待、切换设备。
   - 心理步骤：要回忆什么、要判断什么、要犹豫什么、要克服什么顾虑。
   - 完成标准：清单里至少出现 1 条心理步骤。只列物理步骤说明没列完。

4. **对每一步标注它消耗的元素，找出最短板**
   - 六选一或二：时间 / 金钱 / 体力 / 脑力 / 社会偏差 / 非常规性。
   - 完成标准：明确指出全流程的**最短板项**，并说明它在此场景的具体表现。
   - 特别提示：若目标行为涉及"公开""署名""被人看见""举报""求助""暴露状态"，
     优先怀疑**社会偏差**；若涉及"要求用户换一套做法"，优先怀疑**非常规性**。

5. **只针对短板做删减/替换**
   - 时间 → 减字段、预填、异步化、默认值
   - 金钱 → 免费额度、先用后付、去押金
   - 体力 → 换形态（语音/音频/拍照替代输入）、减少设备切换
   - 脑力 → 复用已有身份、减少选择、去术语、给样例
   - 社会偏差 → 匿名/延迟公开/批量发布/第三方托管/私密默认
   - 非常规性 → 不发明新行为，改造既有行为（转 `autonomy-reactance` 的改良原则）
   - 完成标准：给出 1–3 个针对短板的改造动作，并说明预期删掉哪些步骤。

6. **删到不能再删，然后停手**
   - 停止条件：再删就会伤到步骤 2 里写下的"使用原因"。
   - 完成标准：明确指出哪一步是**不能删**的，以及为什么。
   - 反向检查：删完之后，产品是否还有可沉淀的储存价值？
     若一切都零成本了、用户走了不心疼 → 提示 ce08 风险，转 `investment-design`。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **在投入阶段做简化**——酬赏之后的适度摩擦是有价值的，
  盲目删除会摧毁储存价值（见 ce08）。用 `investment-design`。
- **尚未分诊就动手删**——若真实断点在触发时机或动机，简化再多也没用。
- **阻力来自"被强制"而非"做不到"**——那是逆反心理，
  简化不能解决，转 `autonomy-reactance`。
- **核心价值本身需要复杂度**（专业工具、创作软件、医疗流程）——
  这类产品的长期忠诚恰恰来自用户投入的技能（见 Photoshop 案例）。
  只在**首次行动**处简化，不要削平整个产品。
- 纯视觉美化、性能优化、代码重构——不是能力问题。

### 作者在书中警告的失败模式

- **ce04 — 强化动机而不提升能力**：反过来说，也不要在真正缺动机时死磕简化。
- **ce08 — 把"降低门槛"教条化**：删掉所有需要用户投入的环节，
  结果产品没有储存价值，用户零成本迁移到竞品。
  警告信号：用户走了不心疼、产品无个性化沉淀、留存曲线始终平坦无回升。
- **ce07 — 在酬赏之前索取投入**：注册即要求填完整资料、邀请好友——
  这属于行动阶段的门槛，应删（与 ce08 的边界：删的是酬赏**之前**的索取）。
- **ce19 — 用积分掩盖门槛**：给一个难用的流程加积分，不解决能力问题。

### 作者的盲点 / 时代局限

- 六元素之间可能冲突：省时间往往增加脑力（更少步骤 = 每步信息更密），
  书中未讨论权衡方法，实践中需要取舍。
- "社会偏差"在书中着墨极少（只是列举），但在企业内部产品、
  健康/心理/金融等敏感品类中往往是首要短板，需要自行外推。
- Hauptly 三步默认设计者能观察到全部步骤；对复杂 B 端流程或跨部门流程，
  步骤往往在系统之外（要打电话、要找人签字），需要走查而非凭想象列举。
- 本书成书于移动早期，未涉及语音/对话式/AI 代办这类"把步骤整体外包"的新形态，
  但六元素框架本身对这些形态依然适用（AI 代办主要削减脑力与时间）。

### 容易混淆的邻近方法论

- **可用性测试 / 尼尔森启发式**：找的是界面上的**错误与困惑**；
  本 skill 找的是**资源门槛**。一个流程可以毫无可用性问题却依然门槛过高。
- **精益的浪费消除（Lean/7 wastes）**：面向生产流程效率；
  本 skill 面向单个用户的行为可行性，判据是六元素而非工时。
- **助推（Nudge）/ 默认选项设计**：可视为削减"脑力"的一类手法，属于本 skill 的子集。
- **MVP 精简功能**：那是决定"做什么"，本 skill 是决定"怎么做得更容易"。
