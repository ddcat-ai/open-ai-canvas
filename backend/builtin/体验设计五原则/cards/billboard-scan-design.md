## I — 方法论骨架 (Interpretation)

版面设计的正确类比不是书，是高速公路旁的广告牌：只有几秒，观看者在移动，
注意力是借来的。因此版面的任务不是"把内容摆好看"，而是**在几秒内把结构投递出去**。

六条法则，按修复优先级排列：

**1 利用习惯用法（convention）**。logo 在左上并链回首页、搜索在右上、购物车图标、
下划线蓝字可点——这些惯例的价值在于用户已经替你付过学习成本。打破惯例 = 向每个用户
重新收一次学习税。打破的门槛只有两条：要么不学就懂，要么带来的价值明显更大。
"想显得不一样"不构成理由。

**2 建立清晰的视觉层次**。三条对应关系必须成立：越重要的看起来越突出；
逻辑上相关的看起来相关（同样的字号/颜色/缩进）；包含关系用视觉嵌套表达。
这不是审美，是**替用户做预处理**——你现在花的排版功夫，等价于每个用户省下的解析工夫。

**3 把版面划分为定义明确的区域**。用户要能一眼判断"哪块是我要的、哪块可以整块忽略"。
区域不清 = 用户必须逐个元素判断。

**4 让可点击的地方一望即知**。形状、位置、格式三重线索。扁平化设计削弱了这条通道，
必须用其他方式补偿（颜色、边框、位置惯例、微阴影）。

**5 降低视觉噪声**。三类噪声：喧闹（什么都在喊，都想抢注意）、混乱（缺乏组织）、
背景杂音（大量低强度的小干扰）。默认动作是删，不是重新排布。

**6 为扫描而排版**。标题必须紧贴它下面的正文（而不是漂在两段之间）、段落短、
能列表化就列表化、用留白分组而不是用线条分割。

**移动语境的补充（第10章）**：小屏放大了取舍压力；没有 hover 意味着失去了"这能点"
和"这是什么"两条廉价提示通道，必须显性补偿；藏进汉堡菜单的东西约等于用户看不见的东西。

## A1 — 书中的应用 (Past Application)

### 案例 1: 标题漂浮在两段之间
- **问题**：标题上下留白相同，读者无法判断它属于上一段还是下一段。
- **方法论的使用**：视觉接近性（法则 2 与法则 6）——空间距离必须表达逻辑归属。
- **结论**：标题应贴近它所引导的正文。
- **结果**：作者在全书末尾的"决定性答案"清单里把这条又重复了一遍，说明它高频且易犯。

### 案例 2: 创新 vs 惯例
- **问题**：设计师想用新颖的导航形式表现创意。
- **方法论的使用**：法则 1 的两条门槛——不学就懂，或价值明显更大。
- **结论**：在可用性这一目标函数下，创新的举证责任在创新方。
- **结果**：默认选择惯例；确要创新时，必须先说明"用户为什么不用学就会"。

### 案例 3: 三类视觉噪声
- **问题**：页面"很满"，团队想不出砍哪个。
- **方法论的使用**：把"乱"拆成喧闹/混乱/背景杂音三类，分别对应不同动作
  （降低强度 / 重新分组 / 删除）。
- **结论**：模糊的"太乱"可以被还原为可操作的三类问题。
- **结果**：从"整体重设计"变成"逐类处理"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到一个页面/落地页/仪表盘/海报，觉得"乱、重点不突出、不知道先看哪"。
2. 要做一份需要被快速扫读的材料：PPT、单页说明、活动海报、README 首屏、月报。
3. 团队在争论"要不要跟竞品长得不一样"。
4. 移动端改版：内容放不下、按钮认不出、hover 提示没了。
5. 后台/内部工具的列表页、表单页密密麻麻，同事抱怨找不到东西。
6. 按钮"看起来不像能点"，或者反过来，"不能点的东西被一直点"。

### 语言信号（用户的话里出现这些就应激活）

- "页面太乱 / 太满 / 重点不突出 / 眼睛不知道往哪放"
- "这个按钮不像按钮 / 用户不知道这能点"
- "排版怎么改 / 层次感 / 视觉引导"
- "要不要跟别人不一样 / 我们想做点创新的交互"
- "cluttered / visual hierarchy / scannable / affordance / above the fold"

### 与相邻 skill 的区分

- 与 `frontend-dev` 的区别：那是工程实现层（框架、组件、样式代码、构建、性能）；
  本 skill 只判断版面的认知结构，不产出代码。先用本 skill 定方案，再交给 frontend-dev 实现。
- 与 `dont-make-me-think-audit` 的区别：那个是**通用问号审查**（覆盖命名、流程、术语等）；
  本 skill 专注**单页视觉版面**，给出的是六条具体的排布法则。
- 与 `guizang-ppt-skill` / `awesome-design-md` 等出版式/风格类 skill 的区别：
  那些提供风格与产出模板；本 skill 提供的是判断标准，可以用来评审它们的产出。
- 与 `trunk-test-navigation` 的区别：那个管**跨页的方位感**（我在哪、能去哪）；
  本 skill 管**单页内部**的信息投递。

## E — 可执行步骤 (Execution)

1. **做 5 秒曝光测试，记录"扫到了什么"**
   - 看 5 秒后立刻写下：记住了哪三样东西？最显眼的是什么？
   - 完成标准：写下的三样东西与设计者的期望对比，差异即为问题清单起点。

2. **法则 1｜惯例审计**
   - 列出本版面偏离常见惯例的地方（位置、图标、命名、交互）。
   - 每处追问：不学就懂吗？价值明显更大吗？两问皆否 → 改回惯例。
   - 完成标准：每处偏离都有明确裁决（保留 + 理由 / 改回）。

3. **法则 2｜视觉层次校验**
   - 三条对应关系逐条检查：重要性↔突出度、相关性↔视觉相似、包含关系↔视觉嵌套。
   - 完成标准：能画出一张"视觉重要性排序"，并与"实际业务重要性排序"逐项比对。

4. **法则 3｜区域划分**
   - 用方框把版面切成 3–7 个区域，每个区域用一个词命名。
   - 判停条件：若无法命名或区域超过 7 个 → 结构问题，先分组再继续。

5. **法则 4｜可点性检查**
   - 列出所有可交互元素，逐个判断形状/位置/格式三线索是否至少命中两条。
   - 移动端追加：没有 hover 时是否仍可辨认？点击热区是否够大？
   - 完成标准：每个可交互元素都有"可辨认"结论。

6. **法则 5｜降噪（默认动作是删）**
   - 分类标注噪声：喧闹 / 混乱 / 背景杂音；对应动作：降强度 / 重新分组 / 删除。
   - 完成标准：给出一份"建议删除清单"，且清单非空（几乎不存在无可删的版面）。

7. **法则 6｜为扫描排版**
   - 标题贴紧其下文；段落拆短；能列表化的列表化；用留白而非线条分组；
     关键词前置到句首（中文尤其重要）。
   - 完成标准：改造后再做一次 5 秒曝光测试，对比步骤 1 的结果。

8. **输出**
   - 一张表：位置 / 违反的法则 / 具体改法 / 优先级；外加"要不要打破惯例"的单独裁决。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **问题不在单页版面时**：如果用户找不到东西是因为分类错了、流程绕了、内容根本不存在，
  再怎么排版也没用。此时转 `trunk-test-navigation`（方位感）或信息架构方法。
- **品牌视觉识别体系设计**（VI、色彩系统、字体系统）：本 skill 的目标函数只有"可扫描"，
  完全不考虑品牌表达。
- **沉浸式/艺术性体验**：叙事型网站、游戏界面、展览页面，其目标是让人停留和探索，
  与"几秒内投递结构"直接冲突。
- **纯工程任务**：写组件、调样式、优化性能 → `frontend-dev`。

### 作者在书中警告的失败模式

- **为了创新而打破惯例**。作者的门槛很硬：不学就懂，或价值明显更大；仅仅"想不一样"不够。
- **靠加线条/加边框来"整理"版面**。这是在增加噪声；正确工具是留白与分组。
- **标题漂浮**在两段之间——作者在全书最后的"决定性答案"里特意又强调了一次。
- **移动端把重要功能藏进汉堡菜单**：等于让它消失。

### 作者的盲点 / 时代局限

- 第 3 版正文写于 2013 年。书中把**扁平化当作"目前最新潮流"**，而今天设计已回摆到
  重新强调按钮边框与阴影（正是为了修复法则 4 被削弱的问题）；书中说
  **"响应式设计非常烦琐、难以完善"**，今天响应式是默认工程实践。
  **凡涉及具体控件样式、设备形态、浏览器行为的判断，需在当代移动端与 App/小程序语境下重新检验。**
- **惯例优先会抹平差异化**：以可用性为唯一标准时创新几乎总是输，这对新品类产品、
  品牌表达型产品不利。务实折中：在**任务链路**上守惯例，在**品牌表达面**（视觉气质、
  动效、文案语气）上创新。
- 中文语境未校准：中文无空格分词导致扫描锚点不同；中国用户以移动/小程序为主入口，
  桌面 Web 的部分排版惯例使用频率低。
- 只诊断不生成：本 skill 能判断版面好坏，不能替你生成一版设计。

### 容易混淆的邻近方法论

- **格式塔原则（接近、相似、闭合）**：本 skill 的法则 2、3、6 本质是格式塔的应用版；
  需要理论依据时可回溯，日常执行用本 skill 更快。
- **F 型/Z 型浏览模型**：给出扫描路径形状，可与法则 6 的"关键词前置"配合使用。
