## I — 方法论骨架 (Interpretation)

这本书前十章讲的都是"清楚"——让用户不费力就能看懂、找到、点对。第 11 章加了一个
**正交的维度：值得尊敬**。一个页面可以完全清楚，同时非常令人反感。

核心建模是把用户耐心视为**存量而非判断**：

- **它是水位，不是开关。** 用户不是"满意/不满意"的二值，而是带着一个水位进门，
  每次摩擦降一点，每次体贴升一点。行为（离开、投诉、发帖骂）发生在水位见底那一刻，
  而不是在某个单一设计缺陷发生时。这解释了一个常见现象：投诉的导火索往往是件小事，
  因为前面已经扣光了。
- **初始水位不由你决定。** 因人而异（有人天性多疑），因情境而异（他刚在别处受了气、
  他很赶时间）。**所以不能指望它高。**
- **可以重新注满。** 犯了错之后，只要让用户相信你在为他着想，水位能回升。
- **也可能被一件小事直接清零。** 例如"只是打开一个有大量字段的注册表格"。
  作者特别点明这一点——存量模型不是线性的，存在一次性归零的触发器。
- **后果溢出到产品之外。** 不只是离开：不再想用、不再重视这家公司、在社交平台上开火、
  NPS 下降。好感的损耗是**品牌资产的直接损耗**——作者的强论断是，
  一个页面上的沉默可以抵消每年数百万的品牌投入。

**降低好感的六类动作**（都可归结为"你让用户感到你不关心他的利益"）：
① 隐藏我想要的信息（客服电话、运费、价格）② 因为我不按你的方式做而惩罚我
（信用卡号不许有空格之类）③ 索要不必要的信息 ④ 敷衍我、假装关心
⑤ 给我设障碍（长动画、层层自吹的市场页面）⑥ 外观业余、组织混乱。

关于隐藏，作者给出一条**贯穿性的判据**：**用户迟早会知道吗？** 如果会，
隐藏并不能避免负面反应，只是把它**延后并放大**——藏电话号码的结果是他找到号码时更恼火；
藏运费的结果是在结算页放弃购物车并记住你。反向的例子同样有力：把 800 电话
放在每个页面上，反而让人在网站上停留更久、更可能自助解决问题。

**提高好感的八类动作**（多为上述的镜像）：① 知道人们最想做的三件事并让它们极其容易
② 有话直说（运费、停车费、暂停服务、你不想放前面的一切）③ 尽量减少步骤
④ 花点心思（惠普支持站四标准：信息齐、准确有用、表达清楚、组织易找）
⑤ 预判疑问并回答——真 FAQ，而非 **QWWPWA**（Questions We Wish People Would Ask，
"我们希望人们会问的问题"）⑥ 提供打印友好页之类的协助 ⑦ 让人容易从错误中恢复
⑧ 做不到时坦率道歉，至少让对方知道你清楚给他造成了不便。

最后有一条**冷静的例外**：作者明确承认"故意对用户不友好"可以是合理的商业决定
（弹窗惹人烦但带来 10% 收益，你认为值得，那就用）。他的要求只有一条：
**确定你是有意这么做的，而不是无心之举。** 这条把整个 skill 从道德说教
变成了一个显式的成本核算工具。

## A1 — 书中的应用 (Past Application)

### 案例 1: 罢工期间只字不提的航空公司官网（抽水）
- **问题**：作者订了票，恰逢航司与工会谈判最后期限。主页、搜索、FAQ 全站找不到任何
  与罢工相关的字句。
- **方法论的使用**：作者逐屏记录了自己的水位变化——扫主页（略降）、看到组织良好的新闻链接
  （回升）、发现都是无关新闻（降）、点进 About Us 看到推销机票（大降）、搜"罢工"
  只搜到一年前和 1950 年代的旧闻（几乎见底）、翻完 FAQ 离开。
- **结论**：不管动机是哪一种（没有应急更新机制／法务顾虑／以为旅客不关心／嫌麻烦），
  代价都一样——"他们每年花上数百万美元打造的品牌，对我而言绝对失色不少"。
- **结果**：确立"用户最关心的那件事若在你这里沉默，代价按品牌资产计"。

### 案例 2: 藏电话号码与藏运费（抽水，含反证）
- **问题**：藏电话为省客服成本，藏价格为制造"已投入感"（机场无线接入要点三个页面
  才看到收费提示）。
- **方法论的使用**：用"迟早会知道吗"判据反推——用户终究会打电话、终究会看到运费，
  隐藏只是把愤怒延后并放大。反向证据：800 号码到处可见反而延长停留、提高自助解决率。
- **结论**：隐藏在漏斗指标上是赚的，在存量上是亏的，且亏损滞后显现。
- **结果**：成为"有话直说"的最强论据。

### 案例 3: 惠普技术支持站与真 FAQ（注水）
- **问题**：帮助内容怎样才算"花了心思"。
- **方法论的使用**：作者给出四条可检验标准（产生解决问题所需的信息／准确有用／
  表达清楚／组织良好易找），验证方式很朴素："我买了很多惠普打印机，
  几乎每次有问题都能自己解决。"配套的 FAQ 三条：是真问题而非 QWWPWA 软推销、
  让客服每周提供问得最多的五个问题并置顶、对"你不希望他们问到的问题"保持坦率。
- **结论**：坦率地回答尴尬问题，是涨好感效率最高的动作之一。
- **结果**：把"礼貌"落成可执行的内容运营标准。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要决定某个信息**提前说还是往后放**：运费、总价、附加费、锁定期、退订方式、
   审核时长、库存与工期。
2. 用户/客户在抱怨"你们根本不在乎""这是在耍我"，但界面本身并没有做不到的功能。
3. 设计注册/申请/预约表单，纠结要几个字段、要不要强制手机号。
4. 写故障公告、延期通知、涨价通知、政策变更、下架说明、道歉信。
5. 写 FAQ / 帮助中心 / 客服话术 / 退款政策，或发现现有 FAQ 全是软推销。
6. 团队在讨论"把客服入口藏深一点能省多少成本"。
7. 事情已经搞砸了，要想怎么把关系修回来。
8. 明知某个做法会惹人烦但可能赚钱，需要一个显式的核算框架来做决定。

### 语言信号（用户的话里出现这些就应激活）

- "用户为什么这么生气 / 明明功能都有啊 / 他们说我们不真诚"
- "运费/价格要不要提前显示 / 结算页才说会不会被骂"
- "客服电话放不放出来 / 入口藏深一点"
- "这个表单要不要这么多字段"
- "FAQ 怎么写 / 帮助中心 / 道歉信 / 故障通报 / 涨价怎么说"
- "goodwill / trust / user frustration / 用户体验很差但说不出哪差"

### 与相邻 skill 的区分

- 与 `dont-make-me-think-audit` 的区别：那个问"**清楚吗**"（认知负荷）；
  本 skill 问"**值得尊敬吗**"（情绪与信任）。两个正交维度，一个页面可以极清楚又极讨厌。
  遇到"功能都能用但用户就是不爽"，答案通常在本 skill。
- 与 `manipulation-matrix-ethics` 的区别：那个判断"这个设计**该不该做**"（伦理越界），
  本 skill 判断"这个设计**会花掉多少好感**"（代价核算）。本 skill 明确容许
  "有意为之的不友好"，伦理裁决交给那个 skill。判据分工：涉及欺骗、诱导、
  用户知情后不会同意 → 那个；只是让人不爽但不欺骗 → 本 skill。
- 与 `reciprocity-debt` 的区别：那个是"先给好处制造回报义务"的影响力机制（进攻性）；
  本 skill 是"避免消耗与主动补充信任存量"（防守性），且不以换取顺从为目的。
- 与 `liking-paths` 的区别：那个建立人际好感以推动事情；本 skill 处理的是
  产品/机构与用户之间的信任水位，动作在页面与政策上，不在人际交往上。
- 与 `positioning-outside-in` 的区别：那个解决"信息如何被接受"；
  本 skill 解决"信息该不该早说、说得诚不诚"。
- 与 `omit-needless-words` 的区别：那个删的是无用文字；本 skill 有时要求**加**内容
  （提前披露运费、坦率回答尴尬问题）。冲突时以本 skill 优先——
  隐瞒省下的字数不算精简。

## E — 可执行步骤 (Execution)

1. **画一次水位曲线（诊断）**
   - 沿用户的真实路径逐屏走一遍，每一步标 ↑ / → / ↓ 及原因一句话。
   - 特别标出**归零触发器**：超长表单、强制注册、突然出现的费用、
     找不到人工客服、明显的敷衍话术。
   - 完成标准：得到一条带节点的水位曲线，能指出最陡的那一跌在哪。

2. **跑抽水六项检查**
   - ① 我藏了什么信息？（客服联系方式、运费、总价、附加条款、退订入口）
   - ② 我在因为格式/流程不迁就用户而惩罚他吗？（不许空格、必须特定格式、
     必须先注册才能看）
   - ③ 我要了哪些与当前任务无关的信息？逐字段问"这个字段现在必须要吗"。
   - ④ 哪里在敷衍？（"您的电话对我们很重要"式套话、无意义的自动回复）
   - ⑤ 我设了什么障碍？（开屏动画、层层推销页、强制看完引导）
   - ⑥ 外观是否显得业余、混乱、没下功夫？
   - 完成标准：六项各有结论，命中项进入修复清单。

3. **对每个"隐藏"做迟早判据**
   - 提问："用户迟早会知道这件事吗？"
   - 会 → 隐藏只是延后并放大愤怒，改为**提前披露 + 解释 + 降低摩擦**。
   - 不会（且属于合规可保留的商业信息）→ 记录为有意保留，写明理由。
   - 完成标准：每一处隐藏都有"提前说"或"有意保留+理由"的明确归属。

4. **跑注水八项检查**
   - ① 用户最想做的三件事是什么？它们现在是否极其容易？（三件事通常团队答案一致）
   - ② 有话直说：把运费/费用/限制/时长提到最前面。
   - ③ 步骤能不能再少一步。
   - ④ 花心思四标准（信息齐 / 准确有用 / 表达清楚 / 组织易找）。
   - ⑤ 真 FAQ：让客服提供**本周问得最多的五个问题**置顶；保持更新；
     对你不希望被问到的问题保持坦率。
   - ⑥ 提供实际协助（打印/导出/一键复制/进度可查）。
   - ⑦ 错误可优雅恢复（不清空已填内容、明确说怎么改）。
   - ⑧ 做不到时道歉：说明你知道这给对方造成了不便。
   - 完成标准：至少落地 3 项注水动作，其中必须包含 ② 或 ⑤。

5. **QWWPWA 清洗**
   - 逐条审现有 FAQ：这是用户真的在问，还是我们希望他们问？
   - 后者删除或移入营销页；空出的位置放客服提供的真实高频问题。
   - 完成标准：FAQ 前五条全部来自真实咨询记录。

6. **有意为之的不友好：显式核算**
   - 若某个惹人烦的做法确有收益（弹窗、强制注册、限时压迫），
     写下三行：预期收益 / 预计好感代价与显现时点 / 决策人。
   - 完成标准：它是一个**被记录的商业决定**，而不是没人负责的默认状态。

7. **危机与坏消息模板（故障/延期/涨价/罢工级事件）**
   - 顺序固定：**先承认事实 → 说明对我有什么影响 → 我现在能做什么 →
     你们会做什么、什么时候 → 不确定的部分明说不确定**。
   - 放置位置：用户最先看到的地方（首屏/推送/入口浮层），不是公告页第三级。
   - 完成标准：用户最关心的那一个问题，在第一屏就被正面回答。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **需要裁决伦理越界**：默认勾选订阅、伪装按钮、劫持首页、诱导授权、暗黑模式——
  转 `manipulation-matrix-ethics`。本 skill 只算代价，不划红线。
- **问题是"看不懂/找不到"的纯认知问题**：转 `dont-make-me-think-audit`
  或 `billboard-scan-design`。
- **要靠好感直接换转化率**：好感是滞后、间接、难归因的变量。把它当短期增长杠杆
  会失望，也会诱使团队做讨好式的表面动作。
- **强合规场景下的信息披露**：金融、医疗、保险的披露要求由法规决定，
  不由"会不会掉好感"决定。

### 作者在书中警告的失败模式

- **以为省下的是成本**：藏客服电话省的是话务费，花掉的是信任，且账单延后到达。
- **虚假的真诚**："您的电话对我们很重要"——用户识别虚伪的能力远高于设计者的预期。
- **QWWPWA**：把软推销伪装成 FAQ，是同时浪费版面和信任的做法。
- **对颜色意见的过度反应**：作者提醒——人们爱评论外观尤其颜色，但几乎没人只因"不够好看"
  就离开。用户测试中的颜色评论可以忽略，**除非有三四位用户用到了"令人作呕"这种词**。
- **无心之失最贵**：绝大多数好感损耗不是有意为之，而是没人想过这件事。

### 作者的盲点 / 时代局限

- **储存器模型无法量化**。它是一个好用的思维隐喻，但没有刻度：你不知道当前水位是多少、
  某个改动值几厘米。因此它适合做**方向判断与事前预防**，不适合做 A/B 收益预测。
  想量化只能借助 NPS、客诉率、退订原因、评论文本情感等代理指标，作者只顺带提了 NPS。
- **"迟早会知道"判据的时代变化**：2013 年信息还相对不透明；今天比价插件、
  黑猫投诉、小红书避雷帖、应用商店评论使"迟早"从数周缩短到数小时，
  **隐藏的收益进一步下降、代价进一步上升**，该判据只会更成立。
- **伦理立场偏软**：作者容许"有意为之的不友好"（弹窗换 10% 收益）。
  按今天的法规环境（个保法、诱导续费监管、GDPR 同意要求），
  当年被视为"温和"的一批做法已属违规。**凡涉及默认勾选、自动续费、
  强制授权、诱导点击的判断，一律不适用本 skill 的成本核算，须走合规与伦理审查。**
- **具体载体已换代**：书中案例集中于 PC 网页（打印友好页、Flash 开场、
  机场无线接入付费页）。**具体形态需在 App/小程序/公众号/客服机器人语境下
  重新检验**；存量模型与坦诚原则本身跨介质成立。
- **诊断非生成**：本 skill 判断哪些做法在抽水、哪些在注水，不产出具体的界面设计方案。
- **任务型前提**：模型假设用户带着明确目的而来（买票、找支持、办事）。
  对无目的消费型产品（信息流、短视频），"好感"更多由内容质量决定，本模型解释力弱。

### 容易混淆的邻近方法论

- **服务设计的"关键时刻 MOT"**：同样关注情绪节点，但聚焦跨渠道旅程编排；
  本 skill 更细，落在具体页面与文案动作上。
- **峰终定律**：预测的是**回忆**如何形成（峰值与结尾主导）；
  本 skill 建模的是**过程中的存量消耗**。两者互补：用本 skill 找漏水点，
  用峰终定律安排补偿点的位置。
- **NPS / CSAT**：是结果指标，不是原因分析。本 skill 提供的是原因侧清单。
- **信任修复（服务补救悖论）**：主张补救得当可使满意度高于未出错时。
  与本 skill 第 4 步 ⑧ 一致，但不要以此为借口故意制造问题。
