## I — 方法论骨架 (Interpretation)

习惯测试回答一个问题：**谁是习惯用户、他们为什么留下、怎么让更多人变成他们。**

**第一步：确定用户——定义先于测量**

这是与常规数据分析最大的分歧点。
通常的做法是先看数据再解释；本方法要求**先基于产品逻辑写下假设**：
"对我们这个品类，一个真正养成习惯的用户应该多久用一次？"

- 社交应用：可能是一天多次
- 影评网站：可能是一周一次（看电影前）
- 项目管理工具：每个工作日
- 报表工具：每周一次

**行业均值不能替代自定义。** DAU/MAU 是一个跨品类没有意义的比值。
定义完成后，才有资格去数"有多少人达标"。

**第二步：分析行为——找习惯路径**

不要看单点指标，要做**差集**：
达标用户与流失用户在早期行为流上有什么不同？
产出的不是一个"aha 指标"，而是一条**行为序列**——习惯路径。

书中的例证是 Twitter 的"关注满 30 人"：
跨过这个临界点的用户显著更可能留下。
但重点不是数字 30，而是"找到那条把人送进习惯的路"这个方法。

**第三步：改进产品——把新用户推上路径，然后重测**

改造目标是让更多新用户走上这条路径，而不是提升某个汇总数字。
改完之后回到第一步重新测量，形成循环。

**5% 基准线：一条带停止规则的及格线**

习惯用户占比低于 5% → 二选一的结论：
① 你对"谁是用户"判断错了（定义或目标人群错）；
② 产品闭环有断裂，需要回到 `hook-model-loop` 定位。

**不达标时不许横向加功能。** 这是本单元最有约束力的部分——
5% 不只是一个数字，是一条"停止扩张、回头修闭环"的纪律。

## A1 — 书中的应用 (Past Application)

### 案例 1: Twitter 的"关注满 30 人"临界点
- **问题**: 大量新用户注册后流失，团队需要知道留下的人做对了什么。
- **方法论的使用**: 比较长期活跃用户与流失用户的早期行为，
  发现"关注人数达到 30"是一条清晰的分界。
- **结论**: 习惯不是由单次体验决定的，而是由一段**行为序列**决定的。
- **结果**: 产品把新手引导的目标改为帮助用户尽快关注足够多的人。

### 案例 2: 定义必须先于测量（社交应用 vs 影评网站）
- **问题**: 同样的 DAU/MAU 数字，对不同产品意味着完全不同的东西。
- **方法论的使用**: 作者要求先按品类逻辑写下"理想使用频率"假设，
  社交应用与影评网站的合理频率相差一个数量级。
- **结论**: 没有定义就没有测量；拿行业均值当自己的目标是典型错误。
- **结果**: 成为三步法第一步的核心纪律。

### 案例 3: 5% 基准线的二选一结论
- **问题**: 习惯用户比例很低时，团队该做什么。
- **方法论的使用**: 作者给出一条可证伪的门槛，
  并把不达标的原因收敛到两个：用户判断错、或产品闭环断裂。
- **结论**: 低于 5% 时继续加功能是错误反应，应回到闭环定位断点。
- **结果**: 为产品团队提供了明确的停止规则。

### 案例 4: 三步法的循环性
- **问题**: 一次测量之后怎么办。
- **方法论的使用**: 改进产品后必须回到第一步重新定义与测量，
  因为产品变了、用户构成也会变。
- **结论**: 习惯测试不是一次性诊断，是持续的产品节律。
- **结果**: 与后续的机会扫描（第八章）共同构成产品的长期运行方式。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **拿着一堆数据不知道算好算坏**——"我们 DAU/MAU 是 12%，这算什么水平"。
2. **要定北极星指标 / 激活指标**，团队争执不下。
3. **要判断有没有 PMF / 有没有形成习惯**。
4. **留存不好，团队打算加功能**（这时最需要 5% 的停止规则）。
5. **要设计新手引导**，但不知道该把用户推向哪个行为。
6. **要做同期群分析**，需要一个分析框架而不只是工具操作。
7. **需要向老板/投资人解释产品健康度**，需要一个可辩护的判据。

### 语言信号 (用户的话里出现这些就应激活)

- "DAU/MAU 多少算好 / 留存多少算及格"
- "我们的 aha 时刻是什么 / 激活指标怎么定"
- "北极星指标该选哪个"
- "有没有形成习惯 / 是不是 PMF 了"
- "留存不行，我们准备再加几个功能"（危险信号，应触发 5% 规则）
- "数据看不懂 / 不知道该看哪个指标"
- "habit testing" / "cohort analysis" / "activation metric" / "retention benchmark"

### 与相邻 skill 的区分

- 与 `habit-zone-screening` 的区别：那个是**上线前**的可行性判断
  （频率 × 可感知用途，该不该做习惯型产品）；
  本 skill 是**上线后**的实测（做了，效果如何）。
  若还没有真实用户数据，转那个。
- 与 `hook-model-loop` 的区别：本 skill 告诉你"有没有问题、问题有多大"，
  那个告诉你"问题出在四阶段的哪一环"。
  标准流程：本 skill 发现不达标 → 转那个分诊 → 转具体设计 skill 改造 → 回本 skill 重测。
- 与 `habit-opportunity-scan` 的区别：那个向外找新机会，
  本 skill 向内测现有产品。三步法完成且达标后，才轮到那个。
- 与 `habit-as-business-asset` 的区别：那个论证"习惯值多少钱"（对外说服），
  本 skill 测量"我们有没有习惯"（对内诊断）。

## E — 可执行步骤 (Execution)

1. **写下频率假设（定义先于测量）**
   - 格式："对我们这个品类，一个真正养成习惯的用户应该【多久】用一次，
     并完成【什么核心动作】。"
   - 完成标准：频率 + 核心动作两项都写清楚，且有品类逻辑支撑。
   - 判停条件：若唯一依据是"行业均值是 X" → 不合格，重写（ce11）。
   - 注意：核心动作要选**价值兑现动作**（发出一条内容、完成一次记录），
     不是"打开 App"。

2. **按假设切出习惯用户群，算占比**
   - 用同期群（cohort）而不是大盘：按注册批次分组，避免新老混合。
   - 完成标准：得到一个数字——习惯用户占比 X%。

3. **对照 5% 基准线，读出结论**
   - **≥5%** → 继续到步骤 4，去找习惯路径并扩大规模。
   - **<5%** → 二选一：
     (a) 用户判断错了 → 回步骤 1 重新定义（可能目标人群选错了，
         试着在现有用户里找"哪一小群人用得特别频繁"，重新定义他们是谁）；
     (b) 产品闭环断裂 → 转 `hook-model-loop` 分诊。
   - **纪律：<5% 时不许横向加功能**。完成标准是明确写出"本阶段不做什么"。

4. **做差集分析，找习惯路径**
   - 对比两组：达标用户 vs 首周流失用户。
   - 看的是**早期行为序列**（前 1–7 天做了什么、按什么顺序、做了几次），
     不是人口属性。
   - 候选变量示例：邀请了几个同事、建了几个项目、关注了几个人、
     接入了哪个集成、第几天完成了第一次核心动作。
   - 完成标准：输出一条可表述的路径，如
     "在第 3 天前完成 A 且累计 B 达到 N 的用户，留存率显著更高"。
   - 判停条件：若两组无显著差异 → 样本量不足或核心动作定义有误，回步骤 1。

5. **验证路径是因果还是相关**
   - 警示：多数"aha 指标"只是相关——活跃用户自然会做更多事。
   - 做法：设计一次干预实验（引导一部分新用户更快达成该行为），看留存是否真的提升。
   - 完成标准：明确标注这条路径是"已验证因果"还是"仅相关，待验证"。
   - （这一步是对书中方法的必要补强，见"作者的盲点"。）

6. **改造产品，把新用户推上路径**
   - 手段：重设新手引导目标、调整默认值、
     用 `external-trigger-design` 在恰当时刻提示、
     用 `ability-simplification` 削平路径上的门槛。
   - 完成标准：改造目标明确写成"让 X% 的新用户在 N 天内达成【路径行为】"，
     而不是"提升 DAU"。

7. **重测并形成节律**
   - 改造上线后回到步骤 2 重新计算占比，比较同期群。
   - 完成标准：确定一个固定的复测周期（如每月/每版本）。
   - 判停条件：连续两轮改造后占比仍无提升 → 回 `hook-model-loop`
     重新分诊，或用 `habit-zone-screening` 质疑品类本身是否适合习惯化。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产品还没上线 / 没有足够用户量**——无法做同期群分析，
  先用 `habit-zone-screening` 做前置判断。
- **低频品类**（年度体检、报税、买房）——5% 基准线是为习惯型产品设的，
  套在低频产品上会得出错误的失败结论（ce10）。
  这类产品应换用完成率、满意度、推荐率等指标。
- **B 端强制使用的系统**——使用频率由制度决定，不反映习惯。
- **纯交易型产品**（一次性采购、报名）——没有重复行为可测。
- **只是想要一个数字向上汇报**——本 skill 的产出是行动结论，
  被当作汇报工具会退化为指标粉饰。

### 作者在书中警告的失败模式

- **ce11 — 没定义"习惯用户"就去测量**：直接看 DAU/MAU 或留存率，
  没有基于产品逻辑的频率假设。
  警告信号：指标只有 DAU，没有"理想频率"定义；无法说出习惯用户占比；
  拿行业均值当自己的目标。
- **ce12 — 习惯用户不足 5% 却继续加功能**：闭环没跑通就横向扩张。
  警告信号：需求列表越来越长；每个版本都在加新模块；
  没人能画出产品的完整 hook 闭环。
- **ce22 — 用数据掩盖价值缺失**：指标可以优化，但如果产品本身没有可感知用途，
  习惯用户永远不会出现。
- **ce09 — 把维生素当止痛药**：定义"理想频率"时高估自己的必要性，
  会导致基准线定得过高，误判为失败。

### 作者的盲点 / 时代局限

- **5% 是经验值，书中未给出出处与适用条件**。
  不同品类、不同商业模式（订阅制 vs 广告制）的合理门槛差别很大，
  应把它当作"讨论的起点"而非硬标准。
- **相关 vs 因果未区分**：书中的"关注满 30 人"叙述容易被误读为因果，
  实践中大量团队盲目把这类指标当作 KPI 去冲量，
  结果是刷出了指标却没有留存。本 skill 步骤 5 是对这一空白的补强。
- **幸存者偏差**：差集分析只能看到留下的人和走掉的人的差异，
  看不到"从未注册的人"为何不来，因此不能用它来发现市场机会。
- **未讨论负向习惯**：高频使用也可能是产品难用导致的反复重试，
  或对用户有害的强迫性使用——测量时应与 `manipulation-matrix-ethics` 联用。
- 成书于 2014 年，未涉及今天的**隐私限制**（IDFA、埋点合规）
  对同期群分析可得性的削弱。

### 容易混淆的邻近方法论

- **AARRR 海盗指标**：给出漏斗各环节的指标清单；
  本 skill 的差异是**先定义理想频率再测量**，且只关心习惯这一件事。
- **North Star Metric（北极星指标）**：强调选一个统领性指标；
  本 skill 强调的是**行为序列（路径）而非单点指标**，两者常被混为一谈。
- **Aha Moment / 激活指标（如 Facebook"10 天 7 个好友"）**：
  同类实践，本质是本 skill 第二步的产物；
  本 skill 补充了它前面的"定义"与后面的"5% 停止规则"。
- **PMF 测量（Sean Ellis 的 40% 问卷）**：问的是"如果不能再用会不会失望"，
  是主观测量；本 skill 是客观行为测量。两者可互相印证。
- **同期群分析 / 留存曲线**：是本 skill 使用的**工具**，
  本 skill 提供的是使用这些工具的判据与停止规则。
