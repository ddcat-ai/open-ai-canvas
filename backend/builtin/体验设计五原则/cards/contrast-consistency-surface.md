## I — 方法论骨架 (Interpretation)

表现层是五层顶端,把内容/功能/美学汇成最终感知。两条主轴:

**对比(contrast)**: 吸引注意、传达概念群组的主要工具。无对比=灰色平凡,视线乱飘。差异须清晰到用户能分辨"这是有意传达信息"。错误提示用不同颜色/图形凸显即可质变。但过度对比=混乱。

**一致性(uniformity)**: 分两种要防的问题——
- 内部一致性: 同产品两处用了不同设计方法。
- 外部一致性: 未在同一企业其他产品反映相同方法(破坏企业清晰形象)。
- 栅格(grid)布局保一致但不教条: 设备/分辨率千差万别,死守栅格在行不通时更糟,要能识别何时重审基础。统一品牌识别应贯穿每一层级。

**忠于眼睛(评估法)**: 把"美不美"转成"运作是否良好"。方法: 盯视线第一落点是否在战略目标元素; 眯眼/斜看/走到房间另一头看,判断视线路径是否流畅、是否提供有效引导而不分散注意力。成功设计视线遵循流畅路径且引导支持目标。

## A1 — 书中的应用 (Past Application)

### 案例 1: 视觉设计支持战略而非品味
- **问题**: 视觉讨论总沦为个人偏好("酷不酷")。
- **方法论的使用**: 作者主张评估"运作是否良好"——外观是否强化结构、是否传达品牌(如技术权威感不可用漫画字体+亮粉)。
- **结论**: 视觉是战略定位问题非纯美学。
- **结果**: 把视觉从品味拉回战略。

### 案例 2: 错误提示融入页面被忽略
- **问题**: 错误提示常被埋没。
- **方法论的使用**: 作者建议用不同颜色(红)或醒目图形凸显,让界面质变。
- **结论**: 对比让关键元素被注意(用户无法控制)。
- **结果**: 成为对比用法的范例。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要 this skill?
1. 改版后用户说"页面乱/找不到重点"。
2. 做配色/排版/品牌视觉规范。
3. 评审视觉稿,纠结"好不好看"还是"对不对"。
4. 多产品/多页视觉风格不统一。

### 语言信号
- "这个页面看起来好乱"
- "配色/排版怎么定?"
- "视觉设计 / 对比 / 一致性 / 忠于眼睛"
- "surface / visual design / brand"

### 与相邻 skill 的区分
- 与 `navigation-wayfinding` 的区别: navigation 是"结构中的移动"; 本 skill 是"最终感知呈现"。表现层坐在框架层之上。
- 与 `interface-design-defaults` 的区别: interface 关注控件与行为; 本 skill 关注视觉对比/一致性与评估。

## E — 可执行步骤 (Execution)

1. **忠于眼睛诊断**
   - 完成标准: 看视线第一落点是否在战略目标元素; 眯眼判断路径是否流畅、有无有效引导。
   - 判停条件: 若视线散乱或落点背离目标,进入步骤2/3。
2. **用对比突出关键**
   - 完成标准: 关键元素(错误/主操作)用明显差异凸显,差异清晰到知是有意。
3. **对齐一致性**
   - 完成标准: 检内部(同产品两处一致)与外部(跨企业一致); 用栅格但不教条; 品牌贯穿每层级。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 纯语音/无屏产品,视觉维度不适用(可参考听觉/触觉但非本 skill主域)。
- 不要为"一致"牺牲合理的新功能/新栅格——识别何时重审基础。

### 作者在书中警告的失败模式
- 视觉问题(杂乱/不一致)让用户秒退,永远发现不了你导航/交互的巧思——上层错误削弱下层正确决策。
- 过度对比=混乱; 差异不够清晰=用户困惑"为何不一样"。

### 作者的盲点 / 时代局限
- 偏 Web 视觉; 今天设计系统(Design System)、暗色模式、响应式使一致性更复杂,但"强化结构/引导视线"原则不变。

### 容易混淆的邻近方法论
- 不要与"平面美术/纯审美"混淆: 本 skill 评估标准是战略运作良好,非主观美丑。
