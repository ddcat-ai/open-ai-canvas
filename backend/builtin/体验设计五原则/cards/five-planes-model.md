## I — 方法论骨架 (Interpretation)

五层模型是把"用户体验"这件模糊的事拆成五个坐标的工具:

- **战略层**: 为什么要做这个产品(企业目标 + 用户需求)。
- **范围层**: 产品要提供什么功能和内容(功能规格 / 内容需求)。
- **结构层**: 这些功能与内容如何组织(交互设计 / 信息架构)。
- **框架层**: 界面、导航、信息如何具体排布(界面 / 导航 / 信息设计)。
- **表现层**: 用户最终看到的感官细节(视觉、听觉、触觉等感知设计)。

底层抽象、顶层具体。**每一层都由它的下一层决定**——表现层长得怎么样,由框架层说了算;框架层怎么排,由结构层决定;依此类推。所以任何体验问题都能被"定位"到某一层:一个紫色大按钮不对,可能是表现层(颜色)、框架层(位置)、也可能结构层(它代表的功能不是用户期望的)。模型的价值就是给你一张统一的"地图",让团队用同一套词汇讨论问题。

## A1 — 书中的应用 (Past Application)

### 案例 1: 用五层定位"主页紫色大按钮"问题
- **问题**: 团队争论主页那个紫色大按钮"到底哪里不对"。
- **方法论的使用**: 作者用五层逐层追问——是按钮太大或紫色不合适(表现层)? 放的位置不对(框架层)? 还是它代表的功能根本不是用户期望的(结构层)?
- **结论**: 只有先定位到层,才能知道改什么,而不是笼统地"重做"。
- **结果**: 成为全书"如何提出正确问题"的示范。

### 案例 2: 全书逐层展开
- **问题**: 如何系统讲清用户体验。
- **方法论的使用**: 第3–7章严格按战略→范围→结构→框架→表现五章展开,每章只处理该层要素。
- **结论**: 五层提供了贯穿全书的目录结构。
- **结果**: 读者可用同一坐标理解任何产品。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 拿到一个"体验不好"的反馈,但说不清问题在哪——需要定位到层。
2. 做设计评审/需求评审,团队用词混乱(有人说信息架构、有人说界面)。
3. 启动新产品/新功能,想先建立结构化思考框架再动手。
4. 向上级或跨职能团队解释"为什么 UX 要分这么多层"。

### 语言信号 (用户的话里出现这些就应激活)
- "这个体验问题到底是哪出的?"
- "我们要做网站/App/产品,从哪开始想?"
- "战略层/范围层/结构层/框架层/表现层"
- "UX 要素 / five planes / element of UX"

### 与相邻 skill 的区分
- 与 `bottom-up-chain-effects` 的区别: 本 skill 是"地图/坐标"(是什么层), bottom-up 是"层之间怎么互相决定、该按什么顺序建"(动力学)。先用本 skill 定位,再用 bottom-up 决定建设顺序。
- 与 `functional-informational-duality` 的区别: 本 skill 是纵向五层; duality 是每层内部的横向"功能型/信息型"两半拆分。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **澄清问题现象**
   - 完成标准: 能用一句话描述"用户遇到了什么不爽/产品哪不对"。
2. **逐层定位 (从表现向战略追问)**
   - 完成标准: 对每个候选层问"这是表现/框架/结构/范围/战略哪一层的问题?"并圈定主因层。
   - 判停条件: 若问题横跨多层,列出所有相关层,指出最根因的那一层(通常更靠下)。
3. **用统一词汇复述**
   - 完成标准: 用"这是 XX 层的问题,因为…"句式向用户/团队说明,避免"界面""体验"混用。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 纯后端/算法/技术实现问题,与用户体验坐标无关时——本 skill 不解决代码问题。
- 用户只是要一个现成配色或文案,不需要定位层——直接用更具体的 skill。

### 作者在书中警告的失败模式
- 作者明言现实边界常模糊,一个问题可能横跨多层或"在视觉玩小把戏还是改造导航"难分;此时不要强行归入单层,要承认多层共存(见第2章"应用这些要素")。

### 作者的盲点 / 时代局限
- 模型以 Web/网站为主,对 AI 对话式、语音、无界面产品的"层"映射需重新思考(如 AI 产品的"范围层"可能是能力边界/prompt 约束)。

### 容易混淆的邻近方法论
- 不要和"设计流程/敏捷阶段"混为一谈: 五层是**决策坐标**,不是时间上的开发阶段(尽管建议自下而上建设)。
