## I — 方法论骨架 (Interpretation)

### 前置机制：定制化会让产出自动向上升一级

**定制一件产品，它自动变成一项服务；定制一项服务，它自动变成一次体验。**（对真正的初级产品无效——可替换性使其本质上难以定制。）

这条是本 skill 的动力来源：定制不是成本项，是**升级产出等级的通道**（与 `economic-value-progression` 直接咬合）。

### 先破一个常见错误：多样化 ≠ 定制化

企业的权宜之计是往渠道里堆品种让顾客自选。结果：制造商堆库存、服务商堆冗余，成本与复杂度双升；顾客要在成百上千种里翻找，最后拿到一个"差强人意的近似品"。普通超市已有 5 万多种单品。

**堆品种是"规模化生产思维的最后一搏"，不是定制。**

### 两个正交问题，切出四种方式

- 问题一：**要不要改变产出本身**（功能、内容、配方、服务实质）？
- 问题二：**要不要改变呈现形式**（描述、包装、交付方式、界面、名称、条款）？

| 方式 | 改产出 | 改形式 | 消除的损失 | 产生的体验 | 一句话 |
|---|---|---|---|---|---|
| **合作型** collaborative | ✓ | ✓ | **选择问题** | 探索式体验 | 和顾客一起把需求谈出来，再做 |
| **适应型** adaptive | ✗ | ✗ | **组合问题** | 实验式体验 | 卖一个可自己调的东西，顾客自己试 |
| **装饰型** cosmetic | ✗ | ✓ | **形式问题** | 满足式体验 | 东西不变，为你换个说法/包装/交法 |
| **透明型** transparent | ✓ | ✗ | **重复问题** | 发现式体验 | 悄悄为你改，不让你重复说需求 |

记忆口诀：**透明型 = 旧瓶装新酒；装饰型 = 新瓶装旧酒。两者完全相反。**

### 关键选型判据

- **顾客的损失是"不知道自己要什么"** → 合作型。此时定制商要放弃部分设计控制权，让顾客在互动中**发现**自己的需求。额外产出：顾客"通常还会惊喜地发现现在终于知道自己的愿望和需求是什么了"。
- **顾客的损失是"要从一堆东西里挑"** → 判别规则：必须从大量元素/部件中挑选才能实现功能 → 合作型；可选组合能**内置进产品**由顾客自己调 → 适应型。而且"对此类产品进行试验设置的过程，其本身就是一种充满乐趣的体验"。
- **顾客的损失只在呈现/交付层，功能没问题** → 装饰型。
- **顾客的损失是"每次都要重复说一遍"，且他不想参与决策** → 透明型。前提是有统一标准化的外包装掩饰内在差异。

### 一个反直觉推论

透明型效率最高、顾客最省心，但它**丢掉了"让顾客看见定制行为"这一次免费的体验升级**。丽嘉酒店刻意保留"顾客不知道酒店怎么知道的"神秘感，是主动选择；而很多公司只是默认走了透明型，白白损失了可感知价值。**让不让顾客看见定制，是战略选择，不是技术细节。**

### 两套支撑架构

- **模块架构 = 多样化模块 + 连接系统**（乐高心智模型）。服务企业组合的不是零件而是**无形的处理过程**。
- **环境架构 = 设计工具 + 预设型界面**。没有它，海量模块只会让顾客眼花缭乱。设计工具有双重职能：管理复杂度 + **积极参与顾客决策，帮他确定自己的真实需求**。
- 第三种形态：**故意对顾客隐藏设计工具**（顾客想要独特价值但不想参与决策）。

### 新学习曲线

旧学习曲线：成本随累计产量下降。**新学习曲线：顾客损失随互动次数下降。**这构成真正的转换壁垒——即使对手复制了同样的能力，顾客也不走，因为他还得重新花几个月把对手教会。

两个失效前提：①关系建立后过度提价或削减服务；②错过新技术趋势（亚马逊自造 Kindle 以防电子阅读颠覆纸书）。

## A1 — 书中的应用 (Past Application)

### 案例 1：巴黎三城 Paris Miki 眼镜（合作型，第5章 p137）
- **问题**：配眼镜时顾客根本说不清自己适合什么样的镜框，只能在几百副里试。
- **方法论的使用**：耗时 5 年开发 Mikissimes 设计系统——拍面部数码照 → 系统分析面部特征 → 顾客从形容词表里选风格（正式/传统/自然/运动/端庄）→ 系统推荐镜片形状并合成到照片上 → **顾客与店员一起**旋转、放大、用鼠标画曲线调整 → 一起挑鼻梁垫、铰链、镜腿 → 拍佩戴成品照 → 组装。
- **结论**：合作型的本质不是"给更多选项"，是**把选择过程变成共同探索需求的过程**。
- **结果**：全程不到一小时，配眼镜从服务变成"设计眼镜的体验"。

### 案例 2：路创电子 Lutron 照明（适应型，第5章 p141）
- **问题**：每栋建筑房型窗位不同、每小时天气光线不同、室内人数与用灯方式不同——无法预先谈定。
- **方法论的使用**：GRAFIK 视觉系统让用户反复测试后自行编程出"聚会型/浪漫型/夜读型"等场景，**不为每种效果单独装开关**；顾客花时间调到满意，之后按几下即可。
- **结论**：当变量太多且随时间变化时，合作型谈不完，正解是把定制能力**内嵌进产品**交给顾客自己试。
- **结果**：董事长乔尔·斯皮拉称"创造适应型控制让我们在市场竞争中脱颖而出"。同类：Select Comfort 气室床垫（同床夫妻两边不同硬度）。

### 案例 3：惠而浦"即时速递"（装饰型，第5章 p144）
- **问题**：经销商必须凑满一整车才发货，无法告诉终端顾客到货时间——电器本身没问题，问题全在交付形式。
- **方法论的使用**：改为按经销商年销量每周固定发货，可以是 5 件、4 件甚至 1 件，次日交付；司机穿统一制服，到现场拆外包装、调好开门角度、在规定时间前装完；**车没到就先电话通知经销商准备收货**。
- **结论**：产品一个螺丝没改，价值全部来自呈现与交付方式的定制。
- **结果**：CEO 拉尔夫·哈克："我们为经销商提供的价值是以可视化的方式展现的，每当他们看到我们的货车抵达时都会有这种体验。"

### 案例 4：ChemStation 与丽嘉酒店（透明型，第5章 p145）
- **问题一**：工业清洁用品的配方对洗车店、餐厅厨房、造纸厂各不相同，但客户对成分毫无兴趣。
- **方法论的使用**：一律用统一的"ChemStation 解决方案"包装桶与相同标志，不告诉顾客成分含量——**因为属性复杂晦涩，暴露反而制造损失**。
- **问题二**：常客每次登记都被问"大床还是标间？高楼层还是低楼层？"
- **方法论的使用**：丽嘉首次入住时除直接询问外还**仔细观察**（低敏枕、爵士乐广播、可乐还是百事），录入数据库形成静默式学习关系；管理层**刻意保留**"顾客不知道酒店怎么知道的"神秘感。
- **结论**：透明型的核心是"不让顾客重复描述需求"，而不是"不让顾客知道"。是否揭示是独立的战略选择。

### 案例 5：可口可乐/百事的虚假满意（第4章 p129）
- **问题**：乘客要百事，空乘反问"可口可乐行吗？"，乘客让步。
- **方法论的使用**：作者用它演示"顾客损失"如何被制造并被隐藏——多次之后，这位乘客**直接点可口可乐**。
- **结论**：航空公司"硬是把乘客变成了接受无奈选择的人"，此时才达成"期望"，制造出**虚假满意**。每一次互动都是学习机会，"不幸的是，事实证明很多情况下做出改变的都是顾客而非企业"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **抱怨点分散**：每个用户吐槽的都不一样，加功能加不完。
2. **SKU/品类失控**：为了满足不同人堆了大量型号，库存与复杂度飙升但满意度没涨。
3. **要不要做个性化/推荐算法**：不确定该做哪种个性化，以及要不要让用户看见。
4. **配置太复杂导致流失**：选项一大堆，用户在配置页放弃。
5. **B2B 项目每单都要重做**：交付成本高、无法复用，想找模块化出路。
6. **服务标准化 vs 灵活性的拉扯**：一边说要标准化降本，一边说要贴身服务。
7. **老客户价值挖不深**：不知道怎么把"来过很多次"变成壁垒（新学习曲线）。
8. **接在损失测量之后**：`customer-sacrifice-measurement` 量出了损失，本 skill 决定用哪种方式消除它。

### 语言信号 (用户的话里出现这些就应激活)

- "每个客户要的都不一样 / 众口难调"
- "用户抱怨很多但每个人的点都不同"
- "要不要做个性化 / 千人千面 / 推荐算法"
- "功能越加越多 / 需求提不完"
- "SKU 太多了 / 品类太杂 / 库存压力大"
- "配置流程太复杂，用户在这一步跑了"
- "定制化能不能规模化 / 每单都要重做"
- "老客户怎么留住 / 怎么建壁垒"
- "personalization" / "mass customization" / "configurator" / "one-to-one"

### 与相邻 skill 的区分

- 与 `customer-sacrifice-measurement` 的区别（最重要的一组）：那个**测量顾客损失是什么**（诊断，换掉满意度的参照系）；本 skill **选择用哪种方式消除它**（处方）。顺序是先测后选。本 skill 的四格与损失的四种类型（选择/组合/形式/重复）一一对应。
- 与 `economic-value-progression` 的区别：那个判断卖哪一级；本 skill 是**向上升级的具体动力装置**（定制 → 自动升一级）。
- 与 `dont-make-me-think-audit` 的区别：那个解决**这个界面好不好懂**（认知负荷，单页面易用性）；本 skill 解决**要不要让用户自己选、以及给他什么样的选择结构**（产出结构）。用户在配置页流失时：如果是看不懂 → 前者；如果是**根本不该让他选** → 本 skill（走透明型或合作型）。
- 与 `choice-set-decoy-design` 的区别：那个设计**一组固定选项如何引导顾客选中某档**（选择架构，操纵倾向）；本 skill 处理**要不要有选项、以及选项如何生成**。前者假定选项已定，后者质疑选项本身。
- 与 `investment-design` 的区别（Hook 模型系）：那个讲"让用户往产品里存东西以提高留存"；本 skill 的**新学习曲线**讲的是"企业往顾客身上学，损失随互动下降"——方向相反：一个是用户投入，一个是企业学习。两者叠加就是最强壁垒。
- 与 `ability-simplification` 的区别：那个降低用户完成某个动作的难度；本 skill 决定该不该让用户做这个动作。

## E — 可执行步骤 (Execution)

1. **先确认这是定制问题，而不是多样化冲动**
   - 问："我们现在的做法，是不是在往货架上堆更多品种让顾客自己找？"
   - 是 → 停止堆品种，继续本流程。
   - 判停条件：若顾客真正要的是"品类齐全、我自己会挑"（批发、便利店、工具超市），本 skill 不适用。

2. **定位损失类型（四选一或多选）**
   - **选择问题**：顾客被迫在难以权衡的维度间取舍，且说不清自己要什么。
   - **组合问题**：顾客面对过多制成品/组件必须自己挑。
   - **形式问题**：功能没问题，问题在包装、描述、交付时点与方式。
   - **重复问题**：顾客被迫反复提供相同信息。
   - 完成标准：能举出一个真实顾客的原话作为证据。
   - 提示：**损失往往是多方面的，允许多选**，但排出优先级。

3. **回答两个正交问题，落格**
   - 要不要改产出本身？要不要改呈现形式？
   - 完成标准：明确落进四格之一（或"主用 A 型 + 辅以 B 型"）。

4. **按格搭架构**
   - 合作型 → 搭**环境架构**（设计工具 + 引导式界面），核心是**帮顾客发现需求**而非罗列选项。注意安德森制窗的关键发现：**光有工具不够，还必须培训一线以个人身份与顾客互动**（受训经销商 +20%，未受训的下降）。
   - 适应型 → 把可调能力**内嵌进产出**，并让调试过程本身有乐趣；提供预设起点（"聚会型/夜读型"）降低冷启动。
   - 装饰型 → 找出交付链上最能被感知的那一环，把它个性化（时点、包装、称呼、拆箱、专属条款）。成本通常最低，见效最快。
   - 透明型 → 建观察机制而非提问机制（记录行为，不追问偏好），并保持统一外包装。
   - 完成标准：架构的模块清单 + 连接系统（或界面）各有具体方案。

5. **做"要不要让顾客看见"的显性决策（透明型必答）**
   - 看见 → 多一次免费的体验升级与可感知价值；
   - 不看见 → 更省心、更神秘，但价值不可见、容易被视为理所当然。
   - 完成标准：写出选择及理由。**不能默认漂移到"不看见"。**

6. **换掉提问方式**
   - 把"我们的表现如何"换成"**你的真实需求是什么**"。
   - 顾客说不清是正常的（长期隐忍导致麻木，见移情设计），**问题不在顾客而在提问方式**。
   - 完成标准：新问卷/访谈提纲里没有一道题在问对现状的评分。

7. **建学习关系并设护栏**
   - 记录每次互动降低了哪一类损失（新学习曲线）。
   - 两条护栏：①不要在关系建立后过度提价或削减服务；②盯住可能颠覆自己的新技术（Kindle 之于纸书）。
   - 完成标准：有一个可观测的"损失下降"指标，以及两条护栏的负责人。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **真正的初级产品**（同质大宗商品、标准件、水电煤）：作者明确说定制对它不起作用，可替换性使其本质上难以定制。
- **顾客真的享受挑选本身**（收藏、逛街、淘货、开盲盒）：此时"不用选"是在剥夺体验。作者的"顾客根本不想选择"是一个过强的断言（见下）。
- **安全/合规不允许个性化**（药品剂量、金融风控规则、法定条款）。
- **规模太小、互动次数太少**：学习关系需要多次互动才能形成，一锤子买卖不适用。
- **问题其实在界面易用性** → 转 `dont-make-me-think-audit`。

### 作者在书中警告的失败模式

- **用多样化冒充定制化**：堆 SKU、堆冗余人力，成本与复杂度双升，顾客拿到"差强可用的近似品"。
- **调低顾客期望**（第5章开篇）：迫使顾客接受次于真实需求的东西看似降本又不引发不满，但**必然导致初级产品化**，因为它以牺牲顾客利益换取公司成本。
- **制造虚假满意**：可口可乐/百事案例——把顾客训练成不再提真实要求的人，满意度反而上升。
- **只给工具不给人**：安德森制窗发现未受训经销商的销售额反而下降——设计工具会放大一线能力差距。
- **暴露不该暴露的复杂度**：ChemStation 明确不告诉顾客配方成分，因为"属性复杂晦涩，暴露反而制造损失"。
- **学习关系建立后杀熟**：作者列为两个失效前提之一。

### 作者的盲点 / 时代局限

- **案例来自 1990s 末的制造业与实体服务业**（戴尔、安德森制窗、惠而浦、丽嘉、CEMEX）。**案例已过时；数字化与算法推荐语境下需重新检验**——但四格的两条正交轴（改产出 × 改形式）是结构性的，在 SaaS、内容推荐、电商个性化上依然直接可用。
- **⚠️ "顾客根本不想选择"被过度普遍化。**这在配置复杂、决策成本高的品类成立；但在娱乐、时尚、餐饮、内容消费中，**选择本身就是体验的一部分**（逛、挑、淘、比）。本书没有给出边界，使用时须自补：**选择是成本还是乐趣？是成本 → 定制；是乐趣 → 保留选择并优化选择体验。**
- **算法个性化的阴暗面完全缺席**：透明型定制在 1999 年是丽嘉酒店记住你的枕头偏好，在今天是行为追踪、隐私、信息茧房、算法歧视与"杀熟"。**书中把"暗中观察顾客"当作纯粹的好事，这在今天不成立**——透明型定制必须叠加隐私合规与可解释性设计（这一层是本次整理补入的）。
- **学习关系壁垒被高估**：书中认为顾客不会走因为要重新教会对手。但数据可迁移、跨平台账号导入、AI 冷启动能力已大幅削弱这一壁垒。
- **共创视角缺失**（作者自认）：四种方式都是企业主导，UGC 与开放平台模式下顾客自己就是生产者。
- **未讨论定制的成本上限**：所有案例都假定定制能力可以低成本获得，没有失败样本。

### 容易混淆的邻近方法论

- **"千人千面"推荐算法**：那是透明型定制的一种技术实现，只覆盖四格中的一格。用它替代全部定制思考，会漏掉合作型（帮顾客发现需求）与装饰型（低成本高感知）。
- **SKU 精简 / 长尾策略**：那讨论品种数量的多寡；本 skill 讨论**品种是不是解决问题的正确形式**。堆长尾和砍 SKU 都可能是错的答案。
- **一对一营销（佩珀斯 & 罗杰斯）**：本书明确把它与大规模定制结合成"学习关系"。区别在于一对一营销偏沟通侧，大规模定制偏产出侧。
- **敏捷/迭代开发**：那讲交付节奏；本 skill 讲交付内容的差异化结构。
