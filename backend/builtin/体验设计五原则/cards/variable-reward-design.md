## I — 方法论骨架 (Interpretation)

**第一层：多变性本身就是酬赏。**
斯金纳的间歇性强化实验说明：可预期的奖励会让反应逐渐衰减，
不可预期的奖励会强化行为。
所以设计酬赏时的第一个问题不是"给多少"，而是"**用户能不能猜到会得到什么**"。
能猜到 → 它是交易，不是酬赏。

**第二层：三类型，按心理满足的性质分。**

| 类型 | 满足的是 | 典型形态 | 对应的内部触发 |
|---|---|---|---|
| **社交酬赏**（部落） | 被接纳、被认可、被看见 | 点赞、评论、荣誉分、同侪认可 | 孤独、怕被冷落、怕不被认可 |
| **猎物酬赏**（狩猎） | 获得资源与信息 | 信息流、搜索结果、折扣、抽奖 | 无聊、怕错过、想找到点什么 |
| **自我酬赏**（自我） | 掌控、完成、精进 | 进度条、清零、通关、技能提升 | 混乱感、未完成的焦虑、无能感 |

三类不可互换。给一个孤独的用户发折扣券（猎物酬赏），
或给一个想要秩序感的用户塞社交排行榜，都属于错配。

**第三层：匹配纪律。**
酬赏必须缓解内部触发挖出来的那个情绪。
这是判断"该发红包还是该做点赞"的唯一标准——
不是哪个成本低，也不是哪个行业在用。

**第四层：现金的陷阱。**
现金/积分兑换是**可预期的有限酬赏**，还会把内在动机挤出
（过度合理化效应），并把关系从"社群归属"降级为"交易"。
Mahalo vs Quora 是书中最锋利的对照。

## A1 — 书中的应用 (Past Application)

### 案例 1: Mahalo（现金）vs Quora（点赞）
- **问题**: 如何驱动用户持续贡献高质量回答。
- **方法论的使用**: Mahalo 给现金——可预期、有限、把行为标价；
  Quora 给"赞"——不可预期（不知道会不会被赞、被谁赞）、无现金价值、
  但精准命中"想被同行认可"这个内部触发。
- **结论**: 酬赏的有效性取决于**是否匹配内部触发 + 是否不可预期**，与金额无关。
- **结果**: Mahalo 用户流失，Quora 蓬勃发展。

### 案例 2: Stack Overflow 的点数与徽章
- **问题**: 让程序员无偿贡献大量高质量答案。
- **方法论的使用**: 纯社交酬赏 + 信誉积累。点数不能兑现，
  其价值完全来自同侪认可；下一个答案会得到多少赞、会不会被采纳，不可预知。
- **结论**: 无现金价值的"货币"反而能驱动最持久的贡献。
- **结果**: 成为程序员领域事实上的知识基础设施。

### 案例 3: 《英雄联盟》荣誉分整治恶劣行为
- **问题**: 玩家在游戏中辱骂队友，惩罚机制收效有限。
- **方法论的使用**: 引入由**队友颁发**的荣誉徽章（社交酬赏），
  是否收到、收到几个不可预知，且来自同伴而非系统。
- **结论**: 用酬赏而非惩罚改变行为，且社交酬赏可以直接改造社区文化。
- **结果**: 恶意行为显著下降。

### 案例 4: 电子邮件——三类酬赏同时在场
- **问题**: 为什么查看邮箱这个动作如此顽固。
- **方法论的使用**: 拆开看：谁给我发了信（社交）、里面有没有有价值的信息（猎物）、
  把收件箱清空的秩序感（自我）。三类同时存在，且每次打开的内容都不可预知。
- **结论**: 三类型不是互斥选项，强产品往往同时命中多类。
- **结果**: 成为作者示范拆解的经典样本。

### 案例 5: Mint 的净值曲线
- **问题**: 记账枯燥，用户不愿回访。
- **方法论的使用**: 把用户已绑定的账户数据转成可视的资产净值变化——
  每次打开看到的数字都不同（多变），满足的是掌控感（自我酬赏）。
- **结论**: 自我酬赏可以由用户自身数据自动生成，成本极低。
- **结果**: 被 Intuit 以 1.7 亿美元收购。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **要设计激励 / 奖励机制**，正在纠结发现金、发积分还是做社交反馈。
2. **上线了积分/排行榜但没效果**——典型的类型错配或可预期性问题。
3. **用户完成了核心动作却不再回来**——酬赏环节缺失或无感。
4. **要做签到 / 抽奖 / 任务体系**，需要判断该不该做、怎么做。
5. **UGC 社区冷启动**，需要驱动早期贡献者持续产出。
6. **补贴停了用户就走**——需要把交易关系改造成酬赏关系。

### 语言信号 (用户的话里出现这些就应激活)

- "奖励机制怎么设计 / 激励体系怎么做"
- "要不要发红包 / 发优惠券 / 做积分"
- "排行榜有没有用 / 徽章有用吗"
- "用户做完一次就没动力了"
- "补贴一停用户就跑"
- "怎么让人愿意来发内容 / 回答问题"
- "variable reward" / "incentive design" / "reward system" / "does gamification work"

### 与相邻 skill 的区分

- 与 `internal-trigger-mining` 的区别：那个找**痛**（用户在躲什么情绪），
  本 skill 设计**止痛方式**。本 skill 的输入就是那个 skill 的输出，
  跳过它做本 skill 必然产出 ce19 式的空积分。
- 与 `variability-sustainability` 的区别：那个回答"这份多变性能撑多久、会不会耗尽"，
  是**时间维度**的问题；本 skill 回答"给哪一类、怎么给"，是**类型维度**的问题。
  若问题是"内容做得挺好但用户越来越腻"，转那个。
- 与 `investment-design` 的区别：酬赏是产品**给**用户的，投入是用户**给**产品的。
  顺序不可颠倒（先酬赏后投入，见 ce07）。若问题是"怎么让用户留下点什么"，转那个。
- 与 `commitment-escalation` 的区别：那个是用行动改变态度的说服机制，
  不涉及产品给予；两者常被混为"激励"，实为相反方向。

## E — 可执行步骤 (Execution)

1. **取回内部触发陈述**
   - 需要："当【人】在【情境】感到【情绪】时，她希望【缓解】。"
   - 判停条件：拿不出来 → 转 `internal-trigger-mining`。没有这一句，后面全是猜。

2. **把情绪映射到酬赏类型**
   - 孤独 / 怕被冷落 / 想被认可 → **社交酬赏**
   - 无聊 / 怕错过 / 想找点什么 → **猎物酬赏**
   - 混乱 / 未完成的焦虑 / 想变强 → **自我酬赏**
   - 完成标准：写出主类型 1 个（可加次类型 1 个），并说明映射依据。
   - 判停条件：若三类都对不上 → 情绪可能找错了，回步骤 1。

3. **设计具体酬赏形态，并做"可预测性检验"**
   - 自问：用户在动作之前能不能准确说出会得到什么？
   - 能 → 它是交易/功能反馈，不构成酬赏，必须注入多变性。
   - 完成标准：明确写出"多变性来自哪里"（他人的反馈？内容池？算法？随机？）。

4. **做现金检验（反面清单）**
   - 若方案里含现金、可兑现积分、直接折扣，逐条问：
     - 停发之后行为会不会立刻停止？
     - 用户讨论的会不会变成"能赚多少"而不是内容本身？
   - 完成标准：若两问皆是 → 判定为 ce01 风险，替换为非现金的社交/自我酬赏。
   - 例外：猎物酬赏本就以资源为标的（电商折扣、抽奖），此时保留现金但必须注入不可预测性。

5. **检查多变性的来源与可持续性**
   - 由公司生产（关卡、活动、内容）→ 有限多变性，会耗尽。
   - 由用户/他人生产（评论、内容流、社交反馈）→ 无穷多变性。
   - 完成标准：标注类别；若是有限多变性 → 转 `variability-sustainability` 评估寿命。

6. **保障自主权**
   - 酬赏不能靠强制换取（强制分享、强制授权、默认开启）。
   - 完成标准：确认用户可以拒绝、可以关闭，且拒绝后不被惩罚。
     若方案含强制项 → 转 `autonomy-reactance`（见 ce02）。

7. **定义验证指标与判停**
   - 看：酬赏后的**回访间隔**是否缩短（而不是单次点击率）。
   - 判停条件：上线后活跃短暂上升随即回落 → 典型 ce19，
     说明酬赏可预期或与内部触发无关，回步骤 2 重做映射。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产品本身没有可感知价值**——多变酬赏放大的是已有价值的使用频率，
  不能凭空创造价值（ce22）。
- **内部触发未知**——此时任何酬赏设计都是抛硬币。
- **强合规/强确定性场景**（支付到账、医疗结果、报销进度、航班信息）——
  这些场景用户要的恰恰是**可预测**，注入多变性是灾难。
- **纯交易型关系**（一次性采购、招投标）——不存在需要养成的重复行为。
- **面向脆弱人群的高风险品类**（赌博机制、未成年人、金融杠杆）——
  机制越强伤害越大，必须先过 `manipulation-matrix-ethics`（见 c21）。

### 作者在书中警告的失败模式

- **ce01 — 用现金酬赏替代社交酬赏**：过度合理化效应挤出内在动机，
  停发即断崖。警告信号：用户讨论的是"能赚多少"而不是内容本身。
- **ce19 — 把上瘾模型当成"游戏化"来做**：只贴积分、徽章、排行榜（PBL），
  酬赏可预期且与内部触发无关。
  警告信号：方案里只有积分体系；说不清酬赏对应哪个内部触发；
  排行榜上线后活跃短暂上升随即回落。
- **ce03 — 有限多变性耗竭**：靠公司堆内容制造惊喜，玩家看穿套路后习惯瓦解
  （详见 `variability-sustainability`）。
- **ce02 — 为了提高酬赏强度而牺牲自主权**：Quora 强推"谁浏览了你的答案"，
  被迫撤回。酬赏的前提是"这是我自愿的"。
- **ce07 — 在酬赏之前索取投入**：顺序颠倒，投入变成纯成本。

### 作者的盲点 / 时代局限

- 三类型划分之外，**审美/情绪性酬赏**（好看、治愈、有趣本身）在书中几乎未讨论，
  但在内容与设计驱动的产品中是真实存在的第四类。
- 书中对多变性的伦理刹车讨论集中在第六章，
  但在第四章的设计指引里几乎没有内置约束——
  实践中建议把 `manipulation-matrix-ethics` 作为本 skill 的强制后置检查。
- **算法推荐时代**改变了猎物酬赏的成本结构：书中假设内容池是给定的，
  今天推荐系统可以主动调节多变性强度，这带来了书中未讨论的新风险
  （可以精准地把人留在最难自控的强化区间）。
- 未讨论**酬赏疲劳的个体差异**：同一机制对轻度用户是愉悦，对重度用户可能是失控，
  需要配合 ce15 的尾部保护。

### 容易混淆的邻近方法论

- **游戏化（Gamification / PBL）**：主张用积分、徽章、排行榜；
  本 skill 明确指出这套东西若可预期且与内部触发无关则无效——
  两者结论经常相反，不要混用（这是最容易混淆的一对）。
- **行为经济学的激励设计**：多讨论金额、损失厌恶、框架效应；
  本 skill 的核心变量是**不可预测性与心理类型匹配**，不是金额。
- **自我决定理论（SDT）**：解释内在动机的三要素（自主/胜任/联结），
  与三类型酬赏有对应关系（自主↔自主权、胜任↔自我酬赏、联结↔社交酬赏），
  可作为理论补充，但不提供"如何注入多变性"的操作。
- **忠诚度计划 / 会员积分**：本质是可预期的交易折扣，属于本 skill 明确警告的形态。
