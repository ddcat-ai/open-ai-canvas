## I — 方法论骨架 (Interpretation)

成功标准是"比赛终点线"——用来显示产品上线后是否满足了战略目标与用户需求。好指标有三个特征:

1. **可追踪**: 上线后能量化(转化率、平均停留时长、回访率、客服电话量、广告印象数等)。
2. **绑定用户行为**: 指标必须对应"可以通过设计去影响"的用户行为。例如"注册用户单月访问次数"反映核心用户价值;"客服电话减少"反映自助问答有效。
3. **警惕虚荣指标**: 单纯提高广告印象数(多插导航层)短期漂亮,长期因用户挫败而下跌,甚至比原来更低——因为它偏离了用户需求。

指标可分直接与间接影响;但任何断章取义的标准都易误导,要看网站之外的全貌(竞品广告战、负面新闻也会动数据)。

## A1 — 书中的应用 (Past Application)

### 案例 1: 转化率作为 UX 回报度量
- **问题**: 企业问"投在 UX 上的钱值不值"。
- **方法论的使用**: 作者以电商转化率为例——把 1% 转化率提升 1/10,财政收入可增 10%+; 转化率比单纯销售数更能感受 UX 投入回报。
- **结论**: 绑定"用户是否掏腰包"的行为指标才能衡量 UX。
- **结果**: 转化率成为常用的 UX 效果度量。

### 案例 2: 广告印象数的陷阱
- **问题**: 依赖广告收入的站用"印象数"作指标。
- **方法论的使用**: 作者警告: 主页与内容页间多插导航层能抬高印象数,但用户不需要,长期用户流失、印象数反跌。
- **结论**: 指标若不平衡用户需求会自我反噬。
- **结果**: 说明必须绑定真实用户行为而非表面曝光。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 写产品 KPI/OKR,不知选什么指标衡量体验。
2. 复盘时只报 PV/功能数,被质疑"这代表成功吗"。
3. 申请 UX 预算,需证明 UX 价值。
4. 内部工具上线,想证明"有用"。

### 语言信号
- "怎么衡量这个产品成不成功?"
- "KPI 定什么?"
- "转化率 / 成功标准 / ROI"
- "success metrics / conversion rate"

### 与相邻 skill 的区分
- 与 `strategy-dual-axis` 的区别: strategy 定"目标与需求是什么"; 本 skill 把目标变成"可追踪指标"。先有目标,后有指标。
- 与 `scope-definition-against-creep` 的区别: 范围是"做什么"; 本 skill 是"做完怎么算成"。

## E — 可执行步骤 (Execution)

1. **从战略目标反推行为**
   - 完成标准: 每条战略目标对应一个"用户可做的、能被设计影响的行为"。
2. **选可追踪指标**
   - 完成标准: 指标可量化、有采集手段(如转化率、回访率、任务完成时长)。
   - 判停条件: 若指标不可被设计影响(如新增用户靠营销),标注为"非 UX 可控,仅参考"。
3. **排查虚荣陷阱**
   - 完成标准: 检验指标是否可能通过损害用户需求来短期拉高(如印象数),如是则换指标或加平衡项。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 纯财务/股价等不可被 UX 设计影响的指标,不在本 skill 范围。
- 不要为凑指标而造指标: 指标须服务已定战略。

### 作者在书中警告的失败模式
- 断章取义的指标误导: 如单纯堆广告印象数短期升、长期因用户流失反跌更惨(ce 隐含)。
- UX 不能直接带来新用户(靠营销),却极大影响回访——误把"新用户数"当 UX 指标会错判。

### 作者的盲点 / 时代局限
- 书中指标偏 Web(转化率/印象数); 今天 AARRR、NPS、留存 cohort 等更细,但"绑定可设计影响的用户行为"原则不变。

### 容易混淆的邻近方法论
- 不要与"商业 KPI 全景"混淆: 本 skill 只关心"能反映 UX 是否达成战略"的那部分指标。
