## I — 方法论骨架 (Interpretation)

关于界面"像什么"的两条原则:

1. **克制比喻**: 用现实物体代表功能,常让界面更混淆而非更清晰。一个电话图可能代表"打电话/查语音/缴费"任一种; 咖啡店图代表聊天区会出问题。有效比喻的唯一标准是**减少用户对"功能是什么"的猜测**; 否则干脆去掉猜测成分,用清晰标签。
2. **习惯与一致性**:
   - 与用户**已有习惯**一致(如电话三乘四数字矩阵根深蒂固),降低学习成本。
   - 更要与**自身一致**: 概念模型一致、通用概念(开始/结束/保存)跨处统一处理,让用户迁移知识。
   - 谨慎违背习惯需有"明显益处"且理由充分; 不是无条件死守习惯。

作者强调: 比喻常只反映设计者脑中联系,用户会联想出众多比喻之一(尤其跨文化),内容与功能越多猜测越不可靠。

## A1 — 书中的应用 (Past Application)

### 案例 1: 西南航空书桌首页
- **问题**: 首页用"客户服务书桌"图片代表客服。
- **方法论的使用**: 作者将其列为"过度运用比喻"典型——预订机票可通过电话,但不意味预订系统该用电话图形代表。
- **结论**: 现实物体比喻在屏幕上常失效。
- **结果**: 改版后避免强比喻、增强功能性(c04)。

### 案例 2: 电话三乘四矩阵习惯
- **问题**: 非标准电话布局让用户每次多花 3 秒研究按钮。
- **方法论的使用**: 作者以"习惯魔毯被抽走"说明与习惯冲突的挫败; 三乘四矩阵成多设备标准。
- **结论**: 一致习惯降低下意识操作成本。
- **结果**: 说明"与习惯一致"的价值。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 想用图标/实物图形代表抽象功能。
2. 界面与用户习惯冲突导致误操作。
3. 评审"这个比喻用户懂吗"。
4. 决定"要不要打破常规交互"。

### 语言信号
- "用档案柜图标代表云存储行吗?"
- "用户老点错,是不是习惯问题?"
- "比喻 / 隐喻 / 习惯"
- "metaphor / habit"

### 与相邻 skill 的区分
- 与 `conceptual-model-consistency` 的区别: conceptual-model 讲"概念如何保持一致、选熟悉模型"; 本 skill 讲"克制比喻冲动 + 习惯一致",偏克制与警示。两者同源互补。
- 与 `interface-design-defaults` 的区别: interface 关注控件与最常见行为; 本 skill 关注隐喻与习惯的一致性。

## E — 可执行步骤 (Execution)

1. **检验比喻是否减少猜测**
   - 完成标准: 若图标/实物图形让用户需"猜"含义,改为清晰文字标签或去掉比喻。
2. **对齐用户习惯**
   - 完成标准: 通用控件沿用用户已有习惯(如标准矩阵/标准控件),不无故创新。
   - 判停条件: 若必须违背习惯,写下明确益处并验证。
3. **确保自身一致**
   - 完成标准: 通用概念(开始/保存)跨界面统一处理,概念模型全程一致。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 纯文字/无界面隐喻的内容产品。
- 不要为"一致"牺牲明确益处的新交互——有充分理由可谨慎违背习惯。

### 作者在书中警告的失败模式
- 比喻增加猜测: 电话图/咖啡店图代表多重含义,用户猜错(ce03)。
- 与习惯冲突: 非标准布局让用户每步多花时间、充满挫败。

### 作者的盲点 / 时代局限
- "克制比喻"对游戏/儿童产品未必适用——适度比喻可增趣味; 原则是"减少猜测"而非"全禁"。

### 容易混淆的邻近方法论
- 不要与"品牌视觉风格"混淆: 本 skill 是交互隐喻与习惯,风格指南是视觉一致性。
