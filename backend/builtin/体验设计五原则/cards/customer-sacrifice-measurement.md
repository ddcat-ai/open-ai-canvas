## I — 方法论骨架 (Interpretation)

三个公式，参照系完全不同：

| 指标 | 公式 | 参照系 | 它回答的问题 |
|---|---|---|---|
| **顾客满意度** | 期望值 − 感受值 | **你的现状与同行水平** | 我们做得怎么样？ |
| **顾客损失** | 顾客真正需要 − 顾客勉强接受的现实 | **顾客自己的理想** | 顾客到底想要什么？ |
| **顾客惊喜** | 感受值 − 期望值 | 顾客的预期 | 顾客会回忆什么？ |
| **顾客悬念** | — | 未来 | 接下来会发生什么？ |

（3S 模型是**层叠三角**：满意在底、损失在中、惊喜在顶。"如果没有顾客满意度的提升以及顾客损失的下降，激发顾客惊喜也就失去了基础。"第四个 S 是悬念。）

### 为什么满意度会骗人

满意度的参照系是"顾客的期望"，而**期望是被你和你的同行共同塑造出来的**。所以：

- 整个行业一起糟糕时，满意度可以普遍很高——因为大家的期望都被压低了。
- 满意度衡量的是**市场表现而非每个消费者**；调查的设计目的是便于制表统计；顾客也知道填了对自己没好处。
- 调查的隐含主题永远是"**我们的表现如何？**"，而不是"你到底要什么"。

### 虚假满意的生成机制（本 skill 最锋利的一段）

乘客要百事，空乘反问"可口可乐行吗？"，乘客让步——**产生一次损失**。多次之后，这位乘客**直接点可口可乐**。

此时满意度达标了：期望与感受一致。但真实发生的是——**航空公司硬是把乘客变成了接受无奈选择的人。**

> 每一次企业与顾客的互动，对双方都是学习机会，最终总有一方改变行为。"不幸的是，事实证明很多情况下做出改变的都是顾客而非企业。"

顾客改变行为的两种方式：违心地点自己不想要的东西，**或者转身离开**。

### 顾客说不清，问题不在顾客

- 长期隐忍导致麻木，"连他们自己也很难说清楚到底有哪些需求"；即使解释了顾客损失的概念，大部分顾客仍分不清"得过且过的需求"与"货真价实的需求"。
- 但作者明确定罪：**问题在企业的提问方式**。"人们总是习惯于根据问题的引导来做出回答"，而企业提的问题本身就是规模化生产思维的产物。
- 方法转向：焦点小组、情景法、联合分析、问卷都还能用，但要**从顾客的体验反应中寻找独特性**，而不是从共享式期望里找共性。
- **"普通顾客"不存在**：除非把顾客视为一个个真实的、特定的、活灵活现的个体，否则永远弄不清个体层次上的真实需求。"旁观者清"——单个真实顾客恰恰能一针见血指出"普通顾客"语焉不详的损失。

### 损失的四种类型（与消除方式一一对应）

| 损失类型 | 顾客在忍什么 | 对应的消除方式 |
|---|---|---|
| **选择问题** | 被迫在难以权衡的维度间取舍，且说不清要什么 | 合作型定制 |
| **组合问题** | 面对过多制成品/组件必须自己挑 | 适应型定制 |
| **形式问题** | 功能没问题，忍的是包装/交付/时点/说法 | 装饰型定制 |
| **重复问题** | 每次都要重新说一遍自己是谁、要什么 | 透明型定制 |

### 反向指标：新学习曲线

旧学习曲线：成本随累计产量下降。**新学习曲线：顾客损失随互动次数下降。**
这既是壁垒，也是本 skill 唯一值得长期追踪的指标——**你和这个顾客打交道越多，他被迫将就的东西应该越少。如果没有，学习关系根本没建立。**

## A1 — 书中的应用 (Past Application)

### 案例 1：可口可乐 / 百事（第4章 p129）
- **问题**：航空公司的餐饮满意度调查一直不差，问题在哪？
- **方法论的使用**：追踪一次具体互动——乘客要百事，被反问"可口可乐行吗"，让步；多次之后直接点可口可乐。
- **结论**：满意度上升的原因不是服务变好，而是**顾客的期望被驯化了**。这是"虚假满意"的标准生成路径。
- **结果**：作者指出，藏在虚假满意背后的，正是"把普通服务转变成难忘体验"的创新机会。

### 案例 2：汽车业满意度与重购的脱钩（幕间 p150）
- **问题**：理特咨询调查显示 90% 车主表示"满意"。
- **方法论的使用**：把满意度与真实行为对照——每年仍有数百万人遇到问题车，且**只有 40% 的车主下次还买同一制造商**（同款车型比例更低）。
- **结论**：满意度与重购脱钩。90% 的满意换不来 50% 的忠诚。
- **结果**：作者建议把打折回扣的钱改成**买车之后寄出的意外惊喜奖励**——回扣只在特定期间影响特定型号，惊喜能长期影响下一次购买。

### 案例 3：卢斯气动控制的"集成员"（第5章 p135）
- **问题**：客户说不清自己要什么样的阀门。
- **方法论的使用**：把兼具开发/制造/营销职能的工程师称为"集成员"，**直接到客户产线上观察实际问题**，从模块库快速做出原型，不满意就做第二个第三个，**直到消除所有损失**。
- **结论**：损失不是问出来的，是看出来和试出来的。
- **结果**：耐特实业 CEO 詹姆斯·扎古罗利面对挖角报价的回答："我为什么要跟你合作？卢斯为我们提供的产品要比你们领先五代！"连以压榨供应商著称的通用汽车都不换供应商。

### 案例 4：常客计划的批判（幕间 p150）
- **问题**：航空里程、停车券、咖啡集章卡这些"忠诚计划"为什么不产生忠诚？
- **方法论的使用**：作者指出致命缺陷——**面向整体推出、人人可参加，顾客知道这不是"为我"营造的**，久而久之把额外服务视为理所应当（"这是我挣来的"）。
- **结论**：它纵容顾客期待免费，**和回扣一样加速初级产品化**。
- **结果**：正面对照是 Macaroni 意大利餐厅——不发优惠券（那是期望设定型手段），而在服务和饮食都极好、顾客已准备付账时**随机免单**。成本约每月流水的 3.3%，影响远超同额广告或同比例打折。

### 案例 5：有线电视捆绑（第5章 p132）—— 框架预测力的实证
- **问题**：顾客只对少数频道感兴趣，却被迫接受一大包。
- **方法论的使用**：作者当时（1999/2011）识别出这是典型的"组合问题"损失，并设想把每个节目/电视台当模块，程控组合成"我的频道"。
- **结论**：这是**顾客损失框架的一次公开预测**。
- **结果**：Netflix、YouTube、流媒体订阅、TiVo/Roku 后来完整实现了这一设想——**框架的预测力被事后印证**。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **好评很多但业务不涨**：满意度/NPS/评分都体面，增长停滞或流失上升。
2. **被新玩家快速蚕食**：搞不清对手到底攻的是哪一点。
3. **用户调研做完没有可执行结论**：问卷一堆图表，最后只得出"要提升服务质量"。
4. **用户说不清自己要什么**：访谈里全是"挺好的""还行"。
5. **老客户静悄悄流失**：没有投诉、没有差评、人就不见了。
6. **复购/续费上不去**，但首购转化正常。
7. **要立项做新产品但找不到切口**：损失差额就是切口。
8. **要建长期壁垒**：新学习曲线是可追踪的壁垒指标。

### 语言信号 (用户的话里出现这些就应激活)

- "满意度/NPS/评分挺高的，但是……"
- "好评如潮，客户却在流失 / 复购不行"
- "竞品突然起来了，不知道我们输在哪"
- "用户调研做了很多，没什么用"
- "用户自己也说不清想要什么"
- "客户没投诉啊，怎么就不续费了"
- "客户都说习惯了 / 都这样 / 凑合用"（★这三句是损失的直接语言标记）
- "customer satisfaction" / "NPS" / "voice of customer" / "customer sacrifice"

### 与相邻 skill 的区分

- 与 `mass-customization-four-modes` 的区别（最紧的一组）：本 skill 是**诊断**（测出顾客在忍什么、属于四类损失中的哪一类）；那个是**处方**（用合作/适应/装饰/透明哪种方式消除它）。四类损失与四种定制方式严格一一对应，几乎总是连用。
- 与 `diy-usability-test` 的区别：那个看**用户能不能顺利完成任务**（操作层面的卡点，看得见）；本 skill 找**用户已经默默接受了什么将就**（期望层面的妥协，看不见，用户自己都不觉得是问题）。可用性测试能发现"这里点不动"，发现不了"他其实根本不想点这个"。
- 与 `question-substitution-check` 的区别：那个防的是**你自己**把难问题偷换成易问题；本 skill 防的是**你的调研工具**把"顾客要什么"偷换成"我们表现如何"。两者精神相通，一个对内一个对外，可以叠用。
- 与 `wysiati-evidence-audit` 的区别：那个审查"结论所依据的证据够不够"；本 skill 审查"你在测量的东西是不是正确的东西"。指标错了，证据再多也没用。
- 与 `expectation-experience-engineering` 的区别（★容易混）：那个讲**主动塑造预期来改善真实体验**（把预期当工具用）；本 skill 警告**预期被塑造之后满意度就失去了诊断价值**（把预期当污染源看）。两者不矛盾，但同时使用时必须分清：你是在用预期，还是在被预期骗。
- 与 `goodwill-reservoir` 的区别：那个判断"这个做法会不会惹毛用户"（情绪账户余额）；本 skill 测的是"用户默默忍受了什么"——**不惹毛不等于没损失**，静默的将就恰恰不消耗好感储备，因此最危险。
- 与 `average-user-fallacy` 的区别：那个反对用"平均用户"做设计决策；本 skill 的"'普通顾客'不存在"是同一精神在**调研方法**上的应用。可互为佐证。

## E — 可执行步骤 (Execution)

1. **先做一次指标体检**
   - 列出现有的所有顾客指标，逐个标注参照系：锚在**我们的现状/同行水平**（满意度族）还是**顾客的理想**（损失族）。
   - 完成标准：能说出"我们 100% 的指标都锚在自己身上"。
   - 判停条件：若已有损失类指标且持续下降，本 skill 不适用，转 `mass-customization-four-modes` 继续消除。

2. **换掉提问方式**
   - 禁用："您对……满意吗""打几分""哪里需要改进"。
   - 启用："**如果没有任何限制，您真正想要的是什么？**""这一步您是怎么将就过去的？""您有没有为了配合我们而改变过自己的做法？"
   - 完成标准：新提纲里**没有一道评分题**。

3. **抓"将就"的语言标记**
   - 在访谈/客服记录/评论里搜这些词：**"习惯了""凑合""都这样""也没办法""反正""只能"**。
   - 每一处都是一个损失点。
   - 完成标准：至少收集 20 条原话，附上下文。

4. **去现场看，而不是只问**（移情设计 / 集成员做法）
   - 到顾客实际使用的场景里观察：他自己搭的临时方案、他手写的备忘、他绕开你产品的那一步、他导出到 Excel 再手工处理的那个环节。
   - **顾客自己发明的补丁，就是损失最硬的证据。**
   - 完成标准：至少 3 个现场，每个有一张"顾客自制补丁"的照片或截图。

5. **写损失清单并归类**
   - 每条写成："顾客真正想要 ______，但他勉强接受了 ______。"
   - 归入四类：选择问题 / 组合问题 / 形式问题 / 重复问题。
   - 完成标准：每条都能落到某一类；落不进去的单列，可能是能力缺口而非损失。

6. **识别虚假满意**
   - 交叉核对：满意度高但**行为**（复购、续费、推荐、使用深度）不跟随的地方。
   - 问："我们的顾客有没有被我们训练成不再提要求的人？"（可口可乐/百事检验）
   - 完成标准：列出至少一处"满意但不复购"的落差。

7. **排序并交棒**
   - 按"损失大小 × 可消除性"排序，取 Top 3。
   - 交给 `mass-customization-four-modes` 选消除方式。
   - 完成标准：Top 3 各自标注了损失类型与对应的定制方式。

8. **建立长期指标：损失随互动次数下降**
   - 完成标准：定义一个可重复测量的损失指标（如"顾客需要重复提供信息的次数""顾客自制补丁的数量"），按互动轮次追踪。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产品还没有真实用户**：没有"勉强接受的现实"，就测不出损失。此时用别的方法找需求。
- **合规/安全约束造成的"将就"**：顾客想要但法规不允许（金融风控、医疗流程、实名认证），这不是可消除的损失。
- **顾客的"真正需要"本身有害**（作者在第9章的道德刹车同样适用）：赌博、成瘾、欺诈类需求，消除损失 = 加害。
- **组织没有能力承接结论**：损失清单会指向根本性改造。若只是要一份季度报告，测出来也没人动，反而消耗信任。
- **用户只是抱怨价格**：那不是损失（损失是"想要 A 拿到 B"），转 `reference-price-framing`。

### 作者在书中警告的失败模式

- **调低顾客期望**（第5章开篇）：迫使顾客接受次于真实需求的东西，看似既降成本又不引发不满，但**必然导致初级产品化**。作者称之为以牺牲顾客利益换取公司成本。
- **假设"顾客根本不会在意"**：作者直接称这是损失的源头。不研究个体真实需求，花大力气做出来的东西反而让顾客叫苦，**成本其实更高**。
- **让顾客"帮助我们改造公司"式的问卷**：作者批评某航空公司的做法——"不是夸大普通顾客意见的影响，就是低估企业革新的性质"。
- **常客计划与打折回扣**：纵容顾客期待免费，把额外服务变成"我挣来的"，加速初级产品化。
- **只统计不接触**：调查设计的目的是便于制表，顾客知道填了对自己没好处，于是双方合谋产出无用数据。

### 作者的盲点 / 时代局限

- **案例来自 1990s 末的制造业与航空业**（阀门、汽车、机上饮料、有线电视）。**案例已过时，数字化语境下需重新检验**；但"参照系决定指标有效性"这一机制完全不受时代影响，且在 NPS 泛滥的今天更加尖锐——NPS 同样锚在竞品参照系上，本 skill 的批评对它全部适用。
- **⚠️ 顾客损失无法直接量化**。满意度虽然浅，但可以打分、可以对比、可以进 KPI；顾客损失是一个**差额概念，两端都不可直接观测**（"真正需要"顾客自己都说不清）。本书给了大量定性方法，**但没有给出任何量化方案**——所以它很难进管理仪表盘，也很难说服要看数字的老板。这是本 skill 最大的落地障碍，E 段步骤 8 是本次整理补入的替代方案（用代理指标：重复提供信息的次数、自制补丁数量）。
- **过度贬低满意度调研**：满意度虽然锚错了参照系，但在服务质量的**下限管控**（发现执行崩塌、门店异常、事故）上仍然有效。正确做法是**两者并用**：满意度守下限，损失找上限。书里把它当作应当被取代的东西。
- **"顾客说不清是企业提问方式的错"过于绝对**：有些需求确实需要技术出现之后才能被表达出来（乔布斯式反调研立场）。本书把责任全部推给提问方式，回避了"有些东西只能靠供给侧发明"的情况。
- **共创视角缺失**（作者珍藏版序言自认）：损失由企业去测、由企业去消除，顾客始终是被观察对象。开源社区、UGC 平台上顾客自己就在消除自己的损失。

### 容易混淆的邻近方法论

- **NPS（净推荐值）**：本 skill 的批评对它完全适用——"你会推荐给朋友吗"的隐含参照系仍是"和别家比"。高 NPS 可以与高顾客损失并存（全行业一样烂时）。
- **Jobs-to-be-Done**：非常接近，都在找"顾客真正要完成的事"。区别是 JTBD 关注**任务与动机**（他雇这个产品来做什么），顾客损失关注**妥协与差额**（他为此忍了什么）。JTBD 更适合找方向，顾客损失更适合找具体改造点。两者可叠用。
- **痛点分析**：痛点是顾客**会说出来**的不满；顾客损失是顾客**已经不说了**的妥协。后者更深也更危险——不痛了不代表不亏。
- **可用性测试**：看操作能不能完成；损失测量看"这件事根本不该由他做"。
