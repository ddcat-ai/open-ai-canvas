## I — 方法论骨架 (Interpretation)

第三定律的前提是第二章那条事实：用户在扫描，不在阅读。既然大部分字不会被读到，
那么它们就不是"信息"，而是**负债**——它们占空间、稀释密度、把真正有用的那几个字埋掉。

删减带来三重收益：降低噪声；让剩下的内容显著度上升；页面变短，于是更多内容进入可见范围。
注意第三条是复利效应：删字不只是让这段变清楚，它让整页都变清楚。

有两类文字应该最先被杀：

**① 欢迎词（happy talk）**。"欢迎光临本站，我们致力于为客户提供……"。
它是网页版的鸡尾酒会寒暄，零信息，纯粹占位。全删。

**② 指示文字（instructions）**。绝大多数人根本不读。而且它的存在通常是一个信号：
界面本身失败了，所以需要一段话来补救。正确的顺序是——先试着把界面改到不需要说明；
实在必须保留的指示，删到只剩骨头。

所以本 skill 不只是"精简文案"，它内含一个诊断动作：**这段文字是在传递信息，
还是在给一个失败的设计打补丁？** 如果是后者，删文案只是治标，要标记为设计待重做点。

删的判据很硬：**这句话删掉，用户会做错事吗？** 不会 → 删。
不要用"万一有人需要呢"来保留文字——万一有人需要的东西应该放在他会去找的地方，
而不是撒在所有人的路上。

## A1 — 书中的应用 (Past Application)

### 案例 1: 借用《风格的要素》第 17 条
- **问题**：作者要为"删文字"找一个足够硬的依据。
- **方法论的使用**：直接引用 E.B. White《风格的要素》规则 17——"句子里不应该有多余的
  文字，段落不应该有多余的句子。同样，画上不应该有多余的线条，机器上不应该有多余的零件"。
- **结论**：冗余在任何一种"被制造出来给人用的东西"上都是缺陷，不是文风问题。
- **结果**：把删字从写作偏好升级为设计规则，并给出一个夸张到可执行的量化目标（减半再减半）。

### 案例 2: 欢迎词与指示文字是首要目标
- **问题**：团队不知道该从哪里下刀。
- **方法论的使用**：作者直接点名两类高确定性的删除对象。
- **结论**：不用逐句权衡，先整块清掉这两类。
- **结果**：删减动作从"痛苦的逐句取舍"变成"先做两次整块切除"，效率高且争议小。

### 案例 3: 决定性答案里的重复强调
- **问题**：有些排版规则反复被违反。
- **方法论的使用**：作者在全书最后的"决定性答案"清单里，把"不要让标题漂浮在段落之间"
  又说了一遍，并注明"我知道第 3 章已经提过，不过它很重要"。
- **结论**：删减之后，剩下文字的**归属关系**同样重要。
- **结果**：本 skill 的执行步骤里保留"标题贴紧其下文"这一条排版检查。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手上有一段页面文案/引导页/空状态提示，觉得太长但不知道删哪。
2. 团队提议"这里加一段说明"来解决用户困惑。
3. 写错误提示、表单提示、按钮文案、Toast 消息。
4. 写周报、需求文档、变更公告、群通知，希望别人真的看完。
5. PPT 一页写满字，要压到能被扫读。
6. 帮助文档/FAQ 太长，用户宁可来问客服。
7. 有人说"这段没人看"。

### 语言信号（用户的话里出现这些就应激活）

- "文案太长 / 字太多 / 帮我精简一下 / 压缩到几句"
- "要不要加个说明 / 加个提示 / 写段引导"
- "这段没人看 / 用户不读 / 写了也白写"
- "欢迎语怎么写 / 空状态写什么"
- "too wordy / cut this down / trim the copy / nobody reads this"

### 与相邻 skill 的区分

- 与 `human-writing` / `ra-人话` 的区别：那两个处理**文风**（去 AI 腔、说人话、可读性）；
  本 skill 处理**信息量取舍**（该不该存在），并且服务于"被扫描"而非"被阅读"。
  可以先用本 skill 删，再用它们改口气。
- 与 `positioning-oversimplified-message` 的区别：那个是把**对外传播的定位信息**
  砍到一个词以进入心智；本 skill 是把**界面上的功能性文字**砍到不妨碍任务。
  一个为记忆，一个为操作。
- 与 `ability-simplification` 的区别：那个降低执行门槛（少填几个字段、少交一份材料）；
  本 skill 降低阅读量。
- 与 `dont-make-me-think-audit` 的区别：那个覆盖全部问号来源；本 skill 是它的文字专项，
  且额外带一个"该删文案还是该重做界面"的诊断。

## E — 可执行步骤 (Execution)

1. **确认文本类型与阅读姿势**
   - 判断：这段文字的读者是在**扫**还是在**读**？
   - 判停条件：若属法律/合规/医疗/金融披露、教程长文、叙事写作 → 本 skill 不适用，
     立即说明并终止。

2. **第一刀：整块切除两类目标**
   - 欢迎词（"欢迎光临""我们致力于""感谢您的关注"）→ 全删。
   - 指示文字 → 先标记，进入步骤 3 判断。
   - 完成标准：给出删除后的版本，并报告删掉了多少字（百分比）。

3. **对每段指示文字做"补丁诊断"**
   - 问：这段说明存在，是因为界面本身让人看不懂吗？
   - 是 → 标记为**设计待重做点**（记录下来，别只删文字），并给出界面改法建议。
   - 否 → 删到只剩骨头（通常一句、≤15 字）。
   - 完成标准：每段指示文字都有"删 / 精简 / 界面重做"三种处置之一。

4. **第二刀：逐句问"删掉会做错事吗"**
   - 不会 → 删。会 → 留，但压缩。
   - 特别处理：形容词、程度副词、客套、重复的品牌自述、"请注意""温馨提示"类前缀。
   - 完成标准：字数相比原文下降 ≥50%（第三定律的最低目标）。

5. **关键词前置（中文尤其重要）**
   - 每句/每个链接文字/每个标题，把最能判别的词挪到最前面。
   - 依据：用户只扫一行的前几个字（屏幕阅读器用户则只听前几个字）。
   - 完成标准：逐条检查首词是否具有判别力。

6. **排版归属检查**
   - 标题必须贴紧它下面的正文；能列表化的列表化；段落拆到 ≤3 行。
   - 完成标准：视觉上不存在"归属不明"的标题。

7. **输出三件套**
   - ① 精简版全文；② 删除清单（删了什么、为什么）；③ 设计待重做点清单（如有）。
   - 完成标准：三件都在，尤其③不能省——它是本 skill 与普通"精简文案"的区别所在。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **需要完整披露的文本**：法律条款、隐私政策、合规声明、药品说明、金融风险提示、
  保险条款。这类文本的读者会（也必须）逐字读，删减会造成合规与安全风险。
- **高涉入决策的信息页**：购房、大额 B 端采购、医疗方案对比。用户真的会读，
  信息完整性优先于简洁性。
- **教程、深度长文、课程材料**：目标是被读完并理解，不是被扫一眼。
- **叙事与文学写作**：冗余在这里可能正是价值所在。
- **只需要改文风不需要减信息时**：转 `human-writing` / `ra-人话`。

### 作者在书中警告的失败模式

- **用加说明来治困惑**。作者的立场很硬：说明文字大多数人不读，加说明通常只是把
  失败的设计埋起来。本 skill 因此内置"补丁诊断"步骤。
- **保留欢迎词以显得礼貌**。作者视之为纯噪声。
- **删了字却没修归属**：标题仍漂在两段之间，删减的收益被抵消。

### 作者的盲点 / 时代局限

- 第 3 版正文写于 2013 年，观察对象是英文桌面 Web。**中文语境需要校准**：
  中文单字信息密度高于英文，机械地"删一半字"可能删过头；更准确的理解是
  **"删一半信息噪声"**。同时中文无空格分词，关键词前置的收益比英文更大。
- **未覆盖移动端与小程序的空间约束差异**，也未覆盖语音/对话式界面（那里文字量的
  权衡逻辑完全不同）。**涉及具体设备与控件的判断需在当代语境下重新检验。**
- 作者不提供"如何写好剩下那几个字"的方法（诊断非生成）；写作质量需另配方法。

### 容易混淆的邻近方法论

- **E.B. White《风格的要素》规则 17**：本定律的直接来源，但 White 谈的是写作，
  Krug 把它移植到"不会被读的文字"上，量化目标更激进。
- **金字塔原理**：那是**结构**方法（结论先行、分组归类）；本 skill 是**削减**方法。
  两者可叠加：先用金字塔定结构，再用第三定律砍体量。
