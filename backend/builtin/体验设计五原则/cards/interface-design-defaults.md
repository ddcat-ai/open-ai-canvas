## I — 方法论骨架 (Interpretation)

界面设计=选对界面元素帮用户完成任务、并让其易理解易用。两条要点:

1. **聚焦最常见行为**: 成功界面让用户一眼看到"最重要的东西";不重要的不该被注意(甚至不出现)。组织好用户最常走的路径,用最容易的方式获取。
   - **注意程序员盲区**: 程序员习惯平等对待所有可能性(含边缘情况),因为"建永不犯错的系统"有成就感。但这对界面行不通——为极少数用户呈现极端情况=给大多数用户劣质界面。
2. **降低可发现性 + 设好默认值**: 弄清用户"不需要知道什么",减少其可发现性(或干脆排除)。默认值技巧: 理解多数用户目标后,默认勾选"显示更多细节"等,让多数人不需决策即满意;更好的做法是记住用户上次选择(技术允许时)。

权衡是常态: 下拉菜单省空间但隐藏选项; 单选框显所有但占空间; 六选项时复选框可能更好。按"用户最常做"取舍。

## A1 — 书中的应用 (Past Application)

### 案例 1: 程序员边缘情况盲区
- **问题**: 界面把极端情况平等呈现。
- **方法论的使用**: 作者指出这给大多数用户劣质界面,只满意少数; 好界面组织最常见行为。
- **结论**: 界面设计不等于"覆盖所有可能性"。
- **结果**: 成为界面设计的核心警示。

### 案例 2: 默认勾选"显示更多细节"
- **问题**: 用户常不读复选框标签就决策。
- **方法论的使用**: 作者建议默认设多数人会满意的状态(如默认勾选显示细节),或记住上次选择。
- **结论**: 默认值降低决策负担。
- **结果**: 成为默认值技巧范例。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要 this skill?
1. 设计表单/控件,纠结默认勾不选、暴露哪些高级选项。
2. 界面被说"太复杂/找不到重点"。
3. 工程师坚持"所有情况都要让用户选"。
4. 做组件库/界面规范。

### 语言信号
- "默认勾不选?"
- "这个高级选项要不要显示?"
- "界面太复杂 / 找不到重点"
- "interface design / 默认值 / 最常见行为"

### 与相邻 skill 的区分
- 与 `navigation-wayfinding` 的区别: navigation 是移动路径; 本 skill 是单个界面内控件与行为组织。
- 与 `metaphor-restraint` 的区别: metaphor 关注隐喻与习惯; 本 skill 关注行为聚焦与默认值。

## E — 可执行步骤 (Execution)

1. **识别最常见行为**
   - 完成标准: 列出用户最常做路径,确保其元素最易获取、最显眼。
2. **降低非必要可发现性**
   - 完成标准: 用户不需知道的东西降低暴露(或移除); 不为边缘情况牺牲主流。
   - 判停条件: 若某高级选项仅少数用,默认隐藏/折叠。
3. **设合理默认值**
   - 完成标准: 默认态迎合多数用户目标(如默认勾选),或记住上次选择。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 无界面的纯后台逻辑。
- 不要为"简洁"而隐藏关键必选项——降低可发现性指非必要项,非核心操作。

### 作者在书中警告的失败模式
- 程序员平等对待边缘情况: 给大多数用户劣质界面。
- 不读标签就决策的用户: 默认值设错会大面积误导。

### 作者的盲点 / 时代局限
- "降低可发现性"需掌握好分寸,现代可发现性(渐进披露)更强调"需要时可达"; 全隐藏关键功能会伤可用性。

### 容易混淆的邻近方法论
- 不要与"功能规格"混淆: 本 skill 是界面层行为组织,规格是范围层描述。
