## I — 方法论骨架 (Interpretation)

1. 态度与内容双通道：口气可软，信息必须无歧义。
2. 婉拒 = 软口气 + 硬内容，不是留周旋空间。
3. 把表达落实到沟通最小单位的括号内（如"洗碗和擦灶台"）。
4. "我以为说了其实没说"的乌龙，源于内容不直接。
5. 直接让意思准确，预期管理让直接被接住（见 yt-expectation-buffer）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 晚会拒绝乌龙（c08）
- **问题**: "目前来看，我们的时间可能不行"被理解为有周旋空间，对方上报了名字。
- **方法论的使用**: 正确婉拒应为"因档期无法参加，期待未来合作"。
- **结论**: "目前""可能"给误解留了门。
- **结果**: 填坑耗费更多精力，乌龙典型。

### 案例 2: 洗碗 vs 擦灶台（2-04）
- **问题**: "你负责洗碗吧"事后被责"怎么不擦灶台"。
- **方法论的使用**: 概念需明示——"今天你负责洗碗和擦灶台"。
- **结论**: 洗碗概念不含擦灶台，需落到最小单位括号内。
- **结果**: 撒娇/考验除外，工作指令须精准。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要拒绝一个请求，又不想伤关系。
2. 发现对方总误解自己的意思。
3. 要给团队/伴侣明确指令。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么拒绝不伤人"
- "对方老误解我 / 我说了但他理解成另意思"
- "说清楚点"

### 与相邻 skill 的区分

- 与 `yt-expectation-buffer` 的区别：本卡管"内容精准无歧义"，预期管理管"情绪缓冲"，两者串联。
- 与 `yt-persona-boundary` 的区别：直接声明边界（如"不借钱"）是边界的一种落地方式。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **区分态度（可软）与内容（必须硬）**
   - 完成标准：软口气包裹下，结论无"可能/大概/再说"等模糊词。
2. **拒绝时给明确结论 + 替代/延展弹性**
   - 完成标准：如"因档期无法参加，期待未来合作"，不留周旋空间。
3. **概念落实到最小单位括号内**
   - 完成标准：如"洗碗和擦灶台"，对方无"我以为你说的是另意思"空间。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 亲密关系撒娇/考验（书中明确排除）：此时模糊是互动的一部分。
- 纯情绪宣泄：见 yt-emotion-not-weapon，需做树洞而非给指令。

### 作者在书中警告的失败模式

- 把"委婉"当"含糊其辞"：态度软变成内容模糊，引发"我以为说了其实没说"乌龙（c08）。

### 作者的盲点 / 时代局限

- 弱势方"直接"可能触发对方权力反扑——需配 yt-persona-boundary 评估权力差，必要时先设缓冲（yt-expectation-buffer）。

### 容易混淆的邻近方法论

- 与"态度凶"混淆：本书"直接"=信息精准无歧义，非态度凶；与委婉态度可并存（婉拒）。
