## I — 方法论骨架 (Interpretation)

1. 从"谁负责"到"我负责"：主动为沟通找支点，身份实质转变。
2. 犯错三步：原因 → 方案 → 防范；多数人只走第一步就拐借口。
3. 方案前置：沟通前带解决问题思路，把"问题意识"转"方案意识"。
4. 白皮书：团队把踩过的雷按"原因/方法/防范"写详，防重于补。
5. 道歉重构：态度 + 自己原因 + 建设方案（非借口）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 白皮书机制（c11）
- **问题**: 个人错误重复发生，团队踩同坑。
- **方法论的使用**: 把踩过的雷按原因/方法/防范写详，越详越好。
- **结论**: 问题在发生前被拦截，非事后弥补。
- **结果**: 个人反思升团队，沟通有底气。

### 案例 2: 机场粉丝合照预案（c10）
- **问题**: 突发合照请求易措手不及。
- **方法论的使用**: 方案前置——艺人化妆/人数/安保倒推，五人座位预排。
- **结论**: 问题意识转方案意识。
- **结果**: 临场不乱。

### 案例 3: 道歉"你都是对的"更火（c15）
- **问题**: "对不起我错了你都是对的"比不道歉更火大。
- **方法论的使用**: 找自己原因（非"但是/可是"借口）+ 建设方案（"周六补上"）。
- **结论**: 借口推责，原因自省。
- **结果**: 态度+自因+方案=近完美道歉。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 搞砸了要跟老板/客户/伴侣解释。
2. 想显得靠谱、主动担责。
3. 要修复一段因失误受损的关系。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么道歉"
- "搞砸了怎么说"
- "怎么显得负责 / 有底气"

### 与相邻 skill 的区分

- 与 `yt-expectation-buffer` 的区别：坏消息若属认错，本卡管三步结构、预期管理管缓冲。
- 与 `yt-emotion-not-weapon` 的区别：道歉是修复（态度+自因+方案），不是把情绪当武器。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **认错结构：原因 → 方案 → 防范**
   - 完成标准：不拐借口，三步齐全。
2. **沟通前备方案（问题前置）**
   - 完成标准：进沟通前已知"问题是什么、我的方案是什么、最佳方案吗"。
3. **建白皮书 / 个人反思本**
   - 完成标准：错误按原因/方法/防范记录，防再犯。
4. **道歉 = 态度 + 自己原因 + 建设方案**
   - 完成标准：无"但是/可是/不过"借口，含具体补救。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 非己方责任硬揽（过度自责）：负责≠背锅。
- 把结构性压迫（如职场PUA）归因为个人沟通不当：需识别结构性问题。

### 作者在书中警告的失败模式

- ce03 只说优点掩盖错误：犯错后先汇报漂亮事避重就轻，显眼高手低、无责任心，埋更大雷。
- ce05 道歉用借口："但是/可是/不过"把责任推对方或外界，比不道歉更火大。

### 作者的盲点 / 时代局限

- 视角为老板/经纪人（上位）："主动负责"滑向过度自我苛责；弱势方面对结构性不公时，负责非万能，优先保护自己（见 yt-persona-boundary）。

### 容易混淆的邻近方法论

- 与"背锅"混淆：本书负责=主动找支点解决，非替人扛；从"我得负责"到"必须由我负责"是身份转变。
