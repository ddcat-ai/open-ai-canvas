# 豆包音频提示词

## 范围与证据边界

本技能是结合影策当前协议编写的提示词建议，不是检索到的官方技能，也不是经过真实音频试听验证的效果保证。

适用于旁白、口播、角色对白和参考声音生成。以当前模型目录和工具 schema 为准，不将 seed-audio-1.0 的写法直接套给其他 TTS 模型。

当前协议将节点 prompt 发送为 text_prompt，参考素材另行传输。支持最多 3 段参考音频或 1 张图片，两者不能混用。音频引用使用 @Audio1、@Audio2、@Audio3，与参考顺序一致。

## 写作流程

1. **冻结台词**：用户给定原文则保留，不擅自扩写、添加口头禅或承诺。用户要求创作文案时先定稿。
2. **明确声音任务**：谁在对谁说，什么情绪、什么强度。每段只选一个主要表演方向。
3. **分离表演与速度**：温柔、低声、克制不等于慢速。除非用户要求，默认自然日常语速、短暂停顿，不拖尾音。
4. **明确参考职责**：参考音频用于音色还是语气，写清；不要无意中要求复制慢速参考的全部节奏。只能引用实际连接的素材。
5. **试听短样**：先用一两句试听，分别检查台词准确、音色、语速、停顿和杂音，再扩展长文本。一次只改一个主要变量。

## 建议提示词结构

> 说话方式 + 情绪与节奏 + 要说的原文

这是自然语言写法建议，不是硬编码语法。若说明被念出，先简化为纯台词建立对照，再逐项加回；不要杜撰 SSML 或情绪标签支持。

### 自然口播

```text
用自然、亲切的语气说，正常语速，句间短暂停顿，不拖尾音。只说：“大家好，欢迎来到影策工作台。”
```

### 克制对白，不默认放慢

```text
用压低但清晰的声音说，情绪克制，保持正常对话节奏，句尾干净利落。只说：“我知道了。你先回去吧。”
```

### 广告解说

```text
声音明亮、有精神，表达清楚连贯，重点落在“现在出发”，不逐字强调。只说：“把想法变成画面，现在出发。”
```

### 参考音色

先连接对应参考音频，再写：

```text
参考 @Audio1 的音色，以自然、正常的对话语速说，停顿简短。只说：“我们出发吧。”
```

不要给没有连接的素材编造 @Audio2。多个说话人应明确各自台词与参考映射；如果串音或角色不稳定，按角色分别生成，不保证一次生成就能精确分轨。

### 参考图片

图片单独连接，不把路径写进正文。提示词写清要说的台词；不要无意中把整段视觉描述也作为朗读内容。图片效果需试听确认。

## 避免慢速感

- 不默认堆叠“舒缓、缓慢、娓娓道来、每字清晰、长停顿”等要求。
- 不在每个短语后加省略号、破折号或换行；标点可能影响韵律，但不保证固定停顿毫秒数或固定升降调。
- 紧时长先缩短台词，不用极端语速硬塞。
- 数字、日期、多音字和缩写先确认读法；有歧义时用可朗读文字，不承诺模型自动读对。
- 如果整体音高也降低、时长同比变长，检查播放倍速和采样率/封装，不要只靠提示词补偿。
- 未读取真实任务参数和音频前，不宣称已定位“慢了 20%”的原因。

## 与画布参数分工

- 提示词写在音频节点正文输入框。
- 语速、输出格式、显式音色 ID 在节点参数面板设置；正常语速用 1x。UI 可选范围不等于供应商对所有值都支持，以上游校验为准。
- 未指定音色时保持为空；明确指定时使用当前模型已开通的 ID，不照搬旧版列表，不根据名称猜语言支持。
- 当前豆包协议没有独立映射 audioInstructions、audioLanguage、audioDialect 字段。需要的声音风格或语言要求写入 prompt，并试听确认，不声称填写未映射参数即可生效。
- Agent 只提交实际工具 schema 接受的字段；不要把画布请求对象伪装成 generate_media 调用参数。

## 交付格式

1. 可直接粘贴的提示词。
2. 参考素材映射（没有则写无）。
3. 建议节点参数（默认 1x，音色未指定则留空）。
4. 需要试听确认的事项，不保证克隆、方言、情绪或时长精确执行。
