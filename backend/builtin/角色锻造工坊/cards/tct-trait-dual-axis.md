## I — 方法论骨架 (Interpretation)

1. **不存在纯好/纯坏的特质**：每个特质都有 POSITIVE ASPECTS 与 NEGATIVE ASPECTS 两面。
2. **度决定戏剧张力**：同一特质**过度 = 负面，不足 = 缺失**。例：Adaptable 过度→不重家庭关系；Loyal 过度→为错的人撒谎；Confident 过度→overconfidence。
3. **故障线（fault line）**：找到「这个特质推到极端会塌」的那条线，就是角色最易被攻击的软肋。
4. 因此设计角色先问「这个特质的度在哪里会出问题」，而非「他有没有这个特质」。
5. 正面特质过多→角色成功太易、不可信（ce03）；缺陷过多→不可爱（ce02）。平衡靠度。
6. 与 mckee 维度「连贯的矛盾」同源：维 = 矛盾，双轴 = 矛盾的成因之一。

## A1 — 书中的应用 (Past Application)

### 案例 1：Adaptable 的故障线
- **操作**：标 POSITIVE「可靠、扛压、善变」→ 标 NEGATIVE「若配稳定需求型角色，关系受损」→ 设计挑战场景「必须始终同法回应、无变化」让适应力失灵。
- **结果**：一个原本「全能好特质」变成「有代价的具体人物」。

### 案例 2：Macho Joe 的 show（见 tct-show-dont-tell-trait）
- **操作**：Joe 的 macho 是「需要被认可」的过度补偿；其 NEGATIVE 面=用 swagger 掩盖 insecure。被戳中能力质疑即退缩，暴露故障线。
- **结果**：双轴让「自大」同时是魅力源与弱点源。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 用户困惑「为什么好人设不讨喜 / 为什么反派太脸谱」。
2. 用户说「这个特质我想让他既有优点又有问题」。
3. 用户写反英雄，想平衡深度缺陷与少量可爱点。

### 语言信号
- "特质的正反" / "度的把握" / "为什么好人设扁" / "缺陷的代价" / "fault line" / "过度补偿" / "dual axis"

### 与相邻 skill 的区分
- 与 `tct-trait-entry-blueprint` 的区别：本卡管「正/负两面怎么权衡」，蓝图卡管「13 字段怎么填」。
- 与 `tct-fatal-flaw-arc` 的区别：本卡管「单一特质的度」，弧光卡管「缺陷如何驱动整条成长线」。
- 与 `mckee-character-dimensions` 的区别：麦基讲维=矛盾；本卡给出「如何从一个特质内部找到那对矛盾（过度/不足）」。

## E — 可执行步骤 (Execution)

1. **写正面资产**：该特质在适度时给角色带来什么（POSITIVE ASPECTS）。
2. **找过度代价**：把它推到极端会伤什么人/什么事（NEGATIVE ASPECTS）。
3. **找不足缺失**：若角色该特质不够，又会在什么情境失灵。
4. **定故障线**：综合 2–3，写出「一条角色最易被攻击的软肋」。
5. **配对检验**：用双轴检查「正面特质过多是否不可信 / 缺陷过多是否不可爱」，调到平衡。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- **要填单特质档案** → tct-trait-entry-blueprint。
- **要选弧光类型** → tct-fatal-flaw-arc。
- **纯观念型写作** → 强行双轴会扭曲。

### 作者警告的失败模式
- **ce02 缺陷过载**：读者不尊敬角色→弃书。
- **ce03 正面溢出**：成功太易→不真实。
- **单向标签**：只写正面不写负面，角色成海报。

### Tier B 版权边界
- 引用条目样例（如 Loyal 的过度）≤150 字/段；只借「度」的机制，不搬运整段原文。
