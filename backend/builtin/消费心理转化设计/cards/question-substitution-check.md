## I — 解释

卡尼曼开篇提出的观察比结论更值得停下来想：**你很少被问题难倒。**

想想这有多奇怪。"这家公司未来三年值多少钱""这个人适不适合当 CTO""这项政策会有什么后果"——这些问题在客观上是极难的，很多根本没有可靠答案。但你几乎总能在几秒钟内产生一个意见，而且那个意见带着相当的确信。

这不是因为你聪明。是因为系统 1 有一条永远开着的旁路：遇到答不出的**目标问题**，它自动检索一个**语义上邻近、但回答起来容易得多的启发式问题**，回答那一个，然后通过**强度匹配**把答案换算回原来的量纲。

书里那张对照表值得原样记住：

| 你以为在回答的（目标问题） | 你实际回答的（启发式问题） |
|---|---|
| 你愿意为拯救濒危物种捐多少钱？ | 想到垂死的海豚时，我的情绪波动有多大？ |
| 你这些天对生活满意吗？ | 我现在的心情如何？ |
| 今后 6 个月里总统受欢迎的程度如何？ | 总统现在有多受欢迎？ |
| 这位竞选总统的女士能在政治道路上走多远？ | 这位女士看上去像是个政治赢家吗？ |

注意第一行的换算过程。"对海豚的情绪强度"和"捐款金额"是两个完全不同的量纲，系统 1 用**强度匹配**把它们对齐了：情绪很强 → 数额很大。整个换算不留痕迹，你只看到脑子里浮出一个数字，并且觉得那是你思考的结果。

**这就是本书大部分偏见的公因式。** 代表性启发法是"这属于该类别的概率"被换成"它像不像该类别的典型样本"；可得性启发法是"这类事件有多频繁"被换成"我能多容易想起例子"；情绪启发式是"这个技术的风险收益比"被换成"我喜不喜欢这个技术"；高于均数效应是"我是不是高于平均水平的司机"被换成"我是不是个好司机"。所以本 skill 的位置很特殊：它不是十四个偏见里的一个，它是**入口**。抓出替换之后，你才知道该去用哪个专项工具。

还有一个不那么明显的推论。替换之所以能逃过检查，是因为**答案的量纲是对的**。你要一个金额，系统 1 给了你一个金额；你要一个 1–10 的分数，它给了你一个分数。格式正确让人放松警惕。所以检测的着力点不能放在答案上，只能放在**产生答案的速度与它应有的难度之间的落差**上——一个客观上需要三天调研的问题，你在三秒内有了答案，那三秒里一定发生了替换。

## A1 — 书中的应用

**案例一：迪士尼制片厂董事长解释扎堆上映**
被问到"为什么这么多大制作会同期公映"，他答：

> "一切都是因为自负。如果只关心自己的生意，你就会想：'我有一个优秀的编辑部，还有个很棒的市场部，我们会做好电影的。'你还认为其他人肯定都不会这样想。"

卡尼曼的分析：真正需要回答的目标问题是"别人会怎么做、有多少人会来看我们的电影"，而各制片厂主管回答的启发式问题是"我们的电影怎么样、有强大的部门推广吗"。这就是**竞争忽视**——它不是傲慢，是替换。后果是市场系统性地进入过多竞争者，多西与洛瓦洛把这些公司称为"乐观主义烈士"：对经济有益，对投资者有害。

**案例二：90% 的司机认为自己车技高于平均水平**
卡尼曼把这个经典发现从"自我膨胀"重新解释为"认知偏见"。请对比两个问题：

- 你是一个好司机吗？（容易，几秒可答）
- 你是一个高于平均水平的司机吗？（难，需要先估计司机的平均水平）

人们用第一个回答了第二个。**决定性证据**：当任务换成一个多数人自认为不擅长的事（"你发起与陌生人交谈的技巧高于平均水平吗"），人们会不假思索地把自己划在平均**以下**——如果这是自我膨胀，就不该出现低于平均的自评；如果这是替换，就完全说得通。

**案例三：哈丁总统的当选**
《眨眼之间》里的反面例子：哈丁当选是因为他"高个子、宽下巴，是典型的强硬而果断的领导者形象"。卡尼曼一句话点破："之所以出现了哈丁作为总统表现会如何的直觉预测是因为选民替换了问题。"目标问题是"他会是个好总统吗"，启发式问题是"他看上去像个好总统吗"。这也是本 skill 与 `expert-intuition-validity` 的分工点：**替换产生的不是直觉，是伪直觉**。

## A2 — 触发场景

### 什么时候用

- 一个困难问题被**秒答**，而且答得很笃定
- 要给某个没有客观标尺的东西打分、估值、排优先级
- 设计问卷/用户访谈的问题（**这是最高杠杆的用法**：你写的每个问题都可能被受访者替换掉）
- 评审会上大家很快达成一致，且理由是"感觉""看起来""明显"
- 自我评估、绩效评估、面试评价
- 涉及"别人会怎么做"的判断（竞争、博弈、市场进入）——这类问题**几乎必然**被替换成"我们怎么样"

### 语言信号

> "我觉得这个能成" / "一眼就看出来了" / "这人挺靠谱的" / "我给它打 8 分" / "感觉不太对" / "我们的方案明显比他们好" / "用户肯定喜欢" / "你会用这个功能吗（问卷题）" / "综合来看还是不错的"

**结构性信号**（比词汇更可靠）：
- 答案产生的时间 << 问题应有的难度
- 被问"你是怎么得出这个的"时，理由是**在答案之后**构造的（对方需要想一下才能给出理由）
- 换一种说法问同一件事，答案变了

### 与相邻 skill 的区分

| 情况 | 用这个 | 不用这个 |
|---|---|---|
| 抓出"我回答的不是这个问题"这个动作本身 | ✅ `question-substitution-check` | |
| 已知问题问对了，但证据不够却很自信 | | → `wysiati-evidence-audit` |
| 替换的具体形式是"像不像典型样本" | | → `base-rate-anchoring`（本 skill 抓到后转交） |
| 替换的具体形式是"我能想起多少例子" | | → `availability-bias-correction`（本 skill 抓到后转交） |
| 替换的具体形式是"极端表现之后会怎样" | | → `regression-prediction-moderation` |
| 目标问题是"这个项目要多久/花多少钱" | | → `outside-view-forecast` |
| 想判断某个领域的直觉整体上是否可信 | | → `expert-intuition-validity`（那是环境属性问题，不是单次提问问题） |
| 替换发生在"预测未来的感受"上 | | → `focusing-illusion-check`（本书已验证 · 待整理） |
| 想给一类判断装一个稳定的评分表 | | → `formula-over-intuition`（本书已验证 · 待整理） |

**定位**：本 skill 是分诊台。它的产出通常是"你实际回答的是 X，请改用 Y skill 来回答真问题"。

**分诊速查表**（识别出替换类型后按此转交）：

| 你实际在测量的是 | 转交给 |
|---|---|
| 它像不像那一类的典型？ | `base-rate-anchoring` |
| 我能多容易想起例子？ | `availability-bias-correction` |
| 上一次表现有多亮眼？ | `regression-prediction-moderation` |
| 我们自己的计划有多完善？ | `outside-view-forecast` |
| 说这话的人有多资深、多笃定？ | `expert-intuition-validity` |
| 这个故事讲起来有多顺？ | `wysiati-evidence-audit` |

⚠️ **本 skill 只做识别与改写，不给答案**。如果你已经知道问题问对了，只是想要一个数字或一个判断，**不要**从这里进入 —— 直接用上表右列对应的 skill。

## E — 执行

1. **捕捉**。当出现"难问题 + 快答案 + 高确信"三件套时暂停。把已经说出口的那个答案原样写下来（不要修饰）。

2. **写出目标问题**。用一句可证伪的话写清楚**你本来要回答什么**。标准是：这句话必须包含**判据**和**时间范围**。
   - ❌ "这个人靠谱吗"
   - ✅ "这个人在 12 个月内独立交付一个跨团队项目的概率有多大"

3. **反推启发式问题**。问自己："如果我不知道任何数据，仅凭刚才那几秒能得到这个答案，那我实际在测量什么？"常见的六个候选：
   - 我喜不喜欢他/它？（情绪启发式）
   - 它像不像那一类的典型？（代表性）
   - 我能多容易想起例子？（可得性）
   - 我现在心情怎么样？（当下状态）
   - 它看起来专业/漂亮/自信吗？（表面特征）
   - 我们自己准备得怎么样？（竞争忽视——把"别人会怎么做"换成"我们怎么样"）

4. **检验：换个量纲重问一次**。这是最快的验证手段。如果原问题是打分，改问"你愿意为这个结论下多大注"或"你估计它的概率是百分之多少"。若两次答案不一致（很常见），说明第一次是强度匹配的产物。

5. **改造问题使其无法被替换**。三种改造模板：
   - **加上比较基准**："他靠谱吗" → "把他和我们过去 5 个同岗位的人排，他排第几"
   - **加上时间与证据要求**："你会用这个功能吗" → "你上一次遇到这个场景是什么时候？当时你做了什么？"（迫使调取具体记忆，而不是评价描述）
   - **拆成可独立回答的子项**："这个方案好不好" → 分别评"技术可行性 / 用户到达路径 / 6 个月内的现金消耗"，各自打分后再合并（这一步与 `formula-over-intuition` 衔接）

6. **转交**。识别出替换类型后，交给对应的专项 skill；如果目标问题本质上是"某类事要花多久/成不成"，转 `outside-view-forecast`。

7. **留痕**。在决策记录里写一行："原答案 X 来自启发式问题 Y；改造后的目标问题为 Z。"这一行的价值在复盘时会体现——它让你能区分"决策程序错了"和"运气不好"。

## B — 边界

### 不适用的情况

- **有现成算法或标准答案的问题**。能查、能算、能测的东西不需要这一步，直接去查。
- **低风险、高频、可快速纠错的判断**。中午吃什么、这段文案用哪个词——替换在这里几乎无害，而且是效率的来源。启发法**大部分时候是对的**，这正是它存在的原因。
- **真专家在高效度环境中的快速判断**。急诊医生说"这个病人不对劲"、消防指挥官说"撤"——这是再认，不是替换。区分方法见 `expert-intuition-validity`（看环境规律性和反馈质量，不看速度）。
- **审美与偏好判断**。"我喜不喜欢这首歌"里，"我喜不喜欢"就是目标问题本身，没有替换发生。

### 失败模式

1. **变成瘫痪**。对每一个判断都追问"我回答的是哪个问题"会让人无法工作。使用门槛应设为：**不可逆 + 代价高 + 没有现成标尺**，三者同时满足才启动。
2. **抓出替换后就结束**。指出"你其实在回答另一个问题"只是诊断，不是治疗。必须走到第 5 步（改造问题）或第 6 步（转交），否则本 skill 只是显得聪明。
3. **用它攻击别人**。在会议上对同事使用本 skill 极易被感受为智力羞辱，触发 `autonomy-reactance` 式的抵抗。更有效的用法是**改造流程里的问题模板**（问卷题、评审表、面试评分表），让替换在源头无法发生——问题设计比现场纠正的杠杆高一个数量级。
4. **误把"慢下来"当解药**。多花时间想，常常只是给替换出来的答案补更精致的理由。真正起作用的是**换掉问题的措辞**，不是延长思考时间。

### 盲点

- **替代机制本身不可内省**。你无法通过反省抓到自己正在替换——只能通过外部线索（速度落差、换量纲后答案变化、理由后置）间接推断。因此本 skill 在**审阅他人判断**和**设计问题模板**时比在自省时可靠得多。
- **"目标问题"未必存在良定义的答案**。有些问题（"这个人品格如何"）本身就没有可操作的判据。此时正确的产出不是一个更好的答案，而是承认"这个问题不可回答，我们需要换一个可回答的代理指标，并明确它的局限"。
- **过度使用会削弱有用的直觉**。卡尼曼在以色列军队的例子说明，结构化之后的整体直觉判断**仍然有效**（见 `formula-over-intuition`）。目标不是消灭直觉，是让它在正确的位置上出现。
- **本书方法论的共享边界**：不要援引本书第 3–5 章的启动效应与自我损耗结论——那部分证据在 2011 年后大面积复现失败，作者本人已撤回信任。本 skill 的证据基础（第 9 章替代、第 24 章高于均数效应与竞争忽视）不依赖它们。

### 容易混淆的概念

- **替代 ≠ 答非所问**。答非所问是听错了题；替代是**自以为在答原题**，且答案的量纲完全正确。
- **替代 ≠ 简化**。波利亚式的"先解一个简单点的问题"是系统 2 有意为之的策略，你知道自己在做替换。本 skill 针对的是无意识的、你不知道发生了的那种。
- **启发法 ≠ 错误**。启发法是"协助寻找难题恰当答案的简单过程，虽然找到的答案常常并不完美"。它的默认状态是够用，只在特定结构下系统性失效。

## 相关 skills

- **composes-with**: `wysiati-evidence-audit` — 两个最上游的元认知检查。本 skill 问"我回答的是哪个问题"，那个问"我的自信来自证据还是故事"。通常按此顺序连用。
- **composes-with**: `base-rate-anchoring` / `availability-bias-correction` — 本 skill 是分诊台，这两个是最常见的两个下游科室。
- **composes-with**: `regression-prediction-moderation` / `outside-view-forecast` — 另外两个下游科室。前者接"上次表现很亮眼"型替换，后者接"我们的计划很周密"型替换。
- **contrasts-with**: `expert-intuition-validity` — 本 skill 处理**单次提问**的替换；那个 skill 处理**整个领域**的直觉是否可信。快速答案在高效度环境里是专业技能，在低效度环境里是替换。
- **composes-with**: `focusing-illusion-check`（本书已验证 · 待整理）— 当被替换的目标问题是"我以后会有多快乐"时，转到那里。
- **composes-with**: `formula-over-intuition`（本书已验证 · 待整理）— 执行步骤 5 的"拆成子项"直接通向那个 skill 的评分表设计。
