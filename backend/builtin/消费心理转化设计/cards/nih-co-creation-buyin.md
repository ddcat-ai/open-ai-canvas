## I — 方法论骨架 (Interpretation)

**宜家效应**：自己动手完成的东西，估值系统性高于同质的现成品。
折纸实验中，创作者对自己歪歪扭扭的作品出价接近专家作品的价格，
而旁观者只肯出其约五分之一——**创作者不是在为作品出价，是在为自己的劳动出价，
而且他们真心以为别人也看得见那份劳动。**

**非我发明偏见（NIH）** 是它在观念上的版本：对"自己参与生成的方案"的估值
远高于外来的等质方案。这不是面子问题，是估价机制问题——
对方的大脑在评估你的方案时，缺少一份他自己的劳动作为估值输入。

于是有了本 skill 的核心操作：

> **不要给成品，给一个需要对方补完的半成品。
> 让对方的名字进入方案的【生成】过程，而不是【审批】过程。**

这两个位置的差别是决定性的。**审批位**上的人，其角色定义是"找出问题"——
他越认真，你的方案死得越快。**生成位**上的人，其角色定义是"让它成立"——
他越认真，方案越强，而且最后他会把它当作自己的。

但宜家效应有一条**硬边界**，滥用必败：**劳动必须被完成，且难度可控。**
半途而废的劳动不产生依恋；过难导致失败的劳动甚至反转为厌恶。
所以"让对方多参与"不等于"给对方加活"——你留出的空缺必须是
对方**有能力、且能在有限时间内真正填完**的那一块。

## A1 — 书中的应用 (Past Application)

### 案例 1：折纸实验

- **问题**：自己动手会让人高估自己的作品多少？他们知道自己在高估吗？
- **方法论的使用**：请无经验者按说明折纸鹤和青蛙，然后拍卖自己的作品。
  同时请旁观者对同一批作品出价，另设一组专家作品作参照。
- **结论**：如果估价基于客观质量，创作者与旁观者的出价应当接近。
- **结果**：创作者的出价接近**专家作品**的水平，旁观者只出其约五分之一。
  更关键的是——创作者**真心认为**旁观者也会喜欢自己的作品。
  他们不是在虚张声势，是真的看不见自己的偏差。
- **边界验证**：当研究者故意去掉部分折纸说明、增加难度导致作品更糟时，
  创作者的估价**反而更高**（劳动更多）；但如果任务**被中途叫停未能完成**，
  这种偏爱就不出现。

### 案例 2："鸡蛋理论"与速食蛋糕粉

- **问题**：20 世纪中期，全蛋粉速食蛋糕粉（只需加水）销量不佳，为什么？
- **方法论的使用**：厂商把配方改为**不含蛋粉**，要求家庭主妇自己打一个鸡蛋进去。
  流程更麻烦了，产品"更差"了。
- **结论**：完全无需付出的产品，剥夺了使用者的劳动，也剥夺了她们的所有权与成就感。
- **结果**：销量上升。这个案例后来被称为"鸡蛋理论"，
  是宜家效应在产品设计中最早的商业应用之一。

### 案例 3：NIH 在组织中的表现

- **问题**：为什么外部顾问的报告经常被束之高阁，即使内容正确？
- **方法论的使用**：艾瑞里观察到，人们评估创意时，
  对"自己想到的"与"别人想到的"给出显著不同的评分，即使内容相同。
- **结论**：外部方案在质量上的优势，会被 NIH 造成的估值折扣抵消甚至反超。
- **结果**：推行外部方案的正确姿势不是把它做得更完美（那只会加大折扣的绝对值），
  而是让内部人参与它的生成。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill

1. **提案被搁置**：方案写得很完整，汇报也顺利，但就是没有后续。
2. **跨部门推行新流程**遇到软性阻力：没人反对，也没人执行。
3. **咨询/乙方交付**：报告交付后客户不落地。
4. **引入外部最佳实践**：别的公司验证过的做法，在自己团队被各种理由否掉。
5. **产品经理说服研发**、设计说服产品、下级说服上级。
6. **一开口对方就防御**：还没说完就开始找问题。
7. **家庭与伴侣决策**：搬家、装修、教育方案的分歧。

### 语言信号

- "方案明明更好，就是推不动"
- "他们总能找出一堆问题"
- "汇报完就没下文了"
- "客户说很好，然后放着不用"
- "怎么让老板接受这个想法"
- "他们有 NIH 情结"
- "get buy-in / stakeholder resistance / not invented here / they keep pushing back"

### 与相邻 skill 的区分

- 与 `autonomy-reactance`：那个处理的是**抵触"被强加"这件事本身**
  （与方案好坏无关，核心工具是明确给出拒绝权）；
  本 skill 处理的是**估值折扣**（方案是别人的，所以感觉不够好）。
  信号区分：对方说"凭什么由你决定" → 那个；对方说"这个方案有几个问题" → 本 skill。
  两者常需叠加使用。
- 与 `commitment-escalation`：那个用**一个极小的先行动作**触发一致性与认知失调，
  从而改变**态度**；本 skill 用**共同署名的生成过程**消除估值折扣，
  改变的是**对方案的估价**。前者改人，后者改方案的归属。
- 与 `investment-design`：那是让**用户**往产品里沉淀内容/数据/信誉以提高留存；
  本 skill 是让**利益相关者**参与方案生成以获得组织内认同。场景不同。
- 与 `meaning-recognition-motivation`：那处理持续动机（产出被看见）；
  本 skill 处理一次性的方案接受度。

## E — 可执行步骤 (Execution)

1. **确认阻力类型（分诊）**
   - 听对方的反对措辞：
     - "凭什么/为什么要听你的/我们没被征求意见" → **自主性**问题，
       先转 `autonomy-reactance`。
     - "这个方案有几个问题/不适合我们的情况/我们试过类似的" → **估值折扣**，
       本 skill 适用。
     - "我们做不到/没人手/系统不支持" → **能力**问题，转 `ability-simplification`。
   - 完成标准：明确判定阻力类型，不要三种混治。

2. **算清楚你的方案里哪一块可以拆出去（核心动作）**
   - 把方案分解成：**内核**（不能动，动了就失去价值）
     与 **可让渡部分**（细节、命名、优先级、实施节奏、适用范围、试点选择、
     指标定义、异常处理规则）。
   - 挑出 1–3 块可让渡部分作为"空缺"，要求是：
     - 对方**有能力**完成（在他的专业范围内）；
     - **能在有限时间内完成**（一次会议或一周内，不能拖成长期任务）；
     - 完成后**有可见的产物**（一份清单、一个命名、一套指标）。
   - 完成标准：明确列出内核与空缺，且空缺满足上述三条。

3. **把成品退化成半成品**
   - 具体做法：
     - 方案文档里留下明确标注的 TODO 与开放问题，而不是全部写满；
     - 数据与判断给全，结论留一半；
     - 提供 2–3 个方向而非一个最优解，让对方来选（选择本身也是一种生成）；
     - 用"我卡在这里，你怎么看"替代"我建议这样做"。
   - **反面示例**：把方案做得更完美、把 FAQ 写得更全、把反对意见提前全部驳倒——
     这些都在加大 NIH 折扣。
   - 完成标准：产出一份**故意不完整**的材料，且不完整之处是设计过的。

4. **确保劳动被完成（硬边界）**
   - 参与过程必须有明确的**收尾动作与留存产物**：
     会议结束时当场记录对方补完的内容，并在下一版材料中**署上他的名字**。
   - 检查：如果对方投入了两小时讨论，最后什么都没被采纳、什么都没留下 →
     这是"半途而废的劳动"，会**降低**而非提高认同（比不邀请更糟）。
   - 完成标准：对方的每一次投入，都有一条可指认的痕迹留在最终方案里。

5. **改变归属叙事**
   - 后续所有沟通中，把方案称为"我们的"或直接冠以对方/对方团队的名字。
   - 在向上汇报时，主动把生成过程中的贡献归给参与者。
   - 完成标准：最终方案在组织中的通行名称不再指向你个人。

6. **对外部方案，先本地化再引入**
   - 若方案来自外部（顾问报告、别家做法、书上的最佳实践），
     不要直接引入，先由内部人做一次**改写与适配**，让改写本身成为生成过程。
   - 完成标准：外部方案已有内部署名的适配版本。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **紧急且不可协商的事项**：安全事故、合规红线、法律要求。
  这些不该被"共创"，该被明确执行。
- **对方缺乏相关能力**：让不懂的人补完关键部分，会得到一个更差的方案，
  而且因为他署了名，之后更难修正。
- **内核会被侵蚀**：如果对方要动的是方案不可让渡的核心，
  共创会变成妥协。此时应转为直接的立场沟通。
- **对方人数过多**：共创的边际成本随人数急剧上升，且容易稀释成没有主张的平庸方案。
  一般不超过 3–5 个关键相关方。
- **纯操纵性使用**：假装征求意见、实际一个字不改，被识破后信任损失远超收益。
  本 skill 要求**真的把决定权让出去一部分**。

### 作者在书中警告的失败模式

- **未完成的劳动不产生依恋**（折纸实验的中断条件）：这是最容易犯的错。
  把人拉进讨论却不采纳任何东西，比不拉他更伤。
- **过难导致失败的劳动会反转为厌恶**：给对方一个他填不完的空缺，
  他会把挫败感归因到方案上。
- **创作者看不见自己的偏差**：折纸实验中，创作者真心相信别人也喜欢自己的作品。
  这条也适用于**你自己**——你之所以推不动，可能有一部分是你高估了自己的方案。
  执行本 skill 前应先诚实评估：**如果这个方案是别人提的，我会给它打几分？**
- **把方案做得更完美是反向操作**：越完美的成品，可让渡的空间越小，NIH 折扣越大。

### 作者的盲点 / 时代局限

- 折纸与乐高实验都是**低利害的实验室任务**，产出归属清晰。
  真实组织中的方案往往有多个模糊的共同作者，归属感的分配远更复杂。
- 艾瑞里团队的部分研究已卷入数据可靠性争议（详见 `fudge-factor-integrity` B 段）。
  宜家效应本身由 Norton、Mochon、Ariely 共同发表，并在多个独立团队中得到复现，
  相对稳健；但效应量的具体倍数不宜精确引用。
- 书中未讨论**权力不对等**下的共创：当对方是决策者且明确知道你在用技巧时，
  共创可能被读作操纵。
- 未讨论 NIH 的**组织层面**成因（预算归属、KPI 归属、政治利益），
  而这些在真实场景中往往比心理估值折扣更重要。
  本 skill 只处理心理层，遇到结构性利益冲突时无效。

### 容易混淆的邻近方法论

- **参与式管理 / 共创工作坊**：形式相似，但那些以"集思广益提高方案质量"为目标；
  本 skill 明确以"消除估值折扣提高接受度"为目标，因此**空缺是被设计出来的**，
  而不是真的不知道答案。这个差别决定了执行细节。
- **登门槛效应（Foot-in-the-door）**：那是先小请求后大请求；
  本 skill 是把大请求拆成"我做内核、你做一块"。
- **沉没成本**：那让人因已投入而不肯放弃；宜家效应让人因已投入而**高估价值**。
  前者关于损失，后者关于估价。
