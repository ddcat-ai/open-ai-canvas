## I — 方法论骨架 (Interpretation)

定价的常识是"按价值定价"。现实是：**人几乎无法直接感知价值，
他感知的是过程**。于是出现一个荒谬但稳定的规律——

> **效率提升会降低支付意愿。**

锁匠的例子把它推到了极端：同样是把门打开（结果完全相同、
甚至更快恢复了顾客的生活），花一分钟的专家被压价，
花一小时并弄坏几根工具的生手被加价。顾客付的不是"门开了"，
是"我看到他很辛苦"。

这条规律有两个不对称的后果：

**① 对专业能力的惩罚**
你越熟练，单位时间产出越高，客户的支付意愿越低。
所有以"经验值钱"为前提的专业服务都在与这条规律作对。
这也解释了为什么行业越成熟、交付越快，客单价反而越难提——
不是竞争，是可见性消失了。

**② 与公平机制的耦合**
艾瑞里把它接在"惩罚不公平"这一章之后不是偶然。
当涨价缺少可见的努力叙事时，它会被归因为"趁人之危"，
从而触发**宁可自损也要惩罚**的反应（雨天从 5 美元涨到 10 美元的伞、
暴雨天的动态加价）。所以：

> **涨价必须同时提供"努力/成本"的可见叙事，否则等于购买敌意。**

矫正方向不是延长工时（那是欺诈），而是**把已经存在但不可见的努力显性化**。
专业服务的成本结构里，绝大部分投入发生在客户看不见的地方：
多年的训练、失败的尝试、备选方案的排除、事前准备、
以及"知道该做什么"这件事本身。它们真实存在，只是从未被呈现。

这里必须立一条**硬底线**：本 skill 是**暴露真实努力**，
不是**制造虚假努力**。故意放慢、故意报高工时、故意把简单事做复杂，
既是欺诈也不可持续（一旦被识破，损失远大于溢价）。
判据很简单：**你呈现的每一项，是否都真的发生过？**

顺带得到一条被低估的推论：**呈现方式本身就是交付的一部分**。
写一份诊断记录、留下过程截图、说明你排除了哪三种方案——
这些动作既提高了支付意愿，也真实提高了客户对方案的理解与信任。
它不是包装，是把已完成的工作交付完整。

## A1 — 书中的应用 (Past Application)

### 案例 1：锁匠悖论

- **问题**：为什么技艺提升反而带来更差的收入体验？
- **方法论的使用**：艾瑞里对比同一服务的两种执行过程——
  熟练锁匠一分钟开锁；生手花一小时，中途弄坏几根工具。
- **结论**：结果完全相同，甚至前者对顾客更有利（更快、无破坏）。
  但顾客对前者的支付意愿更低。
- **结果**：**顾客买的是可见的努力，不是结果。**
  锁匠的技艺越高，他的劳动越不可见，越被压价。
  这是所有专业服务的结构性困境。

### 案例 2：雨天的伞与涨价的归因

- **问题**：为什么符合供求关系的涨价仍然引发愤怒？
- **方法论的使用**：雨天把伞从 5 美元涨到 10 美元，
  经济学上完全合理，但顾客的反应是愤怒而非接受。
- **结论**：涨价的**归因**决定反应。归因为"成本上升"可被接受，
  归因为"趁人之危"触发惩罚，且人宁可自损也要惩罚。
- **结果**：涨价沟通的核心不是解释供求，是提供成本与努力的可见证据。

### 案例 3：高估自己的劳动成果（对称的另一面）

- **问题**：为什么自己做的东西总觉得更值钱？
- **方法论的使用**：册5 第10章讨论人对自己投入劳动的产物的估价上调。
- **结论**：努力溢价是**双向**的——
  你高估自己的劳动，客户看不见你的劳动。两个偏差叠加，
  正好构成了报价冲突的完整解释。
- **结果**：所以本 skill 不能只用于"抬价"，
  还必须用于**自查**：我的高报价里，有多少来自客户看不见的真实努力，
  有多少来自我自己对劳动的高估（后者见 `nih-co-creation-buyin`
  与 `endowment-gap-correction`）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill

1. **专业服务报价被压**："就改了几个字/跑了个脚本，凭什么收这么多。"
2. **效率提升后的定价困境**：用了新工具/自动化，交付更快，
   但客户开始质疑价格。
3. **涨价沟通**：怎么说才不会被读作趁火打劫。
4. **危机与稀缺时期的定价**：突发需求下的加价如何不引爆舆论。
5. **内部汇报的价值呈现**：做得又快又好，结果被认为"这个不难"。
6. **AI/自动化产品的定价**："这不就是调了个 API 吗。"
7. **售后与故障处理**：问题很快解决，客户反而怀疑"是不是根本没坏"。
8. **免费/低价获客后的转价**：轻松交付过一次，后续加价极难。

### 语言信号

- "客户觉得太贵，说这活儿很简单"
- "我三十分钟做完的东西，报价被砍到零头"
- "现在用 AI 做，客户就不认这个价了"
- "涨价怎么跟客户说才不会翻脸"
- "领导觉得这个项目不难"
- "修得太快，客户怀疑我没修"
- "effort premium / locksmith paradox / pricing my expertise / value-based pricing 卖不动"

### 与相邻 skill 的区分

- 与 `ultimatum-fairness-leverage`：**这是最需要分清的一对。**
  那处理的是**已经点燃的公平愤怒**（用户抵制、舆论反弹、
  宁可自损也要惩罚），是灭火侧；
  本 skill 处理的是**如何构造过程可见性以抬高支付意愿**，是构造侧。
  判据：对方在说"太贵了"（本 skill）还是在说"这不公平/你们凭什么"
  （那个 skill）。涨价场景常需**两个一起用**：
  本 skill 提供努力叙事，那个 skill 处理公平归因。
- 与 `arbitrary-coherence-pricing`：那决定**数字定多少**；
  本 skill 决定**这个数字如何被接受**。顺序上那个在前。
- 与 `block-price-comparison`：那用捆绑与费率结构**阻止逐项比价**；
  本 skill 用过程暴露**提高单项支付意愿**。
  若客户拿着竞品报价单逐条砍 → 用那个；
  若客户觉得"这事本身不值这么多" → 用本 skill。
- 与 `reference-price-framing`：那处理价格**怎么显示**（尾数、划线价、
  折扣写法）；本 skill 处理**劳动怎么显示**。
- 与 `expectation-experience-engineering`：那用语言与仪式改写**体验本身**；
  本 skill 用过程暴露改写**价值判断**。两者都作用于感知，
  但一个改的是"好不好用"，一个改的是"值不值这个价"。
- 与 `nih-co-creation-buyin`：那是让**对方**投入劳动以提高其接受度；
  本 skill 是让**自己**的劳动被对方看见。互为镜像，可组合
  （让客户参与一次诊断，他既看见了你的努力，又投入了自己的）。

## E — 可执行步骤 (Execution)

1. **先自查：这个价格里有多少是我自己的高估**
   - 承认努力溢价是双向的——你也会高估自己的劳动。
   - 做外部校准：同类服务的市场成交价是多少？
     （若发现自己的估价明显偏离，转 `endowment-gap-correction` 第 3 步。）
   - 完成标准：价格有外部参照支撑，不只是"我觉得值"。

2. **盘点不可见的真实努力**（核心动作）
   - 逐项列出客户看不见但真实发生的投入：
     - **事前**：需求理解、资料调研、同类案例研究、方案排除；
     - **过程中**：失败的尝试、返工、多版本对比、边界测试；
     - **能力沉淀**：为了能在一分钟内解决这个问题，
       此前投入的训练与踩过的坑；
     - **风险承担**：如果做错，谁承担后果。
   - **硬约束**：每一项必须真实发生过，能举出具体内容。
     写不出具体内容的，删掉。
   - 完成标准：得到一张全部可举证的清单。

3. **选择呈现载体**（按成本从低到高）
   - 第 0 档：**口头说明排除项**——"我们考虑过 A、B 两种方案，
     因为××排除了"。零成本，效力却很高。
   - 第 1 档：**诊断/工作记录**——一页纸的问题定位与处理过程。
   - 第 2 档：**过程留痕**——截图、中间版本、测试记录、
     变更日志。
   - 第 3 档：**结构化交付物**——把过程做成正式的交付组成部分
     （方案评估表、风险清单、验收说明）。
   - 完成标准：至少落地第 0 档与第 1 档。

4. **把"快"重新定价，而不是道歉**
   - 常见错误：因为做得快而主动降价，或含糊其辞掩饰用时。
   - 正确做法：**明确把速度作为你交付的价值之一**——
     "同样的问题，别处两周，我们两天，
     这两天里避免的停机损失是××"。
   - 若客户按工时结算，改为按项目/结果结算，
     并同步提供第 2 步的努力清单。
   - 完成标准：报价单上速度是**卖点**而非需要解释的疑点。

5. **涨价必须绑定归因叙事**
   - 归因优先级：**成本上升 > 投入增加 > 能力提升 > 供求变化**。
     最后一条（"需求大了所以涨"）几乎必然触发公平惩罚，
     避免作为主叙事。
   - 提前告知，给老客户过渡期，比涨价幅度本身更影响接受度。
   - 若已经引发抵制 → 转 `ultimatum-fairness-leverage`。
   - 完成标准：涨价通知里有具体的成本/投入证据，不止一句"因经营需要"。

6. **危机与稀缺时期：宁可不涨，也不要涨得没有解释**
   - 雨天的伞是典型反例。短期收益与长期敌意不成比例。
   - 可替代方案：限量、优先级、附加服务，
     而非纯价格上浮。
   - 完成标准：稀缺时期的定价决策有明确的公平性评估。

7. **AI/自动化场景的专项处理**
   - 这是本 skill 在当代最尖锐的应用："这不就是调了个 API 吗。"
   - 三条应对：
     - ①**呈现判断而非执行**——价值在于知道该问什么、
       如何验证、如何在失败时兜底；
     - ②**呈现排除过程**——试了多少种路径才收敛到这一种；
     - ③**承担结果责任**——自动化不承担责任，你承担。
       责任是可计价的，且不会因效率提升而贬值。
   - 完成标准：报价说明里，价值锚点落在判断与责任上，不在工时上。

8. **内部汇报的镜像用法**
   - "做得又快又好"在组织内同样被低估。
   - 在汇报中加入：遇到的坑、排除的方案、避免的风险。
     不是邀功，是补全信息——否则决策者会低估这类工作的必要投入，
     进而在下一次低配资源。
   - 完成标准：汇报中过程与结果的篇幅比不低于 1:3。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **制造虚假努力**：故意放慢、虚报工时、把简单事做复杂、
  编造根本不存在的"失败尝试"。这是欺诈，
  且一旦被识破，信任损失远大于溢价收益。**这是本 skill 的第一红线。**
- **客户购买的核心就是速度**：急救、故障恢复、生产线停机。
  此时强调过程会被读作拖延。正确做法是**先解决，后补记录**。
- **标准化、高度商品化的交付**：耗材、通用件、
  已有公开报价的标准服务。过程叙事在这里无效，甚至显得可疑。
- **对方已进入公平愤怒状态**：此时任何"我们很辛苦"的叙述
  都会被读作辩解。先降温，用 `ultimatum-fairness-leverage`。
- **用它来掩盖交付质量问题**：过程再可见，
  也无法补偿一个没解决问题的结果。

### 作者在书中警告的失败模式

- **"我效率高了，所以我可以按结果定价"是错的**（x17）：
  在缺乏努力可见性的情况下，高效率会被读作"轻松赚钱"，
  直接触发公平惩罚。
- **纯结果导向的报价单在小额高频服务中极易引发反感**：
  金额越小、频次越高，顾客越依赖过程感知来判断合理性。
- **危机时期按需求涨价 = 购买敌意**：人宁可自己受损也要惩罚
  被认为不公平的一方（最后通牒式反抗）。
- **人会高估自己的劳动成果**：本 skill 的使用者本身也在这个偏差里。
  不做第 1 步的自查就直接抬价，会把偏差当成依据。

### 作者的盲点 / 时代局限

- **努力溢价的边界条件在书中未充分界定**：
  后续研究表明，当**结果质量可被独立验证**时（如医疗效果、
  投资回报），努力线索的影响显著减弱。
  换言之，本 skill 在**结果不可验证或延迟验证**的服务中效力最强，
  在结果立即可测的场景中效力弱。这一条件书中未讨论。
- **锁匠案例是叙事性举例，不是受控实验**：
  它生动且被广泛引用，但不应作为效应量的依据。
  相关的受控研究（如 Kruger 等人的"努力启发式"）支持方向，
  但幅度因场景差异很大。
- **艾瑞里团队的部分研究已卷入数据可靠性争议**
  （详见 `fudge-factor-integrity` B 段，含一项已撤稿实验）。
  本 skill 引用的两条机制（努力启发式、公平惩罚/最后通牒）
  主要来自其他团队的独立研究，受牵连较小。
- **未讨论自动化与 AI 带来的结构性冲击**：
  当边际执行成本趋近于零，"可见努力"这一价值锚点将大面积失效。
  本 skill 的第 7 步是本次整理所做的现代化补充，
  不属于原书内容。
- **未讨论平台化与评分机制**：在评分透明的平台上，
  历史评价部分替代了过程可见性，努力叙事的边际作用下降。

### 容易混淆的邻近方法论

- **价值定价（Value-Based Pricing）**：那主张按客户获得的价值定价；
  本 skill 指出**客户感知不到价值，只感知得到过程**，
  因此是价值定价在落地时缺失的那一环，而非替代品。
- **劳动价值论**：那是经济学的价值来源理论；
  本 skill 是消费者感知层面的启发式偏差。两者结论相似、层级完全不同，
  不要混用论证。
- **透明化营销（Process Transparency）**：那强调供应链与成本公开
  以建立信任；本 skill 强调**专业投入**的暴露以抬高支付意愿。
  手段相近，目的不同。
- **宜家效应 / NIH 偏见**：那是**对方**投入劳动后高估产物
  （见 `nih-co-creation-buyin`）；本 skill 是对方看见**你**的劳动后
  提高支付意愿。主语不同。
