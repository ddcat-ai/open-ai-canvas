## I — 解释

有两种完全不同的预测方式。

**内部意见**：看着你自己的项目——已完成的部分、剩下的章节、团队的能力、当前的势头——向前外推。它感觉起来是负责任的，因为它用的是你**最了解**的信息。

**外部意见**：忘掉这个项目的一切细节，只问一件事——"和我们处在同一阶段的那一批项目，后来平均花了多久、多少钱、多少比例失败了？"用那个分布做起点。

关键的心理事实是：**内部意见不是"不够严谨的外部意见"，它是一种系统性偏低的估计**，而且它的偏差不会因为你估得更仔细而缩小。原因是它结构性地无法包含"未知的未知数"——离婚、生病、关键人离职、合作方拖延、需求变更。这类事件单个都不可预见，但"某件事出岔子"的总概率极高，而它们全部都不在你的甘特图里。分解得越细，只会让故事越连贯、越有说服力，不会让它更接近真相。

这里最刺眼的一点是卡尼曼自己的经历：他的团队里**有人知道外部数据**。那位课程专家希莫，只要被直接问到，就能说出"40% 的同类团队根本没完成，完成的用了 7 到 10 年"。但在被问之前，他自己的预测是"两年"。他的知识和他的预测之间没有连线。这不是信息缺失的问题，是**调取失败**的问题。所以外部意见不是一个"去搜集资料"的建议，而是一个**必须被显式触发的提问动作**。

第二个刺眼的地方在结局。听到 7–10 年和 40% 失败率之后，这个由研究判断与决策的专业人士组成的团队，"达成了一种默契，那就是当做什么事都没发生，继续工作"。书最后用了 8 年，写完时已经没人要了。**拿到外部数据只是第一半，把它接到一个具体动作上才是第二半**——如果没有预先约定"数据超过什么阈值就触发什么行动"，这个 skill 只会制造一次尴尬的沉默。

## A1 — 书中的应用

**案例一：以色列课程编写团队（作者本人）**
团队工作一年、自认进展良好时，全员私下写下完稿时间预测，集中在 1.5–2.5 年。随后卡尼曼请团队里的课程专家回忆同类团队：**40% 从未完成；完成的没有少于 7 年，最多 10 年**；且"我们略低于平均水平"。团队集体忽略了这个信息。实际耗时 **8 年**，成书从未被使用。卡尼曼的自评：那天他"是个笨蛋，是个无能的领导者"，因为他既没有把项目终止的选项摆上桌，也没有安排任何后续讨论。

**案例二：弗林夫伯格的参考类别预测**
应用于多国交通项目：识别参考类别 → 取该类别的成本超支与工期分布 → 只在有特别理由时调整。支撑数据：1969–1998 年全球铁路项目中，**超过 90% 高估了乘客量**，平均高估 **106%**，平均成本超支 **45%**；而且三十年间准确度**没有任何改善**——证据一直在，只是没被用。爱丁堡苏格兰议会大楼从 4000 万英镑预算走到 4.31 亿英镑最终造价，中间经历了六次"最终成本"修订。2002 年美国厨房改造调查：预估平均 18,658 美元，实际 38,769 美元。

**案例三：温哥华岛的汽车旅馆**
一对教师夫妇用全部积蓄买下一家汽车旅馆，对卡尼曼说："在我们之前的六七位老板都没能将这家旅馆妥善经营。"——他们说这话时完全无意识、毫无讥讽，还计划贷款扩建餐厅。**参考类别就摆在他们嘴边（六七次连续失败），但它被当成了"我们买得便宜"的理由，而不是"这门生意在这个位置不成立"的证据。**

## A2 — 触发场景

### 什么时候用

- 有人给出工期/预算/成功率估计，而依据是"按我们的计划算"
- 项目已经进行了一段时间，"进展良好"，正要对外承诺一个日期
- 创业、开店、转行、写书、读博等**有大量同类前例但当事人觉得自己特殊**的决定
- 要评估一份别人交上来的计划书（尤其是需要你签字批准的）
- 复盘时发现"又超期了"，想知道下次怎么估

### 语言信号

> "我们估计三个月能做完" / "按目前进度，年底应该没问题" / "这个项目跟以前那些不一样" / "每个案子都是独特的" / "我们团队比他们强" / "只要不出意外的话" / "最坏情况也就多两周" / "上一版我们花了 X，这次应该更快"

尤其注意 **"只要不出意外"** 和 **"我们不一样"** ——这两句话几乎是内部意见的签名。

### 与相邻 skill 的区分

| 情况 | 用这个 | 不用这个 |
|---|---|---|
| 预测**耗时/成本/成功率**，依据是自家计划 | ✅ `outside-view-forecast` | |
| 决策已成形，要在落槌前找出会杀死它的原因 | | → `premortem-doubt-injection`（本 skill 给分布，那个 skill 给失败机制） |
| 判断**一个个体属于某类别的概率**（这个候选人会不会是好员工） | | → `base-rate-anchoring` |
| 已经有了一个极端的直觉预测，要决定收缩多少 | | → `regression-prediction-moderation`（本 skill 负责"基准是多少"，那个负责"往直觉走多远"） |
| 要不要为了未来的自己现在忍住 | | → `future-self-vividness` |
| 讨论这件事**值不值得做**（而非要花多久） | | → `opportunity-cost-swap` |
| 事后复盘为什么搞砸了 | | → `hindsight-narrative-guard`（本书已验证 · 待整理） |

#### ★ 与另外两个"预测类"skill 的硬判据

| 判据 | ✅ 本 skill (`outside-view-forecast`) | ❌ `base-rate-anchoring` | ❌ `regression-prediction-moderation` |
|---|---|---|---|
| 被预测对象 | 一个**项目**（有起止、有交付物、有预算） | 一个**个体**（人 / 公司 / 病例） | 一个**已观测到的极端值**的下一次 |
| 问句形态 | "**要多久**""**要多少钱**""能不能按期交付" | "他/它**是不是**那一类""成不成" | "**下一次**会怎样""这个干预有效吗" |
| 数据单位 | 同类**项目**的耗时/成本/放弃率分布 | 同类**个体**中的发生率（%） | **同一对象**的历史波动 + r |
| 我的产出 | 区间 + 对外承诺日期 + 退出条件 | 一个概率 | 一个收缩后的数值 |
| 一句话 | 定**分布** | 定**起点** | 定**从起点向直觉走多远** |

**三条快速识别**：
1. 出现**时间单位或金额**（"三个月""50 万预算""年底上线"）→ **就是本 skill**。
2. 出现**"我们不一样""只要不出意外""按目前进度"** → **就是本 skill**（这三句是内部意见的签名）。
3. 只是问"这家公司/这个人能不能成"、没有交付物与工期 → 不是本 skill，去 `base-rate-anchoring`。

**依赖关系**：本 skill 是 `base-rate-anchoring` 在时间/成本维度的专门化（执行步骤 1–2 几乎相同）。若连"先归类再看个案"都做不到，本 skill 无法执行。

## E — 执行

1. **锁定被预测量**。写成一个可证伪的句子：不是"这个项目会顺利吗"，而是"从今天算起到 v1.0 上线的天数"或"18 个月后这家店还开着的概率"。含糊的被预测量会让后面每一步都无法进行。

2. **定义参考类别**。找"和本案在**同一起点状态**下的那一批案例"。三条挑选规则：
   - 起点对齐（不是"所有 App 项目"，而是"团队 5 人以内、已完成设计稿、尚未联调的 App 项目"）
   - 宁可类别宽一点、样本多一点，也不要窄到只剩 2 个案例
   - **必须包含失败的案例**——只统计做完了的项目，是本步骤最常见的致命错误（幸存者偏差会把 40% 的失败率抹成 0）

3. **取分布，不取平均**。至少拿到三个数：中位数、上四分位（或最差的那 20%）、失败/放弃比例。如果找不到公开数据，就用最低成本的替代品：问三个做过同类事的人"你们实际花了多久"，并**明确追问"包括中途停摆的时间吗"**。

4. **写下基准预测**。此刻**不允许**使用任何本项目的信息。这个数字通常会让你不舒服——那是它在工作的信号。

5. **只在有硬理由时调整**。允许调整的理由必须是**可以指名道姓的结构性差异**（"我们复用了上个项目 70% 的代码，那批项目都是从零开始"），不允许的理由是"我们更努力/更有经验/管理更好"（那批项目里的每一个也都这么认为）。调整幅度建议不超过基准值的 ±30%。

6. **接上一个动作**（这一步决定本 skill 是否有用）。在看到基准预测的同一次会议里，写下：
   - 对外承诺的日期改成什么（建议：基准的上四分位，不是中位数）
   - 如果到了某个时间点/花掉某个金额仍未达到某个里程碑，**我们做什么**（缩范围 / 加人 / 终止）
   - 这个终止条件由谁在什么时候检查

   没有第 6 步，前五步只会产生一次尴尬。

## B — 边界

### 不适用的情况

- **真正的独一无二事件**。参考类别不存在或只能凑出 1–2 个案例时，本方法会给出一个伪精确的数字，比诚实地说"不知道"更危险。此时改用 `premortem-doubt-injection` + 宽区间。
- **幂律回报的场景**。风投、内容创作、药物研发这类"99 次失败 1 次百倍"的领域，基准预测（中位数≈0）在数学上正确但在决策上无用，因为决策目标不是最小化平均误差，而是最大化捕获极端值的机会。此时外部意见应用于**成本侧**（我最多亏多少、这一轮尝试要花多久），不用于收益侧。
- **短周期、单人、无依赖的任务**。"这封邮件我要写多久"用外部意见是杀鸡用牛刀，且个人任务的历史分布方差小，内部意见够用。
- **价值判断**。本 skill 不回答"该不该做"，只回答"做了会花多久、成不成"。一个成功率 20% 的事完全可能值得做。

### 失败模式

1. **参考类别选得太窄**（只剩自己人的两个项目）或**太宽**（"所有互联网项目"），前者退化成内部意见，后者产生无意义的平均数。
2. **只统计完成的案例**。幸存者偏差会系统性抹掉失败率，这是实践中最常见也最致命的错误。
3. **拿到数据后用"我们不一样"消化掉它**。卡尼曼自己的团队就是这么失败的。防御手段是第 5 步的"必须指名道姓的结构性差异"规则。
4. **只调整估算，不调整承诺与止损**。数字改了，对外的日期没改，退出条件没定——等于什么都没发生。
5. **把基准预测当成锚**。基准预测本身也会成为一个锚（见 `anchor-antidote`），因此顺序不能反：**必须先算完基准再看个案信息**，反过来做，基准会被个案污染。

### 盲点

- **参考类别的选择本身没有严格程序**。这是本方法在学理上最软的地方——卡尼曼靠希莫的记忆举例，弗林夫伯格靠现成数据库，书里没有给出"如何证明这个类别选对了"的判据。实践中的补偿办法：用两个不同宽度的类别各算一次，如果结论方向一致就可以用，如果差异巨大，说明你的类别定义在做实质性工作，需要说明理由。
- **组织政治**。制订计划的人常常**知道**计划不现实，因为不现实的计划才能获批。此时外部意见不是认知工具而是政治动作，会被抵制。书中明确指出："避免规划谬误的最大责任落在了批准计划的决策者身上。"——本 skill 在审批侧比在执行侧更容易落地。
- **乐观本身有价值**。卡尼曼明确说，乐观者更能坚持、更能鼓舞团队、更能募到钱，"当需要采取行动时，即使略带妄想，乐观主义也是件好事"。目标是**校准而非消灭**乐观：把本 skill 限制在不可逆、代价高、难以重来的决策上，别用它去泼日常工作的冷水。
- **本书方法论的共享边界**：卡尼曼在结语中承认，四十年研究并未改善他自己的直觉，改善的是他识别错误和**在关键时刻要求安装程序**的自觉。因此本 skill 的正确用法是把第 1–6 步做成一张会议模板贴进流程，而不是指望"我记住了就不会再犯"。

### 容易混淆的概念

- **外部意见 ≠ 悲观**。外部意见可能给出比你更乐观的数字（例如你以为这类事故很常见，数据显示只有 3%）。它是校准，不是降级。
- **外部意见 ≠ 对标竞品**。对标看的是"他们做成了什么"（幸存者），外部意见看的是"这一类里的所有人后来怎样了"（含失败者）。
- **参考类别预测 ≠ 类比推理**。类比是找一个最像的案例；参考类别是取一整个分布。前者仍然是内部意见的变体。
