## I — 解释

本 skill 处理的是**代表性启发法**：把"它属于该类别的概率有多大"这个难问题，替换成"它像不像该类别的典型样本"这个容易问题。

汤姆 W 实验是这个替换的干净标本。给一段人格描述——喜欢秩序、条理清晰、对人缺乏同情、有科幻爱好——请被试排序汤姆最可能读哪个专业。被试几乎完全按"像不像"排序，把招生人数最少的计算机科学排在最前，把招生人数最多的人文与教育排在最后。**汤姆的描述是被刻意设计成"反基础比率"的**：适合小专业，不适合大专业。

最有说服力的细节在这里：卡尼曼把题目拿给同事罗宾·道斯看——一位资深统计学家、直觉判断的著名怀疑者。道斯笑着说："计算机科学吗？" 卡尼曼一提"基础比率"，他立刻改正。**知道不等于用得上**。随后 114 名学过统计学的心理学研究生做同一题，排序结果与"相似度排序"几乎无差别。

需要记住三条推论：

**① 典型性的第一宗罪：过于喜爱预测低基础比率的事件。**
描述越像某个稀有类别的典型，你越会预测那个稀有类别——而它恰恰是最不可能的。

**② 合取谬误：越具体的场景，概率必然越低。**
琳达问题：31 岁、单身、直率、聪明、哲学专业、关心歧视与社会公正、参加过反核游行。问"哪个更可能——(a) 琳达是银行出纳；(b) 琳达是银行出纳且积极参与女权运动"，**85–90%** 的被试选 (b)，包括斯坦福商学院决策科学专业的学生。逻辑上 (b) ⊂ (a)，(b) 的概率不可能更高。

这条有一个对写材料的人极其重要的反向推论——**少即是多**。奚恺元的餐具实验：A 套 24 件全好，B 套 40 件（31 件完好 + 9 件破损，价值上严格包含 A）。**单独评估**时 B 的报价**低于** A。系统 1 用平均水平和原型来表示集合，不做求和。所以：在提案、简历、产品清单里，**一个弱项会拉低整体估值，而不是被强项稀释**。该删就删，别凑数。

**③ 统计式基础比率会被忽略，因果式不会。**
出租车问题：某市 85% 出租车是绿色、15% 是蓝色，目击者说肇事车是蓝色（可靠度 80%）。正确答案 41%，多数人答 80%——基础比率被完全丢掉。但把同一道题的基础比率改成因果表述（"两家公司车数相同，但绿色车队的事故率占全市 85%"），人们的判断就**接近贝叶斯答案**。

这条决定了本 skill 的执行方式：**光把数字念给人听没用，必须把它翻译成一句因果话。**

## A1 — 书中的应用

**案例一：汤姆 W 与"知道但用不上"**
上文已述。补一个卡尼曼后来做的实验：让一半哈佛学生鼓腮帮、另一半皱眉头做汤姆题。皱眉（增强系统 2 警觉）的那组**确实对基础比率变敏感了**。卡尼曼的结论是："懒惰也许是人们忽视基础比率的合理解释。"——这为本 skill 提供了合法性：它的价值就在于**把一个本可以做但默认不会做的动作变成必做步骤**。

**案例二：琳达与斯坦福决策科学专业的学生**
85–90% 的错误率出现在受过最专业训练的人群里。关键的修复条件是：**把问题改成自然频率表述**——"100 个像琳达的人中，有多少是银行出纳？有多少是积极参与女权运动的银行出纳？"——错误率大幅下降。这说明相当一部分"偏见"是**问题表述的产物**，而非思维的固有缺陷（Gigerenzer 学派的生态理性反驳正在此处）。

**案例三：出租车问题的两个版本**
同一道数学题，只改基础比率的**叙述方式**：
- 统计式（"85% 的出租车是绿色的"）→ 被忽略，多数人答 80%
- 因果式（"绿色车队卷入了 85% 的事故"）→ 被采纳，判断接近 41%

卡尼曼的解释是，因果式基础比率会**改变你对个案的看法本身**（"这个司机所属的车队开车很野"），从而进入故事；统计式只是一个躺在旁边的数字，构不成故事的一部分。

## A2 — 触发场景

### 什么时候用

- 招聘/面试：判断"这个人适不适合"（**最高杠杆的应用场合**）
- 投资/立项：判断"这家公司/这个项目能不能成"
- 医疗筛查、反欺诈、风控：判断"阳性结果意味着什么"
- 任何"这个案例简直和当年那个一模一样"的类比推理
- 写提案、简历、产品介绍时决定**要不要加进那个弱项**
- 有人给出了一个非常具体、非常合乎逻辑的场景预测
- 你听到一个描述后**几乎立刻**知道它属于哪一类

### 语言信号

> "这人太适合这个岗位了" / "简直是教科书级的案例" / "他就是那种典型的技术型 CEO" / "这家公司跟当年的 X 一模一样" / "描述得这么具体，八成就是" / "所有特征都对得上" / "我觉得有八成把握"

**结构性信号**：
- 判断依据是**画像匹配**，而不是基数
- 预测的场景**包含多个条件**（"他会先做 A，然后 B，最后 C"）——条件越多，概率越低，但听起来越可信
- 讨论中从未出现过**分母或历史成功率**
- 描述里有若干**与结论无关但很生动**的细节（这些细节只提高典型性，不提高概率）

### 与相邻 skill 的区分

| 情况 | 用这个 | 不用这个 |
|---|---|---|
| 判断**某个个案**属于哪一类 / 成功概率多大 | ✅ `base-rate-anchoring` | |
| 估计**一类事件**发生得有多频繁、风险多大 | | → `availability-bias-correction` |
| 估**某个项目**要多久、花多少钱 | | → `outside-view-forecast`（那是参考类别预测，用于工期成本） |
| 已经有一个数值预测，问它该不该更保守 | | → `regression-prediction-moderation`（那是收缩，本 skill 是起点选择） |
| 怀疑自己回答的根本不是那个问题 | | → `question-substitution-check`（上游分诊台） |
| 想给这类判断装一个稳定评分表，彻底不靠印象 | | → `formula-over-intuition`（本书已验证 · 待整理） |
| 谈判中对方先抛了一个数字压住你 | | → `anchor-antidote`（那是**谈判锚定**，与统计基础比率无关） |

#### ★ 与另外两个"预测类"skill 的硬判据

这三个 skill 在措辞上都像"别只看眼前，去看历史数据"，真正的分界线是**被预测的对象**：

| 判据 | ✅ 本 skill (`base-rate-anchoring`) | ❌ `outside-view-forecast` | ❌ `regression-prediction-moderation` |
|---|---|---|---|
| 被预测对象 | 一个**个体**（人 / 公司 / 病例 / 交易） | 一个**项目**（有起止、有交付物） | 一个**已观测到的极端值**的下一次 |
| 问句形态 | "他/它**是不是**那一类""成不成" | "**要多久**""**要多少钱**" | "**下一次**会怎样""刚才那个干预有效吗" |
| 数据单位 | 同类**个体**中的发生率（%） | 同类**项目**的完成时间/成本分布 | **同一对象**的历史波动 + 相关系数 r |
| 我的产出 | 一个概率 | 一个区间 + 承诺日期 + 止损线 | 一个收缩后的数值 |
| 一句话 | 定**起点** | 定**分布** | 定**从起点向直觉走多远** |

**三条快速排除**：
1. 问题里出现**时间单位或金额**（"三个月""50 万预算"）→ 不是本 skill，去 `outside-view-forecast`。
2. 问题里出现**"上一次/上季度/去年"这个极端表现**，且在问它之后的变化 → 不是本 skill，去 `regression-prediction-moderation`。
3. 问题里出现**一段人物或公司画像**，在问"像不像/是不是/能不能成" → **就是本 skill**。

**串联而非互斥**：本 skill 与 `regression-prediction-moderation` 合起来才是第 18 章的完整四步法（本 skill 出第 1 步"基准预测"，那个出第 2–4 步"直觉预测 → 估 r → 收缩"）。若用户要的是一个**具体数值**而非概率，本 skill 做完第 2 步后应主动转出。

⚠️ **命名警告**：本 skill 名字里的 "anchoring" 指"把基础比率作为判断的起点"，与《怪诞行为学》系列的**锚定效应**（anchoring effect，谈判/定价中的数字锚）是**完全不同的两件事**。涉及价格、报价、议价，请转 `anchor-antidote` / `anchor-first-offer`。

## E — 执行

1. **先定类别，再看个案**。写下这一句："这个案例属于 ____ 这一类。" 类别要具体到能找到数据（不是"创业公司"，而是"B 轮后、2C 工具类、创始团队首次创业"）。

2. **查出这一类的基准率并写下来**。招聘：过去同岗位入职者中 12 个月内达标的比例。投资：同阶段同赛道的存活/回报分布。医疗：该人群的患病率。**必须是数字，不能是形容词。**

3. **把基准率翻译成一句因果话**（这一步不可省——统计式基础比率会被忽略）。
   - ❌ "同岗位历史达标率是 40%"
   - ✅ "这个岗位过去 10 个人里有 6 个没干满一年，因为它需要在没有授权的情况下推动三个部门——这件事本身就极难"

4. **改写成自然频率**。把所有概率语言换成计数语言："100 个和他背景类似的候选人里，大约有几个能做到 X？" 这一步能显著降低合取谬误与基础比率忽视。

5. **检查合取**。如果你的判断包含"而且"（他既懂技术又懂业务而且还能带团队），逐项拆开分别估概率，再相乘。你会看到那个"完美契合"的画像实际概率有多低。

6. **只用可靠证据做有限调整**。问："这个证据与结果的相关性有多强？"证据越弱，越靠近基准率。**不可靠的信息等于没有信息**——但 WYSIATI 会让你难以遵守这条，所以要写下来。

7. **少即是多检查**（写材料时反向使用）。清点你的提案/简历/产品清单里有没有明显弱于其余项的条目。**删掉它，整体评价会上升**，而不是下降（奚恺元餐具实验）。注意这条只在**单独评估**时成立；如果对方会并排比较，加项反而有利。

8. **留痕**。写一行："类别 X 的基准是 A%，本案因为具体理由 B 调整到 C%。" 复盘时这一行能区分"程序对但运气差"和"程序本身就错"。

## B — 边界

### 不适用的情况

- **找不到合理参考类别**的真正新事物。强行套一个不相干的类别比不用更糟。此时应转向情景推演和小步试验。
- **目标是最大化命中率而非最小化误差**的场合（风投找 100 倍、招聘找明星、内容找爆款）。这类幂律回报下，"预测极端事件"可能是合理策略——见 `regression-prediction-moderation` 的同名边界。
- **个案证据极强且高度可靠**时。基础比率是**起点**不是**终点**；有确凿的一手证据（他已经在同样岗位做成过三次）时，调整幅度应该很大。
- **审美、创意、价值判断**。没有客观基准率。

### 失败模式

1. **只报数字不做因果翻译**（最常见的失败）。会议上念出"行业成功率 15%"，所有人点头，然后继续按原判断走。第 3 步是本 skill 效力的主要来源。
2. **用基础比率当拒绝的借口**。"这类项目 90% 都失败"可以用来否决任何事，包括那 10%。本 skill 的产出应该是**调整后的概率与相应的下注规模**，不是一票否决。
3. **参考类别选得太宽或太窄**。太宽（"所有创业公司"）→ 数据无意义；太窄（"和我们一模一样的公司"）→ 样本量为 1，退回内部意见。合适的粒度判据是：**这一类里至少有 10–20 个可观察的历史案例**。
4. **把它用在人身上时的伦理问题**。用群体基准率判断具体个人，在招聘、信贷、司法场景可能构成歧视，且部分场景违法。判据是：**基准率必须基于行为与绩效数据，不得基于受保护特征**（性别、年龄、地域、族裔等）。这条是硬约束，不是建议。

### 盲点

- **知道了也用不上**。道斯的例子说明，即便是最懂基础比率的人，在看到一段生动描述时也会脱口而出典型性答案。因此本 skill 必须以**流程字段**存在（评估表里一个必填项），而不是以"我会记得"存在。
- **部分"偏见"是表述的产物**。自然频率表述能大幅降低错误率（Gigerenzer 学派的生态理性反驳）。这意味着：不要把所有概率误判都归因于"人不理性"——很多时候改写问题比训练脑子更有效，也更便宜。
- **基准率本身可能是错的或过时的**。历史数据来自历史环境。环境发生结构性变化时（技术、监管、竞争格局），基准率需要显式打折，且这个打折没有公式。
- **本书方法论的共享边界**：不要援引第 3–5 章的启动效应与自我损耗（复现失败，作者已撤回信任）。本 skill 的证据基础（汤姆 W、琳达、出租车问题）是本书中复现最稳固的部分之一。
- **卡尼曼自认直觉没变好**。四十年后他的直觉判断并未显著改善。正确用法是在决策流程里安装检查点。

### 容易混淆的概念

- **基础比率 ≠ 谈判锚点**。见 A2 的命名警告。两者在中文里都可能被说成"锚"，但机制、场景、解法完全不同。
- **代表性 ≠ 可得性**。代表性问"像不像典型"，可得性问"想起来容不容易"。前者归本 skill，后者归 `availability-bias-correction`。
- **合取谬误 ≠ 细节没用**。细节能提高**诊断价值**（如果它与结果真的相关），但会同时提高**典型性**（无论相不相关）。要区分的是"这个细节改变了概率"还是"这个细节只是让故事更像"。
- **基础比率 ≠ 刻板印象**。基础比率是关于**类别的统计事实**且用于**校准概率**；刻板印象是把类别属性**当作个体属性**且用于**替代个案证据**。第 6 步（用可靠证据做调整）是二者的分界线。

## 相关 skills

- **composes-with**: `outside-view-forecast` — 同源方法（都是"先看类别再看个案"）的两个分支：本 skill 面向**个案概率与归类**，那个面向**工期、成本、完成率**。执行步骤 1–2 几乎相同。
- **composes-with**: `regression-prediction-moderation` — 天然串联：本 skill 定基准值，那个决定从基准向直觉走多远（按相关系数比例收缩）。二者合起来就是第 18 章的"直觉预测修正四步法"。
- **contrasts-with**: `availability-bias-correction` — 频率估计 vs 个案归类，是代表性与可得性两条不同的启发法。
- **composes-with**: `formula-over-intuition`（本书已验证 · 待整理）— 当同类归类判断反复发生（招聘、信贷、审核），把本 skill 固化成评分表是最终解。
- **contrasts-with**: `anchor-antidote` / `anchor-first-offer` — **完全不同的"锚"**。那两个处理谈判与定价中的数字锚定，本 skill 处理统计基准。切勿混用。
- **composes-with**: `question-substitution-check` — 上游分诊台。当替换形式是"它像不像该类别的典型"时，转交本 skill。
