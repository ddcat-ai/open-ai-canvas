## I — 解释

事前验尸（premortem）是加里·克莱因提出的。有意思的是**提出者的身份**：克莱因是自然主义决策学派的代表，推崇直觉型决策，公开反对偏见研究，是卡尼曼的"对抗性合作者"。**一个反对偏见学派的人提出了本书里最好用的偏见对策**——这本身说明这个方法不依赖于任何有争议的理论前提。

它的全部效力来自**一次语法变换**：

| | 提问形式 | 心理状态 |
|---|---|---|
| 常规做法 | "大家觉得**可能会有**什么风险？" | 假设性、可回避、提出者要承担"唱反调"的成本 |
| 事前验尸 | "它**已经失败了**，请解释**为什么**" | 既成事实、必须归因、解释是被布置的任务 |

第二种句式做了两件事：

**① 移除说出怀疑的社会成本。** 卡尼曼写得很直白：

> "当一个团队将注意力集中在决策上，特别是当领导宣布他的意图时，人们对计划好的步骤的可行性的疑虑就会渐渐减弱，到最后，这样的怀疑还会被认为是对团队和领导的不忠诚。"

这解释了为什么"大家还有什么要补充的吗"这句会议结束语几乎从不产生有价值的风险——在那个时刻，提出怀疑的**个人成本远大于收益**。事前验尸把怀疑变成**任务合规行为**：你不是在反对，你是在完成布置。

**② 把想象力导向正确方向。** 开放式的"有什么风险"要求人去搜索一个无边界的空间，产出通常是通用清单（"市场变化""执行不到位"）。而"它失败了，为什么"是一个**归因任务**——归因是系统 1 最擅长的事，人会自动生成具体的、有情节的、涉及本项目独有细节的失败路径。

卡尼曼记录的现场反应值得一提：他在达沃斯偶然讲到这个方法，身后一位跨国公司执行总裁低声说："**就为这一点，来参加这次达沃斯论坛值了。**"

必须同时记住它的定位：作者自己说它**不是灵丹妙药**。它减少损失，不消除意外。而且它必须与外部数据配合——第 23 章教材团队的故事正是反面教材：他们**拿到了**外部数据（40% 失败、成功者 7–10 年），但没有任何程序迫使他们处理这个数据，于是"达成了一种默契，那就是当做什么事都没发生，继续工作"。**光有信息不够，必须有程序。**

## A1 — 书中的应用

**案例一：竞争忽视与迪士尼制片厂**
被问到"为什么这么多大制作会同期公映"，迪士尼制片厂董事长答：

> "一切都是因为自负。如果只关心自己的生意，你就会想：'我有一个优秀的编辑部，还有个很棒的市场部，我们会做好电影的。'你还认为其他人肯定都不会这样想。"

这是事前验尸最典型的靶子：内部意见充分、外部对手完全缺席。多西与洛瓦洛把这些过度进入市场的公司称为"**乐观主义烈士**"——对经济有益，对投资者有害。一次事前验尸至少会让"竞争对手同期上了三部片子"这条路径被写下来。

**案例二：加拿大发明家援助计划**
411 项发明按 37 项标准评级，D/E 级代表失败，占 **70%**。评级极准：411 项中仅 5 项达到商业化最低标准，无一非常成功。关键数据是——**收到 D/E 评级后，仍有 47% 的发明家选择继续**，而这些坚持者的最终损失平均是放弃者的**两倍**。而且在乐观测试中得分越高的人，越倾向于坚持。

这组数字说明了本 skill 与 `outside-view-forecast` 必须连用的原因：**外部数据被送到了发明家手上，仍有近一半的人无视它。** 数据本身不改变行为，程序才可能。

**案例三：小企业创办人的自评**
美国小型企业 5 年存活率 **35%**；创业者对"任何类似你们的企业"的成功率平均估 **60%**（已经偏高）；但 **81%** 的创办人认为**自己**的胜算 ≥70%，**33%** 认为失败概率为零。注意这组数据的结构：他们对**同类**的估计只是偏高，对**自己**的估计是断崖式脱轨。事前验尸恰好攻击的就是这个"我们不一样"的部分。

**案例四：过度自信可驯服不可根除**
卡尼曼在提出事前验尸之前先关掉了另一条路：

> "过度自信是系统1特性的直接结果，可被驯服但不能被彻底改变。问题的主要障碍在于，主观自信是由人们构建的连贯的故事决定的，而不是由支持它的信息的质量和数量决定的。"

所以他把希望寄托在**组织**而不是个人身上——组织"思考得更慢，也有能力安装有序的程序"。

## A2 — 触发场景

### 什么时候用

- 投委会/立项会/上线评审，决策已成形但尚未正式下达（**标准窗口**）
- 大额不可逆投入前：并购、招人、签长约、押注单一技术路线
- 团队意见高度一致、会议异常顺利（**一致本身就是触发条件**）
- 领导已经明确表态支持，其他人不再发言
- 产品发布、大促、迁移、重构等有明确"上线日"的动作
- 个人重大决策：换工作、创业、买房、结婚前的财务安排
- 已经做过外部意见分析但团队"看过就算了"（补上执行程序）

### 语言信号

> "大家还有什么风险要提吗" / "那就这么定了" / "我看没什么问题" / "方案已经很成熟了" / "领导已经拍板了" / "下周就要上线" / "我们比他们准备得充分多了" / "只要不出意外就没问题" / "这次跟上次不一样"

**结构性信号**（比词汇更可靠）：
- 会议中**反对意见数量为零**，或只有细节层面的意见
- 决策已成形但**尚未有正式文件**——这正是窗口
- 讨论中**竞争对手/外部环境几乎没出现**（竞争忽视）
- 有人私下表达过担心，但会上没说
- 计划描述接近"一切按预期进行"的理想路径

### 与相邻 skill 的区分

| 情况 | 用这个 | 不用这个 |
|---|---|---|
| 决策将落未落，需要**制度化地引入怀疑** | ✅ `premortem-doubt-injection` | |
| 要估这个项目**要多久、花多少钱** | | → `outside-view-forecast`（那给数据，本 skill 给程序；常连用） |
| 个人层面审计"我的自信从哪来" | | → `wysiati-evidence-audit`（个人自审 vs 团队程序） |
| 要一个"这类事成功率多少"的**数字** | | → `base-rate-anchoring`（那出概率，本 skill 出失败机制清单） |
| 判断某人的直觉在这个领域可不可信 | | → `expert-intuition-validity` |
| 事情**已经失败了**，在复盘 | | → `hindsight-narrative-guard`（本书已验证 · 待整理；那是真验尸，本 skill 是"事前"） |
| 决策本身是"要不要接这个风险"且可重复 | | → `broad-framing-risk-policy`（本书已验证 · 待整理） |
| 想推动一个方案被别人接受 | | → `nih-co-creation-buyin`（跨书；那是说服，本 skill 是自查） |

**与三个预测类 skill 的关系**：本 skill **不产出数字**。若讨论中真正缺的是"要多久/多少钱"→ `outside-view-forecast`；"这类事成的概率"→ `base-rate-anchoring`；"上次那么好这次会怎样"→ `regression-prediction-moderation`。本 skill 只负责把**怀疑变成一道必经程序**，通常在拿到上述数字之后紧接着做。

## E — 执行

1. **确认窗口**。三个条件同时满足才启动：决策**已成形**（有具体方案，不是还在发散）、**尚未正式下达**、**代价高且不可逆**。低代价可逆的决策不要用，会耗尽团队耐心。

2. **选人：只请知情者**。参与者必须了解这个决策的实质细节。不知情者只能产出通用风险清单（"市场变化""人员流失"），毫无价值。人数 5–10 人为宜。

3. **让最高领导先明确授权，然后最好离场或最后发言**。这是最容易被忽略也最关键的一条。领导在场且已表态时，书写会自我审查。可行做法：领导开场说一句"我支持这个方案，正因如此我需要你们尽全力把它打死"，然后**不参与书写、不第一个发言**。

4. **宣读固定台词**（不要改写成温和版本，语法就是效力）：
   > "设想我们在一年后的今天已经实施了现有计划，但结果惨败。请用 5–10 分钟简短写下这次惨败的缘由。"

   注意三个不可省的要素：**具体时间点**、**惨败（不是"不及预期"）**、**写下来（不是口头说）**。

5. **独立书写，不讨论**。每人各写各的。先讨论会导致锚定与趋同，直接毁掉这个方法的核心价值。

6. **轮流朗读，每人只读自己的，不评论**。全部读完前禁止反驳。这一轮的目标是**把清单摆全**，不是筛选。

7. **合并归类，识别"此前从未被讨论过"的条目**。这是衡量本次事前验尸是否有效的指标：**新条目占比**。如果全是老生常谈，说明第 2 步（知情者）或第 3 步（领导在场）出了问题。

8. **对每条 Top 风险指定处置**，三选一：
   - **消除**（改方案）
   - **设监测指标 + 预设触发动作**（"若第 8 周留存低于 X，则回滚"）
   - **明确接受**（写进决议："我们已知 Y 风险并选择承担"）

   ⚠️ 没有这一步，本 skill 只会产生一次尴尬。第 23 章教材团队就是死在这里。

9. **预承诺退出条件**（与 `outside-view-forecast` 的共享条款）。至少写一条可观测、有时间点的退出线。乐观偏见的真正代价不在于开始了错的项目，而在于**不肯停**（加拿大发明家：坚持者损失是放弃者的两倍）。

10. **归档**。把清单存进决策记录。事后无论成败，这份清单都是评估**决策程序质量**（而非结果质量）的唯一证据——见 `hindsight-narrative-guard`。

## B — 边界

### 不适用的情况

- **决策尚未成形**。发散阶段用它会打击探索，且没有具体靶子。
- **低代价、可逆、可快速纠错**的决策。用在这里是仪式性浪费，且会让团队在真正需要时不配合。
- **需要速度压倒审慎的时刻**（危机响应、窗口期极短的机会）。此时可用压缩版：一个人、3 分钟、写三条。
- **团队已经过度悲观/士气低落时**。此时问题不是乐观偏见，反向使用（"设想一年后大获成功，请写下成功的原因"）可能更有价值。
- **参与者不知情**时。宁可不做。

### 失败模式

1. **领导在场且已表态**（头号杀手）。书写会自我审查，产出退化为无关痛痒的条目。见执行第 3 步。
2. **只做不处置**。产出清单后归档了事，决策照旧。这是本 skill 最常见的死法，也是第 23 章教材团队的死法——他们**有数据、有专家、有卡尼曼本人**，唯独没有"数据超出阈值就触发什么"的程序，于是"当做什么事都没发生，继续工作"，最终用了 8 年，成书从未被使用。
3. **变成例行公事**。每个决策都做，很快退化成走过场。设门槛：不可逆 + 代价高 + 团队已趋一致，三者同时满足才启动。
4. **用它来杀方案**。如果发起人的真实目的是否决，团队会察觉，此后所有事前验尸都会被当作政治工具。本 skill 的合法产出是**改进 + 监测 + 退出线**，"取消项目"只应在风险清单压倒性时出现。
5. **写成通用风险清单**。"市场变化""竞争加剧""执行不到位"这类条目说明第 2 步选错了人，或时间给得太短（少于 5 分钟人会偷懒）。

### 盲点

- **它不能消除乐观，也不应该**。卡尼曼明确说乐观者更健康、更长寿、更能从挫折中恢复；"当需要采取行动时，即使略带妄想，乐观主义也是件好事"；因乐观而承担风险的企业家"毫无疑问都会为激发资本主义社会的经济活力作出贡献"。目标是**校准**，不是消灭。因此使用范围应严格限制在不可逆、高代价的决策上。
- **它只能触及"想象得到的失败"**。真正的未知的未知写不出来。这是它必须与 `outside-view-forecast` 连用的理由：历史分布会捕捉到那些没人想到的失败模式（"40% 的同类团队根本没完成"里包含了各种你想不出的原因）。
- **过度自信可驯服不可根除**。做完事前验尸的团队依然会高估自己。不要因为做过一次程序就放松监测。
- **本书方法论的共享边界**：不要援引第 3–5 章的启动效应与自我损耗（复现失败，作者已撤回信任）。本 skill 的证据基础（克莱因程序、CFO 数据、发明家计划、创业存活率）与之无关。
- **卡尼曼把希望寄托在组织而非个人**。他自认四十年研究没能改善自己的直觉。所以本 skill 的正确形态是**写进会议模板的一个环节**，不是"我记得要保持怀疑"。

### 容易混淆的概念

- **事前验尸 ≠ 风险评估会**。风险评估问"可能会有什么"，事前验尸断言"它已经死了"。语法差异就是全部效力差异。
- **事前验尸 ≠ 唱反调 / 魔鬼代言人**。魔鬼代言人是**指定一个人**去反对，其他人依然可以旁观；事前验尸要求**所有人**独立书写，且不需要任何人表达"我反对"这个立场。这是它政治上更安全的原因。
- **事前验尸 ≠ 复盘（postmortem）**。时点相反，用途相反。复盘请用 `hindsight-narrative-guard`。
- **产出 ≠ 否决**。它的正常产出是修改方案、加监测、写退出线。

## 相关 skills

- **composes-with**: `outside-view-forecast` — **最重要的搭档**。那个提供"同类项目的真实分布"，本 skill 提供"迫使团队处理这个分布的程序"。第 23 章教材团队证明了只有数据没有程序会失败；加拿大发明家计划证明了只有数据也无法阻止 47% 的人继续。两个必须一起用。
- **composes-with**: `wysiati-evidence-audit` — 团队程序 + 个人自审。建议顺序：先做事前验尸（团队层面产生风险清单），再对 Top 3 风险各做一次证据审计。
- **contrasts-with**: `expert-intuition-validity` — 若团队的信心来自某位资深者的直觉，先用那个 skill 判定该领域直觉是否可信，再决定事前验尸的权重。
- **composes-with**: `base-rate-anchoring` — 事前验尸产出的是**失败机制清单**（定性），那个产出**这类事的成功概率**（定量）。两者拼起来才是完整的外部意见；只有故事没有数字，会议上会被"我们不一样"轻易化解。
- **contrasts-with**: `hindsight-narrative-guard`（本书已验证 · 待整理）— 事前 vs 事后。本 skill 的第 10 步（归档清单）正是复盘时所需要的输入：有了当时写下的风险清单，才能区分"程序错了"和"运气不好"。
- **composes-with**: `broad-framing-risk-policy`（本书已验证 · 待整理）— 当决策属于"这一类会反复出现"的类型时，除了做事前验尸，还应把它变成一条事先声明的风险政策。
- **contrasts-with**: `nih-co-creation-buyin`（《影响力》系/跨书）— 那个用于**让别人接受你的方案**，本 skill 用于**让自己的方案接受审判**。方向相反，容易被混用。
