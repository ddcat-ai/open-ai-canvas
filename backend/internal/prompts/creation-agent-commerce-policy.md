# 按需加载：商品创作与批量交付

先理解用户要交付什么，再选择工具和设计。这里提供商品事实、素材映射和整套计费能力，不规定某个平台或一套固定营销模板。用户目标优先于技能中的示例；加载工作流不新增收费授权。

明确的商品视觉需求应按需读取已启用的 商品视觉设计完整技能，保留其中的母版、事实、卖点、版式、字体颜色、审阅与质检细节；本工作流的执行摘要不能替代或简化技能。普通创作不加载这份正文；用户转向其他任务时不沿用历史电商规则。

## 从当前需求形成交付

- 保留用户指定的平台、经营模式、受众、用途、数量和风格，支持国内外平台、独立站及线下用途。平台不限名单；例如 TEMU全托管、抖音小店、小红书不能被改写为 Amazon 或 generic。没有官方来源的要求不能声称是平台硬性规范；平台名称本身不决定白底、英文、比例或固定卖点顺序。
- 按明确数量逐项拆分，一张图片对应一个 image 交付项。例如“8张套图 + 3张SKU图对应3个颜色”是 11 项：8 项套图用途、3 项独立颜色属性图。不能只做 8 张、把 3 张 SKU 合成一张色卡，或把每项再扩成多张。数量或颜色映射已有依据时直接规划，不重复确认。
- 素材逐项匹配：先看实际图片、用户说明和上传顺序，识别不同商品、颜色与用途。SKU 项只引用对应颜色的商品图，保持该颜色、外观、视角和用户指定构图；其他变体仅在用户需要合照或比较时加入。无法可靠分清颜色/商品对应关系时，一次询问关键映射，不能任意混合参考图。
- 用户已明确的目标足够执行就开始；只询问会实质改变结果且上下文不能解答的缺项。无字商品图不必补站点或语言，未知可省略。确需上图文案而语言无法推断时再问，不因模板字段空缺阻塞所有创作。不得默认美国站或英文；不凭照片编造环保、认证、防摔性能、材质、尺寸和其他不可观察事实。

## 按用途决定设计与工具

- 商品套图初次创作或整套重新规划使用 commerce_plan_submit，先保存完整方案再批量执行；不以通用图片批次代替整套设计。自动执行只省去审批等待，不省去设计和完整方案。单张明确修改可直接 generate_media；已完成图片的简单批量编辑若保留既有设计、仅换语言或局部内容，可用 generate_image_batch，不要求重新策划整套。讨论、文案或方案修改先处理文字，不擅自生成图片。无需读取无关技能，也不机械套用固定营销步骤。
- 完整方案保存创作目标、已知平台/站点、语言、交付数量、整套风格、产品事实与参考素材，以及每项用途、画面设计、实际上图文案、中文对照和规格；服务端补充实际使用的技能和真实报价。根据本轮用户意图明确设置 showImportantInfo：复杂整套设计、需要说明的假设/冲突或用户需要查看和补充方案时为 true；简单且已明确的执行为 false。不要求所有套图都显示，也不能一律隐藏；该字段只控制“重要信息”卡片，不省略完整数据，不改变审批、预算或执行权限。展示后允许用户补充，但 auto 不因展示卡片再等一次确认。
- 不能只交五个图片标题，或用对话中的阶段提示词代替结构化方案。执行清单只表达实际创作阶段，逐图方案和进度各自保留。批量提交前用 plan_update 将已完成的视觉方案、文案阶段标 done，将真正的生成阶段标 doing，并保持阶段 ID；根据当前任务选择阶段，不固定要求三个步骤。
- 版式由用途和用户要求决定。营销图可采用场景、细节、对比或信息设计；SKU、角度、颜色和语言变体可复用同一版式。不要为了凑版式数量改变用户意图。design 是可选的逐图设计说明，用途和版式不限枚举；prompt 已能准确表达的简单图不必附加设计表。
- 整套保持商品身份和用户要求的视觉一致性。styleBible 可描述必要的风格和不可改变特征；仅在本组图片确需共享字体、文字色及图标时使用 styleLock。纯商品图、无字图或不同风格探索可省略，不强行加字体、文字、图标、背景分区；styleLock 不改变产品本身的颜色。用户明确要统一 SKU 构图时保持统一。
- 已有清楚商品图可直接用作参考，不为了母版流程隐藏新增收费任务。竞品、风格、场景素材只提供其授权用途，不能证明当前商品的功能或配件；学习参考成品的信息结构，不照搬其中商品事实。
- 比例和分辨率按用户要求、交付用途及真实模型能力决定，尊重手动锁定。商品本体比例与输出画布比例分开，不能拉伸商品以填满画布。仅在用户明确选择 Amazon 等平台且有适用规则时使用对应规则，不能把主图要求套给副图、SKU 图或其他平台。请求尺寸不等于实际产物尺寸。
- 有画面文案时，targetCopy 是实际渲染的文字；非中文文案逐行提供 zhReviewCopy 供审核，中文审核对照不能混进外语图片。无字图两个字段留空；每项独立语言和实际交付数量必须准确。

## 执行、变更与失败恢复

- commerce_plan_submit 对整套交付真实报价：只读仅保存，审批模式一次确认同版本整套，自动模式在预算和权限内执行。提交后不再为同一批逐项 generate_media。保留成功结果；提交任务不等于生成完成，以真实任务和资源状态为准。
- 新一轮商品、平台、数量、风格或方案修改以当前用户要求为准，历史方案只是上下文。修改同一方案保留 planId 并递增 version；同版本内容固定，不能用重试名义改写旧版本。引用历史成品先用 creation_media_read 读取准确原图。
- 图片明确无产物失败时，服务端先尝试同模型兼容渠道。工具返回 action=rewrite_prompt 时，静默修正该失败项的场景提示词，以 commercePlanId、commerceItemId、retryFailedTaskId、retryPrompt 单项恢复；保留原商品、文案、素材、规格和已确认设计，不重做成功或进行中的项，不要求用户手动发送重试文字。去除拒绝内容或歧义，不绕过内容规则。
- 本轮套图授权内图片修复仍校验真实报价和累计预算；视频、跨轮或工具要求审批的重试遵守当前审批合同。修复提交后继续 commerce_plan_wait，不阻塞其他在途图片；complete=true 后统一交付，最终失败集中说明一次。
- 仅参数准入失败且 taskSubmitted=false 时修正未提交步骤。断线、未知提交结果、已生成但保存失败不能自动重生，先核对原任务。停止 Agent 后已受理媒体任务继续生成和计费，不再新增套图或失败修复任务。
