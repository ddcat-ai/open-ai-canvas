# Open AI Canvas Product Roadmap

本文件是 `open-ai-canvas` 的产品路线总纲，面向 Codex、AI Agent 和项目协作者。它把分散在功能清单、ADR、实施计划和待测试记录中的方向组织成统一阶段，防止项目演变为彼此孤立的功能集合。

本路线描述产品目标和阶段顺序，不替代具体功能规格、技术 ADR 或版本排期。阶段中的能力只有在代码、测试和产品验收均完成后，才能标记为完成。

## 1. Product Mission

`open-ai-canvas` 的目标是成为可实际用于 AI 影视创作生产的专业工作台，覆盖：

`故事构思 -> 分镜设计 -> 角色与场景资产 -> 图片生成 -> 视频生成 -> 剪辑 -> 导出与创作管理`

产品不以“支持更多模型”作为最终目标。模型、插件和 Agent 必须服务于可连续完成、可恢复、可管理的创作流程。

## 2. Current Foundation

当前项目已经具备产品化升级所需的核心基础：

- 无限画布、节点、连接、框选、缩放、历史与持久化；
- 文本、图片、视频和音频生成渠道；
- 项目、章节、分镜、角色与素材管理；
- 生成任务、失败恢复、资源同步和任务中心；
- 时间线命令状态机、预览、字幕、转写和导出骨架；
- 插件注册、权限边界和内置预设插件；
- 本机 Agent、Runtime 与官方 CLI 渠道连接；
- 工作区外壳、主题、皮肤和三层设计 token。

因此后续采用增量产品化路线，不重写 Canvas，不替换已有状态和任务协议。

## 3. Roadmap Overview

```text
Phase 0  Design Foundation
    ↓
Phase 1  Creative Workspace
    ↓
Phase 2  Story Production
    ↓
Phase 3  AI Agent Studio
    ↓
Phase 4  Production Pipeline
```

各阶段允许技术准备并行，但面向用户的交互升级应遵守上述顺序。后一阶段不能以破坏前一阶段稳定工作流为代价。

## Phase 0 — Design Foundation

### 目标

建立统一的产品方向、设计语言、评审标准和开发边界，让不同开发者和 AI Agent 在长期迭代中保持一致。

### 核心范围

- UI 设计总纲与专项设计文档关系；
- 产品路线、阶段目标和优先级；
- Primitive、Semantic、Component 三层 token；
- 页面、节点、面板、Dock、浮层和任务状态的统一规则；
- UI 改动的截图、交互说明、回归和设计评审流程；
- 明确 Canvas Store、节点 ID、连接和生成恢复等受保护边界。

### 退出标准

- `AGENTS.md`、UI 设计总纲和产品路线相互一致；
- 新 UI 任务能够引用明确的设计原则和专项合同；
- 不再为单个页面临时创建平行设计语言；
- 后续升级有清晰顺序和验收方式。

## Phase 1 — Creative Workspace

### 目标

让用户打开产品后立即进入专业、稳定、高效的创作环境，并能在不丢失上下文的情况下完成高频操作。

### 核心范围

#### Workspace Shell

- 统一工作区侧栏、顶栏、项目范围和全局搜索；
- 强化当前项目、页面位置和任务状态；
- 优化折叠、窄屏和全屏创作模式；
- 减少 Dashboard 式卡片和无必要页面切换。

#### Canvas Experience

- 统一顶部项目操作、底部工具 Dock 和工作模式切换；
- 改善画布空态、创建入口、缩放定位和焦点模式；
- 让生成、失败、恢复和后台任务在画布中持续可见；
- 保持 Canvas Store、视口、连接和历史协议不变。

#### Node System

- 建立统一的 Node Header、Preview、Status 和 Actions；
- 统一节点的选中、关联、生成中、失败、版本和资源状态；
- 提升图片、视频、文本、音频、分镜和工作流节点的专业辨识度；
- 逐步拆分过大的展示组件，但不改变节点数据合同。

### 非目标

- 不重写无限画布引擎；
- 不替换 Zustand、TanStack Query 或 localforage；
- 不为 UI 整理改变生成协议和任务恢复逻辑；
- 不在本阶段扩展大量新模型渠道。

### 退出标准

- 工作区第一视觉层级明确，创作内容占据主要空间；
- 用户能稳定找到创建、生成、连接、素材、历史和 Agent；
- 核心页面在明暗主题和常用视口下保持一致；
- 节点状态无需打开详情即可被识别；
- 关键画布交互和已有生成能力无回归。

## Phase 2 — Story Production

### 目标

把“故事到分镜”从功能组合升级为连续的影视前期生产流程。

### 核心范围

#### Story and Chapter

- 故事梗概、章节结构、剧本和镜头组织；
- 从文本拆解到可编辑分镜；
- 章节进度、缺失项和下一步操作可见；
- 项目、章节、画布和剪辑入口关系统一。

#### Storyboard

- 镜头描述、景别、机位、构图、动作、对白和时长；
- 分镜表格、画布节点和镜头预览保持同源；
- 支持批量生成、单镜头修订和版本比较；
- 分镜图能够继续进入视频生成和时间线。

#### Character and Scene

- 角色身份、外观、服装、声音和版本管理；
- 场景、道具、产品和风格资产绑定；
- 引用素材在分镜和生成任务中可追踪；
- 角色一致性和资产复用成为项目级能力。

### 退出标准

- 用户能够从故事创建章节和可编辑分镜；
- 每个镜头可以明确绑定角色、场景和参考素材；
- 分镜图生成结果自动进入项目素材和后续视频步骤；
- 修改单个镜头不会破坏其他镜头和项目资产关系。

## Phase 3 — AI Agent Studio

### 目标

让多个专业 AI Agent 在同一项目上下文中协作，同时保持操作透明、结果可确认、修改可撤销。

### Agent Roles

- **Writer Agent**：故事、剧本、对白和结构建议；
- **Storyboard Agent**：镜头拆解、景别、构图和镜头连续性；
- **Director Agent**：场面调度、机位、节奏和镜头组织；
- **Character Agent**：角色设定、一致性和资产引用；
- **Image Agent**：分镜图、关键帧、修图和版本比较；
- **Video Agent**：视频参数、首尾帧、片段生成和失败恢复；
- **Editor Agent**：时间线命令、字幕、节奏调整和导出准备。

### 协作原则

- Agent 读取结构化项目上下文，不依赖模拟点击页面；
- Agent 通过宿主命令和权限协议修改内容；
- 少量、低风险操作可以直接执行，大范围修改先展示差异；
- 所有 Agent 操作显示输入、目标、进度、结果和失败原因；
- 人类用户始终拥有确认、停止、撤销和修改权；
- 不同工作区会话保持隔离，避免上下文串扰。

### 退出标准

- 用户可以在当前工作区调用与阶段匹配的 Agent；
- Agent 产物直接成为可编辑节点、分镜、资产或时间线命令；
- 失败和越权操作明确拒绝，不静默修改项目；
- Agent 修改可以追踪、比较和撤销。

## Phase 4 — Production Pipeline

### 目标

把图片、视频、音频、字幕和时间线连接成完整的影视生产与交付链路。

### 核心范围

#### Video Generation

- 分镜图、首尾帧、角色和产品参考进入视频生成；
- 多模型能力通过统一规格和插件渠道呈现；
- 视频任务支持排队、重试、恢复、版本和素材入库；
- 单镜头生成完成后可以直接进入项目时间线。

#### Reference Video Recreation

参考视频拆解与再创作采用 FrameScript 工作流：

`导入参考视频 -> 镜头拆分与抽帧 -> 选帧与转写 -> 人物/产品替换规划 -> 分镜重绘 -> 视频片段生成 -> 素材入库 -> 时间线剪辑`

- 完整工作台作为应用插件入口；
- 画布视频节点提供“视频拆解”快捷入口并自动带入当前视频；
- 选中帧生成画布图片节点；
- 分析和仿拍提示词生成文本或分镜节点；
- 字幕进入项目字幕轨道；
- 视频、图片和中间结果进入项目素材库；
- XLSX、SRT、ZIP 等交付文件下载到本机；
- 工作流基于现有插件、画布、素材和时间线协议实现，不建立第二套项目模型。

#### Editing and Timeline

- 项目级多轨时间线、预览监视器和 Inspector；
- 片段移动、裁剪、分割、删除和属性调整；
- 自动转写、字幕编辑、样式和高亮；
- AI 编辑命令与人工编辑共享撤销协议；
- 画布快速组装和项目级剪辑共享同一 `TimelineProject`。

#### Export and Delivery

- 后端 FFmpeg 渲染和任务进度；
- 导出预设、分辨率、比例、音频和字幕策略；
- 产物进入资源存储、项目素材和下载交付；
- 对缺失资源、失败片段和近似预览给出真实说明。

### 退出标准

- 用户可以从项目分镜连续完成镜头视频、入轨、剪辑和导出；
- 参考视频再创作流程可以在同一项目中闭环；
- 转写、渲染和导出任务可观察、可恢复并可追踪产物；
- 不需要依赖外部手工文件整理才能完成基本交付。

## 4. Cross-Phase Product Requirements

以下能力不是独立阶段，而是所有阶段必须持续维护的产品合同：

- **Asset Integrity**：角色、图片、视频、音频和字幕的来源、引用与删除安全；
- **Task Reliability**：任务幂等、恢复、重试、取消语义和失败诊断；
- **Model Abstraction**：模型名称、Provider、协议、能力和价格分离；
- **Plugin Safety**：插件权限、运行时隔离和宿主协议；
- **Local-first Capability**：本地 Agent、CLI、Whisper 和 FFmpeg 可独立工作；
- **Project Continuity**：画布、分镜、素材和时间线使用可追踪的同源数据；
- **Accessibility**：键盘、焦点、状态非颜色表达和减少动画偏好；
- **Observability**：保存、同步、生成、转写和渲染状态真实可见。

## 5. Prioritization Rules

新需求按以下顺序判断优先级：

1. 是否修复数据丢失、任务错误、权限或安全问题；
2. 是否打通已有工作流中的断点；
3. 是否明显降低高频创作操作成本；
4. 是否提高角色、分镜、素材和生成结果的一致性；
5. 是否增强 Agent 或插件在现有协议上的能力；
6. 是否只是增加另一个模型、设置项或孤立入口。

若功能不能说明输入、输出、保存位置、失败路径和下一步，默认不进入实现。

## 6. Delivery and Acceptance

每个阶段的功能交付至少包括：

- 用户目标和工作流说明；
- 修改文件、组件和数据边界；
- 页面截图与主要交互说明；
- 空态、加载、成功、失败、恢复和权限状态；
- 与现有项目、画布、素材、任务和时间线的衔接；
- 对应测试、构建或浏览器验证；
- 已知问题和后续范围。

完成代码、测试通过和产品验收是三个不同状态，不能相互替代。
