# 画布与 Agent 共用业务工具规格

状态：首批四种视频处理操作已完成本地实现；真实浏览器、供应商效果与费用仍待验收，尚未上线。

## Problem Statement

创作者可以在画布手动调用视频超分、画质增强、去字幕和相对深度，但画布 Agent 尚未接入这些操作。开发者增加画布功能后，还需分别维护 Agent 的参数、能力发现和执行适配，容易出现按钮可用、Agent 不可用，或首次调用成功、刷新后重试却进入普通生成的差异。

目前存在三种不同职责的注册：画布工具栏负责入口展示，Agent 工具策略负责运行权限，模型目录负责模型能力与价格。它们都不能单独承担完整的业务工具合同。仅给 Agent 增加操作枚举，无法统一参数表单、模型筛选、审批、计费和结果持久化。

用户希望新增工具时只注册和配置一次，画布与 Agent 就能共同使用，并保持现有项目的权限、任务、资源与分层规范。

## Solution

建立共享业务工具定义，统一声明操作、输入输出、公开参数、模型要求、执行方式和副作用。画布和 Agent 从同一有效定义获得各自所需的展示与调用合同，并提交到公共执行链路。

首批接入现有视频超分、去字幕、相对深度和画质增强。用户可以从画布点击工具，也可以要求 Agent 处理指定视频；两种入口采用相同的业务参数、可用模型规则、服务端准入与结果保存规则。Agent 收费任务继续执行现有独立审批。

“一次注册”指同一业务操作的规则只有一份。已有执行器支持的新工具，无需再手写一套画布表单、Agent Schema 和任务处理逻辑。新增算法或上游协议仍需实现一次执行器；需要特殊交互的工具可以提供专用界面，业务合同继续共用。

## User Stories

1. 作为创作者，我希望画布可用的视频超分也能由 Agent 调用，以便通过对话完成处理。
2. 作为创作者，我希望 Agent 能处理我明确指定的视频，以便避免处理错误素材。
3. 作为创作者，我希望画布和 Agent 使用相同的工具名称与参数含义，以便理解一致。
4. 作为创作者，我希望新增工具同时出现在适用的画布入口和 Agent 能力中，以便不必等待二次接入。
5. 作为创作者，我希望只看到当前账号可用的工具与模型，以便减少无效操作。
6. 作为创作者，我希望没有可用模型时获得清晰原因，以便知道需要配置什么。
7. 作为创作者，我希望选择源视频后只展示支持该操作和输入的模型，以便正确选择。
8. 作为创作者，我希望工具参数根据有效能力显示默认值和允许范围，以便无需了解供应商协议。
9. 作为创作者，我希望增强工具正确提供分辨率、帧率和码率选项，以便控制交付质量。
10. 作为创作者，我希望单视频超分等工具不出现无效的提示词、画幅或音频参数，以便减少误操作。
11. 作为创作者，我希望源视频时长与尺寸由服务端确认，以便报价和执行准确。
12. 作为创作者，我希望 Agent 提交收费任务前展示操作、源视频、最终规格和费用，以便确认。
13. 作为创作者，我希望 Agent 自动模式仍保留收费媒体任务审批，以便控制支出。
14. 作为创作者，我希望更改审批参数后重新核算报价，以便实际执行符合批准内容。
15. 作为创作者，我希望源资源或模型在审批后失效时停止提交，以便避免执行过期计划。
16. 作为创作者，我希望处理结果保存为新节点并连接源视频，以便保留原片并进行比较。
17. 作为创作者，我希望任务进度和失败信息沿用现有任务中心与画布展示，以便持续跟踪。
18. 作为创作者，我希望关闭页面后服务端任务仍可继续，以便不依赖浏览器常驻。
19. 作为创作者，我希望刷新后能恢复原处理类型和公开参数，以便继续操作。
20. 作为创作者，我希望重试仍执行原处理操作，以便不会意外进入普通视频生成。
21. 作为创作者，我希望指定处理源视频时不再被要求选择无关的生成版本，以便减少重复确认。
22. 作为创作者，我希望视频处理预算按可信源时长计算，以便遵守本轮预算。
23. 作为创作者，我希望重复审批或执行恢复不会提交第二份收费任务，以便避免重复扣费。
24. 作为作品所有者，我希望其他账号不能通过工具读取我的画布或资源，以便保持数据隔离。
25. 作为只读 Agent 的使用者，我希望处理能力不能绕过只读权限，以便保留明确的写入限制。
26. 作为管理员，我希望新增同类处理模型后两端自动发现，以便只维护模型目录。
27. 作为管理员，我希望模型停用或用户分组调整立即影响实际准入，以便执行服从当前配置。
28. 作为工具开发者，我希望只声明一次业务参数，以便自动生成通用表单和 Agent 参数 Schema。
29. 作为工具开发者，我希望复用现有执行器注册新操作，以便减少接入成本。
30. 作为工具开发者，我希望新协议只实现一次执行适配，以便画布和 Agent 共同使用。
31. 作为工具开发者，我希望缺失执行器或不受支持的参数类型在开发或注册校验时被发现，以便避免发布不可执行工具。
32. 作为维护者，我希望专用界面仍使用共享校验和提交合同，以便不产生第二套业务规则。
33. 作为维护者，我希望通过公共执行接口验证两端等价性，以便新增工具后不重复编写相同规则测试。
34. 作为维护者，我希望批量入口明确拒绝尚未支持的操作，以便避免静默退化为普通生成。
35. 作为创作者，我希望图片插值调整尺寸与 AI 超分明确区分，以便理解实际处理效果。

## Implementation Decisions

### 单一业务定义与职责

- 新增共享业务工具注册模块，按稳定工具标识声明业务操作。最小定义包括名称和说明、适用媒体、输入数量及角色、公开参数 Schema、输出类型、执行器标识、模型能力要求和副作用分类。
- 工具定义只包含可公开的合同。凭据、供应商 URL、工作流内部标识、请求绑定和任意执行代码不能暴露给 Agent 或浏览器。
- 注册模块放在不依赖应用组合根的业务域层；应用层负责绑定现有任务、资源存储、审批和画布持久化能力。域模块不得反向依赖 service 或 app。
- 不建立与模型目录竞争的第二份模型、渠道、价格或协议参数清单。工具定义引用现有能力与参数声明，模型有效配置继续由目录、插件合同及管理员允许的收窄范围共同决定。
- 遵循现有图片参数声明 ADR：参数公开语义与供应商绑定分离，渠道不能扩展插件不允许的参数范围。此次不重写图片参数体系。
- 画布工具栏继续拥有图标、排序和位置等展示职责，以工具标识关联业务定义。通用处理入口由有效定义投影，不能要求每个新业务工具再登记一份前端业务参数或操作白名单。
- Agent 运行策略注册表继续作为工具权限与分类的唯一入口。共享定义的副作用通过确定性映射进入既有策略，投影不得放宽只读、作用域或审批要求。
- 通用表单覆盖首批所需枚举、数值和可选参数。额外展示配置只影响外观；特殊界面必须消费同一公开合同，不复制默认值、校验规则或执行逻辑。
- 注册校验拒绝重复标识、未知执行器、不可投影的参数类型和不一致的输入输出声明。未支持的工具不得显示为可执行。

### 发现与调用合同

- 首批沿用 model_list 和 generate_media 的媒体入口，增加受注册定义约束的处理操作选择。避免给超分、去字幕、深度和增强分别增加一套 Agent 执行流程。
- Agent 工具说明、操作枚举及参数约束由共享定义投影。模型查询返回所选工具的有效参数合同、可用模型选择和现有价格信息；精确报价仍以公共准入为准。
- 画布在现有登录态能力与模型目录读取链路中消费同一投影。确需扩展响应时同步接口类型与规范，不额外建立一套工具调用 CRUD。
- 新增处理操作只有注册且存在执行器时才可查询和提交。不能根据模型名称、提示词或任意字符串推断业务操作。
- 没有显式处理操作的现有生成请求继续按现有生成规则解析；显式处理请求不回退为普通生成，也不在失败后自动换模型或再次提交。
- 发现阶段根据用户、功能开关、模型分组、输入媒体和有效配置筛选。读取目录成功不构成授权，执行阶段重新校验。
- Agent 使用当前画布内的真实媒体节点标识，服务端解析受权资源。浏览器与 Agent 均不得提交上游 URL、凭据或原始供应商参数作为替代执行通道。

### 公共准入与执行

- 首批复用现有媒体任务类型、CreateTask、任务队列、provider、预算、账单和结果回写。不新增平行收费任务系统，也不借 MCP 调用绕过内部业务准入。
- 梳理模型解析和处理归一化顺序。处理模型确定后，必须执行源资源与参数强校验；源资源事实在路由匹配和最终计价需要时均使用服务端可信值。
- 当前处理准入发生在模型路由之前并依赖具体渠道选择，逻辑模型可能跳过处理归一化。实施必须解决此顺序问题，覆盖系统渠道和逻辑模型两种选择路径，不能只在 Agent 调用方补丁式校验。
- 统一验证源视频数量、类型、归属、就绪状态、时长、大小和适用的尺寸限制。供应商差异沿用已有协议与处理规则，不复制到 UI 或 Agent 提示词。
- 单视频输入型操作不接受普通生成的画幅、首尾帧、生成音频等不适用选项。公开合同区分可选、省略、false 和 0，不能使用真值判断丢失有效选择。
- 画质增强的分辨率、允许帧率及码率参数通过公开合同进入统一归一化，由服务端转换为供应商命名空间参数。输入型超分、去字幕、深度只接受执行器明确允许的参数。
- 处理提示词由服务端生成展示文案，不强迫 Agent 编造创作提示词以通过普通生成校验。
- 保留现有源视频和原任务，创建新的结果节点与来源连线；任务身份、节点身份和资源身份仍由现有合同约束。

### 持久化、审批和恢复

- 扩展现有 GenerationSpec 公开合同，使操作和可恢复的处理参数能够随草稿、审批、结果节点和任务公开上下文保存。同步现有 Go 到 TypeScript 类型生成，不手工维护第二份合同。
- 统一处理节点的保存和重试解析，覆盖已有增强、深度及其他视频处理节点形态；新接入不能只保存普通生成规格而丢失处理类型。
- 不为此次新增历史兼容平台；已有工具入口在迁移范围内同步消费统一合同，不保留长期双写且无优先级的两套权威数据。
- 处理源视频使用明确的媒体引用角色。文本 sourceNodeId 与生成版本 inheritFromNodeId 保留原语义，不能改作源视频字段。
- 明确处理源视频后，不因画布有其他同类型作品而触发无关的生成版本来源选择。若用户要继承已有处理任务，仍验证原执行事实，不复制不适用的普通生成规格。
- 收费视频处理按 KindMedia 进入独立审批，包括 auto 模式。审批显示工具、源素材、模型、最终公开参数、可信时长和费用。
- 操作、归一化公开参数及影响执行的供应商映射结果必须纳入冻结执行规格核对。现有哈希已经包含任务操作，但尚未显式覆盖处理参数所在的 providerOptions，实施时补齐该影响面。
- 审批编辑使用同一参数合同重新准入、报价和冻结；改变价格、源资源或关键配置时，按既有失效机制重新审批。
- 视频秒数预算在准入回填可信源时长后复核，账单继续按现有处理计费规则预扣与结算。不采用 Agent 自报时长或默认时长兜底。
- 沿用现有准备态、资源签名、租约、事务提交和幂等身份，保证恢复及重复批准不会创建第二份收费任务。已提交失败不得自动重提。

### 接入范围与后续扩展

- 按共享注册与公共执行合同先完成视频超分、去字幕和深度，再接入参数更丰富的画质增强；交付范围包含这四种已有视频处理操作。
- 现有执行器支持的新工具应只需增加共享业务定义及必要的模型配置，通用画布入口与 Agent 投影自动可用。以此作为架构验收标准。
- 全新算法或协议实现一次执行器，再通过同一注册接入。执行器仍承担实际业务处理，不把可执行代码放入配置。
- 批量处理只有在逐项参数、源资源、报价和授权额度完整接入后才开放。首批不要求新增批量处理支持，未支持的批量调用必须明确拒绝。
- 图片调整尺寸、裁剪和切图为后续接入对象。本次只预留真实输入输出和副作用分类的扩展能力，不提前建设所有图片执行器。
- 未来持久化图片处理应按写入策略接入，外部文件处理在检查点事务外执行，资源配额与画布提交继续复用现有能力；浏览器本地使用是否迁移届时单独确认。
- 初期使用代码注册与现有后台模型配置，不新增任意业务工具的后台配置编辑器，不默认新增数据库表。若实际需要数据库结构变更，须另行明确模型与数据库专题更新。
- 实施完成后同步功能清单、代码地图、Agent/任务合同专题和待测试记录；提案本身不登记为已实现能力。

## Testing Decisions

以现有“业务请求 → 公共任务准入 → 最终任务输入与报价”的服务集成接口作为主要测试边界。画布请求与 Agent 工具调用使用相同源资源、工具和公开参数，比较两者的业务结果，不要求包含调用来源、审批身份等控制字段的整个请求字节相同。

该测试边界已提交用户核对；尚未收到反馈时按当前方案写入提案，不将其描述为用户已确认。

- 好的测试验证可观察行为：可发现能力、最终操作与参数、费用、资源归属、审批状态、结果节点和恢复结果。不以私有 helper 调用次数、文件组织或注册表内部结构作为验收。
- 复用现有 Agent 视频操作与模型筛选测试、视频处理准入测试、准备态和审批失效测试、媒体规格继承测试以及公共任务 fixture，不调用真实收费上游。
- 一次注册验收：在测试 fixture 注册一个已有执行器支持的新工具后，画布能力投影、参数表单合同和 Agent 可调用操作同时出现，不增加单独的前端业务分支或 Agent 操作列表；通过公共链路成功准备任务。
- 能力筛选覆盖同类新增模型、停用模型、分组限制、无可用模型、未知操作、缺失执行器和非法参数声明。
- 对四种首批操作分别覆盖系统渠道与逻辑模型选择；最终任务必须完成处理准入，不得遗漏可信时长或误用普通视频生成操作。
- 参数覆盖省略、默认值、显式 false/0、越界枚举与数值、不适用选项、输入型工具拒绝增强参数，以及增强帧率/码率的有效转换。
- 资源覆盖跨用户、跨画布、未就绪、类型不符、多个视频、混入图片/音频、时长未知、超限及审批后资源变化。
- 审批覆盖只读模式不可调用、auto 模式仍需批准、参数编辑后重新报价、处理参数变化导致旧规格失效、报价过期、资源租约与重复批准。
- 预算覆盖 Agent 自报短时长而源资源更长、归一化后超出秒数预算、积分上限不足；失败时不得落入队列或产生收费任务。
- 持久化覆盖处理结果保留原片、来源连线、刷新重读、任务失败后手动重试、审批恢复、参数与操作不丢失及重复执行不重复扣费。
- 来源语义覆盖明确源视频无需选择无关生成版本，文本来源字段拒绝视频，以及无效处理来源不回退独立生成。
- 批量入口覆盖未支持操作明确拒绝；普通文生、参考生视频和现有分镜流程保持既有行为。
- 前端使用真实 React 画布和 Agent 审批组件，验证通用表单、隐藏无效参数、空态、错误态、明暗主题、滚动、键盘焦点和参数编辑。独立 HTML 不作为验收证据。
- 浏览器验收只有在用户要求预览或联调时启动开发服务；静态阅读和服务集成测试不能宣称浏览器已通过。
- 真实供应商输出和最终实际费用属于独立集成验收，未执行时明确列为本地未覆盖。推送前按仓库规定执行相关验证和统一推送前检查。

## Out of Scope

- 本规格不直接实现代码、提交或推送，也不触发部署和真实收费任务。
- 图片 AI 超分模型的新增实现；现有“调整尺寸”仍表示插值处理，不能据此宣称 AI 超分。
- 一次迁移全部画布工具、快捷键、编辑动作或浏览器本地能力。
- 任意脚本、任意 URL、供应商内部 payload 或动态代码作为可执行工具配置。
- 新建工作流引擎、收费系统、Agent 执行平台或通用插件市场。
- 新增工具的后台 CRUD、自由编排编辑器及未证明必要的数据库迁移。
- 批量视频处理的完整实现、自动失败重试、自动切换模型或自动重新生成。
- 改变现有媒体审批要求、绕过服务端归属验证、复制敏感任务配置或历史编辑器架构恢复。

## Further Notes

现状审计依据包括现有 Agent 工具策略与绑定、视频模型筛选和操作推断、公共任务准入、视频处理归一化、生成合同与 TypeScript 投影、审批准备态和执行哈希，以及画布处理节点保存与重试逻辑。本轮只做静态审计，未运行测试或验证线上状态。

相关约束见[图片参数声明与生成合同 ADR](../adr/0055-image-parameter-contract.md)和[Agent 媒体新版本规格继承](agent-media-spec-inheritance.md)。保留现有合同及审批机制，避免重建已明确移出范围的共享草稿平台。

实施成功的判定是：同一操作只有一个业务定义；同类工具新增无需分别改画布业务参数和 Agent Schema；两种入口最终通过同一执行规则，且重试、审批和费用均保留相同业务语义。
