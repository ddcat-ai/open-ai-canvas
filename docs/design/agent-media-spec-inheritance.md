# Agent 媒体新版本规格继承：最小通用修复

状态：按用户确认收敛实施范围，移出新增共享草稿平台，复用现有合同与审批。当前不宣称全产品规格问题根治。

## Problem Statement

用户只要求修改结尾，新版本却从 9:16 变成 16:9。日志确认工具调用省略 size、目标草稿和版本来源，执行器按模型默认发送 16:9。原片和新版本尺寸分别为 720×1280、1280×720，时长均约 5.056 秒，参考图片均为四张。

已有配置解析只读取目标草稿，新建节点没有配置基线。原片只留在对话语义中，工具目录又笼统指导省略规格，导致生成前已选错比例。

## Solution

在现有媒体工具增加独立版本来源 inheritFromNodeId，从当前用户、当前画布原片关联的已完成任务恢复公开执行规格。图片、视频、音频共用相同来源校验和 GenerationSpec 选项映射。原片保持完整，新版本进入已有准备、报价、审批和任务链路。

单条调用漏传来源且画布已有同类型生成版本时，先在原审批卡明确选择原片或独立创作，不采用默认画幅直接报价。来源选择与收费授权分开，确认后展示新的规格和报价审批。

## User Stories

1. 作为创作者，我希望只改结尾时保留原执行画幅，以便满足交付要求。
2. 作为创作者，我希望省略时长和清晰度时保留原值，以便避免隐性降档。
3. 作为创作者，我希望音频和水印的 false 值保留，以便开关不会意外开启。
4. 作为创作者，我希望图片和音频适用同样规则，以便行为一致。
5. 作为创作者，我希望原节点当前选用设置不影响原执行事实，以便继承正确版本。
6. 作为创作者，我希望引用省略、清空、替换含义不同，以便表达实际修改。
7. 作为创作者，我希望支持显式规格变更，以便制作其他交付版本。
8. 作为创作者，我希望审批显示版本来源和最终参数，以便付费前核对。
9. 作为创作者，我希望来源或引用失效时停止，以便避免无基线生成。
10. 作为创作者，我希望原任务与原片完整保留，以便比较和回退。
11. 作为作品所有者，我希望来源受到用户和画布归属限制，以便阻止越权读取。
12. 作为创作者，我希望新作品仍能使用模型默认值，以便正常开始独立创作。

## Implementation Decisions

- inheritFromNodeId 表示原执行版本，与文本来源 sourceNodeId 和媒体参考 referenceNodeIds 分开。原片不会自动变成上游参考视频。
- 校验当前用户、画布、媒体类型、任务完成状态及任务回写节点；来源无效或必要执行规格缺失时拒绝，不静默回退默认值。
- 模型与公开选项以原任务输入为准，经已有合同白名单转换；不复制密钥、URL、账单和任务身份，不读取后来修改的节点选用配置。
- 规格省略保留基线，显式修改仍复用 configurationChange、能力准入和现有审批。原文校验只验证建议来源，不证明任意自然语言的真实授权。
- 保留音色等工具未单独暴露的合同字段；布尔 false 按已设值处理。
- 参考图同步开关纳入同一公开选项合同，统一映射任务配置、节点元数据和冻结规格；省略时保留原任务的 false，显式修改仍进入原审批校验。
- 来源选项展示原任务实际画幅、标题和节点 ID，同名同规格版本仍可区分；审批卡支持定位所选节点，定位不等于批准。
- 引用省略继承，显式 [] 清空，非空集合替换。继承引用须仍指向原资源，继续执行真实资源、连线、能力和预算校验。
- 首尾帧与角色音色关联随来源恢复；引用变更导致不再满足约束时，由已有准入拒绝。
- 当前工具不支持完整蒙版继承，原任务带 mask 时提交前明确拒绝，不能退化为整图编辑。
- 省略音频模式时继承，显式 tts/unified_edit 按素材与能力校验，不能被旧草稿无条件覆盖。
- 来源确认仅由既有审批决定 API 写入，以运行步骤、调用位置和调用 ID 绑定；不能因模型省略或换来源而解除，也不能被下一步骤复用。独立新建必须由用户明确选择，未预选任何候选项。
- 来源阶段不创建草稿、报价或收费任务，确认后仍需批准新的规格报价卡；中断恢复沿用原审批收尾。拒绝来源确认直接结束本轮，不声称保留了尚未创建的草稿。
- 新版本准备后把来源记录于现有目标草稿，审批编辑从该草稿恢复，不重复用原片覆盖用户修改。恢复审批从已有冻结输入恢复完整公开选项。
- 报价、资源租约、过期、审批编辑和幂等提交复用原机制。不新增表、迁移、CRUD、前端 API、配额统计或删除清理机制。
- 新增草稿平台移出当前工作区，先前两个提交保留在 Git 历史，不改写已有历史。

## Testing Decisions

沿用用户确认的“工具调用 → 配置解析 → 报价审批 → 任务输入”服务集成边界，使用现有 fixture，不执行真实收费生成。

- 原任务 9:16、原节点当前选用 16:9，新版本省略规格，审批与任务仍须为 9:16。
- 时长、音频 false、水印 false、引用顺序与原任务须保留。
- 来源不存在、跨用户、跨画布、模式不符须拒绝。
- 显式空引用须保持清空。
- 复用原有草稿继承、能力、预算、准备快照和审批幂等回归。专项测试不代替真实浏览器与供应商验收。
- 原始漏传来源的反例必须先进入来源确认，选择原片后新报价及任务为9:16；明确独立新建后才可使用默认16:9。
- 验收来源选择的空值、缺失、越界、幂等、恢复及跨步骤隔离；真实 React 审批卡必须不预选并正确提交空字符串独立选项。
- 旧音频草稿显式切换全能配音须成功；带蒙版的来源须明确失败，不能以无mask输入准备成功。
- 原任务关闭参考图同步时，准备、审批与最终任务均须保持关闭；用户显式开启时须保留新选择。
- 两个同名视频使用不同执行画幅时，来源标签须包含实际画幅和各自节点 ID；真实 React 审批卡须验证定位不提交审批。

## Out of Scope

- 共享草稿平台及手动画布、分镜、批量的统一修订接入。
- 首次生成表单答案写入权威规格、可信确认字段和上下文绑定。
- 仍不从焦点、提示词、尺寸、标题或最近任务猜测来源；由实际用户来源确认解除歧义。
- 成品客观或视觉验收、自动重生成、退款、线上修改和部署。

## Further Notes

这是已有单条生成流程内的通用来源继承修复。画布已有可验证版本而调用漏传来源时，不能继续以独立创作采用默认规格；来源歧义由实际用户确认解决。首次表单规格确认和跨入口统一治理仍未实施。
