# 角色卡梳妆台功能规格

状态：核心功能已实现，已用独立本地数据与测试图片上游完成主链路验收；真实供应商效果与正式官方内容尚待验收。本文保留需求形成时的代码现状，当前实现说明见角色梳妆台专题与待测试记录。

## Problem Statement

用户已有人物，希望在保留人物身份的基础上，组合衣服、表情、姿势、配饰、发型和五官参考，补充提示词，交给图片模型生成新形象，并命名保存回同一个角色。当前需要自行寻找素材、组织参考图、生成图片，再回到角色管理中绑定，流程分散。

现有业务分类不足以筛选这些参考资产。代码核对表明，“用户不能设置业务分类”并非当前完整现状：个人素材库的新增、编辑表单和批量上传已经支持选择业务分类，但目前仅有角色、场景、道具、素材、其他和系统管理的方舟认证。衣服和配饰的历史枚举还会被归一化为道具。文件夹和标签可以组织素材，但无法代替六类统一业务分类。

角色已有多造型、命名、服装说明、图片绑定与节点独立选用能力；后台已有官方素材发布管理，另有独立姿势库。新功能需要将这些能力接起来，避免新增第二套素材库、角色形象库或生成任务系统。

## Solution

在角色卡节点提供可发现的“梳妆台”按钮，在现有角色工作室中承载梳妆台流程：

1. 以当前节点选用的角色形象作为基础人物，显示基础图和角色名称。
2. 按衣服、表情、姿势、配饰、发型、五官六个槽位选择参考素材。每个槽位首版最多选择一项，可以替换或清除，六项均为选填。
3. 复用素材选择器，支持“官方素材”和“我的素材”，按当前槽位分类筛选；可从现有上传流程补充个人素材。姿势槽位还可以打开现有姿势库选择具体视角。
4. 输入附加提示词，选择可处理这些参考图的图片模型与现有图片参数，提交统一生成任务。
5. 生成后预览结果，选择一张、输入形象名称，再点击“保存为角色形象”。保存成功后加入原角色的造型库，并让发起节点选用该形象；同角色其他节点保留各自选中的形象。

“形象”是梳妆台的用户文案，底层继续复用现有“造型 / outfit”实体。同一角色的表情、姿势或发型变化也保存在该造型列表中。

## User Stories

1. 作为画布创作者，我希望直接从角色卡打开梳妆台，以便为已有人物制作新形象。
2. 作为画布创作者，我希望看到当前人物名称和基础形象，以便确认正在修改谁。
3. 作为画布创作者，我希望以节点当前选中的造型为基础，以便在已有形象上继续变化。
4. 作为画布创作者，我希望分别选择衣服、表情、姿势、配饰、发型和五官参考，以便清楚表达每张参考图的用途。
5. 作为画布创作者，我希望只选择需要改变的类别，以便完成简单的换衣或换表情任务。
6. 作为画布创作者，我希望不选参考素材也能填写提示词生成，以便用文字完成简单调整。
7. 作为画布创作者，我希望替换或清除任意已选素材，以便调整方案。
8. 作为画布创作者，我希望预览参考素材，以便查看细节后再选择。
9. 作为画布创作者，我希望按业务分类和关键词查找官方素材，以便快速得到可用参考。
10. 作为画布创作者，我希望使用自己的素材，以便沿用项目的视觉设定。
11. 作为画布创作者，我希望在选择过程中上传图片并归入当前分类，以便不中断梳妆流程。
12. 作为素材维护者，我希望在个人素材库新增和编辑时选择六个新分类，以便之后能在梳妆台中找到素材。
13. 作为素材维护者，我希望批量上传时设置业务分类，以便一次整理一组服装或表情参考。
14. 作为素材维护者，我希望分类修改在刷新和重新登录后仍然有效，以便避免仅修改了本地显示。
15. 作为素材维护者，我希望继续使用文件夹和标签，以便在统一业务分类下细分自己的内容。
16. 作为画布创作者，我希望使用已有姿势库并选择视角，以便复用站点现有姿势资产。
17. 作为画布创作者，我希望添加提示词，以便描述材质、细节和参考图无法直接表达的意图。
18. 作为画布创作者，我希望生成时尽量保持人物身份，以便得到同一个角色的新形象。
19. 作为画布创作者，我希望更换五官时仅调整指定特征，以便减少人物身份漂移。
20. 作为画布创作者，我希望选择图片模型及其支持的参数，以便控制效果与费用。
21. 作为画布创作者，我希望在模型不支持参考图或数量超限时得到明确提示，以便调整后再提交。
22. 作为画布创作者，我希望看到任务进度、失败原因和已有取消操作，以便理解生成状态。
23. 作为画布创作者，我希望关闭面板或刷新后还能找到已提交任务与结果，以便继续处理。
24. 作为画布创作者，我希望先预览生成结果再决定保存，以便避免不满意的图片进入角色形象库。
25. 作为画布创作者，我希望为新形象命名，以便在后续创作中识别和选用。
26. 作为画布创作者，我希望保存形象后保留角色原有形象、声音和设定，以便延续已经完成的创作。
27. 作为画布创作者，我希望新形象保存后在发起节点立即可用，以便继续画布创作。
28. 作为画布创作者，我希望同角色其他节点保持已选形象，以便不同镜头可以使用不同造型。
29. 作为画布创作者，我希望保存失败时保留结果并能单独重试，以便无需再次付费生成。
30. 作为画布创作者，我希望重复点击或网络重试只保存一份形象，以便避免重复条目。
31. 作为画布创作者，我希望角色被其他操作更新时得到冲突提示，以便避免覆盖新增形象。
32. 作为画布创作者，我希望查看生成所用素材与附加提示词，以便理解新形象的来源并再次创作。
33. 作为管理员，我希望复用官方素材后台上传、命名并归类梳妆素材，以便维护站点内容。
34. 作为管理员，我希望配置素材说明、标签、排序和发布状态，以便控制用户看到的内容。
35. 作为管理员，我希望六类均有可用的初始示例，以便用户首次打开即可体验。
36. 作为管理员，我希望官方素材沿用来源和授权信息，以便持续维护内容。
37. 作为用户，我希望只能使用自己有权访问的素材和角色，以便保障个人及团队资产边界。
38. 作为使用键盘或小屏设备的用户，我希望选择、生成、命名和保存均可操作，以便完成相同流程。

## Implementation Decisions

### 1. 复用边界与模块责任

| 业务能力 | 复用对象 | 必要扩展 |
| --- | --- | --- |
| 角色管理与形象切换 | CharacterStudio、CharacterStudioOutfitManager、CanvasNodeOutfitSelector | 在既有工作室增加梳妆台入口和内容区；保存结果继续进入原造型列表 |
| 参考素材查找 | AssetLibraryPickerModal、现有素材卡片与预览 | 当前槽位分类初始化、图片类型约束、官方/个人来源与上传后的选中回填 |
| 个人素材整理 | 素材库新增/编辑表单、批量上传和现有同步链路 | 增加分类选项并核实服务端持久化；首版不新增批量改分类功能 |
| 官方内容配置 | 官方素材后台、官方素材 API、Resource | 增加分类及筛选，不单建“梳妆素材”后台和数据表 |
| 姿势参考 | CanvasPoseLibraryModal、姿势复制接口 | 增加返回已复制资源的选择模式，避免为了选一张姿势图先向画布插入临时节点 |
| 图片生成 | ModelPicker、已有图片参数合同、runBackendGenerationTask | 梳妆业务负责组装输入和关联结果；模型协议、队列、费用、取消继续走统一链路 |
| 任务恢复与产出 | 现有任务中心、任务同步、结果物化与消费去重能力 | 增加角色、节点及输出关联信息，恢复为待保存结果 |
| 形象持久化 | 角色 representations 写接口、角色版本与 outfit 构建逻辑 | 支持保存来源、并发校验及幂等保存；同步扩展现有造型读写逻辑 |
| UI 外壳及状态 | AppModal、既有按钮/输入控件、资源图片和工作区状态组件 | 使用现有 token 和浮层边界；不复制独立弹窗、媒体卡片或模型参数表单 |

角色卡只发出打开操作；梳妆台负责选择与预览；业务服务组装任务；资源服务处理参考资源；后端校验权限与落库。只有确实缺少的业务编排才新增模块。已有单图编辑弹窗可作为交互参考，但其单参考图合同不足以直接承担六槽位流程，不整体复制它。

### 2. 业务分类合同

沿用资产的单值 `category`，新增以下值，并同步前后端枚举、校验、归一化、显示文案、筛选、计数及导入导出合同：

| 枚举值 | 中文名 | 梳妆用途 |
| --- | --- | --- |
| `clothing` | 衣服 | 服装样式、版型、颜色和材质 |
| `expression` | 表情 | 面部情绪与表情 |
| `pose` | 姿势 | 身体动作与构图参考 |
| `accessory` | 配饰 | 首饰、眼镜、帽子等随身装饰 |
| `hairstyle` | 发型 | 发型、发色与头发细节 |
| `facial_features` | 五官 | 指定面部特征调整 |

- 业务分类与媒体类型、文件夹、标签各自独立。图片依然是 `image`，新分类不成为角色实体类型。
- 每项资产首版只有一个业务分类；跨类复用通过用户调整分类或更换参考完成，不新增多分类标签体系。
- 分类枚举是产品合同，管理员配置素材内容，不能任意新增枚举。
- 用户在现有素材库新增/编辑中手动归类，在批量上传中为本批指定分类；梳妆台上传默认当前槽位分类，持久化成功后才加入可选结果。
- 未分类资产在原库中继续可见，梳妆台空态提供“前往素材库分类”和上传入口，避免让用户误以为素材丢失。
- `accessory` 必须先作为合法新枚举识别，不能再归并为 `prop`；历史 `wardrobe` 输入统一归入 `clothing`。已持久化为 `prop` 的资产不按名称推断或批量重分类，由用户或管理员明确调整。
- 方舟认证分类仍由系统管理，不能手动改为六类；首版不重构认证与业务分类的单字段关系。认证资产如果要以梳妆分类使用，应走已有合法素材副本流程，不能绕过认证锁定或复制认证身份。
- 数据库实体列与资产载荷中的分类必须一致；覆盖个人库同步、官方发布/导入、项目关联和团队共享中真正经过分类解析的链路，防止新值被降为“其他”。

### 3. 素材选择与官方初始内容

- 六类共用一个素材选择器，由当前槽位传入分类和图片类型。每槽最多一项，显示缩略图、名称和来源，支持替换、清除与预览。
- “我的素材”遵循现有用户/空间权限和远端分页结果，不依赖本机缓存是否已加载，不主动展示其他用户或团队的素材。
- 官方来源沿用官方素材库插件的启用与授权规则。不可用时展示现有状态与提示，用户仍可用自己的素材。
- 官方参考图首版沿用“导入个人库后使用”的资源授权链路；已导入项复用现有幂等结果，再解析为参考资源，不直接把管理员资源地址交给生成模型。
- 姿势槽位复用姿势库的搜索、体系、视角和预览，通过现有复制接口得到当前用户资源。姿势库原有体系内分类不改名为资产业务分类；用于梳妆时归属 `pose` 槽位。
- 新增六类普通官方图片统一从官方素材后台配置；已存在姿势库继续由原后台管理。两者在姿势选择中入口清晰，不做目录迁移或复制整套姿势数据。
- 上线内容包括六类各至少一项已授权、资源可访问的官方示例。示例通过既有官方素材管理能力录入和发布，不将第三方图库图片打包进代码或镜像。
- 管理员可编辑标题、分类、标签、说明、资源、排序与发布状态；梳妆台只显示已发布可用项。下架规则沿用现有“停止新导入，保留已导入副本”的合同。
- 无官方内容时有明确空态，可直接切换个人素材，不阻断基础生成流程。示例的具体文件和授权来源在实施上线前准备，不在本规格中虚构现有内容。

### 4. 生成输入与模型合同

- 基础人物必须有可访问的已保存形象图；无图时引导使用现有上传/绑定能力。官方只读角色沿用已有复制为个人角色的流程后才能保存新形象。
- 打开时读取最新角色详情，并默认使用发起节点的 `selectedOutfitId`。允许通过既有造型选择能力调整本次基础形象，提交后冻结输入快照。
- 有效输入为基础人物图、角色身份设定、槽位参考图及附加提示词。六类均为空时要求附加提示词非空；有任意参考项时附加提示词可空。
- 参考图按基础人物、衣服、表情、姿势、配饰、发型、五官的固定顺序组装。相同资源重复使用时只传一次，在提示词中保留它承担的所有类别及正确图序。
- 提示词将“基础人物身份”“各槽位用途”“用户补充”清楚分段，默认保留未指定的外观特征，避免把衣服或姿势参考中的人物当作新身份。五官参考表达为对指定特征的调整，身份一致性是生成目标，不能承诺模型必然精确实现。
- 复用图片能力与参数声明，检查图生图/多参考图能力和数量上限。上限包含基础人物图；超限或模型不支持时阻止提交并给出调整指引，不能静默丢图或降为纯文生图。
- 资源读取失败、素材已删除或权限失效时明确指出问题项，不提交残缺任务。图像参考是唯一首版输入形式，暂不将文本/视频素材自动转换为参考图。
- 通过统一后端任务入口提交图片任务，沿用模型定价、额度、渠道、任务幂等和取消逻辑；不新增供应商直连或独立计费链路。
- 复用现有单次张数能力；默认一张。若模型支持多张，预览全部产出，每次明确选择一张保存。
- 任务关联保存目标角色、发起画布/节点、基础造型和角色版本、六类素材来源、实际参考资源、附加提示词和提交参数快照。只保存稳定 ID，不保存临时签名 URL、上游密钥或 Cookie。

### 5. 任务状态、关闭与恢复

- 沿用任务中心实际状态，梳妆台呈现未提交、排队/生成中、生成失败、结果待保存、保存中、已保存及保存失败。
- 提交后变更槽位或提示词只影响下一次生成，不篡改运行中任务输入。重复点击提交使用同一提交操作标识；用户主动再次生成则产生新操作。
- 关闭工作室不等于取消任务。取消使用已有任务取消操作和服务端实际结果，不通过销毁面板假定任务终止。
- 结果由已有任务结果物化流程落成 Resource；任务成功但资源尚未可用时继续显示处理中，不提前开放保存。
- 面板重开或页面刷新时通过任务中心恢复相关任务与待保存结果。任务没有绑定目标节点也不能丢失产出；节点删除后仍可从任务记录找到结果。
- 保存失败只重试角色写入。角色删除、失去写权限或版本冲突时展示明确原因，已生成结果保留在原任务中，不重新触发模型。

### 6. 命名与保存形象

- 新形象以“新增造型”写回同一角色，不能覆盖原造型图片或新建第二个角色。名称去除首尾空格后不能为空，遵循现有角色形象名称约束；同名可以存在，以造型 ID 区分。
- 新造型继续包含稳定 ID、名称和图片 Resource ID，可选记录本次衣服说明；同时记录来源任务、输出资源及梳妆输入快照，以便追溯。
- 扩展既有造型解析、构建、重命名、删除和再次绑定逻辑，确保这些操作不会丢弃新增来源信息。参考快照只描述出处，不绕过每次资源访问授权。
- 原角色定义、原有造型、声音绑定及其他图像表达必须保留。存储仍使用角色 definition 与 representations，不建立独立形象表；已有构建逻辑若会重建表达列表，应在该唯一源处修正合并行为。
- 优先扩展现有角色 representations 写合同：携带所基于的 `expectedVersionId`、稳定保存操作标识及来源任务/输出资源关联。后端在同一事务内校验当前版本、角色写权限、输出访问权限，并创建新角色版本和完整表达记录。
- 当前写接口尚无显式版本前置条件；不能把“读最新再覆盖”当成并发保护。版本变化时返回明确冲突，前端刷新并让用户重新保存，不能覆盖其他会话新增的造型。
- 同一角色、任务输出与保存操作标识重复提交只生成一个造型和一个成功结果；幂等命中先于版本冲突和来源重新校验。实现复用不可变角色版本作持久回执，以用户、角色、操作标识的摘要派生版本 ID，在版本说明中记录请求摘要；事务内原子比较主版本指针。浏览器消费去重不能代替该服务端事务保证。
- 保存返回最新角色详情及已保存造型 ID。只有服务端确认后更新缓存并提示成功；同步相关角色列表和画布引用数据，不用本地缓存成功代替落库成功。
- 发起节点更新自己的 `selectedOutfitId`、封面和引用提示词；同角色其他节点通过既有造型锁定逻辑保持原选择。节点已不存在时只保存到角色库，不重建节点。
- 再次命名、选用和删除沿用现有造型管理。删除图片素材仍需遵守业务引用检查，不能导致已保存形象的物理资源失效。

### 7. API、数据库和权限约束

- 资产分类列表/筛选仍使用现有 `category` 参数，个人素材写入、官方素材 CRUD 和导入继续使用原业务 API。前端调用统一 `http`，同步收敛选择器中旧分类字面量联合类型。
- 图片任务保留统一任务 API 与资源准入校验。新增业务关联不是权限凭据；服务端重新校验用户、角色、任务、输出和参考资源。
- 角色写入继续在 service/app 业务边界校验，数据库事务承担并发与去重；handler 只负责合同解析与响应。
- 枚举和造型来源优先使用已有分类列及 JSON 载荷；不能因这是 JSON 就跳过后端校验。若幂等存储实际需要新增列、唯一约束或迁移，应在实施时补齐迁移和数据库文档。
- 新分类、角色保存前置条件、幂等及冲突响应在实施时同步到 API/OpenAPI 和数据库专题；机器可读原因使用既有业务错误体系，不能靠解析提示文案判断冲突。

## Testing Decisions

用户已确认：以真实画布上的“角色卡 → 选素材并生成 → 命名保存形象 → 刷新后重新选用”为主要验收边界，再由现有后端测试补充分类、权限和重复保存校验。

### 主要验收链路

1. 在真实画布准备已有两套形象的角色卡，以及同角色的另一个节点；两节点分别选用不同形象。
2. 打开梳妆台，确认基础形象与发起节点一致；从官方库选衣服，从个人库选表情，再通过姿势库选择一个视角。分别覆盖六类筛选、替换、清除和当前类别上传。
3. 填写提示词，选择支持参考图的图片模型，提交任务。检查基础图、实际参考图、用途图序、参数和费用展示遵循现有合同。
4. 等待生成、预览选图、命名保存；确认形象数量增加一项、原始形象和声音保留、发起节点切到新形象、另一个节点仍用原形象。
5. 刷新页面，重新进入角色工作室，确认名称、图片、来源信息和节点选择均持久化，并能重新选用旧形象。
6. 对同一已产出结果重复保存或模拟响应丢失重试，确认只有一项新形象；模拟保存失败后单独重试，确认没有新生成任务及二次生成费用。
7. 覆盖关闭后重开、生成中刷新、角色被更新/删除和素材不可访问，确认任务结果可找回、错误可行动且没有覆盖旧数据。

浏览器自动化可以在统一任务 HTTP 边界控制确定性输出，验收仍操作真实组件与状态；这只能证明产品流程。上线前另用已配置图片渠道完成至少一次真实多参考图生成，人工评估身份保持和槽位效果，不把固定输出当作模型效果验证。

### 现有测试边界与最小补充

- 优先测试用户可观察的筛选、提交输入、保存结果和失败行为，不固定内部组件树、helper 调用次数或提示词全文。
- 分类合同沿用 `asset-category` 专项测试及后端用户资产文档校验/素材库测试，更新旧 `wardrobe`、`accessory` 期望；覆盖六类往返、未知分类拒绝、计数、导入导出与认证分类锁定。
- 角色持久化沿用角色创建、资源访问和形象选用测试，补充已有形象/声音保留、同角色节点隔离、版本冲突、无权限写入和事务幂等。
- 任务链路沿用任务持久恢复、消费去重、素材恢复、图片参考限制与任务安全测试，验证重复事件不会自动重复保存，取消/失败不会新增造型。
- 官方内容沿用官方素材路由、资源权限和导入测试，验证分类、插件可用性、未发布不可见、下架后已导入副本可用；姿势选择复用原复制授权测试。
- 模型切换时校验能力和参数重置；基础图加参考图超限时必须阻止提交；不能仅验证请求发出。
- UI 验收覆盖明暗主题、窄屏滚动、键盘焦点、浮层不触发画布拖拽/缩放、加载/空态/错误态和命名入口。

规格阶段仅做代码阅读与文档差异检查，不运行构建、测试或供应商生成。实现后的验证按实际改动范围执行；如需推送，再执行仓库规定的推送前验证。

## Out of Scope

- 独立梳妆素材市场、第二套资产库/形象库、专用模型协议与独立计费。
- 自动识别并批量重分类用户历史素材、AI 自动打标签或任意自定义业务枚举。
- 单个资产同时属于多个业务分类，以及方舟认证与业务分类的数据模型重构。
- 单槽多件服装/多件配饰叠加、遮罩绘制、局部重绘编辑器、手动合成、3D 捏脸或骨骼编辑。
- 视频、音频梳妆输入，角色声音变化，训练 LoRA、身份模型或人脸替换专用管线。
- 保存结果自动同步替换所有角色节点、自动把所有生成结果加入角色库。
- 搬迁独立姿势库、抓取第三方图库或未经授权分发初始素材。
- 本次文档交付中的产品代码实施、上线与外部 issue 发布。
