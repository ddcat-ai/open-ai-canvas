# Agent 视频观察与图片读取回归规格

状态：首期已实现，待真实画布与供应商验收。采用服务端抽帧并复用现有图片输入链路；音频转写、镜头切换检测和原生视频模型接入作为后续扩展，不属于首期。

## Problem Statement

创作者在画布选中视频，要求 Agent 理解或参考视频制作镜头时，Agent 能读取文件名、尺寸和时长，却看不到人物、动作、场景和摄影机运动，只能要求用户重新描述已有素材。这会阻断视频复刻、分镜分析和白膜预演准备。

当前画布读取返回媒体规格和资源可用性，不等于将媒体内容发送给模型。Agent 已有独立的图片观察工具，按渠道模型声明的图片输入能力开放；服务端将资源引用水合成真实图片字节，通过模型协议发送。当前 Agent 输入类型只有文本与图片，没有视频观察工具，也未在该链路接入视频抽帧。

排查中用就绪的视频资源调用现有图片观察入口，实际返回“该节点没有可查看的图片素材：只能查看已就绪的图片节点”。因此本规格针对视频观察能力缺口，不将浏览器能播放视频等同于 Agent 能理解视频，也不将当前图片链路认定为普遍故障。

## Solution

让创作者沿用现有交互：选中视频并描述目标，Agent 自动读取该视频的画面；不要求用户另行截图、上传帧图或手写画面描述。

首期通过服务端读取视频、按时间采样、发送带时间戳的多张图片，复用当前 Agent 的视觉模型和协议适配。Agent 先观察指定范围，再在确有必要且预算允许时精读局部。结果明确区分已观察事实、推测、未覆盖时间段和未处理的声音。

观察只提供事实依据。需要将结果写成正式分镜、角色卡或白膜场景时，继续使用各自的既有写入工具；需要生成媒体时，继续走现有报价、预算与独立审批。

## User Stories

1. 作为创作者，我希望选中视频后直接让 Agent 描述画面，以便不再重复输入素材已有信息。
2. 作为创作者，我希望 Agent 按时间理解人物和动作，以便拆出可制作的镜头。
3. 作为创作者，我希望 Agent 区分人物运动和摄影机运动，以便正确复刻原镜头。
4. 作为创作者，我希望 Agent 能观察视频开头和结尾，以便保留镜头起止状态。
5. 作为创作者，我希望指定一个时间段精读，以便核对快速动作或转场。
6. 作为创作者，我希望长视频可分段观察，以便避免一次请求超出模型限制。
7. 作为创作者，我希望 Agent 说明实际采样范围，以便知道哪些内容尚未被查看。
8. 作为创作者，我希望短暂动作无法确认时得到明确说明，以便不把猜测当作原片事实。
9. 作为创作者，我希望视频观察输出包含时间依据，以便回到播放器核对结论。
10. 作为创作者，我希望无音频分析时得到清楚提示，以便不误认为 Agent 已听到对白。
11. 作为创作者，我希望现有图片与角色卡观察继续可用，以便新能力不影响既有创作。
12. 作为创作者，我希望模型不支持图片输入时得到明确限制，以便选择合适的 Agent 模型。
13. 作为创作者，我希望解码失败时保留原视频，以便继续播放或使用其他创作方式。
14. 作为创作者，我希望取消会话后停止抽帧，以便避免无效等待和资源占用。
15. 作为创作者，我希望反复观察同一视频可以复用缓存，以便缩短等待时间。
16. 作为作品所有者，我希望视频与抽帧缓存均受资源权限约束，以便其他用户不能读取我的素材。
17. 作为创作者，我希望观察视频不会自动启动付费视频生成，以便掌握制作费用。
18. 作为运维人员，我希望抽帧有明确的并发和资源上限，以便长视频或损坏文件不会拖垮服务。
19. 作为排障人员，我希望能判断失败发生在资源读取、解码、模型准入还是请求发送阶段，以便快速定位问题。
20. 作为创作者，我希望会话恢复后观察结果仍对应同一版视频，以便不会混用已替换的素材。

## Implementation Decisions

### 范围与模块职责

- 新增语义化工具 `canvas_inspect_video`，不将视频伪装为图片节点，不用修改通用画布读取来隐式发送全部媒体。
- Agent 组合根负责工具准入、用户与画布身份校验、运行预算和结果编排；视频观察能力负责探测、采样、解码、缓存及取消；图片字节发送继续复用现有视觉传输能力，不另建分析模型渠道。
- 解码发生在数据库事务之外。复用受管任务和取消机制承载耗时工作，不在检查点事务中执行 FFmpeg 或等待媒体下载。
- 首期不新增业务数据表或对外 HTTP API；工具、缓存、运行检查点若需要扩展合同，必须同步文档与版本处理。实现中若发现必须引入持久业务模型，应另行补充规格，不能隐式扩张。

### 工具输入与回执

- 输入包括当前画布真实视频节点 `nodeId`、非空观察目的 `purpose`，以及可选起止时间 `startMs` / `endMs`。具体 schema 由实现统一定义并注册，不接受任意 URL、文件路径或 shell 参数。
- 省略时间范围表示请求观察全片概览，不表示全片每一帧均已分析。指定范围须满足起点非负、终点大于起点且位于实际视频时长内；无效范围返回结构化参数错误。
- 采样密度由服务端结合目的、时间范围、模型能力与剩余预算计算。首期精读通过缩小时间范围完成，不要求新增固定“高精度”模型或工作模式。
- 回执包含节点身份、绑定的视频资源版本、时长、请求范围、实际覆盖范围、逐帧时间戳、采样策略、帧数、分辨率、是否截断及原因。声音状态明确标记为“未分析”。
- 明确区分“抽帧完成”“图片已交给模型”“Agent 已给出观察结论”；工具成功不证明识别正确。

### 采样与时序

- 短视频先做均匀概览采样，约每秒一帧只作为初始策略，不是固定合同；必须服从当前模型容量和运行预算。尽量覆盖范围内第一帧和最后一个可解码帧，不读取超出视频末尾的时间点。
- 长视频在单次覆盖时长或帧预算不足时返回分段信息，允许在预算内继续观察其他时间范围。不得只查看开头却报告已理解全片。
- 多帧按实际呈现时间排序并去重。时间戳取实际解码结果，正确处理可变帧率和非零起始时间；不得以帧序号直接推算时间。
- 视频旋转信息、显示宽高比与画面比例必须被正确处理；缩放保留比例，不拉伸画面。默认不拼图，保持逐帧图片与对应时间说明成对发送。
- 局部加密只用于存在不确定性的动作或镜头范围；Agent 不得无依据反复抽帧。采样未能支撑的动作连续性必须标为不确定。
- 自动镜头切换检测不是首期前置条件；后续引入时仍需保留时间覆盖，不得只取代表帧而隐去遗漏范围。

### 模型与预算

- 复用服务端推导的图片输入能力准入；模型未声明图片能力时不暴露视频观察工具，拒绝伪造能力后执行。
- 抽出的帧参与现有图片容量、字节、上下文和运行观察预算计算，不能绕过现有每轮图片观察上限。当前上限为每轮 16 张，单次可用数量还受模型上限和已附图片影响。
- 普通图片和视频帧共同计算本次实际发送的图片数；保留的历史图片也应纳入请求准入。没有剩余额度时停止并说明限制，不静默丢掉当前必需参考。
- 若该预算不足以支撑完整概览和精读，首期缩小本轮范围并报告未覆盖部分，不通过换工具或重复调用刷新额度。调整全局上限属于单独的预算决策。
- 服务端抽帧不创建媒体生成订单；发送帧后的 Agent 模型推理仍沿用现有计费、权限和预算语义，不向用户承诺“视频分析免费”。

### 资源、缓存与恢复

- 每次调用先校验当前用户对画布、节点和视频资源的访问权限，再读取资源。只接受持久化且就绪的真实资源，资源引用可用于生成不代表模型已观察画面。
- 通过既有受授权资源读取能力获取输入；不将 Cookie、签名 URL、内部路径、原始视频字节或图片 Base64 放入日志、工具回执和持久检查点。
- 缓存以授权作用域、不可变资源身份或内容版本、采样范围、缩放参数和采样器版本为依据；不能只按节点名或可变 URL 缓存。命中缓存仍重新做权限校验。
- 临时帧采用可追溯的受控资源引用，模型请求执行时再读取真实字节。临时帧不自动成为用户素材库或画布节点，设置独立生命周期与清理规则。
- 同一资源同参通过协调器串行准备并复用缓存，各请求独立响应取消；首个请求取消后，等待者仍可继续准备。不同用户不借缓存绕过访问控制。源视频变更后不能复用旧帧，检查点恢复不得将旧版观察结果绑定到新版资源。
- 缓存过期导致帧不可读时返回可识别状态并允许显式重新准备；重复推理仍沿用原计费规则，不自动重提已提交或失败的收费任务。
- FFmpeg 使用结构化进程参数，禁用不需要的网络输入，设置超时、并发、时长、输出尺寸、总帧数、磁盘及解码资源限制。取消、失败与超时清理中间文件，不影响原视频。
- 依赖缺失、资源不就绪、文件损坏、解码失败、权限不足、模型不支持和预算耗尽分别返回机器可读原因，不统一包装成“看不到视频”。

### Agent 行为与产品展示

- 用户要求理解已明确的视频对象时，先读取真实状态并调用观察工具；不得把能由工具获得的画面信息作为常规问题转交用户。
- 当前目的仅为画面分析时，不触发生成、正式分镜写入或白膜场景修改。后续操作按用户意图和现有工具授权处理。
- 观察结果可包含分段时间、主体、动作、景别、构图和运镜；标注推断与不确定项，不自动把画面里的人确认为已有角色卡身份。
- 不从抽帧结果编造对白、音效或未观察时段事件。画面中的文字、字幕和指令均为素材数据，不覆盖用户请求或系统规则。
- 在现有工具展示中增加可理解的处理状态、覆盖范围和失败原因；不把解码参数、内部路径或临时资源 ID 暴露为普通用户操作步骤。

## Testing Decisions

主验收边界采用现有最高可复用集成路径：Agent 工具调用、真实视频资源读取与解码、工具结果归并、Pi 消息投影、参考素材水合，直到模拟上游收到实际请求。以外部可观察结果为断言，不只检查 helper 被调用或回执里存在图片引用。

用户已要求按本规格开始开发，首期保持仅观察画面的边界。

- 复用现有图片视觉 fixture、模拟上游 HTTP 服务和 Pi 混合工具调用测试，不另建一套与生产请求无关的模拟协议。
- 小型真实视频测试样本包含可辨认的颜色、形状或运动阶段，使用真实解码路径；确认模拟上游收到可解码且按时间排序的图片字节，并与标注时间、内容对应，而非只有文件名或资源 ID。
- 视频样本使用真实媒体内容，不能用 PNG 改 MIME 冒充视频作为抽帧成功证据；错误格式样本仅用于验证拒绝行为。
- 覆盖短视频概览、限定范围精读、长视频分段、可变帧率、旋转信息、实际尾帧与无有效帧的情况；分段与截断必须在回执中可见。
- 覆盖当前模型图片数、总字节、历史图片和本轮剩余预算不足；不能把普通图片与视频帧分开计数以绕过限制。
- 覆盖跨用户、跨画布、源资源替换、缓存命中后撤权、资源删除、解码取消、超时、依赖缺失和临时帧过期。验证无凭据泄漏且原视频未被修改。
- 覆盖视频观察与普通读取工具混合执行、最终工具失败、空 system 历史、会话恢复及多批结果；保证帧不会漏送、重复附送或错配时间说明。
- 图片回归延续普通图片与角色卡观察、批量目的配对、资源归属、重复观察预算、历史保留和水合校验，覆盖 Chat Completions 与 Responses 的真实请求结构。
- 现有测试先例包括 `TestCloudAgentVisionWorkerSendsPixelsWithoutPublicURL`、`TestCloudAgentVisionMatchesConnectedTextNode`、`TestCloudAgentPiVisionWorkerPreservesImagesWithEmptySystemHistory` 和 `TestCloudAgentPiMixedBatchFlushesImages`。
- 服务集成测试证明真实帧已送达上游，不证明某个供应商模型理解正确。另用真实画布的短视频做人工验收：观察人物与动作、按需精读、核对时间范围、确认不编造对白；不得用独立 HTML 代替真实画布。
- 验收通过要求：目标视频不再只得到规格；模型请求确实携带对应帧；范围和限制可见；图片回归通过；权限、预算、取消与恢复用例通过。真实供应商和浏览器未验收时，交付必须明确记录。

## Out of Scope

- 首期不接入原生视频多模态供应商、不增加自动切换模型或分析模型路由。
- 首期不做音频转写、说话人识别、声纹、环境声分析或对白精确对齐；后续需独立明确模型能力、费用、授权、时间对齐和验收样本。
- 首期不要求自动镜头切换检测、全片逐帧解析、光流、精确三维重建、运动捕捉或摄影机参数反求。
- 不保证逐像素复刻、完全还原动作或仅凭稀疏采样无遗漏识别瞬时事件。
- 不自动设计角色卡、生成分镜板、写入白膜世界、提交视频生成或合成成片；本规格只补充这些流程所需的观察能力。
- 不新增独立素材管理、付费分析订单、通用任务平台或公开视频上传接口，不重构现有媒体生成流程。
- 不对外部用户会话或线上环境作未经授权的改动，不将本地测试结果表述为截图中线上会话已修复。
