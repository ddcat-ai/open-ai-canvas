### 客户端数据与缓存位置

运行数据统一位于客户端安装目录下的 `user-data\`。例如安装在 `D:\PeekReel` 时，SQLite 数据库为 `D:\PeekReel\user-data\data\open_ai_canvas.db`。用户可在安装时选择其他目录；实际路径始终以安装目录为准。

| 内容 | 安装目录下的位置 |
|---|---|
| 数据库、后端素材与媒体 | `user-data\data\` |
| 主进程、后端、桥日志 | `user-data\logs\` |
| Electron 用户设置、IndexedDB、Local Storage、Service Worker | `user-data\` 下对应 Chromium 子目录 |
| Electron 磁盘缓存、临时文件、崩溃转储、更新下载 | `user-data\cache\`、`temp\`、`crashes\`、`updates\` |
| 豆包桥任务、账号注册表、图片和截图 | `user-data\doubao-bridge\data\` |
| 豆包账号 Cookie 与浏览器会话 | `user-data\` 下各账号独立的 Electron session partition；旧 profile 目录仅供迁移 |
| 激活配置与桥 token | `user-data\config.json` |

新版本首次启动会将 `%APPDATA%` 中旧客户端数据逐文件复制并校验，校验完成后写入布局标记，再清理匹配的旧来源；冲突、链接或校验失败时中止并保留原数据。安装器真正开始升级时暂存当前 `user-data` 和旧版桥数据，安装成功后恢复供应用迁移；取消向导不移动数据，卸载时保留 `user-data`。更新器下载缓存与安装器复用缓存最终位于 `user-data\updates\`；NSIS 安装过程仍会临时使用系统临时目录和 `%LOCALAPPDATA%`，成功复制安装器后清理后者的复用缓存。

## 三、架构与数据流

```
渲染进程（web-dist，React）
  │  http://127.0.0.1:17831/api/*（local-server 反向代理）
  ▼
canvas-backend.exe（Go，127.0.0.1:<随机>）
  │  读 channel_models.capability_config_json → 决定 UI 能选什么
  │  按 manifest 声明式协议拼请求
  ▼
doubao-bridge（Node，127.0.0.1:8787，Bearer token）
  │  accounts.dispatch：账号池路由（额度冷却 / 忙闲 / 热账号优先）
  ▼
browser-host → Electron 主进程托管的隐藏 Chromium 页面（每账号独立 session partition）
  ▼
豆包网页（用户自己登录的会话）→ 填词、点发送、抓 TOS 资产
```

关键约定：

- **认证**：桥的所有 `/v1/*` 与 `/conversation`、`/session` 都要 `Authorization: Bearer <桥token>`；`/v1/events`（SSE）额外接受 `?token=`（EventSource 不能带 header）。token 落在安装目录 `user-data\config.json`。
- **任务行形状唯一来源**：`tasks.toRow()`。`/v1/tasks`、`/v1/events`（快照与事件）必须同形，否则前端会读不到 `error`（曾因此把失败显示成「未知原因」）。
- **同步 vs 异步**：生图/文本是同步端点（桥挂住 HTTP，上限 180s）；视频是异步（`POST /v1/videos/generations` → `GET /v1/videos/{id}` 轮询）。
- **画布多图**：一个后端任务可以产出多张 → 后端为每个 `outputIndex` 建独立素材 → 前端画布展开成子节点。**这条链路已生产验证**（任务 `2f80f596…` 单任务 4 素材）。

### prepare-resources 做的事

- `go build` 出 `canvas-backend.exe`（`GOMODCACHE=D:\yingce\.local\cache\go-mod`，Go 1.26 在 `C:\Program Files\Go`）
- 复制 `web/dist` → `resources/web-dist`（先 `cd web && bun run build:lite`）
- 复制桥（**排除** `data`、`test`、`chrome-profile*`，只带 `data\skill-pack.json`）
- 复制 `plugin-packages\*.yingce-plugin`

### 常见坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `prepare-resources.ps1` 编码 | 一跑就乱码/语法错 | **必须 UTF-8 with BOM** |
| `ELECTRON_RUN_AS_NODE=1` 被 shell 设置 | Electron 静默退出 | 启动前 `Remove-Item Env:\ELECTRON_RUN_AS_NODE` |
| 打包残留 `.bak-trim-*` | 安装目录多出 1.2/85.4 MB 垃圾 | 打包前清理 `resources\*.bak-trim-*`（**未修，见待办**） |
| `latest.yml` 与 exe 不匹配 | 自动更新静默失败 | 出包后核对 `latest.yml` 的 `size`/`sha512` 与 exe 一致 |

## 七、关键设计决策（改之前先读）

1. **豆包浏览器由客户端托管**
   每个账号使用独立 session partition 和默认隐藏的 Electron 页面，桥通过本机控制端点续租或回收并附加 CDP。页面不提供可见窗口降级；任务执行期间保护窗口，空闲账号按策略回收。

2. **风控和提交状态**
   驱动检测页面验证及发送失败，避免将未发送的消息当作正在生成。上游风控仍可能出现，提交状态不明时不能盲目重复发送。

3. **为什么保留最近使用的账号窗口**
   复用热窗口可减少后续启动开销；其余空闲窗口按配置回收。单账号任务串行，不同账号可并行，双账号真实验收尚未完成。

4. **为什么创作页的「张数」不再拆批次**
   旧实现：选 2 张 → 建 2 个任务各 `count=1`。后果：豆包一次返回 8 张却每个任务只留 1 张（白费 7 张），且两个任务抢同一账号串行队列，第二个常落不了库。现在：模型声明了 `count` 能力 → 单任务请求 N 张，提示词末尾「，请生成N张」。

5. **为什么本地服务必须固定端口**
   Chromium 的 Cache API 按 origin 隔离。原来 `listen(0)` 随机端口 → 每次启动新 origin → 每个 origin 存一份 30.7 MB 的 ffmpeg wasm → 94 次启动 = 2.89 GB。现在固定 17831~17838。

6. **串片防线（别拆）**
   视频任务发送前给页面已有视频拍基线（`snapshotVideoBaseline`），交付时只认新增 + 未交付过的身份（`deliveredIdentities`），并设最短捕获时间。`finishTask()` 是唯一交付闸门。**这条防线是靠一次真实串片事故换来的，改动前先读 `capture-guard.js` 与单测。**

## 九、坑清单（都是踩过的）

1. **PowerShell 与 `\n`**：在双引号字符串里写 `\n` 会破坏 JS 模板/JSON，命令会出现「看起来执行了但没生效」。**改代码用 `edit` 工具或 line-based 脚本，不要用 here-string 拼 JS。**
2. **`Set-Location` 不影响 .NET API**：`[System.IO.File]::ReadAllLines("相对路径")` 仍按进程 cwd 解析。**一律用绝对路径。**
3. **隐藏窗口**：检查客户端宿主和桥连接状态，不依赖系统浏览器是否安装。
4. **`Invoke-WebRequest` 打 SSE 会挂住**：长连接不结束。验证 SSE 用 node 脚本并在收到首帧后 `destroy()`。
5. **登录态迁移**：当前账号使用 Electron session partition；旧 profile 的完整迁移仍需单独验收。
6. **`accountState` 里别乱测登录态**：会 `launch()` 空等，把 `/admin/api/accounts` 拖慢到桌面端读不到 `busy`，与窗口策略互相等死（曾导致派到已回收账号必失败）。
7. **豆包会话 URL 是 `/chat/local_<id>`** 时说明这次发送失败了（没拿到服务端 conversationId），面板会隐藏——**这是症状不是 bug**，去查风控。
