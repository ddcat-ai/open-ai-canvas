# Celadon UI 自研组件层实施计划（唯一方案）

状态：已接受（2026-09-05）。关联：决策记录 [ADR-0008](../adr/0008-ui-component-layer-antd-replacement.md)；组件编写规范 [ui-design-system](./ui-design-system.mdx)。

**视觉数值权威源（AI 消费入口）**：`/Users/zhugeyue/Desktop/project/bigdate/github-source-code/composio-brand-package/`（与 open-ai-canvas 同级的兄弟仓库目录，下称「规范包」）。改造本项目配色/字体/间距时，**数值一律以该规范包为唯一权威源**，消费规则见 §2.4，禁止凭记忆或截图自拟色值/字号/间距。

本方案是本次 UI 治理的**唯一实施计划**，统管两件事：① 把 `web/src/components/ui` 重建为自研组件层（代号 Celadon UI）；② 按功能对等批次替换 AntD，最终脱离 `antd` 依赖。参考对象：**composio-brand-package**（唯一视觉数值权威源，直接采用其配色/字体/间距/圆角体系）+ **dbx**（组织与契约纪律，优秀项保留）+ **BoardUI**（设计深度：语义 token 状态矩阵、复合排版工具、react-aria 无障碍原语、动效纪律、agentic 应用层，弥补 dbx 短板）。

## 1. 目标与非目标

目标：
- 一套**可继承进项目日常开发**的自研组件层：目录规范、token 义务、变体契约、无障碍与动效纪律齐备，页面只消费 `@/components/ui/*`。
- AntD 依赖按批次归零；过程中任何时刻不出现"同一控件两套观感并存"。
- 组件观感以规范包（composio 视觉：近黑底 + 电蓝主色 + Inter/等宽字体）为唯一数值基准，迁移期内与 AntD 皮肤同源过渡（同一套三层 token），无裸值。

非目标：
- 不照搬 dbx/BoardUI 参考代码（dbx 是 Vue，BoardUI 是独立设计系统）；只吸收“形态与规范”。规范包**只取其数值与视觉体系，不取代码**（其为独立 CSS 变量集，落地时翻译进本项目三层 token）。
- 本轮（B1 周期）不启动 Table/DatePicker/Tree/Upload 等重型自研；它们进入 B5 专项评审。
- 不引入 Radix、不重建样式基座、不新增全局 barrel、不为旧组件加兼容层。

### 2.3 BoardUI 事实基线（2026-09-05 勘察）

- 分层目录：`components/{base,application,foundations}`；base 下每"族"一目录（`buttons/`、`badges/`、`kbd/`、`segmented-control/`、`date-picker/`…），族内平铺多个文件（`button.tsx`/`icon-button.tsx`/`close-button.tsx`/`button-group.tsx`），无全局 barrel，深路径导入。
- 每组件：`interface XxxProps`（含 `ref`）+ 具名函数 + `cx` 合并 + 头部注释（Figma 源节点/尺寸/明暗差异）。变体用本地 style map（`sortCx`），不用 cva——**本项目沿用 cva**（既有习惯 + variants 类型导出更贴合 dbx barrel 形态）。
- 语义 token 命名如 `bg-kbd-background`、`text-kbd-foreground`、`text-caption-1-semibold`、`bg-status-dot-green-halo`；radius 语义名 `radius/md`、`radius/2lg`；暗色仅调 halo 透明度等细节。
- 依赖：`react-aria-components ^1.17`、`@remixicon/react ^4.9`、`@tanstack/react-table`、`recharts`、`@internationalized/date`、`motion ^12`、`tailwind-merge ^3`。
- 形态定位："agentic interfaces"（chat/thinking/agent log/composer/sidebar）——与影策 AI 影视短剧工作台高度同构。

### 2.4 规范包（composio-brand-package）——唯一视觉数值权威源（AI 消费规则）

> 用户决策（2026-09-05）：**直接采用 composio 视觉**（近黑底 + 电蓝主色 + 无衬线/等宽字体），数值全部以该包为准。

**消费顺序（AI 每次改造配色/字体/间距前必读，由浅入深）**：
1. `preview.html`——浏览器打开，先看整体视觉基调（近黑 #0f0f0f 底、电蓝 #0007cd 主色、hairline 分隔、终端质感）；
2. `DESIGN.md`——人类可读规范：语义角色 token 表、排版梯度、组件配方、Do/Don'ts（禁止引入色板外颜色等纪律条款）；
3. `tokens.json`——W3C DTCG 机器可读格式，数值唯一权威（颜色/字号/间距/圆角的 $value 一律以这里为准）；
4. `variables.css` / `theme.css`——CSS 变量落地 + Tailwind v4 @theme 映射，作为翻译进本项目三层 token 的对照样本。

**采用边界**：
- 采用：语义角色命名（ink/body/muted/canvas/surface-*/hairline/on-*/primary/accent-*）、完整状态位（-default/-hover/-active/-disabled）、字号梯度、间距/圆角尺度、深色底 + 电蓝 accent 的整体视觉方向；
- 不采用：其品牌名/Logo/营销文案、abcDiatype 字体（无授权，替换为 Inter + 系统栈；代码用 JetBrains Mono/Fira Code 等开源等宽，本项目已有的 lucide/icon 不变）；
- 落地规则：数值翻译进本项目 globals.css 三层 token（Primitive→Semantic→Component），组件继续只消费 `var(--*)`/工具类，**不允许在页面/组件里直接写规范包裸值**；
- 明暗：规范包为深色单主题，本项目 light/dark 双主题照旧——light 由同一 Semantic 角色推导（组件不读皮肤 ID，明暗只翻 token 层）。

## 4. 目标架构（分层）

```text
web/src/
  styles/globals.css        # 三层 token（Primitive→Semantic→Component）+ @theme 工具映射（不改基座，只扩展）
  lib/app-theme.ts          # AntD 皮肤唯一管理点（替换完成前继续使用）
```

导入约定：一律深路径 `@/components/ui/{base,product,fx,application}/<family>/<file>`（或族级 barrel）；不建全局 barrel。

## 5. 目录与导出规范（沿用 dbx 形态 + BoardUI 族目录）

```text
components/ui/base/buttons/
  ├── index.ts          # 重新导出族内全部组件 + variants 类型（族级 barrel）
  ├── button.tsx        # Button（cva variants）

  ├── tool-button.tsx   # ToolButton（aria-pressed 工具态）
```

- 组件族一目录，族内按文件拆分相关变体；每族 `index.ts` 汇总导出（同 dbx）；无全局 barrel。
- 变体契约：cva 定义 `xxxVariants` 并从 `index.ts` 导出 `XxxVariants` 类型；`className` 经 `cn` 合并；forwardRef 透传；根元素 `data-slot`。
- 命名：组件 `PascalCase`、文件 `kebab-case.tsx`、目录 `kebab-case/`。

## 6. token 扩展规范（对齐 BoardUI 深度；数值以规范包为权威，在既有三层上扩展）

### 6.1 语义状态矩阵（Semantic 层补齐）
为高频角色补齐 `-default/-hover/-active/-disabled`（及可选 `-selected`）状态位，命名 `--<role>-<prop>-<state>` 风格（如 `--control-bg-hover`），消费方直接用状态位，不在组件里做色值推算。明暗只改 token 定义，组件不读皮肤 ID。

### 6.2 复合排版工具类（Component 层注册 @theme）
把既有 `--fs-*` 字号 + 行高/字重映射为 `text-body-regular|medium|semibold`、`text-caption-1-*`、`text-title-1-*` 等**复合工具类**（Tailwind v4 `@theme` 或工具类层注册），并扩展 `cn` 的 tailwind-merge 配置使其可正确合并。**组件禁止再写裸 `text-[Npx]`/`text-sm font-medium` 组合**（对齐 BoardUI typography.css 纪律）。

### 6.3 分组色系（沿用既有 --palette-* 思路，扩展完整 ramp）
- `accent`：品牌 ramp 默认取规范包主色 `#0007cd`（含 -hover/-active/-glow 等状态位，见 tokens.json）；不再沿用旧中性主色。
- `chart`：图表系列 `--palette-chart-1..9` + `-active`（供后续图表块使用）。
- `status`：在既有 `--palette-status-*` 上按 BoardUI 语义补齐成对 halo/dot 类 token（如 `--status-success-halo`）。
- `node`：沿用 `--palette-node-*`（画布节点类型），NodeTypeBadge 消费。

### 6.4 专用 token
组件专用语义 token（如 `--kbd-bg/--kbd-fg`、`--segmented-track`、`--toolbar-bg`）按需在 Component 层新增并在组件头注释标注引用组。所有新 token 走 globals.css 三层流程并同步 ADR/规范文档。

## 7. 原语策略（BoardUI 贡献的关键决策）

- **简单件**（按钮、徽章、空态、kbd…）：原生语义元素（`button`/`kbd`/`span`）+ 自有键盘/ARIA 处理（`aria-pressed`、`:focus-visible`）。
- **复杂控件替换（B3+：Select/Modal/Drawer/Popconfirm/日期/Combobox）**：以 **`react-aria-components`** 为无障碍地基（对齐 BoardUI segmented-control/date-picker 做法），在其上包 Celadon 观感与 token——不自研焦点陷阱/键盘导航/ARIA，也不引入 Radix 全家桶。`react-aria-components` 在 B3 启动时作为正式依赖加入。

## 8. 图标契约

- 统一 `lucide-react`（项目既有），**以组件引用传入**（`icon={Move}`），尺寸/颜色由宿主组件用 token 决定；禁止调用方传 icon className 改尺寸（对齐 BoardUI remixicon 引用契约）。`IconButton`/`ToolButton` 提供 `iconSize` 语义档位而非裸像素。

## 9. 动效纪律（项目已有 motion v12）

- 按压动效、工具切换、浮层出入：抽 `press-motion`/入场/出场工具类或小组件（对齐 BoardUI `button-press-motion` 思路），**统一尊重 `prefers-reduced-motion`**。
- 渐变/悬停细节（如 BoardUI 的 `::before` 交叉淡化）抽成可复用类，不在页面散写。

## 10. 组件头注释规范（对齐 BoardUI Figma 溯源注释）

每组件文件头：用途、消费的 token 组、接管/对标对象（原 AntD 组件或 dbx/BoardUI 组件）、明暗差异要点（如有）。页面私有组件不含此注释义务。
