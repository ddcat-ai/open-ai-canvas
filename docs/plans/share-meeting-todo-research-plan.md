## 结论摘要

这 17 项不是同一层面的任务：画布引用与 Agent 状态属于交互/状态一致性；模型思考、工具协议和缓存计费属于跨供应商协议与账务合同；短剧导入、资产衍生和分镜图属于一条有费用的制作流水线；Skills 推荐和开发者联盟则分别是平台能力与社区治理。建议先收敛会导致状态错误或计费偏差的基础合同，再完成已有短剧并行实现的复核，最后扩大生成工作流和社区协作面。

当前最明确的代码级线索：

- Agent 新轮会直接继承父轮 `Plan`；即使本轮 `plan_update` 支持传空数组，下一轮仍可能重新带回旧清单。画布切换会产生范围变更提示，但此前历史和计划仍会进入续轮上下文。
- 画布引用悬浮卡当前优先使用 `previewUrl`，而引用解析的预览通常是缩略图；插入回调没有收到编辑器选区，现有路径会基于整个提示词追加令牌。
- 视频设置是否显示画幅选项取决于 `modelCapabilityConfigFor(...).video.ratios`。没有声明比例时控件自然没有选项；有选项但生成结果被装进旧尺寸节点时，也可能让用户误以为设置未生效。最终症状需按模型和节点状态复现。
- 创作对话的思考设置仍是布尔值，当前 OpenAI 映射固定为 `medium`，Claude 映射固定为 `budget_tokens: 1024`；Agent 已有 `off/auto/deep`，Pi SDK 还会按模型能力裁剪等级。
- 当前供应商用量解析识别缓存读取字段，但没有缓存写入 token 的统一字段/费用项；Claude `message.usage` 这类嵌套结构也需覆盖。账单不能把 cache read、cache write 和普通 input 混成一个计价桶。
- 当前未提交改动已经增加短剧预留章节、角色声音样本与造型子行，并同步了数据库迁移和待测试文档；现阶段最需要的是整链路审查与真实页面/模型验证，不应再起一套并行数据模型。

## 逐项方案

### 1. 清理 Agent 上轮待办

**现状与问题**：`CreateCloudAgentRun` 在有父轮时复制 `parentState.Plan` 到 `inheritedPlan`；状态为空时不会从计划工具契约上自动推导“用户已取消”。`plan_update` 已明确支持空数组整表替换，所以清理当前轮本身有能力，缺口在于新轮是否应继承旧轮、继承后 UI 如何判定其仍有效。

**建议**：把计划生命周期绑定到「对话 + 目标范围 + 任务意图」，而非仅绑定父 run。续轮入口区分“继续未完成计划”和“新目标”；默认新目标不继承未完成项，显式继续时才继承。空计划作为终态事件持久化，前端选择最新计划事件时必须让空数组覆盖旧计划，不能只找最后一个非空数组。画布范围发生变化时，旧计划不自动迁移。

**验收**：计划全部完成后续轮不显示；用户明确取消全部后传空数组并刷新仍为空；新话题不继承旧待办；“继续上轮”保留未完成项；并发两次 `plan_update` 按 run revision 冲突处理，不复活被取消项。

### 2. 修复视频节点比例不可修改

**现状与问题**：`CanvasVideoSettingsPopover` 仅在 `profile.ratios` 非空时展示比例摘要，内部选项同样来自视频能力。后端会把能力配置中的 `Video.Ratios` 映射为 `Options["size"]`；未配置时无可选值。节点 resize 还有手动尺寸/锁定保护，生成同步也保留用户显示尺寸，因此需要区分“请求画幅”与“节点显示框”。

**建议**：先按四种维度建立复现矩阵：系统逻辑模型/自定义渠道、空节点/已有视频、自动占位/手动改尺寸、生成前/原地重生。确保配置选择写入 `metadata.size` 并进入请求；UI 无 ratio 能力时显示“模型未声明可选画幅”，不静默展示无效选择。新生成媒体回填自然宽高；是否自动调整有内容节点尺寸由明确策略控制，手动调整始终保留。审查画幅归一化、报价选项和上游参数必须一致。

**验收**：切换比例后设置值、预估报价、实际请求体一致；新生成 9:16 结果在画布上可辨认；手动改变节点框后再次生成不改变手动框；不支持比例的模型不会出现可点击但不生效的选项。覆盖能力为空、通配符及价格档非笛卡尔组合。

### 3. 图片引用悬浮预览和真实名称

**现状与问题**：提示词引用已经有 inline thumbnail、悬浮卡和双击放大。悬浮卡尺寸上限约 160px，取 `reference.previewUrl`；真实节点标题经 `reference.title` 传入并作为副标题，但若 label 是自动名，层级不明显。

**建议**：维持输入区小缩略图，悬浮卡改为较大的原比例预览（桌面建议最大边 280–360px，视口内自适应），标题优先展示节点真实名称，类型/素材别名作为次级信息。解析层显式区分 thumbnail URL 与原图预览 URL，不在 UI 临时拼 storage key；沿用签名 URL 缓存、过期刷新和失败冷却，避免暴露签名链接到日志或持久数据。视频继续使用首帧海报，提供无图/过期/加载失败状态。

**验收**：普通节点、素材库图片、角色卡、视频首帧分别验收；长标题省略但可访问完整名称；横图/竖图不裁切，卡片不越出 viewport；过期 URL 可刷新且不无限重试；焦点和双击放大不受悬浮层影响。

### 4. 将图片引用插入当前光标

**现状与问题**：面板 `insertPromptReference` 只接收 reference 和 prompt；在未检测到待输入 `@...` 时，从整个文本末尾拼接令牌。编辑器自身已有纯文本偏移与 contentEditable 选区映射，说明插入应复用该映射，而不是重新实现 DOM 范围算法。

**建议**：在打开引用菜单、点击素材架或切换弹层之前，保存序列化后的 `start/end` 选区；插入时根据当前编辑器模式，把引用令牌替换选区或替换正在输入的 `@query`，再恢复焦点与光标到令牌后。同步处理按钮 mousedown 导致浏览器选区丢失、富文本 chip 的文本长度映射、撤销/重做和异步 prompt 更新。多处入口复用一份“捕获/恢复/插入”纯逻辑。

**验收**：在句首、中间、末尾、选中文字、输入 `@图` 过滤状态下插入；分别覆盖纯 textarea、rich editor、放大弹窗、素材架按钮和键盘选择；插入后继续打字位置正确，Undo 一次只撤销本次插入。

### 5. 隔离全局 Agent 跨画布上下文

**现状与问题**：面板是全局挂载，store 保存当前画布；同一会话允许随页面切换画布，并向模型加入范围变更提示。后端续轮保留整段 `TextHistory`，当前画布目录消息与上一轮计划都要分别核对是否清理。仅清空前端当前选择不能删除已经进入服务端历史的旧画布事实。

**建议**：定义上下文来源类别和范围合同：用户文本可跨画布保留；画布目录、节点选择、资源引用、视觉事实和计划需绑定 `canvasId`/scope revision。换画布时剥离或显式标注旧范围事实，重建本轮目录；对“平台级对话”和“绑定画布对话”使用不同会话 scope，禁止从账号级最近活跃画布隐式注入数据。附件、离线队列和引用节点均按 account + conversation + canvas 分区。保留有意的跨画布续聊入口，但必须明确提示并让用户选择保留的文本历史。

**验收**：A 画布选择/目录/视觉事实后切 B，模型请求不含 A 的节点、图片、ID 或目录；全局对话不绑定离开的画布；并发切换页面、刷新、账号切换、断线重连均不串 context；服务器日志只记录 scope 标识，不记录内容或敏感 URL。

### 6. 大文件短剧导入、确认页、按章/批量生成

**现状与并行实现**：当前工作区已有选章列表、选择章导入、未选章节保存为 `reserved`、制作台章节选择器、加入制作 API，并有迁移/数据库/API 文档改动。并行 `pending-test.mdx` 写明实现和测试，但真实登录态导入到后续制作的完整流水线仍待验收。

**建议**：以短剧项目为导入草稿的持久化边界。导入解析后先展示章节目录、字符数、异常、预估费用与所选范围；用户确认后才创建项目和启动任务。上传的全部章节原文可保存为预留状态，但预算和调度只统计进入制作的章节。章节加入采用服务端事务：校验章节归属、状态、单章/总字数、分集规则，再追加 episodes 并推进计划游标；接口保持幂等，重复点击返回原结果。大文件客户端分块读取/解析或限制峰值内存，后端继续使用请求体上限和资源上限，不将整份小说复制进事件日志。

**验收**：覆盖全选、部分选择、预留章节后续加入、非连续章节、重复提交、双标签并发、服务端写失败、超长章和预算冻结；重新打开项目时选择与预留状态准确；任务仅从确认范围开始，账单、章节数和估算一致。

### 7. 主资产多版本衍生

**现状与并行实现**：当前工作区新增角色造型作为 `DramaCast` 子行（parent、造型名、适用章节），圣经提取与镜头/段提示词也已接入造型字段。它是角色造型版本，不等同于完整的通用资产版本系统。

**建议**：先完成角色造型 MVP：角色本体是稳定身份锚点，造型是带父子关系、来源、适用章节和独立媒体版本的衍生项；镜头绑定具体造型 ID，避免只存名称。生成造型参考图时以角色本体图做 image-to-image，用户可锁定、重做、切回历史。后续评估把模式推广到道具/场景前，先定义不可变版本 ID、当前版本指针、来源任务和软删除/引用保留策略，不把不同角色复制成多个同名“本体”。

**验收**：角色同脸、多造型按章默认、单镜覆盖、造型删除后引用回退、历史参考图可恢复；并发修改用 revision/CAS；迁移可重复、旧角色零值升级正确；媒体引用和账单可追溯。

### 8. 短剧待处理页布局

**现状**：Inbox 是制作台中的整页视图，问题摘要与卡片/快捷入口已有独立 CSS；窄屏制作台另有移动 pane。未找到并行改动覆盖 inbox 布局本身。

**建议**：先按信息密度分层：顶部固定摘要/筛选，主体按“待确认、生成失败、过期/阻塞”分组；同类失败可折叠但保留数量和展开入口。桌面使用 `minmax(0, 1fr)` 主列与受控详情区，窄屏单列，避免固定宽度撑破；长标题、错误详情、按钮组及 99+ 计数都要可换行。不要把整页再包进卡片，详情可用路由/弹层而非多个嵌套面板。

**验收**：0/1/大量条目，标题超长、多错误组、加载失败、数据更新、键盘操作；桌面 1280/1440、窄屏 390px、明暗主题和浏览器缩放 200%。

### 9. 聊天窗口与画布 Agent 思考强度

**现状与缺口**：创作聊天偏好只保存 boolean，任务传 `enableThinking`；后端对 Responses 映射 `reasoning.effort=medium`、Chat Completions 固定 `reasoning_effort=medium`、Claude 固定预算 1024。Agent 有 off/auto/deep，Pi 的有效等级依模型能力裁剪；Pi 默认 medium 不代表模型一定支持。声明式渠道的思考能力不能只靠 UI 字段推断。

**建议**：产品层统一语义 `off | low | medium | high`，再由协议 adapter 根据模型 capability 映射；不支持该等级时在选项处说明并回退到 provider default，不发送未知字段。保留 Agent 的 `auto` 语义（模型自行/平台默认），不要把它直接等同 `medium`。配置沿用本机 user-scoped 偏好，任务创建时快照实际值供重试复现。管理端能力合同应声明 thinking 模式及上下限；旧 boolean 映射为 off/medium 的迁移只用于读取，不必增加长期兼容层。

**验收**：无思考模型不发送 thinking 字段；OpenAI/Responses、Claude、Gemini/声明式协议分别有请求体测试；输出 token 上限大于思考预算；续轮更改等级后不会被 Pi session 旧设置静默覆盖；UI 明确展示潜在更高时延/费用，不擅自默认高档。

### 10. Opus 工具协议与缓存写入计费

**现状与根因候选**：云端 Agent schema 中 `generate_media`、`image_layer_split` 有顶层 `oneOf` 候选，其他结构也包含 `anyOf`；当前统一 OpenAI 风格 schema 不保证每个上游协议均接受。Pi runtime 的 assistant→canonical 转换只保留 text/toolCall，没有保留 thinking block/signature；若启用 Anthropic extended thinking 并带工具，需要通过真实协议请求确认是否因此失败。当前 analytics 解析 OpenAI/Gemini cache-read 字段，没有 Anthropic `message.usage.cache_creation_input_tokens` 的明确读取；价格/账单结构只有普通输入、输出和 cached token 桶，无法准确表达 cache write 的不同价格。

**建议**：拆成两个垂直问题分别处理。协议侧按上游协议生成/降级 tool schema：Claude、Responses、Chat Completions、Gemini各自通过 golden request fixture；对组合 schema 做协议能力检查，必要时把互斥字段拆成可选字段并由服务端二次校验，保持工具语义一致。调试日志记录脱敏后的协议、模型、tool name 和响应错误码。计费侧明确三类 input：uncached input、cache read、cache write；在 `ApiCallLog`/订单快照加入 cache-write token 与单价，按供应商响应结构解析增量/累计事件且幂等合并，不能把 `message_start`/`message_delta` 重复累加。历史订单按旧口径维持，不做猜测性重算。

**验收**：同一工具集在真实 Opus 模型最小冒烟能成功注册并完成一次 tool round-trip；标准 Responses/Claude/Gemini fixture 均解析一次且不重复记账；缓存读写、缺字段、0 token、重放 SSE、失败后有 usage、退款/重结算均有测试；账单明细可解释计算输入。

### 11. 清理提示词偏好、隐藏个人模型配置

**现状与问题**：`PromptPreferencesPane`、API 和 operation catalog 仍存在；代码搜索显示真正传 `promptTemplateOperation` 的调用较少，部分 operation 可能已经没有生产者。管理员模板与用户提示词偏好是两条不同能力，不应一起删除。自定义渠道数据保存在按用户 scope 的浏览器配置中，含 API key；功能关闭时前端过滤用户渠道，后端 relay 路由也有 feature gate。

**建议**：逐个 operation 建立“前端 producer → task metadata → backend compiler → 测试/文档”矩阵。没有 producer 的用户偏好入口先隐藏并禁止新写；服务端保留必要读取/迁移窗口，明确保留时长后再删除字段/API。管理员模板运行中被使用的不得清理。个人模型配置按“隐藏 UI”与“禁止使用”分开定义：若只是隐藏，保留本地配置但不得静默自动选成其他模型；若要停用，功能开关同时约束新任务创建和自定义 relay，失败返回机器可读原因，既有任务按创建时冻结配置完成或显式失败。绝不因隐藏 UI 自动删除 API key 或重写用户配置。

**验收**：operation catalog 每一项有生产者/消费者/维护人；隐藏设置后刷新仍不泄露配置，重新开启仍可恢复；开关关闭时新写路径前后端一致拒绝；模型缺失显示明确不可用状态而不落到错误渠道；管理员模板编辑保持独立。

### 12. 短剧高级配置折叠

**现状**：制作设置含分集方式、分镜规则、文字步骤、参考图、模型与成本等连续板块，设置页并非折叠信息架构。创建页还需另行检查，避免只优化一个入口。

**建议**：把用户开工必需项放首屏：作品画幅、分集方式、制作节奏、模型摘要、预算；次级项（提示词/技能、参考图方案、分辨率、并发、重做范围）放入分组折叠区。折叠默认由“新手/高级”明确切换，用户展开状态只做本地偏好；已有未保存更改时切换/离开需提示。费用、影响范围和会触发计费的重做操作不得藏在折叠里或弱化警告。

**验收**：新建作品与现有作品的关键设置可找到；折叠不丢表单草稿；窄屏滚动和保存栏不遮挡；设置快照在保存前后与后端一致；禁用选项说明原因。

### 13. 剧本导入支持更多格式并加 AI 预览确认

**现状**：浏览器支持文本编码识别与章节拆分；后端分镜导入支持 JSON、Markdown 表格和 TSV，解析失败路径可交模型转录。纯文本自动解析不能覆盖 Word 文档、带场次标记的剧本或不规则表格。

**建议**：采用“确定性解析器优先，AI 修复/归一化辅助”的流水线。第一阶段盘点并明确 UI 接受格式；增加 DOCX/常见剧本格式读取时限制压缩包大小、条目数、总展开大小和文本长度。解析结果统一成章节/场景/镜头中间结构，给出未识别行、缺字段、台词归属和切分建议。AI 只生成候选结构，用户在预览页对照原文确认/编辑后才写入；保留原始文本供复核，拒绝将 AI 结果直接自动开工。模型调用需费用预估、取消、重试和结构校验。

**验收**：每种支持格式各有固定 fixture；乱码、空文档、恶意压缩、超限文件、模糊标题、重复镜头均可诊断；AI 输出非法 JSON/遗漏台词/重复行时不能覆盖原文；用户确认后集数、镜头数、原台词与预览一致。

### 14. 内置 Skills 生成分镜图，提升站位连续性

**现状与缺口**：短剧流水线有 Bible、剧本、结构化镜头、角色/场景参考图和段视频；已内置短剧、分镜、角色等 Skills，步骤也能配置写作技能。尚需证明 Skill 生成的走位信息进入了结构化镜头并最终改善分镜视觉，不只是增加提示词长度。

**建议**：先把“站位”定义成可检查的数据合同：镜头内角色、屏幕左右/轴线、朝向、起止位置、动作路径、视线/对手关系和跨镜连续性。用 Skills 辅助输出上述信息，再生成低成本 storyboard/contact sheet 供用户确认；角色本体/造型图作身份锚点。分镜确认后，才把锁定的 storyboard frame/资产引用传给支持图像参考的视频模型。分镜图片生成应为可选步骤，按集/批次设置张数与预算，失败不阻塞文本审阅，不自动重复收费。

**验收**：双人对话轴线、角色入画/离画、走到座位并转身等基准样例；前后镜头角色位置可追踪；人工确认后素材编号与段视频请求一致；费用、失败重试和跳过路径清晰；真实视频模型对比评估穿帮率，而非仅凭提示词单测结案。

### 15. 角色声音参考功能

**现状与并行实现**：当前未提交工作增加角色绑定声音库 profile、上传/录音、试听/清除，并按视频模型 `maxAudios` 和参考图条件装配段音频。并行待测试文档也写明尾帧续接等不发送场景。

**建议**：沿用现有并行实现做代码审查，不另建声音表或上传 API。重点复核资源所有权、MIME/大小/时长上限、孤儿资源回收、角色/造型继承、音频参考不支持时的 UI 说明、模型请求和异步日志中的敏感数据脱敏。将“库中声音名字/描述”和“可实际发送的样本文件”区分；仅在上游能力合同允许时装配，失败不得悄悄退回另一个声音样本。

**验收**：本人/他人资源归属、移除样本、删除角色、切换声音、造型继承、上传失败、录音取消；请求 fixture 确认样本只出现在说话段且排序稳定；真实渠道验证采样率、格式和模型支持组合。

### 16. 下一版本 Agent 主动识别并推荐 Skills

**现状**：服务端已有安装技能目录、关键词召回提示、固定技能和 `skill_search`/`skill_read_file`；Skills 说明只提供工作法，工具权限仍独立。该基础比“自动把全部技能正文塞入上下文”更适合扩展。

**建议**：下一版做可解释推荐而非全自动加载：以用户意图、技能摘要/触发词和当前工作区能力做候选排序，呈现推荐理由、版本和预计上下文成本；用户可接受、拒绝或设为自动/手动。明确点名技能直接读取；低置信度才展示候选，不为了推荐而追问。接受后只加载入口文件及其引用的必要内容，版本在 run 内冻结；技能正文作为不可信数据处理，不改变工具权限、审批、费用或模型路由。

**验收**：中文同义表达、无关短问、多个相近技能、技能被卸载/升级、用户手动关闭自动推荐；记录召回命中与误报指标；冷启动不增加不可控 token；拒绝推荐不会影响任务。

### 17. 开发者联盟

**现状**：项目有 MIT 许可、`CONTRIBUTING.md`、安全报告路径、CI Quality checks，以及 `yingce.plugin/v2` 插件包和专题文档；未发现仓库级 CODEOWNERS、贡献路线图或明确的“good first issue/RFC”入口。

**建议**：把联盟作为治理与招募项目，不与单个功能发布强绑定。先发布贡献者入口页：项目边界、运行方式、模块 owner 联系方式、Issue/RFC/PR 模板、可独立验证的任务标签、插件包开发路径和安全报告渠道。建立轻量流程：提案→维护者初筛→小 RFC/样例→实现者认领→CI/代码审查→发布说明；明确行为准则、知识产权/素材许可、维护响应预期及不承诺的支持范围。初期以插件协议、文档、测试夹具和独立 Skills 为外部贡献边界，核心账务/权限/数据库改动需指定维护者审核。

**验收**：新人在无口头协助下能启动、找到一个入门事项、运行对应检查并提交 PR；第三方插件从 manifest 到测试/打包有可复制示例；维护者分配和安全报告仍走现有渠道。

## 相关补充问题

1. **统一 scope 合同**：Agent 对话、排队消息、临时附件、短剧项目、镜头和素材都要说明归属键与生命周期；用户切换、项目删除、账号退出时如何隔离/清理要有测试。
2. **幂等与并发**：长任务创建、批量补交、章节加入、Agent plan 更新和收费媒体审批都需在服务端用幂等键/条件更新；前端禁用按钮只是体验措施。
3. **能力数据可信**：比例、思考等级、参考音频、输入格式等能力来自服务端模型/协议清单；没有声明时应明确不可用，不能让 UI 推测或把任意参数透传上游。
4. **可观察性与隐私**：记录 provider/model/protocol、失败阶段、用量字段是否齐全和计费来源；不记录 API key、签名 URL、音频/图片正文或用户剧本。
5. **迁移与回滚**：当前并行短剧实现涉及 schema v78；声音与造型应合并审查迁移顺序、SQLite/PostgreSQL 幂等性和旧数据默认值。数据库迁移不能随前端功能开关回滚。
6. **产品指标**：引用插入成功率、比例设置与请求一致率、短剧解析人工修正率、角色连续性缺陷率、Skills 推荐接受/误报率、cache token 计费差异率，分别作为上线后观察指标。

## 建议实施顺序

### 阶段 A：状态与计费正确性（P0）

- 1. Agent 计划继承/清理：先定继续与新目标语义，补后端状态迁移和前端空计划归约测试。
- 2. 全局 Agent 画布 scope：建立来源标签与切换时的历史/附件/缓存剥离合同；先解决串上下文风险。
- 3. Opus schema 与缓存计费：分别抓真实失败样例；先兼容协议，再扩计费字段，历史账单不重算。
- 4. 视频比例：按模型/节点状态复现，分离生成画幅和节点显示框，修复能力配置或节点同步。

### 阶段 B：合并并验收已在途短剧基础（P1）

- 5. 审查选章导入、预留章节和制作台 picker，重点验证事务、幂等、预算及 3000 章/字数上限边界。
- 6. 同审声音/造型模型和 v78 迁移；先完成真实账号短剧 MVP 验收，再将短剧长事务提交。
- 7. 优化待处理页布局，使用大数据集和窄屏验收。
- 8. 清理用户提示词偏好与隐藏个人模型配置，先完成 producer/consumer 清单和 UI/服务端 feature flag 对照。
- 9. 统一思考等级的语义与 adapter，优先覆盖聊天与 Agent 已支持协议。

### 阶段 C：导入和制作体验（P2）

- 10. 独立实现剧本解析预览确认；确定性解析先行，AI 仅补缺/归一化。
- 11. 高级设置折叠，先做创建页，再同步制作设置页。
- 12. 加入 Skills 辅助站位合同与分镜图确认，控制成本、允许跳过，完成基准镜头测试集。
- 13. 将主资产造型的成熟版本机制抽象到其他资产前，评估用户需求和迁移成本。

### 阶段 D：扩展和协作（P3）

- 14. Agent Skills 推荐 UI/埋点，复用现有召回；灰度验证误报和 token 成本。
- 15. 发布联盟贡献入口、任务池和插件样板，核心权限/账务路径明确 owner 审核。

## 验证与发布门槛

- **前端交互**：变更组件的单测/DOM 测试；类型检查、lint、build；关键 UI 在 1440px 与 390px、明暗主题、键盘焦点、Reduced Motion 下实测。不得以静态 mock 页面替代真实路由。
- **后端状态/权限**：专项 Go 单测；并发与幂等测试；涉及账号、资源、任务或账务时补 SQLite 与 PostgreSQL 集成路径。迁移验证覆盖空库、从 v77 升 v78 和重复启动。
- **模型协议**：用可存档脱敏 fixture 测 schema 生成、请求体与响应解析；每个协议一个合同测试。涉及新模型能力参数需真实模型最小冒烟，但密钥不进入测试夹具和日志。
