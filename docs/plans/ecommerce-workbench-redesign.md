# 电商创作体验改造方案

状态：产品与交互提案；产品代码尚未修改。

## 先明确电商页的价值

图片／视频工具箱已经能做白底图、模特上身、商品场景、开箱和环绕视频。电商页如果只换个名称再摆一套上传、模型和生成按钮，用户没有理由多学一个页面。

电商创作应主要解决：**围绕同一件商品，做出一套表达连贯、事实准确、可以逐张调整的商品内容。** 商品资料不必每轮重填，成品可以接着修改或制作视频，复杂套图有人帮忙规划。

基础生成操作沿用工具箱的用法；电商增加商品记忆、整套内容规划和逐张迭代。知识库、行业分类和 Skills 在背后帮助产出，不成为用户开工前需要理解的模块。

**布局保留用户明确要求：左侧方案／图片／视频结果，右侧当前创作与参数。去掉电商画布。** Opus 工具箱实际是左创作、右作品，本轮借鉴的是它的出现时机、场景联动和反馈方式，不将其方位当作用户已批准的替代方案。

## 从 Opus 重做的页面学什么

本轮打开了当前 `/toolbox/image` 和 `/toolbox/video`，实际查看场景库、选择场景后的素材要求、描述短语、模型规格、批次结果及大图预览。独立浏览器没有现有登录态，后续用隔离评审数据进入真实路由；所有业务请求拦截，没有读取个人账号或发起真实模型任务。页面组件和样式是真实实现，场景、模型、报价及任务为评审数据。

我之前的方案主要在列功能、拆模块和安排面板，遗漏了“用户为什么此刻要做这个选择”。工具箱更顺的原因可以归为三个取舍：

| 它作出的取舍 | 用户得到什么 | 电商如何沿用 |
| --- | --- | --- |
| 先讲成品用途，再讲参数 | 先判断“是不是我要做的东西”，再处理输入 | 用产品套图、详情页、模特上身等具体目标开始，模型放在需求之后。 |
| 选择场景会改变素材位和描述帮助 | 不用自己猜需要传哪张图、怎么写 | 服装场景问服装图与人物参考；视频场景问首帧与镜头动作。 |
| 生成与查看在同一处连续发生 | 发出以后知道去哪看，失败知道改哪里 | 在原位置呈现本轮方案、生成状态与成品，单张修改和下载就近完成。 |

图片的辅助词讲背景、光线、构图；视频讲运镜、节奏和氛围。它们都直接进入可编辑描述，用户知道自己选择了什么。报价与生成按钮位置稳定，预览只在查看成品时出现。

也有不应照搬的细节：实测已选服装场景后，作品空态仍提示“选择出品场景”；模型区域已有无模型提示，右下又出现引导浮层。新电商页应让下一步跟随当前状态，不重复指导，不遮作品。

## 首屏只服务当前这次创作

```text
┌────────────────────系统导航与顶栏─────────────────────┐
│ 电商创作                 当前商品 · 已保存    历史／新商品 │
├──────────────────────────────────┬────────────────────┤
│ 本轮方案与作品                   │ [图片] [视频]       │
│                                  │                     │
│ 首次：说明这里会得到什么         │ 这次做什么          │
│ 有方案：按页审阅画面与文案       │ [产品套图 · 更换]   │
│ 生成中：同位置呈现状态           │                     │
│ 完成后：看图、挑图、改图         │ 商品图与所需参考    │
│                                  │                     │
│ [01 主图] [02 场景] [03 细节]    │ 需求描述／场景短语  │
│ [04 卖点] [05 规格] [06 包装]    │                     │
│                                  │ 平台、语言、数量    │
│ 单张预览／修改／下载／制作视频   │ 模型与规格          │
│                                  ├────────────────────┤
│ 已有批次继续保留                 │ 本次费用＋明确动作  │
└──────────────────────────────────┴────────────────────┘
```

这不是一次摆满的表单。右栏围绕当前用途逐步呈现所需信息，左侧承接这次内容的变化。没有点阵、平移、图层或空间排布，也没有大角色欢迎卡和第二个悬浮聊天窗口。

- 初始可给一个清楚且可更换的默认用途，例如产品套图；熟手可直接写需求，不强制先逛场景库。
- “这次做什么”用成品名称表达。常用项可直接切换，其余进入场景库；每项解释产出和必需素材。
- 商品图始终容易找到。已有商品以缩略图和短摘要显示“本轮沿用”，完整资料按需展开。
- 需求描述是主要输入。平台、文字语言、风格和数量在影响当前成品时出现。
- 模型选择沿用系统标准交互；清晰度、画幅、视频时长按当前能力显示，问题在原位置解释。
- 底部只保留当前下一步及对应费用，例如“生成 3 个版本”或“规划这套详情页”；不用一个发送箭头承担不同含义。
- 历史是回看的入口，新商品是明确切换身份的动作；它们都不应先于首次创作成为主线。

## 两条具体使用旅程

### 第一次做服装上身图

| 时刻 | 用户看见什么 | 用户做什么 | 页面怎样回应 |
| --- | --- | --- | --- |
| 进入 | 当前用途和商品素材入口；结果区有简短说明 | 把用途换成“模特上身” | 显示服装图必填、人物参考可选，描述示例也随之改变。 |
| 准备素材 | 两个名称明确的素材位 | 上传平铺服装图 | 原位显示缩略图与上传状态；人物参考可留空，不再反复催用户选场景。 |
| 表达需求 | 可直接编辑的描述，少量姿势、背景、光线短语 | 写“自然站姿、暖色棚拍”，选择 3 个版本 | 所选内容在描述中可见；规格与报价对应当前设置。 |
| 生成前 | “生成 3 个版本”及本次预估费用 | 点击生成 | 左侧马上出现这批 3 个占位；右侧保留提交内容，允许准备下一次。 |
| 得到结果 | 3 张可比较的上身图及各自状态 | 打开其中一张 | 大图优先，附近给下载、修改和做成视频；关闭后原输入仍在。 |
| 有一张失败 | 两张成品和一张失败卡同时存在 | 只重试失败项 | 说明本次只处理这一项及费用，成功图保持不动。 |

这里不要求先建商品项目、填价格与包装、推荐四个方向、审阅逐页方案。任务只需要保真参考与用户的画面要求。

### 做详情套图，再只改第 3 张并制作视频

1. 用户选“详情页”，上传商品图，填写本次必须使用的卖点、目标平台和大致页数。尺寸、功效等事实不明确时，只问会影响本套内容的缺项。
2. 用户点击“规划这套详情页”。按钮明确说明这是策划费用；选风格本身只改变偏好，不启动策划或生图。
3. 左侧出现按阅读顺序排列的草案，每页先讲用途、画面和上图文案。用户能直接改字、调整顺序或删除；完整提示词按需查看。
4. 用户审阅后点击“生成这套 N 张”。显示本次图片费用，已付策划费用与待生成费用分开。每页保持位置，逐步由草案变成成品。
5. 用户打开第 3 张，选择“修改这张”，输入“标题分两行、保留商品、减少背景装饰”。右栏明确显示正在改第 3 张，可返回整套；原整套草稿保留。
6. 新结果成为第 3 张的候选版本，用户能比较新旧并决定采用哪张。其他页面不重做，原图不被静默覆盖。
7. 用户对已采用的图片点“制作视频”。右栏切到视频创作，该图进入首帧位；用户选环绕／推进等镜头、时长和规格，看到费用后生成。
8. 视频出现在当前商品下的新批次，带有来源图片关系。图片和视频都可回看；模式切换不清输入、不停止任务。

复杂套图中的 Agent 是一位可请求的策划者，价值在于分配内容、保持叙事和提出修改，不在于占据一个持续聊天舞台。

## 把容易用坏的细节提前定清

### 场景、素材与描述

- 换场景时先保留用户文字和上传素材。系统建议可替换或追加，用户写过的内容不直接覆盖。
- 素材不适配新用途时，告诉用户具体缺什么，不直接把人物、Logo 或竞品当商品身份。未参与生成的素材需明确标识，避免用户误以为全部都会使用。
- 上传中与失败状态留在对应素材位；失败可重试或移除，不把破图当成已就绪参考。
- 商品主图、风格参考和人物参考用任务语言命名；“图片模型”与“人物模特”清楚区分。
- 字体、品牌色、保真细节等按当前任务展开，不向所有人展示完整商品档案。

### 数量、费用与提交

- “3 个白底图版本”“8 页详情图”“2 条视频”分别表达，不用一个数字混合内容页数和变体数。
- 首次生成直接使用可见模型与设置。无模型、无报价时在相应位置说明和引导；不自动弹另一张教学卡。
- 普通选择和输入不产生策划费用。策划、图片与视频分别在提交前说明本次动作及价格。
- 提交期间避免重复点击；回执不确定时先查刚才请求，不能把网络慢变成再次付费。
- 已运行的任务保留提交时设置。右栏后来改模型或描述，只影响下一次提交。

### 作品、版本与返回

- 一个批次可同时有完成、生成中、保存中和失败项。进度缺少真实百分比时显示阶段，不制造虚假精度。
- 成品预览优先看作品。参数与文案作为上下文，下载、修改、复用和制作视频跟随所选作品出现。
- 多选只在批量动作时出现，操作前说明范围；不把所有卡片长期画成编辑表单。
- 单张重做产生候选版本，原作保留。详情页顺序是阅读顺序，不是画布坐标。
- 关闭预览、回历史、刷新或切模式后恢复原输入。恢复数据本身不触发策划、补交或重试。
- “新商品”明确更换商品事实；同一商品下一轮沿用资料，但用户的新需求优先，不清除旧批次。
- 手机采用“创作／作品”视图切换，保持同一份输入与当前批次；生成完成时给提示，不突然抢走正在输入的焦点。

## 后台：让管理员完成管理任务

将三个电商后台导航合为一个“电商创作管理”。合并目标是少跨页、看得懂实际效果，不是将三个长表拼在一起。

建议三个主标签，名称围绕管理员的问题：

| 标签 | 进入时先回答什么 | 日常操作 |
| --- | --- | --- |
| 使用设置 | 电商是否已开放？还差什么才能使用？ | 查看图片／视频及策划配置，补模型，检查配置，前往功能开放。 |
| 创作规则 | 哪些方法和材料会影响产出？有哪些待处理事项？ | 在方法、知识、来源之间关联查看，审核内容，启停方法，安装与更新。 |
| 品类适配 | 这个商品为什么会用这套方法？ | 搜品类、读继承路径，查看真实有效方法，预览匹配结果。 |

### 配好电商，准备开放

管理员先看到“已关闭／已开放”“可用／待补配置”和具体下一步。需要改模型时才进入识别、策划的选择；不以四个角色名称和多组下拉框作为首页。

当前工作台实际解析为商品识别和套图策划两个调用点，配置中另有总监／营销复用关系；未证实逐图执行独立质检。页面必须显示真正生效的选择，保留旧配置并明确映射，不将“选过质检模型”显示成“成品已通过质检”。

“检查配置”只检查可用性，不收费。付费试运行是另一个明确动作：选择样例、查看将运行什么及预计费用，再提交；检查通过、运行通过和人工看过成品是不同结果。

### 整理方法与审核资料

创作规则中分清“方法”和“参考知识”，并提供关联入口：方法说明怎么策划，知识说明依据什么。它们共享管理语境，不强行合成同一种内容。

- 方法列表显示名称、用途、适用品类、当前状态、来源和版本。打开后先看短说明和影响范围，再看完整正文及许可。
- 安装前可检查来源和摘要，明确选择是否启用；不是因为上传成功就默认已进入所有新任务。
- 更新先说明变化及影响，再应用。已提交任务使用当时版本，已有作品不回滚。自动更新作为明确可选行为。
- 知识默认优先待审核与异常项；打开正文阅读适用条件、来源、许可和有效期。原始结构数据放诊断，不作为主要阅读界面。
- 审核“采用／不采用”要有清楚反馈；理由与批量审核是需新增的能力，未实现前不画可用按钮。
- 来源停用、条目过期和审核未通过分别解释。分类字典节点数与创作知识量分开，不用大数字暗示生成效果。
- 同步后分别展示新增、重复、更新和失败。已有审核、停用及管理员修改不能被默默覆盖。

### 查某个品类的适配原因

管理员搜索“咖啡机”，先得到完整品类路径，打开后看“本级专属／继承上级／通用方法”及具体来源。方法停用时说明实际会退到哪里，并可打开该方法详情；不只给内部 ID 或“覆盖了多少节点”。

品类目录首版只读。匹配预览使用与实际创作相同的规则、不调用模型，解释为什么匹配；自定义覆盖与版本发布属于后续能力，不为了“管理感”添加假编辑按钮。

原三个 URL 进入新页面对应位置；搜索、筛选与返回位置保留。模型配置采用显式保存，启停采用即时反馈；保存失败仍显示上次生效状态。管理入口在普通用户功能关闭后仍可使用。

## 小夜：先去掉重复打扰，再决定帮助形式

建议撤下独立小夜角色、欢迎大卡、待机动效和第二个悬浮聊天窗口。用户已能使用全局创作 Agent，小夜目前没有清楚独立的任务价值；换一张更好的角色图也解决不了这个问题。

保留普通“帮助”入口：解释素材要求、常见操作与错误，链接产品文档，用户需要时打开。静态帮助免费，不占创作舞台。

如确实保留 AI 站内帮助，应主动开启、明确费用、只解释网站使用。推荐问题先填入输入框，由用户确认发送。帮助会话和创作会话分开，不把电商商品知识变成网站 FAQ，也不另做第三种通用聊天体验。

帮助配置管理内容、推荐问题、开放范围和服务模型；头像大小、屏幕坐标和动效退出主流程。旧设置保留，启停集中到功能开放页，不能两处独立控制。

已核实旧问答重试会重新创建收费任务，响应丢失时可能重复付费。撤下或重做入口前，需保留旧回执、任务及账单，并处理“已受理但回复未取回”的状态；移除窗口不等于删除历史。

## 功能开放：开关表达真实用户后果

在 `/admin/settings/features` 增加电商创作总开关、可用后的电商视频子项、独立的站内 AI 帮助开关。图片／视频继续遵守系统现有能力开放；知识、方法、分类不各造一个用户总开关。

新能力建议默认关闭，由管理员检查后开放；已有项目、配置与作品保留。电商管理和帮助设置只显示状态及跳转入口，功能开放页是唯一发布控制位置。

| 管理员关闭什么 | 用户会看到什么 | 继续保留什么 |
| --- | --- | --- |
| 电商创作 | 暂停新分析、策划、生成与收费重试；明确原因和返回入口 | 本人历史、作品、下载、已有草稿、任务状态与取消能力。 |
| 电商视频／系统视频 | 图片仍可继续；视频入口解释当前未开放 | 来源图片、视频草稿与已有视频。 |
| 站内 AI 帮助 | 不显示收费帮助与独立角色 | 静态指南和既有创作 Agent。 |

尚未发出上游调用的排队项在执行前检查，关闭时终止该次未执行调用并按现有规则释放预留；上游是否受理尚不确定时先核对，不能承诺已退款。已经提交的调用继续查询、保存与原订单结算；多阶段流程不再启动下一次新调用。重新开放不自动复活旧任务，由用户主动重新提交。

开关改变后新旧页面与直接入口表现一致。用户重新聚焦页面时同步状态；保存失败时管理员开关恢复服务端原状态。子项保留配置值，但清楚显示依赖关闭而未生效。

## 分批交付与验收

首批交付无画布图片主线、后台入口整合、小夜收敛及电商开关；视频首帧生成闭环作为接续交付。持久版本、规则候选发布、批量审核和多镜头成片分别按真实需求推进，不全塞进第一版。

验收先看操作预期，再看实现：

1. 首次不命名项目、不学画布、不填全商品表单，也能开始简单商品图。
2. 选服装、白底或环绕视频后，素材位、示例和下一步同步变化；已有选择不被空态重复要求。
3. 改场景不丢手写描述；点风格不产生收费任务；模板替换由用户决定。
4. 模型选择全站一致，数量语义清楚，提交前可见本次费用。
