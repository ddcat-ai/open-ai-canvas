## 1. 自研 UI 完整度现状（核实于 2026-09-06）

自研 Celadon UI 层位于 `web/src/components/ui/`，按 rollout 计划推进：

| 层 | 现状 | 说明 |
|---|---|---|
| base（基础原子） | 8 族完成 | buttons / badges / tooltip / select / switch / segmented-control / checkbox / kbd |
| product（业务复合） | 2 族 | 供页面直接消费的高阶形态 |
| application（应用场景块） | 未启动 | rollout 计划的 P3，Canvas AI 助手等高阶场景尚未组件化 |

主界面（Canvas 工作台 `web/src/pages/canvas/` 与 `web/src/components/canvas/`）自研组件消费处于**扩散中**：114 个 tsx 中 35 个已引用 `@/components/ui`（约 31%），但画布 AI 助手等高阶场景仍大量直接使用 AntD 原子或裸 Tailwind，应用层组件缺位。后台管理区（`web/src/pages/admin/`）是另一主要消费方，与画布主界面的「AI 优先」场景仍有落差。

**结论**：基础能力已可用，短板在「应用层组件」与「主界面消费率」。BoardUI 恰以 AI/agent 界面应用层组件见长，与影策画布 AI 助手场景天然互补，不是重复造轮子。

### 2.3 形态参考（不直接搬代码）

- 语义 token 命名/分层结构 → 校验本项目 Primitive/Semantic/Component 三层 token 是否对齐。
- 数据表格组件族（`react-aria-components` 实现）→ 作为后台表格后续脱离 AntD Table 的形态参考。
- 技术栈注意：BoardUI 基于 React Aria + Tailwind v4 + `motion`；本项目为 AntD + Tailwind（自研层替换中），**不引入 react-aria-components 与 motion 依赖**，仅吸收视觉形态与交互语义，落到现有栈。

## 3. 消费落地样板（本轮，可直接验证）

BoardUI 最典型消费场景是「数据变化时数字平滑滚动」。已在运营健康卡落地：

### 6.3 语义/结构备注（domain 对齐）

- 我方以“镜/分镜”为叙事单位（shot → message 分组），boardui 为 thread/message：吸收 UI 形态时保持我方语义命名（`creation-*`），不引 thread 术语。
- create 助手消息与 canvas 侧栏消息为两套视觉（主题化 inline style vs home CSS），若要同源需先抽无主题共享组件（已知中等重构，未立项）。
