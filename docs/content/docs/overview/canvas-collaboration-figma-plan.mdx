# 面向用户无感的画布协作方案

上游移植说明：本文保留原协作方案与调研过程；当前代码入口为 internal/canvas 领域层和 internal/app 组合根，API 客户端为 http，迁移接续 v30/v31。实际交付合同、跨账号媒体权限限制与本次验证见 [共享协作画布](./canvas-collaboration) 和 [待测试](../progress/pending-test)。原分支的测试数量/浏览器记录不等于本次上游验收。

本文是体验方案。标注“待完善”的能力不能作为已交付承诺。架构证据和实现对照见[实时协作调研](/docs/overview/canvas-collaboration-realtime)。

## 用户只需要编辑

普通模式与专注模式只使用“协作”这一名称。在线头像只在有成员状态时出现，不再额外显示一个空的“协作”按钮。独立方案顶部提供“返回来源画布”，适用于多层方案；用户无需手工提交、拉取或理解版本号。

信息分成三类：

| 信息 | 默认位置 | 触发方式 |
| --- | --- | --- |
| 谁在线、谁在输入/拖动 | 顶部头像、对应节点边框和光标 | 自动出现，超时消失 |
| 是否已同步、是否需要处理 | 轻量状态；有必要时打开当前画布弹窗 | 正常同步静默，失败或冲突才提示 |
| 独立方案 | 协作面板主体 | 点击新建才展开命名；创建后直接进入 |
| 历史记录、本机备份 | 协作面板底部次级入口 | 按需查看，不把备份数当成待处理数 |

在线光标和输入状态已与画布内容分离，但当前仍使用 HTTP 心跳/轮询。通过 WebSocket 连续更新光标、拖动临时预览是下一阶段工作。

协作面板顶部集中管理成员，公开分享窗口只提供预览链接。成员显示昵称、用户名及权限，不显示内部用户 ID；画布库通过“共享给我的”标明受邀关系。光标采用紧凑单行姓名，查看状态不追加文案，输入或移动时再展示动作。

## 当前编辑流程

1. 打开时读取服务端内容，检查本账号本画布是否存在未完成队列和草稿。
2. 输入与拖动先显示在本地，自动保存采用 150ms 防抖，持续编辑最多等待 500ms 进入调度。
3. 先在本地保存确切的操作请求，再提交；服务端回执成功才说明云端持久化成功。
4. 其他成员接收已提交的 WebSocket 增量，在原画布更新。缺口通过事件接口或完整快照修复，5 秒轮询作补偿。
5. 独立字段自动合并；真冲突保留草稿，进入当前画布的冲突处理流程。
6. 回执丢失或断网后，复用原操作身份和请求重试。磁盘保存失败时明确提示，不能声称草稿已经持久保存。

500ms 不含网络、媒体上传和先前请求排队。当前全局同步调度与逐项 REST 提交仍是性能限制。

## 冲突只让用户处理必要的内容

目标提示：

> 李四刚修改了“海边镜头”的提示词。你的内容已保留，请确认这段文字。

当前画布弹窗内展示“我的内容”和“最新内容”。默认只提供“采用最新内容”和“保留我的内容”；文字确需人工融合时允许编辑后确认，不让用户理解 JSON 或三方合并术语。

共同起点收在“查看修改前内容”中，供需要追溯时展开。确认前再次校验，其他人又改过时保留已有选择，并明确提示需要重新核对。

删除冲突使用不同文案：

> 李四删除了“海边镜头”。你的编辑还在，可以保存为一个新节点。

恢复是明确的公共内容变更。不能把“恢复我的草稿”悄悄变成对整张共享画布的恢复；优先让用户另存节点或创建独立方案。恢复当前共享内容时说明影响并留下活动记录。

## 自动合并边界

| 场景 | 当前行为 | 后续优化 |
| --- | --- | --- |
| 不同节点编辑 | 可独立合并 | 保持静默 |
| 同节点移动和改提示词 | 顶层字段可独立合并 | 保持静默 |
| metadata 内不同配置 | 仍可能按整体冲突 | 按提示词、生成配置、生成结果拆逻辑组 |
| 同字段不同内容 | 保留草稿并暂停该画布提交 | 只暂停冲突操作和依赖操作 |
| 同节点同时拖动 | 仍检查基线冲突 | 占用提示、实时预览，再评估位置最终顺序策略 |
| 独立连线并发修改 | 部分路径仍比较整个连线集合 | 连线按 ID 操作，结构依赖在服务端校验 |
| 删除与旧编辑 | 已删除对象拒绝旧修改 | 完善业务摘要和另存节点路径 |
| 复制新增节点组 | 新节点和相互连线原子创建 | 保持一组成功或失败，不扩称整个保存批次原子 |
| 生成任务回写 | 需完整路径验收 | 统一校验任务输入、节点生命周期和恢复边界 |

完整的协作撤销仍待完善。当前远端更新不进入我的撤销历史，重叠的旧撤销项保守失效，避免把其他人的后续修改覆盖掉。

## 多人怎样使用独立方案

日常共同编辑同一张画布，只有需要尝试不同创意方向时才创建独立方案。

1. 在“协作”的独立方案区点击“新建”，展开命名；创建前同步当前编辑，冲突或同步失败时保留表单并提示。
2. 输入业务名称，例如“海边婚礼”，创建真实的独立画布，并保留来源与共同起点。
3. 新方案可独立编辑和邀请成员；顶部始终可返回来源画布。
4. 点击“合并到这里”或“合并到来源”，默认目标为该方案的直接来源。弹窗显示源方案和接收画布名称；更换目标在弹窗中按需展开，无冲突时一个确认动作即可提交。更丰富的节点差异摘要仍待完善。
5. 有冲突时只处理需要选择的字段；主画布在正式提交前不变化。
6. 提交时服务端核对源方案与目标状态，旧预览不直接覆盖新的内容。
7. 合并完成后自动打开接收画布，原方案保留。当前编辑器立即接收提交后的版本，同实例在线成员收到重新同步通知。

接口补充：`GET /canvas-projects` 摘要返回 `collaborationEnabled` 与 `sharedWithMe`；后者表示当前用户通过成员关系获邀，不能仅根据开启协作或同部门可见推断。`GET /canvas-projects/:id/collaboration/members` 返回所有者及成员，并包含 `username`、`displayName` 和 `role`（`owner` / `editor` / `viewer`）。成员管理仍由服务端校验所有者权限。`POST /canvas-branches/:id/merge` 返回的 `project.revision` 与 `targetRevision` 一致，提交成功后向目标画布广播 `resync`；这些变更无需新增数据库字段或迁移。

多层方案在列表按来源缩进。界面必须明确“返回来源”和“合并目标”，不能把中间方案和最初主画布都叫主画布。跨画布或多层合并需要展示目标名称，并检查共同起点与节点身份；这些边界仍需专项验收，不能仅凭已有合并按钮视为完成。

## 验收

- 两个真实账号能在原画布内看到内容更新，视口、输入焦点和未提交内容保持稳定。
- 普通编辑不弹版本对话框；冲突只解释正在处理的节点和内容。
- 草稿保存失败可见，不能误报“已同步”或“不会丢失”。
- 断线、丢回执、重复点击后不重复创建节点，不悄悄复活已删除对象。
- 375px、768px 和桌面宽度均可完成分享、处理冲突、创建方案和返回来源。
- 毫秒级同步需要记录真实延迟分布；当前专项单元测试不能代替浏览器和 PostgreSQL 并发验收。
