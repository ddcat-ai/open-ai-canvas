# 共享协作画布与独立方案

协作以服务端画布为共同事实：本地编辑即时显示，REST 提交受校验的操作，WebSocket 通知已提交结果。独立方案是有独立 ID 和版本的持久画布，通过共同基线与来源或其他目标合并。

本次将定制分支的协作实现移植到上游画布领域层，保留分页读取、按需加载、Agent 同步和主题组件。跨账号媒体仍受资源所有者权限限制，本文不将它列为已完成的共享能力。

## 成员与入口

| 身份 | 能力 |
| --- | --- |
| 所有者 owner | 读取、编辑、恢复；搜索用户、邀请、调整角色和移除成员；删除自己的画布 |
| 编辑者 editor | 读取、协作操作、恢复历史、创建方案；有目标写权限时合并 |
| 查看者 viewer | 读取画布、历史及可见方案、查看在线状态；服务端拒绝编辑、恢复及创建/合并方案 |

画布库的分页接口包含个人与直接受邀画布，分别标记“协作”和“共享给我的”。普通模式和专注模式共用协作入口；成员、方案是主要内容，历史记录和本机备份是次级导航。公开分享保留独立的只读预览链接，成员邀请不等于公开分享。

权限按画布检查，不扩展到其他人的项目、任务、账单、素材库或资源。积分入口只统计当前用户在该画布的任务账单。

## 操作同步

自动保存采用 150ms 防抖、持续编辑最多 500ms 进入调度；它不代表网络或远端可见延迟保证。开启协作后拒绝普通全量自动保存，转为带 `opId`、`baseRevision`、字段变更前值和节点 `incarnation` 的操作。

| 操作 | 校验与原子范围 |
| --- | --- |
| create_nodes | ID 不碰撞，关联节点存续，节点组和连线在一次事务内创建 |
| update_node | 节点 incarnation 和被修改字段基线匹配；不覆盖无关字段 |
| delete_node / restore_delete | 生命周期、变更前内容和连线关系匹配；迟到请求不能复活旧节点 |
| update_connections | 连线集合基线和端点有效性；避免覆盖别人的关系修改 |
| update_canvas | 受允许的画布字段及其基线；业务项目关联另做归属检查 |
| restore_snapshot | 强校验当前 revision、快照访问与结构，更新生命周期并要求重新同步 |

服务端锁定画布，在事务内校验权限、修改结构、推进 revision 并保存请求/回执。幂等键为 `(canvas_id, actor_id, op_id)`，同键不同请求拒绝；事务成功后才广播。一个自动保存可能拆为多次 REST 操作，整个保存批次不保证一次性原子提交。

WebSocket 只承载已提交的通知。连续 revision 原地投影，消息缺口补拉事件或快照；恢复和合并通知 resync，5 秒轮询兜底。连接校验登录、画布访问和 Origin，发送前重新检查权限，包含 ping/pong、读写超时、消息上限和 Hub 溢出处理。

## 在线状态

presence 与内容版本分开：光标、视口和查看/输入/拖动/缩放状态不写画布历史。客户端约 120ms 合并发送、5 秒心跳、2.5 秒轮询；服务端状态 15 秒过期。离开画布取消请求并清理会话，坐标根据实时视口换算，姓名标签保持屏幕尺寸。

Redis 可共享 presence；正文 WebSocket Hub 仍在单实例内存中，多实例正文主要依靠后续补拉，未实现 Redis 内容广播。

## 草稿、重试和冲突

IndexedDB 按账号和画布保存共同基线、提交时内容、已确认内容、待提交原请求与阻塞状态，借助 Web Locks/进程队列串行写入。按需登录入口和全量快照入口都恢复未完成队列，不能把缓存草稿误当作服务端已确认内容。

丢失回执时重发相同请求；部分成功时只继续剩余请求；保存期间的新编辑在回执之上 rebase。草稿写入失败阻止替换当前编辑器内容。账号切换、加载过程中的编辑和视口变化沿用上游保护语义。

三方比较以共同起点、本机内容、远端内容为输入。不同节点/字段与相同最终值可自动合并；同字段不同结果、删除与编辑、同 ID 新增等需要人工确认。冲突保留本机内容并暂停该画布后续提交，其他画布可以继续同步。

界面提供快速处理和完整合并工作区，可选择本机/最新内容、展开修改前值、编辑文本、批量选择或下载草稿。提交时重新核对远端版本；旧回执不能把未解决冲突标为已同步。

## 独立方案与合并

创建前先同步当前画布，可从当前内容或仍保留的历史版本创建。创建者成为方案 owner，来源成员按原角色复制；来源 owner 在编辑者创建的方案中成为 editor。跨所有者创建会清除不属于创建者的业务项目关联。

方案有真实画布、独立 revision、来源和共同基线；支持多层方案、返回直接来源、继续编辑、归档。默认合并回来源，也可显式选择其他有编辑权限的目标。

预览只读计算基线、方案与目标的三方差异。正式合并要求双方预览 revision，锁定方案关系及两个画布，校验目标写权限和人工选择，通过 CAS 写入目标、历史快照及合并记录。保留目标 ID、所有者、业务关联与创建时间。

成功合并推进共同基线，保留方案供下次修改；重复请求返回已经提交的结果。前端将合并与自动保存串行，收到回执后保留期间新增编辑并打开接收画布，在线成员收到 resync。只有方案 owner 可归档；归档不删除画布，后续合并被拒绝。

## 历史与存储

数据库迁移接续为 v30/v31，添加协作开关、成员、节点生命周期、操作日志及方案关系；不改写上游 v1–v29 的迁移记录。历史快照和资源引用继续使用上游机制。普通协作操作写操作日志，不为每项操作生成完整历史快照；恢复和分支合并保留快照事务。

详见 [数据库合同](../backend/backend-database) 和 [HTTP API](../backend/http-api)。

## 已知限制与验收

- 跨账号媒体资源仍按原所有者鉴权：受邀者可以读取画布结构，但无法据此读取其他人的私有媒体、素材详情或将其直接用于生成；编辑者创建方案也不会复制媒体所有权。应在资源授权/复制协议完善后再宣称完整媒体协作。
- metadata 等部分对象仍按较粗粒度合并，部分连线操作校验全集；真实冲突暂停整张画布，提交路径保留全局串行队列。
- 远端内容不加入本人的撤销记录，重叠旧记录保守失效；未实现完整操作式协作撤销。
- 内容广播尚未跨实例；presence 的轮询、心跳不代表 Figma 的临时消息协议，也没有端到端毫秒级性能验收。
- 自动化测试不替代两个真实登录账号、媒体权限、PostgreSQL 并发、Nginx/外层代理和浏览器明暗主题/窄屏验收。本次未部署生产。

待验收项维护在 [待测试](../progress/pending-test)。产品与架构调研见 [实时协作对照](./canvas-collaboration-realtime) 和 [协作演进方案](./canvas-collaboration-figma-plan)。
