# 邀请奖励与提现

## 配置与入口

邀请、提现和余额划转默认关闭。管理员在“系统设置 → 邀请配置”（`/admin/settings/invite`）保存策略后启用，用户从“邀请与提现”（`/invite`）查看邀请码、邀请链接、余额及历史记录。

奖励仅来自通过现有支付渠道完成的充值商品订单，不包含订阅套餐。支持一级或二级邀请、通用奖励率、指定充值商品的奖励率覆盖、每名被邀请人的奖励次数及邀请人数上限。金额与比例使用整数存储，前端百分比只是显示方式。

被邀请人通过 `/register?invite=CODE` 的注册链接注册，页面把邀请码作为 `inviteCode` 提交；密码注册与 Linux.do 首次注册均可建立关系，已有账号再次登录不会修改原邀请关系。邀请码无效、功能关闭或人数耗尽不会绕过原有注册认证，也不会阻断一次合法注册。旧用户迁移后取得独立邀请码，不追溯补发历史充值奖励。

邀请功能关闭后不再新增关系或奖励，历史余额与记录保留。提现、划转各受自己的开关控制，以便管理员停止推广后继续处理存量余额。

## 邀请记录与审核

后台“用户与运营 → 邀请记录”（`/admin/invites`）支持状态、关键词、分页及详情，查看邀请人与奖励明细，并可通过、冻结、调整或解除邀请关系。所有管理员接口在服务层验证权限，普通用户不能读取或修改其他人的数据。

邀请审核开启时，新关系为 `pending`，充值奖励暂存冻结余额。通过后释放该关系的待审核奖励；冻结或解除关系会作废尚未入账的奖励，不倒扣已入账奖励。已冻结的关系不会继续获得充值奖励。

支付回调、主动查单和对账补单共用奖励入口。充值与奖励写入同一数据库事务，按订单与层级的引用键防止重复发奖；这不会为旧支付订单补造历史奖励。

修改审核开关同时处理存量关系：开启后，已通过关系重新进入待审核状态，原已入账奖励保留；关闭后，待审核关系通过并释放其冻结奖励。已冻结关系保持冻结。配置及所有管理员审核、关系调整和解除操作与管理员审计日志在同一事务内提交，审计写入失败则回滚。

## 奖励余额与划转

奖励单位为微元（1 元 = 1,000,000 微元），与账户的微积分分开。奖励账户始终满足：

```text
累计奖励 = 可用余额 + 冻结余额 + 已使用金额
```

用户按整数分申请提现或划转，分以下余额保留在奖励账户。“全部”按可用金额向下取整到分。划转的比例以千分数保存，最低划转金额和开关由管理员控制；扣减奖励、增加可用积分、写入 `invite_transfer` 积分流水在同一事务完成。

## 提现审核

管理员配置允许的微信、支付宝和银行卡方式、最低金额、每日次数及手续费。收款账户使用宿主已有 `.settings-key` 加密，列表不返回密文，只有本人常用账户和管理员提现详情可读取必要明文。备份和恢复数据库时必须一并保留原设置密钥。

提现提交将申请总金额从可用余额转入冻结余额，手续费包含在该总金额内，详情展示实际应付金额。后台“提现审核”（`/admin/withdrawals`）支持状态、方式、关键词和日期筛选。

- 审核中：状态 `0`，奖励仍冻结。
- 驳回：状态 `1`，必须填写原因，冻结金额回到可用余额。
- 成功：状态 `2`，管理员完成线下打款后确认，冻结金额转为已使用。

此功能只管理申请和审核账本，不调用微信、支付宝或银行代付接口。审核状态检查与资金移动在同一事务内完成，重复审核不能重复扣款或退款。

## 数据与接口

Schema 58 `invite_rewards` 在保留 1–57 迁移记录的基础上新增六张表：`invite_records`、`reward_accounts`、`invite_reward_records`、`withdraw_requests`、`withdraw_accounts`、`transfer_records`；为用户和 OAuth 状态增加邀请码，并回填旧用户。非空邀请码有部分唯一索引。

升级前备份数据库和 `.settings-key`，按既有流程执行 `migrate-schema up`、`verify` 后再启动新后端。回退到不支持 Schema 58 的旧二进制需要恢复匹配备份，不能只更换镜像。SQLite 和 PostgreSQL 使用同一业务合同，SQLite → PostgreSQL 工具同步包含新增表。

接口前缀均为 `/api`，完整字段见 `/api/openapi.yaml`：

| 路径                                                            | 权限与用途                         |
| --------------------------------------------------------------- | ---------------------------------- |
| `GET /invites/policy`                                           | 匿名可读的策略投影                 |
| `GET /invites/me/overview`                                      | 本人的邀请码、人数、余额与今日奖励 |
| `GET /invites/me/records`                                       | 本人的邀请记录分页                 |
| `GET/POST /invites/me/withdrawals`                              | 本人的提现历史与新申请             |
| `GET/PUT /invites/me/withdraw-account`                          | 本人的常用收款信息                 |
| `GET/POST /invites/me/transfers`                                | 本人的划转记录与新划转             |
| `GET/PATCH /admin/settings/invite`                              | 管理员策略读取与整体保存           |
| `GET /admin/invites`、`GET/PATCH/DELETE /admin/invites/:userId` | 管理员邀请列表、详情与关系管理     |
| `POST /admin/invites/:userId/approve`、`.../freeze`             | 管理员通过或冻结邀请               |
| `GET /admin/withdrawals`、`GET /admin/withdrawals/:id`          | 管理员提现列表与明文详情           |
| `POST /admin/withdrawals/:id/approve`、`.../reject`             | 管理员确认打款或驳回               |

列表支持 `page/pageSize`。提现管理的 `from/until` 为 `YYYY-MM-DD` 本地日期，包含开始日和结束日。请求金额 `amountFen` 是整数分；奖励响应为微元，二者不能直接比较。匿名调用登录态接口返回 401，普通用户调用管理员接口返回 403。
