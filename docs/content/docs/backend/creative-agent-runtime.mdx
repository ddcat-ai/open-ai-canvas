## 聚合交付、执行计划与重要信息

同轮图片按真实任务汇总，成功结果逐张展示；总数来自批次/计划元数据，不能按当前已返回 URL 的数量推断总数。多图堆叠和展开卡片统一方形居中裁切，单图保持自身画幅，点开大图和下载仍使用完整原图。资源使用稳定身份占位，地址补签或补存不会重排图片。

执行计划按创作阶段组织，例如锁定视觉方案、规划文案、生成最终图片；任务列表与阶段计划分别更新。完成项显示勾选及划线，未完成或失败的生成任务不会被标成全部完成，展开/收起由用户控制。重要信息由模型根据当前意图和方案决定是否展示，用于说明目标、规格、事实和逐图方案并接收补充；不要求每次普通问答或单图修改都生成该卡片。

多任务失败使用汇总错误和一个“重试失败项”入口，不把子任务进度和重复长错误串联展示。单任务保留经脱敏的上游诊断。历史恢复先复核原任务状态，避免先闪现缓存中的旧超时错误，再切换为当前状态；观察中断不等于生成失败，也不授权重建收费任务。

## 失败恢复与模型偏好

首页各模式共享稳定的 `/c/:id` 会话地址。链接要求登录原账号，支持刷新、前进后退和跨设备恢复；它不是公开分享链接。无权限、已删除或到期的会话明确报错，不用其他本地历史代替。空白新建仍使用首页，发送或打开历史后更新地址。

普通图片、视频和文本消息复用服务端会话检查点保存必要历史，原文和引用标签保留，生成结果按真实任务恢复。目录仅加载元数据，正文按打开读取；同一会话的保存串行、相同快照去重，已校验旧记录不重复查全部任务和附件。本地缓存与云端成功分开显示，离线同步失败可重试，不能据此再次提交收费生成。

历史抽屉显示实际生效的保留期限，管理员可跳转「资源与策略 → 历史会话保留天数」。0 表示长期保留，正数按最后活动时间计算；自动清理不终止活动任务，不删除任务、账务或媒体。媒体原件保留天数仍由独立存储策略决定。

首页失败按钮逐项核对原任务的归属、提交证据、账务和待保存结果。明确未受理且输入完整、生成设置未改变的图片或视频，直接恢复原提示词、参数和各自参考素材，不调用规划模型；成功项不重新生成。内容审核拒绝才要求调整提示词，不能把账号不可用、限流等服务故障误判成提示词问题。提交结果未知、已有供应商任务号或已有待保存作品时，先恢复或核对原任务，禁止直接生成第二份。

默认模型可选择「优先使用」或「固定模型」，分别保存图片和视频偏好。优先使用允许在明确拒绝且未创建上游任务时，先尝试等价渠道、再尝试同类型兼容型号；固定模型只允许等价前台型号渠道。首次报价时所选模型不支持当前素材或规格，也会在剩余预算内挑选兼容型号，并将实际选择与费用固定到审批方案，批准或恢复时不偷偷改回原型号。素材、画幅、质量、时长等硬约束不降低，内容审核拒绝不通过自动换模型处理。运行中切换最多三次线路尝试，不提高原单项授权金额；用户明确点击重试时重新报价，可以在原轮剩余预算内选择较贵候选。逻辑模型仍使用其配置的路由。

重试共享原轮剩余积分，已结算按实际扣费、退款按零、未结算按保守预占计算；同源兄弟和嵌套重试不获得新的整份预算。自动模式直接按授权提交；请求审批模式审核实际待重试项与报价，报价过期可刷新。重启和重复批准继续使用相同任务身份，提交事务再次核对原任务及账务。

## 智能创作个人记忆

首页复用画布 Agent 的账号私有记忆链路，分类固定为 `smart_creation`（智能创作）。新轮次和运行时提示只附已批准记忆的标题、适用场景；`recall_lessons` 按需读取全文。索引、按 topic 读取、关键词搜索和分类检索均由服务端限制当前账号和入口；首页不召回画布记忆，画布不召回智能创作记忆。记忆不是指令或授权，当前用户需求、模型能力和计费校验始终优先。

`remember_lesson` 只在本轮已有真实成功的媒体任务时记录通用做法，运行中、失败任务和只读查询不算首页成功交付。新记录先待审，用户在「设置 → Agent 记忆」批准后才进入后续索引；自动生成权限不等于批准记忆。已有导入、导出及压缩继续复用，压缩的服务端校验禁止将智能创作与画布用途互相改类或合并，不修改技能全文或自动学习商品事实。

## 独立图片的批量提交

首页提供通用 `generate_image_batch`，不要求加载电商工作流。模型先规划完整的 `items`（每项唯一 ID、标题、提示词、素材映射），通过一次工具调用提交 2–20 张独立图片。续轮“把上面的五张全部换成中文/另一种风格”先精读五张历史成品，再分别把各自原图放入该项参考；已就绪历史图不构成前后依赖。只有依赖本轮新成品的操作才分阶段执行。

批次在首项收费前统一检查所有图片的模型、原图归属、规格、真实报价和累计预算。自动模式直接提交，请求审批模式对冻结的提示词、素材和总报价整批批准一次，过期报价重新展示。每张仍通过原生成准入和账务事务独立入队，固定 `n=1`；已受理项使用稳定任务 ID 恢复，不因重复回调重新计费。通用批次复用原有准备态和审批账本，不创建虚构的电商事实或电商方案。

活动任务额度是同时排队和执行的上限，不是整套图片的数量上限。通用图片批次和电商套图先填满当前可用名额，名额不足时保存剩余项并等待；同账号其他任务释放名额后继续提交，不重走规划、不推进工具游标、不提高额度。即使首项还未受理，也能从持久检查点恢复等待。报价到期、预算不足和权限错误仍明确返回，不能借等待机制自动续期审批。取消只停止尚未受理项。

电商 `text` 交付项使用 `targetCopy` 保存已规划好的实际文案，不为它创建图片或视频任务；`prompt` 和审核译文不能代替文字产物。依赖文字的图片会把已完成的文案纳入冻结提示词，文字自身的前置依赖也必须完成。缺少实际文案或前置内容未完成时明确报错，不静默跳过并将整套标为完成。

`plan_updated` 与 `generation_task_created` 携带服务端确认的 `imageBatchId/imageBatchTotal`，单项另含 `imageBatchItemId`。首张任务刚受理时前端即可显示整批 `0/5`，随后按真实完成任务更新 `1/5…5/5`；简洁摘要、刷新恢复及跨设备加载沿用同一总数。尚未提交、生成中和失败均不计为成功，成功图仍逐张可查看和下载。

同一模型响应连续声明多个独立的 `generate_media` 图片调用时，仍按顺序执行原有参数、素材、报价、预算与审批准入；前序调用在任务和计费回执原子落库后返回 `taskSubmitted: true`，继续受理其余图片，不等待前一张生成。每项数量固定为 1，避免手动总数量与交付项重复相乘。最后一项等待本组真实终态，并在 `batchResults` 中附带前序任务状态；已完成图片仍通过现有任务观察逐张交付。

待交付任务 ID 保存在运行检查点的 `creationPendingImages`，只允许属于本轮任务历史的独立图片。若后续调用在准入前失败，下一模型步骤先核对前序已受理任务，保留结果，不重复提交或扣费。审批模式只受理已实际批准的调用；商品套图的 `commerce_plan_submit` 继续采用整套一次审批、无依赖项统一入队的执行路径。依赖前项成品的编辑或母版生成仍等待真实资源，画布工具不改为并发执行。

停止 Agent 仍只停止后续编排，已经受理的本组图片继续生成和正常计费，归入原会话。重启、重复回调与断线恢复使用持久回执和原任务 ID，不把 `queued` 或 `running` 当作生成完成。

## 同一会话继续创作

首页 `ask_user` 区分 `preference`、`ambiguous_target`、`missing_required_input` 和 `conflicting_requirements`。自动执行中的普通偏好问题返回 `phase: defaulted`，继续编排、不展示等待表单，也不计入确认轮次；缺省分类同样继续，要求模型确有阻塞时再明确分类。后三类必须说明 `blockingDetail`，仍可暂停确认真实歧义。未知但可省略的商品规格、已明确的上图语言、字体配色与模型参数映射不能作为阻塞理由。该返回不是用户回答，不扩大权限或收费预算。

图片参数在准入和 worker 共用规则：模型关闭分辨率参数但明确支持像素值时，默认尺寸档只用于解析比例，不拒绝枚举内的其他像素。像素型模型可将比例映射为同等比例的声明尺寸，优先同等比例默认值，否则选择最小匹配像素，并按所选值真实报价；没有同等比例候选时不静默改画幅。显式分辨率限制、手动参数和审批预算继续校验，图片质量不充当分辨率。

完整 商品视觉设计按商品图片意图读取，Amazon 只是一个适用分支。自动模式仍完成产品事实、母版、逐图设计和报价，但不等待字体、文案对照或事实表审核；请求审批模式才等待整套审批。首页只使用智能创作个人记忆；账号偏好、有限参数纠错与待批准的经验不是递归自学习，不会自动改写技能或把推测的商品事实保存为经验。

首页 Composer 原生集成 Agent、图片和视频模式。Agent 使用 `surface: creation` 的服务端会话，不借用画布，也不依赖独立“智能创作”插件。保留文本理解模型、图片/视频模型偏好、简洁/详细输出、权限、预算和方案审批；套图按已确认方案中的交付项执行。

提交入口先读取服务端会话，核对上一轮的归属和真实状态，再决定能否继续。浏览器缓存的 `running` 不能直接拒绝下一轮；服务端仍在执行或等待审批时保留草稿并提示处理当前轮次。请求仍使用持久幂等键，状态不明时先恢复记录，不能自动重复创建收费任务。

本轮新请求被服务端明确拒绝创建时，清理对应账号、会话和请求标识的待确认记录，保留草稿与原错误，允许修改模型、预算或提示词后再次提交。超时、连接中断及已有结果未知的请求继续保留原请求正文和标识；自动重试中曾发生结果不明，也不能因末次拒绝而放弃原身份。已取得接收回执但本地清理失败时按已提交处理，避免再次收费。

提交锁只允许持有当前令牌的请求释放；失败也会释放，旧轮的异步收尾不能解开新轮的锁。服务端运行版本 `revision` 优先于浏览器本地时间，实时快照同步版本和清理状态，避免本机时钟差异把完成状态覆盖回旧缓存。

Agent 编排运行时，首页分别提供发送补充说明和停止按钮。纯文字补充复用画布的插话入口，在当前轮下一次模型调用前送达；等待审批时排队，不自动批准。修改模型与偏好在下一轮生效，带附件的草稿保留到本轮结束或停止后再发送。插话先持久化消息身份，回执不明时查询并复用原身份，不另建收费轮次；未送达会明确显示。

首页停止只取消对话编排和未提交的后续步骤；已经提交的图片、视频任务（包括排队任务）继续正常生成、按真实结果计费并交付原会话。服务端确认编排清理完成后，可保留输入草稿并在同一会话发送新需求，不必等待媒体完成。中止或失败轮次的状态进入续轮上下文，未配对的原生工具调用仅核对既有回执或补充真实终态，不执行旧调用、不推断退款、不重新提交旧生成任务。

历史目录只请求会话标题与时间，点击某个标题才读取该会话的轮次、事件和图片。失败可重试该会话；连续切换、关闭抽屉、新建会话或切换账号会撤销旧读取，晚到结果不能切走当前草稿。任务恢复只观察当前打开的会话，目录排序使用真实会话和消息时间，不以本地缓存图片的时间为准。

批次恢复按任务 ID 汇总完整状态，而不是只用最后一条订阅事件，也不从当前出现了几张图片推断任务是否结束。成功、失败和取消均可收敛本轮消息；未知状态保留查询语义，不能直接断言 Agent 仍在运行或自动重新提交收费任务。

普通图片/视频消息即使曾因观察中断显示失败，也继续按原任务 ID 恢复。成功结果走正式素材物化；保存暂不可用不计为生成失败。页面卸载只停止观察，主动取消保持取消状态。点击“重新生成”先复核原任务：已成功则恢复结果，仍在执行或结果可恢复则等待，查询不可用时不创建另一个任务。

## 流式展示与会话缓存

正文增量、Agent 编排和媒体任务分别记录状态。只有尚未确认结束的正文使用流式展示；助手正文结束后保持静态，已受理图片和视频继续按真实任务状态更新。工具活动及审批提示来自实际事件，不把整轮运行时间当作正文正在输出，也不展示内部推理。运行期间不自动折叠正在阅读的正文。

当前轮的流事件只重新投影该轮，保留历史消息和已经恢复的媒体结果；旧轮事件、乱序事件及缺少上下文的恢复仍走完整合并。恢复会话时最多同时读取 4 个运行；快照已有从 1 连续到服务端 `eventCount` 的完整事件时直接复用，否则从连续前缀补读并检查缺口。任务状态仍独立复核，不能用缓存或减少查询的目标掩盖漏失的交付。

普通流式快照按账号合并待写内容，采用 200ms 固定窗口；持续输出不会无限推迟写入。任务绑定、结果消费、审批及终态等关键操作立即进入有序保存队列，显式等待保存的调用仍等到实际写入完成。页面离开时发起刷新待写队列，但不把浏览器退出当作写入成功；账号切换不合并不同账号的快照，迟到流事件不能更新新账号。

Gemini 原生 Agent 通过 `streamGenerateContent?alt=sse` 接收真实文本增量，继续使用原渠道鉴权、请求正文与缓存失效恢复逻辑。隐藏思考块不进入可见回复，工具调用保留原结构与签名；流提前结束、工具参数不完整或供应商拒绝不当作成功完成，也不执行未完整接收的工具调用。

## 对话压缩与资源身份

首页运行使用服务端检查点保留最新用户原话、方案、交付项、素材角色和任务事实。压缩后的模型输入与界面完整历史分开；历史方案只供延续，不构成重新生成的授权。未完成占位文案不作为已经发生的创作事实。

首页 Agent 支持只发送本轮主动上传的媒体，消息保留真实空文字，不补造“生成图片”等用户指令。连续对话由模型结合有效历史理解：用户明确约定后续收到商品图就按指定平台、站点、数量和比例制作时，纯图片或图片加站点可以延续约定；局部修改只覆盖有关条件。仅设定角色、说稍后发图或没有明确用途的上传，不视为立即生成请求。

切换话题后停止应用无关约束；换产品重新读取本轮素材，不继承旧产品外观、卖点或图片。历史图片仍按意图静默精读，不回填本轮附件。原生运行时及检查点压缩保留约定的适用条件、覆盖与撤销；再次压缩时，当前素材和方案事实取自本轮运行，不能被旧检查点覆盖。模型判断不增加权限、预算或审批授权，也不把已经完成的任务重新加入待办。

新上传本身不表示换产品。它可以补充细节、提供风格/构图参考，或与前文成品组合；模型需要结合历史和实际画面决定素材关系。相关历史成品与本轮附件可以同时作为明确选中的生成参考，用户消息仍只显示本轮主动上传。无法可靠判断且会影响结果时，只询问这处关系。

图片跨轮引用使用稳定的 `resource:` 身份，并保留消息、图片序号及可用的任务关联。带签名的展示 URL 不作为长期身份或历史执行事实；会话界面中的完整历史与发送给模型的压缩上下文分别处理。

图片、视频模式的已发送历史通过稳定消息身份导入原生会话。服务端根据真实原生分支返回导入收据，浏览器后续只发送新增消息；重复请求不会重复追加相同正文，任务状态仍独立从所属用户的服务端记录更新。已被原生压缩的历史继续使用摘要，不重新塞回旧全文，也不按最近 20 条或固定字数静默截掉用户约定。

云端画布 Agent 的检查点同样以最新用户意图为当前工作，按任务 ID 折叠服务端事件。任务成功、失败或取消后从待办移除；旧检查点中不能证实的提交记录只标记为待查询，不继续声称正在执行。

## 本轮参考图选择

普通对话和创作默认只提供通用工具；模型根据用户目标调用 `load_creation_workflow` 选择电商创作，或主动成功读取已启用的 商品视觉设计入口后，后续模型请求才展示电商整套工具。读取技能目录、无效路径、其他技能或仅上传图片不启用该工作流，也不额外注入电商规则正文。不会根据简单关键词自动套用亚马逊流程。“一只猫、一只狗”未说明同框还是各一张时，先询问；明确各一张、同框或数量后按该要求执行。

用户明确需要商品主图、营销图、详情、SKU、套图或继续修改商品图时，Agent 从当前账号已添加且启用的技能索引中主动读取完整的 **商品视觉设计**，无需手动 @。正文保留产品事实、母版、整套风格锁定、逐图设计、审批与质检方法，并按实际平台及用途应用；Amazon 规则只用于对应分支。单图不会因此扩成套图。上传产品照片、提到平台或历史做过商品图本身不触发读取；若前文有仍适用的后续创作约定，则由模型结合本轮输入决定延续。普通创作只收到轻量索引。`skill_read_file` 有后续页时继续读取，同一上下文已有完整同版本正文则复用；工作流摘要不能替代完整技能。

商品方案保留用户指定的平台与经营模式，`platform` 为有限长度的自由文本，支持 TEMU 全托管、国内平台、独立站等，不再依赖平台白名单。每张图片独立计入交付项；“8 张套图 + 3 张颜色 SKU 图”对应 11 项，SKU 分别使用对应颜色素材，每项数量固定为 1，不与 Composer 的手动数量相乘。平台规则仅按匹配的官方来源目录提供，不能将其他平台规则或模型推断当成该平台规范。

`site`、`language` 未提供时记录为 `UNKNOWN`、`und`，无字图不要求补齐站点和语言。逐图 `design` 和共享 `styleLock` 按用途选用；用途、版式不限枚举，不再强制四张图必须包含三种版式。SKU、颜色或语言变体可以保持统一构图，纯商品图不用强行增加文字或字体。已提供的结构、素材归属、事实来源、报价、预算和审批仍执行校验。

- 新轮附件默认 `replace`，无新附件时保持为空；只有显式 `inherit/append` 才继承或追加。历史素材通过按意图查询使用，不自动放回上传区。
- 素材保留商品、竞品、风格、人物等用途角色；角色不赋予额外访问权限。Agent 的用途角色与供应商的首尾帧参数分别处理，不能直接互传。
- 计划中的素材 ID 必须来自当前有效授权集合，每项交付分别声明使用的素材与用途；不可用、越权或与用户指定角色矛盾的引用明确失败。
- 已生成图片保留为历史交付事实，不自动当作下一轮的全部输入。更换素材或用途时，原计划和审批仍需重新校验。
- 编辑重发恢复该消息的参考内容与生成参数，不从当前 Composer 临时状态猜测旧请求。

`creation_media_read` 默认返回本会话媒体任务及历史上传的轻量元数据目录，包含已带入本会话的普通图片/视频任务，不能只列 Agent 交付。生成成品以 `taskId/outputIndex` 精读；历史上传以 `runId/resourceId` 精读，普通模式历史则以当前 `creationContext.resourceIds` 内的 `resourceId` 精读。任务按 `offset` 分页，历史上传按 `beforeRunId` 分页；目录中的不可用旧素材不会阻塞无关的新创作，精读时强校验就绪状态和来源。任务序号和任务内成品序号分开，定位“第几张”须结合用户指定轮次。按内容定位先读候选图，存在多个合理目标时澄清。

普通生图与 Agent 对话共享页面，但原生 Agent 分支末尾不一定是用户刚看到的成品。前端以实际可见卡片顺序提交 `latestVisibleResult`，聚合多图保留完整任务组；后端核验归属后，把真实成品身份作为独立的 `conversationPosition` 注入本轮。模型结合本轮文字、附件和该位置解释“上面这张图”，再精读对应像素；明确指定更早图片或换题时不强制使用最新图。该位置不替代完整历史、不改写原生会话，也不把历史图回填为本轮附件。

最近精读的图片优先占用对话模型的看图容量，剩余容量再提供其他当前素材；当前上传图也可按 `resourceId` 重新精读。数量受限时可分步轮换查看旧成品和新素材，实际附图结果通过 `visualInputStatus` 返回，不能把只有元数据的资源当作已看过。轮换不改变素材编号、消息附件或生成引用；最终生成仍使用明确选中的素材，并按生成模型能力独立校验。

首页识图沿用资源原件及对话模型声明的图片数量、大小限制，不额外强制缩图。当前上传与本轮明确精读的图片关联原生会话条目；对应条目仍在有效上下文时，后续模型步骤继续收到实际像素。不能仅凭一次模型调用成功就认定视觉事实已经保存。

独立 Agent 根据原生有效分支及 SDK 转换结果声明当前输入的位置 `currentTurnContextIndex`；压缩后该条目不在上下文时为 `-1`。后端把当前图片放回该条输入，精读图片放在对应的完整工具回执组后，后续生成成功记录仍排在其后，不把旧图追加为最新用户消息。身份不由用户可伪造的文字前缀决定。发布时同步更新后端与独立 Agent；声明缺失、类型或位置无效时在模型任务创建前明确拒绝，避免静默漏传或错放图片。

压缩移除相关条目后，历史目录及已保留的观察仍可帮助定位；需要重新观察细节时可以再次精读。新轮不自动附送上轮全部图片，由模型按当前意图查询所需资源。上述机制保证图片实际送达与来源可查，不能保证模型每次正确识别内容或选择引用。

新轮附件默认 `replace`，只保留本条主动选择的素材；历史上下文与附件分开保存。精读选择独立写入运行检查点，后台供模型理解和明确引用，不写回 `Request.Attachments`，不展示为新消息附件。生成工具仍须显式填写 `attachmentResourceIds` 和素材用途；查看过的图不自动加入无参考的新创作。资源、任务及历史来源在每次准入时重新核对用户及会话归属。

已生成合照中的局部替换使用该原图作为 `source`，提示词明确保留其他主体、背景与构图；只修改文字方案时更新方案，不无授权执行图片生成。模型实际像素保持效果仍需真实渠道验收。

同轮媒体失败只展示一个“重试失败项”，提交结构化 `retry: { runId, taskIds }`；单项仍可使用 `taskId`，两者不能混用，批量上限为 20 个不重复任务。点击后先查询真实状态，再一次提交仍失败的项，处理中禁用入口；不覆盖当前草稿或插入固定重试指令消息。服务端逐项限定同用户、同会话、同轮次、已失败且没有待恢复产物，任一目标不满足则拒绝创建重试轮次。每项恢复自己的原素材映射，排除已成功、仍在执行、已停止及有待恢复产物的任务。电商交付沿用原计划和交付项重试，不改写同版本计划。

图片堆叠、部分成功展示和按方案顺序命名继续保留。单图和整批 ZIP 均由浏览器读取原件并保存；并发、容量与 CORS 回退边界见[浏览器媒体处理](/docs/backend/browser-media)。

## 模型请求大小与技能读取

Agent 在资源水合和供应商协议序列化之后记录实际 HTTP 请求正文的字节数，便于定位图片输入或上下文造成的体积增长，不额外设置请求正文总量阈值。诊断只记录任务 ID 和请求字节数，不记录正文、密钥或媒体地址。

后端传给独立 Pi 进程的技能清单仅保留名称、启用状态、说明、版本和哈希，不附上未被该进程使用的全部正文与文件。模型仍收到系统策略中的技能索引，完整正文通过技能工具按需读取。此优化减少内部 RPC 体积，不等于消除了模型请求中的技能索引，也不改变技能启用及权限校验。

## 画布 Agent 审批与运行时

Pi 运行时遇到持久化审批时暂停，不额外请求模型，也不把等待审批误报为失败。其他真实模型错误仍按失败处理。同批工具审批按顺序接续，并使用真实执行回执替换延期占位；批准一项不等于自动批准其他项。

`canvas_apply_ops` 更新不存在的节点时返回可修正的字段错误 `ops[i].id / not_found`，模型可重新读取画布并使用真实节点 ID。错误批次不执行部分写入；锁定节点、不支持的节点类型及权限问题仍按原边界拒绝。连续三次无效操作沿用工具纠错上限终止，中间读取画布不会重置额度；修正参数后仍需满足当前审批规则。

审批卡片修改媒体设置时只回传决策接口允许的模型、尺寸、分辨率、声明式图片参数、质量、时长和视频开关；提示词及引用节点由服务端持有，不随设置对象展开回传。

SDK 在调用宿主工具前拒绝参数时，以当前模型步骤声明的 `PiModelCalls` 核对调用并回填失败，不使用上一工具的宿主游标。工具调用 ID 的去重限定在当前批次，避免供应商跨步骤复用 ID 时把本轮调用误认成已经执行。模型能力、参考资源、价格、预算、权限和审批规格仍由宿主重新校验。

## 账号创作偏好

首页模式、默认模型、图片/视频参数、输出方式和 Agent 权限及预算通过账号偏好 API 保存。切换浏览器读取同一账号值，字段补丁按账号串行合并，避免其他设备的独立设置被整个对象覆盖。首次使用将原浏览器的小型偏好迁入账号；临时离线时保留按账号隔离的待保存字段，重新连接或返回页面后同步，界面区分保存中、已保存和未同步。

刷新读取与保存串行执行。读取期间的本地编辑保持为待保存字段，旧快照返回后先合并本地变更，再提交补丁，防止已保存的新值被较早的读取响应覆盖。已完成初始化的会话遇到刷新失败时仍可尝试保存本地修改；首次读取失败则保留待同步状态，重连后继续。

输入草稿、活动会话、素材文件、原始 `imageParameters` 和 API Key 不进入此云端偏好。切换账号会停止旧同步，迟到响应不能覆盖新账号，服务端另行核对请求声明的账号与登录身份。偏好值不能替代模型能力、任务权限或预算准入。

运行中插话的来源标记按已送达内容的指纹恢复，文本字符串和 Pi 的结构化文本块均可识别。最终回答边界仍有插话时，由持有运行锁的循环继续执行；达到步骤上限则明确退回，不静默丢弃或另开重复任务。

## 验收边界

定向回归与编译不等于真实模型效果验收。登录态仍需确认：同一会话完成一套后继续下一套；新商品图替换旧参考；明确选择上一轮某张图修改；讨论、取消和审批等待不触发重复生成；刷新或断线后恢复真实批次状态。需要真实收费渠道的验收由部署者在可控环境执行。
