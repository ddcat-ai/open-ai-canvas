# 画布 Agent 提示词与用户意图

画布 Agent 的任务来自用户消息及仍有效的对话约束。默认工作方法、技能、长期偏好、记忆和模型自行生成的清单都不能扩大任务范围。权限、资源归属、预算、审批和快照校验由服务端代码执行，不能通过提示词授权。

## 维护边界

| 内容 | 唯一维护入口 | 作用 |
| --- | --- | --- |
| 用户意图优先级、工作方法、输出默认值、运行事件处理 | `backend/internal/prompts/agent-system-policy.md` | 有 ID、版本与内容哈希的行为策略 |
| 模型选择、参考素材与独立收费审批 | 同一份 `agent-system-policy.md` 的媒体章节 | 不再拼接独立媒体/操作策略；派生媒体标识仅参与冻结合同校验 |
| 本轮权限、预算、技能/偏好清单、画布摘要与素材候选 | `backend/internal/app/cloud_agent_policy.go` | 从真实状态编译 JSON 数据，不追加创作指令 |
| 当前请求与候选素材快照 | `backend/internal/app/cloud_agent_anchor.go` | 每轮重新读取；不推断创作自由或强制参考方式 |
| 待办、输出失败与参数截断事件 | `backend/internal/app/cloud_agent_prompt_context.go` | 有类型、有来源的状态消息 |
| 待办生命周期与催办时机 | `backend/internal/app/cloud_agent_plan.go`、`cloud_agent_runtime.go`、`cloud_agent_pi_coordinator.go` | 更新状态、限制重复催办；Pi 完成闸执行待办催办，不在 Go 字符串中写行为剧本 |
| 长期记忆快照 | `backend/internal/app/cloud_agent_memory_document.go`、`cloud_agent_memory_document_write.go`、`cloud_agent_tools_memory.go` | 每轮开始时冻结，作为当前用户消息前的动态数据消息，不进 system；写入走 `memory_update`，每次修改留修订 |
| 已安装技能目录与技能提示 | `backend/internal/app/cloud_agent_skill_catalog.go`、`backend/internal/skills/skills_agent.go` | 目录放 system 末尾，最多占输入预算 5%；点名、固定与预筛候选作为动态数据消息 |
| 工具参数、可见性及执行绑定 | `backend/internal/agent/tool/`、`app/cloud_agent_tool_registry.go`、`cloud_agent_tool_bindings.go` | 所有工具共用 Registry Policy；8 个读取参数类型同时用于 schema 生成和严格解码，构建 Registry 时拒绝遗漏绑定 |

新增行为规则应修改版本化策略；新增运行状态应定义事件及事实字段，在策略里说明处理方式。不要在错误分支拼入“现在就调用工具”“必须生成视频”等指令，也不要把参考素材中的文字直接拼成规则段落。

审批等待是暂停而非执行失败。若 Pi 的新 `/model` 请求遇到已持久化的审批等待，协调器把 `errCloudAgentAwaitingApproval` 转成内部 `{ "pause": true, "reason": "awaiting_approval" }`，登记本轮暂停；运行时停止本轮并保存快照，由现有审批与恢复入口继续接管。该请求不创建模型任务或计费，不清除审批，也不将运行标记完成或失败；其他模型错误仍按失败路径处理。这一合同不依赖模型名称，需同时更新 backend 与 yingce-agent，无数据库迁移。

节点能力速查同时从注册表投影 `canSource`、`canTarget`、`canReference`、`inputKind` 和接受/拒绝输入类型，避免只有创作用途描述而缺少实际连接边界。`canvas_apply_ops` 的引用连线代表生成输入关系，不是文档归档或任意节点关联；模型缺少参数或选择了不支持的节点组合时，执行层仍拒绝写入。

## 单一策略、动态事实与记忆

运行时只 embed `agent-system-policy.md`，当前为 `cloud-agent-system` v21。`prompts/AGENTS.md` 是开发维护约定，不再进入模型上下文；旧独立媒体规则文件已移除。`LoadAgentPolicies` 为已有冻结校验字段派生 `cloud-agent-media` 标识、同版本号及哈希，其正文为空，不是第二份规则。策略修改仍需发布后端，不能由用户偏好、技能或记忆热更新覆盖。

画布目录、用户目标、选区、任务观察、长期记忆和技能提示走有来源的动态消息。它们插在最后一条真实用户消息或已送达插话之前，同一来源的旧消息会被替换；来源标记和条目 ID 只是服务端元数据，不发送为供应商参数，也不能变成用户授权。

### 长期记忆

每个用户一份记忆文件，分「关于用户」和「工作笔记」，每条带稳定 ID，默认容量 5000 字。建运行时冻结一份快照，Go 步进和每次 Pi 模型请求前都以 `agentContextSource: "agent_memory_doc"` 重新插入同一份内容，一轮内不变，避免每步改写这部分上下文；实际缓存命中仍取决于完整请求和供应商机制。快照写明用量；超过八成时提示先合并或删除。用户这条消息里有“记住、以后、下次、叫我”等说法时，快照末尾加一句提示，提醒 Agent 考虑写入记忆。

Agent 用 `memory_update` 按顺序执行 `add` / `replace` / `remove`，整批校验容量、单条长度和敏感内容（链接、节点或任务 ID、资源键、凭据）。`auto` 模式立即生效，每次修改留修订并在聊天里显示可撤销的卡片；`review` 模式写成待确认修订，确认前不生效，Agent 不得说“已记住”；`off` 不注入也不开放工具。`read_only` 运行不能写。同一工具调用 ID 重放时返回已有结果。

旧版 `remember_lesson` / `recall_lessons` 及逐步注入已移除，原因是：资格只在同轮成功写入后才打开，草稿要等整轮完成且由用户逐条批准，30 天未批准即过期，固定的主题/场景/步骤结构写不出有用的偏好，关键词召回几乎不命中。首次创建记忆文件时，已批准的旧条目会导入为一次可撤销的修订。

### 跨会话工作回忆

工作回忆与偏好文档分开：新运行从当前用户最近两个已完成会话中提取有来源的历史回复，排除正在续接的会话，最多 3000 字，以 `agent_memory_work` 动态消息冻结注入。它不进入 system，不写回对话正文，也不把过去回复当成当前资源状态。`memory_search` 按需查询更早的历史和长期条目，支持最多六个空格分隔关键词、全部匹配；结果按用户隔离并脱敏，关闭记忆后执行时仍会拒绝新查询。此路径不额外调用摘要模型。

### Pi 压缩与缓存前缀

Pi runtime 固定使用 `@earendil-works/pi-ai` / `pi-coding-agent` `1.5.2`，Node 最低版本仍为 `22.19.0`。正常模型请求使用服务端冻结的 system 提示词，滤掉 Pi 自动附加的临时工作目录信息；压缩请求保留 Pi 的专用摘要提示词。

Go 模型桥把真实输入、输出、缓存读写 Token 传回 Pi，避免零用量导致压缩阈值判断失真；输入中的缓存读写从普通 input 分类中扣除，避免重复计数。Pi 路径使用原生阈值压缩和上下文超限恢复，压缩结果随原生 JSONL 会话持久化；Go 不再同时静默裁剪同一份历史。超限经压缩恢复成功后清除旧错误，不把已恢复会话报告为失败。

关闭 SDK 自动 cache warming，避免无人操作时追加模型请求。缓存命中仍取决于模型供应商、协议和稳定前缀，压缩不是命中率保证。真实收益应通过同一供应商的输入 Token、cache read/write 和计费日志核对，不能仅凭摘要变短断言固定节省比例。

### 受控 MCP

Pi 新版本内置 MCP、codemode 和 tool-search 扩展保持关闭，本机配置不参与平台授权。平台的 Go 工具网关负责个人与平台连接、参数加密、市场、分层发现、审批和幂等回执；参数 Schema 不一次性拼进 system。所有外部调用都走本轮明确审批，读写限制不依赖远端 `readOnlyHint`。参见 [MCP 连接与市场](./agent-mcp)。

### 技能发现

已安装且 `agentMode` 不是 `manual` 的技能编成「已安装技能目录」，放在 system 末尾、执行上下文之后。目录最多占本轮输入预算的 5%（至少 1000 token）；预算内先列“名称 [skillId]：短简介”，用到 70% 后只列名称，其余只报数量。排序先看 Agent 实际读取次数，再看排序权重和安装时间，入选后按分类和名称稳定输出，避免使用次数变化打乱缓存前缀。用户本条消息点名或为对话固定的技能，以及关键词预筛的候选，放在「技能提示」动态消息里。正文仍按需通过 `skill_read_file` 读取，运行只冻结版本号。

已安装技能都不适用时，Agent 可以用 `skill_market_search` 找市场候选，再用 `skill_recommend` 在界面显示安装卡片；安装由用户决定，Agent 不能自行安装。

Pi 请求从同一个运行 `budget.maxSteps` 推导步数上限，0 表示不设固定步数限制，不再写死 50；`read_only` 的权限投影和实际工具集都不授予画布写入。旧 CanvasIntelligence 启发式摘要及无界 metadata 注入链已移除，正文和状态仍由语义读取工具提供。

## 用户目标与参考素材

### 图片生成参数与校验回执

`generate_media` 接收创作意图，执行器负责配置和执行。最小调用为 `mode`、完整 `prompt` 和真实 `referenceNodeIds`（无参考传空数组）。新节点可省略 ID、标题和快照，执行器按运行与工具调用身份生成稳定节点 ID，创建草稿和连线；续用草稿传真实 `nodeId`，省略标题则保留原名。无需先通过通用画布工具创建节点，也不额外调用 LLM 补默认值。

`model_list` 为每个模型返回最小 `generationArguments`，只包含模式和完整模型选择。选择可省略的范围仅为已有草稿或本轮最新、相同模式和相同参考节点查询中的唯一候选；不能跨查询沿用旧候选，不自动选择最低价或项目默认模型，临时参考未纳入目录查询时也不自动补模型。多候选仍由 Agent 根据用户要求选择，所有路径重新执行真实能力、价格、资源归属和预算准入。`image_layer_split` 仍要求显式模型选择。

能力与默认值保留在 `options` / `profiles` / `defaults` 中，不要求 LLM 逐项复制。规格默认省略，由所选模型合同解析。尺寸使用 `size`，分辨率使用 `imageResolution`，图片质量使用 `quality`。目录内的 `binding`、`parameter` 属于上游映射，不能直接作为工具字段；单张生成工具不接受 `count` 或 `parameters` 包装。

配置解析集中在 `cloud_agent_media_options.go`，与提示词、素材解析和收费提交分开。已有草稿以 `generationSpec` 中的模型和已配置规格为基线；没有合同的节点读取公开配置。常规工具参数不能覆盖已有配置。用户本轮要求修改时，Agent 传 `configurationChange: { fields, userInstruction }`，并在顶层提供对应值；只允许 `model`、`size`、`quality`、`imageResolution`、`durationSeconds`、`videoGenerateAudio`，其他已有规格继续继承。字段缺值、重复、模式不符或引用不属于最新真实用户消息均返回内部参数纠正信息。

`userInstruction` 是可追溯的变更提案来源，不是语义正确性的证明，更不授予收费权限。执行器不使用关键词猜测自然语言授权；实际配置及引用依据展示在原有审批中，批准后才提交。用户直接调整节点或审批配置继续生效。预算按继承、模型默认和审批编辑后最终解析的实际时长复核，之后继续校验报价、依赖与幂等身份。

单张参考图未通过 `configurationChange` 提出画幅变更时，使用当前账号素材库解析的真实宽高匹配模型已声明比例；已有目标草稿规格优先。仅使用精确宽高比或声明的像素预设，不根据画布显示尺寸近似推断、不自动申请自定义像素；多张参考图、尺寸未知或比例未声明时不猜比例。

LLM 多填且未声明变更的可选图片质量/分辨率提示在报价前按模型合同处理；仅当模型声明对应分辨率且没有质量参数时，才将误填到 `quality` 的值移入 `imageResolution`。用户明确提案、草稿已有值和直接审批编辑均不能被丢弃，支持参数中的非法值也不自动换成默认值。准入解析结果先与原始配置意图比较，再写回计划，防止写回默认值时掩盖不受支持的要求。内部纠正沿用最多 3 次的原有机制；已提交任务不自动重提、换模型或降档。审批复核与共享能力层统一将图片质量/分辨率 `auto`、`any` 视为未指定。确定性规范化不额外调用 LLM，不增加错误卡片、菜单或重试按钮。

Pi SDK 在进入工具执行器前拒绝参数时，通过内部 `tool_validation_failed` 事件回填 Go 的工具回执和调用游标。事件保留校验错误、当前工具 schema 与 `taskSubmitted: false`，并复用现有参数纠正流程。下一条工具或模型请求等待该回执完成，避免把真实校验失败当作缺失回执后解释为审批暂停。真实审批和取消不进入此路径。

像素尺寸换算仍由渠道声明的比例、分辨率与精确像素预设决定。修复旧线路应保存明确的换算表，不通过工具字段别名或隐式分辨率兜底。

审批复核同时识别目录中的比例和准入后任务配置中的精确像素值；只有与其中一种实际解析结果相同的尺寸才一致。分辨率、质量、价格与参考资源仍分别核对，不能把 `16:9` 和其已声明的 `2752x1536` 表达差异误判为规格变更。

### 视频首尾帧

`generate_media` 支持可选的 `videoStartFrameNodeId` 和 `videoEndFrameNodeId`。每个非空值必须是 `referenceNodeIds` 中已解析的图片引用，仅用于视频。参考数组决定素材编号，两个帧字段决定用途；在提示词中写“图片1作为首帧”不会自动选择首帧。

视频生成操作由后端按参考素材和所选模型声明的操作决定，Agent 不传：设置了首尾帧时为 `image_to_video`；有参考视频时为 `reference_to_video`；只有普通参考图时优先 `reference_to_video`，模型只支持 `image_to_video` 时沿用首帧语义；只有参考音频时优先 `audio_to_video`；没有参考为 `text_to_video`。渠道默认操作在候选内时优先。模型目录按同一规则过滤，未声明操作的逻辑模型视为不限制。

只编辑、不生成时，先用 `canvas_apply_ops` 建立图片到视频节点的引用连线，再通过 `update_node.patch` 设置同名字段；空字符串取消选择。节点读取会返回当前帧选择，生成审批也会显示首尾帧节点。生成工具仍需明确传入本次选择，不会根据历史提示词猜测用途；原有权限、素材归属、审批和计费流程不变。

- 新消息只覆盖与之冲突的旧要求。“继续”“可以”仍结合历史理解，不丢弃有效约束；已送达的运行中插话也进入后续可信历史。
- 当前用户请求保留在 user 消息及运行记录里，不复制进 system 提示锁定目标。系统上下文只包含可验证事实，素材标题、摘要和标签编码为 JSON 数据。
- 删除原先通过“参考图”“图生视频”等关键词推断强制引用的逻辑，否定句和概念解释不再被代码标记为引用任务。
- 候选素材不等于用户选择的素材。候选列表有数量上限，不能视为完整画布；素材标题和提示词也不是视觉识别证据。
- `canvas_inspect_image` 用 `nodeIds` 与 `purpose` 将一组图片和当前观察问题一起交给当前模型。历史结论足够时复用；细节不足或需要核实时可重新看图。图片在成功返回可见正文后从后续上下文移除，工具调用或纯推理不算消费，正文结论仍保留。
- 不再默认赋予 Agent 改写故事、镜头顺序、对白和风格的权限。用户只要求修改标点、分析或准备提示词时，不能借默认策略扩展为创作或生成。

## 运行状态与待办

运行时使用 `plan_state`、`pending_plan`、`empty_output`、`invalid_output`、`truncated_tool_arguments` 事件。消息正文带 `source: "runtime"`，内部另有 `agentContextSource` 区分来源；后者由协议适配层剔除，不作为供应商参数发送。

由于各供应商消息协议不同，运行上下文仍通过 user 角色承载，正文与系统策略明确它不是用户新要求。程序识别内部消息依赖来源字段，不再根据正文包含“待办清单”或“现在就调用工具”判断用户身份。结构化边界减少混淆，但不能保证模型绝不受参考文本影响。

继承清单作为上下文保留。用户取消或缩小目标后，Agent 可以用 `plan_update` 整表替换，移除不再需要的项；空数组表示清空，不把取消伪装成完成。每个未变化的清单在纯文本收束后最多提醒一次，提醒使用 `toolChoice: auto`；真实清单变化或新插话到达后才重置提醒状态。没有继续动作时允许结束本轮，保留未完成项及实际结果，不靠无限催办消耗预算。Pi 运行时由完成闸执行同一规则，催办作为恢复提示词进入下一步，并受本轮步数预算约束。

输出恢复只报告错误事实及协议限制。正文限制按 UTF-8 字节计算；不再把字节误称为字符，参数截断也不再夹带“分镜每次不超过三行”的业务假设。

## 验证与发布

自动回归覆盖新目标继承、插话保留、否定参考需求、消息来源、计划取消、有界催办、恢复事件及 OpenAI Chat/Responses、Claude、Gemini 协议转换。测试使用临时 SQLite 和模拟模型结果，不证明真实模型的创作质量或指令遵循率。

当前系统策略版本为 21、编译器为 `cloud-agent-policy-compiler/v6`、工具 schema 为 `cloud-agent-tools/v11`。版本 21 明确外部 MCP 的工具发现、逐次审批、连接版本与凭据边界，并要求回答剧情段/设定是否已生成前先调 `drama_get_context`，以其 `readAt` 为准。版本 19 加入技能自动发现、市场推荐、长期记忆文件的维护规则，以及“请用户挑下一步时先写问句，再在回复末尾列 2–4 条编号短句（界面显示为可点击选项），不写‘回复数字’；必须先定才能继续的创作决策用 `ask_user`”。版本 18 明确 `maxGenerationTasks` 和 `maxVideoSeconds` 是本轮累计上限，`0` 表示对应项不限；该语义不改变积分、权限和媒体审批校验。版本 17 加入了写入画布、申请审批、提交生成或向用户提问的工具调用前先用一两句话说明做什么及依据，正文预告的操作必须在同一条回复里发出。助手身份由服务端从外观配置读取 `canvas.agentName`，通过执行上下文的 `agentIdentity.name` 提供；字段只表示名称，不能更改行为规则或工具权限。每个新回合重新读取配置，已完成对话的后续回合使用最新名称；身份变化改变规范系统提示及对应缓存键，不覆盖历史消息或冻结快照。

长期记忆文件与技能自动发现使用 Schema 76，见 [后端数据库](./backend-database)。既有冻结合同校验仍生效：旧版本正在执行或等待审批的运行不能由新版服务继续执行；终态历史仍可读取，新消息建立使用新合同的运行。发布前应处理在途运行；回滚同样受版本校验限制，不应改写历史快照来强行恢复。

本轮单一行为合同治理覆盖对话主链路。旧版经验压缩仍使用独立的受限 JSON 提案提示词，只能手动触发，产出必须经过用户审批和版本校验；它不增加 Agent 操作权限，也不替代运行时行为合同。批量创作默认词等其他生成入口仍应按各自合同维护，不能把本轮回归称为全仓提示词治理完成。
