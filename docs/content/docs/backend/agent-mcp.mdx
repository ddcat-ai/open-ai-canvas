# Agent MCP 连接与市场

Agent 可以通过远端 MCP 服务查询或操作外部系统。用户在「Agent 设置 → 工具与连接」管理个人连接；管理员在「管理后台 → MCP 管理」提供平台连接和市场条目。配置保存在服务端，后续会话可以使用已启用且已授权的工具。

当前支持 Streamable HTTP 和 SSE 两种远端连接方式。不支持在影策服务器上执行用户填写的 `npx`、shell 命令或上传的本地 MCP 程序，也没有自动完成第三方 OAuth 登录的界面。需要 OAuth 的服务应先取得适用凭据，或部署支持当前认证方式的适配服务。

## 连接和市场的区别

| 类型     | 谁配置凭据                                 | 谁可以使用和维护                                           |
| -------- | ------------------------------------------ | ---------------------------------------------------------- |
| 个人连接 | 当前用户                                   | 当前用户使用、编辑、检测和移除                             |
| 平台连接 | 平台管理员                                 | 仅明确列入授权名单的用户可使用；管理员本人使用也需授权；用户不能修改或读取凭据 |
| 市场条目 | 不保存安装后的凭据，只定义地址、说明和参数 | 管理员发布；用户安装后形成独立的个人连接                   |

市场安装不会直接获得外部工具权限。同一个市场条目可以安装多个连接，用于不同服务地址或外部账号。工具清单、允许调用的工具和启用状态分别保存在每个连接中。

## 安装个人 MCP

1. 打开「Agent 设置 → 工具与连接 → MCP 市场」，选择条目并点击「安装」。也可以在「已安装」中添加自定义连接。
2. 填写名称、连接方式、完整服务地址和参数。自定义连接可填写可选的 Bearer 访问令牌；市场条目显示管理员定义的参数。
3. 保存。新连接默认停用，未授权任何工具。
4. 点击「检测连接」。后端实际连接服务并发现工具；失败时显示错误，不能把保存配置视为连接成功。
5. 检测成功后，勾选允许 Agent 使用的工具，打开「启用此连接」并保存。
6. 在后续 Agent 运行中提出任务。Agent 先查询可用连接与工具，再按需读取某个连接的工具参数；实际调用前会请求确认。

服务地址应与连接方式对应，例如 Streamable HTTP 服务的 `/mcp` 地址或 SSE 服务的事件端点。地址不能含账号密码、查询参数、片段或密钥占位符；认证通过请求头参数完成。没有工具的服务可以检测成功，但不能启用为空的工具授权列表。

## 参数和授权变更

凭据加密保存在后端。编辑时不返回密钥原文，只提示哪些密钥已经配置；同一地址和模板下，密钥输入留空表示保留原值。普通参数可回显和修改，密钥不会写入浏览器持久化存储。

修改地址、连接方式、参数或市场模板配置后，需要重新检测并授权工具。重新检测本身也会清空旧授权并停用连接，因为外部服务可能在同名工具下改变参数或行为。更换服务地址或模板时，旧凭据不会自动转移到新目标；需要重新填写所需密钥。

管理员编辑市场模板时，服务端会原子清空已安装连接的全部参数和密钥，同时停用连接、撤销检测和授权。用户需要重新填写、检测并授权。这能防止旧密钥在模板把参数改为普通文本后被回显。

连接带有服务端版本号。Agent 列出工具时取得该版本，审批和执行时重新校验；如果等待确认期间配置、启停状态或授权发生变化，旧操作会被拒绝，需要重新读取工具并确认。

新调用在一个短数据库事务中校验当前运行、审批、连接和模板，并登记回执；该事务提交是执行准入点。此前完成的取消、下架、停用或移除会阻止调用。已经准入的外部操作可能继续完成，撤权或取消不能撤回已发出的操作。

## 管理平台连接与市场

「管理后台 → MCP 管理」提供两个页签：

- **平台连接**：添加远端连接，检测服务，指定允许使用的用户、工具及每个工具的参数范围后启用。平台凭据由管理员维护，空用户名单默认拒绝所有人。
- **市场管理**：编辑名称、介绍、文档链接、默认地址、连接方式、用户参数和请求头模板；发布后出现在用户的 MCP 市场中。

每个参数有唯一名称、显示名称、说明、类型和是否必填。普通文本可以有默认值；密钥参数没有默认值。参数名称以字母开头，仅使用字母、数字和下划线，最多 64 个字符。

请求头使用参数占位，例如：

```json
{
  "Authorization": "Bearer {{token}}"
}
```

此时应定义名称为 `token`、类型为「密钥」的参数。市场模板里不填写真实凭据。服务地址需要用户自部署时，可以将默认地址留空，由安装者填写。

平台连接的 `allowedUserIds` 最多 100 位已启用用户。`toolPolicies` 按工具名保存独立的对象 JSON Schema；每个被授权工具都必须明确配置。它与远端工具声明的 schema 同时生效。以接收 `owner` / `repo` 参数的 GitHub 工具为例，可以限制到指定仓库：

```json
{
  "type": "object",
  "properties": {
    "owner": { "const": "your-organization" },
    "repo": { "enum": ["approved-repository"] }
  },
  "required": ["owner", "repo"]
}
```

必须按实际工具参数配置约束；不接收仓库参数的全局搜索工具不能直接套用此示例。若无法可靠限定范围，应关闭该工具，或让用户安装使用本人凭据的个人连接。显式保存 `{ "type": "object" }` 表示管理员允许该工具的所有合法参数，不会自动生成这种宽泛授权。

请求头模板除少数明确的非敏感标准头外，必须引用 `secret` 参数。自定义认证头也不能通过普通文本参数回显凭据。

不符合当前凭据规则的旧模板不会出现在公共市场，也不能用于检测或执行；管理员仍可查看并修正配置。诊断日志只记录模板 ID 与拒绝类别，不记录请求头值。

## 外部工具执行边界

- 工具发现使用 `mcp_list_tools`，只返回当前用户可用的连接和已授权工具；不把全部外部工具定义永久加入每轮提示词。
- 外部调用使用 `mcp_call_tool`，携带连接 ID、配置版本、工具名和参数。发现、审批和执行都会检查个人归属或平台用户名单；执行还复验启用状态、工具授权、远端 schema 及平台参数约束。
- 每次外部调用都要确认，远端工具声明 `readOnly` 不能免除审批。只读运行不执行外部 MCP 调用。
- 连接使用独立出站策略：默认拒绝私网、明文 HTTP 和重定向，不继承 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS`，也不使用环境代理。可信内网 MCP 只能通过 `CANVAS_MCP_ALLOWED_PRIVATE_HOSTS` 按主机精确放行；连接时复验 DNS 并绑定实际拨号地址。
- 调用前登记执行记录，完成后保存回执。同一个已登记调用不会因重连或恢复而重复执行。已完成回执在连接停用或移除后仍可回放，不会再次访问外部服务。
- 超时、断线或回执未能保存时，外部服务可能已经完成操作。错误分类为 `external_result_uncertain`，`retryable: false`；系统不会自动重放，同一运行换调用 ID 也不能重复相同的未确认操作。应先到外部服务核对结果，再决定是否发起新的操作。
- MCP 返回 `isError` 时显示调用失败；协议响应成功不代表外部业务成功。

## 容量和多用户隔离

| 边界 | 当前限制 |
| --- | --- |
| 个人连接 | 每账号最多 30 个，并发创建在数据库事务中计数 |
| 检测结果 | 每连接最多 128 个工具，单工具 schema 32 KiB，全部 schema 合计 256 KiB；列表仅返回摘要 |
| 检测速率 | 每账号每分钟 6 次；同时每用户 2 个、每连接 1 个、全局 16 个 |
| 外部调用 | 每账号每分钟 60 次；同时每用户 2 个、每连接 1 个、调用全局 32 个；检测和调用总并发受共同上限约束 |
| MCP 持久数据 | 每账号 64 MiB，包含配置、加密参数、工具 schema、调用回执及元数据预留；外部调用前预留回执空间 |
| Agent 持久数据 | 每账号 256 MiB，包含状态、原生会话、事件、消息和撤销快照正文；旧数据在首次写入时纳入账本 |
| Agent 进行中轮次 | 每账号默认 5 个，含无画布对话、排队、等待确认和待清理轮次；后台 `agentMaxRunsPerUser` 可设 1–64 |

PostgreSQL 多实例使用共享协调器和事务锁，协调器不可用时拒绝新的 MCP 外部操作；SQLite 本地使用进程协调器和数据库写锁。已完成调用的回执重放不发外部请求、不重新占用调用额度。存储额度耗尽会拒绝增长写入；Agent 取消和失败清理仍可执行。管理员用户详情显示 Agent / MCP 各自用量。系统不会为了腾空间静默删除用户历史；需要管理员安排归档。维护程序若裁剪 MCP 回执，必须保留永久的调用指纹和 `expired` 标记，不能删除幂等凭证后重新执行外部操作。

媒体批次在终态收尾且历史额度不足时，保留原历史与任务结果、回写已完成媒体，只裁掉已无用途的批次执行参数和校验 hash，不追加事件且不增加存储字节。已提交上游的用户取消任务仍继续完成，再释放批次租约；界面提示到画布或任务中心查看结果。

浏览器账号切换会使旧标签页会话失效，取消进行中的 API / Agent SSE / 文本 SSE，并拒绝晚到响应。请求绑定发起时的 `X-Canvas-Expected-User`；旧草稿保留在原账号缓存，认证恢复后才切换缓存范围。

运行时临时目录由父进程创建和回收，取消后等待子进程退出再清理，定期回收已过期且没有活跃进程的带标记孤儿目录。当前是共享服务进程下的应用层用户隔离，不是每用户容器；不支持执行用户提供的 MCP 程序。若未来开放本地程序、仓库执行或任意代码，必须另设按租户隔离的执行环境。

## 运行时资源与维护

`docker-compose.deploy.yml` 为 Agent 设置只读根文件系统、移除所有 capabilities、禁止提权，并使用有上限的 `/tmp`。backend 保留资源处理和既有插件需要的能力，单独限制 CPU、内存和进程数。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `YINGCE_AGENT_MEMORY_LIMIT` / `YINGCE_AGENT_CPUS` / `YINGCE_AGENT_PIDS_LIMIT` | `4g` / `2` / `256` | Agent 容器硬预算 |
| `YINGCE_AGENT_TMPFS_SIZE` | `512m` | 临时会话文件总量，使用内存型临时卷，计入容器内存压力 |
| `YINGCE_AGENT_MAX_SESSIONS` / `YINGCE_AGENT_SESSION_CAP` | `8` / `8` | 初始并发 / 部署硬上限；实际并发取后台运行策略与硬上限中的较小值 |
| `YINGCE_AGENT_NODE_MEMORY_MB` | `512` | 每个 Node 子进程的 V8 old-space 上限，不是进程总内存 |
| `YINGCE_AGENT_MAX_QUEUE` / `YINGCE_AGENT_QUEUE_TIMEOUT_SECONDS` | `64` / `60` | 队列容量与最长等待秒数；排队期间不读取完整请求正文 |
| `YINGCE_AGENT_BODY_TIMEOUT_SECONDS` / `YINGCE_AGENT_KILL_GRACE_SECONDS` | `30` / `5` | 正文读取期限 / SIGTERM 后强杀前等待秒数 |
| `YINGCE_AGENT_ORPHAN_TTL_SECONDS` | `86400` | 带归属标记且无活跃父子进程的孤儿目录回收期限 |
| `CANVAS_BACKEND_MEMORY_LIMIT` / `CANVAS_BACKEND_CPUS` / `CANVAS_BACKEND_PIDS_LIMIT` | `4g` / `2` / `256` | backend 容器预算，视频转码等高负载需按容量调整 |
| `CANVAS_LOG_MAX_SIZE` | `10m` | backend 与 Agent 日志单文件上限，各保留 3 份 |

修改 Compose 资源参数需重新创建容器。不要把两个 4 GiB 容器上限当作整机最低内存估算，还需给 PostgreSQL、Redis、web、临时文件与宿主机留余量。旧后台若已保存 30 个 Agent 并发，本次部署硬上限仍限制实际执行为 8；调高前需要压测。嵌入模式未设置硬上限时仍允许管理员在 1–64 范围配置并发，不会自动拥有生产容器预算。

backend 与 Agent 镜像须按同一 Release 升级。嵌入模式可配置绝对路径 `YINGCE_AGENT_TEMP_DIR`，须为服务账号独占私有目录；不要设置父进程内部变量 `YINGCE_AGENT_RUN_DIR`。旧版本无归属标记的 `agent-runtime-*` 目录不自动删除，应在确认相关进程已停止后离线清理。

每用户额度不等于数据库物理文件大小。PostgreSQL WAL、索引、备份、系统数据及所有用户累计磁盘占用仍需部署容量告警和保留策略；系统不会为腾空间自动删除用户历史。

## 升级到授权隔离版本

数据库迁移 103 会停用所有旧 MCP 连接（含个人连接），清除旧检测快照和工具授权并增加版本号；凭据和执行回执保留。升级后重新检测并授权，平台连接还必须指定用户和参数范围。迁移 104 新增 Agent 用量账本。应同时更新 backend 与 Agent 镜像；回滚需要恢复升级前数据库和密钥备份。

## 飞书反馈日报

可以连接已部署、已授权的飞书 MCP 服务，让 Agent 调用该服务提供的消息或文档工具。针对“飞书用户提出需求或 Bug，每天汇总给管理群”的固定收件场景，后台还提供独立的飞书事件回调和日报 worker：管理员在 `/api/admin/integrations/feishu` 配置应用凭证、校验 token、目标群、时区和日报时间，飞书将文本事件发送到 `/api/integrations/feishu/events`。

回调会校验 token；配置 EncryptKey 时校验 Lark 签名。首版明确只接受明文文本事件，包含 `encrypt` 字段的加密事件会拒绝并提示关闭事件加密。消息写入现有反馈收件箱，事件按租户和事件 ID 幂等；日报使用跨实例租约和持久化状态，网络结果不确定时不自动重试。MCP 参数配置和飞书收件配置相互独立，MCP 仍适合调用外部文档、查询或操作工具。

浏览器完整流程及真实 MCP 服务仍需按[待测试清单](/docs/progress/pending-test)验收。接口和数据结构分别见 [HTTP API 合同](/docs/backend/http-api)与[后端数据库](/docs/backend/backend-database)。
