# Spec-001：影策跨平台本地启动与更新器

**状态**：源码安装开发版实施中；以下区分当前实现与未验收目标，不代表完整产品放行。当前操作说明见 `launcher/README.md`。

## 1. 当前决定与范围

独立 Tauri + React 桌面应用使用影策图标，管理自己的影策副本，真实服务就绪后在默认浏览器打开。固定订阅 <https://github.com/ddcat-ai/open-ai-canvas> 固定 `main` 分支（上游不发布 Release），解析最新完整提交并下载 GitHub 源码归档，在受管目录本机编译，不关联或修改现有开发仓库。

**本方案已取代最初“等待预构建桌面运行包”的设计**。上游没有 Release 和桌面附件，均不是安装门槛；版本号形如 `main-<短提交>`，更新检查即比较 main 最新提交与已安装提交；也不要求发布公钥、签名清单、云账号或 GitHub Token。旧签名与预构建整理脚本仅为遗留工具，不是活动协议。

范围是本地 SQLite 影策与嵌入 Node Agent，不接管 Docker/Host Updater、服务器 PostgreSQL/Redis 或生产 Agent 容器。在线模型与公共资源仍可能依赖网络，不承诺完整离线推理。

## 2. 安装与架构

```text
Tauri 界面 → Rust core / source_install
                ├─ 固定 main 分支最新提交、下载、安全解压、受管缓存
                ├─ Go/Bun/Node/CC 工具链与本机源码构建
                ├─ 版本/数据指针、文件库存、进度、日志
                └─ 内嵌本机 Go 网关 → 真实后端 → 配套 Node Agent
默认浏览器 → 固定回环来源 → 网关静态页面 / 同源业务 API
```

- Go >= 下载源码 `go.mod`，Bun >= `packageManager` 指定版本，Node >=22.19.0 且含 npm；缺失工具下载到缓存并核对官方 SHA-256。
- Windows 可准备便携 LLVM-MinGW；Unix 系统编译器及头文件是前置条件。真实业务后端启用 CGO=1，不能用 CGO=0 绕过 SQLite。
- 构建实际 Go 后端、Vite 前端、Agent 生产依赖及官方插件包，配套 Node。不是开发服务器、仿制 HTML 或空壳运行包。
- 网关由 `build.rs` 在启动器构建时用 Go >=1.25 编译并嵌入；CI 原生矩阵须准备 Go，不依赖运行时另找外部网关资源。
- 目录包含 `sources/`、`releases/`、`cache/`、`staging/`、`data-versions/`、`logs/` 和 `state/`；数据不放待替换代码目录。

首次点击安装并启动，展示真实阶段进度；编译与依赖安装可能较长。禁止并发操作，就绪后核对精确版本、完整提交，再打开浏览器。默认 `http://127.0.0.1:37890`，端口被占用不静默换端口，以免改变缓存作用域。

## 3. 来源与安全

官方直连为默认；保留 `ghproxy.net`、`ghfast.top`、`gh-proxy.com` 三个第三方 GitHub 代理，以及仅镜像、官方失败后切镜像策略。非官方模式同时为 Go/npm 构建依赖配置镜像；工具下载仍有独立官方链路。详见 `launcher/docs/mirror-options.md`。

HTTPS、摘要、安全解压、本地文件库存及目标平台约束仍保留。源码归档本地缓存摘要不是独立发布者签名，公共代理不是本项目维护的可信基础设施。不得发送私密凭据或改系统证书以绕过失败。

网关仅回环监听，精确检查 Host/Origin，业务登录、归属、权限和 SSRF 不降级。Agent PATH 只指向配套 Node，不继承宿主数据库、远端 Agent 或调试配置。

正常关闭使用认证回环请求：安装器只在下载的 Go 源码副本增加私有关闭适配，不改仓库后端；随机令牌及真实回环来源校验后取消后端上下文。超时强制清理不能称为任务无损；崩溃与孤儿进程仍需原生验证。

## 4. 更新与数据事务

1. **准备（可在服务运行时进行）**：解析 `main` 最新提交，取得源码并构建到新的 `releases/` 目录，核对文件库存，记为“已准备版本”。不触碰数据，也不影响正在运行的服务。
2. **切换（必须先停止服务）**：用户显式先停止服务；运行中拒绝切换。
3. 持有旧数据目录排他锁，将数据复制到全新 `data-versions/` 目录，拒绝覆盖；旧版本与原数据保留。
4. 候选服务仅使用副本启动，数据库启动时自动迁移仅作用于该副本。
5. 精确版本、提交及真实就绪检查成功后，才持久保存新代码/数据指针；此前不开放浏览器。
6. 失败时不提交新指针，保留原数据与旧代码；候选无法安全停止、状态写入失败等需明确报错。

### 增量源码与后台自动更新

- **增量源码**：有上一版的缓存源码包时，取 `git/trees/<提交>?recursive=1` 的目录清单，与上一版逐文件比较 git blob 编号，只下载有差异的文件（走 `github.com/.../raw/<提交>/<路径>`，同样支持镜像）。每个下载文件校验 blob 编号，完成后整棵目录按清单整体复核，失败、差异过大（超过 1500 个文件或 96 MiB）或无上一版包时自动改用完整源码包。镜像对 `compare` 接口会返回 403，因此不用该接口。新版源码同时写成缓存包，供下一次增量使用；缓存只保留已安装和最新两份。
- **构建仍是完整构建，但依赖走缓存**：Go 模块与编译缓存、Bun/npm 依赖缓存、工具链在 `cache/` 中跨版本共享。增量节省的是源码下载，不是编译。
- **后台自动更新**：设置中可开启，每天固定时间或每隔 N 小时；仅在启动器打开时执行，错过的每日时间在下次打开时补做一次。到点只“准备”新版本，不自动停服、不自动切换；准备完成后工作台提示，用户停止服务后一键切换。后台准备不持有管理锁，期间可正常启动/停止服务，但与手动安装互斥。默认关闭。

不承诺完整断电恢复、自动数据库降级、自动删除旧版本或用户已写入新版数据后的无损回退。浏览器 IndexedDB 不包含在服务端数据副本中。

## 5. 当前验证证据

- 已收到专项结果：Rust 28 项通过、5 项实网测试默认忽略；Go 网关测试、前端 11 项 bun 测试、3 项 node 脚本测试（1 项因 Windows 无符号链接权限跳过）及前端构建通过。
- 真实探测已下载约 300 MB 官方源码、验证受管 Bun；直连 Go 依赖失败，镜像 Go 依赖成功。
- Windows CGO 遇到 `\\?\` 规范化路径影响 LLVM 头文件查找，适配已修正，完整重试仍在进行；**端到端首次安装/启动尚未确认通过**。
- macOS/Linux 无原生完整安装验收；CI 编译与历史交叉编译不构成运行成功证据。

显式实网命令与 `.local` 隔离 smoke 根目录要求见 `launcher/README.md`。测试会启动真实后端并保留隔离数据，禁止指向开发账号或生产目录。
