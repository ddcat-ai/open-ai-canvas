# 公共 Release 与源码安装

## 当前活动协议

启动器固定访问 <https://github.com/ddcat-ai/open-ai-canvas> 的最新公开 Release，解析标签到完整提交，以该提交的 GitHub 源码归档作为安装输入。没有桌面运行包附件不再阻止安装；源码需要在用户机器真实构建，不能把 ZIP 当可执行文件运行。

下载解压到受管暂存目录，与现有开发仓库完全独立；成功后源码按提交保留在 `sources/`。完整归档记录提交、来源及本地 SHA-256 后进入缓存，复用时核对；这不是由上游独立签名的源码证明，也不是部分下载续传。

`source_install.rs` 根据源码清单准备 Go/Bun/Node/C 工具链，启用 CGO 构建后端，构建 Vite、安装 Agent 生产依赖并生成插件包。缺失工具从固定官方发布入口取得 SHA-256 并验证后使用。运行文件再生成本地库存摘要，供后续启动与更新检查。

## 更新与数据提交

1. 用户显式停止现有服务；运行时安装/更新被拒绝。
2. 下载并构建目标提交，不修改旧数据。
3. 持有旧数据目录排他锁，复制到新的 `data-versions/<版本标识>-<时间标识>/`，拒绝覆盖目标；保留旧代码及原数据。
4. 候选服务使用副本启动，后端自动迁移只作用于副本。
5. 真实就绪检查与版本/完整提交核对成功后才保存新版本及数据指针，再打开浏览器。
6. 失败保留原持久指针及旧数据；候选停止失败等情况必须明确报错，不宣称已自动恢复全部现场。

这不是共享数据目录上直接替换二进制，也不支持数据库静默降级。断电恢复、迁移失败、存储写入失败及用户使用新版后的回退仍需专项验收。

## 来源及信任边界

- 不要求 `YINGCE_RELEASE_PUBLIC_KEY`、签名清单、云账号或私有 GitHub 凭据。
- 官方与三个公共代理的策略见[镜像说明](mirror-options.md)。代理传输及其返回元数据不是独立可信签名。
- 保留 HTTPS、下载边界、有限安全解压及本地文件库存检查；摘要不能消除上游或代理被攻破风险。
- 包依赖与工具下载还有独立来源，不保证“GitHub 代理能访问”等于全部链路可访问。

## 构建与遗留工具

`build.rs` 用 Go >=1.25 将独立网关编译为目标平台二进制并嵌入 Tauri 应用。CI 原生矩阵通过 `actions/setup-go` 按 `launcher/runtime/go.mod` 安装 Go；下载开发可执行文件无需额外寻找网关资源。该 CI 不发布正式安装包、不操作上游 Release，尚不代表原生端到端运行验收。

`sign-release.mjs`、预构建 staging 示例及旧签名清单设计属于遗留工具，不是当前公共源码安装入口或安装门槛。当前没有新增签名、公证、远端上传或账号操作。
